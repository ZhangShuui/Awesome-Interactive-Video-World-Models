WorldReward

面向相机条件世界模型的奖励建模：把长视频切成「动作对齐的块」，让 VLM 从六张图里同时裁决「动作执行了没有」与「画面好不好」

世界模型生成的交互视频有两件事要对：指令动作要引起预期的画面变化，外观、几何与时间动态要保持连贯。 过去这两件事由两套异构系统分别打分——几何模型估轨迹、图像奖励模型看单帧。WorldReward 用一个 VLM（Qwen3.5-9B 微调）在同一份证据上同时给出两个偏好： 它不看整段视频，而是把每对视频按四个动作一块切开，每块只看六张图（源图 + 帧网格 + 四张动作面板），逐动作比较 A / B，再把各块的裁决投票成视频级的动作偏好与视觉偏好。 训练数据来自 Gemini 3.1 Pro 的块级推理蒸馏，再经 GPT-5.5 工具型 agent 多轮审计与人工校准；在 760 对人工标注的 WorldReward-Bench 上三个维度全部第一，用作 HY-WorldPlay 1.5 的 RL 奖励时在短 / 中 / 长时程上同时提升动作执行与视觉质量。

00TL;DR

一图看懂：局部证据 → 块级裁决 → 投票成全局偏好

这篇论文的核心不是一个新网络，而是一套「怎样把一对长视频喂给 VLM 评判」的输入组织方式，外加一条配套的数据管线和一个人工标注 benchmark。 下图把论文 Fig. 1 的五个步骤压成一张：同一条件下生成的两段视频，被切成动作对齐的块；每块只看六张图，由 WorldReward 写出结构化的裁决；再按块投票。

ACTION

动作一致性：逐动作对比

每个动作的指令是「平移 | 旋转」两轴，VLM 被要求对每个指令分量核对方向（旧内容往哪个边走、新内容从哪个边进）、幅度、纯净度（有没有多余的缩放 / 漂移 / 倾斜）、平滑度与 3D 合理性；四个动作各出一个胜者，再汇总成本块的动作胜者。

VISUAL

视觉质量：三个互补子维度

时间一致性（块内帧间稳定：闪烁、跳变、细节漂移），动态生成质量（是真的在生成运动，还是静止 / 贴图滑动 / 破坏性形变），伪影与结构完整性（模糊、重影、融化、撕裂、身份漂移、以及相对源图的场景漂移）。

AGGREGATE

投票：局部到全局

K 块各投一票，只数 A 与 B，多者胜、相等为 Tie（Eq. 3）。目的有二：把短暂的局部失败放大到能被看见；同时不让某一块特别强或特别弱的表现单独决定整段视频的偏好。

◆ 如果只记三件事

1. 「统一」的含义是同一模型、同一份证据、两个独立偏好：动作偏好与视觉偏好从同一次推理里产出，但作为 RL 信号仍然分开、可加权（Sec. 3.6）。它取代的是 WorldCompass 里「DepthAnything3 估轨迹 + HPSv3 打单帧」的两套系统。

2. 输入组织是全部技巧所在：前置 IDLE 槽 → 4 槽一块 → 每块 6 张图。消融显示去掉源图主要伤外观（−2.37），去掉帧网格伤最大（平均 −2.48），去掉动作面板主要伤动作（−2.82）（Tab. 6）。

3. 超过老师的原因不在蒸馏而在标注精修：直接蒸馏 Gemini 只有 68.69 平均一致率（≈ Gemini 自己的 68.90），GPT-5.5 agent 审计后跳到 75.94，人工校准再 +1.39 到 77.33（Tab. 5）。

01The Problem

三类奖励各缺一半，整段直接喂给 VLM 又太长太吵

相机条件世界模型（camera-conditioned world models）的输出有没有用，取决于两件耦合的事：指令的相机动作是否被忠实执行，以及执行过程中几何、外观、时间动态是否保持连贯。 论文引言把这个奖励建模问题的难点归为三条，并逐一指出现有奖励为什么不够。

1.1现有奖励的盲区

奖励家族代表能看见什么看不见什么
几何奖励DepthAnything3、WorldMirror（3D 基础模型从帧序列恢复相机轨迹，再与指令比对）轨迹执行的几何一致性执行过程的视觉质量：时间稳定性、动态是否合理、生成伪影
图像奖励HPSv3、LAION Aesthetic（逐帧打分）单帧好看不好看动作有没有执行，以及闪烁、运动不连续、外观漂移、动态不一致这类跨帧问题
通用视频偏好模型VideoAlign、UnifiedReward-Flex / -Think感知质量不以指令动作为条件，不验证动作是否被遵循
组合奖励WorldCompass（几何 + HPSv3）两边都有由两套异构、解耦的系统各自评估，没有共同的解释
直接整段 VLM 评判把全部帧 + 全部动作序列一次给 Gemini / GPT理论上都能看上下文又长又吵：稀疏采样漏转变、稠密采样撑爆上下文、局部失败被整体印象稀释

WorldReward 的立场是：VLM 提供了一个把动作和它的视觉后果放在一起推理的共享空间，问题只在于怎样喂。它的解法是「local-to-global」：先把长视频对切成时间对齐的、每块四个连续动作的块，每块从结构化的视觉证据里做判断，再把块级决策投票成分开的全局动作偏好与视觉偏好。

论文对 Table 3 的解读也呼应了这张表：几何估计器（DAv3 70.53）的动作信号有竞争力但完全没有视觉维度；图像 / 视频偏好模型有外观信号但动作维度是空的；WorldReward 是唯一在三个维度上都给出判断、且都最高的模型（Sec. 4.2）。

02Formulation

形式化：一对视频、一个条件、两个维度的偏好

论文把奖励建模放在成对比较的设定里：同一条件下生成的两段视频，模型对每个维度给出「A 更好 / B 更好 / 平」。这与 UnifiedReward 系列的 VLM-as-judge 范式一脉相承，只是多了「必须验证每个指令动作引起的局部转变」这一层。

(1) pθm(A ≻ B | x0, d, a1:N, VA, VB),　m ∈ {act, vis} 条件 = 源图 x0 + 其 caption d + N 步相机 / 动作轨迹 a1:N；VA、VB 是同条件、同轨迹下两个候选视频。维度 m 取动作一致性或视觉质量。

关键的一步是：模型不把 Eq. 1 里的整段视频当一个无结构的输入，而是评估一串块级比较输入：

(2) zk = (d, ask:ek, ℐk),　k = 1, …, K as_k:e_k 是第 k 块的局部动作段；ℐk 是本块的结构化视觉输入——由源图 x0、一张成对的帧网格总览、以及从 VA、VB 中与 as_k:e_k 对应的解码帧块做成的动作级比较面板组成（Sec. 3.1, Fig. 1）。

PER CHUNK · ACTION

动作偏好来自块内逐动作比较

对块内每个动作，判断两段视频的局部场景转变是否遵循了指令的相机 / 动作方向，再把动作级决策汇总成本块的动作胜者（Sec. 3.3）。

PER CHUNK · VISUAL

视觉偏好来自三项联合考虑

时间一致性（跨帧稳定）、动态生成质量（观察到的运动是否像合理的相机条件 3D 动态）、伪影 / 结构完整性（伪影、结构退化、源场景保持）。

这两个块级偏好最后跨 K 块聚合成全局动作偏好与全局视觉偏好（Sec. 3.3 的 Eq. 3，见 §06）。注意 Eq. 1 写的是概率 pθ，但 WorldReward 实际输出的是类别（A / B / Tie），并没有校准的概率分数——RL 里用的是成对胜率（§09）。

03Action-Video Chunk Construction

动作—视频分块：前置 IDLE，四槽一块，帧按动作段对齐

Sec. 3.2 先列出「整段直接喂 VLM」的三个困难：上下文太长（两段视频的很多帧）、一次跟踪全部动作让「局部动作 ↔ 验证它的视觉证据」关联变弱、局部运动错误或伪影被整体印象稀释而难以归因。 解法是把动作轨迹切成 K 个时间有序的块，每块含一小段连续动作和两个候选视频对应的解码帧块。

为什么要前置一个 IDLE 槽？论文说它「与源帧 x0 关联」（Sec. 3.2）。从代码看，IDLE 槽的面板比较的是两段视频各自的第 0 帧——对图生视频而言这通常就是源图本身， 于是 Chunk 0 得到一个天然的锚点：VLM 能先确认两段视频都从同一个场景出发，再看后面三个动作。代价是 Chunk 0 只覆盖 3 个真实动作，而且 IDLE 槽的「动作胜者」几乎总是 Tie。

为什么是四个动作？论文没有做块大小的消融。可以从两端理解：块太小则每次调用看不到跨动作的时间趋势（帧网格失去意义），块太大则动作面板数增加、回到「长上下文」的老问题。四槽让帧网格恰好是 1 + 4×3 = 13 列， 与 Fig. 1 的版式一致；训练轨迹 11 步恰好切成 3 整块，Bench 的 23 步恰好 6 整块——两个库的步数显然是按 4 槽反推设计的。

04Structured Visual Evidence

六图证据，以及每种相机动作留下的「视觉指纹」

论文对块级输入的设计动机是一句话：相机动作会留下方向特定的证据——前进时可见内容逐渐放大；上仰时已有内容向下移、新内容从顶部进入。 这种证据最适合用「动作前后几帧的对比」来核对，于是每块的输入被做成六张图外加文本。

4.1动作的视觉指纹：旧内容往哪走，新内容从哪边进

这是全文最值得记住的一个设计细节，来自开源代码的 prompt（actions.py 的 COMPONENT_EXPECTATION）：对每个指令分量，prompt 都用两个锚点描述预期——已有内容会往哪个边移动（并可能从那边退出），新内容会从哪个边进入。 论文说这种双锚点「让没有天空 / 地面的场景也能判断俯仰方向」：室内特写没有地平线可参考，但「新东西从顶边进、旧东西从底边出」依然成立。下面的模拟器把八个原子动作的指纹画出来。

◇ 我的解读：为什么这套输入能让 9B 模型赢过 GPT-5.5

论文自己的归因是数据精修（§07、Tab. 5），但输入组织同样关键：六张图里，帧网格回答「这一块的整体走势」（时间一致性、动态强弱），动作面板回答「这个动作的首→末到底变了什么」，源图回答「世界身份有没有换」。 Tab. 6 的消融恰好呈现这种分工：去帧网格伤运动与动作（−3.29 / −2.71），去面板主要伤动作（−2.82），去源图主要伤外观（−2.37）。 再加上 prompt 把每个分量的方向预期写成了可核对的两条锚点，模型要做的更像「对照清单逐项核对」而不是「看视频谈感受」。

05Chunk-Level Reward Reasoning

块级推理：VLM 到底要写出什么

每块一次生成，输出一个 JSON：action_control 里是四个动作的逐个比较与本块动作胜者，visual_quality 里是三个子维度的比较与本块视觉胜者。 每个比较都要先分别写 A 的分析、B 的分析，再给胜者——这个「先各自分析、再比较」的层次不是修辞，Tab. 6 的消融显示它值 +2.39 个点。

这里有一个论文正文与代码之间的小出入：Sec. 3.3 写「每个胜者 rkact, rkvis 属于 {A, B, Tie}」，但开源 prompt 明确要求两个 overall_winner 只能是 A 或 B（「若三个子维度全平，也要按更小但具体的优势选出 A 或 B」）。 因此 Eq. 3 里「Tie 的块不投票」这一分支在实际运行中几乎不会触发——Fig. 1 示例的票数 4:2:0 与 6:0:0 里 Tie 都是 0，与此一致。全局 Tie 只会由票数相等产生。

5.2prompt 里值得记住的规则

ACTION CONTROL · 11 条规则中的要点

  • 逐动作独立评判，A / B 各赢几个很正常；用图 2 与图 3–6 判断运动，图 1 与本块首帧的差异不算动作失败（前面的块已经移动过相机）。
  • 模糊、有伪影的视频仍然可以动作正确——只看运动证据。
  • 复合动作必须逐分量写：平移一句、每个旋转子轴一句；只做对一个分量不算正确。
  • 「正确」= 每个指令分量方向都对 且 没有明显的未指令运动（纯旋转时的缩放、纯平移时的倾斜、纯俯仰时的横向漂移）。
  • 块级胜者要与逐动作结果一致：赢的动作多者通常胜；平局时看正确性、幅度与纯净度的细节。

VISUAL QUALITY · 10 条规则中的要点

  • 图 1 是全局的源场景参考；本块首帧不必逐像素等于图 1，但两段视频都应仍像「同一个世界」。
  • 源场景漂移的定义：场景类别翻转（室内↔室外、城市↔森林）、主体被替换、材质 / 颜色 / 语义的强烈不兼容变化、块首帧已像另一个世界且无法用相机运动解释——主要记在「伪影与结构」下。
  • 静止或近乎静止是「动态生成质量」的重罚项，但若另一段视频崩坏得厉害，静止的也不自动整体获胜。
  • 大量像素变化若来自扭曲、融化、幻觉重塑，不是好的动态。
  • 视觉胜者须尊重子维度证据：3:0 必须跟随，2:1 通常跟随，否则要在 summary 里明确说明覆盖理由。

06Local-to-Global Voting

投票聚合：只数 A 和 B，相等即 Tie

记第 k 块预测的动作胜者与视觉胜者为 rkact、rkvis， ncm = Σk 𝟙[rkm = c] 是偏向候选 c ∈ {A, B} 的块数。视频级偏好由投票决定：

(3) Rm = A,nAm > nBm B,nBm > nAm Tie,nAm = nBm ,　m ∈ {act, vis} 预测为 Tie 的块不偏向任何一方；A 与 B 票数相等则全局为 Tie。论文称之为 local-to-global 原则：先把决策落在时间局部的证据上，再把细粒度判断合成视频级奖励（Sec. 3.3）。

Bench 评测时需要三个维度（动作 / 外观 / 运动），而模型输出的是「动作 + 三个视觉子维度」。Sec. 4.1 给出映射：时间一致性与伪影 / 结构完整性决定外观，动态生成质量决定运动； 若两个外观子维度在一块内偏向不同的视频，该块的外观预测记 Tie，再按块投票。开源代码 aggregate.py 的实现略有不同：它把每块的两张外观票直接合并进同一个票池（每块 2 票），动作维度则在块级票数相等时再用「全部逐动作胜者」的多数破平。下面的模拟器按代码实现计算。

投票的两个效果，与一个代价

放大局部失败。一次明显的动作错误哪怕只在一块里，也会以整票的形式进入计数，而不是被 23 个动作的平均印象冲淡。

抑制单块主导。某一块特别糟（比如结尾崩坏）只能贡献一票；论文明说投票「防止一个特别强或特别弱的片段主导视频级偏好」。

代价是粒度。K = 6 时全局偏好只有 4:2、5:1 这类离散结果，「差多少」的信息被丢掉；RL 里通过成对胜率（§09）部分补回，但 Bench 上的一致率也只能是三分类准确率。

07Reasoning-Augmented Preference Data

数据管线：蒸馏一个前沿 VLM，再用另一个前沿 VLM 的 agent 去审它

7.2Agent 审计：为什么不用一次 API 调用做质检

论文的理由（Sec. 3.4）：基于 API 的 critic 通常一次收到一组固定图片，必须在一次响应里完成检查。而 agent harness 可以自适应地多轮调用读图工具：先看源图和帧网格，根据观察决定下一张要看的动作面板，需要交叉核对时回看之前的证据。 这让每次检查聚焦在有争议的块上，局部证据不会被无关的帧稀释。审计结果要么保留原判，要么返回一个把每处修改定位到（块，维度）的 diff——便于追溯，也便于后面的人工复核。

08Training & Inference

训练：普通的 SFT，目标是「解释证据并给出偏好」

没有 RL、没有特殊损失。WorldReward 就是在块级训练集 𝒟 = {(zi, si)} 上做多模态大模型的监督微调：输入是结构化的多模态 zi，目标 si 是那个含推理与偏好的 JSON。

(4) ℒSFT(θ) = − 1Σi=1M Li Σi=1M Σt=1Li log pθ(si,t | zi, si,<t) 教师强制下的标准自回归语言建模目标；损失只算在目标回复的 token 上，caption、局部动作序列与视觉输入只作条件。归一化用的是全部目标 token 总数（token 级平均，而非样本级平均）。

TRAINING · Sec. 4.1

  • 初始化：Qwen3.5-9B（Qwen3.5 是 2026-02 发布的原生多模态模型）
  • 3 个 epoch，全局 batch 128
  • 学习率 8×10−6，余弦调度，warm-up 比例 0.03
  • 开启序列打包（sequence packing）以减少 padding
  • 训练样本 124,942 个块（含互换增强）

INFERENCE · 开源代码 infer.py（论文未列）

  • vLLM，温度 0.0，每块最多 4,096 个输出 token，max_model_len 49,152
  • 每个 prompt 恰好 6 张图；长边超过 2,048 的图先缩到 2,048（JPEG q=92）
  • 发布权重 CodeGoat24/WorldReward-qwen35-9b；同仓库还提供了 Qwen3.5-9B 版的 UnifiedReward-Flex / -Think 作基线
  • 输出解析失败的块会被跳过并在下次运行重试；schema 校验要求 4 个动作条目、3 个视觉子维度、胜者取值合法

值得注意的是，论文没有报告推理成本。按代码的布局，帧网格一张图就是 2 行 × 13 格的宽图（200 dpi 保存），动作面板是 2×2 的大图；六张图进 Qwen3.5 的视觉编码器后，再加约 3,000 词的英文 prompt 与最多 4k 的输出， 一个块的调用远比「打一个分数」的判别式奖励模型重。RL 训练时（§09）作者用独立的 vLLM 集群来服务它——16 个训练 rank 配 16 个 reward 副本。

09World-Model Post-Training

作为 RL 奖励：成对胜率 → 组内标准化 → 最优概率 → DiffusionNFT

论文没有发明新的优化算法：它沿用 WorldCompass 的片段级 rollout + DiffusionNFT 框架和 Pref-GRPO 的成对胜率奖励形式，只把奖励换成 WorldReward 的两个偏好。 两个偏好仍是分开的优化信号（可显式加权），但来自同一个模型对同一份动作对齐证据的解释。

10WorldReward-Bench

WorldReward-Bench：760 对、三维独立、Tie 是显式标签

Benchmark 衡量的是「奖励模型多大程度上复现人类偏好」。每对的两段视频来自同一源图、caption 与轨迹，所以比较把生成条件固定住，只剩轨迹执行与生成内容的差异。生成条件相对训练集全部保留：未见过的图—caption 对，独立重建的 224 条 23 步轨迹库，每段 184 帧 @ 15 fps。

10.1标注协议

ACTION CONSISTENCY

动作一致性

场景变化多忠实地遵循了规定的相机 / 动作轨迹；标注者检查执行控制的方向与时间顺序。

APPEARANCE QUALITY

外观质量

视觉保真度、时间一致性、场景内容与结构的保持。

MOTION QUALITY

运动质量

生成动态的合理性与平滑度，包括不连续或不足的运动。

每对由三名标注者独立评判，模型身份全程隐藏，候选顺序逐对随机。标注前有一轮校准，示例覆盖常见的相机控制错误、外观退化、不合理运动与真正模糊的比较。 只有当一方在该准则下有清晰可观察的优势时才选 A 或 B，否则记 Tie；三个维度各自独立——外观更好不意味着动作更准，运动更大不意味着运动更合理。最终标签按维度取多数；无多数（含 A / B / Tie 三方分歧）的样本交由额外标注者在同一准则下复核。

(12) Accm = 1|ℬ| Σj∈ℬ 𝟙[ŷjm = yjm],　m ∈ {act, app, mot} 三分类偏好准确率，Tie 是显式标签：预测 A 而人类标 Tie 同样算错。这比「只在非平局样本上算二分类准确率」更严格，也要求模型学会何时不站队。

论文没有报告 Bench 里 A / B / Tie 三类标签的比例，也没有报告标注者间一致性（如 Fleiss' κ）——这两个数字会直接影响 Tab. 3 各方法数字的可比性，见 §12。

11.5定性观察（Fig. 4、5）

相对基座：HY-WorldPlay 1.5 对若干控制响应很弱，连续几步只有有限的视角变化，且随轨迹推进输出退化，后期帧出现涂抹区域与模糊的场景结构；后训练模型执行平移与旋转更明确，场景结构在整条轨迹上保持干净连贯。

相对 WorldCompass：WorldCompass 提升了相机控制准确率，但后期帧伴随明显的色偏与纹理一致性的逐渐丢失；作者猜测原因是其图像奖励逐帧独立打分，不直接评估颜色与纹理是否随时间保持。用动作对齐的视频证据评估视觉质量后，后训练模型在整条轨迹上外观更稳定，同时保留了动作跟随的提升——这正是「时间性视觉质量反馈」的价值所在。

12Limitations & My Reservations

局限，以及我读下来的保留意见

论文没有单独的 Limitations 一节（正文以 Conclusion 收尾），所以下面主要是我对照正文、开源代码与配置后的意见，按重要性排序。前两条是正文与代码之间的事实性出入，建议在引用这篇工作时向作者确认。

问题依据影响
1 · 发布的 RL 配置不是「只换奖励」 正文（Sec. 3.6、4.3）说 WorldReward-RL「用 WorldReward 的两个偏好取代异构的几何与图像奖励」「与 WorldCompass 只差奖励信号」。但仓库 train_grpo_16gpu.yaml 同时开启 action_reward_weight: 2.0（DAv3 几何动作奖励）、hpsv3_quality_drift_reward_weight: 1.0、vlm_action 2.0、vlm_vq 1.0。 若实际训练用的是这套混合权重，Tab. 4 衡量的就是「WorldCompass 奖励 + WorldReward 奖励」而非替换；Tab. 9 的「仅动作 / 仅视觉」也需要重新解释。也可能发布配置只是从 WorldCompass 继承的模板——需要作者澄清。
2 · 块级 Tie 被 prompt 禁止 Eq. 3 与 Sec. 3.3 说块级胜者 ∈ {A, B, Tie}，开源 prompt 要求两个 overall_winner 只能是 A / B，「三个子维度全平也要选一个」。 近乎相同的两段视频也会被强制分出胜负，全局 Tie 只能靠票数恰好相等；RL 里对相近候选会引入随机方向的胜率噪声。Bench 三分类里模型「何时该说 Tie」的能力其实来自投票的偶然性。
3 · 「整段直接喂 VLM 更差」没有实验 Tab. 5 第一行「Gemini 3.1 Pro (direct judge)」的数字与 Tab. 3 的 Gemini 行完全相同，而蒸馏用的是块级协议——闭源基线很可能也是用六图块级输入评的。全文没有「全帧 + 全动作序列一次评判」的对照。 引言里对整段评判的批评（稀疏采样漏转变、稠密采样撑上下文、局部失败被稀释）是论证而非实验结论；Tab. 3 证明的是「训练 + 精修的 9B 优于零样本前沿 VLM」，不是「分块优于整段」。块大小（4）与每动作取帧数（3）也没有消融。
4 · 模型从未看过视频 每个动作只取首 / 中 / 末三帧（面板只有首 / 末），一个动作 8 帧里有 5 帧不进模型；帧网格里 IDLE 槽三张相同。 「时间一致性」「闪烁」「运动平滑」都是从关键帧差异推断的；8 帧内的高频闪烁或短暂跳变不可见。论文批评图像奖励「看不见闪烁」，这条批评部分也适用于它自己——它能看到的是关键帧之间的漂移。
5 · Bench 的标签统计缺失 未报告 A / B / Tie 的比例、标注者间一致性、复核比例。 三分类准确率对 Tie 占比极敏感：Tie 多则「保守」策略占优，Tie 少则「总选一边」占优。没有这两个数字，77.63 是「高」还是「一般」缺少参照——比如人类三人之间的一致率是多少？
6 · 老师、审计者、基线是同两个模型 Gemini 3.1 Pro 出标注，GPT-5.5 审标注，两者又是 Tab. 3 的主要对手；GPT-5.5 还是 Fig. 6 / Tab. 10 的外部评判者之一。 「超过老师」成立，但外部评判与训练监督相关；真正独立的只有人类评测（Fig. 6 人类列与 Tab. 10 的人类判断），幸好这部分结论一致。
7 · 未见生成器的泛化没有单独报告 Bench 的 9 个模型里只有 GameCrafter2（9.3%）不在训练池；训练与 Bench 的图—caption 都来自 WorldPlay 的分布。 「不同生成器的失败模式」是 Bench 的设计轴之一，但没有按来源模型分解的结果；对全新架构（例如非 I2V 的世界模型）的泛化未知。
8 · 小子集不要过度解读 艺术风格 ≈ 61 对（1 对 ≈ 1.6 点），Diag_View ≈ 24 对。 Tab. 3 艺术列里 GPT-5.5 运动 77.05 vs WorldReward 65.57 的 11 点差距，也只是约 7 对样本；反过来 WorldReward 在艺术上外观领先也同样脆弱。
9 · 成本没有报告 每对视频 K 次调用，每次 6 张大图 + 约 3k token prompt + 最多 4k 输出；RL 里 G = 12 → 每个 rollout 组每个片段 66 次调用；README 用 16 张 GPU 专门服务奖励。 相比 DAv3 + HPSv3，奖励侧算力可能上升一个数量级；论文没给延迟、吞吐或训练总 GPU 时。作为「更好的奖励」它站得住，作为「可替代的奖励」还缺一张账单。
10 · 动作空间是离散的方向 token 8 个平移 + 4 个旋转原子及其对角组合，每步等长（8 帧）；prompt 对幅度只有「可见但不夸张」的定性要求。 连续相机位姿（CameraCtrl 类）、可变速度、物体交互都不在范围内；Loop_Return 这类「回到起点」的一致性也只能靠块内证据间接反映——回访一致性并没有专门的检查。
11 · 未给出的超参 λ、Z、β、G、EMA 系数在正文中缺失；仓库配置给了 G = 12、adv_clip_max 2.0 等，但与 λ / Z 的对应关系不明。 Tab. 4 / 9 的复现依赖仓库默认值；若第 1 条的混合权重成立，则「λ 平衡两个偏好」的描述也需重新对应到四个权重。
○ 尽管如此，我认为值得记住的贡献

把「动作有没有执行」变成了可核对的清单。双锚点的方向预期（旧内容往哪走、新内容从哪进）、逐分量的纯净度检查、以及「动作侧禁止质量词、视觉侧忽略动作对错」的分工，让 VLM 评判从「谈感受」变成了「对照核对」。这套 prompt 本身就值得被别的相机控制工作直接借用。

数据精修的归因做得干净。Tab. 5 把「蒸馏不涨、agent 审计涨 7 点、人工再涨 1.4 点」拆得很清楚，并且用 Tab. 1 说明了修订发生在哪些粒度。这是近期 VLM-as-judge 工作里少见的诚实拆解。

Bench 的三维独立标注是有用的公共资产。760 对、9 个生成器、同条件配对、显式 Tie，加上代码、权重、数据全部公开——对于「相机控制世界模型该怎么评」这个问题，它给了一个比 DAv3 轨迹误差更接近人类判断的标尺。

13In Context

放回 Awesome-Interactive-Video-World-Models 的坐标系里

这不是一个世界模型，而是评世界模型的模型加一个人工标注 benchmark，外加一条把它当 RL 奖励的应用线。按仓库的分区，它应放进 benchmarks；它的奖励模型部分同时是 control 区「control-fidelity analysis」的直接材料。

严格标准WorldReward 的情况判断
1. 逐步动作条件不适用于奖励模型本身；它消费逐步动作（每块 4 个动作标签）来评判视频。被它后训练的 HY-WorldPlay 1.5 是逐步动作条件的系统。不适用
2. 因果 / 流式生成不生成视频。RL 部分沿用 WorldCompass 的片段级 rollout（因果 AR 基座）。不适用
3. 持久世界状态不适用。评判维度里「源场景漂移」与 Loop_Return 轨迹间接考察了世界的持久性。不适用

C术语

相机条件世界模型
以源图 + caption + 相机 / 动作轨迹为条件生成交互视频的模型；本文的动作是离散的方向 token（平移 8 种、旋转 4 种及组合），每步等长。
动作—视频块（chunk）
4 个连续动作槽 + 两段视频对应的解码帧块；前置 IDLE 槽，末块 PAD 补齐；每块渲染成 6 张图交给 VLM。
帧网格总览（frame grid）
2 行（A / B）× 13 列（参考帧 + 4 动作 × 首 / 中 / 末）的一张图，列边框按槽位着色；用于看块内的时间趋势。
动作面板（action panel）
每个动作一张 2×2 图（行 A / B，列首 / 末），用于核对该动作引起的局部转变。
双锚点预期
prompt 对每个指令分量写明「已有内容往哪个边移动」与「新内容从哪个边进入」；使无天空 / 地面的场景也能判断俯仰方向。
运动纯净度（motion purity）
未被指令的轴不得出现运动：纯旋转时不许缩放，纯平移时不许倾斜，纯俯仰时不许横向漂移；违反者在逐动作比较中被扣分。
源场景漂移（source-scene drift）
世界身份发生不兼容的变化：场景类别翻转、主体被替换、材质 / 颜色 / 语义强变、块首帧已像另一个世界且无法用相机运动解释。因相机移动而与源图不同不算漂移。
三分类偏好准确率
Eq. 12：预测与人类多数标签在 {A, B, Tie} 上完全相同才计 1。
Agent harness QC
Algorithm 1：GPT-5.5 多轮调用读图工具、维护检查历史 ℋ，对 Gemini 的块级判决要么保留、要么输出定位到（块，维度）的 diff。
成对胜率奖励
Pref-GRPO 形式：候选对其余 G−1 个候选的胜 1 / 平 ½ / 负 0 平均；本文对动作与视觉各算一个。
DiffusionNFT
负样本感知的流匹配 RL：用最优概率 pi 加权正 / 负两个隐式速度场的回归损失（Eq. 10–11）；本文沿用 WorldCompass 的片段级实现。
片段级 rollout
每次迭代只为一个目标片段 n 采 G 个候选，共享同一个自回归前缀；奖励模型的块与目标片段时间对齐。
WorldCompass
Wang et al. 2026（2602.09022）：长时程世界模型的 RL 后训练框架，奖励 = DepthAnything3 几何动作奖励 + HPSv3 图像奖励；本文的直接前作与主要对照。
HY-WorldPlay 1.5
WorldPlay（2512.14614）的实时交互世界模型，基于 HunyuanVideo-1.5 的因果动作条件模型；本文的 RL 基座。
