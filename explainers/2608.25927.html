一句话

视频世界模型是从结果里学机制——每一帧游戏画面都是执行一段代码渲染出来的，但那段代码在渲染完就被丢掉了，模型只能从稀疏的视觉后果里反推它。这篇论文的回答是：别再反推了，把代码本身放回环里。让 coding agent 用可执行、可修改的代码维护世界状态，视频模型只负责把状态画出来。

两端之间需要一个接口。论文给出的答案叫 proxy：一个由 agent 程序化构造的粗糙几何表示，被一个确定性编译器渲染成低分辨率的 proxy video，逐帧给视频模型下时空约束；结构化文本负责说清外观、身份和动作语义。两条通道都源自同一份世界状态。

01 · 一图看懂

状态存在哪，决定了世界能不能长期自洽§

论文开篇用的例子值得原样搬过来：玩家刺杀了一座城的统治者，然后离开。这件事应当继续影响继位、治安、贸易、派系关系，以及大量 NPC 的信念、目标和行为；这些后果会在城市不在画面里的时候继续发展，和后来的事件互相纠缠，等玩家很久以后回来才第一次被看见。

一个系统要处理这个场景，需要回答的不只是「玩家回来时这座城该长什么样」，还有：玩家不在的这段时间发生了什么、为什么发生、哪些后果还在生效、当前局面会如何塑造之后的演化。下面这张图把两种架构放在同一个事件上对照，用上面的按钮推进世界时间。

这篇论文真正的主张

不是「视频模型不够好」，而是让视频模型同时承担世界演化和视觉实现，是一次功能上的错配。世界演化需要的是知识、关系推理、长程规划和后果传播；视觉实现需要的是外观、运动和交互先验。这两组能力已经分别在文本/代码和视频两种数据上被大规模训练出来了，论文的做法就是让它们各自回到自己擅长的那一半。

02 · 问题设定

视频只记录结果，不记录机制§

这是全文的地基，值得逐句拆：「每一帧都是执行固定的游戏代码渲染出来的，但产生这一帧的可执行逻辑在渲染之后就被丢弃了，只能通过它稀疏的视觉后果被间接观察到。」

换句话说，游戏录像是一条有损信道：上游有一份完整的、结构化的、因果闭合的世界状态和一套规则，下游只留下一串 RGB 像素。视频世界模型的训练任务，本质上是从信道下游反演上游。论文指出这件事有三重结构性障碍，而它们都不是「多喂数据」能解决的：

  1. 后果稀疏。规则只在被触发时才在画面上留下痕迹，绝大多数时刻的规则是不可见的。
  2. 离屏无记录。大量状态变化发生在画面之外——论文的原话是「off-screen character states have no continuous visual record」。这部分连稀疏证据都没有。
  3. 时间尺度不匹配。当前视频模型的训练上下文窗口通常不到一分钟，而许多需要推理的因果过程在世界时间里要展开数天甚至数年。

论文由此下了一个相当强的判断：把规模继续做大，得到的是更多被观察到的结果，而不是关于机制的直接证据（“more observed outcomes but no direct evidence of the underlying mechanisms”）。学习过程因此「高度低效，并且最终是次优的」。

「Videos record the observable outcomes of world dynamics, whereas the world knowledge, commonsense rules, inter-entity relations, long-horizon plans, and mechanisms of consequence propagation that produce these outcomes are not directly observable.」 §1 Introduction

03 · 分工

稀疏而复杂的推理，和稠密而重复的执行§

论文把「运行一个复杂世界」拆成两类完全不同的负载，这个拆法是整个框架的支点。

① 稀疏但语义复杂的推理

解释新事件、把它接到世界知识／人物关系／社会结构上、判断哪些实体和机制受影响、在长时段上规划后果。

频率低，但每一次都要求很强的推理。→ coding agent

② 稠密而重复的执行

维护位置、属性、日程、冷却、碰撞和数值规则，把高层决策翻译成具体的状态更新。

频率必须显著高于前者，但每一步都简单、确定、可复用。→ code

论文对第二类给了一个很实的理由：语言模型可以为每一次低层更新都被调用一次，但这既不经济也不可靠——「Invoking a language model for every low-level interaction is feasible but computationally inefficient; moreover, critical outcomes often need to be rule-consistent and reproducible」。攻击是否命中，应当由当前世界状态（距离、攻击范围）决定；没有稳定规则，玩家就无法对自己的行为形成可靠预期。

于是有了这句定义性的话：代码既不是被开发者冻结的游戏逻辑，也不是独立于 agent 的控制器，而是 coding agent 持续维护的、可执行且可修改的延伸（“Code is therefore neither permanently frozen game logic nor a controller independent of the agent; it is the coding agent's continuously maintained, executable, and modifiable extension.”）。

agent–code 回路：一次介入的完整形状

论文把这个持续回路写得很具体，四步一循环：

① 情境改变

一次交互或世界事件先改变当前局面。

② agent 读状态并决策

读取被维护的世界状态，选择调用已有代码，或者局部修改世界程序。

③ code 执行

运行可复用机制，一次推进大量状态变量。绝大多数重复更新不需要任何额外的模型调用。

④ 反馈回流

执行结果、测试、以及新的世界反馈回到 agent，成为它下一次决策的证据。

回到刺杀城主的例子：agent 决定这座城进入紧急状态之后，它可以改变派系目标、激活已有的行为规则，或者新增巡逻、继位、消息传播等机制。此后它只需要决定每个角色的高层行为，并在目标改变、出现异常、或机制需要修订时介入；其余时间由代码按既有规则高频更新位置、朝向和其他运行时状态。

这里有一个容易被跳过的词：测试

论文在描述回流时明确写了 “execution results, tests, and new world feedback return to the coding agent as evidence”。也就是说，世界程序是可以被验证的——这是把状态放进代码相对于放进权重的一个额外收益：机制可检查、可测试、可回归。论文本身没有实现或评测这条测试回路，但它在论证里是被算进去的。

04 · 形式化

把 S 拆成可执行态与视觉态§

论文的形式化只有四个式子，但拆法本身就是主张。先看常规世界模型的写法：

最容易被误读的一句

式 (4) 把 Sexet+1 写成 Gθ 的输入，只表达一种抽象的条件依赖，不意味着把原始代码或完整可执行状态直接喂进网络（论文原话：“it does not mean that raw code or the complete executable state is passed directly to the network”）。怎么从 Sexe 里选出相关信息、并把它表示成视频模型能用的条件，正是 §3.2 要解决的问题，也是 proxy 存在的全部理由。

视觉一致性被存去了哪里

还有一句很关键、但混在段落里容易滑过去：「必须持久的视觉信息被保留在世界状态中，由 coding agent 管理，并在相关角色、地点或事件再次出现时重新提供。」

这句话把「长期身份一致性」从一个模型记忆问题改写成了一个状态管理问题。视频模型不需要记住十分钟前那个 NPC 长什么样——那份描述本来就写在 Sexe 的身份记录里，等他再出场时由 agent 重新塞进 prompt。这与用检索历史帧、持久视角表示、surfel 索引等做法来「补记忆」的那条线（论文引的 [32,38,39,40,41]）是两种完全不同的解法。

05 · 接口问题

状态 → 条件：为什么纯文本一个人扛不住§

世界状态在代码里跑得好好的，视频模型该怎么知道它？这是全篇最有工程含量的一节。论文先认真地把最优雅的方案摆出来，再说明自己为什么放弃了它。

方案一：把状态序列化成结构化文本

做法完全可行且自洽：agent 为每个持久身份写下外观、角色、目标的语义描述，存进由代码管理的身份记录；世界运行时，代码持续更新实体的位置、朝向、关系、行为和战斗状态；系统按身份、时间、事件自动组织这些持久描述与运行时变量，与 agent 当前的高层意图和原始文本 prompt 合并，交给视频模型。

论文自己的评价是：「这是最简单、最优雅、看起来也最可扩展的选择」——不引入新的条件模态，天然容纳新的物体、属性和规则。

然后是那句否定

「我们在大规模训练的近期视频世界模型 [31] 上的实验表明，文本条件即便配上专门的相机条件通路，仍然无法对相机轨迹和实体运动提供精确控制。」

论文紧接着做了一次很克制的界定：这不意味着语言无法表达精确状态——给足够长的描述，语言理论上可以指定每一帧的每一个像素。问题是三条现实约束：token 效率极低、撑不住实时交互的延迟要求、当前视频模型也无法可靠遵循这种复杂度的指令。

注：[31] 是 Infinite worlds with versatile interactions（arXiv 2607.07534），即论文相关工作里描述的 LingBot-World 2.0——一个用 pilot / director agent 增强因果视频生成器、支持语义动作与 rollout 中途干预的系统。也就是说，这个否定性结论来自与本文思路最接近的一条基线。

方案二：让 agent 直接搭一个显式 3D 世界

这条路（论文引 HunyuanWorld 1.0 [75]、WorldGen [76]）能给出更强的空间控制，但论文列了三条代价：

  • 需要生产级的几何、资产、动画、材质和渲染系统，成本高；
  • 过早锁死最终的视觉实现（“prematurely constrains the final visual realization”）；
  • 更根本的是，这条路的上限由资产与模拟器的保真度和覆盖度决定——开放世界会不断引入未被现有管线预料的新角色、物体、行为和情境，每一个都要配上新的资产、动作和物理响应。

而视频模型这条路的成本是另一种：每一帧新观测都要跑一次生成推理，边际计算和延迟都高于常规渲染。论文对此的态度很直白——为了视觉保真度和开放式生成的目标，认为这个质量收益值这个代价，并且预期视频推理会越来越便宜。

06 · 核心设计

Proxy：把世界状态先摆进画面坐标，再交给视频模型§

既然目标输出本身是视频，那就用同一种时空模态来表达控制。这样的条件可以直接在图像坐标里指定相机运动、实体位置、遮挡、相对关系和轨迹；视频模型读到的控制信息，其时空组织方式已经是它熟悉的那种。

论文对 proxy 的定义是：把影响当前观测的相机、实体位置、姿态、轨迹和空间关系组织成一个粗糙的、可编程的世界表示；再由一个确定性的渲染过程把它变成时空视觉条件，即 proxy video。

proxy 不是什么

它不试图尽可能完整地表示目标世界，只保留当前观测必须遵守的粗结构与交互状态；它不表达纹理、材质、精细光照等应当由视频模型生成的外观信息。论文写得很清楚：「它的目标不是提供一段低质量的目标视频，而是用最简单可用的形式表达所需的状态与时空关系。」

白盒是硬性要求，不是附赠品

论文在这里下了一条相当克制、但含义很重的限制：这个视觉条件里的信息应当完全来自 coding agent 与代码共同构造并执行的世界状态，不应由另一个信息源或生成模型（例如一个学出来的 3D 生成器）来补充。理由只有一句：那会引入一段 agent 无法直接检查或控制的映射。

于是 proxy 的性质被钉死为四个词：可构造、可检查、可寻址、可局部编辑（constructible, inspectable, addressable, locally editable），而不是「一个学出来的 3D 生成器给出的不透明视觉提案」。从状态到条件的整条路径对 agent 保持白盒——每一个控制信号都能追溯回世界状态。

proxy 通道说什么

相机运动、实体位置与朝向、近似尺度、场景布局、轨迹、遮挡、交互关键状态。逐帧、在图像坐标里、可调。

文本通道说什么

角色与物体的外观与身份、动作语义，以及 proxy 未指定的动态细节。两者来自同一份世界状态，只是表示方式不同。

构造成本被刻意压到很低

agent 不需要建模：它程序化地调用并组合一组给定的、简单可复用的基元，每个基元只用几行代码就能表达，因此「几乎不增加 agent 的表示负担」。可寻址的参数指定实体位置、尺度、姿态、布局、相机和状态标记，再由一个简单的确定性编译器做轻量光栅化——不需要生产级资产、复杂材质、光照、精细动画或昂贵渲染。

token 成本：这一节最好核对的一个数

proxy 在每个空间维度上取目标视频分辨率的 1/4（336×192 对 1344×768），因此像素数是 1/16，给 omni transformer 增加的视觉 token 也只有目标视频的 1/16。论文据此判断「额外推理负担可以忽略」。这个换算本身是对的；不过 1/16 是相对于目标视频那一份 token而言，不是相对于模型总输入——文本、系统指令与参考图分支不在这个比例里。

07 · 权衡

Condition bandwidth：可构造性与约束强度§

论文说，proxy 设计的核心选择就是它的条件带宽。这句话背后是一条并不显然的约束链——proxy 越丰富，grounding 越强，但要求 agent 在推理时构造和维护的基元与参数也越多。

论文给的例子极其具体：如果 proxy 在关节级别编码角色的铰接运动，那么 agent 在推理时也必须控制这个角色的关节轨迹；而当前的 coding agent「仍然难以可靠实现这种关节级运动控制」，这会反过来限制最终性能。反过来，信息太少的 proxy 构造轻松，但可能无法施加足够的时空约束。

所以论文把 proxy 设计形式化成一个权衡：在「可构造性」和「grounding 强度」之间，取当前观测必须遵守的最小充分状态，把最终外观和精细动态留给视频模型。

一个漂亮的闭环：训练数据的表示上限，由推理时的可构造性倒推

这条设计约束藏在 Fig. 3 的图注里，但它其实是全篇最见功力的一处：

「Note that, to ensure that the coding agent can easily reproduce the proxy at inference time, we exclude skeletal pose, detailed 3D models, and other representations that are difficult for coding agents to construct and maintain.」 Fig. 3 caption

也就是说，训练数据里刻意不放骨骼姿态和精细 3D 模型——不是因为拿不到（游戏运行时当然有），而是因为推理时 agent 造不出来。如果训练时用了 agent 在推理时无法复现的通道，模型学到的将是一个推理阶段永远无法满足的条件分布。

proxy 是视觉版的 prompt，不是全局固定的条件

论文特意澄清了一个可能的误解：proxy 不应被理解为一个全局固定的条件，它是 coding agent 用来控制视频模型的视觉提示工具，是文本 prompt 的视觉对应物。在一个完整的 Code World Model 里，是 agent 自己根据当前世界和生成任务决定：

  • 文本足够时，不用 proxy；
  • 观测必须紧跟位置、轨迹、空间关系或交互拓扑时，启用相关的 proxy；
  • 进一步挑选交互关键的实体和区域，并调整所表示的状态类型、空间粒度、分辨率和条件帧率。
但这一段是设计空间，不是本文的实现

论文自己划了界：「本文实例化并评测的是一个固定的 proxy 设计；自主切换与带宽调节仍属于这个更大范式的设计空间。」读这一节时要把「agent 可以自主决定启用/关闭/调粒度」当成路线图，而不是已经跑通的能力。

还有一个反直觉的推论

论文指出，即使把语言模型和视频模型统一成一个全模态网络，这个「状态 → 条件」的问题也不会消失：由代码维护的、持续变化的外部世界状态，仍然必须被编码并供给视觉生成过程。参数共享只是简化了组件间的通信，并没有取消表示问题。

08 · 数据（一）

游戏对：从同一次执行里同步录出来§

要训练视频模型「跟随 proxy」，就需要时空严格对齐的 proxy–目标视频对。游戏是最合适的来源，理由只有一句话：目标视频和它对应的运行时状态，可以从同一次执行里同步获得。

而且因为动作后果和相机运动已经被表示在 proxy video 里，这个接口既不需要单独的动作标签，也不需要显式的相机位姿标注——这一点在下一节处理真实视频时会变成决定性优势。

三个值得单独拎出来的设计

① 可重编译

同一份运行时记录可以被重新编译成覆盖度与信息粒度不同的 proxy，而不需要重新采集目标视频。换句话说，proxy 的表示实验可以在零采集成本下迭代——这在视频数据集里是相当奢侈的性质。

② 基元词表不必统一

论文发现当代视频模型能够学会「不同形状、粒度、视觉风格的粗基元」与目标视觉物体之间的对应。所以基元词表不需要在全部数据上固定成一套。

③ 像素级实例图把文本绑到区域上

运行时记录还提供精确的身份对应：proxy video 的每一帧都有一张像素级的 ground-truth instance map，标出每个像素属于哪个身份。它把结构化文本里每个身份的外观、属性、动作描述绑定到对应的 proxy 区域，得到更精确的条件。

退化路径：bounding box

对于用简单基元无法保持足够可区分性的复杂物体，proxy 可以只用一个包围盒传达位置与粗略范围，身份和属性交给结构化文本。这条退路让 agent 不必去重建复杂几何，同时仍然告诉视频模型「那个位置上有这么个东西」。

论文还报告了一个关于 agent 自主性的观察：对于人、树、车辆、灌木、普通建筑这类常见类别，agent 能够自主地为每个身份分类并组合出对应的基元；对于结构复杂或不常见的物体，它先判断简单基元是否还能保持可区分性，不能就退回包围盒。这是全篇少数几处直接描述 agent 行为的实证观察之一。

09 · 数据（二）

真实视频：用几何代替动作标签§

这一节的论证比它的篇幅更重要。对依赖单独动作或相机条件的方法（论文引 [26,34,37]）来说，把真实视频变成训练数据通常需要动作标签或相机轨迹——而真实世界视频里的「动作」可以在不同语义粒度上定义，标注天然歧义；连续相机运动也难以估计和标注。

proxy 接口只需要三样东西：目标视频、对应的 proxy video、结构化 prompt。动作和相机运动的视觉效果直接被表示在 proxy video 里，而不是被定义成独立的标签。标注负担因此被大幅降低。

为什么非要真实视频不可

论文给的理由不是「规模」，而是天花板：真实视频提供游戏的资产、动画、模拟和渲染管线无法完全覆盖的高保真外观、运动和物理交互。这对具身智能体尤其重要——它们的任务需要关于尺度、遮挡、接触、相机自运动，以及动作引起的运动与物理响应的线索。真实数据能让生成的视觉环境更接近智能体的部署分布，使 CWM 不只服务虚拟世界生成，也能作为可扩展的真实世界视觉环境用于训练和评测。

读这一节时请把它当作 proof of concept

论文的措辞是 “we build a geometry-assisted proof of concept on KITTI-360”，目的是「验证 proxy–观测对可以从真实录像构造出来」。本文的视频模型并没有在这批真实数据上训练——微调只用了游戏对。真实这一路目前只有构造，没有训练结果。

一个容易被漏掉的通道差异

游戏那一路的 proxy 是「fixed-log 深度 + 类别语义 ID 图」（§4.1 实现细节）；真实那一路除了投影得到的 metric depth，还额外算了由深度导出的表面法向，并且论文用的是复数 “across all conditions”。两路的通道构成并不完全相同——在读 Fig. 3 的两张子图时值得留意这一点。

Coding agent 在推理时到底做了什么

这一段的诚实程度值得赞赏。论文明确写：「从零构建 AAA 规模的场景与复杂交互逻辑，对当前的 coding agent 来说仍然困难。」它们的做法是给 agent 现成的脚手架：

  • 现成的游戏引擎代码——基础的玩家控制、碰撞处理、运行时更新循环；
  • 与构造训练数据时完全相同的那套 proxy 基元；
  • 现成的 AAA 游戏场景与玩法逻辑作为模板，由 agent 组合、扩展、重写，构造出目标世界。

结果是一个可执行、可玩家操控的世界，其中与视觉相关的状态用粗糙的 proxy 几何表示，而不是精细 3D 资产。然后：在用户操控下运行这个世界、录下 proxy video、把这段序列作为逐帧条件交给下游视频模型。

这句话决定了如何解读 Fig. 2 的那个闭环

「录下 proxy video，然后把它交给视频模型」意味着本文的原型是离线的两段式：先跑世界录 proxy，再离线生成视频。Fig. 2 里从 Visual World 回到 Interaction 的那条反馈边，以及视频观测反过来影响 agent 决策的路径，在这个原型里没有闭合。论文自己在局限里也承认「没有实现自回归实时生成」。把 Fig. 2 当作范式图读，不要当作系统图读。

11 · 长视频

124 帧窗口、34 帧重叠，以及那张一直被重复喂进去的锚图§

单次推理只能生成 124 帧（5.17 秒）。要拿到项目页上那种数十秒的连续片段，论文用的是重叠窗口 + 全局锚图的组合，而不是自回归。

这里有个值得警惕的依赖

论文的定性结果里，身份与视觉风格的一致性主要由 GPT Image 2 生成的那张外观锚图承担——它初始化第 0 个 latent 槽，同时进 multimodal encoder 和 Ref2VA 参考分支，并且在每一个后续窗口里被再次注入。也就是说，一个不属于本文框架的外部图像模型，在最终视觉结果里出力不小。这不影响「视频模型能跟随 proxy」这个结论（那由逐帧 proxy 保证），但在评估「视觉保真度」时应当把它计入。

另外，这套拼接是非因果、离线的：每个窗口都要完整生成 124 帧再丢掉 34 帧，重叠部分的算力是纯浪费（窗口数越多越趋近 34/124 ≈ 27%）。这与论文局限里说的「未实现自回归实时生成」是同一件事的两面。相关工作里那条做 self-forcing、causal distillation、streaming 的线（[42,50–55]）正是为了解决这个问题——本文没有走那条路，它把注意力放在了接口设计上。

12 · 附录

结构化文本长什么样§

附录 A 给了三个完整的 prompt 示例。它们很值得读——因为这才是「文本通道」在这套系统里的真实形态：不是一句话描述，而是一份带时间片的规格说明书。

schema 是固定的三段：

Appearance and scene

主角的稳定身份特征（论文原文反复用 “stable identity features” 这个词）、服饰材质、开场姿态与画面位置；场景布局、材质、光照、天气、色调、绘画风格；以及相机的完整运动描述。

Protagonist action timeline

按时间片切分的动作说明，覆盖 0.00–5.17 s。片段长度不均匀——静止段可以合并成 2.25 s，动作密集段切到 0.75 s。

Other visible actors

其他可见角色/物体在时间区间上的状态。「没有其他角色」也要显式写出来，而不是留空。

从 prompt 反推设计意图

这些 prompt 里几乎每一句都在做约束而不是描述：「both feet remaining outside the visible area」「the initial lower edge crops the figure at the lower shins」「maintaining level shoulders, a straight torso, softly bent elbows」。这正好印证了 §3.2 的分工——proxy 给的是粗几何与相机，文本必须补上 proxy 表达不了的那一层：裁切关系、肢体细节、材质、光照、以及「不要出现什么」。也解释了为什么关节级姿态被排除在 proxy 之外后，文本会变得这么长。

13 · 批判性阅读

它证明了什么，没证明什么§

论文自己的定位是「preliminary evidence for the viability of the framework's two key components」——为框架的两个关键组件提供初步证据。这个措辞相当精确，值得逐字对待：是两个组件各自可行，不是整个回路已经跑通。

论文自己列的两条局限

① 算力受限

训练规模因此很小，生成质量仍然有限；也没有实现自回归实时生成。

② coding agent 的能力上限

尽管进步很快，当前 coding agent 仍难以可靠地从零实现高度复杂的游戏机制。因此原型没有展示自主构建一个完整开放世界游戏或模拟器。

我在细读中额外注意到的几点

  1. 两个组件是分别验证的，不是端到端串起来验证的。agent 那半边的证据是「它能用现成引擎代码和 AAA 场景模板组合出一个可玩的世界」；视频那半边的证据是「LoRA 微调后能跟随录下来的 proxy」。中间没有一个实验展示agent 因为看到生成结果而改变了世界程序。
  2. 没有 proxy 遵循度的定量指标。这个接口最核心的经验主张是「视频模型会听 proxy 的话」，但论文没有报告任何位置误差、轨迹一致性、遮挡正确率之类的数字，只有定性帧序列和项目页视频。而且论文明说对比「不考虑推理延迟」，这对一个以交互世界为目标的系统是个不小的免责。
  3. 可构造性约束把铰接运动整段推给了文本。骨骼姿态被排除在 proxy 之外，意味着角色的具体肢体动作完全由文本 + 视频模型先验决定。附录 prompt 之所以要一秒一秒地写「肩膀保持水平、手肘微屈、手掌垂在腿侧」，正是在补这个洞。这是设计权衡的直接代价，也是最可能出现身份/动作漂移的地方。
  4. 外部图像模型承担了相当一部分视觉质量。见上一节关于 GPT Image 2 锚图的讨论。
  5. 真实数据这一路只有构造，没有训练。KITTI-360 上做的是离线编译的 proof of concept，微调数据全部来自游戏。「proxy 可以作为学习世界状态的接口」在真实域上仍是待验证的。
  6. 与最接近的基线的比较只在项目页上。与 [31,34,37] 的对比视频不在正文里，正文只给了「更精确、更灵敏」的定性判断。
这不妨碍它是一篇有分量的论文

它的贡献主要是问题的重新切分，而不是某个 SOTA 数字：把「世界怎么演化」从「世界长什么样」里干净地剥离出来，并且给出了一个具体到可实现的接口（proxy），还顺手说明了这个接口为什么让真实视频数据变得便宜（不需要动作标签和相机位姿）。这三件事里的任何一件单独拿出来都站得住。

14 · 定位

它在这条研究线上的位置§

论文的相关工作分三块，每一块的落点都很明确。

研究线它们把世界状态放在哪CWM 的差别
交互式视频世界模型
Genie 系列、Matrix-Game、WorldPlay、Context-as-Memory、VMem、LingBot-World 2.0 …		 视觉历史、隐上下文、视觉记忆。中心建模对象始终是生成的观测序列。 把显式世界状态交给 coding agent 和它的持久代码，包括那些必须继续影响后续交互的后果；视频模型仍负责外观与动态，但通过 proxy 接收相关状态，而不必内化整个演化过程。
生成式 3D 世界
HunyuanWorld 1.0 [75]、WorldGen [76] …		 生成的几何、资产与渲染管线就是视觉世界本身。 proxy 不是最终 3D 世界，也不规定生产级几何与外观；它只是一个粗糙的、程序化构造的条件。显式 3D 在这里是通往视觉生成的接口，而不是终点。
coding agent 与程序化世界模型
WorldCoder [67]、Dainese 等 [68]、Lehrach 等 [70]、ARC-AGI-3 [91] …		 把状态转移、合法动作、观测、奖励、终止写成程序函数，供 planner 使用。世界规则被外化成可检查、可测试、可修订的代码。 沿用「规则外化为代码」这一点，但把输出端从符号观测/planner换成了高保真视频；coding agent 治理的是一个开放视觉世界的演化，而不只是一个可规划的抽象环境。

顺便澄清一个同名问题

「Code World Model」这个名字在 2025–2026 年被至少三拨人用过，方向还不一样。读文献时很容易串：

本文 · arXiv 2608.25927

用代码去做世界模型。coding agent 当大脑，视频模型当渲染器。

Meta FAIR · CWM · arXiv 2510.02387

用世界模型去做代码。在 Python 执行轨迹和 agentic 交互上做 mid-training，让 LLM 学会模拟代码执行，以增强代码生成与推理。方向正好相反。

Lehrach 等 · arXiv 2510.04542

Code world models for general game playing：把状态转移、合法动作、观测、奖励、终止合成为程序函数供 planner 消费。本文引作 [70]。

速查

核心命题
世界演化（知识驱动、规则一致、可持久）与视觉实现（生成先验、开放外观）应当解耦，由代码和视频模型分别承担。
关键机制
proxy —— 由世界状态确定性编译出的粗糙时空视觉条件，逐帧约束视频模型；与结构化文本构成两条互补通道。
关键约束
condition bandwidth 是可构造性与 grounding 强度之间的权衡；训练通道的上限由推理时 agent 的可构造性倒推决定。
关键数字
124 帧 / 24 FPS / 5.17 s；proxy 336×192 = 目标 1/16 token；LoRA r128 × 50 blocks ≈ 596 M；3,534 步；长视频 124 帧窗口、34 帧重叠、步进 90 帧。
最强的一句
“Code is neither permanently frozen game logic nor a controller independent of the agent; it is the coding agent's continuously maintained, executable, and modifiable extension.”
最该保留怀疑的一句
关于 agent 自主启用/关闭/调节 proxy 带宽的那一段——论文明确说本文只实例化了一个固定的 proxy 设计。

如果要接着往下做

  • 把回路闭上。让生成的观测真正回流到 agent 的决策里（哪怕只是通过一个 VLM 读回关键状态做校验），是从「范式图」变成「系统」的最短一步。
  • 给 proxy 遵循度一个指标。用录制的运行时状态作为 ground truth，量测生成视频里实体位置、遮挡、相机轨迹的误差——数据管线本身就自带这份标注。
  • 验证「带宽自适应」。让 agent 在同一段序列里对不同实体使用不同粒度（关键实体用完整基元，背景退回 bbox 甚至关闭），这是论文画出来但没做的那部分设计空间。
  • 把真实那一路训起来。KITTI-360 的编译管线已经在了，缺的是在其上微调并验证跨域迁移。
