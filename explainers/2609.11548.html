World in World

与其给世界模型加一条新的控制支路，不如把每一种控制都伪装成它本来就会读的东西

一个因果视频世界模型在生成下一块画面时，其实只做一件事：读几张已经定稿的干净画面，外加它们的相机位姿和时间戳，然后往下猜。 这条通路就是它的原生自注意力。WiW 的赌注是：既然模型只认「带相机和时间标签的干净画面」这一种东西， 那就把所有想施加的控制都翻译成这种格式—— 源视频帧管事件同步、按深度 warp 到目标相机的投影管空间摆位、 3D 数字人渲染图管新露出表面的补全、存档的历史 K/V管回看时的记忆。 四件毫不相干的事，对模型来说长得一模一样。主干一个参数都不动。 代价也很直白：真正把指标扛起来的，是这四路里最朴素的那一路——而它并不新。

00One Figure

一图看懂：一条总线，四路证据，两个旋钮

全文可以压成一句话：凡是想让模型知道的事，都做成「一张图 + 它的相机 + 它的时刻 + 它哪块可信 + 它什么时候生效」， 然后从自注意力灌进去。点标签逐段看。

Ψb( Eb ; C, s )  =  ( Xb , Pb , ωb , γ(s)b ) Eq.1 X：证据的视觉内容，就是一张（或一段）RGB。　P：逐帧的相机内参、位姿、以及事件时间索引——告诉模型「这画面是哪个机位、哪一刻」。　 ωbj ∈ [0,1]：第 j 个证据 token 的空间可信度，0 就是完全不要信。　γ(s) ∈ {0,1}：这一路在第 s 个去噪步要不要参与。
四路证据（源视频 / 目标视投影 / 渲染几何 / 历史检索）共用这一个签名，这就是论文说的 shared interface。后面所有设计都是这一行的展开。
一句话抓住这篇的取舍

别的方法是「给模型加一条新的输入管道，然后训练它学会用」；这篇是「把新信息伪装成模型已经会读的老格式，一个参数都不训」。 好处是同一套接口同时装下了相机控制、事件同步、遮挡补全、长程记忆，还顺手做出 bullet time、视频稳定、视频编辑、跨实例 K/V 共享。 坏处是：能塞进去的，只有「能被画成一张图的东西」——凡是不能渲染成 RGB 的控制（物理量、规则、不可见状态），这个接口一概表达不了。

01Motivation

它在解什么问题：四个同时成立的要求

任务叫「相机可控的视频重渲染」：给一段已经拍好的动态视频，再给一条你自己指定的相机轨迹， 要求模型把同一个事件从新机位重新「拍」一遍。摘要里那句绕口的话，其实就是四个必须同时满足的要求。

要求 1 · 同步
事件不能跑偏
新画面里的人必须正在做源视频这一刻在做的动作。差半秒，这就不是重渲染而是重新生成了。
要求 2 · 摆位
东西得在对的位置
源视频只告诉你「长什么样」，没告诉你「换机位之后它该出现在画面哪里、谁挡住谁」。
要求 3 · 补全
新露出的面要编得像
相机绕到人侧面，源视频里根本没拍过那半边身子，只能靠生成先验补——但不能补出个第二个人。
要求 4 · 回看
转回来要认得出
三十秒后转回同一个角落，那里应该还是刚才生成的那个样子，而不是重新即兴一个。

这四条对应的现有解法各走各的路：相机控制有 Plücker / ray / 姿态编码那一派；源视频重渲染要额外训一个接收源视频的支路； 补全靠点云 / 网格 / 高斯这类显式表征；长程记忆靠外挂 memory bank。 每加一种控制，就得改一次结构或再训一次。这是论文要打的靶子。

WiW 的观察很简单，但确实是个好观察：因果视频世界模型早就有一条通用的视觉输入口了，只是没人把它当接口用。 自回归生成时，模型通过自注意力去读「初始观测 + 最近定稿的几帧」，这些东西在模型眼里是干净（无噪声）的视觉状态， 并且已经带着相机编码和时间编码。既然如此——任何外部控制，只要能被表达成「某机位、某时刻的一张干净画面」，就能原封不动地走这条口进去。

于是问题被重新定义了：扩展世界模型的可控性，不再是「改模型」，而是「造证据 + 定位证据 + 调节证据」这三件工程活。 这是本文最值得记住的那一句话。

我的看法：这个 reframing 站得住，但它的边界被论文含糊过去了

「把控制翻译成模型已有的输入格式」是很漂亮的思路，而且确实能一套接口装下四种控制。 但它有一条硬边界：接口的表达力 = 能被渲染成 RGB 的东西。 相机、姿态、遮挡、外观，这些都能画出来，所以都能表达；而「这扇门锁着」「这个人中毒了」「这条规则生效」这类非视觉状态， 这个接口一个都表达不了——这恰恰是另一条技术路线（可编程 / 显式状态世界模型）在做的事。论文没提这条边界。

02Shared Interface

共享接口：把一张图变成模型认得的 K/V

这一节是全文的地基，但论文只用了半页。我把它拆成三个动作来讲：怎么变成 K/V、怎么挂进注意力、两个 pre-softmax 旋钮。

2.1 关键技巧：把扩散时间步设成 t = 0

证据是一张干净的图，不是一个噪声潜变量。要让主干「以为」它是自己刚生成完的定稿帧，做法是： 把这张图（连同它的相机和时间信息）喂进冻结的主干，把扩散时间步 t 设成 0，跑一次前向， 把每一层自注意力算出来的 K 和 V 抠出来存起来。这就是论文说的 clean K/V。

为什么必须这么做而不是直接把 VAE latent 当 K/V？因为注意力里的 K/V 是经过若干层 DiT 处理之后的中间表征， 不是输入本身。要拿到「如果这张图真的是第 n 帧定稿结果，模型内部会长什么样」，只能让模型自己跑一遍。 t = 0 的作用是告诉模型「这东西已经去完噪了，别当它是待处理的噪声」。

代价在这里：每一路证据、每一个 chunk，都要各跑一次主干前向。论文强调「EWA 不增加 NFE」是对的， 但那说的是 guidance 环节；证据构造环节的前向次数一次都没省，而且论文完全没有报告这笔开销。见 D05。

2.2 两类槽位：原生 18 槽 vs 用完即弃的临时块

下面这张图可以点开关。注意看：打开源视频证据时，被占掉的是主干原本放初始观测的 6 个源锚点槽； 其余三路是新挂上去的临时块，每生成完一块就整体丢弃、下一块重建。右侧读数是我按论文描述推算的每块额外前向次数。

一个容易被读漏的细节

论文原文：「Source-video evidence occupies the source-anchor slots」。 也就是说源视频证据不是额外加的，而是顶掉了主干原本放初始观测的那 6 个槽。 而那几个槽在 LingBot-World 2.0 里是它抗长程漂移设计的一部分（初始状态永不过期的 sink KV）。 把它换成源视频帧之后，主干的抗漂移能力是否受影响——论文没有做这个实验。

2.3 两个 pre-softmax 旋钮：ω 和 β 其实是同一件事

论文把 ω 和 β 分在两节讲，看起来像两种机制，但数学上它们是同一个动作的两种用法：在 softmax 之前给注意力分数乘一个正数。

  • ωbj（空间支持）：论文说「scaling their unnormalized attention weights by ω」。 未归一化权重就是 exp(logit)，乘 ω 等价于 logit += log ω。索引是 j（证据 token）—— 说的是「这块证据本身可不可信」，比如 warp 之后的空洞区、遮挡边界。取值域 [0,1]，只能压不能抬。
  • βij（对应路由）：论文直接写成 logit += log β。索引是 (i, j)（query–key 对）—— 说的是「这个待生成位置应该去看证据的哪个位置」。取值域是 β > 0，可以大于 1，也就是能抬。

把这两条并排看，接口的逻辑就很清楚了：ω 管「信不信」（证据侧），β 管「看哪」（查询侧），两个都是在 softmax 之前加偏置。 再加上 γ 管「什么时候生效」（去噪步调度）、RoPE 管「什么时候发生」（事件时间）， 一路证据的全部控制权就是这四个旋钮，没有任何可学参数。这个设计是干净的。

顺带一提：γ(s) ∈ {0,1} 是按去噪步开关证据的。但 WiW 用的是 LingBot 的 causal-fast 检查点——那是蒸馏过的少步生成器（consistency distillation + DMD）。少步意味着 s 的取值可能只有个位数， 「按去噪阶段调度证据」这个自由度还剩多少，论文既没给步数也没给调度表。
03Four Channels

四路证据：各补各的洞

四路证据的分工，论文表述得很克制，但逻辑其实是层层递进的： 第一路给外观，第二路给位置，第三路给第一二路都没有的表面，第四路给已经被时间冲走的东西。 点标签切换，右栏是这一路的「能提供什么 / 靠不住在哪 / 什么时候有」。

3.1 并排对比：谁在什么时候可信

通道它唯一能提供的东西它靠不住在哪 空间支持 ω 来自时间可用性
① 源视频 录制事件的外观与时间进度——唯一的「真值」来源 它停留在源相机坐标系里，完全没说内容该出现在新画面的哪 全图有效（但只占 6 个锚点槽） 整条 rollout 都在
② 目标视投影 空间摆位：把已观测外观放到目标相机下正确的像素位置，附带正确的遮挡关系 覆盖范围被源视角可见性死死卡住；深度误差会让结构飘 可见性掩码 × 几何可靠性 整条 rollout 都在，但大视角下 ω 大面积归零
③ 渲染几何 源视频从未拍到的主体表面的形状与外观提案 + 解遮挡用的深度 只对可重建的主体成立（论文只演示了人）；依赖 LHM++ 与 SMPL-X 的精度 渲染得到的几何支持掩码 需要主体在当前事件时刻有有效姿态
④ 历史检索 之前那次生成定下来的外观与布局——源视频里根本不存在的信息 它是模型自己编的，错了也会被当证据反复强化 （论文未明说）按覆盖度排序后整块参与 只有当相机回看且旧状态已被淘汰时才触发
第 ④ 路和前三路有本质区别，论文没有点破

①②③ 三路的信息源头都是外部的、可验证的：源视频是真拍的，投影是几何算的，人体是重建的。 只有第 ④ 路的内容是模型自己上一轮生成出来的。把它当「证据」意味着： 一旦某次生成产生了错误的外观，这个错误会被归档、被检索、被当作权威参照喂回去，形成自我强化。 这是所有 generated-history-as-memory 方案的共同风险，论文既没讨论也没做实验。

04CGAR

CGAR：把「该看哪」写进 logit

证据塞进去了，不等于模型会去看对的地方。大视角变化 + 动态运动 + 重复纹理（栅栏、砖墙、草地）， 会让基于外观的注意力认错人。CGAR 的做法朴素得几乎像个 trick：在 softmax 之前，给「几何上确实对应」的那一对 query–key 直接加分。

ℓcorrij  =  qi⊤kj / √dh  +  log βij Eq.4 左边那项是原本的注意力分数，右边是新加的。因为 softmax 前加 log β 等价于把该项的未归一化权重乘以 β， 所以 β 就是一个直白的「倍率」：β = 3 表示「这一对的权重放大三倍再去归一化」。 对应关系怎么来的：在源视频里跟踪带持久身份的点 → 结合深度与相机把当前视角的 token 和源视频 token 配对。 论文没给：跟踪器的型号、β 的计算公式与取值、「有效匹配」的判据、跟踪失败时的退化行为。

下面这个小玩具演示的是：假设某个待生成位置本来把注意力平摊在 6 个长得差不多的源 token 上（重复纹理场景）， 而几何告诉我们正确的是第 3 个。拖动 β 看 softmax 之后的分布怎么变。注意 β 是乘性的，所以它对分布的影响是「按比例抬」而不是「加一个常数」。

我的读法：CGAR 是个正确但作用面很窄的补丁

它的前提是「存在有效的几何对应」。可是这篇要解决的困难场景恰恰是大视角变化 + 动态主体—— 而这正是持久点跟踪最容易失效的地方（自遮挡、出画、非刚性形变）。 也就是说：CGAR 在最需要它的时候最可能没有匹配可用，在有匹配可用的时候注意力本来也不太会认错。

消融数字与这个判断一致：w/o CGAR 的 RotError 是 1.7828，完整方法是 1.7823， 差 0.0005°；VBench 五个维度上差值在小数点后第三位。它被写进摘要与贡献列表，但量化证据几乎为零。

05EWA · 本文最值得画的一张图

EWA：只放大「证据比主干多说的那部分」

这是全文技术含量最高、也最值得逐项拆开的一个式子。它名字里带 CFG，但做的事和 CFG 不一样—— CFG 是在噪声预测上朝远离无条件方向外推（要两次前向），EWA 是在注意力响应上朝正交方向外推（复用同一次前向）。 这个「省一次前向」是实打实的优点。

õe  =  oe  +  ge · max(0, cos(oe, o0)) · [ oe − Projo0(oe) ] Eq.5 o0：只attend原生块得到的响应，代表「模型自己想画成什么样」。　 oe：原生块 + 证据 e 联合归一化后的响应。　 蓝色项是 oe 中垂直于 o0 的分量，也就是「证据带来的、主干本来没有的新信息」。　 橙色项是一个非负的余弦门。　 紫色项是这一路证据独立的强度。　 最后还要用 ‖o0‖ 做上限裁剪（这一步和 NAG 的归一化裁剪同源）。

5.1 把式子画出来：一张二维向量图就够了

因为公式只涉及两个向量的夹角与模长，它的全部行为都能在二维平面里看完。 拖 θ（证据响应与主干响应的夹角）和 ge，看修正量怎么变。右边那条曲线是我从式子里推出来的修正强度随 θ 的解析形式—— 论文里没有这张图，但我认为它是理解这个设计（以及它的隐患）的关键。

5.2 我推出来的那条曲线：为什么峰值在 45°

把式子的模长写出来。设 θ 是 oe 与 o0 的夹角，则正交分量的模长是 ‖oe‖·sin θ， 余弦门是 max(0, cos θ)。于是修正量的模长：

‖Δ‖ = ge · max(0, cos θ) · ‖oe‖ · sin θ  =  (ge‖oe‖ / 2) · sin 2θ　（θ ≤ 90°），  0（θ > 90°） 推导 这是本页的原创推导，论文里没有。三个直接后果：
① 修正强度在 θ = 45° 取最大值 ge‖oe‖/2。
② θ → 0°（证据与主干完全同意）时修正 → 0。这是合理的：没有新信息就不用推。
③ θ → 90° 乃至 > 90°（证据与主干意见相左）时修正也 → 0，而且 θ > 90° 是硬归零。 第 ③ 条才是真正值得追问的地方。
D07 的来源：这个门控有一个反直觉的方向性

论文对 max(0, cos) 的解释是「suppressing excessive guidance」—— 当证据方向古怪时别乱推。作为安全阀，这没问题。

但它的另一面是：当证据与主干的注意力响应方向相反时，EWA 完全不介入。 而「模型很自信地想画成另一个样子」恰恰是重渲染里最需要被纠正的情形—— 比如相机绕到背面，主干倾向于按它熟悉的正面先验继续画，而目标视投影和人体渲染正在说「不对，这里应该是后脑勺」。 这时两者的响应很可能正是相左的。EWA 在这种时候的贡献是 0。

换句话说：EWA 擅长「锦上添花」，不擅长「力挽狂澜」。它更像一个防止证据把画面搞崩的保险丝， 而不是一个能把模型从错误先验里拽出来的纠正器。论文只描述了保险丝那一面。 怎么验：统计各层各步 cos(oe, o0) 的分布，看有多大比例落在负半轴——那部分证据等于白喂。

这一节里我认为确实成立的部分

「去掉沿 o0 的投影再放大」这个设计是对的，而且理由清楚：直接放大 oe 会把模型本来就有的那部分响应一起放大， 等于无缘无故提高了整体增益，容易过饱和。只推正交分量，就只推「新增的信息」。 再加上按 ‖o0‖ 裁剪上限，整体是一个克制、可控、零额外 NFE 的 guidance 方案。 相对 NAG 的增量在于每路证据独立强度 ge 和正交化——不算大突破，但是干净的工程改进。

06Long-horizon

历史检索：给滚动缓存装一个「回收站」

主干只保留最近 8 个历史状态。相机在一个场景里绕一圈再转回来，早先那块区域对应的状态早被挤掉了， 模型只能重新即兴——这正是 LingBot-World 2.0 自己在 limitation 里承认的问题（原话：「a region that leaves the context window and is later revisited tends to be regenerated rather than recalled」）。WiW 的补法是给淘汰出去的状态建一个库。

归档
存的是 K/V，不是像素
每个被滚动缓存淘汰的定稿状态，把它的逐层 clean K/V 连同相机位姿和时间索引存进历史库。 好处是取出来可以直接用，不用再跑一次前向。
检索
三条排序准则
按目标视角表面覆盖度和视角方向兼容度排序，再取一个多样化的 top-Kret 子集， 避免十个几乎一样的机位挤占名额。
没说的部分
库本身是无界的
论文只保证参与注意力的数量有界（Kret），没有任何一句提到库的存储有界。 逐层 K/V × 整条 rollout，这是线性增长。

下面演示一次典型的「绕一圈回看」。拖时间轴看：某个状态如何从当前块 → 滚动缓存 → 被淘汰 → 进历史库 → 在相机转回来时被检索命中。 同时留意左下角的库体积读数——这就是上面那张红卡说的问题。

和同类工作的差别在哪

WorldMem / VMem / Context-as-Memory / WorldKV 这一路都在处理同一个问题，区别主要在记忆用什么形式存： surfel 索引、显式 3D 点、压缩过的 KV、检索到的像素帧。 WiW 选的是不压缩的逐层 K/V——检索最快、信息最全，但也是最贵的一种。 论文把「压缩」这个整条线都在讨论的核心难题直接绕开了，既没给容量上限也没给淘汰策略。 考虑到主干是 14B 级别的 DiT，逐层 K/V 的体积不是一个可以不提的量。

08Ablation

谁在真正扛指标：算一算消融表的归因

论文摘要把 CGAR 和 EWA 列为两大技术贡献。Table 2 给了五个变体。 我把每个变体相对完整方法的退化量算成占比，结果相当直白。

结论：93%–99% 的可测收益来自最朴素、也最不新的那一路

目标视投影（warp）一条占掉了旋转误差退化的 93.3%、平移误差退化的 98.6%。 而「把源视频按深度 warp 到目标相机，再让生成模型补洞」是这个领域的标准配方—— TrajectoryCrafter、GEN3C、ViewCrafter、以及论文自己在 §2.1 引用的 Warp-as-History，全都这么干。

反过来，两个被写进摘要的新模块：EWA 占 4.6% / 0.6%，CGAR 占 0.011% / 0.12%。 在 VBench 那五个维度上，w/o EWA and CGAR 的 Subject Consistency 是 88.076， 完整方法也是 88.076——一模一样，连小数点后第三位都没动。

论文自己也只用定性图（Fig.6a）来支持 CGAR/EWA。这不等于它们没用——注意力路由这类改动确实容易「肉眼可见但指标不动」—— 但以目前的证据，把它们与 warp 并列写进贡献是过重的。至少需要：多次重复实验的方差、或一个能反映「主体外观保持」的实例级指标。

8.1 一个更麻烦的问题：主表和消融表对不上

Table 1 标的是「on DAVIS and OpenVid-1M」，Table 2 标的是「on DAVIS」。 按最自然的读法，Table 2 的 Full method 就是 Table 1 里 Ours 的 DAVIS 分量。 但两组数差得相当大：

  • Aesthetic：50.720（DAVIS）vs 56.556（合并）
  • RotError：1.7823（DAVIS）vs 2.8326（合并）
  • TransError：0.053291（DAVIS）vs 0.068622（合并）

合并值要高于（美学）或差于（相机误差）DAVIS 分量，只能是 OpenVid 那一半把它拉过去的。 那 OpenVid 上的数必须是多少？这是可以反解的。下面这个小工具就是干这个的： 拖动「DAVIS 在合并均值里的权重 w」，看 OpenVid 分量被倒逼成什么样。

这个反解给出了一条硬约束

VBench 各维度的上界是 100。Motion Smoothness 在 DAVIS 上是 96.074、合并是 97.749， 反解得到：只要 DAVIS 在合并均值里的权重超过约 0.573，OpenVid 的 Motion Smoothness 就必须大于 100——这在数学上不可能。

于是只剩两种可能，两种都值得作者交代一句：

  • 可能 A：OpenVid 子集在评测集里占了一半以上，且它在各项上与 DAVIS 差异巨大 （美学高约 12 分、相机误差差约一倍）。那么「我们在 DAVIS 和 OpenVid 上都最好」这个隐含结论是没被验证过的， 而论文从头到尾没有给任何分数据集结果。
  • 可能 B：两张表根本不是同一套配置 / 同一批视频 / 同一组轨迹跑出来的。 那么消融表就不能用来解释主表的数字，§8 上面那套归因分析也要打折扣。

最小修补成本极低：补一张分数据集的表，或者哪怕在正文里写一句「Table 1 为两数据集 xx:xx 加权平均」。

问题

DAVIS 与 OpenVid-1M 都是单目视频数据集。给定一条新的目标相机轨迹之后，「正确答案」这段视频在物理上不存在。 那么这三个全参考指标是跟什么算的？论文一个字没写。这一点尤其突兀，因为相机误差那一段反而写得很细（用了哪两个估计器、怎么平均）。

三种可能的参考构造，以及各自的偏袒方向
  • A：跟深度 warp 出来的目标视视频比。如果是这个，那把 warp 结果直接当证据灌进注意力的方法（也就是本文）在结构上被偏袒—— 它的目标函数几乎就是评测函数。这会使 PSNR 23.15 这个数失去比较意义。
  • B：只在源视角与目标视角的共视区域上比源视频。那么大视角变化下有效像素很少，指标主要反映「小视角部分做得怎么样」， 与论文强调的「diverse viewpoint changes」不匹配；而且共视掩码怎么定义会直接改变数值。

公开参考视频的构造脚本；或者换到有多机位真值的数据上重测一次（ReCamMaster 就自建过多机位合成集，这条路是通的）。 在此之前，这三个数只能当作同一口径下的相对排序，不能当作绝对保真度。

D07中EWA 的 cos 门控有一个反直觉的方向性：证据越「异议」，被采纳得越少▸
推导（本页原创，论文未给）
‖Δ‖ = ge · max(0, cos θ) · ‖oe‖ sin θ = (ge‖oe‖ / 2) · sin 2θ，θ ≤ 90°；θ > 90° 时为 0

修正强度在 θ = 45° 达到峰值，θ → 0° 与 θ → 90° 都趋于零，θ > 90° 硬归零。 可在 §05 的 Fig.4 里拖着看。

后果

当证据与主干的注意力响应方向相反时，EWA 完全不介入。而这恰恰是重渲染中最需要纠正的情形： 相机绕到主体背面，主干按熟悉的先验继续画正面特征，而目标视投影与人体渲染正在说「这里应该是背面」—— 两者的响应在这种时候很可能就是相左的。

所以 EWA 的定位更接近保险丝（防止坏证据把画面搞崩）而不是纠正器（把模型从错误先验里拽回来）。 论文只描述了保险丝那一面（"suppressing excessive guidance"），没有讨论它的代价。

怎么验

统计各层、各去噪步上 cos(oe, o0) 的分布，看有多大比例落在负半轴； 并做一个消融：把 max(0, cos·) 换成 |cos·| 或恒为 1，看大视角场景的表现是变好还是崩掉。

报 VBench 官方加权分，或直接给每维排名，不做算术平均。

D09中相机误差用生成视频反估轨迹来算，尺度与对齐协议完全未给▸
问题
  • TransError = 0.068622 的单位是什么？从单目视频反估的相机平移只有相对尺度，必须先做 Sim(3) / 尺度对齐才能和「规定轨迹」比。 论文一个字没提对齐方式，也没给单位。没有这个协议，这个数不可解释（这也是为什么 RotError 比 TransError 可信得多——旋转没有尺度歧义）。
  • 用 Depth Anything 3 与 ViPE 各估一次再平均。两者失败模式不同（大视角、弱纹理、动态前景占比）， 论文既没给各自的数，也没给两者的一致性。如果某个方法让其中一个估计器大幅失效，平均会掩盖它。
  • 更微妙的一点：反估器对「看起来更像真实视频」的输出更友好。这会让相机误差与 VBench 画质维度产生相关性， 使「画得好」和「跟得准」这两个本应独立的结论纠缠在一起。
最小修补

写清对齐协议（Sim(3)? 只对齐尺度? 用哪几帧?）、给单位、分别报两个估计器的结果与一致性。

D10中深度与尺度的一致性被一句话带过，而这是整条 warp 链最脆弱的一环▸
论文说了什么
Projection uses a shared coordinate system and scale. …… We align the avatar and body model to the projected scene's coordinate frame and depth scale using depth correspondences in the source view.
问题

DepthCrafter 给的是时序一致的相对深度，不是度量深度。要把它变成能跨帧、跨源/目标相机、还能和 SMPL-X 人体对齐的 3D 场景， 需要一整套尺度标定与漂移控制。论文对这一步只有上面那两句。

连锁后果有两层：① 尺度错了，用户指定的「向前移动 1 米」就没有物理意义； ② 更麻烦的是，反估的 TransError 也要在同一个模糊的尺度里比较—— 这使得 D09 和 D10 叠在一起，让平移误差这一列变得相当难解读。

怎么验

在有真实相机与深度的数据（例如带位姿的多视角序列）上跑一遍全链路，报尺度误差； 或者展示同一场景下不同尺度标定给出的 warp 结果差异。

D11中CGAR 的三个关键构件全部缺失：跟踪器、β、匹配判据▸
缺什么
  • 点跟踪器没有任何引用。Fig.2 画了 "Point tracks" 和 "Warped Tracking Points"，正文只写 "We track points with persistent identities in the source video"，全文没有引用任何跟踪方法。 在一篇处处引用（79 条）的论文里，这是个显眼的空缺。
  • βij 只被描述为「> 0，控制对应关系的贡献」，没有公式、没有取值、没有随层/随去噪步的变化规则。
  • 「valid matches」的判据未给。什么叫有效匹配？跟踪置信度阈值？深度一致性阈值？重投影误差阈值？都没有。
  • 跟踪失效时怎么退化也没写。而大视角 + 动态主体（自遮挡、出画、非刚性形变）正是持久点跟踪最容易失败的场景， 也正是 CGAR 声称要解决的场景——这两件事撞在一起，值得一段讨论。
与 D03 的关系

如果有效匹配的覆盖率本来就很低，那么 CGAR 在消融里几乎不动指标就是可以预期的。 一个覆盖率统计（多少比例的 query 拿到了有效匹配）就能把这件事讲清楚，成本很低。

D12低源锚点槽被占用的代价没做实验；五个应用全部只有定性▸
槽位占用

「Source-video evidence occupies the source-anchor slots」——那 6 个槽在主干里原本放初始观测， 是 LingBot-World 2.0 抗长程漂移设计的一部分（永不过期的 sink）。换成源视频帧之后， 长 rollout 的稳定性是否受影响，论文没做实验。另外，源视频只有 6 个 latent 槽的预算， 长源视频怎么取样 / 滑窗，也完全没写。

五个应用

bullet time、视频稳定、视频编辑、跨实例 K/V 共享、人体动作迁移——全部只有定性图（Fig.4），没有任何量化。 其中「两个同主干实例互传 K/V」这个设定最有意思（相当于让两次独立生成共享记忆）， 但论文连「两个实例的相机坐标系与事件时间轴怎么对齐」都没说，Fig.4(d) 只画了一个箭头。

为什么只标低

应用展示本来就以定性为主，这在同类论文里是常规做法；槽位占用也只是一个未验证的猜想。 这条更像是「下一版该补的实验」而不是「结论有问题」。

最后，我认为这篇确实做对了的事

① 「把控制翻译成模型原生可读的格式」这个 reframing 是真的有价值，而且被四类控制 + 五个应用实际兑现了，不是空谈。
② t = 0 前向抽 clean K/V 这个实现路径干净、通用，换个因果主干就能复用。
③ EWA 复用同一次前向做 guidance、正交化避免重复放大、按 ‖o₀‖ 裁剪——每一步都有明确理由，是扎实的工程设计。
④ ω / β / γ / RoPE 四个旋钮把「信不信 / 看哪 / 何时生效 / 何时发生」正交地拆开了，这个抽象很漂亮。
我的批评集中在实验部分：它配不上方法部分的完成度。

11Positioning

谱系与定位：它在这条线的哪一格

把「新的控制信息通过什么路径进入模型」当作一根轴，这几年的工作排得很整齐。 WiW 站在最右端：不新增任何路径，全部走原生自注意力。

它继承了什么
主干 LingBot-World 2.0 的能力与局限
主干提供：因果 DiT、MoBA 注意力掩码、Plücker 相机条件（AdaLN 注入）、chunk-wise 文本条件、抗漂移预训练 + 少步蒸馏。 主干的公开 limitation 正是 WiW 第 ④ 路证据要解决的：「离开上下文窗口的区域再回看时是被重新生成而不是被回忆起来的」。 从这个角度看，WiW 的历史检索是对主干短板的一次外挂式修补——不改模型，只加证据。
它不能做什么
接口的表达力边界
能进这个接口的，只有能被渲染成 RGB 的东西。 因此它能表达相机、姿态、遮挡、外观、历史外观；表达不了非视觉状态（血量、锁、阵营、规则）、 也表达不了「离屏实体依然存在」这类需要显式账本才能保证的事实。 要覆盖那一类，需要的是另一条路线（可编程 / 显式状态世界模型）。两者并不冲突，反而是互补的。

D 一句话术语表

clean visual state（干净视觉状态）
相对「噪声潜变量」而言：已经定稿、无需再去噪的视觉内容。主干原本只把初始观测和最近定稿帧当作这种东西，WiW 把外部证据也伪装成它。
clean K/V
把干净视觉状态喂进冻结主干、令扩散时间步 t = 0，跑一次前向后从每层自注意力抠出来的 key / value。这是证据真正进入模型的形式。
rolling cache / sink KV
因果视频模型的上下文管理：一部分槽位固定放初始观测（sink，永不过期），一部分滚动保留最近的定稿状态。WiW 的源视频证据占用的就是前者。
temporary auxiliary attention block（临时辅助注意力块）
挂在原生块旁边的额外 K/V 集合，与原生块联合归一化参与同一次 softmax。当前块一定稿就整体丢弃。
joint normalization（联合归一化）
原生块与各辅助块的注意力分数放在同一个 softmax 里归一，而不是各算各的再加权求和。这是 ω、β 能起作用的前提。
NFE（network function evaluation）
去噪网络的完整前向次数。CFG 每步要两次（有条件 + 无条件），EWA 复用同一次前向的注意力响应，所以 guidance 环节是 0 额外 NFE——但证据构造环节的前向不在此列。
Plücker 嵌入
把每个像素的视线表示成 6 维坐标的相机编码方式，是主干 LingBot-World 2.0 原生的相机条件通路。消融里的 "w/o Plücker" 指的是去掉源相机那一路的这个信息。
