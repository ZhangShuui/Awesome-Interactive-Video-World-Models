OctWorld

用一棵会长大的稀疏八叉树，把生成过的世界「融合」成可回访的三维记忆

OctWorld 回答的是一个具体问题：相机走很远、转很大的角度再回到来过的地方时，视频模型怎样把那里画得和上次一样？ 它的答案不是检索旧帧，而是OctMap——一个用 TSDF（截断符号距离场）把每一块生成的 RGB-D 逐帧融合进去的全局三维地图， 存在一棵按深度自适应细分、边界可以倍增的稀疏八叉树里：近处小体素、远处大体素，走出边界就把根节点扩一倍。 每生成新一块之前，先把这张地图提取成网格、渲染到目标相机，得到带可见性掩码的部分观察，作为扩散模型的空间条件； FramePack 打包的历史帧提供时间上下文，Plücker 射线提供相机控制。 主模型 OctWorld-1.0 在 FramePack（Hunyuan DiT，15B）上联合生成 RGB 与深度；1.5 版换到 Wan2.1 14B I2V，深度交给流式 Depth Anything 3。

00TL;DR

一图看懂：地图是主角，扩散模型是「按地图作画」的画师

这篇论文的贡献结构很清楚：生成网络是借来的（FramePack / Wan2.1，加了条件通路），记忆是自己造的（OctMap）。 读它的正确姿势是把 OctMap 当作一个 SLAM 里的建图模块来读——只是它的「传感器」不是深度相机，而是上一块刚生成出来的 RGB 和深度； 它的「定位」也不用估计，因为相机轨迹是用户给定的。

MEMORY · OctMap

会长大的八叉树 TSDF

根体积 L = 2（[−1, 1]³），最深 16 级；叶节点在 8 个角顶点存 TSDF、颜色、权重。每个像素按 s = z / √(fxfy) 决定该去第几级，截断带 τd = 5 ℓd 随层级缩放。越界就把根扩一倍，旧节点整体降一级。

GENERATOR · 1.0 / 1.5

借来的骨架，加三条通路

1.0：FramePack F1（Hunyuan DiT）扩通道联合出 RGB+深度；渲染的记忆投影经 VideoPainter 式控制分支注入；Plücker 相机经小卷积适配器加到目标 latent。1.5：Wan2.1 14B I2V 原生 (x, m, y) 接口直接吃部分渲染 + 掩码，深度改用流式 DA3。

TRAINING · 噪声增强

让模型习惯「历史是生成的」

训练用真值 RGB-D 当历史，与推理有落差；于是对投影记忆与打包上下文都加噪 εα，α 从 11 档 {0, 0.07, …, 0.70} 采样并作为条件输入。1.0 推理用第 3 档，1.5 用 0 档。数据来自 Re10K / DL3DV / SpatialVid 静态子集，深度与位姿由 Pi3 估计。

◆ 如果只记三件事

1. 记忆是融合出来的，不是存出来的。点云缓存和帧库都是「把观察原样堆起来」；OctMap 用 TSDF 的加权平均把多次观察压成一个连续的距离场，噪声被平均、重复被合并，回访时渲染出的是一张干净的几何（Sec. 3.1、Tab. 4a/5）。

2. 分辨率不是全局参数，而是逐像素算出来的：s = z/√(fxfy) 就是一个像素在深度 z 处的物理足迹；体素只需要跟这个足迹一样细。开放世界的尺度不确定问题由此绕开——地图从不需要事先知道场景多大（Sec. 3.1、附录 B.4）。

3. 生成器只看两样东西：渲染出来的部分观察 + 掩码（空间条件）和打包历史（时间条件）。所以论文的消融很干净：去掉 OctMap，相机控制立刻失准；把 OctMap 换成点云或均匀 TSDF，LPIPS 从 0.141 掉到 0.200–0.275（Tab. 4a）。

01The Problem

长程生成为什么难：走得远、转得大，还要回得来

论文把自己的目标场景定义为「长空间范围」（long spatial range）：相机路径长，视角覆盖宽。 难点不在生成本身，而在回访——走了很远之后回到先前生成过的区域，新生成的内容必须和旧的在几何与外观上都对得上。 这需要两件事：跨块（cross-chunk）生成，以及一个能把过去的观察真正「合并」起来的记忆机制。

1.1三条既有路线，各自缺什么

相机控制路线

Plücker 射线当条件

CameraCtrl、Aether 这类方法把相机编码成射线嵌入交给模型学。论文的判断：从相机表示到画面的映射太复杂，控制常常不准、几何一致性有限（Sec. 2）。深度即便有，也只是辅助输出。

几何感知路线

联合预测深度 / XYZ

WVD、Aether、DeepVerse、4DNeX、FantasyWorld 让模型顺带输出几何，短期一致性变好；但它们主要在单个生成块内工作，路径一长、视角一宽就没有机制保证回访一致（Sec. 1）。

记忆路线

点云缓存 / 帧库检索

Gen3C 把点云堆成 3D cache；VMem、Context-as-Memory 存生成过的帧再按相机检索。论文认为它们「缺少有原则的记忆融合和全局整合」，长轨迹下仍会几何漂移（Sec. 1）。OctWorld 就是在这条路线上把「堆」换成「融合」。

1.2为什么不能直接搬 SLAM 的 TSDF

OctMap 建立在 TSDF（Curless & Levoy 1996）之上——这是 KinectFusion 一系 SLAM 系统的标准建图方法：把每帧深度转成「到表面的截断符号距离」，在体素网格里做加权平均，最后从零等值面提取网格。 但论文指出两种任务的前提不同：

前提SLAM 重建开放世界生成（本文）
尺度已知的度量尺度（真实传感器）不确定：只有单目深度给的相对尺度，而且会随生成演化
空间范围有界（一个房间、一栋楼），可以预先开辟体积潜在无界：相机可以一直往外走，事先不知道要多大的盒子
观察来源物理传感器，噪声可建模上一块生成的 RGB 与深度，误差来自模型本身
位姿需要估计（定位）用户给定的轨迹，无需估计
固定分辨率 TSDF 的后果选一个合适的体素大小即可高分辨率 → 体素数按立方增长、内存爆；低分辨率 → 近处细节全糊（Sec. 1）
02OctMap · Data Structure

OctMap 数据结构：一棵存在角顶点上的稀疏八叉树

Sec. 3.1 用不到半页定义了整个数据结构，但每个常数都有含义。把它们摊开：

树

根体积 L，逐级八分

根节点覆盖边长 L 的立方体，每级把一个节点分成 8 个子节点。第 d 级的体素边长 ℓd = L / 2d。 初始化时 L = 2（规范立方体 [−1, 1]³），最深 dmax = 16（附录 B.4）。

叶节点

8 个角顶点各存三样东西

截断符号距离（TSDF）、RGB 颜色、积分权重。论文把 TSDF 与颜色合写为 φ，权重记 w。 注意是每个叶节点自己存 8 个角，相邻叶节点在共享角上各存一份——所以提取网格时要「合并重复顶点」。

截断

τd = α · ℓd，α = 5

TSDF 只在表面前后 τd 范围内有意义；OctMap 让它随层级缩放，细体素配窄截断带，粗体素配宽截断带。α = 5 意味着截断带在每一级都是正负 5 个体素宽（附录 B.4）。

初始化

首帧点云归一到 [−0.5, 0.5]³

为了保证首帧的点都落在根内且留有余量，首帧点云先归一到根的中央一半。这也把「场景尺度」定成了首帧深度的尺度——因此首帧深度被论文当作用户可控的输入（附录 A.4）。

03Adaptive Node Allocation

逐像素自适应分配：体素应该跟像素足迹一样细，不多不少

这是全文最核心的半页（Sec. 3.1「Adaptive Node Allocation」+ Fig. 4）。每来一帧 RGB-D (I, D)，对每个像素做三步： 算足迹 → 定层级 → 沿光线在截断带内采样并分配节点。

3.1算足迹：一个像素在深度 z 处有多大

像素 (u, v) 的深度 z = D(u, v)，反投影到相机坐标：

x(u, v) = ( (u − cx) · z / fx, (v − cy) · z / fy, z ) 针孔模型；fx, fy 是以像素计的焦距，cx, cy 是主点。

相邻像素在该深度上相距约 Δx ≈ z/fx、Δy ≈ z/fy——这就是「像素足迹」。论文取几何平均作为该像素想要的体素大小：

s(u, v, z) = z / √(fx · fy) 近处 z 小 → s 小 → 体素细；远处反之。注意 s 与像素位置无关，只与深度和焦距有关。

3.2定层级：最细的、体素不大于足迹的那一级

d = 满足 ℓd ≤ s < ℓd−1 的最细层级 　⟺　 d = ⌈ log2(L / s) ⌉ 右边的闭式是我的改写（L/2d ≤ s ⇒ 2d ≥ L/s），论文只给了不等式。实际还要夹到 dmax = 16。

3.3沿光线采样、分配、分裂

只更新表面点 x 所在的体素不够——TSDF 是一个场，表面两侧的体素都需要拿到距离值。于是沿该像素的相机光线采样：

xk = o + tk · r(u, v),　tk ∈ [z − τd, z + τd] o 是相机中心，r 是光线方向。每个采样点经空间量化得到第 d 级的体素索引 ik；从根往下遍历到第 d 级，路径上没初始化的节点就分配、该分裂的叶就分裂。分裂时子节点通过空间插值继承父节点属性（附录 B.4 写明是三维最近邻插值）。论文没有给采样间距。
◇ 我的两点理解（论文没明说）

为什么用几何平均而不是取小的那个？ s = z/√(fxfy) 是像素足迹面积 Δx·Δy 的平方根，也就是「等面积正方形的边」。在 fx ≈ fy 的常见情形下它和 z/f 没有区别；对非方形像素它折中了两个方向。

层级只看深度，不看内容。 分辨率的依据是「相机离多近」，而不是「这里几何多复杂」——一面近处的白墙和一株近处的灌木会拿到同样细的体素。论文引用的 [8]（方差自适应体素）是按内容自适应的；OctMap 选了更简单的深度准则，这也是它能在 4–6 FPS 下积分的原因之一。

04TSDF Integration & Mesh Extraction

TSDF 融合与网格提取：把多次观察压成一个距离场，再从零面上抠出网格

节点分配好之后，更新规则就是教科书式的 TSDF 融合（Curless & Levoy 1996），唯一的改动是截断距离随层级变：τd 而不是全局常数。

4.1逐顶点更新：式 (1)

对当前帧「相交」到的每个体素，把它的角顶点投影到相机像平面，读出该像素的观测深度，与顶点自身的深度相减得到符号距离，再按 τd 截断——这就是该顶点的观测值 φobs（颜色同理取该像素的 RGB）。然后做加权滑动平均：

φnew = wold φold + wobs φobswold + wobs,　　wnew = wold + wobs　　(1) 权重累加意味着越早、越多次被看到的顶点越「固执」，新观察对它的影响按 wobs/(wold+wobs) 衰减。论文没有写 wobs 取什么（标准做法是常数 1，或随视角 / 距离衰减）。

4.2网格提取：叶节点各自 Marching Cubes，再合并顶点

每个叶节点是一个角上带 TSDF 值的立方体。因为叶节点彼此不重叠（只共享角），可以并行对每个叶跑 Marching Cubes，得到一堆互不相连的三角形（triangle soup）；再把共享角上重复的顶点合并，就得到最终网格。 网格被渲染到目标相机视角，输出三样东西：部分 RGB、部分深度、可见性掩码（网格没覆盖到的像素为 0）。这就是送给生成器的「世界记忆投影」（Sec. 3.1–3.2）。

05Scene Scale Control

根扩展：场景无界，地图就跟着长——代价 O(1)

附录 B.4 藏着一个很漂亮的小机制。OctMap 一开始只覆盖 [−1, 1]³。相机一直往外走怎么办？答案是不搬数据，只加一层根。

当新一帧的点落到当前边界 [−L/2, L/2]³ 之外时，新建一棵根边长为 2L 的树，把旧树第 1 级的 8 个节点直接挂到新树第 2 级中央的 8 个位置上。所有旧节点的几何位置、特征、权重原封不动；只是每个节点的层级编号 +1，而根覆盖范围变为 [−L, L]³。 因为只动了树顶的 8 个指针，开销是 O(1)；与之相对，均匀 TSDF 遇到同样情况要么预先开一个巨大的体积，要么把整个体积重新分配并搬运。

配合上一节的规则看会更清楚：层级 d 是按 ℓd = L/2d 定义的，根扩展后 L 翻倍、d 加一，ℓd 不变——所以「体素跟像素足迹一样细」这条准则在扩展前后保持一致。唯一的上限来自 dmax = 16：每扩展一次，可用的细分层数就少一层。

△ 论文自己列出的 OctMap 局限（附录 D.2）

粗节点不保留特征：只有叶节点有 TSDF / 颜色，所以做不了「远看用粗层、近看用细层」的视角相关 LOD 渲染。没有体素剪枝：没被观测到的、冗余的体素不会被丢弃。全部节点常驻 GPU：场景越大内存越涨——Tab. I 里 505 帧序列的峰值 CUDA 内存 22.93 GB、最终 3466 万个节点；作者把「视角相关的显存卸载」列为关键方向。

06Generation Network

生成网络：借来的骨架，加三条条件通路（1.0），或干脆用骨架原生的接口（1.5）

论文对生成器的态度很务实：选一个「长时程上下文 + 抗漂移」的预训练模型，然后只加必要的东西。两个版本的取舍不同，值得并排看。

07Noise Augmentation & Data

噪声增强与训练数据：让模型在训练时就见过「不完美的历史」

自回归生成有一个经典的训练–推理落差：训练时历史是真值，推理时历史是自己生成的。OctWorld 用 GameNGen 一系的噪声条件策略来缩小它，而且同时加在两条历史通路上。

7.1噪声增强：11 档 α

α ∈ { x · 0.7 / 10 | x = 0, 1, …, 10 } = { 0, 0.07, 0.14, …, 0.70 } 训练时随机采样一档，用它缩放加到「投影记忆」和「打包上下文」上的标准高斯噪声，同时把 α 作为条件送进网络（Sec. 3.2、附录 B.2）。推理时固定一档：1.0 用第 3 档，1.5 用第 0 档。

7.2训练数据：三个来源，两级过滤

◆ 零初始化：新通路一开始「不存在」

所有新增条件通路遵循零初始化（附录 B.2）：改动过的线性层 / 卷积层里新加的权重置零；控制分支在注入主干之前过一个零初始化的投影。这保证训练第 0 步时模型就是原来的 FramePack，条件是渐进地学进去的——和 ControlNet 的零卷积是同一个思路。

10.3我的保留意见

  1. 「可探索」是离线意义上的。轨迹由用户事先给定并切块（Algorithm 1 第 4 行）；虽然逐块自回归在原理上允许每块再给下一段轨迹，但 0.136 FPS（Tab. II 反推约 4.4 分钟一块）下这不是交互。摘要里的 explorable 应读作「可以离线生成任意轨迹」。
  2. 记忆只和深度一样好，而深度尺度的漂移没有被评估。相机位姿是给定的，所以 OctMap 唯一的误差来源就是生成 / 估计的深度。附录 A.4 证明了模型能在一块内纠正首帧的噪声深度，但没有实验考察长轨迹上深度尺度缓慢漂移时融合会怎样——TSDF 的加权平均对随机噪声很鲁棒，对系统性偏移则会把两次观察融合成两层表面。1.0 用「历史最大深度」归一化来传递尺度、1.5 用流式 DA3，都是在管理这个风险，但没有量化。
  3. Tab. 5 评的是建图，不是生成。那 100 个场景用的是数据集的 RGB-D（重投影回原视角），所以它证明的是「同等代价下 OctMap 比均匀 TSDF 保真」，不是「用生成深度建出来的图有多准」。后者只能从 Tab. 2 / 4a 的端到端指标间接看。
  4. 效率的措辞要读准。「相当的代价」是相对 λ = 0.002 的 TSDF 说的；相对 λ = 0.004（1.97 GB、3.15 s）OctMap 贵 3.7 倍显存、5.7 倍时间。另外 Sec. 4.1 说 OctMap「典型 1–10 GB」，Tab. I 的 505 帧序列峰值却是 22.93 GB——两处数字口径不同，读者应以 Tab. I 为准估长序列。
  5. WorldScore 的优势集中在一致性两项。相机控制 39.12 低于 Voyager 的 46.60，主观质量 31.17 是五者最低，内容对齐 6.37。总分 50.31 对 Voyager 49.93 的领先很小，而 Voyager 还是在单块、压缩轨迹的不利条件下跑的。把「outperforming prior methods」读成「在三维 / 光度一致性上明显领先、其余持平或落后」更准确。
  6. 基线协议对短块方法天然不利。VMem 相机提速 4 倍、Voyager 与 Aether 把 108 帧轨迹压进一块——作者披露得很清楚，但这意味着 Tab. 1 比较的其实是「谁能处理这种长轨迹」，而非同等条件下的生成质量。用户研究也是：VMem 几乎无法生成合理结果，三选一实际上是 OctWorld 对 Gen3C 的 53.8% : 39.5%。
  7. 不少实现细节缺席。wobs 怎么取、光线采样间距、渲染器与渲染分辨率、去噪步数、Tab. II 的 GPU 型号、FramePack 的历史长度与打包配置、颜色如何存 / 渲染（顶点色？）、多分辨率叶节点之间的 T 型接缝如何处理——都没写。代码「Coming Soon」，这些暂时无法核对。
  8. 「第一个」的措辞。贡献一称这是「第一个支持可扩展、全局融合的三维记忆」的长程生成框架。Voyager 的 world cache、Spatia 的可更新空间记忆、EvoWorld 的显式三维记忆都是显式三维记忆；OctWorld 的新意在于TSDF 式的加权融合 + 自适应八叉树，「第一」应限定在这个意义上。
  9. 1.0 与 1.5 的差异没有拆解。1.5 同时改了骨架、深度来源、噪声注入方式、训练数据和步数（7,000 步 vs 110K 步），Tab. IV 的每一项变化都无法归因。项目页的视频全部来自 1.5，而正文所有比较都是 1.0——读者看到的演示和看到的数字不是同一个模型。
○ 尽管如此，值得记住的贡献

把 SLAM 建图的成熟工具正确地搬进了生成。TSDF 融合、八叉树、Marching Cubes 都是二十年以上的技术；论文的贡献是想清楚了生成场景与传感器场景的两点差异（尺度未知、范围无界），并用「按像素足迹定层级」和「O(1) 根扩展」两个小而准的设计回应它们。

消融设计干净。Tab. 4a 把「有没有空间条件」「用什么表示」「块多长」分开；Tab. 5 把「建图本身」从生成里剥离出来单测。这让「OctMap 优于点云与均匀 TSDF」成为一个可以被信任的结论，而不只是一个系统层面的整体提升。

1.5 的原生条件接口是一个值得推广的观察。「部分观察 + 掩码 → 补全」本来就是 I2V / 插值骨架预训练时学过的任务；把记忆投影当作这种条件喂进去，比再造一条控制分支更省、也更能利用预训练先验。

B术语

TSDF（截断符号距离函数）
每个空间点到最近表面的带符号距离（前方为正、后方为负），超过截断距离 τ 就截到 ±τ（常再归一到 ±1）。多帧观察通过加权平均融合；表面就是零等值面。Curless & Levoy 1996；KinectFusion 的核心。
八叉树（octree）
把立方体递归八分的树；第 d 级节点边长 L/2d。稀疏八叉树只为有内容的区域分配节点。OctMap 的属性只存在叶节点的 8 个角上。
截断带 / 截断距离 τd
表面前后需要维护 TSDF 的范围。OctMap 令它与层级绑定：τd = 5 ℓd，即每级都是 ±5 个体素。
像素足迹
一个像素在深度 z 处覆盖的物理尺寸，≈ z/f。OctMap 用它（几何平均 z/√(fxfy)）决定该像素周围体素应该多细。
Marching Cubes
Lorensen & Cline 1987：按立方体 8 个角的正负号查表生成三角形，得到零等值面网格。OctMap 逐叶节点并行执行，再合并共享角上的重复顶点。
根扩展（root extension）
附录 B.4：把旧树 depth-1 的 8 个节点挂到新树 depth-2 的中央 8 个位置，根边长翻倍，O(1) 开销。
世界记忆投影
把 OctMap 的网格渲染到目标相机得到的部分 RGB / 深度与可见性掩码；生成器的空间条件。
FramePack
Zhang et al., NeurIPS 2025：下一帧（段）预测的视频扩散框架，把历史帧按远近逐级压缩打包成定长上下文，并有抗漂移设计。OctWorld-1.0 的骨架（F1 版，Hunyuan DiT）。
Plücker 射线嵌入
用（方向 d，矩 o × d）六维向量逐像素表示相机光线；CameraCtrl 一系的标准相机条件。OctWorld 把它归一到最后一个历史帧坐标系，经小卷积适配器加到目标 latent。
VideoPainter 式控制分支
复制预训练 DiT 的若干块作为控制分支处理条件图，输出经零初始化投影加进主干；OctWorld-1.0 用 4 个块接收渲染 RGB / 深度 + 掩码。
噪声增强（noise augmentation）
训练时给历史条件加可控噪声并把噪声级作为条件（GameNGen）；缩小「训练用真值历史、推理用生成历史」的差距。
逐 token AdaLN（1.5）
为锚 / 历史 / 目标三类 token 分别指定条件时间步 ri ∈ {0, α, t}，各自产生调制参数，避免 1.0 里 α 与扩散时间步的纠缠。
WorldScore
Duan et al. 2025：世界生成统一基准，含相机控制、物体控制、内容对齐、3D 一致性（重投影误差）、光度一致性（前后向光流）、风格一致性（首尾帧特征 Frobenius 范数）、主观质量等维度。
Chamfer 距离
两个点集互相取最近点距离的平均之和；本文用 L1 范数（式 I），点云由 VGGT 从生成视频重建。
Pi3 / MoGe / Depth Anything 3
训练数据的深度与位姿估计器（Pi3）；首帧深度初始化（MoGe，与基线一致）；1.5 的流式深度估计器（DA3 流式版）。
