MiniMax-H3 能推理物理世界吗？

一份 517 题的「隐式 prompt」评测：精读、逐格重算，以及它其实没能回答的那个问题

这篇论文的问题框架是好的：不把答案写进 prompt，而是拆到图、音、视频里，看模型能不能自己推断出该生成什么。但它只测了一个模型、没有任何对照组，而且没交代测的是哪个「H3」。MiniMax 官方文档写明，跨模态关联和复杂逻辑推理由一个托管、未开源的预处理系统 H3-Context-IR 负责。所以 41.97% 只能读作「这套系统在这 517 题上的端到端通过率」，读不出「多模态对齐带来了推理能力」这个结论。

§ 1一图看懂：把答案拆散到几种模态里

常见的视频生成评测，prompt 几乎就是答案，比如「一个人把陶瓷杯推下桌，摔碎了」，模型照着画就行。这篇论文反过来做：故意把关键语义从 prompt 里删掉，拆到图像、音频、视频里，每一路只给一部分证据，只有几路对齐起来才能确定「该生成什么」。下面用论文图 1(b) 的杯子例子演示（三种材质是示意）。

§ 2三句话版本

  1. 这是评测论文，不提新方法。作者只针对 MiniMax-H3 一个模型，造了 517 道「隐式」题，分 4 个场景、29 个子类。H3 生成视频后，3 位专家按每题各自的语义要求判「成功 / 失败」。
  2. 总成功率 41.97%（217/517）。视频续写决策（VDR）56.0% 最高，音频消歧（ADR）27.4% 最低。表 2 的每个百分数都能还原成整数计数，算术完全自洽（§5）。
  3. 但它回答不了自己在摘要里提的问题（“Can multimodal alignment improve the model’s world reasoning?”）。全文没有任何对照：没去掉某一路模态，没替换音频，没把答案写进 prompt 当上限，也没换别的模型比。它也没说测的是托管 API 还是开源权重，而这两者在「谁来做跨模态推理」这件事上是两个不同的系统（§7）。
一句话判断

值得借鉴的是它的问题框架（不告诉模型结局，让它从观测里推），以及 ADR 这种两个候选声源由音频决定的干净设计。数据集发布后，这份题目清单会很有用。现有的数字只能当作一次端到端通过率来读：它说明 H3 这套系统在这批题上大约一半会失败，但分不清失败出在「没看懂/没听懂」、「没想对」还是「没画对」。

§ 3四个场景：每道题藏了什么

四个场景共用同一个生成式 Ŷ ∼ pθ(Y | q, x)：q 是隐式任务 prompt，x 是观测，pθ 是 H3 诱导出的输出视频分布。四个场景的区别只在 x 由哪些模态组成、以及信息被藏在哪一路。表中「公开接口里的入口」一栏是我根据 H3 公开文档做的推断，论文本身没写（§7 细说）。

§ 4数据是怎么造的

每道题最后落成三元组 Ei = (qi, xi, τi)：隐式 prompt、观测、场景标签（MSR / ADR / VDR / AVIR）。另外每题还有一个「标注的语义目标」，也就是专家据以判分的要求。构造分四步：

素材收集

  • 真实：多视角来自 HiFi-UMI-2K、VISTA-UMI-5K、HuMI-Unsheathe、Hy-Embodied-0.5-VLA-Data、10Kh-RealOmin；视频来自 LLaVA-Video-178K；声音来自 FSD50K、ESC-50
  • 合成：视频用 Seedance 2.0 生成，音频用 ChatGPT Voice 生成
  • 按感知质量、语义清晰度过滤
真实 / 合成的比例、每个来源各占多少：均未报告。

按场景构造实例

  • 选观测、定输出目标、写生成 prompt
  • 标注「支持目标的证据」与「合格输出必须满足的语义要求」
  • 要求只约束推断结果，不约束外观与运动的具体实现

隐式 prompt

  • ChatGPT 与 Qwen3 起草候选措辞，专家修改
  • 两条准则：① 文本本身不泄露目标；② 多模态输入足以推出目标
  • 泄露答案、目标含糊、需要输入之外假设的 prompt 被改写
论文写 “we demonstrate that…”，但没有给出任何泄露检测（例如纯文本盲猜率）。

10 轮专家审核

  • 四个维度：场景复杂度 · 推断丰富度 · 条件一致性 · prompt 隐式性
  • 未通过的题改 prompt 或换输入后重审
原句：“Each condition-prompt pair is verified to support the intended inference through video generation for MiniMax-H3.” 审核有没有看 H3 的输出？如果看了，题目就是按被测模型筛过的（§10 M4）。

最终得到 517 题：MSR 200（10 子类）、ADR 146（6）、VDR 100（8）、AVIR 71（5）。MSR 独占 38.7%，所以 「总体 41.97%」是按样本加权的，受配比影响。换成按场景宏平均是 43.70%，按 29 个子类宏平均是 44.47%。差别不大，但说明「总体」这个数没有特别的含义。

§ 5结果：把表 2 逐格重算一遍

表 2 只给了子类的 N 和百分数。每个百分数乘以 N 都正好是整数（例如 Deformation 41.20% × 34 = 14.0，Pouring 58.30% × 12 = 7.0），加起来是 MSR 87/200、ADR 40/146、VDR 56/100、AVIR 34/71，合计 217/517 = 41.973%，与论文完全一致。数字本身没有问题，下面讨论的是它们能支撑多强的结论。

§ 6「隐式」到底有多隐式

表 1 把本文的 Prompt Type 标成 Implicit，好像是全体题目共有的二元属性。我把论文图 1、3、9–12 中公开展示的 12 条 prompt 逐句标了颜色：哪些句子把应当推断的东西直接说了，哪些提示了推断方向，哪些只是在约束格式。评级是我的主观判断，仅供参考；样本也是作者自己挑出来展示的，不是随机抽样。

隐式程度解释不了分数

按展示 prompt 的平均隐式度排，AVIR（3.0）> ADR（2.5）> VDR（1.8）> MSR（0.5）。成功率却是 VDR > AVIR > MSR > ADR。最不隐式的 MSR 并不容易，最隐式的 AVIR 也不是最难。这说明场景之间的难度差主要来自别处：双视角同步渲染本身就难；音频走哪条通路进入模型（§7）。场景分数混在了一起，而论文没有设计能把它们拆开的实验。

§ 7被测的究竟是哪个「H3」

论文图 1 把 H3 画成「模态编码器 → 跨模态对齐 → 统一 token」，摘要说它 “combining multimodal context understanding with joint audio-visual generation in a shared latent framework”。但对照 MiniMax 自己的公开文档，「多模态上下文理解」与「共享潜空间里的生成」其实是两个不同的部件，一个托管、一个开源。全文没提这一点，也没说用的是哪条路径。

这对论文的每个场景意味着什么

场景题目需要的输入公开接口里能对上的入口（推断）后果
MSR左右腕视角的首帧 + 末帧，生成并排双视角视频首尾帧工作流（FL2VA）最吻合。prompt 反复写 “start exactly from the provided first frame … transition accurately to the provided final frame”本质上是给定两端的插值，考双视角同步，不考终态推断

VDR前缀视频 → 续写开源版没有续写工作流。视频只能作为参考片段输入，fal 把它定位为「motion」参考。托管 README 列了 video-to-video，但没说是哪种「续写」到底是真的从最后一帧往后接，还是「参考前缀、另起一段」？论文图 10 看不出来，正文也没说
AVIR视频 + 音频（续写或打红圈编辑）同 VDR，外加「编辑」。开源版没有编辑工作流定位类题目的音频是口述句子（如 “Kick the ball to the middle.”）。开源路径要从音频 latent 里「听懂一句话」；托管路径大概率由 Context-IR 先转成文字
关键推论

如果作者用的是托管 API：被测的是「Context-IR（多模型推理流水线）+ H3-Base」这个组合。H3 官方自己就说，跨模态关联与复杂逻辑推理是 Context-IR 做的。那么把结果归因于 “multimodal alignment in a shared latent framework” 就站不住，这 41.97% 很可能主要反映 Context-IR 这个理解模块的水平。

如果用的是开源权重：音频从来不经过任何语义编码器，VDR / AVIR 也没有原生的续写与编辑入口。那么「ADR 最低、VDR 最高」有相当一部分可能来自接口语义，而不是推理能力。

两种情况论文都没排除。对本仓库更实际的一点是：如果你在开源 H3 上做世界模型（SolarWM 用 LoRA 微调了 H3-33B，LynnReal-Omni 直接以 H3 为底座），这篇的数字不一定适用于你手里的权重。

§ 841.97% 里有多少是「推理」失败？

论文 §4.5 自己承认：“A failed output may arise from incorrect input understanding, weak cross-modal integration, or errors during video generation. Further controlled experiments, such as removing individual modalities or replacing audio while keeping the visual input fixed, could help separate these factors.” 也就是说，每道题的一个 0/1 实际上是一长串环节的乘积：

感知看到或听到了证据隔离手段：去掉该模态 / 换成无关音频
整合推断确定「该生成什么」隔离手段：把答案写进 prompt，看差多少
渲染把事件画对、不违反物理隔离手段：显式 prompt oracle 给出上限 r
专家判 1三人交叉核对未报告一致性 κ，也没说聚合规则

论文只报告了整条链的乘积。下面用 ADR 演示为什么这很要紧。论文展示的 6 个 ADR 例子（图 3 一个、图 11 五个）全都是左右两个候选声源，引言里的杯子例子是三个。设想一个完全不听音频的模型：它从 c 个候选里随机挑一个来动，并且只要挑对了就有概率 r 把事件画对。这个「盲听」模型的成功率是 r / c。

§ 9失败模式：四类，三类在「渲染」这一侧

§4.4 与图 13、14 把失败归成四类。论文没给各类的频数，所以看不出哪一类占主导。但按上面的链条来分，四类里只有第一类明确是「推理 / 锚定」失败，其余三类都发生在渲染阶段。

① 证据锚定错误 推理侧

认出了一个合理事件，却把证据安到了错误的对象或动作上。

图 13(a) 猫叫却让狗动了；13(c) 两种清洁机器的声音分不清。

② 事件没实现 渲染侧

相关物体都在画面里，但隐含的交互没发生。

图 13(b) 打字声却没有打字；13(d) 开罐头，小物体交互失败。

③ 物理 / 构型违例 渲染侧

接触动力学、几何或状态转移出错。

图 14(a) 滑板、(b) 轮胎压杯、(f) 滚球；(c) 滑块拼图、(d) 魔方的细粒度操作。

§ 10存疑清单

先说公道话：做对的地方
  • 问题框架有价值。「不告诉模型结局，让它从分布在多模态里的观测去推」，比现有 VBench / WorldModelBench 那种「照 prompt 画」更接近世界模型该考的东西。
  • ADR 的设计很干净。两个都能发声的候选，由音频决定是哪个。这天然适合做反事实：换一段音频，被动的物体就该跟着换（§11 第 1 条）。
  • 数字全部自洽，表 2 可以完整还原成整数计数。
  • 作者没有掩饰失败：给出了失败分类和图例，§4.5 也主动承认结果混杂了几种因素，并提出了该做的消融。
筛选
H1高被测对象不清：论文从未提到 H3-Context-IR，也没说用的是 API 还是开源权重

MiniMax 在开源公告里写明，Context-IR 是托管的预处理与编排系统，由「多阶段工作流与多个托管模型和服务」组成，负责 “instruction parsing, cross-modal association, temporal understanding, and complex logical reasoning”，然后把理解结果序列化给 H3-Base。本文测的正是这些能力，却把结果归因于 “multimodal alignment … in a shared latent framework”。

论文图 2 称 H3 为 “open-weight”，但开源权重里恰恰没有这个组件。两种路径下，谁在做推理完全不同（§7）。

证据：arXiv 全文无 “Context-IR”“API”“checkpoint”“Ref2VA/FL2VA” 等字样；GitHub README 也未说明推理设置。

H2高标题与摘要提的问题（「多模态对齐能否提升世界推理」）没有被回答

要回答「能否提升」，至少需要一个比较：去掉某一路模态、替换音频、换一个对齐更弱的模型，或者与显式 prompt 对比。本文一样都没做，只有一个单点成功率。§4.5 原话承认 “Further controlled experiments, such as removing individual modalities or replacing audio while keeping the visual input fixed, could help separate these factors”。结论段却仍写 “revealing a substantial gap between omni-modal input support and effective physical-world reasoning”。

H3高没有上下界基线，连「H3 有没有用上音频」都判断不了

缺三类基线：显式 prompt oracle（渲染上限 r）、去模态 / 盲测（下限），以及机会基线。§8 的计算表明，在 c = 2 的 ADR 题上，只要 r 落在 0.42–0.70 之间，27.4% 就和「完全不听音频、随机挑一个」在统计上无法区分。而 r 这个量本文没有测。

H4高人工评测协议不透明
  • 三位专家 “independently evaluate … and then cross-check their judgments”：没有一致性指标（Cohen / Fleiss κ），也没说分歧怎么定（多数票还是协商）。
  • 没说是否盲评。专家很可能就是作者，而且知道被测模型是谁。
  • 判分依据是每题的「语义目标」和场景级的一句话标准，rubric 与语义目标均未发布。
  • 结果只有二元的成败，没有部分得分，也没区分「选对了但画坏了」这种情况，而这恰恰是 §8 需要的信息。
H5高完全无法复现：生成设置为零，数据与结果仍为 TODO

接口 / checkpoint、输出时长、分辨率、采样步数、种子、每题采样几次（单次 pass@1 还是多次取最好）全都没写。H3 输出是随机的，单种子的 517 次二元判定本身就带着采样方差。GitHub 仓库目前只有 README 和 15 个以上的 VDR 样例视频，「开源评测数据集」和「开源评测结果」都标着 TODO。

M1中子类层面的结论大多是噪声

子类同质性检验：MSR p = 0.54，AVIR p = 0.65，都看不出子类间有真实差异。VDR p = 0.047 主要由 Traffic 9/9 与 Puzzles 1/6 驱动。正文却逐条解读 “threading 75% / pouring 58.3% vs cleaning, articulation, transport 33–35%”、“cartoons 20% / puzzles 16.67%”。这些格子的 N 只有 5–8。见 §5 森林图。

M2中「Implicit」被当成全体题目的二元属性，实际隐式程度差别很大

MSR 的展示 prompt 直接写出任务名（“Put the inner pot and the steamer tray into the rice cooker.”），末帧还把终态给了出来；公式 (2) 描述的「K 个视角图、推断单视角看不到的关系」和实际做法（并排双视角、给首尾帧的插值）并不一致。VDR 有的 prompt 把镜头动作写明，有的点名「温度与气压」这两个因果变量。连 ADR 图 3 的例子也有轻微倾向：左边的木板写着「待锯」，右边的电锯写着「已关机」。见 §6。

M3中场景分数与接口语义耦合

按公开接口推断：图 + 音只能走参考模式（参考图不绑定几何，模型得先按文字重画场景）；视频只能作为参考片段；开源版没有续写和编辑入口。因此 ADR 与 VDR 之间 28.6 个百分点的差，有多少是「音频推理弱」，有多少是「音频这条通路本来就只有声学 latent」，又有多少是「VDR 前缀视频的像素直接进入了同一个 latent 空间」，本文的设计分不开。

M4中构造阶段可能按被测模型筛过题

“Each condition-prompt pair is verified to support the intended inference through video generation for MiniMax-H3”，再加上 “Pairs that fail review are revised … and then reassessed” 和「10 轮专家审核」。如果审核时看过 H3 的输出，那题库就是针对 H3 选择过的，偏差方向未知：可能删掉了 H3 完全做不了的题，也可能保留了它「差一点」的题。措辞有歧义，论文没澄清。

M5中只测一个模型，却把结论泛化到「Omni-Models」

结论写 “omni-modal generative models” 的推理差距，证据只有 H3 一个模型。同期已有功能相近的系统：作者用来造测试视频的 Seedance 2.0（2026-02）本身就支持 9 图 + 3 视频 + 3 音频混合参考，还支持视频延长与编辑。在真实数据子集上拿它做对照是可行的；在它自己生成的子集上则会有循环问题。

M6中表 1 的对比对象挑得太「显式」

表 1 只列了 VBench、TC-Bench、VideoPhy、WorldModelBench 四个显式 prompt 基准，于是「Implicit ✓ / Reasoning ✓」看上去是本文独有。但正文 Related Work 自己引用的 Physics-IQ（“without disclosing future outcomes”）、RISE-Video（“explicitly tests implicit world-rule reasoning”）、AV-Phys Bench（生成音视频流内部与之间的物理一致性）、ROVER（全模态生成的跨模态推理）都与本文更接近，却没有进表。表 1 里的 “Multi Scene” 一列也没有定义。

L1低「物理世界推理」的口径被稀释

子类里包括 Cartoons、Animation、Puzzles（滑块拼图、魔方），还有「在视频里画红圈」这种标注式编辑。部分前缀视频由 Seedance 2.0 生成，部分音频由 ChatGPT Voice 生成，合成素材本身的物理未必正确。VDR 的 Synthetic 子类有 19 题，但合成素材的总占比没有报告。

L2低只「omni」了输入，没有评输出音频

H3 会联合生成 32 kHz 立体声，但判分只看画面，生成的音频是否与事件一致从未评估。对一篇以「全模态」为卖点的评测来说，这是一块明显的空白。

L3低「Chain-of-Frames」与图 1 架构示意缺乏依据

“intermediate predictions can be interpreted as a form of Chain-of-Frames” 这句没有任何实验支撑。图 1 的「Modality Encoders → Cross-Modal Alignment → Unified Tokens」是作者自己画的抽象图，与 H3 文档里的实际组件（Qwen3-VL-32B 编码器 + 视频 / 音频 VAE + 33.1B 单流主干 + 托管 Context-IR）对不上，却放在「Omni-Model」框里，容易让人误以为这就是 H3 的结构。

L4低文字与引用瑕疵

“Omni-Modes”（§3 首段）、“Phys. Aaware”（表 1），以及 “We demonstrate that this prompt construction follows two criteria”，但后文其实没有任何论证。Related Work 的「视频生成评测」一段里，引用了多篇作者自己的方法论文（MagDiff、DynamiCtrl、LSTD、CameraNoise、SPEED、RefocusEraser），它们并不是评测工作。

§ 11最值钱的几个补充实验

按「花最少的力气、最能把分数拆开」排序。前两个不需要新数据，拿现有 517 题就能做。

ADR 反事实换音频

同一张图，只把音频换成另一个候选的声音。被动的物体应该跟着换。看「成对一致率」：它直接度量模型用没用上音频，而且对渲染质量不敏感，因为两次画得一样差也能判出来。对应 H3、M3。

显式 prompt oracle

把被隐藏的信息写回 prompt 重跑一遍，得到渲染上限 r。「推理差距 = SR显式 − SR隐式」才是标题问题的答案。对应 H2、H3。

去模态 / 盲测

去掉音频、只给末帧、打乱两个视角，得到下限。如果去掉音频后 ADR 还剩 25%，那 27.4% 基本就是盲猜。对应 H3。

托管 vs 开源，同题对跑

在同一批题上分别跑托管 API 和开源 Ref2VA / FL2VA，两者之差就是 Context-IR 的贡献。对在开源 H3 上做研究的人最有用。对应 H1。

多种子 + 一致性 + 公开 rubric

每题 ≥ 3 个种子，报告均值与方差；报告三位专家的 Fleiss κ；发布每题的语义目标。对应 H4、H5。

至少再测一个模型

比如在真实数据子集上测 Seedance 2.0，给 41.97% 一个参照：这到底算好还是算差？对应 M5。

§ 12定位：它在评测谱系里补了哪一格

下表中其他基准的描述，都取自本文 Related Work 自己的概括；「与本文关系」一列是我的判断。

基准本文对它的描述进了表 1 吗与本文关系

ROVER全模态生成中的互惠跨模态推理没进「全模态 + 推理」的直接前驱
WorldScore / WorldMark / Omni-WorldBench相机轨迹、控制对齐、动作相关的状态转移没进交互式世界模型评测，与本文互补
对本仓库（交互式视频世界模型）的意义

按本列表的范围，它是一个 benchmarks 条目，但考的不是交互式世界模型：没有逐步动作条件，没有流式生成，时长只有 5–15 秒的一次性生成。和世界模型最相关的只有 VDR 的 Memory（6 题，4 题成功）与 Traffic（9 题）两个小子类。

值得搬过来的是方法论：给世界模型一个前缀，让「正确的后果」必须从观测里推出来，而不是从 prompt 里读出来。搬的时候要把本文缺的三件套（显式上限、去模态下限、反事实对照）一起带上。
