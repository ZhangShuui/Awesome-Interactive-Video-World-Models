TourPhysics

给世界模型装一个事务日志：先算物理，再画图，画完过闸才允许写进世界

TourPhysics 的问题很具体：从一张图出发，让人既能推着相机四处走，又能动手戳、拉、吹场景里的东西，而且走远了再回来，那面墙还得是原来那面墙。 它的答案不是把这两件事都交给视频模型，而是把权限拆开：模拟器在任何像素被采样之前就把这一步的物理与相机轨迹算死， 由该轨迹渲出的几何记录 Gn 只读地负责投影、可见性、对应与评测， 视频扩散模型只负责在这条已经定死的轨迹上画出好看的观测， 而它画出来的东西必须先过一道 fail-closed 的质量门，通过了才连同物理终态一起原子提交——不通过就整窗回滚，记忆和世界状态都当无事发生。 一句话：生成的 RGB 可以扩充「我知道这里长什么样」，但永远不能改写「这里是什么状态」。

00 一图看懂

一次动作的完整数据流：三条支路，一个原子提交点

论文自己的 Fig. 2 把整套系统画成了三段。真正需要看懂的是中间那一段——一个动作对应一次事务。 下图把这次事务摊成三条泳道：物理支路决定「发生了什么」，观测支路决定「看起来什么样」，认知支路决定「我记住了什么」。 三条支路的读写权限完全不同，这就是整篇论文的全部主张。

它相比 PhysOmni 多了什么

PhysOmni（同组，ACM MM 2026）解决的是「从单图生成一段物理正确的视频并实时交互」。TourPhysics 保留了它的整套物理前端（分割 → 网格 → 重力对齐 → 多物理）， 加上四样在线的东西：跨动作的持久状态、动作边界处的轨迹模拟、事务化的观测发布、长程外观记忆。

它不解决什么

它不做「真实场景重建」。论文在 B.1 里写得很直白：基准测的是与声明轨迹的一致性，不测所声明的材料参数是不是这张照片里物体的真实参数。 单图给不出尺度、遮挡几何、密度、摩擦——这些都由用户在 Θdecl 里指定。

01 命题

观察 ≠ 干预：两件事都产出新画面，但只有一件改变世界

论文第一句话就是这个区分。移动相机会露出之前没看见的表面——世界没变，只是我对世界的知识变多了； 施加一个力会改变物体的位置、接触与形变——世界真的变了。当前视频世界模型的问题在于，它们用同一套「学到的外观先验」同时承担这两件事， 于是「画得像」被当成了「世界是这样」：回访时场景变了、时序缓存把幻觉一路带下去、规定的交互被模型自己的运动先验忽略掉。

这篇论文真正的技术形状 把术语翻译一下就很清楚了：clone / staged / atomic commit / rollback / retry / fail-closed gate——这是一套数据库事务协议， 只不过被套在了一个视频扩散模型外面。「世界状态」是数据库，「一次动作」是一个事务，「生成的 81 帧」是事务里的写操作， 「质量门」是提交前的约束检查，「记忆页与尾部证据」是只有提交后才对外可见的写集。 论文的贡献与其说是某个新模块，不如说是把权限边界画清楚并强制执行。

02 一次性预处理

场景抬升：把一张照片变成一个可以被戳的物理假设

这一步只做一次，在第一次交互之前。它要从一张欠定的图里造出一个内部自洽的场景假设， 并且把原图与它的标定几何永久冻结成只读参考 R。论文特别强调：这些校正属于「初始假设」， 不是在线的状态修正——运行起来之后没有任何一步会回头改它们。

边界条件

固定物体、地面支撑、粒子钉扎。论文举的例子：把一块布网格顶部若干比例的粒子钉住，就得到一面挂着的窗帘——Fig. 7(a) 的「风中被钉住的窗帘」正是这么来的。

外部力场

常量场、风场、点场、阻力场、涡场、湍流场、噪声场，每个都带激活时间表。这就是为什么「不下干预」的窗口里物理照样在动。

求解器默认值

步长 4 ms；纯刚体场景 10 个子步，含粒子材料 16 个；重力 (0, 0, −9.8)。MPM 域 [−3,3]³、粒子尺寸 0.02、网格密度 32；PBD 粒子尺寸 0.01。静态支撑是放在对齐后地面上的一个刚性平面。

为什么必须冻结

因为重试要能逐位复现同一条轨迹。若声明可以在线改，「同一个动作重试一次」就不再是同一个事务，回滚语义随之失效。冻结是事务协议的前提，不是工程偷懒。

04 核心机制

事务循环：一个动作 = 一次「要么全发生，要么没发生过」

这是整篇论文的心脏。把它拆成九个状态走一遍，就会发现每一条看似啰嗦的规定都在堵一个具体的漏洞： 为什么要克隆？为什么控制张量必须在采样前构造好？为什么暂存的记忆页在本窗口内自己都读不到？为什么重试只允许换种子？

因果性：记忆不能自己读自己

论文写得很死：本窗口生成的页不能被同一窗口内的另一帧选中，尾部证据也不能影响已经用来采样本窗的控制张量。 它们最早生效的时刻是下一个被接受的窗口。这条保证了记忆是因果的、深度补全分支在重试下是可复现的。

重试的严格语义

重试保持同一个已提交索引 n、同一动作、同一轨迹、同一几何记录、同一生成控制、同一已提交记忆，只有采样种子可以变。 阈值在一次尝试内固定、失败后绝不放宽。而且论文明说：实现不做自动重试，必须由调用方显式发起。

一个论文没有回答的问题 既然有一道会拒绝的门，那它到底拒了多少次？全文没有报告任何拒绝率 / 重试次数 / 每序列平均尝试次数。 这个数字很重要：如果拒绝率接近 0，那这道门在实验里其实没起作用，Table 2/3/4 的结果与「有没有门」无关； 如果拒绝率很高，那么生成成本与「在线」的可用性就要打折扣。两种情况下读者对这套机制的评价会很不一样。

06 两种深度

Dgeo 与 Dgen：一个用来算，一个用来画，绝不混用

这是论文两大「一致性机制」中的第一个，也是最容易被读漏的一个。系统里同时存在三个深度量： Dgeo 是有物理单位的米制深度，只有它能驱动投影、可见性、跨视对应与轨迹评测； Dbase 与 Dgen 是无量纲的归一化相对深度，只有后者被送进视频模型。 论文允许用「已接受的尾部证据」去补生成侧的深度控制，但这条通路只改视觉条件，绝不写 Dgeo、碰撞几何或物理状态。

DgenWn = (1 − Wn) ⊙ DbaseWn + Wn ⊙ DWn(En)Wn 在逐点资格测试之外一律为 0

这条通路的实际份量可能不大 尾部证据只取 Tn = {64, 68, 72, 76, 80} 五帧，还要同时满足七项阈值、至少两帧通过、并且只作用于「新暴露且米制支撑不足」的像素。 这是个刻意设计得极难触发的分支。论文没有报告它在基准上实际触发了多少比例的窗口，也没有单独消融它—— Table 4 消融的是缓存与外观记忆，深度补全分支始终开着。所以「分离深度」这条贡献里， 真正被实验支持的是「分离」（不混用），而不是「补全」（用历史补深度）。

07 时间与索引

60 fps 的模拟器怎么对齐 16 fps 的视频：一条去掉歧义的取整规则

模拟器控制记录按 fsim = 60 索引，生成观测按 fgen = 16。 论文用一条取箱中心的规则把两者钉死，并且明确规定：窗口的终态 X⁺, C⁺ 取在被采样的端点 kn(80) 上， 而不是原始原点 on + 300 上。这不是学究气——不把这个约定写死，重试就会「不小心把物理多推进一帧」。

08 外观记忆

参考锚定记忆：几何决定「能不能读」，置信决定「读多少」

这是第二个一致性机制。它要解决的失败模式很具体：相机绕了一大圈之后回到一面墙前， 有限的时序缓存早就把那面墙挤出去了。检索式方案会「贴回旧像素」，代价是布局与光照对不上。 TourPhysics 的做法是：用模拟器几何决定某个目标像素在哪一张早先视图里有可靠的静态对应， 只把那一页注意力特征（不是像素）以有界残差的方式掺进来；一旦对应不成立，输出精确回到原本的参考条件路径。

09 质量门

它到底查了什么：五个像素统计量的合取，仅此而已

「quality-gated commit」听起来很重，但拆开看，这道门完全建立在解码后的 8 位 RGB 帧上， 由五个极其朴素的统计量做合取判断：能不能正常解码、和上一窗的边界接不接得上、边界跳变相对窗内运动幅度是不是异常、黑屏比例、以及冻结比例。 没有任何一项检查物理是否正确。把下面的滑块拖一拖，就能看出这道门实际能挡住什么、挡不住什么。

最该记住的一句 这道门是一个 fail-closed 的「能不能发布」检查，不是物理保真度的评测——论文自己在 Sec. 4.6 第一句就这么写。 它挡得住：解码失败、黑屏、卡死、与上一窗接不上的跳变。它挡不住：物体穿模、接触时机错、形变量级不对、材料看起来不像声明的材料。 所以「质量门通过」不等于「这一窗物理正确」；真正衡量物理的是 Table 2 / Table 3 那些事后的成对指标，它们并不参与在线循环。 换句话说，论文架构图里那条诱人的「retry 闭环」并不是一条物理反馈回路——那条真正的物理反馈通路（erepr 清单）在实验里从未启用。

10 实验

基准怎么搭的，以及每个数字下面站着多少样本

基准是 108 条模拟器定义的交互序列，来自 61 个源图像身份（身份 = 输入图 SHA-256），覆盖纯相机巡游与刚体 / 布 / 弹性 / 颗粒 / 流体的操控。 关键前提论文写在 B.1：基准衡量的是与「所声明的」仿真轨迹的一致性，不检验所声明的材料参数是不是这张照片里物体的真实参数。 这决定了后面所有数字的解释边界。

11 局限

论文承认的，与我读下来还想追问的

论文自己在 C.2 里写的

① 造的是可控的物理假设，不是唯一的真实重建；符合声明轨迹 ≠ 真实世界物理正确。 ② 遮挡区与新暴露区的几何仍不完整。 ③ 外观记忆排除运动与形变物体，因此大形变之后物体自身的外观保不住。 ④ 相机或深度估计不准会直接减少有效跨视对应。 ⑤ 有限窗口扩散不是实时；未压缩的历史页数量随接受视图数无上限增长。

我读下来的补充追问

① 拒绝率缺失：这道门在实验中被触发过几次？没有数据就无法判断事务机制的实际份量。 ② 骨架与延迟缺失：视频扩散用的是哪个模型、多少参数、单窗多久，全文未给。 ③ 深度补全分支未被单独消融，「分离深度」的实验支持其实只落在「不混用」上。 ④ 碰撞类指标的有效支撑只有个位数记录，几个 <0.01% / >99.99% 的极端值实际上都来自 1–2 个事件。 ⑤ erepr 反馈重投影清单是唯一一条能把几何误差反馈进接受判据的通路，而它在所有报告运行中都没启用。

把它放回坐标系里 和 PhysGen3D（用户指定初始条件与材料的相机中心微缩世界）、PhysCtrl / PhysMotion（把物理当条件塞进生成）、 Physical Simulator In-the-Loop（先生成再重建再模拟再引导）相比，TourPhysics 的差异不在「用了模拟器」，而在因果顺序与写权限： 模拟器先把轨迹算死，生成器后在这条固定轨迹上画，并且画出来的东西不能反向修改轨迹或几何。 和 CUT3R 那类「边观察边更新共享点图」的持久表示相比，它反过来——拒绝让观测更新几何，几何只由声明与模拟器写。 这是一条相当强硬的设计取舍：换来了轨迹跟随与可回滚性，代价是场景几何永远只有初始假设那么好，观测再多也不会让它变准。

与本仓库的关联

这篇属于 interactive / world-model + 显式物理 那一支：和 OctWorld 这类「用显式三维记忆保长程一致」的工作解决的是同一个失败模式（回访不一致）， 但走的是相反的路径——OctWorld 让观测去更新几何（TSDF 融合生成的 RGB-D），TourPhysics 则禁止观测更新几何，只让它更新「外观知识」。 两者放在一起读，正好构成「持久性」这个问题上的一组对照：要不要让生成的内容获得几何权威。

一句话总结 TourPhysics 把一个视频世界模型改造成了带事务日志的系统：模拟器持有物理权威，几何记录只读，生成器只有绘制权， 所有视觉证据必须过门才能进入持久状态。它在轨迹跟随上拿到了明确优势，在长程漂移上给出了可复现的消融； 代价是场景几何被永久钉在初始假设上，而那道被反复强调的「质量门」在实现里只是五个像素统计量—— 它保证的是「这段视频能发布」，不是「这段物理是对的」。
