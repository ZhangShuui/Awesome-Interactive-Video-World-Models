DSA

在 Self-Forcing 的自回归学生上挂一个置信度头，让模型在跑完第 1 步之后就先自问一句「这块够干净了吗」——够就直接收工，不够就把剩下 3 步跑完。

这篇论文的真实贡献是一个提前退出（early-exit）开关，不是摘要字面上的「动态调整步数」。Algorithm 1 里的分支是二值的：要么 1 步，要么 4 步，中间没有 2 步和 3 步。它带来的是 1.35× 的吞吐（35 NFE → 23 NFE），延迟一点没动（0.90 s → 0.91 s，而且按算法首块必然满步）。表 1 里那些更漂亮的质量数字，来自换了个 14B 教师，与自适应采样无关。下面我会把论文没写出来的记账（NFE = 7 × (k+1)）反推出来，并指出一个同成本、零新增参数的静态基线——它的 NFE 恰好也是 23，而论文没有做这个对照。

00The whole thing in one figure

一图看懂：一个开关，装在「第 1 步之后」

Self-Forcing 的推理是这样的：把 21 个 latent 帧切成 7 个 chunk，每个 chunk 从纯噪声出发跑 4 步去噪，跑完再用一次 t=0 的前向把干净结果写进 KV cache，然后做下一个 chunk。DSA 只改了一件事：在第 1 步跑完、第 2 步开始之前，插一个 if。

它确实做到了
同质量下 1.35× 吞吐
把固定 4 步的 35 NFE 压到 23 NFE，VBench 总分从 83.94 变成 83.95。这个结论是干净的，而且在 1.3B / 14B 两个教师上都成立。
它没做到但听起来像做到了
「动态调整步数」
Algorithm 1 的分支是 if / else 二值：1 步或 4 步。正文写的「until the output stabilizes」在伪代码里没有对应物。
它不涉及
延迟
prev_c 初始化为 1.0，而 sigmoid 恒小于 1 → 第一个 chunk 必然走满步。所以首帧延迟只能和 SF 持平（0.91 vs 0.90 s）。
01Where the waste actually is

固定步数浪费在哪：先把账算清楚，论文没算

论文的出发点是一句很直觉的话：「有的帧好猜，有的帧难猜，凭什么都跑一样多步？」这句话没错，但要判断省下来的算力值不值得，得先知道一次生成到底做了多少次前向。论文给了消融表里的 NFE 数字，却没解释这些数字是怎么来的——而它们恰好藏着一个关键事实。

1.1把 14 / 21 / 28 / 35 这四个数拆开

消融表（Table 2）里，1/2/3/4 步对应 NFE = 14 / 21 / 28 / 35。等差为 7，且截距也是 7：

NFE = 7 × (k + 1)7 = chunk 个数（21 个 latent 帧 ÷ 每块 3 帧）；k = 每块去噪步数；那个 +1 是每块结束后用 t=0 再跑一次前向，把干净 latent 写进 KV cache。这一步在 Self-Forcing 的 Algorithm 1/2 里明确存在（kvi ← GKVθ(x̂0i; 0, KV)），在 DSA 的 Algorithm 1 第 15 行也在，但论文正文从未把它计入「步数」的讨论。
这个 +1 为什么重要
它把理论加速比的天花板压掉了一截。如果只看「步数」，4 步降到 1 步应该是 4×；算上每块那次省不掉的 cache 前向，实际是 35/14 = 2.5×。DSA 实测的 35→23 也只有 1.52× 的 NFE 比，考虑到还有约 1.5 s 的固定开销（文本编码 + VAE 解码，见 §07），落到墙钟上就是 1.35×。论文摘要里「real-time」的说法成立，但「adaptive computation」省下的份额，比不读记账时想象的要小。

1.2「难帧多跑步」这个直觉，有一个它没验证的前提

论文的动机链条是三段：(a) 视频里的帧难度不均；(b) 难度可以被模型自己估出来；(c) 给难帧多跑步能带来比给易帧多跑步更大的收益。(a) 显然成立，(b) 论文花了整节来做，而 (c) 整篇论文没有任何证据。

这不是吹毛求疵。(c) 完全可能不成立：一个 chunk 之所以「难」，可能是因为它的内容本身熵高（快速运动、复杂纹理），这类内容即使多跑 3 步也未必更接近教师；而一个「易」chunk 少跑 3 步造成的微小偏差，会通过 KV cache 一路传给后面所有 chunk。自回归生成里，误差的代价和它发生的位置有关，而不只和它的大小有关——这一点在 §06 的模拟器里可以直接玩到。

02The foundation it stands on

地基：Self-Forcing 的三件事，DSA 一件都没改

读 DSA 之前要先接受一个事实：它是 Self-Forcing 的一个 patch。学生结构、教师、损失、学习率、critic 更新比例、数据源全部沿用，连超参数值都一模一样。理解这三件事，DSA 的新增部分就只剩半页纸。

地基 ①
自 rollout：训练时就用自己生成的历史
Teacher Forcing 用真值历史、Diffusion Forcing 用加噪真值历史，两者在推理时都会碰上曝光偏差——推理时的历史是模型自己产的，训练时没见过。SF 直接在训练循环里做自回归 rollout，让训练分布 = 推理分布。代价是反传会爆，所以它只对每块的最后一步回传梯度（gradient truncation），并随机采样这个「最后一步」是第几步。
地基 ②
rolling KV cache：训练时也开
KV cache 原本只是推理优化。SF 把它挪到训练里，于是不需要特制的注意力掩码来模拟因果性——缓存本身就是因果的。副作用是每块结束后必须额外跑一次 t=0 前向来把干净 latent 写进缓存，这就是 §01 那个 +1。
地基 ③
DMD：对齐整段视频的分布，而不是逐帧回归
不做 per-frame 去噪损失，而是让学生生成的整段视频分布 pθ(x1:N) 去贴近数据分布。反向 KL 的梯度是两个分数网络之差：冻结教师 fφ（real score）减去可训 critic fψ（fake score）。好处：训练完全不需要真实视频，只需要文本 prompt。DSA 正是靠这一点宣称「no extra video data」。
∇θ Et[ DKL( pθ,t ‖ pdata,t ) ] = − E[ ( sreal(x̂t,t) − sfake(x̂t,t) ) · ∂x̂/∂θ ] 论文附录式 (5)。实现成式 (6) 那个带 stop-grad 的 L2 形式。请记住这个式子的形状：DMD 的残差是「两个分数网络之差」，不是「学生输出与教师输出之差」——§04 会用到这个区别。

03The confidence head, in parts

置信度头：从 DiT 身上抽三处特征，挤出一个标量

论文强调「little architectural modification」。具体有多 little？它在 DiT 的第 13 / 21 / 29 个 block 后各挂一个 cross-attention：用一个可学习 token 当 query，去 attend 该层的全部视觉 token，每层挤出一个 token；三个拼起来过一段 MLP，输出一个标量 logit，sigmoid 之后就是置信度。

这个设计的好处是真的
不需要独立的 critic 网络
对比 APT（Lin et al.）那种用单独判别器来估质量的做法，DSA 直接从生成器骨干里抽 logit，于是 x̂₀ 和 c 是同一次前向的两个输出。这意味着「先算质量分再决定要不要继续」这件事在推理时不增加任何一次完整前向——这是整套方案能真正提速的前提。
但有一处没说清
置信度损失的梯度会流回骨干吗
c 依赖骨干第 13/21/29 层的特征，所以 ∂Lconf/∂θbackbone 非零。论文没说是否对骨干停梯度。如果不停，那么置信度目标在改写生成器本身——它可能把特征推向「更容易预测 c」的方向而牺牲生成质量；如果停，那置信度头只能读一组它无法塑形的特征。两种设计的取舍完全不同，论文一个字没提。

3.1一个被术语掩盖的粒度问题：这不是 per-frame

论文从头到尾说「per-frame confidence」，Fig 1 的图注写「The number of diffusion steps adaptively changes at different frame」。但生成是 chunk-wise 的，一个 chunk = 3 个 latent 帧 ≈ 12 个像素帧；而置信度头一次前向只产出一个标量（1 个可学习 token → 1 个 logit）。

所以真实的自适应粒度是 7 档，每档 0.75 秒视频，不是 81 帧里的每一帧。这个差别对宣传图的说服力影响不小：Fig 1 那种「步数随帧起伏」的想象，在实现上最多是七级阶梯，而且每级只有两个取值。

04One line of loss, one closed form

损失函数：一行公式，一个闭式解，和一个 10 倍的矛盾

整篇论文新增的训练信号就是式 (4) 这一行。它长得像个正则化技巧，但它其实有精确的闭式最优解——把它解出来，就能看清置信度头到底被训练成了什么东西。

L = c ⊙ sg[ d( x̂G, x̂R ) ] − λ log c x̂G = 学生预测的干净 latent；x̂R = 冻结教师（real score network）对同一个加噪 latent 的一步去噪结果；d = 两者的 L2 距离；sg[·] = 停梯度；λ = 正则系数。形式上这是 ConfNet（Wan et al., ICASSP 2018）那一族的「学习型置信度」。

4.1对 c 求导置零：c* = λ / d

∂L/∂c = d − λ/c = 0 ⟹ c* = λ/d，再被 sigmoid 的值域截到 (0,1]，即 c* = min(1, λ/d)。两项的角色一目了然：第一项 c·d 把 c 往 0 压（残差大就别说自己行），第二项 −λ log c 把 c 往 1 拉（别一味认怂）。平衡点就是残差的倒数。

矛盾 · λ 有两个值
正文 §4.1 写 λ = 0.2，附录 §6 写 λ = 0.02。相差 10 倍，而从上图可以看到这不是一个无关紧要的差别：λ 定的是「多大的残差才配叫低置信度」的门槛。若残差的典型量级在 0.1 附近，λ=0.2 会让几乎所有 chunk 都落进饱和区（c*≡1，logit 被推向 +∞，梯度消失），整个自适应机制形同虚设；λ=0.02 才能让 c 落在有区分度的区间。我倾向于附录的 0.02 是实际使用值，但这只是根据机制合理性的推断，论文本身无法判定。

4.2一个更要紧的问题：d 不是 DMD 的残差

论文在式 (4) 后面写道：「whereas the DMD loss forces the generator to match the teacher by minimizing the residual between x̂G and x̂R, our confidence loss leverages this residual…」。这句话是不准确的，而且不是措辞问题。

DMD 实际在最小化的
两个分数网络之差
附录式 (6)：‖x̂ − sg[x̂ − (fψ − fφ)]‖²，梯度 ∝ (fψ − fφ)。这是 critic 与教师对同一个加噪样本的两个预测之差。当 pθ = pdata 时这一项→0。
置信度损失用的
学生输出与教师一步去噪之差
d(x̂G, x̂R)，只涉及教师，不涉及 critic。即使学生已经完美，这一项也不会趋于 0——教师对一个高噪声 latent 的一步去噪必然是后验均值（偏模糊），与任何一个具体的清晰样本都有距离。

这个区别的后果很具体：d 有一个不可约的下界，而这个下界随内容熵而变。快速运动、复杂纹理的 chunk，其后验方差天然更大，d 也就天然更高——哪怕它生成得完全没问题。于是置信度头学到的东西是「内容复杂度」与「生成误差」的混合物，而不是论文所说的「denoising reliability」或「self-calibrated uncertainty」。

这未必是坏事，但改变了故事
如果目标就是「复杂的 chunk 多跑步」，那么一个偏向内容复杂度的信号恰好合用。但论文卖的是「模型知道自己什么时候没做好」（self-assessment / calibrated uncertainty），这个说法需要的是误差信号而非难度信号。论文没有给任何校准曲线（置信度 vs 实际质量），所以两种解释都无法被排除。

4.3还有一处没交代：这一项和 DMD 损失怎么加

「The final training objective incorporates both the above confidence loss and the standard DMD loss.」——没有权重系数。DMD 损失的量级与置信度损失的量级不在一个刻度上（前者是 latent 空间的 L2，后者含一个 log 项），直接相加还是按某个比例相加，会显著影响训练动力学。这是复现这篇论文的第一个拦路虎。

05Line by line, where the claims break

Algorithm 1 逐行：三处正文没说、或与正文相反的东西

这一节是整篇论文里信息密度最高的地方。摘要说「dynamically adjusts the number of diffusion steps」，§3.3 说「continues denoising … until the output stabilizes」——但伪代码里既没有「number」的连续取值，也没有任何「stabilize」的判据。点任意一行看它实际在干什么。

5.1问题一：分支是二值的，不是「动态步数」

第 7 行的 if 在第 8 行的 for 之外，而 for j = T−1 downto 1 内部没有任何 break。所以每个 chunk 的步数只有两种可能：1 步（条件不成立）或 T 步（条件成立，T=4）。不存在 2 步和 3 步。

这与摘要「dynamically adjusts the number of diffusion steps」和 Fig 1 图注「The number of diffusion steps adaptively changes at different frame」的字面含义不符，也与 §3.3 的「until the output stabilizes」直接冲突——后者描述的是一个带停止判据的循环，伪代码里没有。两种可能：要么实现里有 break 而伪代码写漏了，要么伪代码是对的而正文写得过于宽泛。好消息是，NFE=23 这个数在两种读法下都成立（见 §07），所以这不影响速度结论，只影响对机制的理解。

5.2问题二：判据比较的是两个不同精炼程度的量

第 7 行比较 sigmoid(ci) 与 prev_c。但这两个数的来历完全不同：

左边
ci：本块只跑了 1 步之后的置信度
从纯高斯噪声出发的一次前向，t=1000。这是「我一步就画出来了，你看行不行」。
右边
prev_c：上一块收工时的置信度
第 14 行写的。如果上一块跑了满步，它是 4 步精炼后的值；如果上一块也提前退出，它才是 1 步的值。

于是这个判据的行为带有棘轮效应：一旦某块走了满步、把 prev_c 拉高，下一块的 1 步置信度就很难越过这个更高的门槛，于是也倾向走满步；反过来，连续提前退出会让门槛逐级下滑，进入「越省越敢省」的通道。论文自己也承认固定阈值不好使（「the threshold varies by frames and by videos」），但换上的这个相对判据同样是一个启发式——而摘要写的是「requires … no heuristics」。§06 的模拟器可以直接把这个动力学玩出来。

5.3问题三：时间步下标是错的

Require 里声明的时间步集合是 {t1, …, tT}，第 6 行用 tT 起手。但第 8–11 行的循环是 for j = T−1 downto 1，用的是 tj−1，即依次访问 tT−2, …, t0——跳过了 tT−1，并用到了未定义的 t0。对 T=4 与步表 {1000, 750, 500, 250} 而言，正确的序列显然应是 750 → 500 → 250。这是一个无害的排版笔误，但它是「伪代码没被仔细校对过」的直接证据，因此 §5.1 里「实现里可能有 break 只是没写」的可能性不能排除。

一个设计上的优点，论文自己没点出来
第 3 行 prev_c ← 1.0 配合第 7 行的严格小于号，意味着第一个 chunk 几乎必然走满步（sigmoid 的值域是开区间，恒 < 1）。这是个好设计：自回归生成里第一块的质量会通过 KV cache 影响之后所有块，把它锚死是对的。代价是首帧延迟无法被优化——这正好解释了表 1 里 0.91 s vs SF 的 0.90 s。对交互式应用来说，这是个需要注意的定位：DSA 优化的是稳态吞吐，不是响应延迟。
06Play with the scheduler

调度模拟器：把棘轮效应和级联退化玩出来

下面是一个按 Algorithm 1 第 3–14 行逐字实现的小模拟器。七个 chunk，每个给一个「内容难度」，模型据此产生 1 步置信度与 4 步置信度，然后跑论文的判据。你可以拖难度，也可以打开误差累积——后者是自回归模型的真实行为：前面偷工，后面更难。

玩法 ①　棘轮的滞后

09What I would push back on

我的存疑清单

先说立场：这篇论文的速度结论我认为是成立的——数字自洽、记账能对上、开销可忽略这一点有独立旁证。我的疑问集中在「因果归属」上：省下来的算力确实省下来了，但它是因为置信度信号选对了地方，还是因为第 4 步本来就没什么用？论文没有能区分这两者的实验。下面按我判断的严重程度排序，四条「高」里有三条作者补一张表就能解决。

高D1缺少同成本对照：静态前置排程的 NFE 恰好也是 23▶
现象

消融表只对比了「自适应 vs 固定 k 步」。但自适应的收益有两个可能来源：(a) 置信度信号把算力分配到了对的块；(b) 仅仅是少跑了一些边际收益很低的步，跟分到哪块无关。区分二者需要两个对照，论文一个都没做：① 同 NFE 的静态排程（前 3 块满步 + 后 4 块单步 = 23 NFE，见 §7.4）；② 同 NFE 的随机分配（随机挑 3 块跑满步）。

这是整篇论文唯一需要置信度头存在的理由。如果静态前置排程也能拿到 83.9x，那么这篇论文的 35M 新增参数、新增损失、新增训练全都可以删掉，收益不变。而从 Fig 6 能看到，固定步数曲线在 3 步（83.66）到 4 步（83.94）之间已经几乎平坦——边际收益本来就低，这让 (b) 成为一个相当有力的竞争假设。

怎么排除

高D2Algorithm 1 的分支是二值的，与摘要和 §3.3 的表述相冲突▶

高D4推理判据本身就是启发式，而摘要说「no heuristics」▶
现象

摘要与引言两次强调「requires no extra video data, no heuristics, and little architectural modification」。但 §3.3 的推理规则是：论文先否定了固定阈值（「suboptimal since we observe that the threshold varies by frames and by videos」），然后换成「与上一块比」。这个替代品同样是手工设计的规则，而且比固定阈值更难分析——它把决策变成了一个有状态的序贯过程。

为什么重要

除了表述问题，这个规则有两个结构性后果（§06 的模拟器可以复现）：棘轮效应——一次满步会抬高后续块的门槛，倾向于连锁满步；级联退化——连续提前退出会让门槛逐级下滑，在误差累积下形成「越省越敢省 → 质量掉 → 难度升 → 全满步」的震荡。论文承认长视频会退化（§5.1），但把原因归给通用的时序漂移，没有考察调度规则自身是否是贡献因素之一。

中D5λ 在正文与附录中相差 10 倍，且它单独决定了置信度的尺度▶
现象

§4.1 写 λ = 0.2，附录 §6 写 λ = 0.02。

为什么重要

置信度损失的闭式最优解是 c* = min(1, λ/d)（§04）。λ 不是一个无关紧要的正则强度，它就是「多大的残差算低置信度」的定义。取值偏大会让绝大多数块落进 c*≡1 的饱和区（logit→+∞，梯度消失），判据退化为比较浮点噪声；取值偏小会让 c 全都挤在接近 0 的区间。更根本地：既然 c 的绝对尺度由 λ 任意指定，论文所称的「self-calibrated uncertainty」就不成立——它是一个单调变换后的残差估计，不是校准过的概率。

怎么排除

勘误 λ，并报告 d 是按元素平均还是求和（latent 形状 3×16×60×104，两者相差约 3×10⁵ 倍，直接决定 c 落在哪）。另外给一张校准图：横轴 c，纵轴该块的实际质量指标。

中D6式 (1)/(3) 与 Fig 2 宣称「以置信度为条件」，但实现里 c 从未作为输入▶
现象

中D7d(x̂G, x̂R) 不是 DMD 的残差，且有随内容变化的不可约下界▶
现象

论文说「DMD loss forces the generator to match the teacher by minimizing the residual between x̂G and x̂R, our confidence loss leverages this residual」。但 DMD 的梯度是 (fψ − fφ)，即 critic 与教师两个分数预测之差；置信度损失用的是 ‖x̂G − x̂R‖，即学生输出与教师一步去噪之差。这是两个不同的量。

为什么重要

教师对高噪声 latent 的一步去噪是后验均值，天然偏模糊；即便学生完美地从数据分布采样，‖x̂G − x̂R‖ 也不会趋于 0，其下界由该内容的后验方差决定。于是快速运动、复杂纹理的块会系统性地得到低置信度——哪怕它生成得没有任何问题。置信度头因此是「内容复杂度 + 生成误差」的混合估计。这对「难块多跑步」的目标也许恰好有用，但对「模型知道自己何时没做好」的叙事是致命的。

怎么排除

做一个对照：在同一段内容上人为注入退化（如强行减步、加噪），看 c 是否随之下降；再在不同复杂度的内容上看 c 的分布。两条曲线的分离度就是「误差信号 vs 难度信号」的答案。

中D8通篇写「per-frame」，实际粒度是 per-chunk（3 个 latent 帧 ≈ 12 像素帧）▶

现象

Self-Forcing 原论文自述「real-time video generation at 17 FPS … on a single H100」，本文表 1 把它测成 15.30（且与 CausVid 完全相同，说明是按「同架构同 NFE」估的）。而本文自己的固定 4 步基线是 16.33——同样 35 NFE，比它重测的 SF 快 6.7%。附录提到本文用了 FlashAttention-3。

为什么重要

摘要和正文引用的「1.5× faster than Self-Forcing」里，约 1.07× 来自实现优化，1.35× 才来自方法。这个拆分论文自己已经具备（Table 2 的 4 步行），但没有明示。

怎么排除

在正文里直接写：「相对我们自己的固定 4 步基线，自适应带来 1.35× 加速」。这个数字更小但更可信，而且作者手里就有。

低D10Algorithm 1 第 8–11 行时间步下标 off-by-one▶
现象

Require 声明步集为 {t1,…,tT}，第 6 行用 tT；第 8 行 for j = T−1 downto 1，第 10–11 行用 tj−1，于是实际访问 tT−2…t0——跳过 tT−1，用到未定义的 t0。

为什么重要

本身无害（显然应是 750→500→250），但它说明伪代码没经过仔细校对，因此 D2 里「实现有 break 只是没写进伪代码」的可能性不能被排除。

怎么排除

改成 for j = T−1 downto 1: … Ψ(x̂₀, ε, tj) … Gθ(·; tj, K)。

低D11c 的记号在 logit 与概率之间反复横跳，Algorithm 1 疑似双重 sigmoid▶
现象

Fig 3 说头部末端「projected to yield a single scalar logit, which is finally converted to a confidence score via the sigmoid function」——即 c 已经是 (0,1) 内的概率。式 (4) 里有 log c，也要求 c ∈ (0,1]。但 §3.3 说「predicts both the denoised frame and its confidence logit ci」，Algorithm 1 第 7、14 行又写 sigmoid(ci)。

为什么重要

不影响结论（sigmoid 单调，第 7 行的比较不受影响，前提是第 14 行存的也是同一种量，而它确实是）。但它是读者理解式 (4) 的一个绊脚石。

怎么排除

统一记号：让 c 始终表示 sigmoid 之后的分数，Algorithm 1 里去掉多余的 sigmoid。

低D12三处设计选择零消融：抽头层 13/21/29、可学习 token 数 = 1、两个损失的相对权重▶
现象

「we extract and process features from DiT blocks 13, 21 and 29」——为什么是这三层？一层行不行？「a single learnable token as the query」——为什么是 1 个？最终目标「incorporates both the confidence loss and the standard DMD loss」——权重系数未给。整篇论文只有一个消融（固定步数 vs 自适应）。

为什么重要

这些是复现的必需信息，也是判断方法鲁棒性的依据。35M 参数的头部有没有过设计，从现有材料无法判断。

怎么排除

补一张小表：抽头层数 {1,2,3} × token 数 {1,4} 的置信度预测质量（比如与 d 的秩相关系数）。

低D13NFE 会随随机种子波动，但吞吐与延迟都只报了一个点估计▶
现象

第 5 行 x ~ N(0,I) 的抽样直接影响第 6 行的 x̂₀ 和 c，进而影响分支。同一个 prompt 换个种子，NFE 可能从 20 变成 29。论文只给了「22.01 FPS」一个数，没有方差、没有分位数、没有说明是多少个 prompt 的平均。

为什么重要

对离线批量生成，均值就够了。但论文的定位是「interactive video generation」——交互系统关心的是最坏情况和抖动。一个块从 2 次前向突变成 5 次，在 10.4 次前向/秒的速率下是 0.29 s 的突发延迟，足以在实时渲染里造成可感知的卡顿。

怎么排除

报告 NFE 的分布（跨 prompt × 跨种子）与 p95 的逐块生成时间。

低D141000 步训练里要同时收敛 DMD 与一个从零初始化的置信度头▶
现象

「Training runs for 1000 steps with batch size 128」。置信度头（≈35M 参数）是新增模块，从随机初始化开始学；同时生成器每 5 个 critic 步才更新一次，意味着生成器实际只更新了约 200 次。

为什么重要

短训练本身是优点（成本低），但它让「置信度头是否学到了有意义的信号」这件事更需要证据。而论文既没有给训练曲线，也没有给置信度与质量的相关性。在 D1 的对照补上之前，不能排除「置信度头输出的其实接近常数/噪声，而收益全部来自少跑步」。

怎么排除

给一条 c 与 d 的散点/秩相关随训练步数的变化曲线。若相关性显著且稳定，D1 的竞争假设会被大幅削弱。

11Where it sits

谱系与定位

11.1加速视频扩散的四条路，DSA 在哪条上

路线 A
少步蒸馏（step distillation）
把 50 步教师压成 4 步学生。DMD / DMD2 / SiD / PCM / APT。DSA 站在这条路的终点上——它不改蒸馏本身，只在已经压到 4 步之后再省。
路线 B
缓存复用（caching）
TeaCache、AdaCache、DeepCache、Block Caching：复用相邻去噪步之间变化不大的特征。DSA 在引言里把自己和这条路对立起来（「requires neither additional video data nor handcrafted heuristics」），但两者其实正交：缓存省的是单步内部的算力，DSA 省的是步数本身，理论上可叠加。论文没做这个组合实验。
路线 C
因果化 + KV cache
CausVid、Self-Forcing、MAGI-1、SkyReels-V2：把双向注意力换成因果注意力，换来流式生成与常数级增量成本。DSA 的全部地基。
路线 D
token / 分辨率削减
ToMe、VidToMe、区域化生成。与 DSA 正交，论文未讨论。

把 DSA 放进这张图里，它的位置很清楚：路线 A 之后的一个小增量，借用路线 B 的问题意识（自适应计算），但实现手段是砍步数而非复用特征。它的真正新意在于「用蒸馏目标的副产品（教师残差）来免费训练一个难度估计器」——这个想法是干净且可迁移的，即使这篇论文的具体调度规则被更好的规则取代，这个训练信号仍然值得留下。

11.2对「交互式视频世界模型」这条线意味着什么

先说不适用的部分
DSA 是纯文生视频：没有动作条件、没有交互接口、没有状态记忆机制、没有可控视角。它不是一个世界模型，也没有声称是。它与这条线的接口只有一个——推理效率。
  • 它优化的是吞吐，不是延迟。交互式世界模型的核心指标是「从用户输入到画面响应」的延迟和抖动。DSA 的首块必然满步（prev_c=1.0），延迟原地不动（0.91 vs 0.90 s）。如果你在做一个需要 <100 ms 响应的交互系统，这篇论文帮不上忙。
  • 可变算力对实时系统是负债不是资产。实时渲染需要的是确定的帧预算。一个块突然从 2 次前向变成 5 次，在 ~10 次前向/秒的速率下是 0.29 s 的突发。要用在交互系统里，得反过来设计：给定固定预算，让置信度信号决定怎么花（比如在预算内决定哪块多分一步），而不是决定花多少。这是一个值得做的改造，论文没往这个方向走。
  • 置信度信号本身对世界模型有独立价值。一个能在线判断「我这一块生成得有多可信」的标量，在世界模型里可以用来做：触发重新生成、切换到显式状态记忆、向下游策略暴露不确定度、或者作为长程漂移的早期报警。这个副产品可能比它的原用途（省步数）更有用——前提是 D7 先被回答清楚（它到底是误差信号还是难度信号）。
  • 长程漂移这个老问题它没解决，可能还加了一点。论文自己在 §5.1 承认长视频会退化。而 §06 的模拟显示，相对判据在误差累积下会形成「连续提前退出 → 门槛下滑」的通道。要用在长视频/世界模型上，判据至少要改成有绝对锚点的形式。

11.3一句话评价

这是一篇工程上干净、叙事上过度包装的短论文。它真实做到的事——「在 Self-Forcing 之上，用蒸馏的免费副产品训一个轻量难度估计器，把 NFE 从 35 降到 23 而质量不掉」——是一个值得发表的结果。但它把一个二值提前退出开关写成了「dynamic step allocation」，把换大教师的质量收益写进了自适应采样的功劳簿，并且没有做那个只需要改几行推理代码就能做的同成本对照。读这篇论文时，请把摘要的三句话拆成三件事分别验收。

C术语速查

NFE
Number of Function Evaluations，模型前向次数。本文里 包含每块结束时那次 t=0 的 KV 刷新——这是论文没说但消融表隐含的定义。
DMD
Distribution Matching Distillation。用反向 KL 把少步学生的输出分布贴近教师/数据分布，梯度是「冻结教师分数 − 可训 critic 分数」。不需要真实视频。
real score / critic
DMD 的两个辅助网络：real score（fφ，冻结的预训练教师）估数据分布的分数；critic（fψ，可训）估学生当前分布的分数。两者之差就是更新方向。
曝光偏差 exposure bias
训练时喂真值历史、推理时喂自己生成的历史，两者分布不同导致的误差累积。Self-Forcing 用训练期自 rollout 来消除。
Self-Forcing
本文的地基。训练时做自回归 rollout + rolling KV cache + 视频级分布匹配，只对每块最后一步回传梯度。
棘轮效应（本文用语）
指 ci < prev_c 这个相对判据的副作用：一次满步抬高门槛 → 后续倾向连锁满步；连续早退拉低门槛 → 越省越敢省。见 §5.2 与 §06。

  1. 先把 D1 补掉（同成本静态排程 + 随机分配）。这是判断整条路线是否值得投入的分水岭，改几行推理代码，不需要训练。
  2. 把判据改成预算约束下的分配问题：给定总 NFE 预算 B，用置信度做 7 块之间的排序，把额外步数分给最低置信度的若干块。这样既消除了棘轮，又给了实时系统确定的帧预算——对交互式世界模型来说这是必要改造。
  3. 把置信度信号拿去做别的事：长程漂移的早期报警、触发局部重生成、向下游策略暴露不确定度。这可能比省步数更有价值。做之前先回答 D7。
  4. 和缓存类方法叠加（TeaCache / AdaCache × DSA）。两者省的是不同的东西，论文自己把它们对立起来，但没有理由不能组合。
