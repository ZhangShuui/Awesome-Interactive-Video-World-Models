MotionSpec 精读

训练时把模型"一步去噪"得到的视频和真实视频都过一遍光流网络。先逐对比较相邻帧光流（LFC），再把 60 帧长的位移序列做时间傅里叶变换，比较幅度和相位（STC）。

想法清楚，改动也轻：在 FlowLoss 式的"光流对齐损失"外面，套了一层 Generative Image Dynamics 的"谱体积"表示，不改模型结构，也不增加推理开销。证据链有三处要打折。第一，VMBench 平均分 +2.89 里，LFC 单独就贡献 +1.91，而 LFC 与已有的 FlowLoss 几乎同构；STC 在 LFC 之上再加 +0.98，全表没有方差，也没有外部基线。第二，VideoJAM 的 Motion 分从 87.4 涨到 93.6，按 VBench 的聚合公式反推，主要是 dynamic degree 在涨，它衡量的是视频"动没动"，同期 VMBench 的幅度分 PAS 只涨了 0.8。第三，谱体积原本是为静态机位下树叶、烛火这类振荡运动设计的。放到跑步、骑车这类带平移和运镜的视频上，60 帧跨度的直接光流不处理遮挡和出画，频谱也会被斜坡泄漏主导，论文没有讨论这些。

§1一页读懂

一句话：在 flow matching 训练里加两个"光流空间"的辅助损失，一个管相邻两帧，一个管 60 帧的长程轨迹，后者放到频域里比。

三步版本

  1. 得到一段"预测视频"

    在任意时间步 t，用 x̂ = D(z_t − t·v_θ) 把模型的一步去噪结果解码成 81 帧像素视频，和这条样本的真实视频 x 配对。

  2. 两把光流尺子

    LFC 比较相邻帧光流 F_i，只在真实视频里动的区域计分。STC 从锚点帧 a 出发，算到后面第 1…60 帧的位移 G_{a,τ}，对每个像素做时间 FFT，比较前 16 个非零频率上的 log 幅度和相位。

  3. 低噪声时才认真算

    两项损失乘以 α(t)=(1−t)²，加在原来的 flow matching 损失上。实验只有一个设置：Wan2.1-T2V-1.3B，1 万条 OpenVid-1M 视频，256×256×81，单张 H200。

站得住的

  • 同数据、同配置下，LFC 和 STC 都比 FM-only 好，两者合用最好。FM-only 这个对照排除了"只是换了数据"的解释。
  • STC 的幅度/相位拆分、圆周相位距离、按目标幅度给相位降权，这几处设计干净，而且没有推理开销。

要打折的

  • +2.89 里 LFC 占 +1.91；平均分增益有 43% 来自 OIS（人体骨架）。
  • VideoJAM Motion 分的大涨，反推下来主要是 dynamic degree；PAS 几乎没动。
  • 没有方差和外部基线；光流网络型号、τm、τφ、wk、学习率、步数都没给。

论文没讨论的

  • 傅里叶表示与平移、运镜的视频不匹配；60 帧直接光流不处理遮挡和出画。
  • 损失集中在低噪声步，而粗粒度的运动在高噪声步就已成形。

§2背景：flow matching 损失为什么"看不见"动作

原损失逐元素比较 latent。颜色偏一点和物体挪一个像素，只要数值差一样，罚得就一样多。

Wan2.1 在 VAE 的 latent 空间里训练。训练目标（论文式 1）让网络预测的速度 v_θ 贴近 z₁ − z₀，是一个逐元素的 L2。模型从来没有被明确告知"这只手在下一帧去了哪里"，对应关系只能从大量数据里间接学到。

rectified flow zt = (1 − t)·z0 + t·z1,   z1 ~ 𝒩(0, I),   t = 0 为干净数据，t = 1 为纯噪声
x̂ = D(zt − t·vθ),    ẑ0 − z0 = −t·(vθ − (z1 − z0)) 第二行右式说明：flow matching 损失本身就等价于"按 t² 加权的 x₀ 回归"。MotionSpec 盯的还是同一个一步估计，只是先把 x̂ 和 x 都换算成光流，再在光流空间里量误差。

所以新损失没有引入新的数据或新的监督来源，它改变的是"哪种误差更贵"：位置和运动方向上的错误，在光流空间里被放大；纯颜色上的偏差，光流几乎看不到。

这一点决定了后面的很多判断

两个新损失都是逐样本的配对回归：预测视频和这条样本自己的真实视频比。它们不是分布层面的约束，也不直接作用在采样出来的视频上。§3 的动机图测的却是采样视频的分布，两者之间隔着一步推理，论文没有补上（§6、§9）。

§3动机：Fig. 1 说了什么，没说什么

生成视频的轨迹谱幅度整体偏低，这和"生成视频动得少"的常见观察一致。但"低频绝对差距最大"这个细节，几乎是任何带平移的轨迹都会自动产生的形状。

论文 Fig. 1 用 500 对生成/真实视频，各取开头 81 帧（16 fps），以第一帧为锚点算出每个像素的位移序列，再做时间 FFT。左图：非零频率上的平均幅度，生成视频在 x、y 两个方向都更低，低频处差得最多。右图：每条视频在 40 个频点上的 RMS 幅度分布，生成视频集中在 0 附近，真实视频更分散。80 个位移、16 fps 对应 0.2 Hz 的频率分辨率，正好 40 个正频点到 8 Hz，这和图注对得上。

动机图的四个缺口
  • 形状是自动的。只要轨迹里有平移，谱幅度就按 1/sin(πk/L) 从低频往高频衰减（推导见 §5.5）。生成视频哪怕只是整体慢一些，绝对差也一定是低频最大，而相对差在每个频点都一样。要说明"低频特别缺"，应该画相对差或 log 差。论文的 STC 恰好用 log 幅度，Fig. 1 却用的线性尺度。
  • 生成模型和数据来源没说。"generated videos in our evaluation" 是哪个模型、什么分辨率、用什么 prompt 没交代。如果真实视频来自按运动幅度筛过的训练子集（§7.1），差距会被放大。
  • 训练后没有重画。方法号称要缩小这个谱差距，但实验部分没有给出训练后的同一张图，动机和结果之间没有闭环。
  • 测的是采样视频，训的是一步估计。见 §2 的提示和 §6。

§4LFC：相邻帧光流，只看真实视频里在动的地方

81 帧给出 80 张相邻帧光流。预测视频也算 80 张，逐像素比较，但只在真实视频"在动"的区域计分。

式 (2)(3) Fi = O(xi, xi+1),   Mi(p) = clip(‖Fi(p)‖₂ / τm, 0, 1),   ρ(r) = √(‖r‖₂² + δ²)
LLFC = (1/(T−1)) Σi [ Σp Mi(p)·ρ(Fi(p) − F̂i(p)) ] / [ Σp Mi(p) + ε ] 掩码只由目标（真实视频）的光流决定。每帧先在掩码内求加权平均，再对 80 帧取平均。τm、δ、ε 的取值论文都没给。
  • 软掩码：真实视频里光流越大的像素权重越高，超过 τm 就封顶为 1；完全静止的像素权重为 0。
  • Charbonnier：大误差时像 L1，不会被个别离谱的光流值主导；在 0 附近可导。
  • 逐帧归一化：每帧的分数是"动的区域里平均差多少"，所以动得少的帧和动得多的帧权重一样。
单侧掩码的后果

掩码只看真实视频，所以预测视频在静止区域里多出来的运动，LFC 几乎看不见：背景的"呼吸"、纹理的漂移、镜头不该有的抖动，都落在 M ≈ 0 的格子里。这类错误只能靠 flow matching 损失和不加掩码的 STC 去管。它也许能解释一个现象：Table 1 里只加 LFC 的变体 PAS（感知运动幅度）最高，因为 LFC 只奖励"该动的地方动起来"，不惩罚"不该动的地方也动"。

和 FlowLoss 对照

论文把 FlowLoss 列为引用 [9]，但没有做对比。两者的核心完全一样：从一步去噪的预测视频和真实视频上各提一次光流，直接比较，并在高噪声时压低权重。

§5STC：把 60 帧的位移序列丢进 FFT

对每个像素、每个方向分量，把"从锚点帧出发，1 帧后、2 帧后……60 帧后分别挪了多远"这 60 个数当成一条时间信号，做一维傅里叶变换，再比较幅度和相位。

5.1 锚点与窗口

式 (4) Ga,τ = O(xa, xa+τ),   τ = 1, …, L;   a = 1, 1+s, 1+2s, …  且 a + L ≤ T 注意这是"锚点帧到第 a+τ 帧"的直接光流，不是逐帧串起来的跟踪轨迹。论文称之为 anchor-relative trajectory。L = 60、s = 10、T = 81 时只剩 3 个锚点。

论文说 L = 60、s = 10 的用意是"覆盖视频的前、中、后段，同时保持较长的时间跨度"。实际上 3 个窗口分别覆盖第 2–61、12–71、22–81 帧，中间 40 帧被三个窗口重复覆盖，开头 10 帧和结尾 10 帧各只被一个窗口看到。说成"前中后"有些夸大。

5.2 从位移到频谱

式 (5)(6) Sa,k(p, d) = Στ=1L Ga,τ(p, d) · exp(−j·2πk(τ−1)/L),   d ∈ {u, v}
丢掉 k = 0（DC），保留 k = 1…K;   Aa,k = log(1 + |Sa,k|) 按 16 fps 算（论文没写训练帧率，这里沿用 Wan 的默认值和 Fig. 1 的设定），L = 60 时频率分辨率是 16/60 ≈ 0.27 Hz，K = 16 保留 0.27–4.27 Hz，奈奎斯特频点是 k = 30。K = 16 这个数和 Generative Image Dynamics 相同。

整组 S_{a,k}(p, d) 就是"运动谱体积"（motion spectral volume）：每个像素位置上有 2 个方向 × 16 个频率的复数系数。这个表示来自 Generative Image Dynamics（GID，CVPR 2024），GID 用它从单张图片生成树叶、花、烛火的摆动。

5.3 幅度项和相位项

式 (7)–(11) Qa,k = clip(|Sa,k| / τφ, 0, 1),   dφ(s, ŝ) = 1 − Re(s·ŝ*) / (|s||ŝ| + ε)
Lamp = (1/|𝒜|) Σa Σk wk ⟨|Aa,k − Âa,k|⟩p,d,   Lphase = (1/|𝒜|) Σa Σk wk ⟨Qa,k·dφ(Sa,k, Ŝa,k)⟩p,d
LSTC = Lamp + λφ·Lphase ⟨·⟩p,d 是对所有像素和两个分量取平均，STC 没有运动掩码。wk 归一化到和为 1，但具体取值没给。τφ 和 ε 也没给。

幅度：比"动了多少"

取 log 之后，大运动和小运动之间的差距被压扁，比较的更像是运动大小的比例。整条轨迹等比例缩成 s 倍时，在幅度大的频点上 log(1+s|S|) − log(1+|S|) ≈ log s，罚分大约是 |log s|，和运动本身有多大无关。

相位：比"什么时候、往哪边动"

d_φ ≈ 1 − cos Δφ，是圆周上的距离，不会在 ±π 处跳变，这比 SMA 直接相减角度要合理。目标幅度太小的频点，相位只是噪声，用 Q 把它们的权重降到 0。注意 Q 只看目标，不看预测（§5.6）。

5.4 轨迹实验室

下面是单个像素、单个方向分量上的 STC，参数按论文设置：L = 60，K = 16，16 fps，wk 取均匀。目标轨迹由"匀速平移 + 正弦摆动"组成，预测轨迹可以在速度、摆幅、频率、时间上各错一点，也可以反向或者半路停住。先点预设看几种典型错误各被哪一项抓住。

5.5 匀速平移的频谱长什么样

设一个像素每帧匀速挪 v 像素，G_τ = v·τ。代入式 (5)，对 k ≠ 0 有闭式解（我用数值 FFT 核对过，前 16 个频点完全一致）：

推导 |Sk| = v·L / (2·sin(πk/L)),    arg Sk = π/2 + πk/L  （v > 0；v < 0 时整体再加 π） L = 60：k = 1, 2, 4, 8, 16 时 |Sk| 分别是 573v、287v、144v、73.8v、40.4v，k = 1 是 k = 16 的 14 倍。
  • 相位与速度大小无关，只由 k 和 v 的正负决定。对平移来说，相位损失只检查"方向对不对"。方向完全反了时，dφ = 2，而幅度损失为 0。
  • 幅度按 1/sin(πk/L) 衰减。这是 DFT 把 60 帧窗口当成周期信号、首尾接不上造成的"泄漏"，视频里并没有真实的 0.27 Hz 运动。
  • 于是"低频管慢趋势、高频管快变化"只对周期运动成立。带平移的轨迹，所有频点都被同一个斜坡污染，摆动的峰被压在 1/k 的尾巴上。常见的处理是先减掉线性趋势，或者加 Hann 窗，论文都没有做。
  • GID 的数据全是静态机位下的振荡运动，而且 GID 在局限一节写明：非振荡运动和大位移会失败。MotionSpec 的定性例子却都是跑步、骑车、转呼啦圈，其中前三个是明显的平移或运镜场景。

5.6 相位损失的数值脾气

把预测系数写成 ŝ = r·e^{jθ}。在 Δφ = π/2 处，dφ 对 ŝ 的梯度大小是 |s| / (|s|·r + ε)，r 不太小时约等于 1/r。Q 只按目标幅度门控，所以目标在动、预测几乎不动的频点上，相位梯度会很大，最大到 |s|/ε。这恰好是论文动机里的场景（生成视频运动偏弱）。另一头，d_φ = 1 − cos Δφ 的导数是 sin Δφ，在方向完全相反（Δφ = π）时为 0，相位项对"整段反着动"几乎没有推力。

实际训练里有两点会缓和这个问题：α(t) 让损失主要作用在低噪声步，这时预测和目标本来就接近；而且梯度还要经过光流网络和解码器才回到 DiT。论文没有给 ε，也没有讨论训练稳定性。

5.7 频域损失和时域损失，差别只可能来自四处

按 Parseval 定理，如果在所有频率上用 L2 直接比较复数谱，结果和时域 L2 完全等价，只差一个常数 L。所以 STC 和"直接比较 Ga,τ"的区别只能来自：

  1. 对幅度取 log，压缩了大运动；
  2. 丢掉了 DC（整段位移之和，也就是这段时间里走了多远的主体信息）；
  3. 只保留 k ≤ 16，相当于一个低通；
  4. 相位按目标幅度门控，加上频率权重 wk。

Table 3 的"time-domain"消融没有写具体形式（L1 还是 Charbonnier、有没有掩码、是不是同样的锚点），所以没法判断 STC 的 +0.47 来自哪一处。表里还有一个细节：只加幅度（64.52）和只加相位（64.47）都低于简单的时域损失（64.60），两者合起来才更高（65.07）。

§6时间步权重：损失在哪些噪声水平上真正起作用

α(t) = (1−t)γ，γ = 2。t 越接近纯噪声，一步估计越模糊，光流越不可靠，所以压低权重。代价是损失几乎只在低噪声段起作用。

两难

粗粒度的运动在高噪声段就定下来了。VideoJAM 在附录里说明，它只在前一半采样步使用运动引导，因为"这些步决定了视频的粗运动"。MotionSpec 的权重把光流损失集中在低噪声段，而在低噪声段，zt 里已经含有大部分真实运动，x̂ 的光流很大程度上是直接从输入"抄"出来的。

在高噪声段硬加又有偏差。MSE 训练下，最优的一步估计是条件期望 E[x₀ | zt]，也就是多种可能动作的平均。要求这个平均的光流贴合某一条具体样本，会把速度场从条件期望拉开，模型学到的不再是精确的概率流。α 小时偏差小，作用也小。

论文没有 γ 的消融，也没有按噪声段拆开看增益。它的实验能说明"加了有用"，不能说明"为什么有用"：可能是改善了低噪声段的细节（肢体结构，对应 OIS 的上涨），而不是改变了运动本身。

VideoJAM 附录写明：Motion 分由 VBench 的 motion smoothness 和 dynamic degree 按 VBench 论文的权重聚合。我按 VBench 官方的归一化常数和权重（dynamic degree 权重 0.5）写出下面的式子，用 VideoJAM 自己表里的 10 个模型核对，重算值与报告值相差不超过 0.3：

我反推的公式 Mot = [ (MS − 0.706) / (0.9975 − 0.706) + 0.5·DD ] / 1.5 MS 是 motion smoothness（各家模型都在 0.97–0.99 之间，接近上限），DD 是 dynamic degree：用 RAFT 光流判断一条视频"算不算在动"，再统计比例。Appearance 分同理可由四项 VBench 指标重算，同样吻合。

结论：Mot. 从 85.3 涨到 93.61，只靠 MS 做不到（MS 本来就贴着上限，而且运动越多 MS 通常越低，VideoJAM 附录也讲过这个此消彼长），必须由 DD 大幅上涨撑起来。完整方法的 DD 至少 80.8%。DD 衡量的是"动没动"，由 RAFT 光流判定，和训练用的光流损失同源；训练数据又是按运动幅度筛过的。所以 Mot. 的 +6.2（相对 FM-only）主要说明视频更常被判为"在动"，不能直接读作"运动更合理"。同一批变体在 VMBench 的 PAS 上几乎没变化，两个指标对"动得多"的定义不同（PAS 看主体关键点位移并扣除镜头运动），论文没有解释这个差异。

§8定位：哪些零件是新的

MotionSpec ≈ FlowLoss 式的光流对齐 + GID 的谱体积 + SMA 式的幅度/相位拆分。新东西是把三者接在一起，并把相位距离换成了圆周形式。

MotionSpec 是双向注意力的文生视频训练技巧：没有逐步的动作条件，也不是因果或流式生成。按 how-to-contribute 的三条标准，它不该打 systems 标签。它对世界模型的意义在于训练期的运动损失能不能迁过去。LFC 和短窗口的 STC 可以直接用在自回归模型的 self-rollout 输出上；60 帧的锚点窗口要一次解码整段视频，在逐 chunk 生成的训练里需要重新设计窗口，也要处理跨 chunk 的梯度。

§9存疑清单

按严重度排序，共 20 条。"高"指会改变对主要结论的判断，"中"指削弱某一部分论证，"低"指细节或写作问题。每条都附了能直接回答它的实验。

  1. 高增益的大头来自 LFC，而 LFC 基本就是 FlowLoss#1 · 贡献归因

    相对 FM-only，只加 LFC 是 +1.91，只加 STC 是 +1.49，STC 叠在 LFC 之上是 +0.98。LFC 的形式（一步去噪视频与真实视频的光流直接比较、低噪声加权）和论文自己引用的 FlowLoss 一致，差别只在掩码、Charbonnier 和权重函数。标题和贡献都落在 STC 上，但在主指标 VMBench 平均分上，STC 单独不如 LFC 单独。

    怎么验证：加入 FlowLoss 原式作为基线；报告 STC 叠在不同光流损失实现上的增量。

  2. 高没有方差、种子和置信区间，消融结论落在噪声范围内#2 · 统计

    Table 2、3 里各变体的平均分差距是 0.05–0.5 分。论文据此得出"幅度项改善平滑度和结构稳定性，相位项改善时间连贯性"的分工，但完整方法的 MSS（89.99）反而低于只加幅度（90.21）和时域损失（90.12）。按 §7.7 的假设性估算（σ = 12，ρ = 0.5），两倍标准误约 0.74 分，Table 2、3 里只有"完整方法相对 LFC"的 +0.98 超过它。

    怎么验证：至少 3 个训练种子 × 固定的采样种子；对每个 prompt 做配对 bootstrap，报告平均分差的置信区间。

  3. 高VideoJAM "Mot." 的大涨主要是 dynamic degree#3 · 指标解读

    按 VBench 的聚合公式反推（§7.5，用 VideoJAM 原表核对过），Mot. 从 85.3 到 93.61 必须靠 dynamic degree 的上涨撑起，完整方法的 DD 至少 80.8%。DD 由 RAFT 光流判断"动没动"，和训练用的光流损失同源，训练数据又按运动幅度筛过。同期 VMBench 的 PAS 只 +0.83。论文把 Mot. 当作"运动质量"来引用，但它在这里主要反映"动得更多"。

    怎么验证：报告 VBench 的 motion smoothness 和 dynamic degree 分项；补 FVD 或人评。

  4. 高没有任何外部方法对比#4 · 实验设计

    对照只有原始 Wan2.1、FM-only 和自家消融。VideoJAM、Track4Gen、FlowLoss、Physics-guided motion loss、SMA 都在参考文献里，没有一个进表；FlowMo、SpecLoR 这类推理期方法也没有比较。"consistent improvements" 只能读作"相对自己的基线"。

    怎么验证：同 backbone、同数据、同训练预算下复现至少 FlowLoss 和 Physics-guided motion loss（两者都是即插即用的损失）。

  5. 中动机和结果之间没有闭环#5 · 动机

    Fig. 1 的论点是"生成视频的轨迹谱幅度偏弱"。但训练后没有重画这张图；STC 也没有让 PAS 变大，叠在 LFC 之上还让 PAS 下降了 0.53。数据筛选和 LFC 对"动起来"的贡献，比 STC 更直接。

    怎么验证：对 FM-only、+LFC、+STC、完整方法各生成 500 条视频，重画 Fig. 1，并改用相对差或 log 差。

  6. 中损失作用在低噪声的一步估计上，粗运动却在高噪声段成形#6 · 训练机制

    α(t) = (1−t)² 把损失集中在低噪声段，此时输入里已经有大部分真实运动。高噪声段的最优一步估计是条件期望，强迫它贴合单条样本的光流会让速度场偏离概率流（§6）。论文没有 γ 的消融，没说 t 的采样分布和是否用了 timestep shift，也没说 α 用 t 还是 σ。

    怎么验证：扫 γ ∈ {0, 1, 2, 4}；把损失只加在某一噪声段，分别看 OIS 和 PAS 的变化。

  7. 中60 帧直接光流不处理遮挡、出画和运镜#7 · 表示

    Ga,τ = O(xa, xa+τ) 最长跨 3.75 秒，没有前后向一致性检查，也没有遮挡掩码。STC 不加运动掩码，对所有像素平均。跑步、骑车这类跟拍镜头里，背景像素几帧后就出画，之后的"轨迹"没有意义，却和前景一样计分。FlowLoss 至少用了带遮挡估计的 DOT 并给遮挡区降权。

    怎么验证：统计 Ga,60 的前后向一致性误差；加遮挡掩码或运动掩码后重跑 STC。

  8. 中傅里叶表示和非周期运动不匹配#8 · 表示

    对匀速平移，|Sk| ∝ 1/sin(πk/L)，相位 = π/2 + πk/L，与速度大小无关（§5.5）。所有频点都被斜坡的泄漏占据，"低频管趋势、高频管细节"的解释只对周期运动成立。论文没有去趋势，也没有加窗。

    怎么验证：对比"去线性趋势后再 FFT"和"Hann 窗"两种变体；按周期运动与平移运动分层报告增益。

  9. 中时域消融的定义缺失，说明不了"频域分解"本身有用#9 · 消融

    按 Parseval 定理，STC 与时域损失的差别只可能来自 log 压缩、去 DC、低通 K = 16 和相位门控（§5.7）。Table 3 没写时域损失的具体形式。另外，只加幅度（64.52）和只加相位（64.47）都低于时域损失（64.60）。

    怎么验证：给出时域损失的公式；补"时域 + log 压缩""全频带 STC""保留 DC"三个变体。

  10. 中平均分增益集中在 OIS，也就是人体骨架#10 · 指标解读

    完整方法相对 FM-only 的 +2.89 里，OIS 占 43%。OIS 用 MMPose 检查肢体长度和角度的突变，只对含人的视频有意义，在 256×256 下关键点检测本身也更不稳。训练集按"人、物体、复杂运动"筛选，定性例子全是人。非人运动（动物、刚体、流体）的收益不明。

    怎么验证：按 VMBench 的六类运动（流体、生物、机械、天气、群体、能量传递）分别报告。

  11. 中关键超参和实现细节缺失，代码未公开#11 · 可复现

    没给：光流网络的型号、迭代次数和输入分辨率；τm、δ、ε、τφ、wk；学习率、步数、batch、全参还是 LoRA；t 的采样和 shift；训练帧率；评测分辨率、采样步数、CFG、种子和样本数；数据筛选阈值；Fig. 1 的生成模型。完整清单见 §10。

    怎么验证：放出代码和配置文件。

  12. 中计算成本没有报告#12 · 成本

    每个训练样本要把 81 帧解码到像素，再跑约 260 次带梯度的光流并反传。FlowLoss 在 14 帧视频上报告训练时间增加 10%–82%。MotionSpec 的帧数和光流调用都多得多，但没给每步耗时和显存。

    怎么验证：报告 FM-only、+LFC、+STC、完整方法的每步耗时和峰值显存。

  13. 低相位项的梯度在两头都有问题#13 · 数值

    梯度约为 1/|ŝ|，目标在动而预测几乎不动时会很大（上限 |s|/ε）；Q 只看目标幅度，拦不住这种情况。另一头，方向完全反了时 sin Δφ = 0，相位项没有推力（§5.6）。低噪声加权会缓和前一个问题，论文没给 ε，也没讨论训练稳定性。

    怎么验证：记录训练中相位项梯度范数的分布；对比用 min(|s|, |ŝ|) 做门控的版本。

  14. 低LFC 的掩码只看目标，静止区域的伪运动它看不见#14 · 损失设计

    背景漂移、纹理"呼吸"落在 M ≈ 0 的区域，只能靠 FM 损失和 STC 去管（§4 演示）。这可能是只加 LFC 时 PAS 最高的原因之一。

    怎么验证：对比"目标 ∪ 预测"取并集的掩码；报告背景区域的 warping error。

  15. 低"前、中、后段"其实是三个大幅重叠的窗口#15 · 细节

    锚点 1、11、21 的窗口覆盖第 2–61、12–71、22–81 帧，中间 40 帧被看了三次，首尾各 10 帧只被看一次。Ga,1 还与 LFC 的 Fa 重复。L、s、K 都没有敏感性分析。

    怎么验证：扫 L ∈ {20, 40, 60, 80}、s ∈ {5, 10, 20}、K ∈ {4, 8, 16, 29}。

  16. 低Fig. 1 的"低频差距最大"被 1/k 形状自动解释#16 · 动机

    整体等比例变慢就会产生同样的形状（§3 演示）。图也没说生成视频来自哪个模型，真实视频是否来自按运动筛过的子集。

    怎么验证：改画相对差；说明两组视频的来源。

  17. 低定性例子和机制对不上，且都来自评测集#17 · 定性

    第 1 组"倒着骑车"是身体朝向错误，光流对朝向几乎不敏感；第 4 组的衣服颜色一致性也不是光流能约束的。四条 prompt 全部出自 VideoJAM-bench，没有失败案例，也没有 FM-only 的对照图。

    怎么验证：给出同 prompt、同种子下 FM-only 与完整方法的对照；随机抽样而非挑选。

  18. 低相关工作的遗漏与归类#18 · 引用

    SpecLoR（2606.11969，x̂₀ 频谱幅度校正，同样用 log(1+A)，同样在 VideoJAM-bench 上评测）和 FlowMo 没有引用。FreeInit [15] 讲的是初始噪声的低频成分，作者自引的 FREAK [18] 是音频驱动的说话人像，把它们归为"用谱正则改进视频运动"比较牵强。SMA [16] 已经做过"运动信号的时间维频域对齐 + 幅度/相位损失"，论文说前人"没有显式对齐稠密运动轨迹的时间谱"，区别只在光流轨迹与 latent 帧差、FFT 与小波这一层。

    怎么验证：在相关工作里补上这些，并写清与 SMA 的具体差异。

  19. 低记号和笔误#19 · 写作

    Fig. 2 说模型输入"timestep t, noise level σ"，但式 (12) 的 α 只写 t；在带 shift 的调度下两者差别很大（§6）。另有 "o n the dataset"、"root-mean-squar"、"the gain of STC merely come from" 等笔误。

    怎么验证：统一记号，写明 α 的自变量。

  20. 低规模有限，基线的评测条件没说#20 · 外推

    只有一个 1.3B backbone、256×256、1 万条视频、单卡。Wan2.1 基线在什么分辨率上评测没有说明：如果也是 256×256，这对 Wan2.1 属于分布外，FM-only 的 +0.61 可能部分来自分辨率适配。更大模型、更高分辨率、更长视频上是否成立都未验证。

    怎么验证：写明基线的评测设置；至少在一个更大的 backbone 或 480p 上复现主表。

§11公道话，以及最值得补的实验

做对了的地方
  • FM-only 对照。用同一批数据、同样配置只跑 flow matching，把"换了数据"带来的 +0.61 单独剥出来。很多同类工作漏掉这一步。
  • 相位用圆周距离，并按目标幅度降权。避开了 ±π 处的跳变和"零幅度处相位是噪声"两个坑，比 SMA 直接相减角度更讲究。
  • 即插即用。不改结构，不增加推理开销，训练代码只多两个损失。
  • 有幅度/相位拆分和时域对照的消融，方向是对的，只是缺方差和形式说明。
  • 表格算术一致，定性部分的措辞也比较克制（"may contribute"）。

最值得补的六个实验

  1. 外部基线

    同 backbone、同数据、同预算下加入 FlowLoss 和 Physics-guided motion loss，最好再加一个 VideoJAM 的光流预测头。

  2. 方差与分项

    3 个训练种子，配对 bootstrap 的置信区间；报告 VBench 的 motion smoothness 和 dynamic degree 分项；补 FVD 或 2AFC 人评。

  3. 闭合动机

    训练后重画 Fig. 1，用相对差或 log 差，看谱差距有没有缩小。

  4. 拆开 STC

    时域 L1 + log 压缩；保留 DC；K ∈ {4, 8, 16, 29}；去线性趋势或加 Hann 窗；加遮挡掩码；扫 L、s、γ、τφ。

  5. 按运动类型分层

    人、动物、刚体、流体；固定机位与运镜；周期运动与平移。这能直接检验"谱表示适合什么运动"。

  6. 成本

    每步耗时、峰值显存，和 FM-only 对比。
