AlayaVista

把 360° 全景视频的潜变量当成世界状态，只把你此刻真正在看的那一块做到高保真。

这篇的核心动作只有一个：把「视口选择」提前到「高保真合成」之前。 世界在一个 960×480 的全景潜空间里低成本地往前滚，用户要看哪儿，就把那一块投影出来，再单独把这一块做超分与细节生成。 论文用 Gibson「视野有界、世界无界」和人眼「周边低频 + 中央高锐」的类比来包装它，但真正决定这套设计上下限的，是一个论文没有明说的事实： 以相机为中心的全景态，对「转头」是一份精确、完整、零成本的记忆；对「走路」则什么也不是。 本文把方法拆开讲清楚，把论文没算的账算一遍，并列出我认为最需要追问的 12 处。

世界状态
全景视频潜变量
不是 3DGS、不是 mesh、不是 point cloud，也不是显式空间记忆库， 而是一串 30×60×48 的 ERP latent，以相机为中心随时间演化。 好处：任何时刻天球上每个方向都有值，转头不需要任何检索； 代价：没有度量尺度、没有深度、没有遮挡关系。
交互界面
视口是后选的
yaw / pitch / FOV 改变不需要重跑世界模型——它们只喂给 R_ψ。 这是这套架构里最被低估的性质：同一份全景态可以同时渲多个视口、可以事后改视角、 可以把转头的延迟压到只剩「渲染 + 精修」。论文没有强调，也没有做这个实验。
画质来源
细节是现编的

如果只记一句话

02What the state actually remembers

全景态到底是什么：一份只对旋转有效的记忆

论文反复说全景态「保住了画面外的内容」。这句话是对的，但只对一类相机运动成立。 把这件事想清楚，这篇论文的每一个实验数字就都有解释了。

论文对 Zpan1:T 的定义写得很谨慎： 「一个以演化中的相机位姿为中心的全向视觉表征，而不是显式的度量 3D 地图」。 这两句话分别对应两种截然不同的能力：

  • 「全向」意味着在任意时刻 t，天球上每一个方向都有一个已经算好的 latent 值。 用户把视角从正前方甩到正后方，不需要检索、不需要重新生成、不需要任何记忆机制——那块内容就在当前这一帧的 ERP 里。 这是纯透视模型要靠地标库和长上下文才能勉强做到的事。
  • 「以相机为中心 / 非度量」意味着一旦相机平移，整张全景图的内容必须按视差重排： 近处的东西横向扫过去、正前方的东西放大、被前景挡住的东西露出来。 这一切都得由 Gθ 自己「想」出来，因为状态里既没有深度也没有尺度。 在这件事上，AlayaVista 和一个纯透视世界模型没有本质区别。

我的判断：这篇的正确读法

不要把 AlayaVista 读成「更省的全景世界模型」，而要读成 「一个把旋转记忆外包给表征、把平移记忆继续留给模型去扛的透视世界模型」。 在以转头为主的交互里（VR 看片、街景漫游、监控巡视、固定机位的场景理解），这套设计的收益是实打实的； 在以走动为主的交互里（游戏、导航、具身智能），它相对纯透视方案的额外收益要小得多， 而多出来的约 78% 全景分支计算是照付不误的。

03ERP-aware backbone

ERP 几何三件套：位置编码、VAE 边界、时序切块

主干是 Wan2.2-TI2V-5B（30 层 / 隐藏维 3072 / 24 头 / 48 通道 latent / 16×16×4 压缩）， 文本条件与 flow-matching 参数化原样保留，只改三处：位置编码、VAE 的边界填充、时序注意力的因果结构。 这是一套低侵入的适配，不是重新设计的骨干。

3.1球面 RoPE：把宽度轴换成两条球面路径

把一张 2:1 的 ERP 图直接喂给一个在透视视频上预训练的 DiT，有两个几何谎言： 最左列和最右列在球上是邻居，但在 RoPE 里相距最远；以及 越靠近极点，同样的经度差对应的实际角度越小，但 RoPE 一视同仁。 论文按 SpheRoPE 的做法替换掉宽度轴的 RoPE（时间轴与高度轴不动）：

  • 高频通道用整数经度谐波：相位是 λ 的整数倍，于是 λ = −180° 与 λ = +180° 的相位严格相等，接缝自然连续。
  • 低频通道用连续球面坐标，正比于 cos φ · cos λ 与 cos φ · sin λ——正是单位球面点的 x、y 分量。 它们同样跨接缝连续，而且 cos φ 会随纬度升高而衰减，从而「降低极点附近对经度的依赖」。
我在这里的一个追问

低频通道用 cos φ·cos λ 与 cos φ·sin λ，在极点处 cos φ → 0，两个坐标同时趋近于 0。 这意味着最上一行（或最下一行）的所有 token，在低频相位上几乎完全相同—— 它们彼此的可区分性只剩下高度轴 RoPE，而同一行的高度轴坐标又是一样的。 「降低极点附近的经度依赖」是设计意图，但它的副作用是极点整行位置退化。 对 ERP 来说极区本来就是过采样、像素最冗余的地方，退化也许无害；但论文既没有讨论，也没有做极区的消融。 如果实际渲染里看到天顶/天底（nadir patch 那一带）出现旋转性伪影或涂抹，第一嫌疑就在这里。

3.2VAE：只改填充，不动权重

全景 VAE 在编解码时对空间卷积与重采样算子沿经度方向改用循环填充， 时间轴与纬度轴的填充保持原样；VAE 权重全程冻结；空间 tiling 被关闭，以免在图内部引入人造边界。

三个值得注意的后果：

  • 零样本换填充。卷积核是在零填充/复制填充下训练出来的，现在换成循环填充却不微调。 这跟 SpheRoPE 那条「zero-shot、免优化」的路线是一致的，但意味着接缝列的特征统计对 VAE 来说是 OOD 的， 残留误差会被冻结进编解码器，只能由 Gθ 学着去补偿。
  • 关 tiling = 一次性吃下整张图。960×480 尚可，但训练时若用更高分辨率的 ERP 来构造监督，显存压力是实打实的。论文没给任何显存或卡型信息。
  • 只处理了经度环绕，没处理极点拓扑。ERP 的上下边界在球面上各自坍缩成一个点， 正确的填充应当是「跨极点绕到对侧经度」。论文明确说纬度填充保持原样，也就是极点仍然被当成普通的图像上下边界。

3.3切块与缓存：1 秒一块，缓存没说有界

块内双向、块间因果。一块 = 4 个 latent slice，按 Wan VAE 的 4× 时间压缩换算 ≈ 16 帧 RGB @ 16 FPS = 1.0 秒。 单图起步时，把扩张出来的全景图重复 13 帧再编码，得到 4 个 slice 的干净初始化块 （这正好对上 Wan VAE 的 Tlat = 1 + (T−1)/4：13 帧 → 1 + 3 = 4 ✓）。

原生自注意力与全景 UCPE 注意力各自维护一份 KV cache，时间偏移对齐， 于是每一块都能复用此前生成的全景特征而不必重算历史。

把轨迹按「平均每帧位移」归一，等价于告诉模型「你只需要知道往哪走、怎么拐，不需要知道走多快」。 推理时用户给的轨迹同样会被归一，所以「向前走 1 米」和「向前走 5 米」在条件里可能是同一条轨迹—— 差别只剩下 ViPE 重估时的尺度对齐。这和以相机为中心的全景态本身没有度量尺度是同一个问题的两面。

另一处细节：这条旁路用的是「压缩过的注意力特征」（compressed attention features）+ 每个 transformer block 的零初始化输出投影。 零初始化保证训练起点等于预训练模型，压缩降低了旁路成本——但两者都作用在输出幅度上，不改变 logit 的尺度，所以上面的分析不受影响。 论文没给压缩比，这是复现清单上的一条（§12）。
05Latent viewport rendering

潜空间视口渲染：用一个网络去逼近一个确定性算子

这是全篇最新的一个模块，也是唯一一个完全没有量化评估的模块。 它要做的事听起来很朴素：把 ERP 潜变量里对应视口的那一块取出来，变成透视潜变量。难点在于latent 对几何形变不等变。

训练目标由一个确定性参考算子定义——把全景 latent 解码成 RGB、做球心投影（gnomonic）、再用标准透视 VAE 编码回去：

Eq. 4Zview,∗ = EWan( Wκ( Dpan(Zpan) ) ) 部署时这条 RGB 路径被丢掉，换成一个在 latent 空间里学到的映射。几何决定采样位置，网络只学 VAE 特有的非线性修正。
Eq. 5Zview,LR = Sκ(Zpan) + ΔZglobal + ΔZlocal Sκ 是几何条件下的双线性 latent 采样（保留显式几何先验）；ΔZglobal 来自一个分解式视频 transformer，ΔZlocal 来自一个只看 4×4 ERP latent 邻域的零初始化局部重采样适配器。两者先后训练：先训全局，冻住，再拟合局部。

5.1为什么不能直接做解析投影

因为 Wan VAE 是 16×16×4 压缩：一个 latent 元素编码的是一个 16×16 像素块（× 4 帧）的非线性摘要。 球心投影在这个块内部是不均匀的——靠近视口中心几乎等比、靠近边缘被拉伸、跨越接缝时还要换块。 对 RGB 做双线性重采样是正确的；对 latent 做同样的事只是一个粗糙近似，误差随视场角和纬度增大。 所以论文的做法是：保留双线性采样作为「载体」，用两路残差把 VAE 的非线性补回来。这与 §06 里上采样器「NN 载体 + 零初始残差」是同一个套路。

几个实现细节值得记住：

  • 透视 query 由几何对齐的 ERP 邻居 + 分数采样偏移 + 球面位置与畸变特征构成——即把「我该去 ERP 的哪个亚像素位置取样、那里畸变多大」显式写进 query。
  • cross-attention 带一个软几何偏置，由投影足迹（projection footprint）与相机运动扫过的范围导出，之后再做透视空间与时间自注意力。
  • 因为每个非初始 latent slice 代表 4 帧 RGB，模块每个 slice 保留 4 个视口位姿锚点，而不是把块内的相机运动塌成一个位姿。
  • 训练用的视口轨迹覆盖静止、平滑、快速、整圈自转、跨接缝五类。
  • 监督 = 通道归一化的 latent 重建 + 一阶/二阶时间差分 + 解码后的感知相似度、图像梯度、高频时间一致性。
一个容易被漏掉的事实：这个「渲染」同时还是一次 2× 超分

ERP latent 是 30×60。90° 视场在赤道上只占 60 / 4 = 15 个 latent 列，竖直方向约 9.8 个 latent 行。 而输出是 18×32。也就是说 Rψ 不是「取一块」，它是「取一块，同时在 latent 空间里放大约 2.1 倍」。 再经过 Uω 的 2×，从全景态到 carrier 一共放大约 4.3 倍。 论文把 Rψ 描述为逼近一个确定性投影算子，但那个参考算子 Eq.(4) 里的 Wκ 同样包含了这次放大—— 所以「确定性目标」本身就含有一段没有信息来源的插值。

06Perspective refiner

精修分支：carrier 是什么，那 94% 的细节从哪来

精修分成两截：一个确定性的 latent 上采样器 Uω，和一个生成式的精修网络 Fφ。 分工很明确：前者负责把画幅撑到 1024×576 并锁住布局与运动，后者负责把纹理编出来。

6.1Uω：最近邻做载体，零初始化残差做修正

Eq. 6ΔZraw = Aω( μ + s ⊙ Zview,LR ) ，   C = NN2×(Zview,LR) + ΔZraw ⊘ s μ, s ∈ ℝ48 是 Wan VAE 的固定逐通道均值与标准差。输入先反归一化到原始 latent 域（LTX-2 上采样器的惯例），输出再除以 s 换回归一化单位。 因为加的是差值，μ 的偏置自然抵消，所以只除 s 不减 μ 是正确的。Aω 的最后一层投影零初始化，训练从「就是最近邻」起步。 结构上是 3D 残差块 + 空间 PixelShuffle：只翻空间，不动时间长度。18×32 → 36×64，即 512×288 → 1024×576。

训练目标也是一个确定性算子：把 LR latent 解码、做 2× bicubic、再编码回来（Eq. 14）。 输入混合了三种来源——真实视频的 ERP latent、双向全景生成、四步全景生成——每一种都用自己的 LR 输入构造自己的目标，保持确定性对应。 这是个干净的设计：Uω 学的是「VAE 域里的 2× 放大」，而不是「猜细节」。猜细节的活全部留给 Fφ。

6.2Fφ：把 carrier 重新加噪，再把干净的 carrier 当参考贴在后面

Eq. 7 / 8Xn,σ₀ = (1 − σ₀)Cn + σ₀ϵn ，   序列布局 = [ Ẑn−1 , Xn,σ , Cn ] 同一份 carrier 被用了两次：一次作为加噪起点（决定它能偏离多远），一次作为零扩散时刻的干净对齐条件（决定它不能偏离到哪去）。 前一块的精修结果 Ẑn−1 作为干净前缀（第一块没有）。块内双向、块间因果，只解码当前目标 token。

三个数值得记：一块 = 4 个 latent slice；蒸馏后每块 4 步；长视频直接拼接，没有重叠融合 （不过 §3.1 的符号说明里提到 Fφ「在需要时包含重叠融合」，正文与符号表在这一点上口径不一致）。

序列一共 12 个 slice：4 个前缀 + 4 个噪声目标 + 4 个干净 carrier。按 1×2×2 的 patch 换算， 目标 2,304 token，条件 4,608 token，合计 6,912 token——上下文是恒定的，不随 rollout 变长，这一点和全景分支形成对比。

两个直接影响结论的未知数

① σ₀ 没给。重加噪水平是这个模块最关键的超参：σ₀ 小 → 输出紧贴 carrier、细节贫瘠但稳定；σ₀ 大 → 细节丰富但会偏离几何、也更容易在块间跳变。 论文连一个数值区间都没有，这意味着 Table 1 的 Quality / Consistency / Dynamic 三个数完全无法解释——它们首先是 σ₀ 的函数。

② 前缀只有 1 块。纹理的时间一致性只靠前 1 秒的干净前缀维持。 对连续画面够用；但对「转开 20 秒再转回来」这种 revisit，前缀早就滚走了， 全景态能保住布局，保不住纹理——同一面墙第二次看到时的砖缝不必和第一次一样。 论文在摘要和结论里两次声称验证了「viewpoint-revisit consistency」，但正文里没有任何 revisit 实验（见 D1）。

7.1两处蒸馏的公式差异

Eq. 13g = ( Ẑfake − Ẑreal ) / ( mean( Ẑstu − Ẑreal ) + ε ) 全景分支的 DMD 更新方向。

8.1为什么非要 4K：把监督分辨率倒推回去

精修器的目标是 1024×576 的透视视频。要从 ERP 里无插值地裁出这样一块（90° FOV、平视）， 需要的 ERP 角密度至少是透视图中心的角密度：

Dpersp = (Wout/2) / tan(FOV/2) = 512 / 1 = 512 px/rad = 8.94 px/度
⟹ WERP ≥ 360 × 8.94 ≈ 3,217 px 4K ERP 通常是 3840×1920，3840 ≥ 3217 ✓，还留 19% 余量；而 2.5K（2560）就不够了。 也就是说「≥4K」这个筛选条件，正好是把精修器的监督喂满的最低门槛。这个推导论文没写，但数字咬得很紧，我倾向于认为是反推出来的设计。
同理，帧率 ≥ 30 FPS 的门槛对应模型的 16 FPS 时基——但 30 → 16 不是整数倍，必然要重采样。 论文没说重采样策略（抽帧 / 插值 / 变速），而这会直接影响运动的时间统计。相比之下 30 → 15 是干净的，模型却选了 16。

8.2标注：分层，且把「主体动」和「相机动」拆开

标注沿用 AlayaWorld 的方案，MUGEN 与 Sekai2 走同一条流水线，从而可以直接混训。 ERP 帧不切成立方体面，整张喂给 VLM，每帧带 [mm:ss] 时间戳，采样率 1–2 FPS。

  • 视频级：天气、时段、地点类型、相机视角、相机运动、视频风格——受控词表，用于全局条件与平衡采样。
  • 片段级（带 time_range_s）：四条正交轨道——subject_motion / environment_motion / static_scene / camera_description。 把主体运动与相机行为显式分开，是为了让模型能区分「人在走」和「相机在推」、「物体在转」和「相机在绕」。这一条对相机可控性是关键的。
  • 提示词：融合成 5–9 句现在时的 full_prompt，外加 15–45 词的 short_prompt 用于 caption dropout 与多描述增广。
  • 相机路径标签：每段一个 16 类离散标签，与主体运动独立定义，与连续逐帧轨迹互补。

9.214 dB 的 PSNR 是什么概念

FIG 11把三个 PSNR 放到尺子上
Consistency 和 Dynamic 天生互斥，赢一个输一个不构成证据

VBench 的 Consistency 本质是帧间特征相似度，Dynamic Degree 本质是光流幅度上的一个二值判定再取平均。 一个视频越少变化，前者越高、后者越低。AlayaVista 拿到最高的 Consistency（0.9240）和最低的 Dynamic（0.9200）， 正是「更平滑 = 更少运动」的典型指纹。论文把它解释成「潜空间渲染与精修可能衰减了局部运动」——诚实，但没有继续追。

还有一个更值得注意的读法：Dynamic Degree 是逐视频的二值判定，0.9200 意味着 200 个视频里约 16 个被判为「基本静止」。 在一个每一例都有相机运动的评测集上，这更像一个失败率，而不是一个风格偏好。MoVerse 的 1.0000（200/200 全判为动）作为对照，这个差距不小。

还有一层容易被忽略的关系：AlayaVista 站在 HY-World 2.0 的肩膀上

AlayaVista 的第一步——把单张透视图扩成 360° 全景——用的正是 HY-World 2.0 的全景模型（冻结）。 所以表 1 的这一行对比，准确的读法不是「A 打败了 B」，而是 「给定 B 的全景扩张结果，我们的时间演化 + 视口合成路线，比 B 自己的 3DGS 路线更接近参考视频」。 这是个合理且有价值的结论，但和「整体更强」不是一回事。论文没有把这层关系说破。

高D4零消融：核心新模块一个对照实验都没有▶
现状

论文提出了至少 6 个可独立开关的设计：球面 RoPE、经度循环填充、全景 UCPE 旁路、潜空间渲染模块（全局残差 / 局部适配器）、carrier 条件精修、稀疏谱锚点。 表 1 里一个都没有单独验证。只有「AlayaVista 整体 vs 两个外部基线」。

最该补的三条
  • Rψ 的上下界：用 Eq.(4) 的解码–投影–编码算子替换 Rψ（上界）；用纯双线性 Sκ（下界）。这直接回答「这个模块值不值」。
  • 球面 RoPE 与循环填充：关掉之后接缝处的失效程度。这是最容易做、也最能说明 ERP 适配有效的实验。
  • 稀疏谱锚点：开/关的长程漂移曲线。这是唯一的抗漂移机制。
一个附带的困难

因为训练是分阶段且逐级冻结的，很多消融需要重训下游模块才公平（比如改了 Rψ，精修器就得重训）。 这可能正是没做消融的现实原因——但它同时也说明这套分段式训练的迭代成本很高，是这条技术路线本身的一个代价。

中D5渲染模块只见过真实 latent，部署时却吃生成 latent▶
论文自己的两句话放在一起看
§3.6.2（渲染模块）：We train the render module with cached panoramic–perspective latent pairs ... The inputs are derived from real panoramic videos.

§3.6.3（上采样器）：Inputs are mixed from real-video ERP latents, bidirectional panoramic generations, and four-step panoramic generations, all processed by the fixed render module.
问题

下游的 Uω 特意混入了三种分布来消除训练/部署差，上游的 Rψ 却没有。 而 Rψ 学的恰恰是「VAE 特有的非线性修正」——这种修正是对输入 latent 的统计分布敏感的。 4 步蒸馏生成器吐出的 latent，在高频能量、通道相关性、时间平滑度上都不可能和真实视频编码出来的 latent 一致。

为什么它可能被掩盖了

因为 Uω 和 Fφ 在训练时见过「Rψ 处理生成 latent 之后的结果」，所以下游会学着去补偿上游的这个误差。 也就是说系统整体不会崩，但 Rψ 的几何保真度在生成分布上是没有被直接监督过的—— 这可能正是 Dynamic 偏低、局部运动被衰减的一个来源。

怎么验

在生成 latent 上直接比较 Rψ 的输出与 Eq.(4) 参考算子的输出（latent 域 L2 + 解码后 LPIPS），并和真实 latent 上的同一指标对照。差多少，一目了然。

中D6轨迹重缩放丢掉了绝对尺度，而 TransErr 正是在尺度上评的▶
论文原文
Camera poses are expressed relative to the first frame, and moving trajectories are rescaled using their mean displacement between adjacent latent frames; near-static trajectories are left unchanged.
两个后果

① 能力上：「向前走 1 米」和「向前走 5 米」在条件里可能变成同一条轨迹——模型学到的是方向与形状，不是速度与距离。 再叠加全景态本身没有度量尺度，这套系统在原理上就不该被期望精确跟随平移幅度。

② 评测上：TransErr 的计算方式是用 ViPE 从生成视频里重估轨迹，再与输入轨迹比。 如果生成轨迹的尺度是任意的，这个比较必然依赖某种尺度对齐（Umeyama 对齐 / 归一化 / 尺度自由）。 论文只说「following CameraCtrl」，没有说具体怎么对齐。对一个尺度已知被破坏的方法来说，这一句必须写清楚。

另一层（我的推导，论文未提）

见 §04：Γ = I ⊗ T 里的 T 是带平移的齐次矩阵，不保范，logit 尺度随 ‖t‖² 增长。 所以重缩放很可能首先是数值必需品，其次才是数据增广。如果这个推断成立，那么「丢掉尺度」不是一个可以随手修掉的选择，而是这条 UCPE 路线自带的约束。

中D7Dynamic 0.9200 更像失败率，不是风格取舍▶
论文的解释
The lower Dynamic score (0.9200) may reflect attenuation of local motion during latent rendering and video refinement, suggesting a possible trade-off between motion activity and temporal consistency.
我的读法

VBench 的 Dynamic Degree 是逐视频的二值判定（基于光流幅度阈值）再取平均。评测集的每一例都带相机运动， 所以 0.9200 的字面含义是：200 个视频里约 16 个被判为「基本静止」。MoVerse 是 1.0000（200/200），HY-World 2.0 是 0.9850（约 3 个）。

「局部运动被衰减」会让每个视频的光流幅度整体下降，但要跌破二值阈值，通常意味着那一例基本没动—— 考虑到初始化块是把全景图重复 13 帧得到的一段静止，一个自然的假设是：有一小部分样本没能从静止启动。 如果真是这样，这是个失败模式，值得单独看那 16 个例子，而不是当作一个指标上的权衡。

顺带

Consistency（帧间特征相似度）与 Dynamic 在构造上就是反相关的。同时拿最高 Consistency 和最低 Dynamic，不构成「时间一致性更好」的独立证据。 要说清楚这件事，需要在控制运动量的前提下比较一致性，比如按 Dynamic 分箱后再比 Consistency。

中D8σ₀、六个 λ、伪目标来源：三个决定结果的东西全是空白▶
① carrier 重加噪水平 σ₀（Eq. 7）

它单独决定了精修器「可以偏离 carrier 多远」。σ₀ 太小 → 输出等于放大后的 carrier，纹理贫瘠但稳定；太大 → 细节丰富但几何漂移、块间跳变。 Quality / Consistency / Dynamic 三个指标首先是 σ₀ 的函数。论文连数量级都没给。

② 六项损失的权重（Eq. 15、17）

LQ = LFM + λstrLstr + λhfLhf + λpercLperc + λtempLtemp + λbndLbnd， 以及蒸馏的 λDMD、λstr、λbnd、λrel。十个权重，一个数字都没有。 其中 Lstr（锚住 carrier 的低频）与 Lhf（恢复目标高频）是直接对抗的一对。

③ 「固定的高质量伪目标」
Real examples use VAE-encoded high-resolution perspective videos as targets, while generated panoramic inputs are paired with fixed high-quality pseudo-targets.

伪目标从哪来？谁生成的？凭什么比学生好？这是整条蒸馏链上唯一一个来源不明的监督信号，却承担着「让生成分布上的输入也有高质量目标」的关键作用。

低D12极点处理只做了一半▶

经度方向做得很干净：整数谐波让相位跨接缝连续，VAE 的空间卷积与重采样改成循环填充。纬度方向则原封不动：

  • VAE 的纬度填充保持原样，也就是把上下边界当成普通图像边界处理，而球面上这两条边各自坍缩成一个点，正确的做法是绕到对侧经度。
  • 低频球面坐标 ∝ cos φ·cos λ 与 cos φ·sin λ，在极点 cos φ → 0，整行 token 的低频相位塌成同一个值。设计意图是降低极点的经度依赖，副作用是位置退化。
  • VAE 权重冻结，却换了填充方式——接缝列的特征统计对编解码器来说是 OOD 的，残留误差被冻进去，只能由 Gθ 学着补偿。

ERP 的极区本来就是过采样、像素最冗余的地方，这些问题多半不致命。但论文既没讨论也没消融，而全景视频里天顶/天底（尤其是 nadir 补丁那一带）恰恰是伪影高发区—— MUGEN 的质量过滤专门查了 nadir patch，说明作者清楚这件事。

B术语速查

ERP（equirectangular projection）
等距柱状投影。把球面按「经度 → 横轴、纬度 → 纵轴」摊平成 2:1 的矩形。两个几何后果：左右边界在球上是同一条线（接缝），越靠近极点横向越被拉伸（过采样）。
全景态（panoramic state）
本文对 Zpan1:T 的称呼。一串随时间演化的 ERP 视频潜变量，以相机为中心，不是度量 3D 地图。它同时是「世界状态」和「中间表示」，但永远不被解码成最终输出。
视口（viewport）κ
yaw / pitch / 水平 FOV 三元组，逐 RGB 帧给定。它决定「看哪儿」，与决定「相机在哪」的轨迹 Π 是两回事——这是本文一个容易混淆但很关键的区分。
球心投影（gnomonic projection）
把球面上的一块投到切平面上，也就是「透视相机看球面」。特点是直线保持为直线，但越靠视场边缘拉伸越厉害，且 FOV 接近 180° 时发散。
carrier
上采样后的高分辨率透视 latent。它只承载布局、运动和粗略外观，把有歧义的高频纹理留给精修器。在精修时它被用了两次：加噪起点 + 干净对齐条件。
UCPE（Unified Camera Positional Encoding）
把每个 token 的相机/射线位姿写成 4×4 齐次矩阵，通过 q̃ = ΓTq、k̃ = Γ−1k 让注意力只依赖相对位姿。与 RoPE 的关键区别：它不保范（见 §04）。
chunk-causal / 块因果
块内双向注意力（块内可以互相看），块间因果（只能看过去的块）。是「质量」与「流式」的折中：块越大质量越好、延迟越高。本文的块 = 1 秒。
Self-Forcing / DMD
少步蒸馏的两件套。Self-Forcing 让学生在自己生成的历史上训练，消除 exposure bias；DMD（分布匹配蒸馏）用一个真分数模型和一个假分数模型的差，把学生往真实分布推。
COVER
一个综合视频质量评估器（CVPR-W 2024），本文用它做数据过滤（阈值 0.7）与 MUGEN-HQ 的排序依据。
ViPE
本文用来从全景视频估计逐帧相机轨迹的工具，同时给出深度图与实例掩码。它既是标注器，也是评测时估计生成视频轨迹的工具——注意这意味着训练信号与评测指标来自同一个估计器。
B 补充：ViPE 既标注又评测，这件事值得单独记一笔

训练时的相机条件来自 ViPE 的估计，评测 TransErr / RotErr 时又用 ViPE 去估计生成视频的轨迹。 这不是作弊——目前大家都这么做——但它意味着指标测的是「ViPE 眼中的轨迹一致性」。 如果模型学到了任何能让 ViPE 更容易/更一致地估计位姿的偏好（比如更稳的结构、更少的运动），它会同时提高 RotErr 和 Consistency，而不一定对应更真实的相机运动。 三家之间的相对比较仍然有效，因为用的是同一个估计器。

C如果你要在这上面接着做

最高性价比
把全景 KV 做成有界
全景分支是唯一会「越跑越慢」的部分，而它又是分辨率最低的一侧。 一个 sink + 滑窗 + 稀疏锚点的组合，大概率能把延迟压成常数，代价很小。 这件事做完，「streaming」才真的成立。
补上另一半记忆
全景态 + 小的度量几何
旋转已经免费了，缺的是平移。 不需要完整的 3DGS——一个粗糙的深度/点云缓存，只用来给 Gθ 提供视差先验就够。 MUGEN 里的深度图已经算好了，一次都没用。
让细节也进状态
纹理的回访一致性
现在纹理是每块现编的，精修器只回看 1 块。 可以试：把视口相关的高频残差写回一个按方向索引的小缓存， 回访同一方向时作为条件喂给 Fφ。这是把「全景态存布局」扩展到「也存一点外观」。
拿回尺度
解耦旋转与平移的条件通路
UCPE 的不保范问题来自平移分量。 可以把旋转走保范的 RoPE 式通路、平移走一个单独的、显式带尺度的嵌入（比如对数尺度分箱）， 这样既不炸 logit，也不必把绝对尺度归一化掉。
