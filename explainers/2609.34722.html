GEAR — 几何只当地址，不当记忆 · 精读

长程相机控制视频生成，难点在于把以前看过的东西找回来：镜头转回某个地方时，那片区域早已滑出模型的上下文窗口。GEAR 的做法是把“记忆”拆成两半。视觉内容原样保留在逐帧的 latent 里。几何只负责寻址：每张历史帧单独估深度、建一张局部网格，用它算出“目标画面的这个 patch 应该去历史帧的哪个 patch 读”。然后在 Wan2.1-I2V-14B 的偶数层里插入一个稀疏注意力 GCA，每个目标 token 只看几何点名的那几个历史 token，最多 9 个。另有一棵只记录“哪些空间从没看见过”的 Invisible Octree，负责剔除“几何上投得过去、实际被挡住”的对应。

一句话：GEAR 让几何只回答“去哪读”，“读出什么”交给注意力。这样几何误差只影响单次读取，不会像点云融合那样被永久写进场景。但几件事要先看清。第一，它每块都要调用外部 3D 模型估深度。第二，逐帧编码使 token 数约为时间压缩编码的 4 倍。第三，用于可见性过滤的八叉树和可见网格本身仍是全局融合的结构。第四，全文没有提到任何相机嵌入，目标相机似乎只能通过几何对应进入模型。这意味着“去掉 GCA”的消融同时去掉了相机信号。

01它在解决什么：长程生成是一个“记忆访问”问题

给一张图、一段文字和一条很长的相机轨迹，逐块自回归地生成视频。要求两件事：画面严格跟着轨迹走；某个区域离开视野很久后再回来，要和当初一样。第二件事意味着模型要能从越来越长的历史里，为当前画面的每一小块找到对应的旧证据。已有做法分两派，图中间是它们各自的问题。

隐式派的问题

WorldMem、Context-as-Memory、WorldPlay 等把历史帧当上下文。信息完整，但注意力要在不断变长的 token 集合里找到当前视角需要的少数几个。帧检索或历史压缩能减负，但粒度是整帧或整段，可能丢掉精确回访需要的细节。

显式派的问题

Spatia、WorldStereo、GEN3C 等把历史融合成点云、网格或体素，再重投影到目标视角当条件。局部几何错误一旦被融合，就变成持久的漂浮物、重复表面，并随每次重投影传进后续生成。

中间路线

AnchorWeave 保留多个局部几何，渲染成锚视频后用 ControlNet 融合。UCM 按几何扭曲位置编码。Lyra 2.0 把扭曲后的源坐标和深度编码成嵌入，加到 DiT token 上。GEAR 认为这些做法里，几何仍在“构造条件信号”，对视觉特征的访问是间接的。

人话类比

把历史想成一座图书馆。隐式记忆是每次都在整座馆里翻一遍。显式 3D 记忆是把所有书抄进一本总账，以后只查总账，但抄错的地方永远是错的。GEAR 是用一张索引卡（几何）告诉你“去第 3 排第 5 本的第 12 页”，你读的仍然是原书（历史 latent）。索引卡写错一次，只影响这一次查阅，不会改掉书的内容。

02全流程：每一块都走一遍“检索 → 寻址 → 生成 → 更新”

GEAR 是逐块（chunk）自回归的。每块生成 23 帧，生成前先为这 23 个目标视角准备好“去哪读”，生成后再把新帧和它们的深度写回历史。点击下面的步骤看每一步做什么、花多少时间。

03帧对齐 VAE：先让“一个 latent = 一个相机”

要按几何给 latent token 寻址，前提是每个 latent token 对应唯一一个相机位姿和一块确定的图像区域。Wan 的 VAE 做不到这一点：除第一帧外，它把每 4 帧压成一个 latent 帧，快速运镜时这 4 帧看的可能是完全不同的地方。GEAR 沿用 AnyRecon 和 FrameCrafter 的做法，每一帧都单独走 VAE 的“首帧编码路径”，解码时也逐帧解码。

Token 账：逐帧编码贵在哪里

下面按 480×832、每帧 1560 token 计算一块的序列长度。“原生”一栏假设同样帧数走 Wan 的时间压缩。注意力代价按序列长度的平方粗估，只用来比较量级。

论文配置是 9 + 23 = 32 个 latent 帧，共 49,920 个 token，约为 Wan 标准 81 帧片段（21 个 latent 帧、32,760 个 token）的 1.52 倍。而这一块在 16 fps 下只有约 1.4 秒画面。另外，DiT 预训练时见到的都是时间压缩后的 latent，现在喂给它的是一串“首帧式”的 latent，所以需要 rank-32 LoRA 来适配（论文 §4.1）。逐帧解码也放弃了时间 VAE 的平滑，可能带来帧间闪烁，论文没有单独讨论这一点。

04几何地址：局部网格 → 双视角光栅化 → Face-ID 对应

这一节是 GEAR 的核心。目标是：对每张被选中的历史帧 s 和每个目标帧 t，给出 patch 级别的对应表“目标 patch i ↔ 源 patch j”。整个过程只用帧 s 自己的深度，不与其他帧融合。

① 局部网格（全分辨率）

对 DA3 估出的深度图 Ds，把每个像素中心反投影到世界坐标（Eq. 14），每个有效像素是一个顶点。每个 2×2 像素格沿固定对角线切成两个三角形。

两类三角形丢掉：任一顶点深度无效；或任一条边的相对深度跳变 |D(pi)−D(pj)| / min(D) > τdisc（Eq. 15）。后者防止网格像橡皮膜一样把前景和背景连起来。τdisc 的取值论文没给。

为什么不直接在 latent 网格上建：一个 16×16 的 patch 常常跨多个表面，把深度先降采样会糊掉边界。

② 双视角 face-ID 光栅化（latent 分辨率）

用 nvdiffrast 把同一张源网格分别在源相机和目标相机下光栅化，分辨率取 latent patch 网格 Hℓ×Wℓ = 30×52。每个格子记录 z-buffer 胜出的那个三角形的 ID，0 表示背景：

Fs = R(Gs; cs)　Fs→t = R(Gs; ct)

③ 同 ID 即对应（Eq. 6/17）：Cs→t = {(i, j) | Fs→t(i) = Fs(j) > 0}。

④ 多源缓存（Eq. 7）：𝐂 ∈ ℤNt×Nc×Hℓ×Wℓ×2，只存源 patch 坐标、不存特征。每对（目标 patch，源帧）至多一个匹配，所以每个目标 patch 至多 Nc = 9 个候选。

人话：这一步到底算了什么

对目标帧的每个 patch，取它的中心，沿视线打到“源帧 s 自己的那张网格”上，看击中的表面点在源帧里属于哪个 patch。这和经典的“深度重投影 + 最近 patch”本质相同。光栅化的好处有两个：z-buffer 自动处理源网格自身的前后遮挡；深度跳变过滤会在物体边缘留出“洞”，不会凭空连出一张不存在的面。

它不能处理的情况是：目标视线和源表面点之间，隔着源帧从没看见过的东西。源网格在那里只有一个洞，视线会穿过去。这正是 §05 的 Invisible Octree 要补的。

存疑 D3 · 复现关键

论文写的是“记录可见三角形的 ID，共享 ID 即对应”，同时强调网格建在原图分辨率、光栅化在 latent 分辨率、ID 不插值。按这个字面读法：源图在每个 patch 中心只采到 1 个三角形，覆盖面积 0.5 像素²；目标 patch 中心击中的表面点落在源图上是一个连续位置，恰好落进这 1560 个小三角形之一的概率约为 1560×0.5 / (480×832) ≈ 0.2%。我用斜面场景、200 组随机相机运动模拟，平均只有 0.18% 的目标 patch 能配上。可这套对应既要告诉每个目标 token 去哪读，又是模型唯一的相机信号，论文图 3 画的也是成片匹配的格子，实际一定是稠密的。

所以真实实现必然有一个没写出来的细节。最可能的是三角形按所属源 patch 编号，即 face ID 实际上是“源 patch ID”，这样 Eq. 6 就退化为“查目标 patch 中心击中的源 patch”。其他可能包括超采样后投票，或按邻域匹配。这三种实现在边界处的行为不同，官方代码未发布，复现时需要自己定。

还有一个量化上的细节：地址是整数 patch。目标 patch 中心落在源 patch 内的哪个位置（亚 patch 偏移，最多 ±8 像素），GCA 不知道，它拿到的是整个源 patch 的特征。细对齐只能靠骨干自注意力去补。

05Invisible Octree：投得过去 ≠ 看得见

单帧几何只知道“源帧看见了什么”，不知道“源帧没看见的地方藏着什么”。当目标相机从侧面看过去时，源网格边缘的洞会让视线直接穿到背景上，产生“几何上投得过去、实际被挡住”的错误对应。GEAR 维护一个全局的稀疏八叉树，只记录可见性：哪些空间确定是空的，哪些从没被看见过。它不存外观，也不当渲染条件，只做二值过滤。

构建与流式更新（附录 A.4）

  • 初始化：用第一帧的相机和深度设定世界包围盒，粗网格每轴 2⁴；外面包一层一格厚的 invisible 壳，兜住深度无效的区域。第一块从粗到细细分到每轴 2¹⁰。
  • 两个全局代理：八叉树 𝒪 记录尚未解开的不可见空间；全局可见网格 Gvis 记录已观测到的表面，由反投影深度三角化得到。八叉树节点按 Gvis 渲染出的深度分类，保证两者一致。
  • 更新：新帧来了，对八叉树的 invisible 叶子建 BVH 做光线投射，得到每条光线遇到的第一个不可见体素的深度 dinv；再光栅化 Gvis 得到 dvis。满足 dinv + ε < dvis（Eq. 19）的像素说明“不可见空间出现在已知表面前面”，即新暴露的区域。只用这些像素的深度重新分类对应节点，并把这部分表面并入 Gvis。
  • 保守：只有 invisible 叶子能被后续观测改写，已确定的 free 不会被后来生成帧的深度覆盖。

过滤（§3.3 + A.4）

对每个目标相机，把两个全局代理投影进去比较深度，得到目标视角的不可见掩码。掩码内目标 patch 的所有候选都删掉，GCA 在那里输出 0，由模型自己生成。

这里有两处口径值得留意，完整讨论见存疑 D4、D9、D10：

  • Gvis 是跨帧融合的全局网格。论文“不做全局融合”的说法只对外观成立，可见性这一路是融合的，而且更新是保守的，早期的错会一直留着。
  • 正文说“落在累积可见边界之后的候选被拒绝”，像是逐候选的深度测试；附录说“把掩码直接作用于缓存”，是逐像素的二值掩码。若是后者，一个候选即使被别的历史帧见过的已知几何挡住，也不会被删。
  • Eq. 18 把“足迹内没有有效深度”的格子判为 free。如果这也包括投影落在视锥外的格子，从没看过的空间就会被当成空的；如果反过来判为“未见过”，相机一后退，几乎所有对应都会被拒。两种读法各有问题，§06 可以亲手试。

实现上，八叉树管理和更新用 NVIDIA Warp 在 GPU 上并行，每块 23 帧约 3.4 s（表 4）。本质上它是经典的体素化空间雕刻（free / unknown 二分），与机器人领域 OctoMap 这类占据八叉树同源。论文的新意在于只把它用作对应关系的过滤器。

06Flatland 实验室：在二维里把几何这一路完整跑一遍

把三维场景压成俯视的二维“平面国”：相机是一维的，图像只有一行 96 个像素，每 8 个像素算一个 patch，共 12 个 patch（论文是 16×16 像素一个 patch，30×52 个）。步骤和论文一致：每张历史帧用自己的深度建局部网格（一维里就是折线），丢掉跨深度跳变的边，在源和目标相机下按 patch 中心光栅化得到对应，再用四叉树（二维的八叉树）记录可见性，过滤被挡住的候选。场景的真实几何已知，所以可以给每条对应判对错：绿色是正确保留，红色是错误保留，紫色是被正确拒绝，黄色是误拒。

建议这样玩
  1. 绕到柱子侧面（预设会切到“只有 H1”，源帧也设为 H1）。先把过滤设为“关”：目标视线穿过 H1 网格在柱子边缘留下的洞，打到墙上，出现红线。再切到“二维掩码”：红线变紫，被八叉树拒掉，这就是 §05 图 5 的情形。同时会出现黄色（误拒）：只有一张历史帧时，八叉树无法确认那片空间是空的，只能保守地拒掉。
  2. 默认视角（三张历史帧、多源）：“二维掩码”下仍有红线。这些错误对应的成因是：源帧自己没看到挡在前面的柱子，但别的历史帧看到过，柱子已在可见网格里，所以视线没有穿过“未见过的空间”，二维掩码就放行了。切到“逐候选深度”，红线减半，这就是存疑 D9。
  3. τdisc 拉到最大：柱子和墙之间被一张“橡皮膜”连上，目标视线打到这张不存在的面上，错误对应明显增多。深度跳变过滤是必需的。
  4. 切换到“字面：三角形 ID”：一维里每个 patch 只有 8 条边，匹配数掉到约 1/8；二维中每个 patch 有 512 个三角形，匹配率约 0.2%（D3）。
  5. 后退：相机退到所有历史相机身后，前方有一根近处的小柱子，是任何历史帧都没见过的。按 Eq. 18 字面，视锥外算 free，小柱子挡不住错误对应（红）。勾选“视锥外判为未见过”：错误对应被拒了，但正确的也几乎全被拒（黄）。这是一个真实的两难，论文没交代怎么取舍（D10）。
  6. 转向新区域：历史帧都没看过这里，没有任何候选，GCA 输出 0，全交给生成先验。

说明：四叉树的更新规则按附录简化实现，即 H1 初始化，后续历史帧依次只改写 invisible 叶子，视锥外的叶子保持不变；可见网格用三张局部网格的并集近似 Gvis；目标视角的掩码按论文逐 patch 计算，条件是 dinv + ε < dvis。“正确”的判据是源网格击中点与真实场景第一击中点相距小于 0.3 个单位。

07GCA：只在几何点名的候选上做注意力

地址算好之后，要把历史特征“读”进目标 token。GEAR 的办法很简单：9 张历史 latent 和 23 张带噪目标 latent 沿时间拼在一起，照常进 DiT。在第 0、2、4…38 这 20 个偶数层里，自注意力之后插入一个稀疏交叉注意力 GCA。每个目标 token 的 key/value 只来自它在缓存里的候选。

规模（我复算过）

Wan2.1-14B 隐藏维 5120、40 层。每个 GCA 模块有 Q/K/V（5120→640）和 O（640→5120）四个投影，共 4×5120×640 = 13.1M；20 个模块合计 262.1M，与论文的“262M、占骨干 1.9%”完全一致。这说明 GCA 里没有别的大部件，比如额外的 MLP 或位置编码网络。

按 FLOPs 估，GCA 只占骨干的 0.4% 左右。实测每步 +2.1%，多出来的部分大概是 gather 和索引的开销。显存多 1 GB。

“只在候选上 softmax”意味着什么

归一化范围是 𝒩(i)，至多 9 个，每张历史帧一个。几个视角同时看到同一区域时，注意力按 query 和 key 的相似度混合它们，互补外观。

反过来：只有一个候选时，α 恒等于 1，不管这个候选多不像，都会原样注入。GCA 没有“一个都不要”的选项（没有 null key 或门控），唯一的退路是 WO 学得更小，或者靠骨干去覆盖。这一点影响对“抗对应扰动”实验的解读（D8）。

相机信号从哪里来

全文没有提到相机编码，没有 Plücker 图、位姿 token，也没有扭曲后的渲染条件。Wan2.1-I2V 本身也不吃相机。那么目标相机只能通过“哪个目标 patch 对应哪个历史 patch”进入模型，靠的是 GCA 注入的特征，以及骨干对这些特征的传播。

这是一种巧妙的设计，对应关系本身就是相机。但它有两个推论：没有任何对应的区域，只能从周围间接获得相机约束；去掉 GCA 的消融等于同时去掉了相机条件（D1）。

玩具模型：什么时候注意力能挑出正确的候选

这不是论文的实验，只是把 Eq. 9 的机制做成可调的小模型。16 维特征：真值特征 f*；正确候选是 f* 加观测噪声；干扰候选与 f* 的相似度为 ρ（ρ 小相当于论文里偏移 64–128 像素，ρ 大相当于只错开一个 patch）。query 里含 f* 的比例由“query 信息量”控制：去噪早期目标 token 还很噪，这个比例低；后期高。

08训练：两种样本、一个“做旧”的历史

可训练的只有 LoRA 和 GCA，骨干全部冻结；GCA 的 WO 零初始化，所以训练开始时模型行为与原版一致。数据来自 DL3DV-10K：去掉明显运动模糊或光照不足的场景后剩约 6.5K 个，切成不重叠的 55 帧片段，共约 30K 个。相机和深度由 DA3 估计，字幕由 Qwen3-VL-8B 生成。

I2V 样本（30%）

只用前 32 帧：第一帧是条件，它的几何用来初始化八叉树，并与目标视角建立对应；其余帧是生成目标。对应推理时的第一块。

H2V 样本（70%）

前 32 帧组成历史库，按 §09 的贪心覆盖从中取 9 张关键帧，用来建多源对应缓存；八叉树用全部 32 帧建。后 23 帧是生成目标。对应推理时的后续块。

退化历史增广：让训练时的历史也“不完美”

训练时历史是真值帧，推理时历史是模型自己生成的，这个差距会让误差沿 rollout 累积。GEAR 的办法是：以概率 pdeg 给历史 latent 加一点噪声，再用当前模型一步去噪回来。这样得到一个“模型自己会画成这样”的略有失真的版本，用它替换历史条件，目标块的 flow matching 损失不变。

09长程推理：关键帧检索、深度更新与成本

历史库会无限增长，但每一块只从中取 9 张关键帧当条件。取哪 9 张，看它们对即将生成的 23 个目标视角的几何覆盖。

贪心覆盖检索（附录 A.5）

把目标块所有帧的所有 patch 位置记为集合 Q。每张历史帧 s 把自己的局部几何投到每个目标视角，再用八叉树掩码去掉被挡住的部分，得到覆盖集 Vs ⊆ Q。首帧和最新帧必选，然后每轮加入边际增益最大的一帧：

Eq. 20nq(S) = Σs∈S 𝟙[q ∈ Vs],　Δ(s | S) = Σq∈Vs 𝟙[nq(S) < Ncovered]，Ncovered = 3

一个位置被覆盖满 3 次后不再计分。这样既鼓励覆盖面广，又在同一区域保留多个视角，让 GCA 有东西可以“互补”。下面用 14 张合成的历史帧演示，每张帧覆盖目标块里的一段区域。

深度更新（附录 A.6）

每块生成完、逐帧解码后，用 DA3 给新帧估深度。为了让新深度和历史库里的几何一致，会从历史中每隔 max(1, ⌈Nhist/25⌉) 帧取一张锚帧，约 25 张，与 23 张新帧一起送进 DA3 的位姿条件模式（喂入规定的相机轨迹），只保留新帧的深度，历史深度不动。约 25 张锚帧加 23 张新帧，合计约 48 帧，与表 4 里“48 帧一次调用 14 s”对得上。

一个值得注意的耦合

位姿条件模式假设生成画面严格按规定相机拍摄。如果某块画面实际偏离了轨迹，DA3 只能把这个偏差吸收到深度里，于是几何带着偏差进入历史库、八叉树和下一块的对应。换句话说，相机误差和深度误差会互相转化。论文的“对应扰动”实验（D8）只模拟了一种相当极端的形态。

11存疑清单

按“如果成立，会不会改变主要结论”分级。高 会改变结论；中 影响适用范围、解释或复现；低 是细节。每条都注明了依据：论文正文或附录、公开页面，或我的推算。标“我的推算”的内容可能有误，欢迎用原文核对。

D1消融把“几何寻址”和“相机信号”绑在了一起，核心主张缺一个公平对照

全文（含附录）没有描述任何相机编码：没有 Plücker 射线图、位姿嵌入，也没有扭曲渲染条件，而 Wan2.1-I2V 本身不接相机。目标相机唯一明确的入口是对应缓存 → GCA，外加八叉树掩码。由此：

  • w/o GCA 很可能是一个“不知道目标相机”的模型。它的 SSIM 0.1324 低于表 1 全部基线，这更像是缺了相机条件，不像是少了一条记忆通路。所以“GCA 提升相机控制”几乎是同义反复。
  • w/ Dense Attention（同参数量）把 key/value 换成全部历史 token，同样没有任何几何信息。它比 GEAR 差，证明的是“有相机信息优于没有”，不能证明“稀疏几何寻址优于稠密检索”。

缺的对照：同骨干、同数据、同样 9 张关键帧，用稠密上下文加 Plücker 或 UCM 式 PE 扭曲作相机条件，这才是公平的隐式记忆基线；或者 GCA-dense 加相机嵌入。没有这个对照，“几何当地址”相对“几何当相机条件”的净增益无法分离。如果论文其实有一个没写出来的相机编码，那就是漏写了一个关键部件，问题同样存在。

D2DL3DV 评测场景可能在训练集里，而主表左半和全部消融都在这个集上

DL3DV 官方 Benchmark 的 140 个场景是“sampled from DL3DV-10K”（HuggingFace 数据集页原文）。DepthSplat 等工作训练时会显式剔除这些场景，TokenGS 的 issue #13 也在追问同一件事。GEAR 在 DL3DV-10K 上训练（过滤后 6.5K 场景），评测写的是“DL3DV-Evaluation [23]”，全文没有说剔除了评测场景，评测场景数和生成长度也没写。

如果存在重叠，与 GT 帧比较的 SSIM、LPIPS、FVD 会被记忆效应抬高。即使没有重叠，GEAR 是专门在 DL3DV 上训练的，而论文没有交代各基线是否见过 DL3DV，域内优势至少没有被排除。WorldScore 部分不受这个问题影响，GEAR 在那里仍然领先，但见 D6、D7。

D3Face-ID 对应按字面读几乎配不上，真实实现有未写明的关键细节

论文写的是：网格建在原图分辨率（每像素一个顶点，每个 2×2 格两个三角形），光栅化在 latent 分辨率，“记录可见三角形的 ID，不做插值，共享 ID 即对应”。按字面理解，源图在每个 patch 中心只采到 1 个面积 0.5 像素² 的三角形；目标 patch 中心的表面点落回源图时，恰好落进这 1560 个小三角形之一的概率约为 1560×0.5 / 399,360 ≈ 0.2%。我用斜面场景和 200 组随机相机运动模拟，平均 0.18%，最高 1.3%。而这套对应要承担“每个目标 token 读哪里”和“唯一的相机信号”两项职责，论文图 3 画的也是成片匹配的格子，实际必然是稠密的。

所以实现里一定有别的东西。最可能的是三角形按所属源 patch 编号，这样 Eq. 6 等价于“目标 patch 中心重投影后落在哪个源 patch”，§06 实验室的默认模式就是这种读法。“共享 face ID 保留全分辨率精细结构”的说法也应理解为：深度边界处理在全分辨率上做，地址本身仍是 patch 级。代码未发布，这是复现时第一个要定的细节。

D4“不做全局融合、误差不累积”只对外观通路成立

可见性这一路本身就是全局融合的：Invisible Octree 与全局可见网格 Gvis 都由各帧的 DA3 深度（包括生成帧的深度）累积而成。而且更新是保守的，已确定的 free 不会再改。两类错误因此会永久化：早期某帧深度估得偏远，真实表面前的空间被“雕”成 free，之后穿过那里的错误对应永远不会被拒；深度估得偏近，不可见区域偏大，正确对应被误拒，模型只能凭空生成而不是回忆。这两个代理还决定了关键帧检索的覆盖计算。

另外，视觉记忆本身就是生成出来的 latent，误差当然会累积，这正是退化历史增广存在的理由。论文没有做八叉树自身误差随 rollout 增长的分析。更准确的说法是：外观不再从一个融合表示里重新渲染，这一点确实成立，也有价值。

D5算力口径差异很大，“交互”一词容易误读

GEAR 用 14B 模型、25 步、CFG 5，逐帧 latent 使每块序列长 49,920 token，单卡每步 34.5 s。按表 4 推算（我的估算），一块 23 帧约 14.7 分钟，600 帧约 6.4 GPU·小时，比实时慢约 600 倍。基线里 HY-WorldPlay 明确定位为实时交互模型，论文没有报告任何基线的算力。图 1 的“Interactive Control”指的是任意轨迹可控，不是实时交互。

仓库 TODO 里有一个“4 步 DMD checkpoint”，论文里完全没有它的结果。对交互式世界模型来说，关键问题是 GEAR 的优势在少步蒸馏后还剩多少：少步时每一步的 query 都更“噪”，Eq. 9 的挑选能力会变弱（可以在 §07 玩具模型里调低 query 信息量看看）。

D6WorldScore 只报了 7 项中的 4 项，其中一项没有区分度，另一项数值反常

WorldScore-Static 官方有 7 个维度：Camera Control、Object Control、Content Alignment、3D Consistency、Photometric Consistency、Style Consistency、Subjective Quality。本文报了后面 4 个里的 3 个加上 Content Alignment，没有 3D Consistency 和 Camera Control，而这两项正是本文的卖点。

Subjective Quality 八个方法全在 0.5005–0.5018，极差 0.0013，不应计入“领先”。Photometric Consistency 上 WorldStereo 0.0837、Lingbot 0.0889，与其他方法差一个数量级，而 WorldStereo 的回访 SSIM 却排第二，可能是归一化或失败样本造成的，值得核查。Style Consistency 全是两位小数补零（0.8600、0.8300…），与其他列的精度不一致。样本是随机抽的 50 个场景，没有方差。

D7回访协议不清，而最可能的读法对 GEAR 天然有利

回访 SSIM/LPIPS 的定义是“生成的回访帧与匹配相机位姿下的参考观测”之间的比较，轨迹是闭环。如果闭环回到起点，参考观测就是输入图。GEAR 的检索永远保留首帧 Hfirst，回到起点时对应几乎是恒等映射，GCA 相当于直接把首帧 token 抄过来。这是最容易的回访。

真正考验记忆的是回访中途生成的区域：参考本身是生成的，要靠历史库和检索把它找回来。论文没有说明参考帧是哪一帧、有几个回访点、闭环多长。

D8“抗对应扰动”实验挑的是容易的情形，而 GCA 在单候选时没有退路

扰动只加在“多视角观测”的区域：9 个候选保留 2–3 个正确的，其余偏移 64–128 像素（4–8 个 patch）。离得这么远的 patch 特征通常差别很大，注意力容易甩掉。现实中的深度误差更常见的是 ±1 个 patch 的小偏移，特征相似；另一种常见情形是只被一张历史帧看到的区域，此时 𝒩(i) 只有一个元素，α≡1，错了也会原样注入。

GCA 没有 null key 或门控，无法“一个都不要”。§07 的玩具模型可以直接看到：ρ 调高，或者候选总数设为 1、正确数设为 0，误差都会显著上升；勾上 null key 能缓解。论文也没说扰动是只在推理时加，还是训练时也加。

D9过滤若是逐像素的二维掩码，就挡不住“被其他帧见过的已知几何”遮挡的候选

正文说“落在累积可见边界之后的候选被拒绝”，听起来像逐候选的深度测试；附录说“把目标视角的不可见掩码直接作用于缓存”，是逐像素的二值掩码。掩码只标记“视线在到达已知表面前先穿过不可见空间”的像素。

考虑这种情况：源帧 s 没看到某个遮挡物 Y，但另一张历史帧看到过，Y 已经在 Gvis 里。目标视线先撞上 Y，这个像素就不在掩码里，于是 s 给出的穿过 Y 的对应会被保留，只能指望注意力去压低它。逐候选比较“候选表面点在目标视角的深度”与 dvis 几乎零成本。论文两处说法不一，也没有针对这一点做消融。§06 实验室的默认视角可以对比两种读法：在三张历史帧、多源的设置下，二维掩码放过的错误对应，逐候选深度能拒掉一半。

D10Eq. 18 的边界情况：视锥外怎么算？“无界环境”与固定包围盒怎么统一？

Eq. 18 把“足迹内没有有效深度”的格子判为 free。本意大概是天空这类无穷远区域，但它同样覆盖了投影落在视锥外的格子。按字面，所有从没看过的空间都被当成空的：相机后退、侧移时，任何历史帧都没见过的近处遮挡物，挡不住穿过它的错误对应。反过来，如果视锥外判为“未见过”，相机一后退，视线一出发就在未见过的空间里，几乎所有对应都会被拒，记忆整体失效。§06 实验室的“后退”预设可以同时复现这两种结果。这是一个真实的两难，论文没说怎么处理。

此外，八叉树的世界包围盒在第一帧时“按场景尺度”设定，外面包一层 invisible 壳；可论文又说它“随探索扩展，支持无界环境”。相机走出包围盒后怎么办，没有说明。

D11退化历史的消融训练口径不明

增广只在第 8K–10K 步启用，只作用于 H2V 样本，概率 40%，相当于最后 2K 步里约 28% 的样本。去掉它后 FVD 从 838 升到 1166（+39%）。w/o 变体是不加增广训满 10K 步，还是直接取 8K 断点？若是后者，训练长度也混在里面。全部结果都是单次运行，没有方差。

D12复现所需的若干细节缺失
  • 超参：τdisc（Eq. 15）、ε（Eq. 19），八叉树包围盒怎么由“场景尺度”确定。
  • GCA 的头数、是否有归一化、是否接受 timestep 调制；历史 token 用什么时间步（Wan2.1 的时间调制是整段共享的）；Wan2.1-I2V 的首帧通道拼接在 H2V 下怎么处理。
  • 评测：DL3DV 场景数与生成长度；TransErr/RotErr 的定义与单位；Umeyama 是否含尺度；GPU 型号。
  • “minute-long”：图中帧号到 #600 左右，播放帧率没写。600 帧在 16 fps 下只有 37.5 s，要 10 fps 才是整一分钟。
D13相关工作的定位偏窄

“注意力只看对应位置”在多视角扩散里已有先例，例如 MVDiffusion 的 correspondence-aware attention 按已知几何只注意对应像素的邻域，此外还有一系列极线注意力工作。可见性八叉树与机器人领域的占据八叉树（OctoMap）、体素空间雕刻同源。论文都没有讨论。GEAR 的新意在于把这些用于长程流式生成的记忆寻址，并配上流式更新，这一点是成立的，但应当放在这些工作的脉络里说清楚。

D14静态世界假设

free 空间一旦确定就是永久的，训练和评测（DL3DV、WorldScore-Static）也全是静态场景。场景里有运动物体，或需要响应交互动作的世界模型，都不在本文范围内。“world generation”的叙事要这样限定。

D15整数 patch 地址，候选不带视角信息

地址是整数 patch，最多有 ±8 像素的量化偏差，GCA 并不知道目标 patch 中心落在源 patch 内的哪个位置。候选也不带相对位置、视角或距离信息，注意力只能靠特征相似度区分“近处清晰的观测”和“远处斜视的观测”。它也不像 MVDiffusion 那样取对应点周围的邻域，所以对 ±1 patch 的误差更敏感。

12结论与启示

我的判断：GEAR 的核心拆分有价值：外观留在帧 latent 里，几何只给 token 级地址，用稀疏注意力读取。这条“直达通道”几乎不增加计算，相机跟随上的提升很显著。但论文把几件事绑在一起报告了：几何对应既是记忆地址，也是模型唯一的相机信号；可见性这一路仍然依赖全局融合；主评测集可能有训练重叠。所以目前能确定的结论是“把几何对应当作 token 级条件，在 Wan-14B 上非常有效”。“几何当地址优于隐式记忆”还需要 D1 那个对照来证明。

做对的地方

  • “哪里读”和“读什么”分工清楚，外观误差被限制在单次读取内。
  • 很轻：262M 参数，每步 +2.1%；WO 零初始化，骨干冻结。
  • 意识到“投得过去 ≠ 看得见”，八叉树的消融效果明显（ATE +67%）。
  • 给了同参数量的 dense 对照（思路对，只差相机）、推理成本表、详细的基线配置，也主动说明了 AnchorWeave 没比、Infinite-World 的动作是离散化的。

对交互式世界模型的启示

  • 对应本身就是相机：能拿到 token 级对应，就可能不需要单独的相机编码。动作经相机、再经对应进入模型，是一条可借鉴的条件化路径。
  • 硬路由的记忆读取极便宜（FLOPs 约 0.4%），可以接到 Self Forcing 这类 KV 流式模型上，按几何从历史 KV 里 gather。瓶颈会转移到每块的深度估计（14 s）上，也就是作者说的“把几何学进生成器”。
  • free / unknown 可见性账本是很便宜、不含外观的全局状态，值得借用，但要做成可修正、考虑视锥的版本。
  • 评测记忆时，要逼模型回忆中途生成的内容，不能只回到起点；同时报告算力。

最值钱的补充实验

  1. 公平的隐式基线：同骨干、同数据，稠密上下文加 Plücker 或 UCM 相机条件；以及 GCA-dense 加相机。
  2. 剔除 DL3DV-140 后重新评测，报告场景数、长度和方差。
  3. 现实的对应扰动：±1 patch、单候选区域、深度尺度误差；再加 null key 或门控做对照。
  4. 逐候选深度测试对比二维掩码；视锥外处理；可修正的八叉树更新。
  5. 4 步蒸馏后优势还剩多少；真实的逐块时延。
  6. 回访中途生成区域的协议；报全 WorldScore 7 项。
