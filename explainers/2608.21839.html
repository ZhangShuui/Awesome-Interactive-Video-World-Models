FIRM-Video · 先把「要查什么」写成一张可核验的清单，逐条对着画面查完，再让分数从核验结果里算出来

这篇论文真正解决的不是「怎么打分」，而是怎么造出可信的打分监督。 多阶段推理流水线判得准但太贵，端到端奖励模型够快但全看训练监督的成色——于是把昂贵的那条链离线跑一遍， 把它的可靠性蒸馏进一个 8B 模型。链的形状是三条：IF 的清单从提示词自上而下拆、 WC 的清单从视频自下而上 ground、PQ 用一张固定的缺陷分类表。 三条清单出处不同，归因也就自动解耦——同一处毛病不会被三个维度各扣一次。

00TL;DR

一图看懂：分数是从哪里冒出来的

三种做法的差别只有一句话：分数和理由，谁先谁后。 固定量表让模型自己决定查什么；开放式推理让理由和分数在同一次生成里纠缠； FIRM-Video 把顺序钉死——先有逐条核验，再有分数，最后才有理由，而理由不能反过来改分数。

一句话记住

别的方法是让模型「看完视频说个分」；FIRM-Video 是先给这一条样本写一份专属的验收单， 对着画面一条条打勾，然后把勾算成分。验收单可以被人检查，分数可以被回溯到具体哪一条没过。

01Problem

瓶颈不在模型，在监督

奖励模型要同时满足两件互相拉扯的事：判得准和判得起。 多阶段推理流水线准，但每条视频要调好几个大模型，做不到规模化；端到端奖励模型一次前向就出分， 可它准不准完全取决于训练时喂了什么。所以论文把问题重新定义成一句话： 如何为端到端奖励模型构造可靠的监督。

被点名的三种失效方式

论文对既有做法的批评很具体：它们缺一份逐样本的、可显式核验的评测合同——写明这一条样本要查什么，以及每个判断由什么证据支撑。缺了它，就会同时坏在三个地方。

① 检查不全 Incomplete inspection

评测者盯着显著的全局属性看，跳过提示词里指定的细属性、物体之间的关系、一闪而过的动作、事件的先后顺序，以及局部的画面瑕疵。 「整体感觉还行」和「第 3 条要求没实现」是两种精度。

② 理由不忠实 Unfaithful justification

不受约束的推理文本，可能是在为一个已经想好的分数补理由，而不是分数从这些理由里长出来。 读起来越顺，越难判断它是证据还是修辞。

③ 归因纠缠 Entangled attribution

同一段开放式推理被三个维度复用时，一处「手部结构畸变」会被同时读成语义不符、物理违背和画质缺陷——一处毛病扣三次分， 而三个维度本该是互补而非重叠的。

我的读法

这三条不是并列的三个 bug，而是同一个缺失的三个投影：没有把「要查什么」从「查得怎么样」里分离出来。 一旦分离，① 由清单的覆盖度负责，② 由「分数先于理由」的次序负责，③ 由三条清单的不同出处负责。 FIRM-Video 的三个设计点，正好一一对应。

02Architecture

三条清单，三个出处

整套框架只有一个统一动作：构造清单 → 逐条核验 → 只聚合已核验的判定。 三个维度共用这个动作，但清单从哪来完全不同——这正是归因能解耦的原因。 IF 的清单是提示词拆出来的（自上而下，提示词就是合同）； WC 的清单是视频 ground 出来的（自下而上，因为违背常常发生在提示词没提的东西上）； PQ 的清单是一张固定的缺陷分类表（与样本无关，人工整理）。

谁能看到什么：这套流水线里的信息屏蔽

这篇论文最容易被读漏的设计，是每一步刻意不给某些信息。 grounding 不给提示词，是为了让「查什么」由画面决定而不是被提示词带偏；WC 的核验器既不给提示词，也不给重要度，是为了让「查得怎么样」不被「这条有多重要」污染，权重只在最后的聚合公式里出现一次。 （IF 的核验器能看到什么，论文只列了「提示词 + 按时间排序的帧 + 清单」，没有说明重要度是否随清单一起给进去。）

「grounding 阶段决定评什么，提示词决定怎么解释它。」（the grounding stage determines what to evaluate, whereas the prompt specifies how it should be interpreted） 一句话把 WC 里提示词的角色限定死了：它不是评分依据，只是免责说明——如果提示词本来就要求一只会飞的鲸鱼，那么鲸鱼在天上就不算违背物理。

03Instruction Following

IF：把提示词拆成一份加权验收单

IF 评的是「视频有多准确、多完整地照做了提示词」——主体、属性、动作、场景、视觉风格、镜头视角，以及事件的先后顺序。 两个阶段：先把提示词拆开，再对着画面逐条查。

阶段一 · 提示词分解

文本规划器（Qwen3-32B）只看提示词，把它拆成一组原子的是非题，覆盖所有被要求的视觉元素， 并剔除与音频相关的要求（模型只看帧，判不了声音）。每条对应一个可观察的要求，并配一个重要度 mi ∈ {1,…,5}。

一个容易被略过但很重要的细节：同一个提示词生成的所有视频共用同一份清单。 数据集里每个提示词平均对应约 10 个不同模型生成的视频，共用清单既省掉 9 次规划器调用， 也让这 10 个视频的打分建立在完全相同的验收标准上——横向比较才有意义。

阶段二 · 清单核验

闭源多模态评测器拿到「提示词 + 按时间排序的视频帧 + 清单」，对每一条给出二值答案和一句画面证据。 规则里有一条保守的默认值：无法从视频中确认的要求，一律记为未满足。 这个默认值是有代价的——只采样 8 帧的情况下，「一闪而过但确实发生了」的要求会被判负（见 §10）。

sIF = Σi=1..N wi zi ,　　wi = mi / Σj mj　　　sIF ∈ [0, 1]
Eq. 1 / A.2

zi ∈ {0,1} 是第 i 条的核验结果。整个式子就是「按重要度归一化后的满足比例」。 附录 A.1 还写了序列化细节：权重四舍五入到两位小数；被舍成 0 的正权重强制设为 0.01；余量补给最大的那个权重，保证 Σwi = 1。分数保留四位小数。

我的读法：共用清单是把双刃剑

同一提示词的约 10 个视频共用一份清单，好处是横向可比、成本摊薄；代价是清单本身的偏差会被系统性地放大 10 倍。 如果 Qwen3-32B 把某个要求拆错了（比如把「camera slowly pans right」误拆成两条），这个错误会同时污染这一组的全部样本， 而且因为它们分数一起偏，训练时看起来还很「自洽」。论文没有报告清单质量的人工抽检结果，这是我最想看到的那个缺失数字。

消融：IF 上重要度加权几乎不起作用

附录表 4 把「均匀平均」和「重要度加权」放在一起比（清单、核验结果、映射全部固定）：IF 上 MAE 两者都是 0.68，SRCC 都是 0.69， 只有 STD 从 0.70 降到 0.68、宽松准确率从 0.88 升到 0.90，严格准确率反而从 0.44 掉到 0.43。 也就是说，IF 的收益几乎全部来自「把提示词拆开逐条查」这件事本身，而不是来自权重。权重真正发挥作用的地方在 WC。

04World Coherence

WC：清单必须从视频里长出来

WC 评的是「生成内容是否符合日常知识、常识与基本物理规律」——时序不一致、不自然或断裂的运动、物理上不可能的交互、 物体与人物的结构畸变或形变。它不能沿用 IF 的做法，原因很直接： 违背常常发生在提示词根本没提的东西上。

论文还给了第二个理由：即使改成「直接对着视频出题」，也会漏掉边缘实体和短暂动作—— 模型会自然地围绕画面主体出题，而穿模的路人甲、只出现半秒的手部动作正是违背高发区。 所以 WC 用了三个阶段，把「先把画面里有什么清点出来」单独拎成一步。

阶段一 · 视频 grounding（不给提示词）

多模态 grounding 模型（Qwen3-VL-235B-A22B-Instruct）在看不到提示词的条件下分析视频，产出三样东西： 结构化的场景摘要、实体清单、动作与交互清单。每个 grounded 目标 t 配一个重要度 mt ∈ {1,…,5}。论文对这一步的解释是：显式 grounding 既提高了目标覆盖率，又减少了提示词带来的偏置。

阶段二 · 清单构造（提示词只做解释）

文本规划器（Qwen3-32B）把每个目标转成一组核验问题：实体查时序一致性与结构合理性，动作查运动质量与物理合理性。 每个问题继承所属目标的重要度。论文提到有一道自动检查：目标覆盖不全会被检出并重新生成。 提示词只在这一步进场，用途单一——把「有意的奇幻设定、风格化、非常规运动」和真正的违背区分开。

阶段三 · 盲验（既不给提示词，也不给重要度）

闭源多模态评测器只拿到视频和问题。注意极性和 IF 是反的：这里回答「yes」表示检出了违背，「no」表示没看到违背。

ct = 1 − (1/|Qt|) Σj∈Qt bj　　　　sWC = Σt α(mt) ct  /  Σt α(mt)
Eq. 2 / A.3–A.5

ct 是目标 t 的「干净率」：这个目标下的问题里，有多少比例没查出违背。 分数是所有目标干净率的重要度加权平均。这个式子做了两件事： ① 目标只被部分影响时给部分分；② 聚合发生在目标层面而不是问题层面，所以内容丰富的视频不会因为「问题多」而被额外惩罚。

消融证据：WC 上加权是真的有用

附录表 4：目标级均匀平均 → 重要度加权，MAE 0.86 → 0.80，严格准确率 0.37 → 0.41，宽松准确率 0.82 → 0.84，SRCC 0.61 → 0.63。 对比 §03 里 IF 上「加权几乎无差别」，可以得到一个干净的结论： 当清单来自提示词时，条目本来就都是用户要的，重要度差异小；当清单来自视频时，画面里什么都有，重要度才成为必需品。

一个论文没写的细节

IF 明确规定「无法从视频确认的要求记为未满足」（偏严）。WC 这一侧，如果核验器对某个问题给不出判断，论文没有说默认记成什么。 按公式，bj 只有 0/1 两种取值，缺省成 0 意味着「没看到违背 = 干净」（偏松）。 两个维度的默认方向是相反的，而这会系统性地把 IF 的分数往下拉、把 WC 的分数往上抬。 结合 90K 里 IF 和 WC 的分布都偏低（2 分分别占 30.3% 和 37.9%），这个不对称值得复现时确认一下。

05Perceptual Quality

PQ：唯一一条不需要现造清单的链

PQ 评的是渲染出来的画面本身有多好看、多干净：分辨率、整体与局部清晰度、锐利或模糊、亮度与色彩稳定性、闪烁、压缩伪影， 以及其他影响观感的低层失真。这些缺陷与具体拍了什么无关，所以清单可以是固定的——论文用了一张人工整理的通用缺陷分类表。

流程只有一步：闭源多模态评测器按这张表分析视频，直接产出清单式的自然语言理由和一个 1–5 分。 提示词提供，但用途被严格限定——只用来认出「这是提示词要求的风格化打光」而不是「渲染错了」，不参与语义对齐判断。

论文没有公开这张分类表的完整条目；能确定的是维度定义与附录 D 推理提示词里列举的那几类。

我的读法：PQ 是三条里最弱的一环，而数据也这么说

三个证据放在一起看：① 结构上 PQ 没有可核验的中间产物（上图）； ② 结果上 PQ 的 MAE 0.82 没能拿到全表最优（Doubao-Seed-2.0-Lite 是 0.80），SRCC 0.51 也低于自己的老师 0.61； ③ 数据上 90K 里 PQ 的 4 分占了 62.5%，分布严重右偏——论文的解释是「现在的生成模型普遍能产出观感可接受的视频」， 这解释成立，但它同时意味着 PQ 这一维的训练信号方差很小，模型只要照着 4 分猜就能拿到不错的 MAE。 我倾向于认为，PQ 的做法更像是「为了三个维度对称而补上的一格」，而不是这套方法真正的贡献所在。

06Data Synthesis

从核验结果到 88,044 条监督

显式的 check-before-score 流水线能给出可靠的监督，但每条视频都跑一遍多阶段、多模型的链条太贵了。 论文的处理很直接：把这条链离线跑完，把结果做成训练数据，然后让一个 8B 模型学会一步到位。

把结构化判定「念」成自然语言

三条链产出的东西互补：IF 给出满足与未满足的提示词要求，WC 给出场景 grounding 与目标级违背，PQ 给出按通用清单的画质评估。 IF 和 WC 由 Qwen3-32B 转写成简短的、分维度的自然语言分析：

  • IF 分析：先总结满足了哪些提示词要求，再解释哪些没做到或做错了。
  • WC 分析：先给一句场景摘要，再按目标和评估方面组织主要违背。
  • PQ 分析：评测器本来就产出了连贯的清单式理由，直接用。

论文在这里写了一句必须划重点的话：「分数在生成理由之前就已确定，确保自然语言分析只是把已核验的判定说出来，而不会改变最终判断。」 这就是第 ② 种失效方式（不忠实的理由）的解药——不是让模型「说得更真诚」，而是让它没有机会说谎：分数已经算完了。

训练样本长什么样

// 输入：原始提示词 + 均匀采样的 8 帧 + 该维度的评测指令 // 目标：一个结构化 JSON { "reasoning": "<由已核验条目转写而来的分析>", "score": <1–5 的整数> }

只保留 IF / WC / PQ 三个维度都评测有效的视频，每条视频每个维度产生一条训练样本： 29,348 × 3 = 88,044。数据来源是两个人类偏好数据集——Rapidata 的 Text2Video-Human Preferences（过滤后约 3K）和 VideoFeedback2（约 27K）， 覆盖 20 多个生成模型（Sora2、Veo3、HunyuanVideo、Pika2.2、Wan2.1 等），每个提示词通常从约 10 个随机选中的模型各采一条视频。 提示词中位长度 27 个词，视频中位时长 3.3 秒，多数在 1–6 秒之间。

08Benchmark

FIRM-Video-Bench：先把尺子重做一遍

论文没有直接拿现成标注来评。它从 VideoFeedback2 和 VideoPhy2 里挑了 250 对提示词–视频， 把原标注全部丢掉（理由是采集口径不同、且含噪声），按自己的统一定义重新标一遍，得到 750 条逐维度标注。 与 FIRM-Video-90K 没有任何视频重叠。

标注流程：每条样本由多位人类专家独立打 1–5 的整数分，分歧通过讨论解决。 标注者拿到的材料是提示词 + 完整视频 + 模型看到的那 8 帧——完整视频用来做整体判断， 那 8 帧则是为了让人的判断和模型可用的视觉证据对齐。

这个细节比看上去重要：如果只让人看完整视频、只让模型看 8 帧，那么测出来的差距里会混进一大块「采样损失」，而不是纯粹的判断力差距。 论文选择把评测放在同样的证据条件下。代价是——这套 Bench 衡量的是「在 8 帧预算下与人对齐得多好」，而不是「视频真实质量判断得多准」（见 §10）。

配平也是刻意的：每个维度的每一档都有样本，任何一档都不超过 30.4%，为的是压掉「一律猜众数」的取巧空间。 论文列的主要指标是四个：MAE、严格准确率、宽松准确率（允许差 1 档）和 SRCC（排序一致性）；表 1 里另外报了绝对误差的标准差 STD。

WC 上，把模型放大没用

开源模型在 WC 的 MAE：InternVL3-8B 2.10、InternVL3-38B 2.11、Qwen3-VL-8B 1.79、30B-A3B 1.90、235B-A22B 1.63。 参数量涨了近 30 倍，误差几乎没动。SRCC 更刺眼：0.15–0.31，排序能力接近于无。 这不是容量问题，是没人告诉过它「按什么标准看物理合理性」。

IF 上，闭源模型本来就不差

GPT-5 的 IF MAE 是 0.62，仍然是全表最低，FIRM-Video-8B 的 0.65 只是接近它。 道理也直白：「视频有没有照着提示词做」是个描述性任务，强通用模型本来就会。 清单方法真正撬动的是那些没有现成标准可依的维度。

PQ 上，它没赢

Doubao-Seed-2.0-Lite 的 PQ MAE 是 0.80，FIRM-Video-8B 是 0.82。SRCC 上 FIRM 是 0.51， 不及自己的老师 0.61，也不及 Doubao 的 0.55。这与 §05 的结构分析吻合：PQ 这条链缺少可核验的中间产物。

两个基座都被显著抬起来

Qwen3-VL-8B：1.33 → 0.78；InternVL3-8B：1.56 → 0.85。 两个不同家族的基座都得到大幅改善，说明收益来自数据而不是某个基座碰巧和 grounding 模型同源 （grounding 用的是 Qwen3-VL-235B，与其中一个基座同族，这个混淆因素靠 InternVL3 那一支排除了）。

09Generalization & Best-of-N

换个场子还能不能用

Bench 是自己造的，所以论文补了两组外部验证：MJ-Bench-Video 上的成对偏好（域外泛化）， 和 VBench 上的 Best-of-N 采样（当选择器用，看它挑出来的视频到底好不好）。

MJ-Bench-Video：域外偏好判断

在三个能力档位不同的生成器上各生成 8 个候选，由不同的打分器挑一个，再交给 VBench 评。 比较对象是随机采样、Qwen3-VL-8B、InternVL3-8B 和 VideoScore2。

Total Score 的净胜幅

相对最强的那个竞争者（不是随机）：LaVie-Base +0.27（80.72 vs InternVL3 的 80.45）、 CogVideoX-2B +1.01（79.68 vs VideoScore2 的 78.67）、Wan2.1-T2V-1.3B +0.66（82.36 vs InternVL3 的 81.70）。 Semantic Score 的净胜幅是 +1.24 ~ +2.11。

候选池越大越稳

在 LaVie-Base 上扫 N ∈ {2,4,8,12,16}：N=2 时 FIRM 略输给 Qwen3-VL-8B， 但 N ≥ 4 全部第一，分数从 80.36 一路升到 80.97。N=16 时领先随机 1.03 分、领先 Qwen3-VL-8B 0.33 分。 候选越多，排序质量的差距越显形——这正是奖励模型该有的性质。

被主文跳过的一格：动态程度

附录表 7 里有一列 Dynamic Degree（画面运动量，映射给 IF 维度）。把随机采样当基准看：

LaVie-Base：随机 55.56 → FIRM 56.94（↑）　CogVideoX-2B：随机 73.61 → FIRM 65.28（↓ 8.3）　Wan2.1：随机 62.50 → FIRM 59.72（↓ 2.8，且是五种策略里最低）

也就是说，三个生成器里有两个，被 FIRM 挑出来的视频比随便拿一个更「不动」。 这是奖励模型的经典张力：静止的画面更容易「看起来什么都没错」——没有滑步、没有穿模、没有闪烁。 公平地说，CogVideoX 上所有选择器都掉（FIRM 还是其中最好的），但 Wan2.1 上 FIRM 是唯一低于随机的那个。 主文只报了「多数代表性维度第一」，这一格没有出现在正文里。如果之后真的拿它去做 RL 对齐，这会是第一个要盯的 reward hacking 面。

10Limitations

局限，以及我读下来的保留意见

论文自己写的局限只有一条，很坦率：目前只验证了「与人对齐」和「Best-of-N 选择」，还没有真的拿它去优化生成器。 下面是我读完之后另外记下来的几点——都标明了哪些是论文事实、哪些是我的判断。

① 整套监督的天花板，压在一个没有具名的闭源模型上

论文事实：IF 核验、WC 盲验、PQ 评测这三步都由「a proprietary multimodal evaluator」执行，论文自始至终没有说是哪个模型。 Qwen3-32B（规划）和 Qwen3-VL-235B-A22B（grounding）都点了名，唯独核验器没有。

我的判断：这是复现路上最硬的一道坎。清单方法的价值主张是「把评测拆成简单的是非题，让核验变容易」， 这个主张成立的前提是核验器足够可靠——而表 1 里那个 0.73 就是核验器加上这套聚合规则能达到的上限。 换一个更弱的核验器，整条链会退化到什么程度，论文没有做这个消融。对想复现的人来说，这个数字比 0.78 更重要。

② 8 帧的证据预算，和 WC / PQ 的定义打架

论文事实：训练与推理都是均匀采样 8 帧；视频中位时长 3.3 秒，即约 2.4 fps。 而 WC 的定义里包含「时序不一致、不自然或断裂的运动」，PQ 的定义里包含「闪烁 flickering」。

我的判断：2.4 fps 基本看不出闪烁，也很难判断运动是否连贯——8 帧之间的插值全靠模型脑补。 论文的处理是让 Bench 的人类标注者也看到同样的 8 帧，把评测放在同样的证据条件下，这在方法上是干净的； 但副作用是这套 Bench 结构上就无法暴露采样带来的损失。换句话说，0.78 这个 MAE 衡量的是 「在 8 帧预算下与人对齐得多好」，而不是「视频的时间性质量判断得多准」。 有意思的是 VBench 上 Temporal Flickering 反而拿了第一（98.12 / 97.33 / 99.22 均为最优），这说明 8 帧仍能捕捉到一部分统计线索， 但这和「真的看见了闪烁」不是一回事。

③ 所有的阈值都是「经验确定」的，且不对称

论文事实：评分映射阈值论文原话是 "empirically determined thresholds"，没有说明确定过程。 α(m) 是「预定义的递增权重」，也没有敏感性分析。IF 拿 5 分要求 s 恰好 = 1.00，WC 拿 5 分只要 s ≥ 0.89。

我的判断：这个不对称本身是合理的——IF 的每一条都是用户白纸黑字要的，漏一条就不该满分； WC 的核验器会误报，留 0.11 的余量是对噪声的让步。但既然两条尺子的形状差这么多， 读者就有权知道它们是怎么定出来的。整篇论文里，这是可调旋钮最多、说明最少的一块。 尤其 IF 那条刀锋直接决定了 90K 中 5 分样本的比例（20.4%），而它只是四个数字里的一个。

④ 训练集和测试集共享一个上游来源

论文事实：FIRM-Video-90K 的约 27K 来自 VideoFeedback2；FIRM-Video-Bench 的 250 条来自 VideoFeedback2 和 VideoPhy2。 论文明确保证「两者没有重叠的视频」。

我的判断：视频不重叠不等于提示词分布不重叠，也不等于生成模型构成不重叠。 Bench 里有相当一部分样本，很可能来自训练集见过的同一批提示词和同一批生成器。 这不影响「比基座强」这个结论（基座也没见过），但会让 0.78 相对于最强基线 Doubao-Seed-2.0-Lite 的 1.05 显得更好看一些。 MJ-Bench-Video 那组域外结果就温和得多——FIRM 在 Overall 上只排第二——这个对比本身就是提示。

⑤ 「efficient」这个词，全篇没有一个数字支撑

论文反复强调端到端奖励模型「far more efficient」、「substantially reducing inference cost」， 但没有报告任何时延、吞吐或 FLOPs 对比，也没给出数据构造阶段的总开销。 定性上这当然对（3 次 8B 前向 vs 7 次多模型调用，其中还有 235B 和闭源 API）， 但一篇把「准确度—效率权衡」写进摘要第二句的论文，我期待看到那张表。

值得肯定的地方，也说清楚

抛开上面这些，这套方法有两个我认为很扎实的设计：一是把「清单出处」作为区分三个维度的第一原理， 而不是像多数工作那样把三个维度当成同一个 prompt 模板的三次调用——出处不同，归因才真的解耦； 二是把「分数先于理由」写死在数据构造里，用流程约束取代了对模型「说实话」的祈祷。 这两条都是可以直接搬到别的评测任务上的、与视频无关的一般性做法。

11Relevance

它和「交互式视频世界模型」有什么关系

先把话说清楚：按本仓库的收录标准，这篇论文并不在范围内。 它既不做逐步动作条件，也不做因果 / 流式生成，更没有持久世界状态； 按宽口径的三条轴（动作控制、实时与流式生成、长时程一致性与记忆）来看，它也都不直接沾边。 它是评测与对齐侧的基础设施，不是世界模型本身。

但有两处关联值得记下来：

  • WC 维度评的就是「这个世界讲不讲道理」。结构畸变、穿模、滑步、物理上不可能的交互—— 这些正是交互式世界模型最难过的关。这篇论文的贡献是给出了一种把这个模糊判断 拆成可逐条核验的问题的做法：先 ground 出画面里有什么，再针对每个目标问「它在时间上一致吗 / 它的运动符合物理吗」。 这个拆法本身与视频是不是可交互无关，可以直接搬过来。
  • Best-of-N 和未来的 RL 对齐，是把生成器往「物理更靠谱」推的现成钩子。 论文自己把 RL 列为未来工作；但 §09 里那个 Dynamic Degree 下降的信号提醒我们， 在把 WC 分数当 reward 之前，需要先解决「静止画面天然更容易通过一致性检查」这个漏洞。

最后一个必须点明的边界：这套清单是在中位 3.3 秒、8 帧的片段上构造的。 交互式世界模型真正关心的长时程一致性——走开再回来，房间还是不是那个房间—— 完全超出它的评测预算。把这套方法用到长时程场景，需要的不只是加帧，而是清单本身要有跨片段的目标身份。

读这三段提示词能发现一个细节：推理提示词里没有任何清单。 模型被要求「先给简短推理，再给分数」，格式与开放式推理判官完全一样—— 差别全部藏在训练数据里。这也正是这套方法的主张：清单不需要出现在推理时，它只需要出现在监督里。
