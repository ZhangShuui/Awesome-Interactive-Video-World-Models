Recency Forcing 精读

给"中间那段历史帧"的注意力加一个随去噪步变化的负偏置，让它们在被踢出 KV cache 之前就已经无足轻重——外加一个把偏置搬到 softmax 外面、从而能用 FlashAttention 的代数恒等式。

机制本身很小也很便宜，只是一张只看时间距离 Δ和去噪步 t的 logit 偏置表。但"为什么有效"和"有多有效"论文都没讲清楚。按它自己的 Eq.8 与 β = Lhistory（按帧计，β = 12），第 1 个去噪步里所有历史帧的权重都不超过约 10⁻⁴，早期步骤实际上就是截断。Table 3 的 SOTA 质量分全部来自 dynamic degree 一项，扣掉这一项后训练版排在 Rolling Forcing 与 LongLive 之后。再者，最终选中的幂律族在"各步曲线在哪里分叉"这件事上，正好和论文自己测到的 R̃ 相反。

§1一页读懂

先把论文的故事原样讲一遍，再说我的判断。

问题

Self-Forcing / Causal Forcing 这类"从双向模型蒸馏出的 4 步因果视频模型"只在 5 秒（21 个 latent 帧）片段上训练，推到 60 秒会出现颜色漂移、糊、重复或主体变形。

论文的诊断

KV eviction mismatch：训练时上下文帧全在 KV cache 里，推理时显存有限，最老的帧会被驱逐。论文认为模型"依赖过的上下文被拿走了"。

论文的药方

不截断上下文，而是给 历史帧 的注意力 logit 加一个 ≤ 0 的偏置 TRB：离得越远越负，并且在早期（高噪声）去噪步压得更狠。等某帧真被踢出时，它早就没什么权重了。

全流程：两种用法共用同一套推理机制
实线 = 论文明确写出的步骤；虚线框 = 沿用前作、并非本文贡献的部分
我的判断 · 一句话版
  • 真正新的只有两样：① 让 ALiBi/KERPLE 式的距离偏置随去噪步变化，并把它用在"sink 与 recent 之间的那段历史"上；② BAR 这个工程写法（数学上精确，但不是唯一的精确写法）。
  • "KV eviction mismatch"这个诊断并不新：Self-Forcing §3.4 就发现过首块被驱逐导致的训练-推理不一致，并在训练时限制注意力窗口来模拟；LongLive 也用与推理一致的短窗口来训练。本文把两者都归为"截断"。
  • 按论文自己测的 R̃，驱逐边界附近的帧影响只剩 0.1%–0.4%。"驱逐拿走了模型依赖的信息"很难解释 60 秒退化。更可能起作用的是：压低漂移中的历史 + 随机强度的上下文增广 + 重训。
  • 结果层面，SOTA 靠的是 dynamic degree。所有默认超参也都是靠 dynamic degree 选出来的（§7 可交互复算）。

§2背景：滚动 KV cache 与"驱逐"

先把"窗口里有什么、谁会被踢出去"看清楚，后面的一切都建立在这张图上。

Wan2.1 的 VAE 在时间上压 4 倍：21 个 latent 帧对应 81 个视频帧，16 fps 下约 5.06 秒。模型按 块（chunk） 生成，每块 3 个 latent 帧，每块做 4 步去噪。生成完的块会以"干净帧"的身份写进 KV cache，供后面的块做注意力。

推理时注意力窗口 Lattention = 21 个 latent 帧，被切成四段：

  • global 视频最开头的 3 帧（第 0 块），永不驱逐，当 attention sink 用；
  • history 中间 12 帧（4 块），TRB 只作用在这一段；
  • recent 紧挨着的 3 帧（上一块），不衰减，负责短时运动连续性；
  • current 正在去噪的 3 帧。

训练和推理，到底差在哪

切到"训练片段"、把 k 拖到 6 就能看到：训练时最后一块看到的上下文正好也是 18 帧（第 0 块 + 中间 4 块 + 上一块），和推理时每一步看到的数量完全一样。所以在任何单独一步里，模型都没有被拿走"训练时能看到、推理时看不到"的帧。

真正不同的是窗口里装的内容：

  • 训练时最老的历史就是视频开头；推理时最老的历史是视频中段。
  • sink 与历史在内容上不连续，只能靠相对 RoPE 把位置"拼"起来。
  • 推理时每一步都有一块离开窗口，历史整体在慢慢漂移。

所以与其说这是"驱逐不匹配"，不如说是窗口内容的分布偏移。这个区分很重要：它决定了 TRB 的收益究竟来自"让驱逐变得无害"，还是来自"少依赖正在漂移的历史"。

§3诊断工具：位置响应 R(Δ, t)

论文最有意思的部分：先量一量"模型到底有多依赖第 Δ 帧"，再按测到的形状去设计偏置。

怎么量

取当前帧 xi，在第 t 个去噪步（t=1 噪声最大、t=4 最小），把距离为 Δ 的某一个上下文帧换成"同一个 prompt、换随机种子"生成的另一段视频里同位置的帧，看模型输出的速度场变了多少：

Eq.3 / Eq.4 R(Δ, t) = 𝔼 ‖ vθ(xit | x<i0) − vθ(xit | δΔ(x<i0)) ‖²   ,   R̃(Δ, t) = R(Δ, t)R(1, t)

用"替换成另一段合理视频的帧"而不是"加噪声"，是为了让扰动留在数据分布内。这个选择是对的。统计量是 30 个 prompt × 20 个替代上下文的平均，测量对象是 frame-wise 的 Causal Forcing。

  • 驱逐边界上的帧本来就几乎没影响。窗口 21 帧时，最老的历史帧离当前块约 Δ = 15–17。图上这里的 R̃ ≈ 1–4×10⁻³，也就是说，按论文自己的量法，基线模型对这些帧的依赖只有最近一帧的 0.1%–0.4%。如果驱逐前影响已经这么小，"驱逐拿走了模型依赖的上下文"就很难是 60 秒退化的主因。
  • 尾部并不单调。Δ ≈ 19–20 处曲线又抬头了。这正是视频最开头的几帧，也就是 sink 效应。Self-Forcing 论文专门讨论过 Wan 的第一个 latent 帧统计特性不同。这部分由显式的 global sink 负责，与 TRB 无关。
  • 单帧替换会低估"一段历史"的集体作用。相邻帧高度冗余：只换第 Δ 帧时，Δ±1 帧还保留着原内容，模型可以"绕过去"。要测历史整体有多重要，应该整段替换或整段删除。论文没做。
  • 归一化让近处"相似"部分是人为的。所有曲线在 Δ=1 处都被除成 1。"最近帧的响应在各步都接近最大，所以 recent 不衰减"这条理由因此有循环论证的成分。
  • 测量对象与使用对象不一致。R̃ 在 frame-wise Causal Forcing 上测，方法跑在 chunk-wise 上，免训练版又套在 Self-Forcing 上。

§4TRB：Temporal Response Bias

在 softmax 之前给每个 (query 块, key 帧) 对加一个只取决于时间距离和去噪步的数。

Eq.5 SDPA(Q, K, V; B) = Softmax( QK⊤√d + B ) V ,   Bi,j = bias(Δi,j, tdenoise) ≤ 0

三条设计原则：(1) 强度随去噪步变化，早期强、后期弱；(2) 随 Δ 快速衰减，对应 R̃ 的陡降；(3) 偏置非正，只压不放大。global 与 recent 不加偏置（B=0），只衰减 history。

三个候选族

Eq.6 线性biaslin = − α(t) · (Δ − Lrecent)
Eq.7 对数biaslog = − α(t) · log(1 + Δ − Lrecent)
Eq.8 幂律 ★biaspow = − β · Δ̃γ(t) ,   Δ̃ = Δ − LrecentLhistory ∈ (0, 1]
Eq.9 步调度 α(t) = αbase − t/4 ,   γ(t) = γbase · 2t   (t ∈ {1,2,3,4})

训练时 αbase ~ U(0, 2)、γbase ~ U(0, 1)，β = Lhistory；推理时 γbase = 0.1。全文实验都用幂律。

先把 Eq.8 读成人话

因为 Δ̃ 在 0 到 1 之间，γ 越小，Δ̃γ 越接近 1，偏置越接近 −β，所有历史被一起压到底；γ 越大，只有最远那一帧还被压（Δ̃=1 时恒等于 −β），近处的历史几乎不受影响。γ(t) = γbase·2t 随步数增大，所以第 1 步压得最狠、第 4 步放得最松。这符合原则 (1)。

还有一个没写出来的推论：最远的历史帧在所有步上都被压到同一个值 e−β。各步曲线在远端强制汇合。

  • α 在幂律里根本不出现。论文称"αbase 与 γbase 是仅有的两个自由参数"，训练时也采样 αbase ~ U(0,2)，但 Eq.8 只含 β 和 γ。在线性/对数族里，α(4) = αbase − 1 有 50% 的概率 ≤ 0，会违反原则 (3)。切到线性族、把 αbase 拖到 1 以下就能看到。
单位歧义：β 到底是 12 还是 4？

附录说推理时"Δ 按块计算"，但 Eq.8 里的 Lrecent = 3、Lhistory 都以帧为单位给出，β = Lhistory。按帧读，β = 12，最远历史乘子为 e−12 ≈ 6×10⁻⁶；按块读，β = 4，最远乘子为 0.018。两种读法差 2–4 个数量级，而 Fig. 2d 画出来的远端是 10⁻³（对应 β ≈ 6.9），与两者都不一致。好在 Δ̃ 在两种读法下相同，都是 0.25 / 0.5 / 0.75 / 1。

§5BAR：把偏置搬到 softmax 外面

FlashAttention 把 softmax 融进了 kernel，不给你插手 logit 的机会。BAR 的办法是：既然偏置只看位置、不看内容，就把它变成乘在 V 上的权重。

  1. 对一个 query 块，偏置只取决于 key 的位置：Bi,j 与 qi, kj 的内容无关。记 wj = eBi,j ∈ (0, 1]。
  2. 展开 softmax：oi = Σj esj+Bj vj / Σj esj+Bj = Σj esj wj vj / Σj esj wj，其中 sj = qikj⊤/√d。
  3. 构造增广的 value：ṽj = wj · [vj ; 1] ∈ ℝd+1，然后做一次不带偏置的标准注意力：õi = Softmax(qiK⊤/√d) Ṽ。
  4. õ 的前 d 维正比于分子，最后一维正比于分母，公共的 softmax 归一化常数约掉：oi = õi[:d] / õi[d]。精确，没有近似。

BAR 相关的三处保留
  • "零推理开销"没有被测量。Table 1 只对比了 FlexAttention+bias 和 BAR-FlashAttention 两个数，没有给"不加偏置的 FlashAttention"的耗时，也没说明序列长度、硬件、FlexAttention 是否经过 torch.compile。11.76× 的差距与 FlexAttention 论文自报的量级（0.68–1.43× FA2）相去甚远，更像是未编译或非最优用法。
  • "一次标准 FlashAttention 调用"有前提。要让一次调用里所有 query 共享同一个 Ṽ，同一次调用里的所有 query 必须看到同一行 w。这只在"Δ 按块计算、一次只算一个 query 块"时成立。Eq.5 写的是逐元素的 Bi,j，按帧计算时每个 query 帧要一个自己的 Ṽ。
  • 每个去噪步都要重算 Ṽ，因为 w 依赖 t。代价是 O(Nd)，确实很小，但 KV cache 里得存原始 V。

§7实验：数字都对得上，但结论要打折

§8存疑清单

按严重程度排序。点开看依据；每一条都尽量给出可核对的数字或原文位置。

高1. SOTA 质量分完全来自 dynamic degree

用 VBench 官方归一化常数逐行复算 Table 3，8 行全部吻合（误差 ≤ 0.01）。扣除 DD 后，训练版 84.73 < LongLive 85.24 < Rolling Forcing 85.47。训练版的领先完全来自 DD（贡献 5.81 分，Rolling Forcing 是 2.67）。

依据：Table 3；VBench 归一化常数；§7.1 可交互复算。

高2. 消融里的每个默认选择都只在 DD 上胜出，且文字与表格矛盾

扣除 DD 后：线性 84.69 > 幂律 84.39；γbase 0.01（84.77）> 0.1（84.39）；Lrecent = 0（86.29）与 6（84.90）都 > 3（84.39）。Table 4 中截断的 Quality 81.10 与 Imaging 66.40 都高于基线的 80.56 / 65.09，正文却说截断"harming the overall quality"。

依据：Table 4–7；§7.2。

高3. Table 6 的解释与 Eq.8 方向相反

Δ̃ ∈ (0,1]，γ 越小 Δ̃γ 越接近 1，偏置越接近 −β，压制最强。论文却写"small values insufficiently suppress distant frames, while large values over-suppress history"。要么公式、要么解释写反了。没有代码，读者无法判断实际实现的是哪一个，这直接影响对 γbase=0.1 这一默认值的理解。

依据：Eq.8、§4.2 "Effect of decay strength"；§4 实验台。

高4. 选中的幂律族与 R̃ 的"两轴结构"相反，"derived directly from R"没有拟合过程

R̃ 的步间差异随距离增大（t4/t1：1.3× → 约 2.5×）。幂律在远端强制汇合（Δ̃=1 时都等于 −β），差异集中在近端，β=12 时近端 t4/t1 ≈ 2,400×。线性和对数族反而是"近处重合、远处分叉"。全文没有任何从 R̃ 拟合 α/β/γ 的过程，免训练版的参数值也未报告。步间差异的量级也对不上：R̃ 是 2–3 倍，TRB 是 10²–10³ 倍。

依据：Fig. 2a/2d；Eq.8–9；§4"两轴结构"对照。

高5. 训练版缺少"同配方、不加 TRB"的对照

训练版是在 4×H100 上以 3,500 步 × batch 4 重跑 DMD；Causal Forcing 官方是 750 步 × batch 64。基线用的是官方权重。此外，训练时 γbase~U(0,1) 的随机采样本身就是一种上下文增广。Table 3/4 的提升目前无法归因到 TRB 的形状。

依据：附录 B；Causal Forcing 附录 D。

中6. "KV eviction mismatch 没有前人处理"不成立

Self-Forcing §3.4 明确描述了"模型习惯了总能看到第一帧，滚动时第一帧被驱逐后泛化失败"，并在训练时限制注意力窗口，让最后一块看不到第一块。LongLive 用与推理一致的短窗口 + frame sink 做"train-long-test-long"。本文把这两种都归为"截断"。它说截断损害运动一致性，证据只有 Fig. 3 一个例子，外加与正文相矛盾的 Table 4。

依据：Self-Forcing §3.4；LongLive §3.3。

中7. 按论文自己的 R̃，驱逐边界上的帧本来就几乎没影响

最老的历史帧在 Δ ≈ 15–17，R̃ ≈ 1–4×10⁻³。按论文自己的量法，驱逐本来就几乎"无损"，那么把驱逐变得更无损，不能解释 60 秒的大幅改善。更可能起作用的是降低对漂移历史的依赖、随机上下文增广和重训。论文引入了 R 这个诊断工具，却没有在 TRB 模型上重测 R，也没有直接测"丢掉最老块前后输出变化多少"。

依据：Fig. 2a；§3。

中8. 单帧替换扰动会低估历史的集体作用

相邻帧高度冗余，只换一帧时模型可以从邻帧"补"回来。陡降可能部分反映的是冗余，而不是"不用"。应补做整段历史替换或删除的成组消融。

依据：Eq.3 的定义。

中9. β 与 Δ 的单位不明，读法不同效果差 2–4 个数量级

附录说推理时"Δ 按块计算"，但 Lrecent=3、β=Lhistory 以帧给出。按帧 β=12，最远乘子 6×10⁻⁶；按块 β=4，为 0.018。Fig. 2d 的远端是 10⁻³，与两者都不符。

依据：Eq.8、附录 B、Fig. 2d。

中10. α 在幂律中不出现；若出现，α(4) 有一半概率为负

论文称"αbase 和 γbase 是仅有的自由参数"，训练时也采样 αbase~U(0,2)，但所用的 Eq.8 只有 β、γ。在线性/对数族中，α(t)=αbase−t/4 在 t=4 时 ≤ 0 的概率为 50%（t=3 时为 37.5%），会违背"非正偏置"原则。

依据：Eq.6–9、附录 B。

中11. BAR 的"零开销"未测量，11.76× 的对照设置不明

Table 1 没有"不加偏置的 FA"这个基线，也没给序列长度、硬件、是否编译。FlexAttention 论文自报在 ALiBi 等变体上是 FA2 的 0.68–1.43×。另外 V 从 128 维变成 129 维，常见 FA 接口需要 Q/K/V 同 head dim 且按 8 对齐，一般会落到更大的 head-dim 模板上。

依据：Table 1；FlexAttention 论文 §6.2。

中12. BAR 只和最慢的方案比，而且其"一次调用"有前提

key 增广、分组 + LSE 合并同样精确（我实测误差 ≤ 1.5×10⁻¹³）。后者不改 head dim。BAR 要求同一次调用内所有 query 共享同一行 w，只在块级 Δ 下成立。

依据：§5 验证。

中13. Table 2 是跨协议拼贴，差距小于协议噪声

基线数字分别来自 Self-Forcing（改写 prompt）、LongLive、Rolling Forcing（不改写、946 prompt）、Causal Forcing 四篇论文。同一个 Self Forcing 在两篇论文里相差 0.57，而本文对 LongLive 的领先只有 0.21。

依据：§7.3。

中14. 免训练版的增益可能主要来自共享的 sink + 相对 RoPE；并且漏引 ALiBi / KERPLE

三个免训练方法 DD 几乎相同（56.0–56.3），缺"Self-Forcing + sink + 相对 RoPE、不加 TRB"这一行；附录只说给 Causal Forcing 基线加了这两样。另外，Eq.6–8 分别就是 LLM 长度外推里的 ALiBi（线性）和 KERPLE 的对数、幂律变体（−r₁·log(1+r₂|m−n|)、−r₁|m−n|r₂），均未引用。"none of the three prior families modifies attention weighting"的说法过强：LongLive 的短窗口、Deep Forcing 的 Top-C 保留，本身都在改注意力能看到什么。

依据：Table 3、附录 B；KERPLE（NeurIPS 2022）。

低15. Table 7 的解释与数据不符，且无方差

"Larger Lrecent improves motion stability with diminishing returns"，但 Lrecent=6 的 Quality（82.14）和 Dynamic（49.03）都比 3 差。DD 从 40.9 到 81.6 再到 49.0 大幅非单调，说明 50 prompt 验证集的方差很大，而全文没有误差棒。另外，Lattention 固定时增大 Lrecent 会同时缩小 Lhistory 和 β，两个变量被混在一起。

低16. 用户研究的"最大优势在运动动态"只对 LongLive 成立，引用编号错

见 §7.4。对 LongLive 颜色一致性的 59.7%，按每格约 135 票估算，95% CI 下界约为 51%。附录把 Rolling Forcing 引成了 [25]（Rolling Sink）。

§9公道话、定位与值得补的实验

做对的地方
  • 数字自洽：Table 2 的 Total 都等于 (4·Quality + Semantic)/5；Table 3 的 Quality 都能用 VBench 常数精确复算；用户研究的百分比与"≈1,620 票"也对得上。
  • R(Δ, t) 是个好问题：把"模型用了多少历史"变成可测的量，并且注意到它随去噪步变化。用"换成另一段合理视频的帧"来扰动，避免了加噪声带来的分布外问题。
  • BAR 数学上精确，实现简单，不需要改 kernel。对部署在只支持标准 FA 的硬件（论文作者来自 Qualcomm）上很实用。
  • 便宜：免训练即插即用；训练版只要 4 张 H100 跑 12 小时。
  • 局限性写得诚实，给了 5 分钟的失败例。

定位

2026 年这条线大致分三类：做记忆（MemRoPE / MosaicMem / AlayaVista 等），做蒸馏效率（Causal Forcing / AnyFlow / CrossDistill / DSA），做"5 秒训练、推得更长"的外推（Rolling Forcing / LongLive / Deep Forcing / ∞-RoPE / Rolling Sink / Relax Forcing）。Recency Forcing 属于第三类，而且是其中最轻的一种：一个随去噪步变化的软窗口正则。它与记忆类方法的方向正好相反。它的主张是"少依赖历史"，所以窗口外的东西注定会被忘掉，Fig. 8 里鸟的例子就是这样。对交互式世界模型来说，这意味着它能缓解画质漂移，但不解决"回头看还是不是原来的样子"。

最值得补的六个实验

  1. 同配方重跑 DMD，分三组：不加 TRB / 随机硬截断 / TRB。把"TRB 形状"和"重训 + 随机增广"分开（对应存疑 5）。
  2. Table 3 加一列"扣除 DD"，并报 Rolling Forcing 用的 ΔQualitydrift（首末 5 秒画质差）和多种子方差（对应存疑 1、2）。
  3. 在 TRB 模型上重测 R̃，并直接测"丢掉最老块 vs 保留"的输出差。这才是"驱逐不匹配被关闭"的直接证据（对应存疑 7）。
  4. 成组版 R：整段历史替换或删除，衡量历史的集体作用（对应存疑 8）。
  5. 公开 β、Δ 单位和免训练参数，并在"扣除 DD"的指标下重做衰减族比较（对应存疑 3、4、9）。
  6. 计时补全：无偏置 FA / BAR / key 增广 / 分组 LSE 合并，在 Wan-1.3B 的真实形状上各跑一遍（对应存疑 11、12）。

核对方法：论文全文逐段通读。公式推导与数值（BAR 等价性、TRB 取值、VBench Quality 复算、扣除 DD 的均值、用户研究置信区间）都用脚本复算过。Fig. 2a 与 Fig. 6 的数值是在浏览器里把 PDF 放大后目测读出的。相关工作的数字都回到原论文核对过。
