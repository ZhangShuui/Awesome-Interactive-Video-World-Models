EchoWM

Open and Enterable Omnimodal World Models — 可进入的全模态世界模型

把「用户想怎么观察并穿过这个世界」抽象成唯一的交互语言：相机意图。 键盘按键和连续位姿都被映射成同一条度量尺度下的相对 6-DoF 轨迹；第一人称里它就是观察者自身的位移， 第三人称里它同时驱动角色位移、相机跟随与画面构图——而后者的耦合关系不写进网络结构，从数据里学。 在这条轨迹条件下，一个联合音视频扩散骨干同时吐出 720p 画面、环境声、音乐与语音。

00The one idea

一张图看懂：一条轨迹，两种世界响应

世界模型的老问题是动作空间绑定了具体载体——第一人称用 WASD 推观察者，第三人称要一套角色控制器加一套相机 rig， 开车、骑马、机器人各有各的语义。EchoWM 的做法是把这些全部退化成一句话：「接下来这台相机要怎么动」。 第一人称下这就是观察者的自我运动；第三人称下它是相机的演化，而角色该怎么走、相机怎么跟、场景怎么变， 是模型从数据里学到的观察者–主体关系，而不是一段显式的 rig 逻辑。

Architecture

统一视点语义与尺度

异构视频源的度量尺度和控制语义天然不一致，朴素归一化要么抹掉位移幅度、要么破坏控制一致性。 对策：离散命令与连续位姿同映射到相对 6-DoF 轨迹 + 一个数据集级固定尺度，几何以 relative UCPE 进注意力。

Data

音视频丰富度 × 控制精度

真实视频声音好但运动脏，仿真几何准但语义单薄。对策：四源互补的数据引擎，产出 AV-rich / control-clean / balanced-HQ 三套配方，让两种能力各自从最可靠的监督里学。

Training

解耦多模态质量与控制响应

把音视频合成和精确控制硬塞进一次训练会产生严重的分布冲突。对策：四阶段课程 AV-CPT → Action-SFT（冻骨干）→ Joint-FT（低学习率）→ 自回归后训练。

这篇文章的边界在哪
相机意图接口只覆盖导航与视点类控制——那些效果可以被相机运动表示的动作。 跳跃、攻击、物体操作这类语义动作不在建模范围内；论文也没有实现游戏引擎那样的规则、碰撞状态与确定性转移。 读的时候要一直记着这条线，否则很容易把它误读成「通用可玩世界」。

1.1三种媒体上下文，一个模型

M 可以是三种形态之一，训练时按概率采样，推理时对应三种使用方式：

  • 空 ∅ —— 纯文本条件生成，从零开一个世界。
  • 单张参考观测 I_ref —— 最常用的「进入某个已有画面」的入口；它同时钉住场景外观与初始视点。
  • 同步音视频前缀 (V₁:τ, A₁:τ) —— 续写模式；这也是多轮交互每一轮的输入形态。注意音频也在上下文里， 所以续写时声音和画面被同一段近历史约束，而不是画面续上了、环境声重新开始。

被暴露出来的上下文 token 保持干净（不加噪），并且不计入去噪损失——这一点在 AV-CPT 里写得很明确。

1.2结构化文本：把「持久属性」和「时变事件」拆开

标注管线用 Qwen3-Omni 与 Gemini-3-Pro 同时看视频和音频，输出被归一化成七个字段。 这七个字段不是随便切的，它们按是否随时间变化被分成两组，而这个分组直接决定了后面哪个阶段能用哪些字段：

持久上下文 · 四个静态字段

关键设计 · 防止文本泄漏运动
narrative 字段在所有轨迹条件训练里都被拿掉。理由很直接：它会用文字把「相机往左转、角色走过去」说出来， 模型于是可以从文本里读出目标运动，而不去看轨迹。拿掉之后，静态字段 + 参考帧定义初始场景， 轨迹成为唯一指定后续相机演化的条件。这条约束贯穿 Action-SFT 与 Joint-FT，是整套控制能力可信度的前提。

02World data engine

世界数据引擎：四种缺陷互补成一套课程

训练一个可进入的全模态世界需要四种属性同时成立：外观多样、音频自然、运动可交互、相机几何可靠。 现实是没有任何单一数据源同时具备这四点。论文的做法不是去找完美数据源，而是承认每种源都是残缺的， 然后设计一条管线让不同能力从各自最可靠的监督里学。

一个容易漏掉但很重要的区分
自采游戏同时留下了动作日志和实际相机轨迹，论文强调这两者记录的不是同一件事： 发出一个前进指令，角色可能被地形卡住、被物理阻挡，于是位移为零。 动作流记录的是控制意图，相机轨迹记录的是环境真正允许发生的运动。 两者都被保留在数据集里，但当前模型只用后者作为统一运动条件——动作流留给对齐分析和未来的交互建模。

2.2度量位姿恢复：为什么要先重建一分钟

除 UE 外的轨迹源都要从视频里反解相机。论文遵循 SANA-WM 的「稳健标注」原则： 把位姿估计与轨迹质控分开，不把估计器的原始输出直接喂给训练。技术栈是 ViPE 作优化框架， VGGT-Ω 提供时序连贯的长序列几何，MoGe-2 提供逐帧度量深度约束，ViPE 把两路线索联合优化成 时序一致、度量尺度的相机位姿与内参；并额外改造 ViPE 支持逐帧内参优化， 以应对网络视频里的变焦、防抖、裁剪和内参未知。

重建在 ≈1 分钟的连续窗口上做，而不是在最终的短训练片上做，原因有两条： ① 相邻片段因此继承同一次几何重建，落在共享坐标系里；② 长窗口给优化提供更宽的时间支撑与更持久的对应关系。 重建完再按统一时间边界切片，视频、立体声、位姿、内参、原生控制流用同一组边界切，时间戳按片段起点重新索引。

计算上不可能每帧都估，所以先时间下采样再估计，然后用 SLERP 插值旋转、线性插值平移把稀疏轨迹对齐回原始时间戳。 论文特意声明：这个插值只用于恢复帧对齐的轨迹标注，视频观测本身没有被合成或修改。

三类轨迹质检

  • 重建可靠性与内参标定稳定性；
  • 时序一致性：帧间平移/旋转抖动过大、朝向突变；
  • 运动合理性：不合理位移、退化轨迹、极端尺度离群。

不通过的序列在切成短片之前就被剔除。UE 真值轨迹走同样的坐标约定转换与运动范围检查，但原始度量值被原样保留。

3.1为什么监督用轨迹，而不是原始动作标签

论文给了三条理由，每一条都对应一个具体的失败模式：

  1. 数据覆盖面。帧对齐的动作日志只有被插桩的游戏和仿真才有；相机轨迹在位姿质检之后可以从大得多的视频池里恢复出来。
  2. 没有依赖控制器的逆映射。从观测到的相机运动反推伪动作是病态的：同一段位移可以来自不同的用户输入、控制器动力学或相机平滑规则。 第三人称尤其严重——角色运动和相机跟随共同决定了观测到的相机轨迹，你无法唯一地把它拆回按键。
  3. 连续 6-DoF。键盘是离散且系统相关的词表；相机轨迹直接保留连续的平移与旋转，包括垂直运动、roll、运动幅度、以及平移–旋转耦合——这些在按键词表里根本没有位置。
相对化解决了什么，没解决什么
ΔTt 去掉了全局刚体坐标系的依赖，同时保留了平移与旋转的连续幅度和方向。 但它没有解决异构数据源之间的平移尺度差异：同一个数值 0.5，在一段用 ViPE 恢复的手机视频里和在 UE 的真值里可能对应完全不同的物理位移。 这正是下一节要处理的问题。
接口的适用边界
这个接口的作用域被限定在「效果可以由相机运动表示的导航与视点类控制」。 攻击、跳跃、物体操作这类语义主体动作不在建模范围内。论文在方法一节和 Limitations 里各声明了一次， 说明作者自己也清楚这是全文最大的适用性折扣。

4.1三种选法的取舍

选法 A · 逐片段归一化

被否决

把每个 clip 各自归一化到相同范围，优化确实更容易。代价是抹掉了有意义的位移差异—— 「慢慢走近」和「冲过去」在条件里变成同一个数；更糟的是它会在续写边界处引入人为的尺度跳变， 上一段和下一段的速度尺度对不上。

选法 B · 取语料最大位移

被否决

用全语料最大值作为尺度，看似保留了全部动态范围，但对重建离群点极度敏感： 一条 ViPE 崩掉的轨迹就能把尺度拉大一个量级，正常轨迹全被压到接近 0 的窄区间里。

选法 C · 稳健分位数

采用

从度量训练轨迹里估一个稳健尺度 Q0.9。跨样本的位移关系被保留， 相邻 rollout chunk 落在同一速度尺度上，不会产生归一化诱发的速度跳变； 代价是 90 分位以上的轨迹被丢弃，训练分布上限被硬性截断。

这个设计想换来的是什么
是推理期的速度可控性：因为尺度固定，用户给出的轨迹幅度就成了一个真正的控制量—— 「走近一点」和「冲到跟前」在条件里是两个不同的数，模型也应当给出不同的realized位移。 论文在 5.5.1 里为此设计了完整的评测协议（相关性、响应斜率、绝对尺度误差、跨 chunk 速度变化）， 但正文里没有给出对应的数字表格——这是第 10 节要展开的一个实质性缺口。
05Relative UCPE conditioning

把相机几何塞进注意力，而不是塞进一个编码器

有了标定好的轨迹 P₁:T，剩下的问题是怎么注入。 主流做法是 Plücker 射线 + 一个独立的相机编码器；EchoWM 换成 UCPE：把成对的相对射线几何直接放进注意力的位置编码里。 这个替换不是效率优化，它改变了条件信号的不变性。

5.1基线的问题：Plücker 坐标是绝对的

06Progressive training

四阶段课程：让每种能力从它最干净的信号里学

第 04 节那两条分布曲线已经把冲突摆出来了：富音视频样本运动幅度小，控制干净样本运动幅度大。 如果在同一次训练里同时优化两种目标，两个分布会互相拉扯。论文的解法是把它们在时间上分开， 并且用参数冻结而不是损失权重来隔离。

07Streaming AR post-training

把双向多步扩散改造成因果少步流式生成器

前三个阶段结束时，模型是一个双向、多步的音视频扩散器：要看到整段才能出结果，每个 chunk 要跑几十步去噪。 要变成能实时交互的世界，需要两个正交的改造：把时间注意力改成因果的，以及把迭代去噪压成少步采样， 并且后者必须在自己生成的历史上仍然稳定。论文分三步做完。

7.1第一步：音视频 Teacher Forcing

把视频与音频两条 latent 流切成 N 个时间对齐的宏 chunk。一对视频–音频 chunk 覆盖相同时间区间， 但两者token 数可以不同。对每一对采一个共享的噪声水平 σi，让配对的音频与视频处在一致的扩散阶段：

xmσ_i, i = (1 − σi) xmi + σi εmi ,   εmi ∼ 𝒩(0, I) ,   m ∈ {v, a} 共享 σi 是保持跨模态同步的最小机制：如果视频和音频的加噪水平各走各的，交叉注意力交换的就是不同扩散阶段的信息。
(13)

为了在不牺牲训练并行度的前提下实现因果生成，把干净 latent 与加噪 latent 拼接在一起，然后施加下面的注意力可见性：

𝒮( Bi,clean ) = { Bj,clean : j ≤ i } ,    𝒮( Bi,noisy ) = { Bj,clean : j < i } ∪ { Bi,noisy } 每个加噪 chunk 能看到全部在先的干净历史与本 chunk 内的加噪 token；对应的干净目标与所有未来 chunk 都被屏蔽。 同样的因果约束施加在 video 自注意力、audio 自注意力、A2V、V2A 上。
(14)
ℒTF = Σm∈{v,a} λm 𝔼 [ Σi=1..N ‖ vmθ( xmσ_i,i, σi | C, P(≤i) ) − ( εmi − xmi ) ‖22 ] 目标函数没有换——还是预训练那套 flow matching，只是注意力可见性变了。 这一步的产物是「一个能因果生成、但仍需多步去噪、且只在真值历史上训练过」的模型。
(15)

7.2第二步：短程音视频 Self-Gradient Forcing

Teacher Forcing 之后还剩两个差距：① 训练时看的是真值历史，推理时看的是自己生成的历史； ② 每个 chunk 仍然要多步去噪。SGF 一次解决两个——在自生成的自回归历史上训练， 同时用 DMD 把多步生成器蒸成少步采样器。它的巧妙之处在于怎么把梯度找回来。

x̄s,i = (1 − s) x̄i + s ηi ,   ηi ∼ 𝒩(0, I)    ·    ℒDMD = 𝔼i,s,η [ w(s) ⟨ sg( sfake(x̄s,i, s) − sreal(x̄s,i, s) ) , x̄i ⟩ ] 与普通 DMD 的区别只有一处，但很关键：这里的 x̄i 是在生成器自己产生的音视频历史下得到的预测， 所以这个目标同时完成了「少步蒸馏」和「适配自回归推理时的历史分布」两件事。
(16–17)

7.3第三步：长程 SGF 与有界因果上下文

短程 SGF 只覆盖基础模型的时间跨度。持续流式生成时，模型面对的历史里累积了长得多的序列上的误差。 于是继续在更长的同步音视频轨迹上做自 rollout 训练：少步采样器与 DMD 目标沿用，只是 rollout 被拉长。

  • 段间续帧。长轨迹由多个片段顺序生成，每段用短程 SGF 时的 rollout 长度。 第 k 段的最后一帧作为第 k+1 段的首帧——模型不会在段边界重新从一个独立的视觉状态开始， 后面的段因此继承前面段累积的预测误差，这正是训练想要暴露的状态。
  • 有界缓存。完整因果 KV cache 会随 rollout 无限增长，改为每个模态各维护一个 sink + FIFO 缓存。
Hmi = [ x̂m1, …, x̂mmin(S_m, i−1) ] 注意力 sink  ‖  [ x̂mmax(S_m+1, i−R_m), …, x̂mi−1 ] 近期 FIFO 每层注意力可直接访问的历史 chunk 数被限制在 Sm + Rm，与 rollout 总时长无关。 sink 保留生成轨迹的固定前缀，FIFO 保留最近上下文。
(18)
逐层长程梯度：为什么窗口有界，感受野却不有界
sink+FIFO 限制的是单层里一个 query 能直接够到的 K/V。但上层保留下来的那份 FIFO 表示， 在更低的层里已经吸收过它当时可见的因果上下文。反向传播时，后面 chunk 的损失先到达当前层可见的 sink 与 FIFO 表示， 再继续往下层走，通过中间 chunk 触及更早的 K/V。堆叠因果注意力层因此形成一条多层梯度路径， 其有效时间跨度可以长于任何单层的直接窗口。而这一切都不需要对串行 rollout 反传—— Forward 1 记录的潜变量、去噪状态与缓存轨迹始终是 detach 的。
ℒLong-SGF = Σk=1..K ℒ(k)DMD 每一段都算损失，而不是只监督轨迹末尾。于是每段都在自生成轨迹的不同阶段受到监督： 靠后的段所处的历史里已经反映了前面段积累的误差。
(19)

两个实现约束值得记下来：生成器在长程 rollout 中保持原有 RoPE 配置，与 sink+FIFO 缓存策略无关； 而 real/fake 两个 score 模型仍是预训练那套定长双向架构，因此它们的 DMD 求值被限制在预训练观察过的时间范围内。

08Interactive inference

两种续写模式：重编码尾窗 vs 持久缓存

论文明确区分了两种推理模式，并强调它们的差别只在历史管理方式上——轨迹接口与模型参数化完全相同。

模式 A · 双向多轮续写
取上一轮生成结果的尾窗作为下一轮的干净上下文：
M(j−1) = Tailw( V(j−1), A(j−1) )  (20)
( V(j), A(j) ) ∼ pθ_PT, φ_PT( · | M(j−1), C(j), P(j)1:T )  (21)
每一轮可以换一条新轨迹。因为上下文窗口里同时含视频与音频，画面与声音的续写被同一段近历史约束。 这是「tail 重新编码」模式，代价是每轮都要重新编码尾窗。
模式 B · 因果流式推理
不从解码后的尾窗重启，而是维持一份持久流式 KV 缓存：视频、音频各一套， 外加与 video token 绑定的相机注意力 KV 状态，结构与训练时的 sink + local 一致。
( V, A ) ∼ pθ_PT, φ_PT( · | K(t), C, P )  (22)
旧的 local token 被移出时，对保留下来的缓存重新 rebase 时间 RoPE 与相机编码，保持位置布局一致。 持久 sink 在整段自回归 rollout 里提供长期上下文，不需要外部记忆库。
和显式检索式记忆的取舍
WorldMem、Context-as-Memory 这类方法按位姿或视场索引并检索历史视图； Infinite-World、WorldPlay、Matrix-Game 3.0 则维护分层或相机对齐的记忆。 EchoWM 选了另一条路：不做检索，只保留有界的 sink+FIFO 历史，并从过去 chunk 里写出一份紧凑状态。 好处是省掉了长历史搜索与匹配的额外计算；代价写在 Limitations 里——没有显式的持久 3D 记忆， 几何、主体身份、世界状态与音频会在反复续写中漂移。第 09 节的 revisit consistency 指标就是在量这件事。

9.6消融：写了协议，但数字大多没给

论文的消融围绕四件事组织：轨迹尺度、相机意图语义、推理期速度控制、以及音视频预训练任务配比。实际给出的内容是：

  • 定性尺度控制（Fig. 22）：在匹配的参考观测与导航条件下，LingBot-World-v2 在相机接近前景角色时会出现主体表观尺度的突变、 位移响应难以预期；EchoWM 的尺度变化更渐进可控。——定性图，无数字。
  • 推理期速度控制：构造「相同参考观测、相同方向与旋转，只改平移幅度」的轨迹组，测 realized 位移与请求位移的 相关性、响应斜率、绝对尺度误差，多 chunk rollout 还要测跨边界的 realized 速度变化。 ——协议描述完整，但正文没有给出对应的数值表格。
  • 视点语义（Fig. 24）：第一人称下 LBW2 会在 rollout 中途切换成外视角，EchoWM 保持自我中心语义； 两个第三人称例子里 LBW2 把被控主体（人 / 球）跟丢，EchoWM 保持主体在画面内。——定性图，无数字。
  • 3D 重建佐证（Fig. 19）：对生成序列做三维重建，跨视点仍保留可辨识的场景布局与主要表面。 论文自己声明这依赖下游重建流程，只作为多视一致性的定性支持，不主张度量几何精度。
这一节是全文最薄的地方
「全局尺度标定优于逐片段归一化」是本文三大技术设计之一，作者也为它写好了完整的量化协议， 但读者在正文里拿不到那组数字。同样，UCPE 相对 Plücker + 相机编码器的收益、四阶段课程各阶段的边际贡献， 也都没有对应的消融数值。也就是说：方法论上的主张是清楚的，实证支撑主要落在两个整体基准的端到端分数上。
10Limitations & critical reading

局限与批判性阅读

先把作者自己承认的写清楚，再说我读下来觉得需要保留判断的地方。 需要说明：以下第二部分是我的判断，不是论文的结论，也未必正确——每一条我都尽量指回可核对的表格或段落。

10.1论文自陈的局限

  • 动作空间受限。只覆盖能被相对 6-DoF 轨迹表示的导航与视点动作；跳跃、攻击、操作、机器人指令都不被显式建模。 也没有实现常规游戏引擎的规则、碰撞状态与确定性转移。
  • 没有显式持久 3D 记忆。几何、主体身份、世界状态与音频会在反复续写中漂移。
  • 交互幅度受全局过滤器限制。对显著更大的位移、更高的速度或异常旋转，泛化性未被验证。
  • 位姿标注仍不完美。来自网络与游戏视频的位姿估计即使经过过滤仍有误差，并且可能与场景内容或运动模糊相关。

10.2我读下来的保留意见

01 · 证据缺口

音频端零定量指标

「omnimodal」是全文最大的差异化卖点，但音频只有 Fig. 20 的四个定性例子和一句免责声明 （不主张有单独监督的 action-to-sound 能力）。没有 AV 同步性、音频质量、语音可懂度（如 WER）的任何数字， 也没有和 LTX-2.3 / Cosmos 3 这类原生音视频模型的音频侧对比。Table 1 里那一整行勾， 目前只有视频与控制两列有基准背书。

02 · 证据缺口

核心设计的消融数字缺席

全局尺度标定、relative UCPE、四阶段课程是论文自陈的三大技术贡献。 5.5.1 为尺度标定写好了量化协议（相关性 / 响应斜率 / 绝对尺度误差 / 跨 chunk 速度变化）， 正文却没有给出结果表；UCPE 与课程的边际收益也没有对照实验。 读者只能从两个端到端基准反推整体有效性。

03 · 指标落后

Hard split 上的位姿精度不如 SANA-WM

短程 241 帧 Hard split：R 1.697 vs 1.248、T 0.256 vs 0.199、CMC 0.266 vs 0.206，三项全输； 长程 961 帧 Hard split 旋转误差 12.05 vs 10.02 仍然落后。 对一个把「可控性」当作立论核心的世界模型，困难轨迹恰恰是最该赢的地方。 论文用画质领先来平衡，逻辑成立，但不能替代。

04 · 措辞

长程多步设置下并非 VBench 第一

Table 6 里 LingBot-World 的 VBench 是 81.82 / 81.89，高于 EchoWM 的 81.36 / 81.72。 论文正文只列举自己赢的项（最低 T 与 CMC、最高重访 PSNR），没有说自己在综合画质上是第二。 字面无误，但读者容易被引导。

05 · 数据可疑

蒸馏前后两维分数的反常跷跷板

EchoWM → EchoWM-Flash：Setting +8.9、Consistency −12.3。 同一模型的因果四步蒸馏很难同时带来这两个方向的巨变。 更可能是这两维在 158 例上噪声较大或口径耦合。这直接影响 Average 仅领先 0.8 分的可信度。

06 · 设计权衡

P90 之上整条丢弃 = 硬截断分布上限

为了避免裁剪改变位移幅度，超过 s_global 的轨迹被整条剔除。 好处是尺度语义干净，代价是训练分布的运动幅度上限被人为设死—— 这正好对应作者在 Limitations 里承认的「更大位移/更高速度不保证泛化」。 可控性与覆盖度之间的这个折中，论文没有给出别的解法。

07 · 概念张力

训练学的是「已实现运动」，用户给的是「意图」

论文明确区分了动作日志（控制意图）与相机轨迹（环境实际允许的运动），并选择用后者训练。 这让模型学到了「被墙挡住就不动」这类真实响应，是优点。但推理时用户可以随手给出一条 在该场景里不可达的轨迹——模型是硬跟随、还是穿墙、还是拒绝，论文没有讨论，也没有实验。

08 · 标注耦合

控制精度评测里混着标注噪声

非 UE 数据的位姿来自 ViPE 估计，作者承认误差可能与场景内容或运动模糊相关。 这意味着训练标签的噪声不是独立同分布的，而是和画面内容耦合的； 在以位姿误差为主指标的评测里，这种耦合会同时影响训练与评估，难以拆开。

同时也要说清楚：哪些结论我认为是稳的
① 因果同类之间的长程对比（Table 7）是全文最扎实的结果——EchoWM-Flash 在画质、三项轨迹指标与三项重访指标上都取得同类最好成绩（Simple split 的重访 PSNR 为并列第一）， 且 IQ 窗口分解（Fig. 10）经得起「ΔIQ 小可能只是本来就差」这一质疑。 ② 把离散命令与连续位姿统一成相对 6-DoF 轨迹这个接口设计，本身的合理性不依赖实验—— 它解决的是一个可以被清楚论证的表示问题（无控制器逆映射、连续 6-DoF、数据覆盖面）。 ③ 「narrative 字段必须移除」这条防泄漏约束是可迁移的工程经验，任何做条件控制的人都该抄。
11Where it sits

在这条研究线上的位置

EchoWM 的定位可以用一句话说明：它站在两条此前基本平行的线的交点上。

线 A · 交互式世界模型（强控制，静音）
Genie 3 · Matrix-Game 3.0 / 3.5 · LingBot-World · SANA-WM · DreamX-World · WorldPlay · Infinite-World。 它们把视觉保真度、域覆盖和交互时长推得很远，但基本都是纯视觉世界模拟器， 且交互接口往往绑定特定域、环境或控制方案。
线 B · 联合音视频 / 全模态生成（强感知，弱控制）
Movie Gen · Veo 3 · SyncFlow · LTX-2 系列 · OmniForcing · Cosmos 3。 原生音视频联合生成已经很强，但大多不暴露对生成世界的连续几何控制。 EchoWM 的骨干正是来自这条线（LTX-2.3）。

技术血统上，EchoWM 的每个部件都能找到明确来源，贡献在于组合方式与工程取舍：

  • 相机条件：CameraCtrl 的 Plücker 稠密射线 + 独立编码器 → LingBot-World 的 AdaLN 调制 → UCPE 的注意力内相对射线几何。EchoWM 取最后一条，并只用其相对射线部分。
  • 因果化：Diffusion Forcing 把全序列生成器改成因果预测 → Self Forcing 在自生成 rollout 上训练 → Self-Gradient Forcing 在此基础上找回上下文梯度。
  • 长上下文：FramePack 限定 token 预算 · LongLive 保留早期帧作 attention sink → EchoWM 的 sink + FIFO。与 WorldMem / Context-as-Memory 的显式检索路线相对。
  • 少步蒸馏：DMD 的分布匹配目标，在自回归历史下重新解释。
  • 条件组织：WorldEvent 的「持久场景描述与时变运动描述分离」，在这里落地为静态四字段 + 显式几何轨迹。
如果只带走一件事
不是 UCPE，也不是 SGF——这两个都是别人的。真正属于 EchoWM 的判断是： 「相机意图」这个抽象层次，恰好是既能统一异构输入设备、又能统一第一/第三人称、还能从海量无标注视频里恢复监督的那个层次。 它比按键高，比角色动作低；高一层会丢掉几何精度，低一层会绑死载体。 这个抽象选得准不准，是这篇文章能不能立住的真正赌注。

D五条可迁移的设计原则（论文 Discussion 的提炼）

  1. 把交互建立在观察意图上，而不是给每种视点定义一套控制语义。
  2. 在「世界」这一层表示交互：不同输入设备的效果通常都能表示为共同的相机空间变化，从而不把生成器绑死在某种输入布局或动作编码器上。
  3. 让尺度与视点语义显式化：逐样本归一化会让优化变容易，却抹掉了交互条件本该表达的相对位移；而单靠几何也无法说明一次旋转是自我中心的、跟随角色的还是环绕的。
  4. 把音频留在被生成的世界内部：轨迹只进视频流，声音通过既有的跨模态耦合被间接影响，因此不需要显式的 action-to-sound 控制器。
  5. 让每个训练阶段对上它最干净的信号：先用富音视频建世界先验，冻住它再用控制干净数据单点学导航，最后用小学习率在交集上共适应。
