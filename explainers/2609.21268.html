Edit-VAR

不训练、不反演：把源视频直接编码成由粗到细的离散 token，再在每个位置上决定「留着源的」还是「换成编辑提示下的新预测」

它要解决的老问题。扩散式视频编辑常卡在两难里：要么先把视频"反演"回噪声、再按新提示重新生成——反演是数值近似，误差会沿时空累积，背景跟着漂； 要么不反演，直接用源视频去牵制生成——牵得太紧，该改的地方又改不动。

它换了一类骨干。视觉自回归（VAR）模型的 tokenizer 能把任何视频确定性地编码成一整套由粗到细的离散 token。 "源视频在模型里长什么样"不需要反推，直接编码就有——反演误差这一头因此消失了。

编辑变成逐位置的选择题。每个位置上，沿用源 token，还是采纳编辑提示下模型自己的预测？ 判据是：这个源 token 从源提示换到编辑提示后，模型对它的支持度掉了多少。掉得越多越该换。"允许掉多少"由两样东西决定： 交叉注意力（越像是要改的物体，越宽松）和尺度位置（最粗的几个尺度完全照抄源，保住布局和运动）。 最后再用残差剪枝让最后两个尺度只有一半 token 过 Transformer，省时间。

00The whole thing

一图看懂：两遍前向，一道门

整套方法只有两次前向，不训练任何参数。先用五句话把它说完，再看图。

  1. 源视频不用反演。VAR 的 tokenizer 直接把它编码成 30 个尺度、由粗到细的离散 token——这就是"源参考"。
  2. 第一遍：照着念。用源提示跑一遍模型，但每一步都把编码好的源 token 硬塞进去（teacher forcing），只让模型报出"它对这个答案有多大把握"（记作 p̂src），顺便记下锚点词（比如 "zebra"）的注意力落在哪。
  3. 第二遍：正常生成，但每一步都过一道门。换成编辑提示生成。每个位置上比一比：源 token 在新提示下的支持度掉了多少？掉得太多就换成新预测，否则保留源的。
  4. "允许掉多少"（γ）因地而异。注意力高的地方（要改的物体）门槛宽松，背景严格；最粗的几个尺度 γ = 2，完全照抄源，保住布局和运动。
  5. 高分辨率尾巴上省时间。最后几个尺度第一遍不再真算——论文叫 Scale-Decoupled Generation，本页简称"尺度解耦"，它的边界就是 Sstop；第二遍最后两个尺度只让一半 token 过 Transformer（残差剪枝）。

01Why autoregression

为什么把编辑搬到 VAR 上：源参考不用"找回来"

这是全文立论的基础，而且它来自骨干的结构，不是调参调出来的。

扩散式编辑想拿到"源视频在模型内部长什么样"，只有两条路。一是反演：把视频沿采样轨迹一步步推回噪声，再按编辑提示重新生成——反演是数值近似，误差会在时空里累积，表现为背景漂移和帧间闪烁。 二是不反演：用某种传输或引导把源视频"牵"住——牵得太紧，语义就改不动。论文

VAR 至少拿掉了第一个问题：它的 tokenizer 编码器本身就是一个确定性函数，把任意视频映射成每个尺度上的离散 token 索引。源参考是编码出来的，不是反推出来的，所以不存在"反演误差"。 但"改得动 vs 保得住"的权衡并没有消失，只是从"反演质量"变成了一个可以显式调节的旋钮 γ（第 03 节）。

论文附录 C 给了一个直观的对照：同样的输入帧，Wan2.1 走「VAE 编码 → 反演重建 → 解码」，InfinityStar 走「编码成多尺度离散 token → 直接解码」，都在全帧上算重建指标。论文

离散 token 的第二个便利

VAR 每一步都是在有限个候选里"挑"一个。既然是挑，就可以在挑的那一刻插手——给某个候选加偏置。扩散模型没有这样一个离散的、可以逐位置干预的选择时刻。

由粗到细，天然对应"改什么"

早期尺度决定布局和运动，后期尺度决定纹理。于是"保留结构、重画细节"可以直接写成一条关于尺度下标的规则，不需要额外的分割网络。

代价：结构改不了

作者在局限里写明：方法本质是逐位置替换，删除物体、大幅改动布局这类需要"把腾出来的区域合理补上"的编辑做不了。这是设计决定的，不是调参能绕开的。论文

02The decision rule

决策规则的真面目：一道"置信度门槛"

论文把这条规则写成 token 级的两式对比，读起来有点抽象。化简一下再对照代码，它其实是一句很具体的话： 只有当编辑模型足够确定"这个源 bit 该变"时，它才会被翻掉；在默认设置下，这个"足够确定"至少是 80%。

先认识几个符号

符号名字人话
x̂源 tokentokenizer 从源视频编码出来的那个 token——"原来是什么"
x*编辑最优编辑提示下模型最想要的那个 token（argmax）——"新提示想要什么"
p̂src(x̂)源把握第一遍、源提示下，模型给源 token 的概率——"原来就该是这个吗"
pedit(·)编辑分布第二遍、编辑提示下，模型给各个候选的概率
γ容忍度允许支持度掉多少还保留。2 = 永远保留，0 = 完全不管源。它随位置和尺度变化（第 03 节）
γstart, γfg/bgendγ 的起点与终点最粗尺度 γ = 2.0；最细处前景降到 1.60、背景降到 1.78。计算器里的"前景 1.60 / 背景 1.78"就是这两个终值，过渡中的尺度 γ 更高（第 03 节）
b偏置额外加给源 token 的分：max(γ − p̂src, 0)
τ翻转门槛本页推导的等价形式：编辑模型给源 bit 的概率低于 τ 才翻（论文里没有这个符号）

论文怎么写 论文

在尺度 s 的位置 i 上，先给源 token 算一份偏置，再和编辑分布的最优解比：

bi(s) = max( γi(s) − p̂src(s)(x̂i(s)) , 0 )　　…… 式 (2)
xi(s) = x̂i(s) 若 pedit(x̂i) + bi ≥ pedit(x*i)，否则 x*i　　…… 式 (3) 翻译：给源 token 加上偏置 b 之后，如果它的得分还不低于编辑分布的第一名，就保留源 token，否则换成第一名。

论文接着做了一步关键的改写：偏置为正时，源 token 的调整后得分可以整理成

pedit(x̂) + b = γ − [ p̂src(x̂) − pedit(x̂) ]　　…… 式 (4) 方括号里是"支持度跌落"：从源提示换到编辑提示，模型对这个源 token 的支持掉了多少。源 token 不是按自己的绝对概率参赛，而是按"掉了多少"参赛——掉得越多，越容易被换掉。

这是整篇方法的立意所在。它还有一个不太直观的推论：源模型自己越没把握的 token，反而越会被保留。 因为跌落量最多也就 p̂src 那么大：源模型只给了 0.3 的 token，就算编辑模型把它压到 0，也只跌了 0.3，调整后得分 γ − 0.3 ≥ 1.3，赢下任何对手都绰绰有余。 这个性质在第 06 节会用到。

代码里是什么：逐 bit，不是逐 token 代码

骨干 InfinityStar 继承 Infinity 的按位（bitwise）建模：每个 token 由若干个二值比特组成——每个塔前 12 个"语义尺度"是 16 bit，后 3 个"细节尺度"是 64 bit——预测头对每个 bit 各做一次二分类， 而不是在 216 或 264 个码字上做 softmax。官方实现里的采样器因此是这样的（节选，略有简化）：

# tools/editing_utils.py · spatial_gamma_sampling（节选）
batch, length, vocabulary = logits.shape      # vocabulary == 2；length == token 数 × 每 token 的 bit 数
edit_probs   = logits.softmax(dim=-1).view(-1, vocabulary)
source_probs = source_probs.reshape(batch, -1, 2)
gamma = spatial_gamma.repeat_interleave(bits_per_token)   # 同一 token 的所有 bit 共用一个 γ

source_bit_probs = torch.gather(source_probs, 1, source_indices)
bias  = (gamma - source_bit_probs).clamp(min=0)
edit_probs = torch.scatter(edit_probs, 1, source_indices,
                           torch.gather(edit_probs, 1, source_indices) + bias)
selected_probs, selected_indices = torch.topk(edit_probs, k=1, dim=-1)

γ 是逐 token 的，但比较是逐 bit 做的。所以落地的 token 可能全部来自源、全部来自编辑预测，也可能是两者 bit 的混合—— 在 BSQ 这种"码本就是整个二值超立方体"的量化器里，混合出来的仍然是合法码字。混合发生得多频繁、解码出来是什么样，论文和代码都没有测 推断。 论文正文从头到尾按"保留 / 替换一个 token"叙述，没有提到这一层。

化简：它等价于一道置信度门槛 推断

因为每个 bit 只有 0、1 两个候选、概率加起来等于 1，式 (3) 可以直接解出来。设源 bit 为 b̂：

保留 ⟺ pedit(b̂) + γ − p̂src(b̂) ≥ 1 − pedit(b̂)
⟺ pedit(b̂) ≥ τ，其中 τ = ( 1 − γ + p̂src(b̂) ) / 2 τ 就是"编辑模型必须把源 bit 压到多低，才能把它翻掉"。γ = 2 时 τ ≤ 0，永远保留；γ = 0 时偏置被 max(·,0) 截成 0，退化成纯 argmax（τ = 0.5）。这是纯代数推导，不依赖实验。

代入论文的默认值：

  • 前景（γ = 1.60）：τ = (p̂src − 0.6)/2，最大 0.20。编辑模型至少要有 80% 的把握（押在另一个 bit 上），才能改掉一个源 bit——这还是 p̂src = 1 时最宽松的情形。
  • 背景（γ = 1.78）：τ = (p̂src − 0.78)/2，最大 0.11，至少 89% 的把握。
  • 两者的区别不只是 80% vs 89%。当 0.60 < p̂src ≤ 0.78 时，前景 bit 还有机会被翻，背景 bit 则永远翻不动。 所以在"源模型中等把握"的那一段，γ 场确实是"开 vs 关"；在高把握段，它只是门槛的高低。
  • 实际配置里 γ 都 ≥ 1.4，比任何概率都大，所以式 (2) 里的 max(·, 0) 只在 γ < 1（比如论文提到的 γ = 0"不加偏置"）时才真正起作用。

03The gamma field

γ 场：两个 sigmoid 叠出来的"哪里能改"

γ 不是一个数，而是一张随尺度和位置变化的表。造它只用了两个 sigmoid，没有可学参数，也不需要分割模型。 第一个 sigmoid 管"这个尺度整体多宽松"，第二个管"这个尺度里哪些位置更宽松"。

第一级：尺度包络——越往细处越宽松 论文

每个塔（图像塔 / 视频塔）内部，先按尺度在塔里的相对位置 t = slocal/(Ntower−1)（0 = 最粗，1 = 最细）算出这个尺度的 γ 取值区间：

γ(s){low,high} = γstart + ( γ{fg,bg}end − γstart ) · σ( (t − tc) / wt )　　…… 式 (5) 起点 γ_start = 2.0：最粗的几个尺度整体锁死，全盘照抄源的布局与运动。终点分两条：γ_low → 1.60（给前景用，可改），γ_high → 1.78（给背景用，要保）。 t_c 是过渡中心（塔内下标 5 / 4，即图像塔第 6 个、视频塔第 5 个尺度）；w_t = 0.06 决定过渡多陡——从 10% 到 90% 大约跨 3.7 个尺度。

两个塔各自重新计时。视频塔一开始 t 又回到 0，γ 又被拉回 2.0，然后再降一次。这是刻意的：视频塔最粗的几个尺度定的是整段视频的运动骨架，必须照抄源。 推论是：运动基本继承自源视频 推断——这与论文局限里"不适合需要大幅结构改变的编辑"一致 论文。

第二级：逐位置的注意力映射——越像要改的物体越宽松 论文

γ(s)i = γ(s)high + ( γ(s)low − γ(s)high ) · σ( (ai − ca) / wa )　　…… 式 (6) a_i 是位置 i 对锚点词（比如 "zebra"）的交叉注意力，每个尺度归一化到 [0,1]（代码里用的是 min–max）。注意力高（像斑马）→ γ 靠近 γ_low（可改）；注意力低（背景）→ γ 靠近 γ_high（要保）。 c_a = 0.50、w_a = 0.10：注意力从 0.28 到 0.72 之间完成 10%→90% 的过渡——这是一张相当软的掩码，而不是硬分割。
γ 场生成器左：尺度包络（真实的 30 个尺度）　右：注意力 → γ 的映射可交互

07Residual pruning

残差剪枝：用"上一个尺度改了多少"猜"这一个尺度还要改多少"

这一块是纯效率工程，逻辑很朴素：Transformer 在某个位置上把输入改得越多，说明那里越"活跃"；几乎没改的位置，下一个尺度干脆别算了。

机制 论文

  • 只作用于最后两个生成尺度（s = 28、29）。它们合起来占全部 token 的 65.9%、占 token-步的 42.5% 代码。
  • 活跃度信号 = 上一个尺度每个位置的残差大小 ‖fθ(x) − x‖（代码里是整个 36 层堆栈输入与输出之差的范数），三线性插值到当前尺度的网格上。
  • 按残差从大到小取前 K%（默认 K = 50%）送进 Transformer；其余位置跳过当前尺度的全部计算（Q/K/V、注意力、FFN），输入状态直接送到输出头——它们照样会得到预测（按代码还会照样过决策门；按论文算法这两个尺度已在早停之后，用的是纯 argmax），只是没被这一尺度细化。
  • 保留哪些位置，在 36 个 block 里固定不变；被保留的 token 仍能读到更早尺度的 KV 缓存。

我的存疑清单

先说结论：核心想法成立，同骨干的消融也做得扎实——注意力引导、尺度包络、尺度解耦各自的作用都被干净地隔离出来了。 下面这些问题不改变我对方法本身的正面判断，但会改变你怎么引用它的数字、以及照着论文写代码时会踩到什么。按严重度排序，点开看依据。 所有"代码里是什么"都基于 2026-09-07 的官方仓库快照；作者跑实验用的版本可能和它不同。

筛选：
D1高尺度解耦：论文写"γ = 0 自由生成"，代码里是"γ ≈ 1.60/1.78 + 源概率常数 0.95"▸
论文写了什么
§3.2："beyond this point, no source probabilities or attention are cached, and Phase 2 generates freely (γ = 0)."
算法 2 第 17 行：x_i^(s) ← argmax_j p_edit^(s)(j) ∀i
代码里是什么

第一遍在 si >= early_stop_si 确实跳过 Transformer，但同时把源概率缓存填成常数：源 bit 记 0.95（early_stop_default_prob），另一个 bit 记 0.05。 第二遍的 build_spatial_gamma_maps 为全部 30 个尺度都生成 γ 图，采样器一路照用——所以后段的 γ 是 1.60 / 1.78，不是 0。 代入门槛公式，源 bit 的翻转门槛是 0.175（前景）/ 0.085（背景）。官方 README 的说法反而准确："dynamic source likelihoods are replaced by a fixed preservation bias"。

另有一处小出入：论文的下标从 1 开始（"source caching is disabled for s ≥ 25"），折算下来后段是 6 个尺度；代码从 0 开始，后段是 5 个。

我的判断

方法仍然有效，但机制的解释需要改写。按代码，"有 / 无尺度解耦"唯一的区别就是后段源概率用真实值还是常数；如果表 2 用的是发布的代码，它的增益就只能来自这次替换 推断。 它的作用更像是"把约束拉平"：对源模型没把握的 bit 放松（原本永远保留的那批变得可改），对很有把握的 bit 反而略收紧（第 06 节）。这是和数据不矛盾的假说，不是结论。 风险在于：照论文算法 2 复现，会得到一个约束明显更弱的系统（预计背景更易漂移，未实测）。

D4中表 7 的"最佳基线"和表 1 对不上：比较对象不明▸
推理

论文说指标先对每个视频的帧取平均、再对全部用例取宏平均（式 7），四类各 40 条。于是任何一个方法在表 1 的数，都等于它在表 7 四类的平均——Edit-VAR 四行的平均确实和表 1 完全一致。

D5中Sstop：默认值是个尖峰，而且两张表之间不单调▸

(2) Sstop = 29（按代码下标，只解耦最后一个尺度）的 PSNR 18.93、LPIPS 0.231、Smooth. 0.921，都比表 2 里完全不解耦（21.43 / 0.189 / 0.980）还差。 按理它该介于"默认的解耦最后五个"和"完全不解耦"之间；按论文 1 起的下标字面理解（解耦最后两个）也一样。

我的判断

要么 Sstop 附近的行为本身就很不规则，要么两张表不是在同一条件下跑的。无论哪种，Sstop 都是这套方法里最脆的一个旋钮：换视频长度、换分辨率（尺度表会变），大概率要重新调。

D6中剪枝只和随机对照，而且零残差会延续到最后一个尺度▸
论文写了什么

表 6 给出残差引导 vs 随机选择在同样 token 预算下的对比（K = 50%：编辑区 CLIP-S 0.976 vs 0.954，LPIPS 0.176 vs 0.235），据此认为残差是个好信号。

我的判断（三条）

① 对照太弱。随机是最低的基线。更有信息量的是：用当前尺度的真实残差做上界，或者和更便宜的信号比（注意力熵、高频能量、γ 图本身——代码里其实还留着一个未文档化的 token_prune_mode='gamma' 分支）。缺了这些，只能说"比随机好"。

② 零残差延续。s = 29 的选择依据是 s = 28 的残差，而 s = 28 被跳过的那一半位置残差恒为 0（代码里输出直接等于输入）。 受影响的比例在 25%（两次选择独立）到 50%（完全延续）之间。这不一定有害，但这一半位置的选择依据不是"测出来的"，它们没机会被重新发现。改法很便宜：继承上一次的残差，或两个尺度交错选择。

③ 被跳过的位置也退出了同尺度注意力。论文写明被剪的 token 跳过当前尺度的 Q/K/V，所以被保留的 token 在最高分辨率上只看得到一半的同尺度上下文。 随机剪枝有同样的上下文损失，所以"残差 vs 随机"比的是选哪些；但"少细化"和"少上下文"各自损失多少，没有被拆开。

D9中没有误差棒；"每个用例跑两次取平均"对确定性流水线几乎等于没做▸

问题

11Where it sits

谱系与定位：它不是交互式世界模型，但有两样东西可以带走

按本列表的严格标准，Edit-VAR 三条都不满足：没有逐步的动作条件、不是闭环生成、也没有跨步的持久状态。它是一个离线的、整段视频的文本编辑方法。

它值得留在单子里的理由：

  • 它是 InfinityStar 这条"离散自回归视频生成"路线在下游任务上的一次实测。81 帧、720p（按发布代码），单卡一遍前向约 65 秒——这个量级正是交互式生成关心的。 表 4 也给了一个有用的参照：多尺度离散 token 直接解码的重建（29.93 dB），明显高于"VAE + 反演"（25.62 dB）；不过这个差距里 tokenizer 本身和反演误差是混在一起的。
  • "逐位置决定保留还是重生成"本质上是一种显式的记忆机制。把源视频换成"上一段已经生成的世界"，把 γ 场换成"这一步哪些区域应该变"，它的形状和长时序一致性要解决的问题是同构的——这大概也是它被打上 memory 标签的原因 推断。
  • 残差引导剪枝可以直接搬。它不依赖"编辑"这个任务，对任何 next-scale prediction 的实时生成都适用，收益集中在最后两个尺度（那里有 66% 的 token）。 尺度解耦则不行：它省的是"第一遍照着念"的时间，普通生成没有这一遍。

反过来，它的局限也提示了这条路线的边界：逐位置替换保不住"改变运动"这类需求。作者自己写在局限里——物体删除、布局改动做不了，因为腾出来的区域需要被合理补全，而不是逐 token 替换。 对交互式世界模型来说，"动作会改变物体的运动与位置"恰恰是核心；所以这套保留机制能提供的是"背景稳定"，不是"世界演化"。

名词对照

next-scale prediction

VAR 的生成方式：不是逐个预测下一个 token，而是逐"尺度"预测下一整张更高分辨率的 token 图；同一尺度内的 token 并行给出。每一级都是在上一级基础上补的细节（残差）。

BSQ / 按位建模

Binary Spherical Quantization：码本就是整个二值超立方体，所以一个 token 就是一串独立的二值位（这里语义尺度 16 位、细节尺度 64 位），预测头对每一位各做一次二分类。

语义尺度重复

InfinityStar 论文的设计：决定布局和前景位置的前 12 个"语义尺度"各预测 3 次，每一轮都在细化同一个尺度的残差，用来提升结构稳定性和运动质量。发布配置里图像塔 15 个尺度都预测 3 次，视频塔最后 3 个尺度依次 2、1、1 次。

强制解码（teacher forcing）

第一遍用的技巧：把已知的源 token 直接喂进去，只让模型报出"它本来会给这个答案多少概率"。所以第一遍不产生新内容。

反演（inversion）

扩散式编辑常见的前置步骤：把真实视频沿采样轨迹反推回噪声。VAR 不需要它，因为 tokenizer 编码本身就给出了确定的源表示。

APG

Adaptive Projected Guidance：对条件 / 无条件预测之差做投影和归一化的引导方式，比普通 CFG 更能承受大系数。这里 cfg = 34，是 InfinityStar 官方默认。

图像塔 / 视频塔

InfinityStar 的时空金字塔：（720p 配置下）先用 15 个尺度把首帧从 1×1 画到 45×80，再用 15 个尺度把其余 20 个 latent 帧由粗到细画出来。

token-步

本页用来衡量工作量的单位：token 数 × 该尺度被预测的次数（重复次数）。它是份额的粗略度量，不等于真实计算量（注意力是超线性的）。

一句话总结

Edit-VAR 把"视频编辑"翻译成了一句关于离散 token 的话：每个位置上，源 token 要不要让位，取决于它从源提示换到编辑提示后掉了多少支持度； "允许掉多少"由交叉注意力和尺度位置共同决定。这个翻译干净、便宜、可实现。 论文的问题不在想法，而在叙述与实现之间有几处错位（尤其是尺度解耦和锚点自动化），以及主表和分类表的几处归因与一致性问题。
