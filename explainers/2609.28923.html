ViRDM

把 Self Forcing / Causal Forcing 里「在线 14B 教师 + 在线 critic」这套 DMD 栈拿掉，改成在冻结的视频编码器特征空间里，让生成视频的分布去贴一份离线算好的参考分布。只训生成器，20 次更新收工。

一句话结论。省资源这件事成立，而且有代码能复现：8 张 A100、2 小时、每卡峰值 48.3 GB，对照 DMD 的 22 小时、77.1 GB。让它跑得动的三招（随机出口、分段 VJP、轻量解码器）设计得干净，值得借鉴。

「VBench 比 Causal Forcing 高 0.36」这句要打折。最后一步 +1.46 分几乎全部来自动态正则，而发布代码里的动态正则，就是 VBench Dynamic Degree 判据的可微复刻：同一个 RAFT 权重、同样按 8 fps 取帧、同一个 11.25 px 阈值、同样看「第 10 高的帧对」。论文还缺一个最基本的基线：初始化模型本身（0 次更新）是多少分。

Glossary

先认几个词

少步因果视频生成
视频按段生成：每段 3 个 latent 帧，7 段拼成 21 个 latent 帧（解码后 81 帧、832×480、16 fps）。每段只去噪 4 步，靠 KV cache 接上前文，所以能边生成边播放。
DMD
Distribution Matching Distillation。把生成器的输出加噪，分别送进冻结的教师（估计真实分布的分数）和在线训练的critic（估计生成器自己分布的分数），两者之差就是梯度方向。Self Forcing、Causal Forcing 都用它：生成器 1.3B、教师 14B、critic 1.3B，三个视频扩散网络同时在显存里。
RDM
Representation Distribution Matching。不算分数，直接把生成样本和参考样本都送进一个冻结的表征编码器，比较两堆特征的分布差。图像上的前作是 RDM / iRDM（ref [17]）与 FD loss（ref [68]），都只做了一步图像生成。
MMD
最大均值差异。两堆点之间的「核平均」距离，由三项组成：生成–生成（把生成点互相推开）、生成–参考（把生成点拉向参考）、参考–参考（常数）。
V-JEPA 2.1 / SigLIP2
冻结的视频编码器（ViT-L/16，所有 token 做全局平均得到 1024 维）和文本编码器（1152 维，L2 归一化）。两者拼接成 2176 维的联合特征。
随机出口 S
stochastic exit，沿用 Self Forcing。训练时每次随机选第 S 步（1–4）的干净预测 x̂0 当作这一段的输出，只对这一步回传梯度，前面几步不留计算图。
VJP
vector–Jacobian product。给定输出端的梯度，算出输入端的梯度，不需要显式构造雅可比矩阵。反向传播本质上就是一串 VJP。
TAEW2.1
给 Wan2.1 latent 用的小型解码器（madebyollin/taehv）。只在训练的梯度路径里替代完整的 Wan VAE 解码器。
Dynamic Degree（DD）
VBench 的「动态程度」维度：用 RAFT 光流判断每条视频「动了没有」，报告判为动态的视频占比（0–100）。它在 VBench Quality 里的权重是其他维度的一半。
AOverview

一图看懂：三个网络换成一张「特征分布靶子」

DMD 每一步都要问教师和 critic「这个样本该往哪挪」。ViRDM 换了个问法：把整条生成视频变成一个特征点，然后看 64 个生成点组成的点云，和 6,505 个参考点组成的点云，差多少。参考点云离线算一次就冻结，训练期间只剩生成器一个大网络。

三道坎，三个对策

作者把「图像 RDM 为什么不能直接搬到视频」拆成三个问题，逐个解决，每一步保留验证过的选择，最后叠成完整配方。

坎一 · 显存
梯度链太长
损失在「4 步自回归 rollout → Wan VAE 解码 → V-JEPA」之后，整条链一起反传直接 OOM。
对策：随机出口 + 分段 VJP + 轻量解码器。→ 细节
坎二 · 配方
图像的超参不迁移
图像 RDM 要 2048 张以上的新样本；视频做不到。直接从双向模型起步也会漂移。
对策：B = 64，从因果 ODE 初始化起步。→ 细节
坎三 · 动态
表征对运动不敏感
匹配完分布，画面更好看但动得少（DD 48.6）。
对策：加一个 RAFT 光流的单边 hinge 正则。→ 细节
BObjective

核心目标：在特征空间里「拉近 + 推开」

一条视频先变成一个 2176 维的点：前 1024 维来自 V-JEPA（这条视频长什么样、怎么动），后 1152 维来自 prompt 的文本特征。训练就是让 64 个生成点组成的点云，和 6,505 个参考点组成的点云，在高斯核意义下尽量重合。

ĥ = h(v̂, c) = [ ϕv(v̂) ; β · τ(c) ],   τ(c) = ϕt(c) / ‖ϕt(c)‖2 视频特征不做归一化；文本特征单位化后乘一个缩放 β，让两部分在核里分量相当。论文 式 1
k(h, h′) = exp(−‖ϕv − ϕ′v‖² / 2σ²) · exp(−‖τ − τ′‖² / 2σt²),   β = σ / σt 联合核可以拆成「视频相似度 × 文本相似度」。只有画面像、prompt 也像，两个样本才算近。σ 与 σt 用参考集上的中位数距离定（median heuristic）。论文 式 2
LRDM = (1/B²) Σi,i′ k(ĥi, ĥi′) − (2/BN) Σi,j k(ĥi, h*j) + (1/N²) Σj,j′ k(h*j, h*j′) 第一项：生成点彼此越近越大，最小化它就把生成点互相推开，防止塌缩到同一个样子。第二项：生成点离参考点越近越大，前面带负号，所以把生成点拉向参考。第三项与 θ 无关。B = 64 条生成视频，N = 6,505 条参考。论文 式 3

视频带宽 σ = 26.09（V-JEPA 特征未归一化，所以数值大）；文本中位距离 1.097；β = 26.09 / 1.097 = 23.77。参考侧 6,505 行，吸引项用 4,096 个 Nyström 地标近似（论文式 3 写的是精确求和）。每条生成视频用的 prompt 就是参考表里同一行的 caption，文本特征直接查表取出。

这一节留下三个伏笔，后面会展开：

  • 只有一个视频编码器。图像前作 iRDM 的核心发现之一，是任何单一编码器都能被「刷」到比真实数据还近而图像仍然假，所以它用 10 个编码器互相牵制，另留 4 个做评测。ViRDM 只用 V-JEPA 2.1。→ D9
  • 一条视频只剩一个全局平均向量。41×30×52 ≈ 6.4 万个 token 平均成 1 个点代码，时序细节只能靠 V-JEPA 自己的上下文编码保住。这是坎三的根源。
  • 参考集是什么决定了靶子在哪。6,505 条来自 Causal Forcing 的数据集。CF 论文说这批数据由 Wan 双向基座用 VidProM 提示词合成，而 ViRDM 项目页写的是「real video-text pairs」。→ D5
CBarrier 1 · Memory

坎一：显存。随机出口 + 分段 VJP + 轻量解码器

直接端到端反传需要同时保留三张计算图：4 步 × 7 段的自回归 rollout、Wan VAE 解码 81 帧 480p、V-JEPA 处理约 6.4 万个 token。编码器和解码器冻结只省掉参数梯度，激活值照样要存。作者分两刀解决：先把「生成器那张图」缩到只剩一步，再让三张图轮流上场。

第一刀：一致性式采样 + 随机出口

少步采样器每一步都先预测一个干净的 x̂0，如果还要继续，就把 x̂0 用新噪声重新加噪到下一个时间步再预测一次。所以每一步的 x̂0 都是一条可以解码、可以打分的完整视频。RDM 只看终点分布，不关心中间轨迹，于是可以沿用 Self Forcing 的随机出口：每个微批随机抽一个 S，7 段都在第 S 步停下，把那一步的 x̂0 当作这段的输出，只有这一步带梯度。

第二刀：分段 VJP，三张计算图轮流驻留

MMD 把 64 条视频耦合在一起（每一条的梯度都依赖其他 63 条），所以不能「生成一条、反传一条」。作者的做法是先全部无梯度生成、算出每条视频在特征端的梯度，再从后往前一段一段地把梯度「翻译」回去：Φ 把 ∂L/∂ĥ 变成 ∂L/∂v̂，D 把它变成 ∂L/∂ẑ0，最后生成器按记录下来的随机数重放 rollout，把 ∂L/∂ẑ0 反传进 θ。每一段用完就释放。

第三刀：换一个轻量解码器

即使分段，只对 Wan VAE 解码器做 VJP 也会超 80 GB。作者的理由是：解码器在这里不是被优化的对象，只是把 latent 递给编码器的「可微的桥」，不需要完整容量，于是训练路径里换成 TAEW2.1。推理和评测仍用 Wan VAE。

EBarrier 2 · Recipe

坎二：每次要多少条新视频？从哪个模型起步？

图像 RDM 发现生成侧的新样本要 2048 个以上才好，B = 512 就明显变差。视频上 B = 1024 意味着每张卡累积 128 次、每次更新 96 分钟。作者固定 20 次更新，只改 B。

读法：B = 8 已经有效，B = 64 之后收益很小；B = 1024 其实最高（83.57），只是贵 16 倍。所以更准确的结论是「大种群在视频上不值这个价」，而不是「图像的大种群处方不成立」。论文最终用 B = 64。

这张表缺的那一行

所有行都是「初始化 + 20 次 RDM」之后的分数，没有任何一行报告初始化本身（0 次更新）的 VBench。因果 ODE checkpoint 已由 Causal Forcing 公开，补这一行只需推理和评测。

这一行很关键，因为 20 次更新走得很近：Adam 每步每个参数的位移量级约等于学习率，20 × 2×10⁻⁶ ≈ 4×10⁻⁵推算。没有 0 次更新的基线，就说不清 83.41 里有多少是 RDM 带来的。→ D3

TBarrier 3 · Dynamics

坎三：表征对「动」不够敏感？

到这里，配方已经在不含 DD 的 VBench 上超过 Self Forcing（85.77 vs 85.34），但 DD 只有 48.61，Self Forcing 是 67.78、Causal Forcing 是 83.33。作者用一个「冻结动态」的干预来诊断原因。

干预是这样做的论文 §3.5.1：每条 81 帧视频保留 0/25/50/75/100% 的均匀间隔帧，再重复补回 81 帧。每个保留比例取 20 组、每组 64 条视频，算它们对参考分布的 RDM。图像版把 81 帧各自送进 DINOv2（每组 64×81 = 5,184 个特征），视频版每条视频一个 V-JEPA 全局特征。

这个干预测的其实是「卡顿」，不是「动了多少」

保留均匀帧再重复补齐，物体从第 0 帧走到第 80 帧的总位移没有变，变的是它走得一顿一顿的。下面把一个匀速运动的物体按论文的做法处理，同时给一个「真的少动」的对照：把运动慢放到同样比例。右侧用 VBench Dynamic Degree 的规则（8 fps 取帧、看第 10 高的帧对是否超过 11.25 px）判一下它们「动不动」。

所以结论要改写

Table 5 说明了两件事：图像边际对帧的顺序和间隔完全无感（这点成立，也是预期内的）；V-JEPA 对时间上的不自然很敏感。它没有检验「V-JEPA 能否区分中等运动和大幅运动」，因为干预根本没有改变运动幅度。

还有一个更直接的问题没回答：参考集自身的 DD 是多少？如果 6,505 条参考视频本来就只有中等运动，RDM 停在 48.6 附近恰恰是在如实匹配靶子，动态正则则是把分布往靶子之外推。→ D4

GDynamics Regularizer

动态正则：一个可微版的 VBench Dynamic Degree

论文对它的描述很简短论文 §3.5.2：受 VBench 用光流幅值衡量动态的启发，用冻结 RAFT 在采样的帧对上估计光流，汇总高幅值响应得到视频级分数 s(v̂)，再加单边损失 Ldyn = [τ − s(v̂)]+。s 怎么汇总、τ 取多少，正文都没给。发布代码把它们写得很清楚代码。

  1. 用 TAEW2.1 解码 81 帧，每 2 帧取 1 帧（16 fps → 8 fps），得到 41 帧、40 个相邻帧对。
  2. 每个帧对跑 RAFT（raft-things 权重，20 次迭代）得到光流。
  3. 每对取光流幅值最大的 5% 像素求平均，得到这一对的「运动分」，单位是像素。
  4. 40 个运动分从大到小排，取第 10 名，记为 s10。
  5. 若 s10 < 11.25 px，损失为 11.25 − s10，只对第 10 名那一对求梯度，经 TAEW2.1 的 VJP 回到 latent；否则这条视频不产生梯度。
  6. latent 上的总梯度 = RDM 梯度 + (5×10⁻⁴ / 8) × 动态梯度，再走 Stage 4 进生成器。

「超过阈值的帧对至少 10 个」和「第 10 高的帧对超过阈值」是同一个条件。所以这个正则的 hinge 正好卡在 VBench 判「动 / 不动」的那条线上：一条视频只要被 VBench 判为不动，就会收到梯度；一旦被判为动，梯度立刻归零。VBench 的 DD 本身就是「被判为动的视频占比」。

HArithmetic check

数字复核：把 VBench 的账摊开

VBench 的总分是加权平均，权重是公开的。把它写出来，就能把「+0.36」拆成几块，看清每块从哪来。

Total = 0.8 · Quality + 0.2 · Semantic 官方权重：Quality 4 份、Semantic 1 份。
Quality = ( 主体一致 + 背景一致 + 时间闪烁 + 运动平滑 + 美学 + 成像 + 0.5 × DD ) / 6.5 各维先按官方 min/max 归一化；DD 的归一化区间是 [0, 1]，等于原值。所以每 1 点 DD = 0.5/6.5 = 0.0769 点 Quality = 0.0615 点 Total。反过来，去掉 DD 后的 Quality = (6.5·Q − 0.5·DD) / 6。

存疑清单

按对结论的影响排序。「高」表示会改变对论文主张的判断；「中」影响解读或复现；「低」是表述与小问题。

高D1动态正则就是可微版 VBench Dynamic Degree，而最终的 +1.46 几乎全来自它▶
现象

论文说正则「受 VBench 用光流衡量动态的启发」，没给 s(v̂) 的定义和 τ。发布代码里，光流网络、迭代次数、取帧率、每对的打分方式、阈值 11.25 px、「第 10 高的帧对」这 6 项与 VBench DD 的实现完全一致（见动态正则一节的对照表）。这不是受启发，是把评测判据直接变成训练损失。

为什么要紧

按 VBench 权重，每点 DD = 0.0615 点 Total。无正则 → 有正则的 +1.46 中 +1.44 可由 DD 单独解释；没有这个正则，ViRDM 的 Total 是 83.41，低于 Causal Forcing 复测的 84.51。论文 §4.3 用 4 个时序维度做「目标外诊断」、再加人评，这点值得肯定，但那 4 个维度本来就偏爱少动，分不清「真运动」和「为过线而加的运动」。另外，hinge 对所有训练 prompt 一视同仁，要求每条视频至少 10 个帧对过线，不管 prompt 是不是在描述静止场景。

建议

换一个与评测无关的运动度量（不同光流网络、不同阈值与取帧，或 Causal Forcing 那套 100 条动作 prompt 上的 DD）重训一遍；报告主表时同时给出去掉 DD 的分数。

高D2「比 Causal Forcing 高 0.36」：构成偏向静止维度，且在种子与协议方差量级内▶

+0.36 = 非 DD 质量维 +1.06 − DD 0.70 + Semantic 0（图 H）。非 DD 质量维中 4 个（主体一致、背景一致、闪烁、运动平滑）静止画面天然高分，同一篇论文里 DD = 18 的 DINOv2 版在这些维度上最高（图 S）。论文没有 16 维分项，无法判断 +1.06 有多少来自美学和成像质量。

只跑了一个训练 seed，没有置信区间。同一个 Causal Forcing checkpoint 在 CF 原文是 84.04，本文复测 84.51，同一模型跨论文最大相差 0.47–1.00（见跨论文对照表）。同环境复测比抄数更可比，但 seed 方差没有报告。

高D3缺「0 次更新」基线，也没有训练曲线▶

所有表都是 RDM 之后的分数，因果 ODE 初始化本身在同一协议下的 VBench 没有报告，而这个 checkpoint 是公开的。20 次 Adam 更新、学习率 2×10⁻⁶，每个参数的位移量级约 4×10⁻⁵推算，模型离初始化很近，「RDM 贡献了多少」目前读不出来。

结论写「ViRDM converges in 20 generator updates」，但发布代码只保存第 20 步，论文也没有损失或分数随更新次数的曲线。继续训下去会不会开始钻 V-JEPA 的空子，同样不知道（见 D9）。

高D4Table 5 的「冻结动态」干预测的是卡顿，不能支撑「分不清中等与高动态」▶

保留 p% 均匀帧再重复补齐，总位移不变，只是走得一顿一顿（图 F）。在 VBench 的 8 fps 取帧下，p = 50% 与原视频完全一样，p = 25% 的单对位移反而翻倍。所以这组干预并没有造出「中等动态」与「高动态」的对照，也就无法检验 V-JEPA 能否区分二者。合适的干预应该改变运动幅度，例如慢放、或按实测光流分档的真实视频。

更直接的缺口：参考集自身的 DD 没有报告。若参考视频本身只有中等运动，RDM 停在 48.6 是在如实匹配靶子，而动态正则是把分布推离靶子。这会让「表征对动态不敏感」的叙事换一种解释。

中D5「teacher- and critic-free」的边界：教师从在线挪到了离线▶

在线教师和 critic 确实去掉了，连 14B 模型都不需要加载，这是本文最实在的贡献。但靶子和起点都来自教师：参考集取自 Causal Forcing 的数据集，CF 论文附录 D 说这批数据由 Wan 双向模型用 VidProM 提示词合成（论文写约 3K，HF 上公开的是 6K 版本）；初始化是 CF 的 teacher forcing（2K 步）+ 因果 ODE 蒸馏（1K 步）。Table 7 只比最后一段，对和 CF 比较是公平的，但「不需要教师」更准确的说法是「不需要在线教师」。

中D6论文公式与发布代码不一致（Nyström 近似、损失自归一化）▶

① 吸引项在代码里用 4,096 个 Nyström 地标近似 6,505 条参考，而式 3 写的是精确求和。② 代码把 RDM 除以它自己的 detach 值，梯度等于 ∇ log MMD²；式 7 的 λ = 5×10⁻⁴ 实际上是相对这个归一化后的量。照论文公式复现，动态项的相对权重会偏差 30–160 倍（取决于当时 MMD 的大小，Table 5 量级 0.006–0.03）。③ 梯度裁剪 10 也没写。这几处不影响结论本身，但会直接影响复现。

顺带一提：Adam 对单一损失的整体缩放基本不敏感，所以自归一化主要改变的是 RDM 与动态项之间的相对权重。这也意味着论文用「损失差值变小」来论证「优化信号变弱」（§3.5.1）说服力有限，在 Adam 下真正起作用的是梯度方向，而不是幅值。

中D7训练时生成侧与参考侧用了不同的解码器▶

参考特征：Wan VAE 解码 → V-JEPA。生成特征：TAEW2.1 解码 → V-JEPA。推理和评测再换回 Wan VAE。于是 MMD 里含一个恒定的「解码器域差」，生成器可能被推去补偿 TAEW 的模糊或色偏，这种补偿在 Wan VAE 解码下未必有益。论文把解码器定位为「可微的桥」，但没有量化这座桥本身带来的偏差。最简单的检查：把同一批参考 latent 分别用两种解码器解码，算两组特征之间的 MMD。

中D8「训练快 11 倍」主要来自更新次数，而 DMD 需要多少次没有扫▶

每次更新 DMD 约 11 分钟、ViRDM 约 6 分钟，只差 1.8 倍；另外 6 倍来自 120 对 20 次更新。同一因果 ODE 初始化下 DMD 的「更新次数–质量」曲线论文没有给。若 DMD 20–40 次更新就接近收敛，时间节省会缩到 2–4 倍（图 I）。显存节省（77.1 → 48.3 GB）是结构性的，不受影响。

中D9只用一个视频编码器，也没有留出编码器上的评测▶

图像前作 iRDM（ref [17]）明确指出：任何单一表征都能被优化到「比真实数据还近」而样本仍然假，所以它用 10 个编码器加 Lagrangian 权重平衡，另留 4 个编码器专门评测。ViRDM 借用了它的 Nyström 估计，却只用 V-JEPA 2.1 一个视频编码器，评测只看 VBench，没有任何与训练编码器无关的分布距离（例如 I3D 的 FVD 或其他视频编码器上的 MMD）。20 次小步更新可能恰好停在「还没来得及刷」的区间，论文没有讨论这一点。

中D10两个扩展实验的设置交代不清▶

Table 10：基线（Causal Forcing++、ASD、One-Forcing）的分数是复测还是引用没有说明，而且把逐帧模型和逐段模型放在一起比。Table 11：论文写「bidirectional Wan2.1-1.3B generators」，发布代码的 bid4 配方却沿用因果 ODE checkpoint 作初始化；1/2 步双向的训练配方代码里没有，可能是 4 步模型直接少步采样，也可能是未发布的配方。

中D11种群大小的结论比数据更强▶

Table 2 各行 Total 相差不超过 0.38，单 seed。B = 1024 实际最高（83.57）。数据支持的是「大种群在视频上不划算」，而不是「图像的大批量处方不迁移」。另外 B 变了而学习率与更新次数不变，大 B 的估计更准却没有多拿到更新，这个设计本身就偏向小 B。

低D12人评规模小，prompt 选择方式未说明▶

25 人；四选一 20 个 prompt，正则消融 10 个 prompt。四选一里 Self Forcing 第二、Causal Forcing 第三，与 VBench 的排序相反，这本身提醒 VBench 上零点几分的差距不一定对应主观偏好。

低D13项目页称参考集为「real video-text pairs」▶

与 Causal Forcing 论文对这批数据的描述（由 Wan 双向模型合成）不符；论文正文只说是 CF 构建的训练数据。HF 数据集需要登录，本页无法直接核对，以 CF 原文为准。

低D14Algorithm 2 的小笔误▶

Stage 1 只缓存 ẑ0、ĥ 和随机轨迹 T，但 Stage 3 第 14 行要在 v̂ 上重放 Φ。代码的做法是在 Stage 3 再用 TAEW 解码一次得到 v̂，算法框图里漏了这一步。

低D15Semantic +0.48 的解释缺分项证据▶

论文把加入正则后 Semantic 的 +0.48 归因于 Human Action 这类需要动作才能满足的语义维度，但没有给出 Semantic 下各维的分数，这个解释目前只是合理推测。

综合判断。成立的部分：RDM 在少步因果视频上可以训得动、训得快，只需要一个生成器在显存里；随机出口 + 分段 VJP 的重放设计干净、有断言校验，代码开放、可复现；因果兼容的初始化是必要前提，这个发现与 DMD 系工作互相印证。

要打折的部分：「质量超过 DMD 基线」的最后一段增益，来自一个与评测判据同构的正则；和 CF 的差距落在种子与协议方差量级；缺初始化基线和训练曲线。更稳妥的读法是：ViRDM 用约 1/10 的算力、不加载教师，得到了与 DMD 基线同一档次的 VBench。

WPlacement

定位：对交互式视频世界模型意味着什么

ViRDM 解决的是「少步因果生成器怎么便宜地后训练」，没有动作条件、没有长时记忆、只生成 81 帧。它对世界模型的价值主要在训练管线层面。

可以直接用的
后训练门槛大幅降低
不需要加载 14B 教师，单张 80 GB 卡可跑（68.5 GB），一次后训练约 16 A100·h。对需要频繁换数据域、换条件、重新蒸馏的世界模型团队，这把迭代成本从「一天」降到「一顿饭」。推理结构完全不变，可与 KV cache 压缩、稀疏注意力等推理加速叠加。
需要先有的
因果兼容的少步初始化
RDM 精修不了一个非因果的模型。你仍然需要 teacher forcing + 因果 ODE（或因果 CD）这一段，而它依赖教师轨迹。ViRDM 替换的是 DMD 那一段，不是整条管线。
要改造的
动作条件与时序对齐
现在的联合特征只拼了文本。换成动作条件，需要把动作序列编码进 h（类似 β·τ(c)）。但全局平均池化会抹掉「动作在第几帧生效」的对齐信息，交互式世界模型最在意的正是这个。按时间窗口分块匹配、或保留 V-JEPA 的时序 token，是自然的扩展方向。
要小心的
动态正则在世界模型里是错的方向
世界模型里「动多少」由动作决定：动作是「停」时画面就该静止。一个要求每条视频至少 10 个帧对超过 11.25 px 的正则，在这里会直接违背动作条件。如果要借用 ViRDM，建议去掉这一项，或者把它条件化到动作上。
可以试的组合
RDM 作为 DMD 之后的廉价精修
论文把 RDM 当作 DMD 的替代品来比，没试两者叠加。RDM 的目标直接定义在终点分布上、只要一个网络，放在 DMD 之后做领域适配（比如换到游戏或机器人视频的参考集）可能更划算。
