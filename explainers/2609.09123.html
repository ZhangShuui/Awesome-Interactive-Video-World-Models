Mask Forcing

在 self-rollout 里让约两成 latent token「偷偷提前一步」，用来对冲反向 KL 的模式塌缩

这篇论文只改了 self-rollout 训练循环里的一行：把「用 ε 把上一步的干净预测重新加噪到 tj」换成 「加噪到 tj 和一个更低的 t′k，再用一张随机 0/1 掩码把两者按 token 拼起来」。 模型仍然被告知「你现在在 tj」——于是约 20% 的 token 的真实噪声水平和条件时间步是对不上的。 作者给这件事安了两个理由：① 每次 rollout 的扰动都不一样，学生轨迹被摊开，DMD 就能在学生尚未覆盖的教师模式上给梯度； ② 更干净的 token 可以当作其余 token 的去噪上下文。 代价是零——不加前向、不加真实数据、不加后训练阶段。 收益是三条基线 × 两种设定 × 两个基准共 12 个格子全部为正，人评偏好 72–83%。 我读下来最大的保留：全部梯度都在推理时永远不会出现的输入上算出来，而论文的理论只分析了训练时的混合分布； 以及「减少误差累积」这个说法，用它自己 Tab. 8 的数据复算，斜率没有变。

00TL;DR

一图看懂：整篇论文只动了「重加噪」那一格

AR 视频蒸馏的 self-rollout 训练里，学生要在训练时自己把视频一步步生成出来。每个 chunk 走 4 个去噪步， 每一步的输入都是把上一步的干净预测重新加噪回去。Mask Forcing 就改了这一步： 加噪到两个噪声水平，再用一张随机 0/1 掩码按 token 拼起来。其余一切——损失函数、教师、KV cache、调度、推理流程——都没动。

00.1如果你只想看代码改了哪几行

把 Self Forcing 的 rollout 循环拿出来，Mask Forcing 是这样一个 diff。它不改损失、不改优化器、不改数据、不加前向。

# self-rollout 内层循环，j 从 T-1 递减到 exit step s
  for j in range(T-1, s-1, -1):
      eps = torch.randn_like(x0_hat)
-     x_in = (1 - t[j]) * x0_hat + t[j] * eps                 # 式(9)：原版只有这一行
+     lo   = max(t_min, t[j] - delta / 1000)                  # 式(6)  delta = 250
+     t_k  = uniform(lo, t[j])                                # 式(7)  每步重采
+     x_hi = (1 - t[j]) * x0_hat + t[j] * eps                 # 式(9)  同一个 eps
+     x_lo = (1 - t_k)  * x0_hat + t_k  * eps                 # 式(8)  同一个 eps
+     x_in = M * x_lo + (1 - M) * x_hi                        # 式(10) M ~ Bernoulli(0.2)
      x0_hat = G(x_in, cond=c, timestep=t[j], kv=kv_cache)    # 注意 timestep 仍然是 t[j]

M 在 chunk 开始时按 Bernoulli(α) 采一次，形状是 L×H×W（每 chunk 的 latent 帧数 × 潜空间高 × 宽）， 也就是说逐 token、逐帧独立，chunk 之间重采、chunk 内的 4 个去噪步之间不重采——这正是消融里胜出的 “per-frame + per-chunk” 方案。

变了什么
rollout 输入的局部噪声水平
约 α=20% 的 latent token 被推到一个更低的噪声水平 t′k，而模型的条件时间步仍是 tj。
没变什么
损失、教师、推理
DMD 目标原封不动（式 1–3），教师仍是 Wan2.1-T2V-14B，推理时没有掩码，走原调度。
代价
训练输入分布 ≠ 推理输入分布
Self Forcing 的立身之本是「训练时就按推理的方式 rollout」。Mask Forcing 主动在这上面开了一个新口子。
一句话版本

把 DMD 的 mode-seeking 问题，当成一个「训练时探索不足」的问题来治，而治法是给 rollout 加一个结构化的随机扰动。 掩码和双噪声只是这个扰动的具体形状；论文的理论部分（§04）证明的其实是「任何随机扰动的混合分布，反向 KL 都不会比它自己各分量的平均更差」—— 这句话对高斯噪声、dropout、时间步抖动同样成立。论文没有做这个对照实验。

01Problem

过饱和和过平滑到底从哪来

要理解这篇论文在治什么病，得先把 AR 视频蒸馏这条线的四代训练范式摆在一起看。 它们真正在争的只有一个问题：训练时，模型看到的"历史"和"当前输入"，跟推理时是不是同一个东西。

01.1反向 KL 为什么会「挑模式」

DMD 的梯度是两个分数函数之差（论文式 3）：

∇θLDMD = 𝔼[ −( sreal(xt,t) − sfake(xt,t) ) · dG/dθ ]式 (3) 这是 DKL(pfake ‖ preal) 的梯度，注意顺序：pfake 在前。 这一项在 pfake 有质量、而 preal 没有质量的地方会被罚成 +∞； 反过来 preal 有质量而 pfake 没有的地方，被积掉了，一分钱也不罚。

于是学生的最优策略非常朴素：找一块教师概率最高的地方蹲着，别乱跑。这就是 mode-seeking。 在图像上它表现为「每次生成都很像」，在视频上它额外表现为两件事：颜色被推到几个高对比度的「安全配色」上（过饱和）， 高频纹理被抹掉因为纹理是最容易踩空的地方（过平滑）。论文开篇的整段动机就是这两个词。

这条诊断本身不是本文提出的，DMD2、DFD、rCM、DistillAlign、Mode-Seeking-meets-Mean-Seeking 都在说同一件事。 区别在开的药：

路线代表工作做法代价
掺真实数据DMD2 / DFD加 GAN 损失或把真实数据放进蒸馏分数里要数据策展；DFD 还要在 DMD2 预训练模型上再做后训练
RL 后训练Astrolabe在蒸馏好的 AR 模型上做 RL受限于奖励模型；超参敏感
混合散度rCM / DistillAlign / MS-meets-MS把 mode-covering 的一致性损失和 mode-seeking 的 DMD 加权相加多一个损失和一套权重；论文说结果仍偏饱和
扰动 rolloutMask Forcing不动损失，只把学生自己走的轨迹摊开零额外开销；但训练/推理输入分布被拉开

01.2第二条动机：中间预测没人管

还有一条论文提得比较轻、但其实是它「干净 token 当上下文」那半个故事的立足点： DMD 损失只在 rollout 结束后算一次（对完整的 Xθ），中间那些 x̂⁰i,j 没有任何显式监督。 但它们会被两次复用——作为下一去噪步的输入，以及（在 exit step 上）作为写进 KV cache 的历史。所以中间预测的误差会一路滚下去。 论文希望「更干净的 token 给更噪的 token 当上下文」能改善中间预测。

这里有一个我认为需要点破的地方

那些「更干净的 token」不含任何新信息。它们是 x̂⁰i,j+1——学生自己上一步的预测——被加了更少的噪声而已。 它们不是真值，也不来自教师。所以它们能做的只是让模型对自己刚才的猜测更有信心，而不是纠正它。 如果 x̂⁰i,j+1 已经偏了，把它以更高信噪比塞回去，直觉上更像是放大误差而不是抑制误差。 论文没有为「减少误差累积」提供直接证据；§07 我用它自己 Tab. 8 的数字做了斜率复算，结论是这条主张没有被支持。

02Method

Dual-Noise Masking Rollout：五个式子逐个拆

论文 §3.2 一共给了 7 个式子（4、6、7、8、9、10、11）。它们其实只讲三件事： 在哪个区间里采一个更低的噪声水平（6、7）、怎么造出两个噪声水平的样本（8、9）、怎么拼（10）。 下面按这个顺序过，并且每一处我都会指出「论文写了什么」和「我从中读出的、论文没有明说的含义」。

02.1先把 rollout 的骨架摆正

AR 模型把视频写成 F 个 chunk：x = (x1, …, xF)， chunk-wise 设定下每个 chunk 含 3 个 latent 帧（论文实现细节；对应 Self Forcing 官方配置的 num_frame_per_block: 3）， frame-wise 设定下每 chunk 1 帧。流匹配的加噪定义是

xti = (1 − t)·x0i + t·ε,　ε ∼ 𝒩(0, I),　t ∈ [0,1]式 (4) t=1 是纯噪声，t=0 是干净图。这个约定和 DDPM 的 σ 方向相反，读论文时要注意——本文里「更低的 t」＝「更干净」。

训练时学生走 T = 4 步去噪，时间步取自 Nt = 1000 个训练时间步中的一个固定调度。 论文没有写出这 4 个值，但它的三个基线全部基于 Self Forcing 的官方配置，那里是 denoising_step_list: [1000, 750, 500, 250]。 这个细节等一下会变得很关键。每一步学生从带噪 chunk 预测一份干净估计：

x̂0i,j = Gθ( xtji | x<i, c, tj )式 (5)

注意三个条件：x<i 是之前 chunk 的干净预测（存在 KV cache 里），c 是文本， tj 是条件时间步。Mask Forcing 动的是第一个参数，第三个参数原封不动——这就是整篇论文的杠杆点。

02.2式 (6)(7)：那个「更干净的时间步」在哪儿采

ℓj = max( tmin, tj − Δ / Nt )　　　t′k ∼ Uniform( [ ℓj, tj ] )式 (6)(7) 论文取 Δ = 250（以训练时间步为单位，即归一化宽度 0.25），tmin = 调度索引 20 处的值（约 0.02，防止注入的信号"几乎全干净"）。 t′k 在每个去噪步都重新采一次。

02.3式 (8)(9)：同一个 ε，于是它其实是一次「偷跑的欧拉步」

xt′ki = (1 − t′k)·x̂0i,j+1 + t′k·εj　　　 xtji = (1 − tj)·x̂0i,j+1 + tj·εj式 (8)(9) 两式里的 εj 是同一个采样。论文文字里写的是 “we sample εj ∼ 𝒩(0,I) and use it to re-noise … at t′k and tj”，Alg. 1 第 16–17 行也是先采一次 εj 再用两次。

把两式相减：

xt′ki − xtji = (tj − t′k)·( x̂0i,j+1 − εj ) = −(tj − t′k)·v 其中 v = εj − x̂⁰ 正是流匹配里这条插值路径的速度。所以：被掩码的 token 相当于沿着这条路径多走了一个步长为 (tj − t′k) 的欧拉步， 而且用的是"作弊"的速度——不是模型预测的 v̂，而是构造这个样本时真正用到的 εj。所以这一步是精确的，直接朝 x̂⁰ 插过去。

02.4式 (10)(11)：掩码怎么拼，以及"骗时间步"这件事

xtmixi = Mi ⊙ xt′ki + (1 − Mi) ⊙ xtji　　　 x̂0i,j = Gθ( xtmixi | x<i, c, tj )式 (10)(11) Mi ∈ {0,1}L×H×W，比例 α = 0.2。条件时间步仍然是 tj——论文原话： “requiring the model to denoise inputs whose local noise levels are partially inconsistent with the global timestep”。

这句"partially inconsistent"是全文最该被划线的一句。扩散模型的时间步嵌入本质上是在告诉网络"输入的信噪比大概是多少、你该去掉多少"。 现在有两成位置的信噪比比声明的高，网络若按 tj 的力度去噪，在这些位置上就会去过头。 DMD 的梯度会教它适应这种混合输入——但推理时输入是处处一致的。所以这个"适应"到底往哪个方向调整了模型，论文没有分析。

03Algorithm

伪代码里藏着的四个细节

论文正文对 Alg. 1 只有一句"we provide detailed pseudocode"。但那 33 行里有四处，只看正文是读不出来的， 而它们直接决定了这个方法到底在优化什么。下面这个交互把 Alg. 1 逐行跑一遍。

03.1细节一：第一个去噪步永远不加掩码

Alg. 1 第 12 行，从纯噪声出发的那次前向写的是 G(x^{t_T}; c, t_T, KV)，注释是 “initial unperturbed prediction”。 这不是设计选择而是结构性的：式 (8)(9) 要重加噪的对象是 x̂⁰i,j+1，而在 j = T 时还没有"上一步的干净预测"可用。 所以掩码只能作用在 j = T−1, …, s 这最多 3 步上。

03.2细节二：s 是每条 rollout 采一次，不是每 chunk

第 3 行 s ∼ Uniform{1,…,T} 在 chunk 循环之外。这来自 Self Forcing 的梯度截断技巧： 为了省显存，一条 rollout 里只有一次前向带梯度。它带来两个后果：

  • s = T 时（概率 1/T = 25%），第 13 行的 if s < T 不成立，内层循环整个跳过——这一整条 rollout 里每个 chunk 都只做一次前向、且完全没有掩码。换句话说，论文的方法有四分之一的训练步等于什么都没做。
  • s < T 时，带梯度的那次前向发生在第 24 行，输入是 x^{t_mix}。也就是说：只要掩码生效，生成器收到的全部梯度就都是在含掩码的输入上算的。
细节三：这是我认为最值得停下来想一想的一点

把上面两条合起来：生成器参数的更新，要么发生在完全没有扰动的 rollout 上（25%），要么发生在一个推理时几乎不可能出现的输入上（75%）。

为什么说"几乎不可能出现"？掩码是逐 token 的伯努利采样，一个 chunk 有 3 × 60 × 104 ≈ 1.9 万个 latent 位置， 全零掩码的概率是 0.818720，实际上就是 0。而推理时输入恒等于全零掩码那一档。 所以训练分布和推理分布之间不是"有点偏"，而是推理点位于训练分布支撑集的一个测度极小的角落。 这不必然是坏事——dropout、数据增强都是这个形状——但它意味着 §04 那个理论分析（它分析的是训练时的混合分布 q̄） 并不能直接推出推理时那个分量 q无掩码 的性质。

03.3细节四：扰动会顺着 KV cache 传染给后面所有 chunk

第 29 行：kv_i ← G_KV(x̂⁰_{i,s}; c, t_0, KV)。写进 KV cache 的是 exit step 的那份预测， 而当 s < T 时这份预测正是由含掩码的输入产生的。于是：

  • 扰动不只作用在当前 chunk 的这一步，它会沿自回归方向一路往下走——第 3 个 chunk 的历史上下文里已经带着前两个 chunk 的扰动痕迹。
  • 这是"扰动 rollout 轨迹"这句话真正兑现的地方：不是单点抖动，而是整条自回归轨迹的分叉。论文 §3.2.3 把这些采样合称为"masking trajectory V"，正是为此。
  • 反过来说，这也让 §08.3 的担忧更具体：训练时喂进 KV cache 的历史，其统计性质与推理时的历史不完全一致。

04Theory

附录那个 KL 分解，到底证明了什么

论文 §3.2.3 和附录 6.1 给了一个命题，被用来支撑"掩码能缓解 mode-seeking"。 它是对的——而且证明只有半页，是一个标准的互信息分解。但它证明的东西比读者第一眼以为的少。这一节我把它拆开，并做一个能亲手验证的数值沙盘。

04.1命题本身

固定文本条件 c 和一个 DMD 加噪时间步 τ。把一条 rollout 里采到的全部掩码和低噪时间步打包成 V = {(Mr, tk,r)}r=1..R ∼ π，称为一条 masking trajectory。给定 V = v， 学生的条件输出分布记作 qvθ,τ；对 V 求边缘得到 q̄θ,τ。那么

DKL( q̄θ,τ ‖ pτ ) = 𝔼V∼π[ DKL( qVθ,τ ‖ pτ ) ] − Iθ(V ; Xτ | c)式 (13) / (21) 右边第二项是条件互信息，等于 𝔼V[DKL(qV ‖ q̄)]，衡量"不同掩码轨迹产出的分布彼此差多远"。 互信息非负，所以 DKL(q̄‖p) ≤ 𝔼V[DKL(qV‖p)]，当且仅当掩码轨迹不影响输出时取等。

用人话讲：一堆各自缩在不同地方的窄分布，把它们混起来，混合体离教师分布反而比"平均每个分量离教师分布"更近。 这就给了一条出路——不需要让每一个条件分布都变得 mode-covering，只要让不同轨迹缩在不同的教师模式上， 混合体自然就覆盖了多个模式。而 DMD 的假分数模型 sfake 不看 V，它估的正是混合体 q̄ 的分数， 所以 DMD 的梯度确实是在把 q̄（而不是某个 qv）往教师身上推。这个逻辑链是自洽的。

04.2四条它没有证明的事

缺口 1
它比较的不是「有掩码 vs 没掩码」
式 (21) 把 D(q̄‖p) 和它自己的分量平均 𝔼VD(qV‖p) 相比。 而我们真正想知道的是它与基线 D(q无掩码‖p) 谁小。式 (21) 对此一言未发： 左右两边都随 θ 变化，而基线是另一个训练过程的产物。
缺口 2
它对任何随机扰动都成立
推导只用到"V 是随机的、fake score 不看 V"。把 V 换成高斯抖动、dropout、随机时间步偏移、甚至随机 crop， 式 (21) 一字不改。所以这个理论不能把功劳归给"掩码"或"双噪声"这两个具体形状。 要归因就得做对照实验，而论文只消融了自己的三个超参。
缺口 3
训练分布 ≠ 部署分布
理论对象是训练时的混合体 q̄。但推理时不采 V，输出来自 qv=∅。 即使 DMD 收敛到 q̄ = p，混合等于 p 也不蕴含每个分量等于 p——恰恰相反， 式 (21) 在 q̄ = p 时给出 𝔼VD(qV‖p) = I > 0， 即每个分量都必然偏离教师，偏离量正是互信息。
缺口 4
精确分数假设
式 (18)(19) 假设 sreal, sfake 是精确分数。论文自己注明"用于识别目标"。 但实际的 sfake 是一个在线训练的网络，现在它要拟合的是一个被扰动加宽了的分布—— 同样的训练预算下拟合更宽的分布，误差通常更大，而 DMD 的梯度对 sfake 的误差是敏感的。这一项没有被讨论。
我的判断

把缺口 3 摊开看，其实指向一个有意思的可能：Mask Forcing 的收益也许并不来自"混合体覆盖了更多模式"这条叙事， 而更像是一个朴素得多的机制——训练时的输入分布被加宽了，模型被迫在更宽的输入邻域上把 x̂⁰ 预测对， 这本身就是正则化，而正则化会抑制"把所有输入都映射到几个高频安全色块"这种退化解。 这两种解释在现有实验下无法区分，因为区分它们需要的正是缺口 2 说的那个对照实验： 把掩码换成一个不改变输入信噪比结构的随机扰动（例如给 xtj 加一点各向同性噪声，或只随机抖动全局 tj 而不做逐 token 掩码）。 后者其实就是 α = 1——而论文的 α 消融停在 0.5。

06.2最想看却没有的那个消融

如果要我给作者提一条最有价值的补充实验，是这个：α = 1。

α=1 意味着掩码全为 1，所有 token 都走 t′k——掩码消失了，只剩"每步把整个 chunk 随机多去噪一点，但仍告诉模型是 tj"。 这是一个纯粹的全局时间步抖动基线。如果 α=1 也能拿到大部分收益，那么"逐 token 掩码 / 空间与时间轴的随机性"这些贡献点就站不住； 如果 α=1 明显更差，掩码的必要性就被坐实了。这个实验零额外实现成本（把 M 置为全 1 即可），而论文的 α 扫描停在 0.5。

第二条我想看的是：把 xt′k 的 ε 换成独立采样。 §02.3 说明了共用 εj 让整件事退化成"沿同一条线段的精确插值"；换成独立噪声后，扰动的性质会从"进度错位"变成"真正的双噪声"， 这两者是不同的机制，而论文的命名（Dual-Noise）指向后者，实现却是前者。

07Verification

"减少误差累积"这条主张，我用它自己的数据复算了一遍

摘要、引言、方法、结论四处都写了"reducing error accumulation"。这是一个关于斜率的主张： 如果误差累积被抑制了，那么随着 rollout 变长，质量下降应该更慢。论文附录 Tab. 8 恰好提供了检验它的数据—— MovieGen 上 0–30 秒、每 6 秒一段的 CLIP Score 和 HPSv3。我把这 20 个数拿去做了线性回归。

结论：这是一次「整体抬升」，不是一次「衰减变缓」

Tab. 8 支持的结论是：Mask Forcing 让长视频在每一个时间段上都更好——这本身很有价值，也确实是论文写的 "achieves higher CLIP and HPSv3 scores than LongLive across all intervals"。 但它不支持"reducing error accumulation"。误差累积对应的是曲线的斜率，而斜率一模一样。 更准确的描述是：起点被抬高了，衰减速度没变。论文自己在这一段的措辞其实是克制的（只说各段都更高）， 但摘要和方法部分把它写成了"减少误差累积"，两者不是一回事。

这也和 §01.2 的机制分析对上：被注入的"干净 token"来自学生自己的预测，它提高的是对当前预测的信心，而不是纠错能力， 因此没有理由改变误差随 rollout 增长的速率。如果作者想支持"减少误差累积"，需要的是一条斜率明显更平的曲线， 或者在更长的时程（比如 60s、120s）上显示交叉之前的差距在扩大。

附带一提，附录 6.5 的相机控制 I2V 实验里，论文对 Self Forcing 的失效描述是"videos become darker and lose fine-grained details as the rollout proceeds"， 并说 Mask Forcing "mitigates this degradation"。这是一个纯定性的展示（Fig. 10，没有任何数字）。 考虑到 Tab. 8 的斜率复算结果，我倾向于认为那里看到的同样是"整体更亮更细"而不是"衰减更慢"，但在没有数字的情况下无法判断。

存疑清单

先把话说清楚：我认为这是一篇有价值的论文。零成本、可插拔、方向一致的 12 个格子、加上收敛曲线， 这些是真实的贡献。下面这些是我在精读时记下的、我认为需要作者补充或读者自行留意的地方，按我判断的严重度排。 每一条我都尽量给出"要怎样才能消除这个疑虑"。

反过来说，我认为最站得住的三条

① 零成本是真的。Alg. 1 里没有任何额外前向，式 (8)(9)(10) 全是逐元素运算，训练预算与基线一致（1.5k step / 8 卡 14 h）。 对一个"往现有 pipeline 里插五行"的技巧来说，这是最重要的性质。

② 方向一致性是真的。3 基线 × 2 设定 × HPSv3 与 VBench Total 两个基准 = 12 个格子全部为正。 即使没有误差棒，全为正这件事本身就压低了"纯噪声"的解释空间（在无效假设下概率约 2−12， 尽管这些格子并不独立）。

09.2它在本仓库这条线上的位置

09.3如果要在自己的世界模型里用它，我建议的顺序

  1. 先做 α = 1 的对照（§06.2）。五分钟的改动，能直接告诉你收益是来自"逐 token 掩码"还是来自"训练输入被加宽"这件事本身。如果是后者，你可能有更适合自己 pipeline 的加宽方式。
  2. 把 Δ 对齐到你自己的调度。论文的 Δ=250 之所以合理，是因为 Self Forcing 的 4 步调度间隔正好是 250（§02.2）。 如果你用的是 3 步或 8 步、或者非均匀调度，直接抄 250 是没有意义的；应该抄的是"窗口 ≈ 一个调度步的间隔"这条相对关系。
  3. 在长时程上验证斜率，而不是只看首段质量（§07）。交互式世界模型真正致命的是 rollout 走到几十秒以后的坍缩， 而这篇论文没有证据表明 Mask Forcing 改变了衰减速率。抬高起点当然也有用，但别把它当成解决了长时程问题。
  4. 注意 KV cache 里的历史统计变了（§03.3）。如果你的世界模型对历史上下文有额外约束（几何一致、记忆检索、动作条件）， 训练时那份历史是由被扰动的预测写进去的，值得单独看一眼这些模块的表现有没有受影响。

10.4术语表

Self-rollout
训练时让学生用自己生成的历史逐 chunk 往下写，而不是喂真值历史。Self Forcing 的核心，用来消除训练/推理的历史分布差。
DMD（Distribution Matching Distillation）
用"真实分数 − 假分数"的差作为生成器梯度，把多步教师蒸馏成少步学生。目标是反向 KL D(pfake‖preal)。
Mode seeking / mode covering
反向 KL 惩罚"学生有、教师没有"，因此倾向缩到少数高密度模式（seeking）；正向 KL 惩罚"教师有、学生没有"，倾向铺满（covering）。
Exit step s
Self Forcing 的显存技巧：一条 rollout 里只在随机选中的第 s 个去噪步保留梯度，其余步 no-grad。本文的掩码在 s=T 时整体失效。
Dual-noise input
本文的输入 xtmix：一部分 token 处在 tj，另一部分处在更低的 t′k。两者用同一个 ε，所以是"双噪声水平"而非"双噪声样本"。
Masking trajectory V
一条 rollout 里采到的全部 (Mr, tk,r) 的集合。理论分析把学生分布写成对 V 的混合。
HPSv3
人类偏好打分模型（Human Preference Score v3），本文的主视觉质量指标，也是选超参用的指标之一。
VisionReward
多维人类偏好模型，本文用它报 Vision.（视觉）、Instruct.（指令遵循）、MQ（运动质量）三个子分。
Dynamic Degree
VBench 的运动幅度指标，本文用 RAFT 光流计算。论文自己指出它会把漂移误判为运动。
CMMD / VMMD
在 CLIP / V-JEPA2 特征空间上算的 Maximum Mean Discrepancy，本文用来度量学生与教师生成分布的距离（参考集由教师生成，不是真实视频）。
Self-Flow
Chefer 等 2026 的工作，提出混合时间步调度 + 掩码用于表征对齐。本文"干净 token 给噪 token 当上下文"这一半的直接来源。
