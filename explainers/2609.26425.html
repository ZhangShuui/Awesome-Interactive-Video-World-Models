QuantWM 精读

把视频世界模型的 KV cache 压到 2 bit 时，不只要求 Key "存得准"，还要求 Query 看 Key 时"看得准"。具体做两件事：先挑一个对查询最友好的质心，再在 Query 最常看的几个方向上把剩下的误差补回来。

方法本身很干净：QSAC 和 PSAC 都在压同一个量，也就是查询看到的 logit 误差 E[(qᵀe)²]，一个在"选质心"时下手，一个在"存完之后补"。问题出在证据链上。第一，基线 QVG 的复现结果比 QVG 原论文自报的低 8–13 dB；评测协议不同只能解释其中一部分（同一对比里 KIVI 只低 6.6 dB），论文没有解释。第二，没有同 bit 数的对比：QuantWM 实际约 2.6 bit/元素，比 QVG 自报的约 2.3 bit 多。第三，标题主打的"闪烁"从头到尾没有被直接测量。另外，PSAC 的思路和 SQuat、GEAR 高度重合，两篇都没有引用。我用项目页的 54 段视频补测了 warping error（一种无参考的帧间一致性指标）。在 17 个有效展示样例上，QVG 平均比 BF16 高约 22%，QuantWM 只高约 2%，这一点支持 QuantWM。

§1一页读懂

一句话：它是 QVG（"质心 + INT2 残差"）的升级版，只改了 Key 的存法，而且改动全部围绕"让 qᵀk 算得准"展开。

它做对的
  • 目标选得对：不再追求 ‖k − k̂‖ 小，而是追求 Eq[(qᵀe)²] 小。
  • 统计量在线累积，只用已经生成的 Query，不需要校准集，也不用训练。
  • 覆盖 5 个开源自回归模型（3 个交互式世界模型 + 2 个视频生成模型），测了 480p 和 720p。实现是真实的打包格式加 Triton 内核，内存和端到端时延都有实测。
  • 项目页视频的复测（§9）支持"比 QVG 更少帧间抖动"。
最该打折的地方
  • QVG 复现值比原论文低 8–13 dB，全文最重要的对比都建立在这个复现上。
  • 没有同 bit 数的对比；"2-bit"实际约 2.6 bit，PSAC 自己就占 0.13–0.26 bit。
  • "闪烁"没有直接指标；PSNR 对 BF16 衡量的是"轨迹偏离了多少"。
  • 和 SQuat / GEAR / Tuncer 2026 的关系没有讲清楚（§4、§5）。

§2背景：视频 KV cache，以及 QVG 的"质心 + 残差"存法

先把地基打牢：QuantWM 的一切改动都建立在 QVG 的存储格式上，而 2 bit 下误差从哪来，决定了后面两个模块为什么要这样设计。

为什么视频模型的 KV cache 这么大

自回归（chunk-wise）视频模型一次生成一小段帧（一个 chunk）。生成新 chunk 时，要通过注意力回看所有历史 chunk 的 Key/Value。为了不重算，历史 K/V 被缓存下来，这就是 KV cache。视频的 token 数远比文本多，480p 一个潜帧约 1,560 个 token（Wan 系 832×480：VAE 8× 下采样，再 2×2 patch，合计 16×），每层、每个头都要各存一份 K 和 V。论文给的例子：LingBot-World-v2 生成 5 秒（93 帧）需要 21 GB 以上的 KV cache；LongCat-Video 为 21.709 GB，HY-World 1.5 为 12.09 GB。

流式设置下有一个关键约定：正在去噪的当前 chunk 始终保持 BF16；chunk 一旦完成，就被压缩一次，之后不再重新压缩。所以"被量化的"永远是历史，Query 永远来自当前 chunk。

QVG 怎么存一个 Key

QVG（Quant VideoGen, 2602.02958）的观察是：视频 token 冗余很大，相邻帧、相邻像素块的 Key 很像。于是对一个 chunk 内的所有 Key 做 k-means（256 个质心），每个 token 只存它属于哪个质心（uint8 编号）和它与质心的差（残差）。质心用 BF16 存，残差用 INT2 存：

Eq. 3–4ri = ki − μzi,    k̂i = μzi + Qb(ri) Qb 是逐组的非对称均匀量化：每 64 个通道一组，取组内 min/max，分成 2b − 1 = 3 个台阶，也就是只有 4 个可表示的值。

2 bit 只有 4 个台阶，台阶宽 Δg = Rg/3，其中 Rg 是该组残差的极差（max − min）。按经典的"均匀噪声"近似（Widrow），每个通道的量化误差方差约为 Δg²/12 = Rg²/108。这个式子对后面理解 QSAC 非常关键：误差大小由整组的极差决定，同一组里只要有一个通道残差特别大，其余 63 个通道的误差也会一起变大。

§3动机：为什么 Key 比 Value 更"娇气"

论文的出发点有三条观察：VBench 几乎不掉分，但视频在闪；只量化 K 比只量化 V 糟得多；K 的重建误差反而更小。我逐条核对了一遍。结论是方向没问题，但"意外"这个说法言过其实，表 1 本身也有反例。

用人话讲：同样大小的噪声，放在 K 上和放在 V 上，后果不一样

注意力输出是 o = Σj aj vj，权重 a = softmax(qᵀkj/√d)。

  • V 的误差是线性、被平均的：Δo = Σ ajΔvj。如果各 token 的误差互相独立，注意力越分散，误差就越被平均掉（方差 ≈ σ²·Σaj²）。
  • K 的误差先被 Query 放大，再进指数：Δℓj = qᵀΔkj/√d，其方差和 ‖q‖² 成正比，并集中在 Query 能量大的方向上。logit 变了，softmax 就会把权重挪到别的 token 上，也就是论文说的"换了个参考帧、换了个位置去抄"。
  • 还有一个系统性偏差：零均值的 logit 噪声经过 exp 之后，期望变成 eσ²/2 > 1，于是被量化的历史 token 整体"偷"走了当前 chunk 的注意力。这正是 Tuncer et al. 2026（2605.26266，论文引用了）所说的 Jensen bias。

所以"K 的 MSE 更小、输出误差却更大"并不矛盾：K 的敏感度取决于 ‖q‖²·σk²，而不是 σk² 本身。下面这个小实验把这件事做成了可以拖动的形式。

我的判断

动机的方向是对的，而且 QuantWM 后面的设计正好对准了"‖q‖² 加权"这件事。但有三点要打折：（1）"Key 比 Value 敏感"在 LLM 的 KV 量化里早有结论（KIVI 发现 Key 有通道离群值，需要按通道量化；AsymKV 发现 loss 对 Key 量化更敏感），在视频扩散里 Tuncer 2026 也已专门分析过，谈不上"surprisingly"。（2）K 和 V 的绝对 MSE 不能直接比：QVG 论文报告 max|K| 约 1e2、max|V| 约 1e3，量级本来就不同，应该报相对误差。（3）表 1 本身就有反例（LingBot 中间层），表 2 只基于少数样例。

§4QSAC：挑一个"对查询最友好"的质心

QVG 给每个 Key 分配欧氏距离最近的质心。QSAC 改成：先按"Query 在意的通道"加权距离挑 4 个候选，再在候选里挑量化后 logit 误差最小的那个。质心本身不变，变的是"谁归哪个质心"。

  1. 攒历史 Query 的二阶矩

    对每个注意力头 h，把所有已完成 chunk 的 Query 累积成 Mh = (1/N)Σ q qᵀ（Eq. 6，d×d）。用"过去的 Query"去近似"将来会来看这些 Key 的 Query"。

  2. 把 logit 误差写成二次型

    Key 误差 e 造成的 logit 误差平方，对 Query 取期望：Eq[(qᵀe)²] = eᵀMhe（Eq. 7）。这一步是精确的，是全文最干净的一个式子。

  3. 只保留对角线，得到通道敏感度

    eᵀMe ≈ Σc Mcc ec²（Eq. 8），归一化成 wc = Mcc / mean(Mcc)（Eq. 9）。Mcc = E[qc²]，也就是说，Query 在哪个通道上能量大，哪个通道就"敏感"。

  4. 第一阶段：加权距离挑 top-M 候选

    dQ(k, μj) = Σc wc(kc − μj,c)²（Eq. 10），取最小的 M = 4 个。

  5. 第二阶段：估计每个候选量化后的误差

    候选残差 rij = ki − μj，每组极差 Rg（Eq. 11）。按均匀噪声近似，E[ec²] ≈ Rg²/(12·(2b−1)²)（Eq. 12），b = 2 时就是 Rg²/108。代回第 3 步，得到期望 logit 误差（Eq. 13）。

  6. 取打分最小的候选

    S(ki, μj) = Σg (Σc∈Gg wc) · Rg(rij)²，zi = argminj∈Ci S（Eq. 14）。第一个 chunk 没有统计量，就令 wc = 1（附录 C.3）。

三个值得注意的细节

① S 和 Tuncer 的"Jensen bias"是同一个量

Tuncer 2026 给出的单个 logit 的量化噪声方差是 σi² = (1/12d)Σc qc²Δi,c²，偏置校正项 bi ≈ σi²/2。对 Query 取期望，并代入组内共享的 Δg = Rg/3：

我的推导Eq[σi²] = 1/(12d) · Σg (Σc∈Gg Mcc) · Rg²/9  ∝  Σg Wg Rg² = S 也就是说，QSAC 挑的正是"期望分数噪声最小"的质心，而分数噪声越小，Jensen bias 也越小。QSAC 同时在减轻"top-1 换人"和"注意力被历史偷走"这两种现象，但论文只讲了前者，没有测注意力质量偏移 ΔPS，也没有和 Tuncer 的零内存校正做比较或叠加。Tuncer 已经在 MAGI-1 上演示过，他们的校正可以直接叠加在 QVG 上。

② 第二阶段其实只看两个数

这几个模型的注意力头维度基本都是 128（例如 Wan 系：1536/12、5120/40），组大小 64，于是每个 token 每个头只有两组，S = W1R1² + W2R2²。通道级的敏感度差异在第二阶段被"组内求和"抹平了，只剩下"前 64 维和后 64 维谁更重要"这一点信息。真正细到通道的加权，只发生在第一阶段。

§5PSAC：在 Query 最常看的方向上把误差补回来

2 bit 再怎么挑质心，误差也消不掉。PSAC 的想法是：logit 只关心误差在 Query 方向上的投影，而 Query 的能量集中在少数几个方向上，那就只把这几个方向上的误差单独记下来，用的时候加回去。

  1. 算出 QSAC 之后剩下的误差

    E = K − K̂0（Eq. 15），在压缩时原始 K 还在手上，所以可以算出来。

  2. 期望 logit 误差按特征方向拆开

    D(E) = EQ‖QEᵀ‖F² = Tr(EMEᵀ)（Eq. 16）。把 M = UΛUᵀ 代进去（Eq. 17），就得到 D = Σj λj‖Euj‖²：误差在第 j 个 Query 主方向上的分量，按该方向的 Query 能量 λj 计价。

  3. 只存前 r 个方向上的分量

    C = EUr（Eq. 18），每个 token 存 r = 8 个数，量化成 INT8，每行再带一个 FP16 scale；Ur 用 BF16 存。如果某一行量化后反而让加权误差变大，就把这一行置零；每个 chunk 在稠密和稀疏两种布局里取更省的那种（附录 D.1）。

  4. 解码时加回去

    K̂ = K̂0 + CUrᵀ（Eq. 19）。补完之后剩下的期望 logit 误差正好是 Σj>r λj‖Euj‖²（我的推导，忽略 INT8 误差）。换句话说，前 r 个方向上的误差被清零，其余方向一点不动。

几点观察

  • r 从 0 到 2 是大头。在 HY 上，r = 0 → 2 带来 +0.40 dB（17.99 → 18.39），r = 2 → 32 总共只再加 +0.12 dB。这和"Query 能量高度集中"一致：图 4 中 LingBot-v2 第 38 层前 8 个方向占 71.14%（正文写的是"超过 60%"）。我的猜测是，最前面一两个方向里有一个"所有 Query 共享的均值方向"。误差在这个方向上的分量，会让某个历史 token 对所有 Query 都一起变亮或变暗，这恰好也是 Jensen bias 式"整体偷注意力"的来源。
  • ΔBit 与 r 严格成正比。HY 每个秩 0.01676 bit，CF 每个秩 0.03211 bit，精确到小数点后 4 位都对得上，所以 r = 8 在 HY 上约花 0.13 bit/元素，在 CF 上约 0.26 bit。CF 的斜率正好等于"每个 token 存 r 个 INT8、只存 Key、按 K+V 平均"的 8/256 = 0.03125，再加上 Ur 的摊销。HY 只有一半，可能是约一半的系数行被置零了，但论文没说。另外，严格线性也暗示这一列是按公式算的，而不是在附录 D.1 那种"自适应稀疏布局"下实测的。
  • Eq. 19 右半边只是代数写法。QK̂ᵀ = QK̂0ᵀ + QUrCᵀ 看起来像一条低秩快速通道，但实现里是先把 K̂ 整个重建成 BF16，再交给原生 FlashAttention，并不节省注意力计算。
相关工作：PSAC 的两个"近亲"都没有被引用
  • SQuat（Subspace-orthogonal KV Cache Quantization，COLM 2025，2503.24358）：对 prompt 阶段的 Query 做 SVD 得到子空间，量化 Key 时逐块更新剩余元素，让误差尽量正交于这个 Query 子空间。它的两个出发点（"要保内积而不是保 Key"、"Query 落在低维子空间里"）和本文 §3、§4.2 几乎一字不差。区别在于 SQuat 不额外存东西，PSAC 则多存了 0.13–0.26 bit 的投影系数。
  • GEAR（2403.05527）：量化之后，用低秩矩阵逼近量化残差，再加一个稀疏矩阵收拾离群值。PSAC 可以看成"把 GEAR 的 SVD 基换成 Query 主方向"。

两者都是 LLM 上的免训练方法，迁移到视频 KV 上并不难。最起码，SQuat 这种"零额外存储"的版本应该作为消融出现。

§6系统与"2-bit"的真实账单

论文说"2-bit"，是指残差用 2 bit。可 KV cache 里除了残差，还有质心、编号、scale、zero-point 和 PSAC 系数。按论文自己报的压缩比倒推：HY 的 6.20× 相当于 2.58 bit/元素，LongCat 的 5.99× 相当于 2.67 bit/元素。

运行时：省的是常驻内存，不是带宽

生命周期（附录 D.1）：当前 chunk 保持 BF16；chunk 完成时做 QSAC + INT2 打包、算 PSAC 系数，然后释放原 BF16。每次注意力调用，Triton 内核把整段历史解包、加质心、加 PSAC，写出一份临时的 BF16 K/V，交给模型原生的 FlashAttention 或 SDPA 使用，用完即丢。对 pre-RoPE 缓存的模型，重建后再补上位置编码。

这意味着在 GPU 常驻的场景里，每一步的内存流量是"读压缩数据 + 写一份 BF16 + 注意力再读一遍 BF16"，比原本的 BF16 cache 还多，所以时延会上升（LingBot +5.44%，HY +5.87%）。LongCat 反而快了 17.78%，原因是它的原生管线会把 KV cache offload 到 CPU 内存，压缩后主机与 GPU 之间要搬的数据变少了（附录 D.2）。这是 offload 带来的红利，不是量化本身带来的加速。

§7玩具沙盒：把 QVG、QSAC、PSAC 放到同一组合成数据上

论文没有公开代码，所以我用 JavaScript 实现了一个"缩小版"：32 维、两组（每组 16 通道）、640 个 Key、24 个 k-means 质心、INT2 组量化，Query 的协方差谱可调。所有数字都在你的浏览器里实时算出来。

沙盒里看到的（不代表真实模型）
  • PSAC 很稳：α 越大（Query 越集中），PSAC 砍掉的 logit 误差越多，这与机制推导完全一致。
  • QSAC 不稳：在这组通用假设下，两阶段 QSAC 大多和 QVG 打平，偶尔变差；只用第一阶段（M = 1）的版本经常明显变差。原因就是 §2 的滑块演示的那件事：第一阶段只奖励"敏感通道残差小"，却看不见同组里某个不敏感通道的大残差会把整组台阶一起拉宽。
  • 二者叠加不是 1 + 1：在沙盒里，QSAC + PSAC 通常只和"只开 PSAC"持平。原因之一是 QSAC 用完整的 diag(M) 加权，其中包括 PSAC 随后会清零的那 r 个方向。论文表 5 也显示出强烈的次可加性：单独开 +1.87 dB 和 +1.73 dB，一起开只有 +2.33 dB。
  • 论文在真实模型上报告 QSAC 单独就有 +1.87 dB。这说明真实数据里存在沙盒没有的结构，比如 Query 与 Key 共享的离群通道，或者大量"几乎等距"的质心。可惜论文没有刻画这些结构，也就无法判断 QSAC 在别的模型上会不会同样有效。

§9我用项目页视频做的独立复测

论文没有任何直接衡量闪烁的指标，但项目页的 GitHub 仓库公开了 18 组对比视频（每组 BF16 / QVG / QuantWM 三段，共 54 段）。我把它们全部下载下来，补测了一个无参考的帧间一致性指标。

warping error
用 DIS 光流把第 t−1 帧对齐到第 t 帧，再算平均绝对误差（0–255）。画面越闪、越抖，这个值越大；正常的运动因为已经被光流补偿，影响较小。这是视频时序一致性的常用指标。
PSNR vs BF16
逐帧和 BF16 比较（与论文口径相同），用来看"偏离轨迹"随时间怎么变。
局限
这些都是作者挑出来的展示样例，而且经过 h264 压缩；光流本身也有误差。结论只能说明方向，不能替代正式评测。
顺带发现：一段"QVG"视频其实就是 BF16

项目页仓库里的 causal-forcing-2-qvg.mp4 和 causal-forcing-2-bf16.mp4 逐字节相同（大小都是 1,561,879 字节，md5 都是 283e0c5e…）。逐帧 PSNR 是无穷大，warping error 也完全一样。这应该是上传时放错了文件，不影响论文的表格，但项目页上这个例子的"QVG"列并不是 QVG 的输出。其余 53 个文件两两不同。

§10存疑清单

按严重度排序。"高"表示会动摇主结论，"中"表示影响解读或方法设计，"低"是笔误或信息缺失。每条都附了能自己核对的证据。

  1. 01高基线 QVG 比它原论文低 8–13 dB，没有解释

    LongCat-Video 480p INT2：QVG 自报 PSNR 28.72（6.94×），本文复现 20.68。HY-World 1.5（= HY-WorldPlay-8B）：自报 29.17（7.05×），本文复现 16.12。评测协议不同能解释一部分：HY 上 KIVI 也从 24.27 掉到了 17.68（−6.6 dB）。但 QVG 掉得多一倍（−13.1 dB），结果从"远好于 KIVI"变成了"不如 KIVI"；LongCat 上也是同样的排名颠倒（QVG 论文：KIVI 20.32 < QVG 28.72；本文：KIVI 24.45 > QVG 20.68）。QVG 原文的实现细节（缓存 pre-RoPE 的 Key、FP8 scale）与本文"遵循各模型原生缓存约定"的做法是否一致，本文没有交代。"QVG 会严重闪烁"这一核心论断完全建立在这个复现上。

    证据：本文表 3；QVG 2602.02958 表 1、§5.1。

  2. 02高没有同 bit 数的对比

    QuantWM 的 6.20× 和 5.99× 相当于 2.58 和 2.67 bit/元素；QVG 自报的 INT2 配置约为 2.27–2.31 bit。本文没有报告 QVG 和 KIVI 在其复现下的内存，而 KIVI 还保留了 BF16 的最近窗口、用 32 的组大小。PSAC 本身就占 0.13–0.26 bit（表 9 的线性斜率）。QVG 论文显示，QVG-Pro（约 5×）比 QVG 高 1.7–2.4 dB。零点几个 bit 就能换来几个 dB，所以必须画同一横轴（bit/元素）的 Pareto 曲线才能比较。

    证据：§6 计算器；本文表 9；QVG 表 1。

  3. 03高标题说"时间一致"，但没有一个直接测闪烁的指标

    PSNR、SSIM、LPIPS 都是和 BF16 比的保真度，衡量的是"轨迹偏了多少"（§9 的曲线显示，它们在视频后段主要由分叉主导）。VBench 只报了 4 项，恰好没报它自带的 Temporal Flickering 和 Motion Smoothness。也没有 warping error、FVD 或用户研究。我在项目页视频上补测的 warping error 支持论文的方向（QVG 平均 +22%，QuantWM +2%），但那是精选样例。

    证据：本文 §5.1 Metrics；§9 复测。

  4. 04高长视频实验和论文自己的论点冲突

    全文的论点是"VBench 看不出退化"，1 分钟实验却只用 VBench；而且量化版多处高于 BF16（Causal-Forcing：QVG +1.78 分，QuantWM +3.46 分；HY +0.60；LongCat +0.32；LingBot +0.21）。这说明该设置下 VBench 的差异不能当作"对累积误差更鲁棒"的证据。

    证据：本文表 8、附录 B.2。

  5. 05中动机表 1 有反例，比较方式也不成立

    LingBot-v2 中间层 K-only 的输出误差（0.1868）小于 V-only（0.1946）。K 和 V 的绝对 MSE 不可直接比（QVG 报告 max|K| 约 1e2、max|V| 约 1e3），应该报相对误差。"Output MSE"是哪一层的输出，没有定义。表 2 只在图 2 的样例上算，LB-2 的 K2V2 甚至高于 K2V16。

    证据：本文表 1、表 2；§3。

  6. 06中"Key 更敏感"并不是新发现

    KIVI（Key 有通道离群值，需要按通道量化）、KVQuant、AsymKV（loss 对 Key 量化更敏感）早有结论；Tuncer 2026 已在视频扩散里专门分析过"量化 Key 偷注意力"。摘要里的"surprisingly"言过其实。

    证据：Tuncer 2605.26266 §2 相关工作。

  7. 07中PSAC 的近亲 SQuat、GEAR 没有被引用

    SQuat（COLM 2025）用 Query 子空间约束 Key 量化误差，让误差与子空间正交，而且不需要额外存储；GEAR 用低秩矩阵补量化残差。PSAC 相当于"把 GEAR 的低秩基换成 SQuat 的 Query 子空间，再额外存下投影系数"。两者都应该出现在相关工作和消融里。

    证据：SQuat 2503.24358 §3.1–3.3；GEAR 2403.05527 §3。

  8. 08中QSAC 的打分就是 Tuncer 的分数噪声方差，却没有和 Tuncer 比

    对 Query 取期望后，S = ΣgWgRg² 与 Tuncer 的 σi² 成正比（§4 ①），所以 QSAC 同时也在减轻 Jensen bias。论文只用"top-1 换人"来解释收益，没有测注意力质量偏移，也没有和 Tuncer 这种零内存、可以叠加在 QVG 上的校正做比较或组合。

    证据：本文 Eq. 13–14；Tuncer Eq. 7、13，表 1（QVG + 校正）。

  9. 09中top-1 漂移率既不透明，又是弱代理

    统计口径没有交代：哪些层、头、去噪步参与统计，是否用同一份 Query 做 teacher-forced 比较。top-1 对近似平局极其敏感，QVG 61% 的漂移率下 VBench 几乎不变。而 PSAC 直接最小化 logit 误差，用它来评 PSAC 有自证之嫌。应该补注意力输出误差或 JSD。

    证据：本文表 4、表 5、§5.3。

  10. 10中QSAC 的代理目标可疑

    如果 S 真能近似 logit 误差，穷举（M = 256）应该不差于 M = 4；实际 Causal-Forcing 从 16.283 掉到 16.207。第一阶段只看残差大小，看不到组量化的"一个离群值拖累整组"（§2 的演示）。在我的沙盒里，只用第一阶段会变差。另外，每个头只有两组，第二阶段只剩两个数；质心位置是否随新分配更新，论文也没说。

    证据：本文表 11；§4、§7。

  11. 11中QSAC 和 PSAC 各做各的，没有联合设计

    QSAC 用完整的 diag(M) 加权，其中包括 PSAC 随后会清零的前 r 个方向。更自然的做法是按"PSAC 修不到的剩余敏感度" M − UrΛrUrᵀ 来加权。表 5 显示两者高度重叠：单开 +1.87 dB 和 +1.73 dB，一起开只有 +2.33 dB。

    证据：本文表 5；§7 沙盒。

  12. 12中冷启动恰好伤在最要紧的第一块

    第一个 chunk 没有统计量，只能令 w = 1、关闭 PSAC。可这一块往往是 attention sink 或条件首帧：图 3 中 Matrix-Game-2 的 BF16 top-1 正好选中 Frame 0。而且第一块刚生成完时，它自己的 Query 已经可用，拿来用并不违反因果，"严格因果"的限制是自己加的。论文没有分析首块的误差。

    证据：附录 C.3；图 3。

  13. 13中RoPE 约定下的统计量没说清

    M 是用 pre-RoPE 还是 post-RoPE 的 Query 统计的？对于缓存 pre-RoPE Key 的模型，logit 误差是 qpostᵀRne，相关的二阶矩应当是旋转之后的。旋转会把每对 rotary 通道的敏感度混在一起，直接影响 w 和 Ur 是否对准。

    证据：附录 D.1 最后一句只说了重建之后怎么补 RoPE。

  14. 14中效率数字不完整，还有矛盾

    同为默认配置，Causal-Forcing 的时延在表 10 是 101.21 s，在表 11 是 135.08 s。QVG 和 KIVI 的时延没有报告；表 6 缺了 Matrix-Game-2 和 Causal-Forcing。LongCat 的 −17.8% 来自 KV offload，不是量化本身的加速。GPU 常驻时，每步都把整段历史重建成 BF16，内存流量反而比 BF16 更大。

    证据：本文表 6、10、11；附录 D.2。

  15. 15低VBench 的差异落在噪声里

    10 个"模型 × 分辨率"格子中，QuantWM 有 9 个 ≥ BF16；"一致高于 QVG"的最小差距只有 0.08 分。全文没有种子数，也没有方差。

    证据：本文表 3、表 7（我已逐格复算，均值都对）。

  16. 16低项目页有一个视频放错了，代码未公开

    Causal-Forcing 例 2 的"QVG"视频与 BF16 逐字节相同。论文说实现了定制 Triton 内核，但仓库里只有静态网页。

    证据：§9；github.com/quantwm-project/QuantWM。

  17. 17低引用和交叉引用错误

    引言把 Causal-Forcing 引成 Huang et al. 2026（那是 Self Forcing）；图 7(d) 图内写的是"Self-forcing"；LongCat-Video 被引成了 LongCat-Flash-Omni 技术报告（2511.00279）。附录 C.4 说"M in Eq. 9"、"Query-aware distance in Eq. 13"，应为 Eq. 6 和 Eq. 10；同一段里 top-m 和 top-M 混用。正文说"top-8 超过 60%"，图 4 标的是 71.14%。表 4 和表 5 的同一个数分别写成 0.6136 和 0.6137。"reduces the shift ratio up to 10.19%"里的 10.19% 其实是最小值。

    证据：本文 §1、§5.1、附录 C.4、图 4、图 7、表 4–5。

  18. 18低评测细节缺失

    每个模型生成了多少条视频、用了哪些种子、PSNR 是否包含条件首帧，都没有交代。项目页样例有 144–221 帧的，与正文"93 帧"的设置不同。表 9 的 ΔBit 与 r 严格线性，更像按公式算的，而不是在 D.1 的自适应稀疏布局下实测的。

    证据：本文 §5.1；§9；表 9。

  19. 19低目标函数层面的两处简化

    E[(qᵀe)²] 对所有 Key 等权，并且会惩罚"对所有 Key 相同的 logit 平移"，而 softmax 对这种平移并不敏感。它也没有利用注意力权重或 Value 的信息。另外，M 对全部历史等权累积，世界模型场景切换之后可能已经过时，论文没有 EMA 或窗口的消融。

    证据：本文 Eq. 6–7、16。

§11公道话、定位与最值得补的实验

公道话

QuantWM 抓住了一个真问题：在 2 bit 下，"Key 存得准"和"注意力算得准"是两回事。它用了一个很朴素的工具，把历史 Query 的二阶矩 M 当作"误差计价表"，同时指导"选质心"和"补误差"。这个工具免训练、严格在线、实现成本低，而且在 5 个模型、两种分辨率上的方向一致。我在项目页视频上的复测也表明，相比它所复现的 QVG，QuantWM 的帧间一致性确实好得多。如果作者能补上同 bit 对比、澄清 QVG 的复现问题，它会是一篇扎实的工程论文。

定位

工作针对的误差手段额外存储
KIVI / KVQuant（LLM）Key 的通道离群值Key 按通道量化，pre-RoPE无
GEAR（LLM）量化残差低秩 + 稀疏补偿有
SQuat（LLM）Query 子空间内的 logit 误差让量化误差与子空间正交无
QVG（视频）Key/Value 的动态范围k-means 质心 + 多级残差质心
Tuncer 2026（视频）Jensen bias（历史偷注意力）对每个 logit 减去 σ²/2无
QuantWM（视频）Query 加权的 logit 误差Query 感知的质心分配 + Query 主子空间补偿约 0.13–0.26 bit

最值得补的五个实验

  1. 同 bit 的 Pareto 曲线：QVG（1–4 级，组 16/32/64）、QVG-Pro、KIVI、QuantWM（r = 0…16）画在同一横轴"实测 bit/元素（含全部元数据）"上。
  2. 对齐 QVG 的复现：用 QVG 原文的配置（pre-RoPE Key、FP8 scale、同样的评测协议）重跑一遍，两种结果都报。
  3. 直接测闪烁：VBench 的 Temporal Flickering 和 Motion Smoothness、光流 warping error、FVD，再加一个小规模用户研究；同时报 BF16 在不同种子间的波动作为噪声底。
  4. 与 Tuncer 比较并叠加：报告注意力质量偏移 ΔPS，测"QVG + 偏置校正"和"QuantWM + 偏置校正"。
  5. QSAC 的解剖：不开 PSAC 时分别测第一、第二阶段；按剩余敏感度 M − UrΛrUrᵀ 加权；解释 M = 256 为什么变差；第一块改用它自身的 Query 统计。
