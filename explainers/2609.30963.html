Where & When to Force — Routed Forcing 精读

实时数字人（音频驱动、流式、每块 4 步的因果生成）在蒸馏时，DMD 会把手势、转头这类“可有可无”的动作压掉。Routed Forcing 借用 DFD（让教师看真实视频）把动作补回来，但只补给人物（非嘴）区域，而且只在高噪声的打分查询上补。嘴、背景，以及所有低噪声查询，仍然用原来的 DMD。

01它在解决什么，在谱系里的位置

流式数字人要同时做到两件事：一是实时，几十 FPS、首帧不到一秒；二是“活”，头会转、手会动、表情有变化。实时靠蒸馏：把多步的双向教师压成少步的因果学生，常用 Self Forcing + DMD。但 DMD 有个老毛病，学生会退到最“安全”的模式上，生成一张几乎不动、画质却很好的说话脸。

出发点 · DMD / Self Forcing

学生自己 rollout，教师在学生的样本上打分。DMD 优化的是反向 KL：学生跑出教师支撑集会被罚，漏掉教师的模式却不受罚。结果是动作少，不同 seed 生成的视频长得一样。

直接前身 · DFD（2606.18478）

只改一行：教师不再看学生的样本，改看同条件的真实视频。真实视频里有学生从没生成过的动作，于是能把多样性拉回来。原版做法是每步以 50% 概率在 DFD 和 DMD 之间随机切换，作用于整幅画面、所有噪声水平。

本文 · Routed Forcing

损失本身不动，改的是 DFD “用在哪儿、什么时候用”。空间上只用在人物非嘴区；噪声上只用在高噪声查询，即 t ≥ 0.832，恰好占全部查询的一半。嘴、背景和所有低噪声查询都交给 DMD。

同赛道怎么分

DynaForcing（2608.17707）改的是 rollout 的起点（从加噪真值出发），再加动态奖励；Reward Forcing 改的是梯度权重；DP-DMD 在第一步换成教师目标。这几种方法都对整幅画面用同一个目标，Routed Forcing 的新意是按像素、按查询噪声把目标拆开。它和你库里的 CrossDistill（2609.14725）看上去很像，都是高噪声和低噪声用不同目标，但两者切的不是同一根“噪声轴”，§5 会把两根轴画出来。

02先看懂两块积木：DMD 和 DFD 只差教师的输入

两者用的是同一个学生样本 xs、同一个 fake score、同一个教师，也加同一份噪声 ε。唯一的区别在于教师看的是哪段视频。

(2)gDMD(t) = wt [ x̂fake(zts, c, t) − x̂T(zts, c, t) ]
(3)gDFD(t) = wt [ x̂fake(zts, c, t) − x̂T(ztr, c, t) ]　　zts = αtxs + σtε，　ztr = αtxr + σtε（同一个 ε）

人话版：梯度是什么

x̂ 是去噪器对干净视频的估计。fake score 学的是“学生现在会生成什么”，教师学的是“真实数据长什么样”。两者的差 g，就是按教师的口味、这个样本应该往哪边挪。实际实现时，拿 xs − g 当伪目标，让学生去回归它。

DFD 的原始配方（2606.18478）

  • 必须从已经收敛的 DMD 检查点出发。从头训不收敛，原文把这个前提称为 validity condition。
  • 每一步以 50% 概率用 DFD，否则用 DMD。
  • 只训 100–300 步，属于“短后处理”。
  • 本文 Table 1 的 “DFD” 行就是这套配方（整幅画面）。Fig 4 的 “0.5 DMD + 0.5 DFD” 用的也是这套配方，但区域路由始终开着，所以只作用在人物区。
理解后文最关键的一个事实

每个条件只对应一段真实视频。条件 = 首帧 + 音频 + 文本，三样都取自同一段真实片段 xr。所以 DFD 不是在“真实分布”上采样，而是用这一条真实轨迹做监督。噪声低时，教师几乎能把 xr 看得一清二楚，DFD 就退化成“把学生的输出回归到 xr”。不同 seed 都被拉向同一个目标，平均下来就糊了。这是 §5 “When” 的出发点，对应附录的 Prop. 2。

03观察：塌缩按区域不同

作者用 OmniAvatar 当教师、LiveTalk（由 OmniAvatar 经 DMD 蒸馏而来）当学生，在 SpeakerVid 上取 100 组“首帧 + 音频”，每组跑 4 个 seed，分区域计算跨 seed 的平均成对距离：正文用 LPIPS，附录 Fig 7 用 L1。

作者的解释。对同一段语音，人物非嘴区可以有很多合理的动作，比如点头、转头、手势，所以教师在这里的多样性高，学生塌得也最狠。嘴被音频强约束，本来就没多少可塌。背景几乎就是首帧的复制，自然稳定。

换成附录的语言。一个区域能塌多少，取决于在给定条件下这个区域还剩多少不确定性，也就是条件方差 Σc。这和 §7 的“转移增益”是同一件事，所以这个观察和后面的理论是连贯的。

我复算 / 我的读法

人物区 −37.9% ✓。嘴 (0.0836 − 0.0750)/0.0836 = −10.3%，论文写 10.4%，差别来自四舍五入。L1 版本 −39.7% ✓，嘴 −14.9%（论文 14.8%）✓。

论文没交代的地方：这里的教师是 1.3B 还是 14B；区域掩码取自哪个 seed（手挥进背景时，那块算哪个区域？）；区域 LPIPS 是裁剪后计算还是按掩码平均。另外只有一对模型，没有误差条。详见存疑 M6。

04Where：按语义区域路由

用掩码把每个空间位置分进三类：嘴 Mm、人物非嘴 Mp、背景 Mb，三者相加为 1。只有 Mp 这一类用 DFD。

(4)g = Mp · ½ [ gDMD(t) + gDFD(t) ] + (1 − Mp) · gDMD(t)

这是只做区域路由时的期望梯度。人物区里仍按原版 DFD 的做法，以 50% 概率随机切换；其他区域全用 DMD。

我的读法：嘴被排除，更像是因为“对不齐”，而不是因为“嘴不需要多样性”

真实视频里的嘴形和音频完全同步，本该是最好的口型监督。可 IoU 只有 32.7%，意味着这份监督会被贴到学生脸上的错误位置。消融结果也支持这个读法：只做噪声路由时，DFD 仍作用在嘴上，但只在高噪声，Sync-C 只从 4.03 掉到 4.01；全局 DFD 则掉到 3.92。换句话说，口型的损伤主要来自低噪声的 DFD，区域路由在此之上只再改善了 0.06。论文还有几处没写：Mp 怎么由两种掩码组合；像素掩码怎么映射到 latent（空间压缩 8 倍，时间压缩 4 倍，一个 latent 帧覆盖 4 帧里移动的嘴）；掩码是软的还是硬的。

05When：按查询噪声路由

即使只在人物区用 DFD，低噪声的查询仍然会让手变糊。作者用 Eq. 5 解释：共享噪声 ε 在两者相减时抵消，于是学生样本和真实视频之间的距离，以噪声为单位来量，等于

(5)‖zts − ztr‖ / σt = √SNRt · ‖xs − xr‖，　SNRt = αt2 / σt2

高噪声（SNR 小）

在噪声底下两段视频差不多，教师只看得清粗粒度结构，比如手大致抬没抬、头朝哪边。这时 DFD 搬过来的是真实视频“大动作的方向”。

低噪声（SNR 大）

教师能把 xr 看得一清二楚，DFD 约等于回归到那一条真实轨迹。可那条轨迹里手的位置、头的角度都和学生的不同，结果就是糊和伪影。这一段应该交给 DMD，让学生沿自己的轨迹修细节。

(6)gNR-DFD(t) = { gDFD(t)，t ≥ τ（高噪声）；　gDMD(t)，t < τ（低噪声） }
(7)gRF = Mp · gNR-DFD(t) + (1 − Mp) · gDMD(t)

实现上，u ~ U(0,1)，查询噪声 t = 5u/(1+4u)，即 shift-5。“Top-50%”指 t ≥ 0.832，对应 u ≥ ½。0.832 对应 u ≈ 0.498，所以人物区约有一半（50.2%）的查询走 DFD，和原版“50% 随机混合”期望上的 DFD 用量几乎一样。这个预算是对齐的，因此 Fig 4 里两者的比较是公平的。论文没点明这一点，算是它做对的地方。

最容易看错的一点：这里的“噪声阶段”不是学生的采样步

互动：沿查询噪声轴走一遍

附录的 Prop. 1 在高斯情形下给了一个很好用的量，叫转移增益。沿条件协方差的第 i 个方向，DFD 比 DMD 多出来的那一项，等于

(10)ui⊤bt = hi(t) · ui⊤δ，　hi(t) = rtλi / (1 + rtλi)，　δ = xs − xr

bt 是 DFD 比 DMD 多出来的那一项，hi 是它在方向 ui 上的增益。论文只写了 SNRt = αt²/σt²；下面的互动里我按 Wan / OmniAvatar 的 rectified flow 假设 αt = 1−t、σt = t，即 rt = ((1−t)/t)²。这个换算是我的假设，论文没写。

λ 是这个方向在给定条件下的方差：动作方向大，细节方向小。拖动下面的查询噪声，看两类方向各被搬过来多少。

07附录 A 的理论：用人话讲四个命题

作者在理想化的设定下分析“查询噪声水平如何改变 DFD”。设定如下：固定条件 c；教师等于数据的后验均值去噪器，不带 CFG；fake 等于当前学生分布的后验均值；xr 被当作条件数据分布里的一个抽样，讨论的是总体层面的梯度。作者特别注明：训练集里每个条件只有一段真实视频，所以这些期望描述的是一个总体模型。

Prop. 1 · 高噪声：按协方差加权的修正

DFD − DMD = mT(zs) − mT(zr) = Atδ。其中 At ⪰ 0；rt → 0 时 At ≈ rtΣc。

人话：DFD 比 DMD 多出来的那一项，就是把学生与真实视频的差 δ 按教师在该条件下的方差加权后再拉回来。方差大的方向（动作）拉得多，方差为零的方向完全不拉。噪声极高时这一项消失，DFD 退化成 DMD。

Prop. 2 · 低噪声：退化成配对回归

E‖uDFD − (xs − xr)‖² ≤ 4d / rt，所以梯度 ≈ ∇ ½E‖Gθ(ξ,c) − xr‖² = ½E‖G − μc‖² + 常数。

人话：噪声低时，DFD 会把所有 seed都拉向同一个条件均值 μc。多样性变成零，画面发糊。这就是低噪声段必须交给 DMD 的数学理由。

Prop. 3 · 玩具：DFD 的不动点

教师有 1 个静态模式（权重 0.1）和 2 个动态模式；学生是两个 seed，被限制在“动作圆”上。在 r=0.1 时，DFD 把两个 seed 送到 β ± a*，也就是两种不同的动作。

Prop. 4 · 玩具：DMD 的不变盒

同样在 r=0.1，DMD 从静态附近出发就再也出不来：运动量 A 和 seed 差异 V 都 < 0.40，而动态模式的 A = 626。原因是在静态样本处查询时，教师看到的几乎只有静态模式，动态模式的权重只有 1.7×10⁻⁴。

A.4 的三段式结论：(i) r → 0 时 DFD ≈ DMD；(ii) 有限的高噪声下，DFD 带一个按协方差加权的修正，只搬动作、不搬细节；(iii) 低噪声下退化成配对回归，seed 直接照抄真实视频。NR-DFD 的设计就是只用 (ii)，把 (iii) 交给 DMD。

我复现了附录的全部数字

用 40 万样本的蒙特卡洛加 80 点 Gauss–Hermite 积分：τ = (24.9996, 0.5000, 0.0604)，论文 (24.9995, 0.5000, 0.0606)；a* = 1.0010，论文 1.001；A / V = 625.91 / 0.709，论文 625.90 / 0.709。r = 10 时 A = 625.99、V = 0.0007 ✓。Eq. 15：在静态处查询时动态模式的总权重为 1.73×10⁻⁴（2000 万样本），论文 1.7×10⁻⁴；在真实视频处查询时 x⁺ / x⁻ 的权重为 0.535 / 0.465 ✓。DMD 梯度流从 θ₀ 收敛到 (0.0055, 0.226, 0, 0)，论文 (0.0045, 0.227, 0, 0)。独立复核用精确积分加 ODE 求解，得到 (0.00449, 0.2275, 0, 0) 和 τ₃ = 0.0606，与论文完全一致；我的蒙特卡洛估计有少许偏差，论文是对的。

我的扩展：玩具里的多样性来自“圆”这个约束

把学生从“只能落在圆上”换成“可以输出任意点”，即两个 seed 为 m ± h，DFD 的总体梯度变为 g_m = m − τ、g_h = h·B(r‖h‖²)。不动点是 m = τ、h = 0：两个 seed 重合在圆内部的“平均动作”上，多样性为零，也就是“糊”。勾上上面的复选框就能看到。论文的 Prop. 3 里其实也能看出这一点：沿直线方向 ρ，DFD 同样把 seed 间距 v 压到 0（gv = v·B(κ)）。

这对真实系统意味着什么

DFD 在总体层面只是在匹配一个均值，即教师在加噪真实视频处的后验均值 τ。多样性要出现，前提是生成器没法输出这个均值（它在真实视频的流形之外）。在真实系统里，能扮演这个约束的只有低噪声段的 DMD，因为它会惩罚“平均出来的糊样本”。这恰好是 NR-DFD 必须把低噪声留给 DMD 的另一个理由，论文既没这样论证，也没检验。另外，DFD 原论文只证明了 E[Δ] = 0，这个期望没有 Jacobian 加权，因此并不能推出 pθ = pdata 是 DFD 梯度的不动点。这也解释了 DFD 为什么只能当 100–300 步的“短后处理”来用。

理论给不出具体的阈值

Prop. 1 的 Eq. 9 在任何噪声水平下都精确成立，高斯例子（Eq. 10）和“条件噪声窗口”（Eq. 11）也覆盖了有限的中间 SNR。所以理论并不缺中间段，缺的是具体数值：窗口的位置取决于 λ动作、λ细节，而这两个量在真实视频 latent 上是未知的。Prop. 2 的界 4d/r 也只在 r ≫ 4 / (每维 δ²) 时才有信息量；按每维 δ² ≈ 0.075 这个示意值，需要 r ≫ 53，即 t ≪ 0.12（按 rectified flow 换算），只占约 2.7% 的查询。因此阈值 0.832 是靠 Fig 4 的 3 点扫描（25 / 50 / 75%）选出来的。A.4 也写明“条件多样性在实践中能否提高，是经验问题”。另外，训练时教师用 CFG 4.5，理论里没有 CFG。

10存疑清单

按严重程度分三级：高 会动摇主结论；中 影响某张表或某个论断的可信度；低 表述、实现细节或引用问题。凡是从论文数字推算出来的，都标明是我算的。

H1“多样性 +7–25%”的参照点，是作者自己先削弱过的基线高

从 Fig 6 的矢量数据读出：LiveTalk（第 0 步）的 LPIPS 多样性为 7.72、L1 为 2.97；作者再训 1000 步 DMD 后降到 5.07 / 2.17；Table 1 的 Self Forcing 行（再训 200 步 DMD）是 4.96 / 2.14；RF 是 6.09 / 2.29。RF 从 SF-1000 起训，只补回了损失的 38% / 15%（若以 Table 1 的 SF 为参照则是 41% / 18%），仍比 LiveTalk 低 21% / 23%。这里有一个前提：Fig 6 和 Table 1 用的是同一套评测协议。两者都写的是 100 条 SpeakerVid、4 个 seed，而且 SF-1000 的 5.07 / 2.17 和 Table 1 SF 的 4.96 / 2.14 非常接近，支持这个前提。

正好是包含 LiveTalk 的 Table 2 没有多样性列。整条链路相对 LiveTalk 的净效果是：运动变强（RAFT 4.77 → 7.80），画质变好（FID 28.77 → 25.43），多样性变差。论文也没做“直接从 LiveTalk 起训 RF”的消融，无法判断那 1000 步 DMD 是必需的，还是反而有害。

H2没有教师参照；“DMD 压缩动态”在本文自己的主指标上并没有被直接证明高

作为 real score 的 OmniAvatar-14B，本应是“有动态”的那个上限，却没出现在任何一张表里。唯一的教师家族成员 OmniAvatar-1.3B（Table 2）RAFT 全表最低（2.27 / 1.76），比所有被说成“塌了”的学生都低。作者自己的 DMD 阶段（LiveTalk → SF）也让 RAFT 从 4.77 升到 5.62。所以没法判断 RF 的 7.80 是“恢复”了动态，还是“超调”成了抖动。能支持“教师更动态”的只有 Fig 1a 的定性帧，和一个教师规模未注明的区域 LPIPS。

H3效应量小，没有任何统计检验高

100 条视频 × 4 个 seed，每个变体只训一次，没有置信区间，也没有多次训练的 seed。口型差异很小：RF 相对 Self Forcing 只有 0.02–0.04，各方法之间最大也只有 0.16。“区域路由保护嘴”这个说法，依据是 Sync-D 10.94 对 11.02，相差 0.08。100 条片段算出来的 FVD 本身就很不稳定。Fig 4 里纯 DMD 的口型曲线没有趋势却来回跳 ±0.1（归一化单位），这个噪声幅度和很多被当作结论的差异是同一个量级。

M1只训 200 步；阈值和步数可能是在测试集上选的中

Top-75% 在第 125 步最好，50 步内就崩了；Top-50% 在第 200 步仍在全线上升，训练恰好停在这里。没有更长的训练证据。Fig 4 只写了“SpeakerVid 上的训练曲线”，没说用哪个评测集；如果用的是那 100 条测试视频，τ 和步数的选择就可能带有选择偏差。AVSpeech 可以部分充当留出集：那里 FID 的收益确实更小（−2.5% 对 −6.4%），但 FVD、RAFT、DINO-T 和四项多样性的收益反而更大，所以这条偏差目前只是一种可能，不能坐实。

M2玩具模型的多样性来自“圆”约束；DFD 的不动点并不是 pdata中

见 §7 的扩展：换成可以输出任意点的学生，DFD 的不动点就是两个 seed 重合在 τ，多样性为零且发糊。在论文自己的 Prop. 3 里，沿直线的 ρ 方向 v 也被压到 0。所以玩具只说明了“在流形约束下，DFD 会把 seed 分到不同动作上”。真实系统里这个约束靠什么提供（多半是低噪声的 DMD），论文没有讨论。DFD 原论文只证明了 E[Δ] = 0，不带 Jacobian 加权。

M3正文把两根“噪声轴”混着用中

§3.4 的动机句“高噪声阶段的去噪决定粗粒度轨迹”说的是采样轴，而路由实际作用在打分查询轴上。附录承认两者不同，并把这句直觉改写成“每个目标强调哪些变化”。读者如果拿它和 CrossDistill、Phased DMD 这类在采样轴上分段的方法对比，很容易误以为两者在做同一件事。

M4基线的复现可能没调好中

DynaForcing 原文是 14B（WanS2V / LiveAvatar）、4000 步，由三个组件组成，其中包括参考图扰动。本文完全没交代基线是怎么复现的：相关工作里对 DynaForcing 的描述只有“加噪真值起点 + 动态奖励”，基线训练步数也没写（只说同一初始化、数据和随机种子；200 步只对 RF 和 Table 3 明写），pdata、α 等超参都没报告；结果在 SpeakerVid 上 7/10 项、AVSpeech 上 9/10 项不如 Self Forcing，和原文结论相反。Reward Forcing 换成了 DynaForcing 的奖励。原版 DFD 有 100–300 步的先例，200 步对它算合理。

M5Table 2 的可比性问题中

四点：RF 在 SpeakerVid 上是域内训练；四组 FPS / 延迟数字和 LiveTalk 论文逐字相同，却没注明；OmniAvatar-1.3B 的分数和 LiveTalk 论文比明显异常（FID 比值 2.43，其他模型 1.18–1.39；Sync-C 3.16 → 0.99）；“规模可比”收了 14B 的 FantasyTalking，却没收 14B 的教师。

M6支撑“区域异质塌缩”的证据偏薄中

只有一对模型，100 × 4 个样本，没有误差条。教师是 1.3B 还是 14B 没写；如果是 14B，这里的差距里还混着模型容量的差距。区域掩码在不同 seed 之间怎么取、区域 LPIPS 怎么算也没写，而手挥进背景这种情况恰好就是人物区多样性的来源。背景的 “−1.4%” 发生在 0.0032 这个量级，已经在测量地板附近。

M7指标只奖励“动”，不惩罚“抖”；也没有人评中

RAFT 取光流最大的 5%，DINO-T 取相邻帧特征距离，两者都会被抖动、闪烁、身份漂移推高；成对多样性也会被伪影推高。论文没有 warping error 或平滑度、身份一致性（ArcFace）、手部质量这类指标，也没有用户研究。可论文的核心定性论据之一恰恰是“手更清楚”。

M8只测了 5 秒片段，“流式”没做长时验证中

81 帧只有 7 块。标题说的是流式数字人，可论文没有分钟级 rollout。LiveTalk 用 AHIS 维持分钟级身份，DynaForcing 测了 5 分钟以上。注入更多运动会不会在长时生成中累积漂移，这是实际部署最关心的问题，论文没有回答。

L1“嘴走 DMD”的理由与实际机制对不上低

论文的理由是嘴部塌缩轻、DFD 会破坏口型。但真实视频的嘴形恰恰是和音频同步的“正确答案”，问题其实出在对不齐：嘴部掩码的 IoU 只有 32.7%。消融也显示，口型损伤主要来自低噪声 DFD。如果把真实视频的嘴按关键点对齐到学生脸上再用 DFD，结论可能完全不同。

L2正文 Eq. 5 “在噪声里很接近”依赖尺度低

按 Wan2.1 VAE（空间 8 倍、时间 4 倍压缩、16 通道）估算，latent 维度 d = 64×64×21×16 ≈ 138 万，这一点论文没写。取示意值：30% 的维度有差异、每维 RMS 为 0.5，那么 ‖δ‖ ≈ 321。在 t = 0.832 时（按 rectified flow 换算），√SNR·‖δ‖ ≈ 65 个 σ，远大于 1，教师完全分得清两者；只是相对于噪声本身的范数（约 1173σ），它只占 5.5%。决定后验的是每个方向上的 rλ，所以附录 Prop. 1 的逐方向表述才是准确的，正文的直觉说法有误导性。

L3理论给不出 τ 的数值，只能靠 3 点扫描；训练用了 CFG，理论里没有低

见 §7 末尾。Prop. 1 和 Eq. 10/11 在有限 SNR 下都成立，理论本身不缺中间段；缺的是 λ 的数值，因此给不出 τ 的具体值，0.832 只能靠 3 点扫描。作者在 A.4 也把“多样性能否提高”列为经验问题，所以这是局限，不算错误。

L4实现细节缺失，也没有代码低

缺失的有：像素掩码如何映射到 latent（空间 8 倍、时间 4 倍压缩），掩码是软是硬；Mp 的组合方式；wt 在 DFD 分支里怎么归一化；拼接目标在掩码边界处的接缝怎么处理；高噪声时教师前向翻倍带来的额外开销；GPU 型号；各基线的超参。

L5引用：用自引凑数，同时漏引相关工作低

“Diffusion model distillation” 那一段在 “multi-step diffusion models” 后面，和 Ho et al. 2020 并列引用了 Tan 2026a/b、Su 2026a/b。这四篇都是作者自己的论文，内容分别是 RL 微调、熵约束、视频水印、统一多模态理解，和蒸馏无关。Safe-Sora 标成 NeurIPS 38 / 2026，年份也对不上。漏引的有：Phased DMD（2510.27684，按 SNR 分段做 DMD，附录还专门讨论“高噪声查询对 DMD 至关重要”）和 TDM（不相交的 SNR 区间）。CrossDistill 是同期工作，没引可以理解。

11结论、做对的地方、对世界模型方向的启示

做对的地方

  • 受控对比做得干净：同一初始化、同一数据、同一随机种子。
  • Top-50% 和“50% 随机混合”的 DFD 用量是对齐的，所以 Fig 4 的比较公平。
  • 阈值写明了在哪根轴上（shift-5 之后的 t，对应 u 的分位数），比 CrossDistill 清楚。
  • 嘴部掩码来源做了消融，还报告了耗时。
  • 附录的理论很诚实：写明是理想化设定、承认是经验问题，玩具的每个数都能复现。
  • 只改训练，推理零开销，改动很小。

对交互式世界模型的启示

  • Self Forcing 系的流式世界模型有同样的 DMD 塌缩问题。“可交互 / 受动作影响的区域”对“静态远景”天然适合做区域路由。
  • 交互日志本身就提供“条件匹配的真实轨迹”，但每个条件只有一条。低噪声段的真实监督等于 teacher forcing 回归，结果是平均化、发糊，所以只在高噪声查询上用。
  • 采样轴（CrossDistill：先分岔再精修）、查询轴（本文）、空间轴（本文），是三个相互正交的旋钮，可以叠加。
  • 评估多样性一定要对照蒸馏前的起点和教师，否则“提升”可能只是在修补自己造成的损失。

最值得补的后续实验

  1. 在 Table 1 / 2 里补上 OmniAvatar-14B 和 LiveTalk 的多样性、动态两行；做“直接从 LiveTalk 起训 RF”。
  2. 跑 3 个训练 seed，加 bootstrap 置信区间；把 Top-50% 训到 1000 步，看会不会后崩。
  3. 加抖动、身份、手部质量指标，再做一个小规模人评。
  4. 做分钟级流式 rollout。
  5. 对齐实验：把真实视频的嘴对齐到学生脸上后再对嘴用 DFD。
  6. 把区域路由搬到 T2V 或世界模型上验证。
