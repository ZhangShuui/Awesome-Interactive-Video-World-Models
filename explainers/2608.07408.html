一页读懂

一个比喻先把全文说完。把 KV cache 当成一间图书馆：自回归视频世界模型每生成一段画面，就把这段的 Key/Value 上架， 以后再生成时靠 attention 去「查书」。问题出在索书号上 —— 这个模型只学过「距今 0 到 5 格」这几个索书号怎么读。 rollout 一长，老书的索书号变成了 30、100、300，书还在架子上，但目录里没有这些号，查不到。

WorldTrace 做的两件事，也可以用这个比喻讲：

① 重新编号（Slot Indexing）

把远处的历史压成固定的 Ns 个「摘要槽位」， 每个槽位永久占用一个目录里有的号：第 s 号槽永远挂在「距今 Lattn−1−s 格」。 rollout 多长都不变，而且槽和槽之间号不重复。

② 换个空间写摘要（canonical 域）

要把几本书合订成一本摘要，不能直接把「已经盖了不同邮戳的页面」叠在一起 —— 邮戳（RoPE 旋转）方向不同会互相抵消。 得先把每页的邮戳撕掉、对齐、再合订，读的时候才盖上新邮戳。

「写什么进槽位」有两种选择，对应两种需求：

WorldTrace-Field ｜ 要连贯

把离开近期窗口的历史按时间切成 Ns 段，每段在 canonical 空间取均值写进一个槽。 画面不会突然变成另一个世界。代价：细节被抹平。

WorldTrace-Landmark ｜ 要认得回来

检测「场景切换」的那一帧，把它的 canonical Key 原封不动冻结进一个槽。 绕一大圈回到原地时能还原原来的样子。代价：最多只能记住 Ns 个地方。

位置，而不是内容，是长程记忆的瓶颈。证据是 Tab.1 那组控制实验：压缩方式完全固定不变，只换位置分配方案， TempSSIM 就从 0.377 / 0.390 变到 0.413（N=8）。更狠的是 Tab.4 里那一行 —— 「canonical 均值 + Block-relative 位置」的四个 PAC 数字和滑动窗口一模一样（0.540 / 0.412 / 0.504 / 0.631）， 因为位置被截断后摘要槽拿到的 softmax 权重是 0，压缩等于白做。

④ TempSSIM 衡量的是「相邻帧有多像」，画面越静、越糊越容易得高分，它不锚定到真实场景。
⑤ 最难的 360° 全景 pan 上，增益几乎消失（0.559 → 0.577）。

01

病因 A：位置决定「读不读得到」

自回归视频世界模型（Matrix-Game-2、Oasis、Genie 这一类）是一段一段（chunk）生成的：每生成一段， 就把这段的 Key/Value 追加进 KV cache；下一段去 attend 这个 cache。所以「记忆」在物理上就是 cache 里那些 K/V。

关键是训练时模型只见过有界的相对偏移。设 q 是当前 query 帧的绝对位置、k 是某个 cache 里 key 帧的位置：

0 ≤ δq,k = q − k ≤ Δttrain MG2：Δt_train = 5，L_attn = 6 latent frame

时间维 RoPE 对注意力分数的贡献是一个旋转：

afq,k = Re( Afq,k · e i θf δq,k ) A 是「内容」，e^{iθδ} 是「位置」 内容项 Afq,k 是 query 与 key 在 canonical 坐标下的内积，与位置无关；位置全部藏在那个旋转角 θf δq,k 里。

推理时 δq,k 无界地涨。旋转角一旦超出训练见过的范围，这个频率分量就开始胡说。 而且这件事是分频率发生的 —— MG2 继承 Wan 2.1 的 3D RoPE，每个头 128 维里 2ct=44 维给时间（22 个复数对）、 高和宽各 42 维，base θ=10000，第 f 个时间频率是 θf = 10000−f/22， 从 θ0=1.0（转最快）一路降到 θ21≈1.5×10−4（几乎不转）。

下面这张图是全文的病理切片，横轴是频率序号，纵轴是推理时的 query–key 距离，颜色是相位 θf|δ| 落在哪个区间（鼠标悬停看具体弧度）：

< π/8：几乎不受位置影响，是纯语义载体 π/8 – π：位置信号正常 π – 3π：出分布，模型没学过 > 3π：相位绕了多圈，等于随机噪声
按论文 Fig.7 的口径重算（θ_f = 10000^(−f/22)）。虚线是训练见过的最大偏移 Δt_train=5。 论文原文给的两个校验点：δ=5 时 f≥10 的相位 < 0.08 rad（本图算得 0.076）；δ=30 时 f≤2 全部超过 3π，f=3 为 8.5 rad、f=5 为 3.7 rad —— 与本图一致。

这张图说明了三件事，都很重要：

  1. 坏的只有「转得快」的那几个频率。右侧一大片（f≥10）在任何距离下相位都极小，它们本来就不编码位置，是语义载体，长程下依然可靠。
  2. 坏得很快。δ 从 5 涨到 12，f=0 就已经进了噪声区；δ=30 时前 3 个频率全废。而 rollout 到 N=48 chunk（每 chunk 3 latent frame）时，最老的帧距今超过 140 格。
  3. 不稳定性是「相邻偏移之间跳变」。f=0 的 θ=1.0，key 往后挪一格相位就变 1 弧度，贡献可以直接变号。所以不是「缓慢衰减」，是「读数抖动」。
这条推理链里有一个隐含假设，值得记住

「相位 > 3π 就等于随机噪声」是一个启发式阈值，论文没有直接测量「这些分量对 attention 的实际破坏量」， 只是从波长与上下文长度的关系（沿用 YaRN 的 NTK-by-parts 框架）推出来的。真正的实验证据是间接的 —— 把位置换掉，指标就变好。

02

病因 B：压缩方式决定「读到的东西还在不在」

既然 cache 不能无限长，自然想法是把远处的历史压成固定几个槽。最常见的压法是求平均。 但 cache 里存的 Key 已经被 RoPE 转过了，直接平均的是一堆「已旋转」的向量：

K fnaive = (1/M) Σm=1..M R(θf tm) Kfm 每一项被转了不同的角度

每个源帧的时间戳 tm 不同，旋转角 θf tm 就不同。 时间戳挨得近时角度接近，平均没什么损失；时间戳差得远时角度可能几乎相反，相加互相抵消 —— 这个频率的信息被抹掉，跟它原本编码了什么无关。这就是「相位相消（phase cancellation）」。

用论文的真实参数算的一个具体例子：f=1（θ₁≈0.658），4 个源帧取 t=2 / 9 / 17 / 25。 假设它们的 canonical 内容方向一致（只看旋转造成的损失），左边直接平均后模长只剩 0.31；右边先回 canonical 再平均，模长保住 ≈1.00，位置在读的时候才补上。

论文给的实测证据是 Tab.5：位置方案固定住不动，只换压缩空间，看 LatentDiff（越低越好）：

注意这里的趋势比绝对值更有说服力：naive 的误差随槽数单调变差（0.257 → 0.312）， 因为槽越多、每槽跨的时间戳越杂、相位越乱；canonical 那一列没有这个趋势。这正好是相消假说预测的样子。

两个病因是耦合的，这是全文的立论方式

论文特别强调：以往工作大多只治一个。

  • 只管位置：∞-RoPE 的 Block-relative 把每个 cache 帧相对当前 chunk 重新编号，保证 δ 永远在训练范围内 —— 但它的目标是无限长视频，不是压缩。
  • 只管内容：H₂O / SnapKV / PyramidKV 决定丢谁，Token Merging / Compressive Transformer 决定怎么合，MemRoPE 用双速率 EMA 平滑。

耦合点：位置对了但压缩把信号抵消掉了没用；内容对了但槽位落在出分布的偏移上也没用。 更微妙的一层是 —— 「在什么偏移分布下压的」和「在什么偏移下被查的」必须一致， 否则 §04 里那个「均值保持注意力分数」的保证就失效了。

03

解法骨架：近期窗口 + 摘要槽位 + 按槽序号定死的虚拟位置

把本来的局部注意力窗口 Lattn 一切两半：

Ns + Nr = Lattn MG2 上 L_attn = 6，实验用 4+2 或 2+4 ℛ（recent window）：最近 Nr 个 latent frame，原样存。 　𝒮（summary cache）：Ns 个槽，每槽占一个 latent frame 的位置，装被压过的远期历史。
对应论文 Fig.2 上半部分。要点在最后一行：无论 rollout 走到 N=16 还是 N=512，模型读到的偏移集合永远是 {0,1,2,3,4,5}， 变的只是「每个槽里装了多长的历史」。

04

为什么槽位里必须存 canonical Key（去旋转的裸内容）

这是「位置」和「内容」两条线的交汇点，逻辑很干脆：

槽位的虚拟位置 tvs 由槽序号决定，跟槽里那些源帧的原始时间戳 {tm} 没有任何关系。 所以想把内容放到 tvs 上，就必须先撕掉每个 Key 身上原来的旋转，再补上目标位置的旋转。 在旋转域里压缩会同时踩两个坑：

  1. 相消（§02）：不同旋转的向量相加会互相抵消。
  2. 相位残留：即使不相消，压出来的 Key 身上带的还是「源时间戳的相位」，而不是 tvs 的相位 —— 等于贴错了门牌号。
canonical Key：　Kfm = R(−θf tm) Kftm 存的是「纯内容」，位置在读的时候才加 注意：只有 Key 带 RoPE，Value 不转。所以 Value 侧就是普通的取均值（Field）或原样复制（Landmark）。

这样一来，「内容」和「位置」在表示上被彻底解耦：槽里存的是与位置无关的内容，槽的时间身份 100% 来自它的虚拟位置。 论文用一个命题把这件事的价值说清楚：

Prop.2　均值保持注意力分数（mean attention preservation）
⟨ Qfq , Kffield(tv) ⟩ = (1/M) Σm ⟨ Qfq , R(θf tv) Kfm ⟩

一个摘要槽代表了 M 个源帧，那么 query 看它得到的分数，应该等于「把这 M 个源帧都搬到 tv 上、逐个打分再取平均」。 canonical 均值精确满足这一点（证明只用了旋转的线性性）；旋转域平均则没有任何这样的保证，相消会把分数压低， 让模型系统性地忽略远期历史。

但这个保证的边界要看清

① 它只对 softmax 之前的分数成立。softmax 之后每个权重都依赖其它所有 key，保证不传递过去。
② 它的参照是一个反事实：「如果这 M 个源帧都被搬到 tv」。它不保证等于「这些帧在原本位置上本来会得到的分数」。 那个差距被论文单独称为 repositioning error，而且明确说了没有给出解析上界，只用 Tab.1 的位置消融间接测量。
③ 有一个副作用被故意留着：M 个互不相关的 canonical Key 取平均，模长约缩到 1/√M，所以摘要槽进 softmax 时 logit 天然偏小。 论文说这是好事（相当于自动给被高度压缩的历史打个折，让 verbatim 的近期窗口更响），并且试过乘 √M 补回来，长程下没用。

05

写法一：WorldTrace-Field —— canonical 均值，为「连贯」服务

骨架搭好之后，剩下的唯一自由度是「往槽里写什么」。Field 的选择是：把离开近期窗口的 T−Nr 帧 按时间顺序均分成 Ns 段（最老的一段进 s0），每段在 canonical 空间取平均。

Kffield(tv) = R(θf tv) · (1/M) Σm=1..M R(−θf tm) Kftm Def.2　Eq.3 读法：先撕（内层 R(−θtm)）→ 再平均 → 再贴（外层 R(θtv)）。 M 不是超参，它由分段决定：M ≈ T / Ns，随 rollout 线性变长。

两种 writer：recompute 和 streaming

recompute writer（论文主实验）

保留所有被挤出帧的 canonical Key（在 host 内存，不占显存，每 latent frame +5.4 MB）， 边界一动就重算受影响的槽均值。

代价：host 侧状态是 O(N) 的。显存峰值和滑动窗口完全相同。

streaming writer（附录 E.7）

每槽只维护一个running sum + count，帧折进去一次就丢掉；边界移动时把相邻 bucket 精确合并。 writer 状态是 O(Ns)，与 rollout 长度无关。

代价：TempSSIM 略降（N=32：0.613→0.606；N=48：0.545→0.538），但 N=32 的 Scene Drift 反而最低（0.0223）。

这两个 writer 的对比其实还有一层方法论意义：streaming writer不在 cache 外保留任何历史， 它仍然显著好于滑动窗口 —— 这就把「槽序号位置的贡献」和「recompute 顺手多留了统计量的贡献」分离开了。

连贯性结果（Tab.2，开放式轨迹，不是回环）

N=32 时 Field 的 TempSSIM 最高（0.613 vs 0.571），但 Scene Drift 反而是四者里最差的（0.0250）； N=48 时两项都最好（0.545 / 0.0295）。论文自己也点出 Centroid-linear「在不同 horizon 上排名不一致」。
对 Field 要有的现实预期

Field 的作用是「让画面不要漂走」，不是「让你能认出回到了哪」。Tab.10 的召回测试里它几乎没有优势： N=16 时 PAC 0.555，滑动窗口 0.540，而 naive 平均是 0.570 —— 比它高。 论文对此的解释是，naive 那一栏用的是 Block-relative 位置，本身就不反映可寻址性，两者都处在 0.4–0.6 的「压缩档」， 距离锚定档和 verbatim 档（0.95+）差一个量级。换句话说：Field 解决的是连贯，Landmark 解决的是召回，两者不能互相替代。

06

写法二：WorldTrace-Landmark —— 冻结的场景入口，为「召回」服务

如果 query 想要的不是「一段历史的大致氛围」，而是「某个具体地点长什么样」，取均值就是错的方向。 Landmark 的选择是：把 Ns 个槽拿来原样存几帧高价值的过去帧。

怎么挑那几帧：场景入口检测

检测器极其轻量 —— 就是在 canonical Key 表示上算相邻帧的余弦距离，超过阈值 τ 就判为一次「场景入口事件」：

曲线为示意；检测规则来自论文 §3.4 与 Alg.1。这里也暴露了方法最硬的一个上限：一次 rollout 最多可靠重访 Ns 个不同地点。

为什么要「冻结」：躲开反复转来转去的数值漂移

槽是从老到新排的（s=0 最老），所以每来一个 chunk，每个缓存条目都往老的那头挪一格。 如果按常规摘要更新方式，每挪一格就要「撕掉旧旋转 → 贴上新旋转」一次。挪几十次之后， 这些 unrotate/rerotate 循环累积浮点误差 —— 在 bfloat16 下尤其明显（Wang et al. 2025 专门论证过 bf16 会破坏长上下文的 RoPE）。

Kfland(tvs) = R(θf tvs) · R(−θf tℓ*) Kftℓ* Eq.4 下划线部分 = 在成为 landmark 的那一刻算一次，之后永久复用。 每次槽位左移只施加一次全新的外层旋转，不做第二次撕贴。形式上它就是 Eq.3 在 M=1、不做平均时的特例。

和相关工作的界线论文划得挺清楚：canonical 缓存这个机制 MemRoPE 也用（存 pre-RoPE 的 Key，读的时候再转）； Landmark Attention 也叫 landmark。WorldTrace-Landmark 的差别在于三点叠加： ① 只在检测到的场景入口上用，不是对每个 cache Key 都用； ② 存的是 verbatim 帧级 Key（不是训练出来的代表 token，也不是 EMA 平滑值）； ③ 配上槽序号位置，所以任意 horizon 下每个 landmark 都占一个不同的在分布位置。

统一视角：把 cache 压缩看成一个投影矩阵 P

这一节是论文的理论骨架，也是把两个 variant 收进一个框架的地方。想法是：用固定 L 个槽去逼近对全部 T 帧的完整注意力。 定义 P ∈ ℝL×T（行随机，每行是历史帧上的一个分布），第 i 个槽的压缩 Key 就是 PiK：

压缩后的 cache 和「无限长 cache」的差距被拆成两块：

放松之后就是 NMF，而两个 variant 分别对应 k-means 和 k-medoids

把 α̂ 从 softmax 里解耦成自由变量，目标变成 minB,P≥0 ‖BP − A‖1 —— 这是带 ℓ₁ 保真项的非负矩阵分解。在这个视角下：

  • Field 的均匀分段行 = 用簇均值做原型的 k-means 的 ℓ₁ 版本，只是「时间顺序分段」替代了学出来的分配步骤。
  • Landmark 的 0/1 行 = 在注意力分布上做 k-medoids，而 canonical Key 余弦距离规则是它的一个 O(1) 单遍近似。
一个很干净的不可能性结果，值得单独记住

L 行、每行是 T 帧上的分布 → 总权重 L 摊到 T 列上 → 某一帧至多拿到 maxi Pi,t ≤ L/T。 于是任何一个「只想看某一帧」的 query，错配都不小于 2(1 − L/T)。
推论：压缩比一旦拉大，就不存在「通用最优」的压缩方式，只能选择保留什么。 这就是为什么论文不去找一个更好的单一 writer，而是定义了两个目标 query 家族，各配一个 writer：

  • ε-coherent（Eq.6）：query 只关心「哪一段历史」，不关心段内是哪一帧 → Field 的误差 ≤ Σ εq，接近最优。
  • δ-covered（Eq.8）：query 集中在某一个具体的过去帧上 → Landmark 的误差 ≤ Σ δq，接近最优。

但要注意：这两条是「按定义成立」的条件性刻画，不是无条件最优性。 论文明确说没有在预训练模型上测量 ε 或 δ —— 因为要测就得跑超出训练 horizon 的未压缩 rollout，而那时参照物本身就坏了。

八条打折读法

下面这些不是「论文有问题」，而是读这篇论文时容易读多的地方。前四条是我从表格里对出来的，后四条论文自己不同程度地承认了。

① 同一个基线数字，全文出现了三个版本 —— 不要跨表比

「滑动窗口在 ABA / N=16 上的 PAC」：Tab.3 是 0.723（n=100 个不同初始场景）、 Tab.10 是 0.540、Tab.8 是 0.837（明确写了「固定 seed」）。 TempSSIM 同样如此：同一个「滑动窗口 / N=16」在 Tab.3 是 0.761、Tab.8 是 0.754、Tab.4 是 0.9945。 这个跨度比论文报告的很多增益还大。同表内的对比是可信的，跨表拼数字一定会得出错误结论。

② 两个头条数字都是「相对增益」

+15.5% ← TempSSIM 0.472 → 0.545（Tab.2, N=48）；+19.5% ← PAC 0.723 → 0.864（Tab.3, ABA N=16）。 绝对提升分别是 0.073 和 0.141。摘要里写「improves temporal consistency by +15.5%」不算错，但读者容易理解成绝对值。

③ Tab.4 那个消融表实际上是「反面证据」，而且 Field 在里面几乎没赢

「Field 平均 + Block-relative」那一行的四个 PAC 和滑动窗口逐位相同（0.540 / 0.412 / 0.504 / 0.631）—— 这正是论文想证明的（位置一塌，压缩等于没做）。但同一张表里 naive 平均在 N=16 上 0.570，高于 Field 的 0.555， 而 Field 相对滑动窗口只多 +0.015。Field 对召回的贡献接近于零，它的价值只在 §05 的连贯性指标上。

④ Tab.8 里 Field 在 N=48 上输给了基线

Tab.8（ABA 重访、固定 seed）：4F+0L 的 TempSSIM 在 N=48 是 0.767，滑动窗口 0.776。 而 Tab.2（开放式轨迹）里 Field 在 N=48 是 0.545 vs 0.472，大胜。协议不同，方向相反。 另外 Tab.8 的中间配比（3F+1L / 2F+2L / 1F+3L）非单调，有几个还低于基线 —— 论文自己的结论是「收益来自把槽位专门拿去做 landmark，不来自任何特定混配」，这个说法是诚实的。

⑤ 「O(1) 记忆」说的是显存 cache，不是总状态

Field 的 recompute writer 把每个被挤出帧的 canonical Key 留在 host 内存， 每 latent frame +5.4 MB —— 这一部分是 O(N) 的。N=512、每 chunk 3 帧 → 约 8 GB 主机内存。 真正 O(1) 的是附录 E.7 的 streaming writer（代价是 TempSSIM 掉 0.007 左右）。Landmark 本身确实是 O(1)。

⑥ Landmark 有一个硬上限：最多 Ns 个地点

槽满之后淘汰最老的。实验用 Ns=4，也就是一次 rollout 最多可靠重访 4 个不同场景。 而且能不能召回完全取决于检测器有没有在对的那一帧触发 —— 阈值 τ 是个超参，论文没给敏感性分析。 §06 那个「Ns=3 → 4 的悬崖」正是这个上限的直接体现。

⑦ 连贯性的两个指标都奖励「不变化」

TempSSIM = 相邻解码帧的 SSIM；Scene Drift = 到上一个 chunk 的 CLIP 距离。 两者都不锚定到真实场景，越静、越糊分越高。而 Field 的已知副作用恰好是「blur specific scene details」。 所以 Field 那 +15.5% 里有多少是「真的更连贯」、多少是「更平滑了」，这两个指标区分不出来。 相比之下 Landmark 的 PAC 增益更硬 —— 它靠 verbatim 复制拿分，而不是靠让画面变静。

⑧ 整个故事是在一个训练窗口极短的模型上讲的

MG2 的 Δttrain = 5 个 latent frame（局部注意力窗口 6）。这是个非常紧的窗口 —— 所以「δ 很快跑出分布」这件事在它身上格外突出。 换到窗口长得多的基座上，位置 OOD 是否还是首要瓶颈，论文没有建立。 LingBot-World（14B）那组结果是个提示：Field 在那儿基本是平的，Landmark 在 2× 也没有增益。 另外，论文没有和 Matrix-Game-3 比（理由充分：MG3 把记忆训进了生成器，没有可改 cache 的固定 checkpoint）， 也没有和外部记忆库/检索类方法（WorldMem、VMem 这一路）做数值比较。

论文自己给的定位是：据其所知，还没有工作同时做到「让任意多个压缩槽在任意 horizon 下保持互不相同」 ＋「在 canonical（pre-RoPE）域里写摘要」。前者 MemRoPE 做不到（它只有 2 个 EMA 流，所以天然不撞车）， 后者 Block-relative 一系不做。WorldTrace 的新意主要在这个「配对」上，两个零件各自都不算新。

三条最有价值的外推

  1. 「记忆」这个词在世界模型里应该拆成两个问题。不是「怎么记更多」，而是 （a）怎么让存下来的东西保持可寻址；（b）该为将来的什么 query 存什么样的痕迹。 这个拆法比任何具体的 writer 都更耐用。
  2. 位置编码的外推问题，在「压缩」场景下变成了一个新问题。 所有 RoPE 外推工作（PI / YaRN / LongRoPE / RIFLEx）都是给单独保留的 token 重映射位置。 但一个「合并了好几帧」的摘要该占什么位置？token 保持独立身份时这个问题根本不存在。这是论文最原创的一问。
  3. 写入域和读取域必须一致（§3.5，也被 Tab.9 里 MemRoPE+WorldTrace 的退化实测到）。 这条对任何做 KV 压缩的人都是硬约束：别把别人的位置方案和别人的内容写法自由拼装。

论文自己列的未来方向里，两条最实在

几何感知的 canonical Key

把「撕旋转 / 贴旋转」这个原语和相机位姿 warping（MosaicMem 的 Plücker、UCM 的 Warped-RoPE）耦合起来， 先把帧对齐到统一场景坐标系再平均 —— 这样一个摘要 token 混的就是同一块场景内容的多次观测，而不是不同地方的画面。

用重访结果反过来训记忆策略

「回去时有没有还原出原来的场景」是可直接测量的，所以它天然是免费的监督信号 —— 可以做 SFT，也可以直接把 revisit 分数当 reward 做 RL。骨干冻结，只训 cache 上那个轻量策略（存什么、压什么、淘汰谁）。

一句话收尾

WorldTrace 真正贡献的不是那两个 writer（一个是均值，一个是原样存），而是那个 6 个字的诊断： 长程失忆是寻址问题。一旦接受这个诊断，「给每个压缩槽发一个训练分布内的、按序号定死的门牌号」 就成了几乎不可避免的解法 —— 而它恰好不需要训练、不需要显存、不需要改架构。 从工程角度，这是一个可以在既有 checkpoint 上当天试出来的改动； 从研究角度，它把「记忆」这个模糊的词换成了两个可以分别攻的具体问题。
