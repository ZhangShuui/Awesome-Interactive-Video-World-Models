CoRe — 让潜空间奖励"跟着生成器走" · 精读

潜空间奖励模型（LRM）直接给视频扩散模型的中间噪声潜变量打分，不用把潜变量解码成视频，对齐成本低很多。作者发现：拿一个训好就冻住的 LRM 去优化 Wan2.1-1.3B，几十到几百步之内奖励一路涨，画面却越来越糊、越来越不动。他们管这叫潜空间奖励破解，病因归为分布逃逸：生成器跑出了奖励模型见过的数据范围。CoRe 的解法是：生成器每走 1 步，就拿它当前的样本把奖励头重新拟合 10 步。拟合时生成样本当"输家"，偏好视频当"赢家"，另加一项"好视频赢差视频"的排序。生成器则只追到与同一提示的偏好视频同分为止，外加一个特征核锚点和一个流匹配锚点。论文报告的结果：VBench 83.96→84.92，VBench-2.0 56.3→58.03，全程约 8 GPU·h。

  1. 现象可信，病因的证据有混淆。无锚点时奖励约 20 步饱和到 0.95；有锚点时 1000 步内 dynamic degree 从 68 掉到 28。Table 1 里 sreal / sgen / spread 这套监控也值得照搬。但有两件事没排除。第一，"真视频"来自 VideoDPO 偏好对，而 VideoDPO 的做法是用模型自己生成视频、再按 VBench 类指标挑出最好和最差的，这些都不是实拍视频。step 0 时奖励模型就已经给 Wan 的样本更高的分（0.666 对 0.551）。第二，奖励和生成器共用 DiT 主干，生成器的梯度可以直接改写奖励读的特征。
  2. 方法等价于一个潜空间 relativistic GAN，再加对参考视频的回归。奖励头就是判别器："x⁺ 胜过生成样本"这一项 BT 就是 RpGAN 的判别器损失；相对 hinge 是真样本做了 stop-grad 的生成器损失；核锚点是逐样本的 feature matching；再加一项 SFT。论文没有讨论 GAN、LADD 或 DMD2 的 GAN 头。这类目标的平衡点是 pgen = px⁺，所以参考视频的质量就是天花板。§6.4 自己也写了：训练末期奖励头几乎分不开真假（两边的 sigmoid 都在 0.55 左右，44% 的生成器步 hinge 为 0）。所以拉动生成器的主要力量，很可能是 λfm=1.5 的 SFT 和核锚点。可论文没有做只用 SFT 的对照。
  3. 数表有三处对不上，而且都落在结论上。(i) Table 2 里 CoRe 的 Total 写 84.92，按 VBench 公式 (4Q+S)/5 算出来是 84.76，低于 SIPO 的 84.79，"全表最高"不成立；巧的是，84.92 正好是同表 Wan 的 Quality 分。(ii) Table 3 的 CoRe 行（DD 86.72、AQ 64.47、BC 98.21，均值 84.05）和附录"全部 run"的 Table 7 对不上。按 Table 7，CoRe 的 6 维均值是 81.0 / 81.4，和预训练的 81.4 持平；6 维里有 5 维低于预训练，也低于它自己的起点 83.6。正文 §6.3、§6.4 引用的数字和 Table 7 一致，不和 Table 3 一致。(iii) Table 2 的基线拼自 4 篇论文。SIPO 和 Self Forcing 自己测的 Wan 是 84.26，表里的 Wan 却用了官方榜单的 83.96。

01它在解决什么

视频扩散模型的偏好对齐通常分两步：先训一个奖励模型，再让生成器去"刷分"。像素空间的奖励要把潜变量解码成视频，很贵。PRFL 等工作换成了潜空间奖励模型：直接拿视频生成模型自己的前几层 DiT 做特征提取器，给任意噪声水平的中间潜变量打分，生成器只需要在最后一步去噪处反传梯度。这样确实便宜，但作者发现它极易被刷：奖励几十步就饱和，视频却糊了、也不动了。

问题（论文的说法）

固定的 LRM 会被很快"破解"。根因是分布逃逸：生成器几百步内就离开奖励模型训练数据的覆盖范围，落进一块奖励模型从没被监督过、却一律给高分的区域。

改法

不冻结奖励模型。生成器每走 1 步，奖励头就用生成器的最新样本重新拟合 10 步。拟合时生成样本当"输家"，偏好视频 x⁺ 当"赢家"，再加一项"x⁺ 赢 x⁻"。生成器那边只追到与 x⁺ 同分为止，外加核锚点和流匹配锚点。

证据（论文报告）

Wan2.1-T2V-1.3B 上：VBench 83.96→84.92，VBench-2.0 56.3→58.03（其中 controllability 33.8→38.29）。消融中，固定奖励和"朴素在线奖励"都会崩，CoRe 到 step 600 没崩。训练约 8 GPU·h。

02潜空间奖励模型：人话版

CoRe 的对照基线和基本设定都来自 PRFL（Mi et al., CVPR 2026，Video Generation Models Are Good Latent Reward Models）。先把它讲清楚。

奖励模型长什么样

取视频生成模型的前 8 个 DiT 块，输入是某个噪声水平 t 下的潜变量 xt，外加文本和 t。得到的时空特征用一个可学习 query 做注意力池化，压成一个向量，再接 3 层 MLP，输出一个标量分数。训练时 t 随机采样，所以它学会在任何去噪阶段打分，不用等视频生成完、也不用 VAE 解码。

PRFL 的奖励模型是单独的一份权重（前 8 块单独微调）。CoRe 则让奖励模型和生成器共用同一套 DiT 参数 θ，奖励头只包括池化和 MLP 的参数 ϕ。

生成器怎么用它

从纯噪声出发，不带梯度地去噪到某个 t 的前一步，然后带梯度走最后一步，得到 x̂t，交给奖励模型打分，再反传。梯度只经过这一步去噪，所以显存和时间都省。PRFL 另外每步交替做一次 SFT（在真视频上跑流匹配损失），防止跑偏。

CoRe 沿用了这套"无梯度 rollout + 一步有梯度"的做法，训练用 40 步调度，t∈[200,800]（1000 刻度）。

作者给的"潜空间更容易被刷"的三个理由

理由论文原意我的看法
① 连续改几个潜变量通道就能改分数，不像语言模型只能改离散 token说得通，但论文没有拿像素空间奖励对照过"逃逸速度"，停留在论证
② 无遮挡直接对 xt 打分，少了 VAE 解码器这层隔离同上，没有实验隔离这个因素
③ 梯度路径短奖励梯度只过一步去噪就到生成器；共享主干时，还会直接穿过奖励读取的那些特征后半句很关键：这不是"分布逃逸"，而更像是篡改奖励的输入。生成器不用改视频，改特征提取器就能涨分。CoRe 保留了共享主干，但没做"切断这条路"的消融（§06、存疑 M2）

03破解诊断：论文看到了什么

诊断用的是 PRFL 式流程：先在偏好对上用 Bradley–Terry 损失训好奖励模型，冻住，再用"对原始 logit 的 hinge"去优化生成器。分两种设置：有流匹配（SFT）锚点和没有。

没有锚点（Fig 8a、Fig 1）

  • 约 20 次更新后，奖励饱和到 ~0.95
  • 第 15 步开始糊，第 24 步出现网格状伪影，第 100 步彻底崩
  • Fig 1 举的单条提示（"a person swimming in ocean"）：奖励 0.40 → 0.86（step 300）→ 0.71（step 600），单条视频的 imaging quality 74 → 54 → 34

有流匹配锚点（Table 1、Fig 8b）

  • 1000 步内奖励 0.636 → 0.742，dynamic degree 68.06 → 27.78，imaging 67.91 → 64.23
  • 生成特征的"spread"从 1.16 缩到 0.74：生成样本在奖励特征空间里越挤越紧
  • Fig 8b 却说：有锚点时 2.5k 步内奖励"没有明显上升趋势"，结论是"固定奖励只有两种结局：迅速被刷，或几乎没优化"

存疑 · 这些证据能说明"分布逃逸是根因"吗
  1. 起点就已经"逃"了。step 0 时生成器还是预训练模型，sgen（0.666）已经高于 sreal（0.551）。论文没有报告 step 0 时两者在特征空间里是否就已经可分。
  2. 这里的"真视频"不是实拍视频。训练数据是 VideoDPO 偏好对。按 VideoDPO 原文，它的做法是用被对齐的模型为每个提示生成 4 个视频，再用 OmniScore（实现里是图像质量、美学、主体一致性、闪烁、平滑度、dynamic degree，外加 ViCLIP 图文对齐，基本就是 VBench 那一套）挑出最好和最差的一对。原文的对象是 VideoCrafter2、T2V-Turbo 和 CogVideo，公开发布的只有 VideoCrafter2 版（320×512、16 帧）。CoRe 没说视频由哪个模型生成；如果用的是公开版，x⁺ / x⁻ 就是被放大到 480p 的 VC2 短片（这是我的推断）。无论哪种，它们都不是 real videos。如果是旧模型的输出，奖励模型在 step 0 就给 Wan 更高分，可能恰恰是对的。
  3. "固定奖励"到底固不固定？§3 说奖励模型和生成器共享 DiT 主干。如果诊断用的"固定奖励"也是共享的，那冻住的只有头，特征提取器会随生成器一起变：生成器可以直接改奖励读的特征。如果是一份冻结的副本，那它和 CoRe 的差别就不只是"固定 vs 共演化"，还包括"共享 vs 不共享"。
  4. 两个"固定奖励"实验对不上。Table 1 的锚定跑法在 step 500 时 DD 54.17、IQ 67.07；Table 3/7 的"Fixed LRM, step 500"却是 DD 68.1（没变）、IQ 60.01（掉了 8 分）。Fig 8b 说锚定时奖励"没有明显上升"，Table 1 却是 0.636→0.742。

04CoRe 的流程

一句话：奖励头每轮都在生成器的最新样本上重新拟合，所以生成器永远在奖励头"刚被监督过的地方"被打分。下图是我按论文 Fig 3、Algorithm 1 和 §3 重画的。

一次迭代里的数据流和梯度流
青绿实线 ①：梯度经最后一步去噪回到 θ。红色虚线 ②：梯度还会穿过共享 DiT 主干，直接改奖励读的特征（我标出的风险）。紫色：奖励损失只更新 ϕ。

Algorithm 1，用人话写

  1. 奖励头连做 nD=10 步。每步取一个提示 c 和它的偏好对 (x⁺, x⁻)。冻结的生成器从噪声 rollout 到随机的 t∈[200,800]，得到 x̂t；把 x⁺、x⁻ 前向加噪到同一个 t。算 LR，只更新池化和 MLP 的参数 ϕ。每一步都用新的 rollout，所以奖励头拟合的是生成器"此刻"的分布。
  2. 生成器走 1 步。再取一个提示和它的 x⁺，rollout 到 t，最后一步保留梯度，得到 x̂t；x⁺ 加噪到同一 t。算 LG = 相对 hinge + 核锚点 + 1.5×流匹配，更新 θ。梯度同时经过最后一步去噪和共享主干。
  3. 更新 EMA。θema ← 0.99·θema + 0.01·θ，评测时用 EMA。
  4. 之前还有一段 warm start（附录 C、D）。先只训奖励头 200 步，再用绝对目标（推到 0.9 分）训生成器 100 步，然后只重拟合奖励头 100 步。这就是"ckpt-400"。之后各变体再训生成器；附录写的是 100 步，但 CoRe 报告在 step 600，其他变体在 450 / 500。

sg[·]
stop-gradient，论文里用上划线表示。生成器看得到 x⁺ 的分数和特征，但推不动它们。
δ
相对 hinge 的余量。论文只说"δ=0 时追平就没梯度"；从 §6.4 的描述看实际用的就是 0，但没有明写。
λk, σ

LFM
流匹配损失，也就是在"真视频"上做 SFT。Algorithm 1 第 5 行只采 x⁺，所以大概率是在 x⁺ 上做，λfm=1.5。
w
"x⁺ 赢 x⁻"这一项的权重，固定为 0.5。没有做 w=0 的消融。

生成器只在 ℓ(x̂) 低于配对 x⁺ 的 ℓ 时才有奖励梯度；判别器则一直在学"x⁺ 高于生成样本"。判别器容量足够时，唯一能让它分不开两者的状态是 pgen = px⁺。核锚点和 SFT 锚点也都指向 x⁺。所以 CoRe 的终点是"长得像 VideoDPO 里的 x⁺"，不会超过 x⁺ 的质量。基座比参考数据差时，这是好事；基座比参考数据好时，它会把模型往下拉（§07 的玩具里可以直接看到）。论文 §6.4 自己观察到：静态视频的 imaging quality 从 70.4 掉到 66.2，"与生成器向 480p 训练视频的图像统计靠拢一致"。

05三方 BT 拔河台

把三个 logit 放在一条数轴上：生成样本 ℓ(x̂)、偏好视频 ℓ(x⁺)、非偏好视频 ℓ(x⁻)。拖动圆点，看奖励头（紫箭头）和生成器（蓝箭头）各往哪边拉、拉多大力。箭头长度正比于该 logit 上的梯度大小。

看什么。① 奖励头把 x⁺ 往右推，把 x̂ 和 x⁻ 往左推。② 生成器只看"x̂ 离 x⁺ 还差多少"：在相对 hinge 下，一旦追平（ℓ(x̂) ≥ ℓ(x⁺) − δ），蓝箭头就消失；在绝对目标下，目标是 logit(0.9)=2.20，只要没到就一直推。③ 任何一项都不比较 x̂ 和 x⁻：把 x⁻ 拖到 x̂ 右边，生成器的受力不变。

论文的一处说法不准。§5.3 说只用"真 vs 生成"两方目标时，一旦生成样本难以分辨，判别器梯度就会 "flatline"。实际上 softplus(ℓ(x̂)−ℓ(x⁺)) 在两者相等时的导数是 σ(0)=0.5，正处在较大的位置。消失的是有用的信号（梯度方向变成噪声），不是梯度本身。第二项的作用是让判别器的方向有意义，而不是"保持梯度活着"。

② 核锚点：在期望上，它在惩罚多样性

核锚点把每个生成样本的池化特征 z(x̂) 拉向同一提示下那一个 x⁺ 的特征。VideoDPO 每个提示只有一对视频，所以对某个提示来说，目标是一个固定点。设同一提示下生成特征近似服从 N(μ, s²Id)，与目标的距离为 Δ = ‖μ − z⁺‖，那么可以精确算出：

𝔼z[1 − exp(−‖z − z⁺‖² / 2σ²)] = 1 − (σ² / (σ² + s²))d/2 · exp(−Δ² / 2(σ² + s²))我的推导

对 s 求导，符号等于 sign(d(σ² + s²) − Δ²)。所以最优离散度是 s* = √max(0, Δ²/d − σ²)：一旦生成特征的均值离 x⁺ 不远（Δ² ≤ dσ²），核锚点在期望上就要求 s→0，即同一提示下的所有样本长成同一个样子。只有离得很远时，它才鼓励散开。

核锚点的期望损失随"生成特征离散度 s"的变化
拖动滑块。竖线 = 当前 s；圆点 = 最优 s*。纵轴是期望损失，越低越好。

这里假设了高斯，也忽略了 z 是 ℓ₂ 归一化的；x⁺ 那一侧加噪带来的随机性相当于给 s² 再加一项，结论不变。论文 §6.4 自己的描述与此吻合："核项把每个生成潜变量匹配到同一提示的真视频上，于是生成器照搬了那条视频的镜头和物体运动。"论文没有测多样性（同一提示多种子下的 LPIPS / DINO 方差），也没有人评。

③ SFT 锚与共享主干

SFT 锚的分量可能最大

λfm=1.5，训练数据大概率是 x⁺，也就是 VideoDPO 的赢家视频。它本身就是一次"在偏好视频上做 SFT"。奖励项有一半的步为 0、平均只有 0.04，核锚点的权重是 0.03–0.05，损失上限是 1。仅凭损失大小不能断定梯度大小，但只做 SFT 的对照是判断"共演化奖励到底贡献了多少"的最低要求，论文没有做。PRFL 原文的表里 SFT 本身也能大幅改动 DD。

共享主干：生成器能直接改奖励

LG 的梯度经过路径 ② 进入 θ，而 θ 也是奖励的特征提取器。stop-grad 只挡住了"对 x⁺ 那一路求导"，挡不住 θ 变化带来的影响。于是 Fig 4c、5c 里"生成样本与真样本在奖励特征中重叠"，可能有一部分是特征提取器被训得分不开它们，而不是视频真的变像了。核锚点优化的恰恰就是这个距离。要区分这两种情况，需要一个独立的探针（冻结的预训练特征，或像素空间分类器）。论文没有做。

07玩具实验：逃逸、共演化与天花板

下面把"奖励特征空间"画成 2D。它不是论文的复现，只用来直观展示三种机制：固定奖励会一路外推；共演化判别器会把生成器停在参考数据上；参考数据的质量就是天花板。

  • 横轴 z₁ 代表"质量方向"，纵轴 z₂ 是与质量无关的特征。x⁺（青绿三角）在 x⁻（橙方块）右边，而且在 z₂ 上带一点偶然的偏移，也就是一个伪特征。
  • 细框是参考数据的覆盖区。框内的真实质量 Q = z₁；出框后 Q 迅速跌到 −1.5，相当于视频"崩了"。奖励模型看不到 Q。
  • 生成器是一个对角高斯（蓝点）。背景紫色越深，表示当前奖励头给的 logit 越高。
  • 固定奖励：用二次特征做逻辑回归，只在 x⁺ / x⁻ 上训一次，然后冻住；生成器用 hinge 往上推 logit。CoRe：同样的奖励头，每步在生成样本上用三方 BT 重拟合 10 次；生成器用相对 hinge + 核锚点 + SFT 锚，其中 SFT 锚 = 把高斯拉向 x⁺ 的均值和方差。玩具里的学习率和 λ 与论文没有数值对应。
生成样本 x⁺ x⁻

你会看到：

  1. 固定奖励：奖励分数很快到 1.0，真实质量先升后崩，生成器沿着奖励的线性外推方向（含伪特征 z₂）冲出覆盖区。z₁ 方向的离散度收缩，与 Table 1 中 spread 1.16→0.74 同向，原因之一是 hinge 只推还没过线的那一侧样本。
  2. 固定奖励 + 强 SFT 锚：能停在覆盖区边上，质量甚至高于 x⁺。固定奖励并不一定会崩，取决于锚的强度和早停时机。论文没有给固定奖励基线做这种调参。
  3. CoRe：生成器停在 x⁺ 那一团上，sgen ≈ sx⁺，和 Fig 4a"差值≈0"一致；质量 ≈ x⁺ 的质量。
  4. CoRe · 强基座：起点质量约 0.93，被拉回到约 0.7。这就是参考数据的天花板。
  5. CoRe · w=0：奖励头把 x⁻ 排到了 x⁺ 前面，因为它学的是"真 vs 假"，不是"好 vs 坏"。但生成器的终点几乎不变。三方项改变的是奖励"表示什么"，不是生成器"去哪里"。所以要证明它对生成器有用，必须做 w=0 的消融。

Wan 行来自 Wan 技术报告的官方榜单（83.96）。DPO 系三行来自 SIPO，而 SIPO 自测的 Wan 是 84.26。CausVid 和 Self Forcing 来自 Self Forcing 论文，用 Qwen 改写了提示，其 Wan 也是 84.26。VBench-2.0 的三行来自 BLADE（CFG 5）。CoRe 在自己的协议（CFG 6、固定种子）下测的 Wan 总分没有报告。VBench 官方协议是每个提示采 5 个样本，"fixed seed"是否意味着只采 1 个样本，论文没说清楚。

VBench-2.0 上 58.03 对 58.0 属于舍入内平手。由 Total 反推，CoRe 其余三维的均值是 63.6，低于 TDM（65.2）和 BLADE（64.1）。对比对象多为 4–8 步蒸馏模型；最相关的潜空间奖励基线（按 PRFL 原配置并做早停）没有出现在主表里。

澄清：在同一协议下自测所有基线，并报告 VBench-2.0 的全部 5 维。

高H4"real videos"不是真实视频；参考数据的质量是天花板；奖励标签与评测指标同源

论文通篇称 x⁺ / x⁻ 为 real videos、positive reals、genuine videos。但训练数据是 VideoDPO 偏好对。按 VideoDPO 原文，它的做法是用被对齐的模型为每个提示生成 4 个视频，再用 OmniScore 选出最好和最差的一对；原文用的模型是 VideoCrafter2、T2V-Turbo 和 CogVideo，公开发布的数据集只有 VideoCrafter2 版（320×512、16 帧）。CoRe 没有说明视频由谁生成；如果用的是公开版，x⁺ / x⁻ 就是被放大到 480p 的 VC2 短片（推断）。dyn300 用的 VisionReward 运动偏好对，据我所知也是生成视频。

这带来三个后果。① 如果是旧模型的输出，step 0 时奖励模型给 Wan 更高分（0.666 对 0.551）可能是正确的，而不是"逃逸"。② CoRe 的平衡点是 pgen=px⁺，参考视频的质量就是上限；§6.4 观察到的 IQ 下降（静态视频 70.4→66.2，"向 480p 训练视频的统计靠拢"）与此一致。③ OmniScore 由图像质量、美学、主体一致性、闪烁、平滑度、dynamic degree 和图文对齐构成，几乎就是 VBench 的维度。用它挑出的偏好去训练、再用 VBench 评测，存在循环。

澄清：说明数据来源；换成真实视频，或 Wan 自己的 best-of-N，重做实验。

高H5"稳定"没有在同等时长下验证；DD 的增益来自 warm start 里的朴素阶段

CoRe 只有 step 600 一个检查点，约 200–300 次生成器更新。附录 C 说"再训 100 步"，而其余变体停在 500，两处对不上。朴素 v2 在 200 次更新时（step 400）还没塌（均值 82.67），要到 550 次（step 750）才塌。CoRe 的起点 v2@300 的 DD 已经是 89.6，CoRe 阶段结束时是 81.9 / 84.7。Fig 4a 的横轴按"各自归一化的进度"画，掩盖了各 run 实际长度的差异。

澄清：把 CoRe 与 v2 都跑到 ≥1000 次生成器更新，每 50 步评一次。

高H6缺关键消融；训练末期奖励头几乎没有区分力，生成器的拉力可能主要来自 SFT 和核锚点

缺少的消融：只做 SFT（λfm=1.5，在 x⁺ 上）、只用核锚点、w=0（即二方 BT）、nD 的取值、共享主干 vs 独立主干。§6.4 说奖励头对真假样本的 sigmoid 都在 0.55 左右；相对 hinge 在 44% 的步为 0，平均只有 0.04。Fig 4c 的分数全部挤在 0.48–0.60 之间。在这种状态下，CoRe 可能主要是"在 VideoDPO 赢家上做 SFT，加上特征回归"。

澄清：在同一 warm start 下，逐项去掉各组件，跑相同步数。

中M1本质是潜空间 relativistic GAN，相关工作缺位

奖励头的损失就是 RpGAN 的判别器损失；相对 hinge 是 stop-grad 版的生成器损失；nD 对应 n_critic / TTUR；核锚点是逐样本的 feature matching；在扩散主干特征上接判别头，与 LADD、DMD2 的 GAN 头同构。论文正文也把奖励头叫作 discriminator，却没有引用 GAN、R3GAN、LADD 或 APT，也没有讨论它与这些方法的区别。真正的新意是"x⁺ 赢 x⁻"这一项，以及把判别器当作"奖励"来叙述。

中M2共享主干：生成器可以直接篡改奖励特征；Fig 4c / 5c 用的是被优化过的特征来自证

生成器损失的梯度会穿过共享 DiT 进入 θ，从而改写奖励读的特征（论文引言 (iii) 自己也提到了）。诊断里的"固定奖励"如果也共享主干，那它并不真的固定；如果是一份冻结副本，那它与 CoRe 的区别就不只在于是否共演化。Fig 4c、5c 说"生成样本与真样本重叠、分数不再依赖来源"，但这个重叠正是核锚点通过同一个特征提取器直接优化的量。需要一个独立的探针才能说明问题。

澄清：在冻结的预训练 DiT 特征上重训一个线性探针，或用像素空间分类器，测 step 0 和训练末期的可分性；另做一组"奖励特征 stop-grad"的消融。

中M3核锚点在期望上惩罚多样性；多样性与人评都缺失

每个提示只有一个 x⁺，核锚点的期望损失在 Δ² ≤ dσ² 时随离散度 s 单调上升（推导见 §06），也就是鼓励同一提示下的样本收缩成同一个样子。论文自己观察到"生成器照搬了配对视频的镜头和物体运动"，SC 从 96.35 掉到 92.89，但没有测任何多样性指标，也完全没有人评。对一篇讨论"奖励破解"的论文来说，只用自动指标（而且其中几项在视频静止时反而升高）来证明没被破解，说服力有限。

中M4消融只用 72 个视频、单个种子，没有误差条

DD 以 1/72=1.39 分为最小单位，单点的 95% 置信区间宽约 ±9 分。λk 0.05 和 0.03 之间只差 2 个视频；relgap（50/72）和绝对目标（41/72）之间差 9 个视频，不配对的两比例检验 p≈0.12，并不显著。其余维度没有给方差。

中M5两次"固定奖励"实验互相矛盾

Table 1（有锚点）在 step 500 时 DD 54.17、IQ 67.07；Table 3/7 的 Fixed LRM 在 step 500 时 DD 68.1、IQ 60.01。Fig 8b 说有锚点时 2.5k 步内奖励"没有明显上升"，Table 1 却是 0.636→0.742。附录 D 又说"固定奖励不改变 DD，只让 IQ 降 8 分"。三处描述的"固定奖励"行为各不相同，论文没有说明它们分别是哪次运行、用了什么设置。

中M6Table 3 的 EMA 对照换了数据集，caption 没有说明

"no EMA / EMA, step 400"两行其实是 dyn300 / dyn300ema，按附录 D，它们换成了 VisionReward 运动偏好对。换数据后 DD 塌得更快（47.2 / 58.3，同一步的 v2 是 77.8）。这两行既不能说明"EMA 只能减缓塌缩"，也不能直接和 CoRe（有 EMA、用 VideoDPO）比。另一方面，朴素的 v2 / w1p5 评测时不用 EMA，而 CoRe 用了，比较本身就不对等。

中M7训练规模不透明：帧数、batch、rollout 是否用 CFG 都没给

每个生成器步伴随 11 次 rollout，每次平均 20–32 步。若按 81 帧 480p 算，2.1 h 只在最省的配置下才可能达到；如果训练用的是 VideoDPO 原生的 16 帧短片，那又意味着训练和评测的长度不一致。此外，CoRe 总共只有约 200–300 次生成器更新，如果 batch 很小，实际见过的视频可能只有几百个。这对判断效果从何而来很关键。

低L1"二方目标的梯度会 flatline"这一说法不准确

softplus(ℓ(x̂)−ℓ(x⁺)) 在两者相等时的导数是 0.5，并不会消失。消失的是梯度方向上的有用信息，而不是梯度的大小（见 §05）。

低L2关键超参缺失

核带宽 σ（符号还和 Eq. 3 的 sigmoid 重名）、绝对目标的具体损失形式、batch 大小、训练帧数、rollout 是否用 CFG、Fixed LRM 的训练细节（数据、步数、是否共享主干）都没给出；δ 只能从上下文推断为 0。§4.1 说"沿用 Mi et al. 的做法"用 BT 损失训奖励，但 PRFL 默认用的是 BCE，而且它的奖励模型是一份独立的权重，不和生成器共享主干。

低L3数字上的小毛病

DD 值 86.72、89.67、83.72 都不在 1/72 的网格上，而同表其余 DD 都在。Table 3 中 Fixed LRM 的 DD 写作 67.06，Table 7 是 0.681（=68.06），Table 3 的均值 80.60 是按 67.06 算出来的。v2@750 的 IQ / AQ / SC 在 Table 3 是 62.10 / 64.03 / 97.50，在 Table 7 是 0.629 / 0.631 / 0.978。Table 7 中 v2@300 写 0.896，Table 3 写 89.67（后者应舍入为 0.897）。

低L4显著性标准前后不一

双时间步监督比单时间步高 +0.25，被说成"不显著"；主表中 CoRe 比 SIPO 高 +0.14（重算后是 −0.03），却被称为"最高"。

低L5正文前后不一与笔误

nD 在 §5.1 写 10，在 §5.4 写 5–10。§4.2 说评估了 OOD sensitivity，Table 6 却没有这一列。§6.3 说"Tab. 3 isolates the generator objective"，数据其实在 Table 8。"The fixed reward is unstable across checkpoints"，但固定奖励只报了一个检查点。Physics 一项只说低于 TDM，没提同样低于 BLADE（61.7）。Table 6 的 stable steps 是在哪种设置下测的没有说明。另有残句（"indicate that CORE compute budget than online RL"）和"we shows"等笔误。

低L6EMA 让共享 warm start 的变体差异被压缩

EMA 衰减取 0.99，100 步后初始权重仍占 0.99¹⁰⁰ = 36.6%。绝对目标、相对 hinge 和 CoRe 三个变体的评测模型里，有约三分之一是同一个 warm start 的权重，它们之间的差异因此被压缩。

低L7代码未公开；run 名与描述不符

代码只说"将作为补充材料发布"。run 名 "w1p5" 看起来像是某个权重取 1.5，附录却说它和 v2 只差学习率。

11公道话，以及对交互式视频世界模型的启示

做对的地方

  • 把"潜空间奖励会被快速刷爆"量化了：约 20 步饱和，外加 Table 1 的 sreal/sgen/spread 三件套。这套监控可以直接拿来用。
  • 负面观察报告得比较诚实：朴素在线奖励先升后崩；SC 为此付出代价（96.35→92.89）；奖励头到后期区分力很弱；核锚点会让生成器照搬参考视频的运动。
  • 相对 hinge（追平就停）便宜又合理，Table 8 显示它比绝对目标少掉 DD。
  • 加入 x⁻ 让判别器同时学"好 vs 坏"而不只是"真 vs 假"，这个思路值得在别处试。
  • 附录 Table 7 列出了所有 run 的原始数字，正是它让我们能发现正文里的不一致。

对世界模型意味着什么

  • 如果要用 PRFL 式潜空间奖励去后训练自回归世界模型（比如动作跟随、物理合理性），要预期几十到几百步内就会被刷。监控时要在留出的真实片段上看 sgen−sreal，再加一个独立探针，不能只看同一个奖励。
  • CoRe 这套机制在世界模型里其实更顺理成章，因为世界模型有真正配对的真值：同一段历史、同一个动作下的真实后续帧。这时"相对 hinge + 核锚点"近似于对真值后续做对抗式的 teacher forcing；"负真样本"可以用同一段视频配上错误的动作来构造，让判别器学到动作一致性，而不是真实感。这比 VideoDPO 的合成偏好对干净得多。
  • 要避开三个坑：① 共享主干带来的篡改通道，奖励特征应改用 EMA 副本或做 stop-grad；② 参考数据的质量天花板；③ 逐样本核锚点导致的塌缩，世界模型需要保留多种可能的未来。

最值钱的后续实验

  1. 在同一个 warm start 下分别跑：只做 SFT、只用核锚点、只用相对 hinge、全套组件。每组都跑到 ≥1000 次生成器更新，每 50 步评一次，用 ≥300 个视频、3 个种子。
  2. w∈{0, 0.5, 1} × nD∈{1, 5, 10} 的网格消融。
  3. 共享主干，对比"奖励特征 stop-grad / EMA 副本"。
  4. 独立探针：在冻结的预训练 DiT 特征上训线性分类器，测 step 0 和训练末期"生成 vs x⁺"的可分性。
  5. 把 VideoDPO 换成真实视频（或 Wan 自己的 best-of-N），检验天花板假说。
  6. 多样性（同一提示多种子下的 LPIPS / DINO 方差），以及人评。
