MemRoPE精读 · arXiv 2603.12513
Training-free · Autoregressive video diffusion · KV cache

把时间撒个谎，然后一直撒下去 MemRoPE 的两个动作：① KV cache 里所有 key 都不带位置存，注意力时才临时编号；② 被挤出窗口的帧用两个速度的 EMA 揉进 2 个 token。合起来，一个 12 帧的定长缓存可以撑一小时的生成——而且不训练。

arXiv:2603.12513v1 2026-03-12 · cs.CV USC Kim*, Hu*, Kuo, Beerel training-free Wan2.1-T2V-1.3B base: Self-Forcing / LongLive
一句话

自回归视频扩散靠 KV cache 记住过去，而 cache 是定长的：FIFO 把老帧直接扔掉（上下文丢失），attention sink 把开头几帧冻住（不会随剧情更新），Deep Forcing 用注意力分数选 token（会锁死在一组老 token 上，偶尔换一次就闪一下）。MemRoPE 说：别再挑该留谁，把挤出去的帧连续地揉进一个滑动平均里——但要揉就必须先解决一件事，RoPE 不能对加法分配，带着不同旋转相位的 key 平均出来不对应任何位置。于是它把 cache 里的 key 全改成不带位置存，每一步注意力时从 0 开始重新编号。两件事互为前提。

01The whole idea in one picture

一图看懂：视频越来越长，模型看到的索引永远是 0–11

上半张图是真实发生的事：视频一直往前长，历史被指数式地遗忘。下半张图是模型每一步真正看到的东西：永远是 12 个槽位、永远编号 0…11。MemRoPE 的全部魔法，就是让这两张图一直对得上。拖动滑块看 1 秒到 1 小时。

Sink（S=3）

Algorithm 1 第 1–2 行：第 0 块生成后立刻取 K/V 存下，此后永不更新。论文的理由是早期帧在训练范围内、且 DMD 蒸馏模型开头质量最高。

μL / μS（2M=2）

每次有 chunk 被挤出 local window，就把它空间池化成 1 个 token，再按两个速率写进两条 EMA。key 和 value 都做。

Local（L=4）

最近的帧，原样保留、全空间分辨率。这是唯一能提供细节的部分。

Query（3 帧）

当前 chunk 的 3 个 latent 帧，4 步去噪（t=1000/750/500/250）。只有最后一步的 K/V 才进 cache。

02What actually breaks

它在解什么问题：三种缓存策略，三种忘法

同样是定长缓存，「留下谁」的策略决定了失败方式。下图把三种策略放在同一条时间轴上跑：每一列是一个已经生成的 chunk，颜色深浅＝这个 chunk 的内容此刻还能影响生成多少。

论文对三者的批评可以压成一句话：FIFO 把过去删掉，sink 把过去冻住，PC 把过去锁死。而 PC 的锁死还有个副作用——Fig. 3(c,d) 显示，每当那一小撮 token 终于换一次，相邻帧的 SSIM 会掉、LPIPS 会尖峰，也就是画面「跳一下」。EMA 的卖点不是记得更多，而是每一次遗忘都足够小，小到看不见。

先把术语对齐：这里的「一个 token」有多大

480×832 经 Wan2.1 的 VAE（空间 8×）与 patch=2，一个 latent 帧约 30×52 = 1560 个 token（我按 Wan2.1 配置推算）。所以 sink=3 帧≈4680 token、local=4 帧≈6240 token，而整个历史被压进的 μL+μS 一共只有 2 个 token。记住这个比例，后面很多事情就解释得通了。

03Memory tokens — the dual EMA

双速记忆：一条快的追动态，一条慢的「累积全部历史」

机制本身只有两行。每当一个 chunk 被挤出 local window，先把它空间池化成一个 key k̄，然后写进两条流：

μL(t) = (1 − αL) μL(t−1) + αL k̄new     μS(t) = (1 − αS) μS(t−1) + αS k̄new Eq.(3)(4)，αL ≪ αS；论文取 αL=0.01、αS=0.1。value 同样处理。

论文对这两条流的描述是：「长期流累积全部生成历史成一个稳定表示，短期流追最近的动态」。这句话在数学上只在很弱的意义上成立——EMA 的确对每一个历史 chunk 都有非零权重，但权重是指数衰减的。所以真正的问题是：它的时间尺度到底有多长？下图把这个尺度算给你看。

我的第一个意见：「长期记忆」是一个 75 秒的指数窗口，不是「全部历史」

按论文的 αL=0.01：时间常数 100 chunk = 75 秒，半衰期 69 chunk = 51.7 秒。也就是说，在 Fig. 1 那个一小时的例子里，生成到第 60 分钟时，μL 中5 分钟以前的全部内容加起来只占 1.8% 的权重，10 分钟以前占 0.03%，55 分钟以前（也就是视频开头）占 6×10−20。开头的人脸不是被 μL 记住的——它是被那 3 帧冻结的 sink 锚住的，而 sink 是 attention sink 老办法，不是本文的新东西。

这不否定方法有效，但它改变了机制叙事：MemRoPE 的 EMA 不是「记忆」，更像一个平滑的、时间尺度约一分钟的低通锚，作用是抑制逐帧漂移（曝光、色调、整体统计），而不是召回远处的具体内容。论文自己在 Limitations 里承认「EMA 聚合是有损的，可能限制对远处内容的精确召回」，但摘要与 Fig. 1 的表述（"compress all past keys"、一小时身份完美保持）比这个承认强得多。

要验证很容易：把 αL 换成 1/t（真正的累计平均，无衰减）再跑一次；或者在 30 分钟处切换场景，看 μL 是否还携带开头的信息。论文两件都没做。

还有一个没人提的细节：μ 从零开始，而且没有偏置校正

Algorithm 1 第 3 行：μ_L, μ_S ← 0。EMA 的经典问题是初期被零值拖着（Adam 用 1/(1−(1−α)t) 做偏置校正），而论文没有做任何校正。于是在视频前几分钟，μL 的幅度只有稳态的一小部分——一个幅度很小的 key，注意力 logit 也小，行为上更接近一个内容近乎为零的「空槽」（经典的 null attention sink）而不是携带信息的记忆。

04Spatial pooling — 1560 → 1

压缩比：两千两百万个 token，压进 2 个

Algorithm 1 第 16–17 行：k̄ ← SpatialPool(K_local[0])。被挤出去的那一帧，它的 1560 个空间 token 被池化成一个。所有更早的历史，全部住在 μL 和 μS 这两个 token 里。

池化之后的 key 和 value 在注意力里意味着什么，值得说清楚：

  • 池化的 key：q·mean(k) = mean(q·k)，也就是这一帧对当前 query 的平均相关度——一个「这帧整体像不像你要的东西」的标量式匹配，没有任何空间选择性。
  • 池化的 value：注意力从这个槽位取回的是整帧 value 的均值，也就是一个全局的「色调／曝光／整体统计」的直流项。它能拉住画面不要跑偏，但不可能还原「左上角那栋楼」。
  • 所以 §07 会看到的现象就顺理成章了：MemRoPE 的增益几乎全在 Imaging Quality / Aesthetic Quality（逐帧画质、曝光、色彩）上，而在真正测「同一个主体有没有变」的 Subject Consistency 上只有零点几分。机制解释了指标形状。
顺带一个复现上的硬伤：池化后的 token，3D-RoPE 的空间坐标是什么？

Wan2.1 用的是 3D-RoPE，每个 token 的旋转由 (t, h, w) 三个坐标决定。Eq.(7) 只给了一条一维的连续索引 φ，对普通帧可以理解成「只重排时间轴、空间坐标照旧」。但池化后的 μ 只有一个 token，它的 (h, w) 取什么？取 (0,0)？取中心？还是空间分量干脆置零（等于不旋转）？论文正文、算法、附录都没写，而这个选择会实打实地改变 μ 在注意力里的行为。没有代码的话，这一条足以卡住复现。

05Online RoPE indexing

为什么「先存再转」就没法平均：相位是会互相抵消的

RoPE 的全部好处来自一个恒等式：q̃i⊤k̃j = qi⊤Ri−jkj，注意力只看相对距离。代价是：标准实现在写 cache 的时候就把 k̃j = Rjkj 转好存下，这个 key 从此被钉死在位置 j 上。

α Rjkj + (1−α) Rj′kj′  ≠  Rφ( α kj + (1−α) kj′ )   对任何 φ Eq.(5)：RoPE 对加法不分配。论文据此说「平均后的 key 不对应任何合法时间位置」。

论文到此为止。但这句话其实可以算得更准，而算准之后结论会软一点——下面这张图是我推的：把 EMA 作用在「已经旋转过的 key」上，对每一个 RoPE 频带而言，等价于一个单极点低通滤波器。

|H(ω)| = α / |1 − (1−α)e−jω|   ≈   α / (2 sin(ω/2))　（当 ω ≫ α） 我的推导：设各时刻的 key 内容相近，EMA 权重 α(1−α)k 对频率 ω 的旋转求和 = Σk α(1−α)ke−jωk。−3dB 截止点恰好在 ω ≈ α。

第二件事：索引从哪儿开始数

存原始 key 之后，位置就成了一个可以每一步重新发的号码牌。Eq.(7) 把整个 cache 当成一个块，从 0 开始连续编号：

[0 … S−1]sink   [S … S+2M−1]memory   [S+2M … S+2M+L−1]local   → query 从 S+2M+L 开始 论文配置 S=3、M=1、L=4 → cache 占 9 个索引，当前 chunk 占 9,10,11。总跨度 12，永远落在训练见过的范围里。
我的第二个意见：「省掉了每步旋转」这句话说反了

论文说 ∞-RoPE「需要对已存的 key 每步做相位旋转，而我们省掉了这一步」（Sec. 4.2 末）。但 Algorithm 1 第 10 行写得很清楚：Apply R_φ to q_s, K——MemRoPE 在每个去噪步、每一层都对整个 cache 施加一次旋转。旋转量不比 ∞-RoPE 少，甚至更多；真正省掉的是「就地改写已存 key」这个破坏性操作，以及由此带来的不可聚合性。

这不是空口推断：Tab. 8 里同为 C=12 时，LongLive 4.409 FPS → +MemRoPE 4.376 FPS，慢了 0.7%，方向正好和「多做了旋转」一致。论文把它描述成「negligible overhead」是对的，但机制表述应该改成「rotation is cheap」，而不是「rotation is eliminated」。

要给的肯定：position-free cache 本身是个干净的抽象

把「内容」和「位置」在 KV cache 里解耦，之后位置就变成了注意力时刻才发放的号码牌——这使得任何基于聚合的缓存压缩（不止 EMA：聚类、低秩、merge、token pooling）在 RoPE 模型上第一次变得良定义。这个抽象比论文里具体那条 EMA 更有价值，也更容易被后续工作复用。Rolling Forcing 只对 sink 做过类似的事，MemRoPE 把它推广到了整个 cache。

整个方法就是这 24 行，没有新损失、没有新模块、不改一个权重。注意三处 w/o RoPE——它们是全文的支点。

一个对不上的账：C 到底是 9 还是 12，L=4 又是什么单位

论文的配置是 S=3、M=1、L=4，正文明写 C = S + 2M + L，代进去是 9；而 Tab. 8 的延迟表里 MemRoPE 写的是 C = 12。我能找到的唯一自洽还原是：C 指的是「索引跨度」，把当前正在去噪的 3 帧也算进去——3 + 2 + 4 + 3 = 12，正好等于 Eq.(7) 里 query 拿到 9,10,11 之后的总长度。Self-Forcing 那行 C=21 也刚好是它 21 个 latent 帧的完整窗口（含当前 chunk），互相印证。

但这个还原会立刻撞上第二个问题：L=4「帧」不是 chunk（3 帧）的整数倍。而 Algorithm 1 内部本身就不自洽——第 16 行池化的是 K_local[0]（一个元素），第 22 行却写 "Evict oldest chunk"（3 帧）。两种读法各自和论文别处的数字打架：

这不是吹毛求疵：local window 到底留 4 帧还是 12 帧，直接决定了「有多少细节是原样保留的」——也就决定了该把多少功劳记在 EMA 头上。没有代码，这一条只能存疑。

07Reading the numbers

结果怎么读：赢的是画质分，不是一致性分

先说结论：论文报的 43 行 VBench-Long 数据，平均值一行不差地等于 6 项指标的无权平均（我全部核算过，最大偏差 0.007，全是四舍五入）。数字本身是干净的。问题出在这个「无权平均」上。

我的第三个意见：这个「平均分」几乎就是 Imaging + Aesthetic 两项

六项指标的量纲差得离谱。在论文全部数据行上，各项的标准差是：Imaging 3.43、Aesthetic 2.86，而 Subject 1.13、Temporal 0.74、Background 0.62、Motion 0.60（我算的）。无权平均的结果是：方差大的两项几乎决定一切。

我把每一组的 Δ平均 拆开，看它由谁贡献（下图）。对 ∞-RoPE 的全部 10 组比较里，Aesthetic+Imaging 贡献了 107%–140%——超过 100% 的意思是，其余四项的净贡献是负的。而 Aesthetic（LAION 美学打分）和 Imaging（MUSIQ 画质）都是逐帧指标，衡量的是「这一帧糊不糊、过不过曝」，不是「这个人还是不是同一个人」。论文把这两项称作「对长程上下文保持最敏感的维度」，这个说法需要打个问号：真正测身份保持的 Subject Consistency，MemRoPE 相对 ∞-RoPE 只有 +0.07 ~ +0.47。

我的第四个意见：六项里没有 Dynamic Degree，而摘要点名要治的正是 motion stagnation

摘要开篇列的三个失败模式是 fidelity degradation、identity drift、motion stagnation。VBench 里正好有一项 Dynamic Degree 专门测运动幅度，而论文选的六项里没有它（Deep Forcing / ∞-RoPE 这一系文献普遍如此，不是本文独创，但本文的动机让这个缺席格外刺眼）。

为什么要紧：Subject Consistency 与 Background Consistency 本质是跨帧特征相似度，Motion Smoothness 和 Temporal Flickering 奖励帧间变化小。一个把历史往均值上拉的 EMA 记忆，天然会让画面更「稳」。也就是说，「画面更稳」和「画面更死」在这六项指标上是同号的，而唯一能把它们分开的那一项没有报。补一列 Dynamic Degree 是零成本的（视频都已经生成好了），不补就无法排除「分数是靠冻住画面换来的」。

跨时长的绝对分不要连起来看

Tab. 2 的 1 小时那组，两种方法的分都比 2 分钟那组高（MemRoPE 87.99 vs 86.45，∞-RoPE 87.01 vs 85.58），而 480 秒那组又比 2 分钟低。如果真有「累积退化」，分数不该这样上下跳。原因很直接：1 小时只用了 10 条 prompt、480 秒 20 条、120/240 秒 128 条，三组打分对象根本不是一批。论文自己在附录 C 里也承认了这点，特意用固定的 20-prompt 子集重画了 Fig. 8。可主表 Tab. 2 没有提醒读者，很容易读成「越长越好」。

08Ablations, at their real size

消融：两条流的边际收益是 +0.02

论文的两个关键消融都在 LongLive、60 秒、20 条 prompt 上做。把它们画在同一把尺子上，差距的实际大小就出来了。

我的第五个意见：双流设计的定量证据只有 +0.02，而定性图说「只有双流才行」

Tab. 5：无记忆 85.48 → 只要 μL 85.84 → 只要 μS 85.95 → 双流 85.97。也就是说，在「只用短期流」的基础上再加一条长期流，只换来 +0.02——在 20 条 prompt、没有任何方差报告的设定下，这个量级和噪声无法区分。

可 Fig. 11（论文的定性图）却说：无记忆、只长期、只短期三种情况下背景建筑都会逐渐消失，只有双流才保住。定量和定性在这里是打架的。要么定性图挑了个别例子，要么 Tab. 5 的平均分掩盖了某类样本上的显著差异——无论哪种，论文都应该给出方差或按 prompt 的分布，而不是只给一个平均。

position-free 这一刀，实测值多少

Tab. 7 是全文最该被注意的消融：把「先去位置再 EMA」换成「带着 RoPE 直接 EMA」，两者都比基座好，差距是 +0.84 vs +0.71（Self-Forcing）和 +0.53 vs +0.37（LongLive）。也就是说，Eq.(5) 那个「相位冲突导致表征无效」的理论问题，实际只值 0.13 / 0.16 分。

这和我在 §05 推的低通滤波解释完全一致：带 RoPE 聚合并不会得到垃圾，它得到的是一个只保留低频位置带、幅度被压缩的 key——有损，但不是废的。所以 position-free 是更干净的设计（而且顺手解决了外推），但论文用的 "essential" 一词比证据强。

12Where it sits

谱系与定位：它是抗漂移稳定器，不是世界记忆

长视频的「记忆」这条线上大致有四类做法，MemRoPE 在最右边一栏——也是最便宜的一栏：

路线代表记忆载体训练能做空间回访吗
几何/检索记忆WorldMem, VMem, Context-as-Memory位姿索引的历史帧库需要能
架构级压缩记忆FAR (FlexRoPE), VideoSSM, FramePack多尺度 patch / 状态空间从头训部分
长上下文微调LongLive, Self-Forcing++, Context Forcing更长的窗口 + 对齐训练需要不能
推理期缓存管理∞-RoPE, Deep Forcing, MemRoPE定长 KV cache 的分配策略不需要不能

对交互式世界模型而言，这个区别是要命的：交互的核心考验是「我转身走开再回来，那面墙还是不是原来那面」。MemRoPE 的记忆是 2 个空间池化的 token，没有任何空间选择性，加上一个约 1 分钟的指数窗口——它在原理上就不可能支持空间回访一致性。它真正解决的是另一件同样重要的事：长时间 rollout 的数值漂移（曝光跑飞、色调偏移、结构逐渐糊掉）。

所以它在这个仓库里的正确位置是：一个可以叠加在任何自回归视频世界模型上的、零成本的稳定层。特别值得注意的是 Self-Forcing 那组——cache 从 21 帧砍到 12 帧，FPS 提升 41%，分数还涨了 0.98~1.85。对实时交互来说，「更快 + 更稳」比「多记 10 秒」更有直接价值。而它最可复用的零件不是那条 EMA，是 position-free cache：任何想在 RoPE 模型上做 KV 合并/聚类/检索的工作，都可以先把这一刀借走。

术语

  • Attention sink：StreamingLLM 观察到的现象——序列最开头的几个 token 会吸走大量注意力，删掉它们会让模型崩掉。视频这边把开头几帧固定留在 cache 里，就是这个思路。
  • FIFO eviction：cache 满了就丢最老的。滑动窗口的默认策略。
  • Participative Compression (Deep Forcing)：按累计注意力分数挑 token 留下。本文 Fig. 3 指出它会自我强化地锁死在一组老 token 上。
  • 块相对 RoPE（∞-RoPE）：把 cache 的位置索引整体平移到训练见过的区间里，从而突破 1024 帧上限。
  • VBench-Long：把长视频切片打分再聚合的评测套件。本文用其中 6 项，不含 Dynamic Degree。
  • 2AFC：两选一强制选择，用户研究的标准范式。
