    GATO-Vid

    用闭式解替代反向传播的空间定位文生视频
    Spatially-Grounded Text-to-Video Generation via Inference-Time Gradient-Free Optimization

    要让 14B 的视频 DiT 把「一只猫」生成在你指定的框里，主流 training-free 做法是对交叉注意力图做梯度引导——前向一遍、显式物化注意力图、算定位损失、再反向穿过整个网络。在 Wan2.2 这种量级上，这一步要多花 300% 的时间和 26 GB 显存。 GATO-Vid 的主张是：这个梯度其实不必算。把交叉注意力的目标函数换成一个可解析求解的代理分数，它的最优方向有闭式解，而且只依赖文本键——于是整个引导退化成「在 block 内部把 query 往一个算好的方向掰一下，再拉回 RMSNorm 的椭球面」。代价：+0.4% 推理时间；每层只多两个 d 维向量，显存开销可忽略。

    01The whole idea

    一图看懂：把「反向传播」换成「block 内部的一次掰正」

    两条路线的输入输出完全一样：一段 prompt、一串逐帧包围框、一个冻结的 T2V 生成器。差别只在于拿到引导方向的方式——一边靠反向传播把误差信号送回 latent，一边直接用文本键算出方向、就地改写 query。

    旧路的瓶颈 1
    注意力图必须显式物化
    现代引擎用 FlashAttention 就是为了不把 A 写进显存。梯度法为了算 Ā 又把它逼出来，等于主动放弃了这项优化。
    旧路的瓶颈 2
    反向要穿过全部参数
    对输入 xt 求梯度 ⇒ 计算图覆盖整个网络。原文实测：只在 Wan2.2 两个 transformer 之一上做一次反向，就要额外 26 GB。
    新路的支点 1
    目标函数换成 logits
    丢掉 softmax 的非线性，直接在 QK⊤ 上定义分数——于是它对 q 是线性的，可以解析求极值。
    新路的支点 2
    最优方向只依赖文本键
    解出来的 b± 是 K(T) 与 K(Tc) 的函数，与视频 query 无关，所以每层算一次就能广播给全部 3 万多个 token。
    02Problem setup

    任务与符号：两个索引集合 M 和 T

    整篇论文的所有机制都建立在两个索引集合上：M 是目标物体轨迹在视频 token 序列里占据的时空位置，T 是 prompt 里指向这个物体的那几个词。剩下的一切都是「怎么让 M 里的 query 更喜欢 T 里的 key」。

    2.1 采样循环与交叉注意力

    生成器是 latent flow matching：从高斯噪声 x0 出发，每步预测速度场再交给调度器推进，t=1 时用 VAE 解码回像素。

    vt = fθ(xt, τ, t), xt+Δt = FlowSch(xt, vt, t)
    Eq. 1
    冻结的采样主干。GATO-Vid 不改这一行的任何东西——它不改 xt，只在 fθ 内部动手；这正是它与梯度法（Eq. 6 直接改 xt）的结构性区别。
    A(Qi, Ki) = softmax(QiKi⊤√d), cross-attn = A(Qi,Ki)Vi
    Eq. 2
    Qi ∈ ℝTHW×d 是视频 query，Ki, Vi ∈ ℝ|τ|×d 是文本 key/value。论文引用 Shen et al. 的观察：不管架构是 UNet 还是 DiT，把文本信息「贴」到空间位置上的就是这一层——所以所有 grounding 方法都在打它的主意。
    ◆ 一个容易绕晕的措辞

    正文说「DiT 把文本和视频 token 拼接后过 self-attention，cross-attention 是其中的子运算」——这是为了同时覆盖 MMDiT 式的拼接架构。但 Alg. 1 里写的是 Wan2.2 的显式 cross-attention 分支（b.to_k(τ)、b.to_v(τ) 与视频流分开）。两种写法下 GATO-Vid 的落点是一样的：norm_q 之后、attention 之前的那个 q。

    2.2 RMSNorm：query 被钉在一张椭球面上

    这是后面所有几何操作的前提。现代 DiT 在 q/k 投影之后都会插一层 RMS Normalization：

    q ← √d q ⊙ γ‖q‖
    Eq. 3
    γ ∈ ℝd 是可学习缩放，⊙ 是逐元素乘。这个映射的像不是球面，而是一张超椭球面：把上式记作 v，则 v ⊘ γ = √d · q/‖q‖，于是恒有 ‖v ⊘ γ‖ = √d。所有进入 attention 的 query 都躺在这张曲面上——GATO-Vid 的注入必须把结果送回这张面。

    2.3 符号速查

    xt第 t 步的时空视频 latent，ℝC×T×H×W
    τtokenize + 文本编码后的 prompt，|τ| 个 d 维向量
    fθ冻结的 T2V flow-matching 生成器（本文 = Wan2.2）
    M / Mc目标框覆盖的视频 token 索引 / 其补集
    T / Tc指向目标物体的文本 token 索引 / 其补集
    Qi, Ki, Vi第 i 个 block 的 query（视频）/ key, value（文本）
    Bblock 总数；Wan2.2-A14B 为 40
    γRMSNorm 的可学习逐通道缩放，决定椭球形状
    b+ , b−解析求出的正 / 负单位方向向量
    λ±注入强度，扮演梯度法里学习率 μ 的角色（=1.5）
    SB施加注入的 block 集合（前 20 层）
    P(a, b)把 a 投影到 b 的正交补上（Eq. 15）
    03Why gradients break

    旧路：梯度引导为什么在 DiT 上走不通

    先把要打倒的对象写清楚。梯度引导分三步，每一步都在现代视频 DiT 上撞墙。

    (vt, {Qi, Ki}Bi=1) = fθ(xt, τ, t)
    Eq. 4
    ① 前向并把每层的 Q、K 全部留下。光是留住它们就已经不便宜。
    Ā = 1B BΣi=1 A(Qi, Ki)
    Eq. 5
    ② 求 B 层注意力图的均值。这一步是灾难的源头——它逼你把 A 显式写进显存。
    x′t = xt − μ ∇xt ℓ(Ā, M, T)
    Eq. 6
    ③ 对 latent 求梯度并更新。ℓ 通常是 Ā（在目标词上平均后）与 M 之间的 Dice 或 ℓ₂ 损失。对 输入 求梯度意味着计算图要覆盖整个网络。

    3.1 把「贵」换算成具体数字

    论文给出的实测是：单次反向 +300.31% 推理时间、+26 GB 显存（合计 59 GB，且只加载了双专家中的一个），而如果还要显式算注意力图和注意力损失，80 GB 的 H100 直接 OOM。下面这个滑块是我按 Wan2.2-A14B 的公开配置做的量级换算，帮助理解为什么会 OOM。

    ◆ 我的一点保留

    Eq. 5 的均值对全部 B 层取平均，所以梯度必须同时流经 40 层注意力分支——这确实很贵。但反过来看：GATO-Vid 自己的消融（§8）显示只用前 20 层甚至更少就够了。如果把同样的「只用前若干层」约束加到梯度法上，它的反向深度也会相应变浅，成本远没有 +300% 那么夸张。

    论文比较的是「全层梯度法」与「前 20 层无梯度法」，没有给出「前 20 层梯度法」这个更公平的对手。真正不可约的成本是显式 Ā 的显存（下图），而不是反向传播本身的深度。这不影响 GATO-Vid 的结论方向，但会影响你对「300%」这个数字的解读。

    04Step 1 · A solvable surrogate

    第一步：把目标函数换成一个能解析求解的分数

    梯度法之所以要梯度，是因为它的损失函数不可解析求极值——softmax 把一切都非线性化了。GATO-Vid 的第一刀砍在这里：如果我根本不做 softmax，只在 logits 上定义目标，那么目标对 query 是线性的，最优解可以直接写出来。

    4.1 为什么可以丢掉 softmax

    看单个 query qj 对第 l 个文本 key 的注意力：

    A(qj, Ki) = [ … , exp(qj·kl / √d)Σk∈Ki exp(qj·k / √d) , … ]
    Eq. 7
    要抬高这一项，只有两条路：抬高分子 qj·kl，或者 压低分母里其他 key 的贡献。而 exp(·) 对 qj·k 严格单调递增——所以「压低 exp 项」等价于「压低对应的内积」。两条路都可以只在内积上表达。
    A′(Q, K) = QK⊤
    Eq. 8
    于是直接拿 pre-softmax logits 当代理。注意这一步的性质：它保序但不保值——最优方向被保留了，最优步长没有任何保证。后面 λ± 要靠人手调，根源就在这里。

    4.2 三项分数：一个「抬」、两个「压」

    把 logits 矩阵按「query 在不在框里 × key 是不是目标词」切成四类，GATO-Vid 只对其中三类下手：

    4.3 因式分解：双和坍缩成三次点积

    这是全文最漂亮的一步。Eq. 9 的每一项都是「两个集合上的双重求和的平均」，而内积对求和是双线性的——所以求和可以先做完再点积：

    s = Q(M) · (K(T) − K(Tc)) − Q(Mc) · K(T)
    Q(M) = Σj∈M qj|M|, K(T) = Σl∈T kl|T|
    Eq. 10
    Eq. 11
    三万多个 query 和五百多个 key 之间的 1600 万次内积，坍缩成 4 个 d 维均值向量之间的 3 次点积。更关键的是：这个式子里再也没有「注意力图」这个对象了——不需要物化，自然也就不需要 FlashAttention 让路。
    05Step 2 · The closed form

    第二步：最优方向长什么样——两行就解完了

    Eq. 10 里 s 对 Q(M) 和 Q(Mc) 都是线性的。线性函数在单位球上的最大值点是初中知识：与系数向量同向。整个「优化」到此为止。

    5.1 为什么必须加单位范数约束

    如果不约束长度，s 是无界的——把 Q(M) 沿着正确方向拉到无穷，分数就到无穷。所以论文令 b+、b− 为单位向量去替换 Q(M)、Q(Mc)：

    s(b+, b−) = b+ · (K(T) − K(Tc)) − b− · K(T)
    Eq. 12
    两个变量互不耦合，可以分别求。项 (i) 和项 (ii) 合并成了一个方向 K(T)−K(Tc)——「靠近目标词、同时远离其他词」在向量空间里就是一个减法。
    b+ = K(T) − K(Tc)‖K(T) − K(Tc)‖, b− = −K(T)‖K(T)‖
    Eq. 13
    全文的核心结论。注意 b± 完全不含视频 query——它们只由该层的文本 key 决定。所以每层只需要算一次，就能广播给三万多个 token；这才是 +0.4% 的真正来源。
    ◆ 顺手能推出来的一个量（原文未列）

    把 Eq. 13 代回 Eq. 12，最优分数有干净的闭式：s* = ‖K(T) − K(Tc)‖ + ‖K(T)‖

    它只依赖文本键的几何：目标词与其余词分得越开（第一项大）、目标词本身范数越大（第二项大），这一层能提供的引导就越强。这解释了 Fig. 4c 的现象——早期 block 的注意力分数高，正是因为那里的 K 分离度更好。也提示了一个论文没做的事：可以用 s* 作为廉价指标自动挑选该注入哪些层，而不是手工定「前 20 层」。

    ▲ 这个「最优解」不能字面使用

    Eq. 13 的字面含义是：把框内所有 query 全部替换成同一个向量 b₊。真这么干，前景区的几万个 token 会瞬间同质化——它们的 query 完全相同，cross-attention 输出也完全相同，画面必然塌成一片。

    论文在 Eq. 14 前面用一句话带过（「直接替换或朴素相加会因为幅度不匹配破坏网络内部表示」），但真正的问题不只是幅度：是「最优」这个目标本身与「保留内容」是对立的。所以 b± 在实现中只能当作方向神谕，用 λ± 做一次有限插值。换句话说——这套推导给出的是方向的严格解，步长仍然是超参数，和梯度法的学习率 μ 处境完全一样。论文自己也承认这一点（「λ± 扮演学习率的角色」）。

    ◆ 单位范数与椭球约束之间的缝隙

    推导时把 Q(M) 约束成单位球上的向量，但真实的 query 被 RMSNorm 钉在椭球 ‖q ⊘ γ‖ = √d 上（Eq. 3）。两者只有在 γ 各向同性时才一致。严格做法应当在椭球约束下解 max b·c，其最优解是 b ∝ γ² ⊙ c（按 γ 的平方逐通道加权），而不是简单归一化的 c。

    论文选择了「先在球上解、再投影回椭球」的两段式做法（Eq. 13 → Eq. 14）。这在工程上更简单，但并不是那个约束优化问题的解。消融 (i) 显示去掉投影后 IoU 只从 0.363 掉到 0.355、但 AQ / IQ 明显变差，说明椭球这件事影响的主要是画质而非定位——从这个角度看，用更严格的 γ² 加权解也许还能再挤出一点画质。

    06Step 3 · Geometry-aware injection

    第三步：把方向注入回 RMSNorm 的椭球面

    现在有了方向，要把它塞进 query 里。论文的注入式由三个部件拼成，每个都在解决一个具体的失败模式。

    qj ← { √d‖(λ+b+‖qj‖ + qj) ⊘ γ‖ (λ+b+‖qj‖ + qj)若 j ∈ M √d‖(λ−b−‖qj‖ + qj) ⊘ γ‖ (λ−b−‖qj‖ + qj)若 j ∈ Mc
    Eq. 14
    三个部件：① 乘 ‖qj‖ —— 让扰动幅度相对于该 token 自身的尺度，而不是绝对量；② 乘 λ± —— 控制强度，等价于学习率；③ 前面那个系数 —— 把结果径向拉回 RMSNorm 椭球面。
    ◆ 一个必须看清的细节：重投影不改方向

    部件 ③ 只是一个正标量缩放：qnew = c · (q + λ‖q‖b)，c > 0。所以它完全不改变加法之后的方向，只把长度调回椭球面上。

    推论：query 转了多少度，全部由那一次加法决定，和重投影开关无关。设 θ 是 b 与 q 的夹角，把 b 分解到 q 方向与其正交方向上，立刻得到旋转角 φ：

    tan φ = λ sin θ1 + λ cos θ

    • b ⊥ q（θ = 90°）：φ = arctan(λ)。论文取 λ±=1.5 ⇒ 56.3°。这不是「轻微扰动」——它把 query 的方向掰过去了大半。
    • b 与 q 接近反向（θ → 180°）且 λ > 1：分母 1+λcos θ 变号，φ 一路逼近 180°，query 被整个翻面。这正是 §6.1 要用正交投影拦住的事故。

    所以 λ=1.5 给出的典型扭转在 56° 量级，最坏情况是彻底反向。这解释了为什么 GATO-Vid 只能在前 15% 的采样步里用——多用画质就垮。

    6.1 背景为什么要多一层正交投影

    论文的说法是「若 b− 与原 query 过于接近，加负偏置会扭曲已有的背景特征」，于是只保留 b− 中与 q 正交的那一份：

    P(a, b) = a − (a · b‖b‖) b‖b‖
    Eq. 15
    把 a 投到 b 的正交补上。代入 Eq. 14 的背景分支，就得到最终形式 Eq. 16：λ−P(b−‖qj‖, qj) + qj，再照旧重投影。
    ◆ 把这句话翻译成具体的事故

    假设某个背景 query 恰好 q ≈ −‖q‖·b−（即 q 本来就指向 K(T)，这在「画面里本来就有一只猫、但位置不对」时非常常见）。朴素更新给出

    q + λ‖q‖b− ≈ (1 − λ) q

    λ = 1.5 时结果是 −0.5 q：这个 token 的 query 被整个翻到反面，它的语义内容不是被「削弱」，而是被取反。加上 P 之后，同样的情形给出 P = 0，更新退化成不动——正确的兜底行为。这就是为什么消融 (i)「去掉椭球投影」只掉一点点，而正交投影这一层在原文里被单独拎出来讲。

    6.2 最后一块补丁：把 λ₊ 做成高斯

    真实的交叉注意力图在物体语义中心最强、向边缘衰减。如果对框内所有 query 施加同样的 λ₊，得到的注意力会均匀得很不自然。论文的处理是：给每一帧的包围框拟合一个归一化的二维高斯，用它去乘 λ₊——于是框内每个位置的注入强度不同。

    ◆ 完整配方（论文 §3.3 末段）

    ① 用高斯噪声采样 x0；② 在前 15% 的采样步、前 20 个 block 内，用该层文本 key 算出 b+、b−，按 Eq. 14 / 16 改写 query（λ±=1.5 并带线性衰减，框内再乘高斯）；③ 其余步骤完全按 Eq. 1 原样走。没有任何一步需要额外的前向或反向。

    算法逐行走读（含原文的三处对不上）

    下面是 Alg. 1 的逐行中译。点上面的按钮会高亮对应的行——请特别留意第 11、13 行，它们和正文 Eq. 13 / 16 不一致。

    Algorithm 1 · Bias InjectionRequire: fθ, x, t, τ ∈ ℝ|τ|×n, 目标图 M, 目标词 T, 注入层集合 SB
    1. x ← f.tokenize(x)　▷ 展平成 THW×n 的 token 序列
    2. for blk in fθ.blocks do
    3. x ← x + blk.SelfAttention(x)　▷ 视频自注意力，不动
    4. q,k,v ← blk.norm_q(blk.to_q(x)), blk.norm_k(blk.to_k(τ)), blk.to_v(τ)
    5. if blk ∈ SB then　▷ 只在前 20 层 × 前 15% 步
    6. b₊ = Normalize( mean(k[T]) − mean(k[T ᶜ]) )　▷ = Eq. 13 的 b⁺ ✓
    7. q′ ← q[M]　▷ 取出框内 query
    8. q′ ← q′ + λ₊‖q′‖ b₊　▷ 加正偏置
    9. q′ ← √n / ‖q′ ⊘ blk.norm_q.γ‖ · q′　▷ 重投影回超椭球
    10. q[M] ← q′
    11. b₋ = Normalize( mean(k[T ᶜ]) )　▷ ✗ 与 Eq. 13 冲突（见下）
    12. q′ ← q[M ᶜ]　▷ 取出框外 query
    13. q′ ← q′ − λ₊‖q′‖ b₋　▷ ✗ 缺正交投影 P，且用了 λ₊
    14. q′ ← √n / ‖q′ ⊘ blk.norm_q.γ‖ · q′
    15. q[M ᶜ] ← q′
    16. x ← x + blk.CrossAttention(q, k, v)　▷ 用改写后的 q 走原本的注意力
    17. x ← x + blk.FFN(x)
    18. return f.detokenize(x)
    ① 前 4 行完全是原生 Wan2.2 的 block 流程。关键是第 4 行：q 是 norm_q 之后的量——也就是说，注入的落点在 RMSNorm 的像上，这正是后面必须手动重投影回椭球的原因。
    ▲ 伪代码与正文的三处不一致
    • 第 11 行的 b₋ 方向错了。正文 Eq. 13 是 b⁻ = −K(T)/‖K(T)‖，配合 Eq. 14 的加法，效果是「背景 query 远离目标词」。而 Alg. 1 写的是 b₋ = Normalize(mean(k[T ᶜ])) 再做减法，效果变成「背景 query 远离其他词」——方向完全不同，甚至可能把背景 token 推向目标词。结合 Eq. 10 中负项写的是 −Q(M ᶜ)·K(T)，以及消融 (iv) 的描述（「移除 Eq. 10 的负向影响」），正文版本才是真实实现，第 11 行的 T ᶜ 应为 T。
    • 第 13 行丢了正交投影。Eq. 16 明确要求背景分支用 P(b⁻‖q‖, q)，伪代码里没有。考虑到 §6.1 那个「λ>1 时 query 被翻面」的事故，这一步不可能真的省掉。
    • 第 13 行用了 λ₊ 而非 λ₋。这条大概率无害——实现里两者都取 1.5。

    另外伪代码里的高斯调制也没有出现，维度字母从正文的 d 变成了 n。结论：把 Eq. 13/14/15/16 当作权威，把 Alg. 1 当作骨架。

    ◆ 注入是极其外科式的

    看第 16 行的残差结构：改写后的 q 只影响 cross-attention 这一支的输出，自注意力（第 3 行）已经跑完，FFN（第 17 行）拿到的是加过残差的 x。也就是说，每层的干预量被残差流稀释了一次；这解释了为什么需要 λ=1.5 这么大的值才有效果，也解释了为什么必须连做 20 层。

    消融：哪一块在出力，哪一块在保命

    四个消融（Set 1）。表面结论是「每一块都有用」，但把数字摆开看，四块零件的分工完全不同：两块负责定位，两块负责别把画面搞坏。

    (i) 去掉椭球重投影，改成朴素相加 q ← q + λ‖q‖b；(ii) 去掉高斯调制，框内 λ₊ 恒定；(iii) 去掉正偏置 b₊；(iv) 去掉负偏置 b₋。

    9.1 正负偏置的「超加性」

    ◆ 一个论文没给但很实用的推论

    如果你的场景更在意画质而非极限定位精度，「只开 b₊」是一个论文里没有单独推荐、但数据完全支持的配置：IoU 0.154→0.241（+56%），AQ 0.631→0.628（几乎无损），DD 0.248→0.258（甚至略升）。相比之下完整版把 IoU 再推到 0.363，但要付出 AQ −0.077、DD −0.145。这是一个非常清晰的两档旋钮，值得在实现里直接暴露出来。

    9.2 注入范围：为什么是「前 20 层 × 前 15% 步」

    迭代范围的消融（原文 Fig. 4a）结论是单调的：注入的采样步比例越大，IoU 越高、AQ 越低，作者取 15% 作为折中。原文只在散点旁标出 0.0 / 0.10 / 0.12 / 0.15 / 0.20 / 0.30 六个比例，不印任何 IoU / AQ 数值；加上 Fig. 4b 的读数已经与 Tab. 1 对不上（见上图注），这条曲线的绝对位置无法核实。因此本文不做复刻，只保留「比例越大 → IoU 越高、AQ 越低」这个单调趋势。

    10Limitations

    局限，以及我读下来的保留意见

    先说清楚：这篇论文的诚实度很高——画质代价、任务难度、基线普遍失效，作者都写在正文里而不是藏在附录。下面几条里，前三条是原文承认的，后面几条是我读的时候记下来的。

    10.1 原文自己承认的

    Trade-off
    定位换画质
    Set 1 上 DD 0.248→0.113（−55%）、AQ 0.631→0.551。原文措辞是「空间约束会导致更静态的构图」与「背景退化」。对视频而言这不是小代价。
    Task difficulty
    任务本身极难
    三个 SOTA 无梯度基线里有两个（VideoTetris / SwitchCraft）在 DiT 上几乎等同于什么都没做。原文把这一点当作贡献之一来陈述，是对的。
    Generality
    只验证了一个 backbone
    全部实验在 Wan2.2 上完成，超参（20 层 / 15% / λ=1.5）都是在它上面调出来的。

    10.2 我的保留意见

    ◆ 1 · 评测链路存在闭环风险

    Set 1 的「真实包围框」是这样来的：用 Wan2.2 自己生成参考视频 → 用 SAM 3 抽框 → 再用 SAM 3 评测生成结果。真值和裁判是同一个分割模型，而目标分布来自被测生成器自己。这会系统性地偏向「不太偏离 Wan2.2 原生行为」的方法——所以 Set 2（人造轨迹）才是更有说服力的那一组，而 GATO-Vid 在 Set 2 上的优势（IoU 0.324 vs 0.171）确实依然成立。

    ◆ 2 · IoU / CD 的幸存者偏差没有被消化

    原文明确说 CD 与 IoU「只在 SAM 3 成功检出的视频上计算」，也确实引入了 SR 来兜底，但表格里三个指标是并列呈现的。Peekaboo 在 Set 2 的 SR=49.2%，它的 0.171 IoU 与 GATO-Vid 的 0.324（SR=74.7%）不在同一个样本集上。更干净的做法是给一个「未检出记为 IoU=0」的悲观版指标；那样 Peekaboo 的 Set 2 成绩会进一步劣化，而 GATO-Vid 的领先幅度会更大——也就是说这个偏差不利于本文，作者没有利用它。

    ◆ 3 · 多物体场景是完全的空白

    整套推导从头到尾只有一个 M 和一个 T。可 b₊ 是对全体框内 query 广播的同一个向量——如果场景里有两个物体、两个框，就需要两个 b₊，而 M₁ 与 M₂ 之外的背景要同时远离 K(T₁) 和 K(T₂)，两个负偏置会在同一批 query 上互相干扰。论文没有讨论、没有实验、连一句 future work 都没提。而它比较的 Peekaboo 与 VideoTetris 都是明确支持多物体的方法。

    ◆ 4 · 「无梯度」不等于「无搜索」

    λ± 扮演的是学习率的角色，取值 1.5 是调出来的；注入层数、步数比例同理。这些都是外层超参搜索，成本没有出现在那个 +0.4% 里。公平地说，梯度法的 μ 也一样要调——但「gradient-free」这个卖点容易让人以为省掉了调参，实际上省掉的只是单次推理内的反向传播。

    ◆ 5 · 一个缺席的对照组

    既然消融证明「前 20 层就够」，那么一个只在前 20 层建注意力损失的浅层梯度法，反向深度只有全网的一半、显存也大幅下降。这个对手没有出现在表里。它未必能赢，但它是「梯度法真的贵到不可用吗」这个问题的直接答案。

    ◆ 6 · 代理与原目标的联系只有一个玩具实验支撑

    「最大化 s 等价于最小化 ℓ₂ 定位损失」这一步，全部证据是 Fig. 1b：一个三层随机初始化的交叉注意力模型，跑 100 次，看到 λ 增大时 ℓ₂ 单调下降。这说明在随机权重下方向是对的，但没有说明在训练好的 Wan2.2 上、在 softmax 的强非线性下，logit 空间的最优方向与真实注意力图的最优方向偏差有多大。最终结果好，但机制上的这一环是经验性的。

    11Relation to interactive world models

    放回「交互式视频世界模型」的坐标系里看

    这个仓库关心的是「用户给一个控制信号，视频要有响应」。包围框轨迹是这条线上最直观的一种空间控制，所以值得问一句：GATO-Vid 能不能直接拿来当世界模型的空间控制插件？

    11.1 它带来的三件好东西

    可叠加性
    零训练 · 零权重改动
    只要目标模型有 cross-attention 和 RMSNorm 的 query，就能挂上去。任何现成的 DiT 世界模型都是候选宿主。
    实时可行
    +0.4% · 显存几乎不增
    这是它对交互场景最关键的性质。梯度引导的 +26 GB 直接把消费级显卡排除在外，而交互式世界模型恰恰要跑在用户设备上。
    范式可迁移
    「推理时优化 → 闭式注入」
    这套推导的适用条件是：控制目标能写成 attention logits 的线性泛函。相机位姿、动作标签、深度提示，只要能表达成「某组 token 该和某组 key 更亲近」，都能照抄。

    11.2 但对世界模型来说，三个硬伤更疼

    ▲ 动态度掉一半，对世界模型是要害

    DD 0.248 → 0.113。对一个「生成漂亮视频」的任务，这是画质折损；对一个世界模型，动力学就是它要建模的东西本身。把场景按住来换定位精度，等于把要测的量给消掉了。

    ▲ 只在前 15% 步生效 ⇒ 无法做闭环控制

    交互的本质是「用户随时改主意，画面随时响应」。GATO-Vid 的注入窗口在采样早期，一旦布局定下来，后 85% 的步骤里控制信号已经无处施加。它是一个开局条件，不是一个控制回路。要用在自回归 rollout 的世界模型上，只能在每个新片段的开头重新注入——片段内部依然不可控。

    ▲ 单目标假设与交互场景不匹配

    交互式世界模型的典型画面里通常有多个可操纵实体。§10.2 第 3 条提到的多物体空白，在这个语境下不是「未来工作」，而是准入门槛。

    1. 先只实现 b₊ 分支（Alg. 1 第 6–10 行）。这一支最简单，且据消融 (iv) 应当能把 Set 1 的 IoU 推到 0.24 左右而画质几乎不掉——是一个干净的正确性检查点。

    D · 一句话摘要（可直接引用）

    GATO-Vid 把「用梯度优化交叉注意力图以实现空间定位」重写成「在 pre-softmax logit 空间定义一个三项代理分数」，该分数关于 query 是线性的，因而其在单位球上的最优方向有闭式解 b⁺ = (K(T)−K(Tᶜ))/‖·‖、b⁻ = −K(T)/‖K(T)‖；该方向仅依赖文本键，于是可以在 DiT 的每个 block 内部以 λ‖q‖ 的幅度加到 query 上、再径向重投影回 RMSNorm 椭球面完成注入。在 Wan2.2 上，以 +0.4% 推理开销把 Set 1 的 IoU 从 0.154 提到 0.363，代价是动态度 −55%、美学分 −0.08。

    E · 如果只记三件事

    ① 丢掉 softmax 换来的是线性，线性换来的是闭式解。整条推理链的起点就是「保序即可，不必保值」。

    ② 最优方向不含 query，所以能广播。这是 +0.4% 的全部秘密——每层只算两个均值向量，然后三万多个 token 共用。

    ③ 重投影只改长度不改方向，所以扭转量完全由那一次加法决定。tan φ = λ sin θ / (1 + λ cos θ)：b ⊥ q 时 φ = arctan(1.5) ≈ 56°；b 与 q 接近反向时 φ 可逼近 180°。这是画质代价的直接来源，也是它只能用在前 15% 步的原因。
