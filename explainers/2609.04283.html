DM-Align

把「加速」和「对齐」写成同一个分数空间里的两个梯度，一次训练同时做完

这篇论文要解决的是一个非常具体的工程死结：视频模型既要蒸馏（100 步 → 4 步）又要对齐人类偏好（RL）， 而这两件事按顺序做，哪个顺序都不对——先 RL 再蒸馏，RL 阶段每步要采样 20–40 次，慢到 423 s/step，而且蒸馏会把 RL 刚拿到的动态性还回去； 先蒸馏再 RL，少步模型的参数极度敏感，稀疏的 RL 梯度会直接把它打崩。 作者的解法不是调顺序，而是换框架：注意到 DMD 蒸馏的梯度本质是「真实模型分数 − 假模型分数」， 那么偏好对齐也可以写成同一形状的「偏好样本处的分数 − 当前生成处的分数」——两个梯度住在同一个分数空间、共用同一个假模型 μfake、共用同一批少步采样出来的样本， 于是可以直接线性相加，在一个阶段里同时优化。代价是每步只多 5 次函数求值（51 vs 46 NFE）。

00TL;DR

一图看懂：两个梯度长得一模一样，所以能直接相加

这篇论文的全部内容可以压进一句话：DMD 蒸馏的梯度是「两个网络在同一点上的分数之差」，作者把偏好对齐写成「同一个网络在两个点上的分数之差」， 于是它们成了同一个空间里的两个向量，加起来就行。其余所有工程收益——不用把扩散采样改写成 MDP、不用反时 SDE、不用 20–40 步采样、不用担心蒸馏后崩溃——都是这一步的推论。

① 蒸馏方向
清晰度从哪来

sreal − sfake，两个网络在同一个加噪点上的分数差。指向教师分布密度更高的方向，负责「像不像原模型」。

② 对齐方向
偏好从哪来

sfake(x⁺) − sfake(xgen)，同一个网络在两个不同样本上的分数差。指向人类偏好样本所在的位置。

共用的枢纽
假模型是全场唯一的估计器

μfake 既当①的减数，又当②③的全部。它靠一个纯去噪损失训练，因此论文说它是「一个异常鲁棒的去噪器」。

读这篇论文的正确姿势

不要把它当成「又一个 RLHF 变体」。它的立场是：传统 RL 那一整套（MDP 化、反时 SDE、轨迹概率、多步采样）对扩散模型是一层不必要的翻译层。 如果你要的只是「把分布往偏好方向推一点」，分布匹配本来就直接提供了这个操作——你只需要一个样本告诉它往哪推。所以叫 sample-guided：偏好是以样本形式、而不是以标量奖励+概率比的形式进入梯度的。

01The Deadlock

两阶段的死结：先 RL 太贵，后 RL 会崩

要把一个视频基座模型交付出去，通常要做两件事：蒸馏（把 100 步采样压到 4 步，否则没法用）和对齐（把生成推向人类偏好，否则不好看）。 现有做法把它们当成两个前后相接的阶段。论文 Fig. 1 左半边说的就是：这两个顺序都有问题，而且问题的性质完全不同。

1.1先 RL 再蒸馏：贵，而且蒸馏会把 RL 的成果吐回去

贵的原因有两层。表层是采样：RL 要拿到一条完整的生成轨迹才能打分，扩散模型采一次要 20–40 步，所以 DanceGRPO 一个优化步要 1536 次函数求值、423 秒。 深层是范式：现有 RL 方法必须把扩散的连续 ODE 轨迹改写成 RL 要的马尔可夫决策过程，这就要沿采样路径算轨迹概率，于是需要转成反时随机微分方程并依赖高斯假设。 论文对这一层的态度很直接——这是一层「为了套用现成算法而付出的翻译成本」，本身不产生任何生成质量。

更麻烦的是第二个问题：蒸馏会撤销 RL 的收益。Tab. 1 里这个证据非常干净：DanceGRPO 把 Dynamic Degree 从 56.40 推到 75.78， 接着做 DMD2 蒸馏，它掉回 60.85——一次蒸馏抹掉了 14.93，也就是 RL 涨幅的 77%。Pair 那一组同理：Flow-DPO 把 Dynamic Degree 推到 67.13，蒸馏后回到 53.43。 原因不难理解：蒸馏的目标函数就是「向教师看齐」，而教师正是那个没对齐过的模型。你在第一阶段推开的距离，第二阶段有一个显式的损失项在把它拉回来。

1.2先蒸馏再 RL：便宜，但会崩

反过来，先蒸馏拿到 4 步模型，再在这个快模型上做 RL——采样便宜了 25 倍，听起来是显然的做法。论文 Fig. 5 给出的是失败图：模糊伪影、闪烁，最后完全崩溃。 作者的解释是一句假设（原文用了 “We hypothesize”）：蒸馏模型的参数是超敏感的，少步生成依赖一个被压缩得很紧的连续映射，稀疏的 RL 梯度稍一扰动就把它打散。

我认为这个解释是对的但不完整，可以更具体一点：DMD 蒸馏出来的 4 步生成器，其输出流形是被 sreal − sfake 这个持续存在的约束顶住的。 一旦进入纯 RL 阶段，这个约束消失了，唯一剩下的信号是奖励模型的标量分。而奖励模型（论文自己在 §4.1 承认）对退化内容有严重的误判—— VideoAlign 会给纯白噪声和闪烁帧打出高的运动/视觉分。没有分布约束 + 奖励模型可被欺骗 = 标准的 reward hacking 崩溃路径。这一点很重要，因为它同时解释了本文为什么必须把 λDMD 一直保留着（见 §09 的 1:3 那一列）。

论文自己踩到的坑，写在了 §4.1 里

「我们观察到 VideoAlign 奖励模型会给退化内容（如纯白噪声或闪烁帧）错误地打出很高的运动/视觉分数。为了防止 DanceGRPO 和我们的方法训练崩溃，我们在 VidProM 上主要只用文本对齐（TA）这一项奖励。」

这句话的分量比它的篇幅大：它意味着 Tab. 1 下半部分那些漂亮的 Dynamic Degree / Aesthetic 提升，并不是被直接优化的目标，而是「只优化 TA」的副产物。这既是好消息（说明没有在指标上作弊），也是一个提醒（说明奖励模型本身仍是这条路线上最脆的一环）。

02Background · DMD

DMD 回顾：三个模型、一个分数差、一个加噪技巧

要理解本文的贡献，必须先把 DMD 的梯度看成一个几何对象而不是一个损失函数。这一节把 §3.1 的三个式子摊开，并配一个可以拖的一维探针。

2.1目标：让学生的分布贴上教师的分布

DMD 的目标是最小化学生（少步生成器）输出分布与教师（多步原模型）分布之间的 KL 散度：

式 (1) LDMD = DKL( pfake ‖ preal ) = 𝔼z~𝒩(0,I), x=Gθ(z) [ −( log preal(x) − log pfake(x) ) ] 注意方向是 反向 KL（pfake 在前）。反向 KL 是「mode-seeking」的：它惩罚「学生在教师没有密度的地方生成」，但不太惩罚「学生漏掉教师的某个模式」。这正是少步蒸馏想要的性质——宁可少样，不要糊。同时这也是后面 §11 里多样性问题的根源。

2.2梯度：密度算不出来，但分数差算得出来

式 (1) 里的两个 log p 都无法直接估计。DMD 的做法是只求梯度——对 θ 求导后，密度变成了分数（score），而分数恰好就是扩散模型在训练的东西：

式 (2) ∇θLDMD ≈ −𝔼t,z [ ( sreal(F(Gθ(z),t), t) − sfake(F(Gθ(z),t), t) ) · dGθ(z)dθ ] 三处细节值得记住。（i）F(·,t) 是前向加噪：不加噪的话两个分布的支撑集几乎不相交，分数差要么是 0 要么是无穷；加噪把两个流形「泡开」，让它们重叠，梯度才有定义。（ii）两个分数在同一个加噪点 xt 上求值——这是式 (2) 成立的前提。（iii）dGθ/dθ 把「样本空间里的一个方向」翻译成「参数空间里的一个方向」，所以整个方法只需要给生成器输出一个目标位移向量。

2.3假模型：一个只会去噪的陪练

式 (2) 里的 sreal 由冻结的教师提供；sfake 没有现成的，所以 DMD 现训一个：

式 (3) Ldenoiseϕ = ‖ μfakeϕ(xt, t) − x0 ‖22,　　x0 = Gθ(z),　xt = F(x0, t) 就是标准扩散训练，只不过数据集是生成器此刻的输出。因此 μfake 是一个「追着生成器跑」的分布估计器。它通过 Tweedie 公式与分数相连：s(xt,t) = (αt μ(xt,t) − xt) / σt²。这条换算关系是 §04 全部推敲的工具。
一句话记住 DMD

它给生成器的不是「损失」，而是一个逐样本的位移向量：「你现在在这儿，教师的密度更高的方向在那儿，往那边挪一点」。这个接口非常宽——只要你能说出「那儿」在哪，任何目标都能塞进来。本文塞进去的就是「人类偏好样本在那儿」。

03The Pivot

把「对齐」重写成「分布匹配」：只需要 RLHF 教科书的第一页

这一步是纯粹的改写，没有新东西，但它决定了后面所有的形状。论文用两个式子把「最大化奖励」翻译成「向某个目标分布做分布匹配」。

3.1最优策略有闭式解，所以「对齐」本来就是一个分布

在 Bradley–Terry 假设下的标准 RLHF 里，「在不跑离参考分布太远的前提下最大化期望奖励」这个约束优化问题有闭式最优解（这是 DPO 推导的起点，也是 KL 正则化策略搜索的经典结果）：

式 (4) p*(x) = 1Z pref(x) · exp( r(x)β ) 读法：把参考分布按奖励做指数重加权。β 小 → 尖锐地压向高奖励区；β 大 → 几乎不动。Z 是配分函数，算不出来，但做分布匹配时求梯度会把它消掉——这正是可以往下走的原因。

既然对齐的目标是一个分布 p*，那么「对齐」就可以写成 DKL(pθ ‖ p*) 的最小化——形状和式 (1) 一模一样。走一遍和 DMD 完全相同的重参数化推导，梯度同样落到分数域：

式 (5) ∇θLalign ≈ −𝔼t,z [ ( ∇xt log p*t(xt) − ∇xt log pθ,t(xt) ) · dGθ(z)dθ ] 把式 (5) 和式 (2) 并排看：它们是同一个式子，只是把 preal 换成了 p*。这就是论文说的 gradient compatibility（梯度兼容性）。两个梯度住在同一个向量空间（分数空间），量纲一致、作用点一致（都通过 dGθ/dθ 施加给生成器输出），所以相加是有意义的——这不是随手把两个 loss 加起来。
为什么这一步就已经绕开了传统 RL 的全部麻烦

传统扩散 RL 要的是「这条采样轨迹的对数概率」，因为 PPO/GRPO 的目标里有 πθ(a|s) 的比值。为了算它，必须把 ODE 采样改写成反时 SDE、假设每步转移是高斯、再沿路径累乘。 式 (5) 里根本没有轨迹：它只需要「终点样本」和「分数」。Z 消失了、β 被吸收进了后面的权重 λ、轨迹概率从来没出现过。整层翻译成本被删掉了。

我的一点提醒：β 去哪了

式 (4) 里的 β 控制「向偏好走多远 vs 向参考分布靠多紧」。式 (5) 之后它再也没出现过。实际上它的角色被 λDMD : λalign 接管了——而且接管得并不完全等价： β 的锚点是 pref（原始预训练模型），而 λDMD 的锚点是教师 preal。在这篇论文里两者恰好是同一个模型，所以看不出区别；但如果有人把这套框架用在「教师 ≠ 参考」的场景（比如教师已经被别的方法微调过），这个隐含等价就会失效。§09 的权重敏感性分析（Tab. 5）实际上就是在实验层面标定这个 β。

04The Core Approximation

核心近似：用假模型「看一眼偏好样本」当作目标分数

式 (5) 里有一项是算不出来的：∇ log p*t。整篇论文的技术贡献就是它的替代品。这一节先把论文的做法讲清楚，再把我自己的核对过程完整摆出来——因为这里有一处我认为写得不够严谨、但很可能实现上是对的地方。

4.1论文的替换：一行，但是全文的支点

作者的观察是：μfake 被式 (3) 持续训练，是一个异常鲁棒的去噪器；由 Tweedie 公式，去噪预测和分数一一对应。 因此，把一个人类偏好样本 x⁺ 加噪后送进 μfake，得到的是「它在已学到的高奖励流形上的隐式投影」（原文：an implicit projection onto the learned high-reward manifold）。于是：

式 (6) ∇θLalign ≈ −𝔼t,z [ ( sfake(F(x⁺,t), t) − sfake(F(Gθ(z),t), t) ) · dGθdθ ] 与式 (2) 逐项对照：sreal(xt) → sfake(F(x⁺,t))，sfake(xt) → sfake(F(Gθ(z),t))。教师被「偏好样本 + 假模型」这个组合替代了。代价：一次额外的 μfake 前向（外加对 x⁺ 的加噪），这就是 Tab. 3 里 51 − 46 = 5 NFE 的来源。

4.2我卡住的地方：式 (2) 和式 (6) 的结构其实不一样

把两式的括号内部并排写出来，差别就很明显：

  • 式 (2)：sreal(xt) − sfake(xt) —— 两个不同的函数，在同一个点上求值。
  • 式 (5)：∇log p*t(xt) − ∇log pθ,t(xt) —— 同样是两个函数、一个点。这是 KL 梯度成立的前提。
  • 式 (6)：sfake(x⁺t) − sfake(xt) —— 同一个函数，在两个不同的点上求值。

论文把这一步写成「用 sfake(F(x⁺,t),t) 近似 ∇log p*t(xt)」，但没有给出这个近似的误差分析或条件。我按 Tweedie 把它展开算了一遍，结果值得摆出来。取方差爆炸式记号 xt = x0 + σtε（αt=1，只是为了少写符号），Tweedie 给出 s(xt) = (μ(xt) − xt)/σt²，于是：

sfake(x⁺t) − sfake(xt) = 1σt² { [ μfake(x⁺t) − μfake(xt) ] − [ x⁺t − xt ] } 第一个方括号是「两次去噪预测之差」，第二个方括号是「两个输入之差」。如果 μfake 是个好去噪器（μ(x⁺t) ≈ x⁺、μ(xt) ≈ x），两个方括号几乎相等，整个式子被减到只剩噪声项。反过来，如果 μfake 确实像论文说的那样把 x⁺ 投影回它学到的流形，那么差值 ≈ (P(x⁺) − x⁺)/σ²——方向是从偏好样本指回生成器流形，也就是我们想要的反方向。

换句话说：把式 (6) 当作字面意义上的分数差来读，它要么退化成噪声，要么符号相反。这不是小数点级别的疑问，所以我把这个玩具算例做成了下面的图，读者可以自己拨参数验证。

4.3最可能的解释：实现里用的是去噪预测差，不是字面分数差

以下是我的推断，不是论文的陈述；论文未放代码，我无法验证

在所有 DMD 的实际实现里，传给生成器的位移向量都不是按 (α μ − xt)/σ² 逐项算出来再相减的，而是直接写成两个去噪预测之差： sreal(xt) − sfake(xt) = αt[μreal(xt) − μfake(xt)]/σt²——因为两项的 xt 完全相同、精确抵消。 如果实现时沿用了同一段代码、只是把两个网络换成「同一个网络的两次前向」，那么算出来的就是：

g ∝ μfake(F(x⁺,t)) − μfake(F(xfinal,t)) ≈ x⁺ − xfinal

这个量方向正确、大小合理、不退化，而且完全对得上论文所有的文字描述（「把生成拉向偏好锚点」「利用假模型统一的去噪向量场提供稠密、稳定的引导」）。 我倾向于认为式 (6) 是一个为了和式 (2) 形式对齐而写的分数域表述，实际实现走的是去噪预测域；两者在 DMD 原本的场景下等价，在这里不等价，论文没有指出这一点。

如果这个推断成立，还有一个副产品值得注意：μfake 是非线性且随 t 变化的。t 大时两个输入都被映射到粗结构上，差值主要反映低频/结构性的差异；t 小时才落到细节。 所以「在 t~U(0,1) 上取期望」实际上是在做一个多尺度的偏好差分，这大概率就是论文说的「shifts the model's overall distribution toward optimal structural preferences」的真正来源，而不只是修辞。

还有一个更朴素的问题：x⁺ 不是 p* 的样本

式 (4) 定义的 p* 是「参考分布按奖励重加权」。但 DM-Pair 里的 x⁺ 来自 ConsistID 的真实视频（§4.1），它是数据分布的样本，不是 p* 的样本——两者只有在「参考模型已经完美拟合数据」时才重合。 论文在 §4.1 用了一个务实的辩护：真实视频比生成内容有「更自然流畅的人体运动和真实物理动态，为偏好对齐提供了更好的上界」。这个辩护我认为是成立的，但它意味着 DM-Pair 实际上更接近「用分数场做的 SFT」而不是 DPO： 没有 Bradley–Terry、没有参考模型概率比、没有 log-sigmoid 饱和，负例是生成器自己的输出而非标注的 lose 样本。称它 “inspired by DPO” 是合理的，但读者不该期待它继承 DPO 的任何理论性质。

05DM-PairLoss

DM-PairLoss：把一段真实视频当成「往哪走」的路标

Pair 变体是两个实现里更简单的那个：式 (6) 原样使用，x⁺ 直接从预标注的正样本里取。论文只用了一小段描述它，但里面有三个决定值得单独拎出来。

决定一 · 正例
用真实视频，不用「更好的生成」

数据是过滤后的 ConsistID（约 6K，人物中心）。论文的理由：真实视频的人体运动和物理动态比任何生成内容都更自然，因此提供了更高的对齐上界。

决定二 · 负例
负例是免费的

不需要标注 lose 样本——生成器当前的 xfinal 自动就是负端。这也意味着负例随训练自动变强，对比度会随收敛自然收窄。

决定三 · 用哪个样本
负端必须是 x_final

不是 DMD 那个中间态 x，而是完整 4 步跑完的成品。只有成品才和 x⁺ 处在同一个「干净样本」空间，两者加同一档噪声才可比。

还有一个论文没有明说、但从 Algorithm 1 第 16 行读得出来的细节：x⁺ ← sample(Dpref, c) ——正样本是按当前 prompt c 条件取的，不是随机抽一个漂亮视频。 这很关键：如果 x⁺ 和 xfinal 内容完全无关，那么 x⁺ − xfinal 里绝大部分是「内容差异」而不是「质量差异」，梯度会把生成器往一个随机的内容方向推。 条件配对把内容差异压下去，剩下的才是论文想要的结构性偏好差异。也正因如此，Pair 变体天然受限于成对高质量数据的可得性——这是它和 Group 变体最实际的分工线。

Pair 变体的适用边界

它要求：（i）有条件配对的高质量真实数据；（ii）该数据与目标 prompt 分布同域。ConsistID 是人物中心数据集，所以论文 Tab. 1 上半部分的评测也在 ConsistID 上——这是自洽的，但也意味着这一组数字不能直接外推到通用 T2V。论文自己在 §4.4 用「只用 prompt 的交叉评测」（Tab. 6）回应了这个质疑，见 §09.4。

06DM-GroupLoss

DM-GroupLoss：没有标注数据时，把锚点现场造出来

Group 变体解决 Pair 变体的数据依赖：给定一个 prompt，采 K = 8 个输出，用奖励模型打分算优势， 再把分数最高的 4 个样本取平均当作偏好锚点 x̄⁺。整组样本按优势加权地推开或拉回。

式 (7) ∇θLDM-Group ≈ −𝔼t,z [ Σi=1K Ai ( sfake(F(xi,t),t) − sfake(F(x̄⁺,t),t) ) dGθdθ ] 注意括号内的顺序和式 (6) 是反的（式 (6) 是「偏好 − 生成」，这里是「生成 − 锚点」），符号由 Ai 补回来：Ai < 0 的差样本被拉向锚点；Ai > 0 的好样本被沿自身方向继续外推，越过锚点、朝偏好流形的峰去。这一正一负是论文说的「动态分布偏移」。

6.1一个代数上的观察：优势一旦中心化，锚点就不影响净梯度

把式 (7) 的求和拆开（用 §04.3 的去噪读法记 m(x) ≡ μfake(F(x,t))）：

Σi Ai [ m(xi) − m(x̄⁺) ] = Σi Ai m(xi) − ( Σi Ai ) m(x̄⁺) 因为 m(x̄⁺) 与 i 无关，可以提出求和号。如果 Ai 按 GRPO 惯例做组内标准化（Ai = (ri − r̄)/std），则 Σ Ai = 0，第二项整体消失。

论文只说「compute their rewards and advantages Ai」，没有写 Ai 的具体定义。于是有两种可能，各有各的含义：

  • 如果做了标准中心化：锚点 x̄⁺ 在期望意义上不影响梯度方向，它的作用是控制变量（control variate）——在每个 minibatch 的随机估计里降低方差，尤其是当 m(·) 的输出量级很大时。这是一个正当而且常见的做法，但和论文正文的描述（「把差样本拉向高质量组均值」）在因果上不是一回事：真正决定方向的是 Σ Ai m(xi)，锚点只是把公共部分减掉。
  • 如果没有中心化（比如直接用归一化奖励），那么锚点是实质性的：它把整个组的位移额外平移了 −(ΣAi)·m(x̄⁺)，等价于一个指向锚点的全局偏置。这时「top-4 均值」这个设计才真的在起结构性作用。

这是我认为论文最该补一行说明的地方——因为它决定了「top-k 锚点」到底是核心设计还是方差削减技巧。上面的图把两种情况都做出来了，读者可以自己切换看数字。

另一个必须问的问题：K=8 的样本从哪来，NFE 怎么只多了 5

Tab. 3 说 DM-Align 每步 51 NFE，只比 DMD2 的 46 多 5。但 Group 变体要为一个 prompt 采 K = 8 个样本，即使每个只要 4 步，也是 32 次额外前向。两个数对不上。

我能想到的最自洽解释是：论文用 32 张 H100、每卡 batch size = 1（§4.1），所以「一组 8 个样本」很可能是跨数据并行的 8 张卡凑出来的——每张卡仍然只生成 1 个样本，组内统计通过 all-gather 完成。这样 51 NFE 就是每卡的数字，和 Group 变体不矛盾。 如果这个解释对，那么 Tab. 3 的 51 NFE 对 Pair 和 Group 都成立，但也意味着 K 的可调范围被 GPU 数绑死了。论文没有讨论这一点，也没有做 K 的消融。

07The Training Loop

统一单阶段循环：26 行伪代码里藏着三个设计决定

Algorithm 1 本身很短，但它的缩进结构比内容更值得读——哪一行在 if 外面、哪一行在里面，决定了这套方法的真实开销和稳定性。

式 (8) Ltotal = λDMD LDMD + λalign Lalign 论文 §3.3 的总损失，两项各取 0.5。它在 Algorithm 1 里以梯度形式出现（第 22 行）。「相加」在这里之所以合法，全靠 §03 那个观察：两项是同一个分数空间里的向量。

7.1决定一：一次采样，三处复用

第 6 行返回两个东西 (x, xfinal)，随后被三条路吃掉：假模型的去噪训练用 x（第 9–10 行，带 stopgrad）； DMD 梯度用 x（第 14 行）；对齐梯度用 xfinal（第 17 / 20 行）。 对齐几乎不额外产生采样开销——这是「51 vs 46 NFE」的全部秘密，也是本文能声称「单阶段几乎免费」的唯一依据。

顺带一个证据：第 19 行是 x_group ← groupSamples(x_final, K)，动词是「从已有的 xfinal 里切出一组」，而不是「再采 K 个」。 这和我在 §06 末尾的推测一致：组是从已有 batch（跨数据并行）里凑的，不是新生成的，所以 Group 变体也不额外增加 NFE。

7.2决定二：两个 timestep 是分开采的

第 5 行采的是蒸馏时间步 τ ~ Uniform{1000, 750, 500, 250}——它决定生成器这一次走到少步轨迹的哪个节点上； 第 8 / 13 行采的是去噪时间步 t ~ U(0,1)——它决定用多大的噪声去「泡开」两个分布以求分数。 这两件事在概念上完全独立，论文特意分开采样（§3.3 原文：“the DMD and DM-Align gradients are evaluated after applying forward noise at an independently sampled level t ~ U(0,1)”）。 混淆这两个 t 是读 DMD 系论文最常见的错误，值得单独记一笔。

7.3决定三：不做 DMD-only 预热

直觉上应该先纯蒸馏几百步、等生成质量起来再加对齐——否则早期的生成全是糊的，奖励模型打分毫无意义。论文明确说不需要，给了两条理由：

  • 即使早期生成模糊，粗色块和基本运动模式已经足以提供相对优势——注意 Group 变体用的是组内相对比较，不是绝对分数，所以只要排序大致对，方向就大致对。这是 GRPO 类方法一个被低估的鲁棒性来源。
  • 早期阶段 DMD 梯度本身量级就占优，会自动主导，无需显式调度。

不过论文还是测了一个 “Varying” 调度（λDMD:λalign 从 1:0 线性走到 1:3），结果不如固定 1:1（Tab. 5：Wan-1.3B 上 TA 1.45 vs 1.65，HPSv2 27.56 vs 28.89）。 这个负结果其实挺有意思：它说明「后期加大对齐权重」是有害的，和「1:3 会崩」是同一个现象的两种表现——蒸馏项不是脚手架，是必须一直在场的约束。

训练稳定性：论文声称不依赖 EMA

§4.1 提到 DanceGRPO 和 Flow-DPO 这类基线严重依赖 EMA 来维持稳定，去掉 EMA 生成质量就会退化；而本文框架「natively 收敛稳定」。 但要注意论文自己也用了 EMA（step 500 起，decay 0.99），所以这个对比是「依赖程度」的差别而不是「用不用」的差别。论文没有给去掉 EMA 的消融，这条声明目前只有文字支持。

10Why Not X

两条「看起来更自然」的路，论文为什么说走不通

10.1为什么不直接把 RL 损失加到 DMD 上

这是最省事的做法，也是并行工作 FlashDMD、DMDR 的做法：保留现成的 GRPO/DPO 损失，和 DMD 损失相加。论文做了这个变体（DanceGRPO 损失 + DMD 损失），结论见论文 Fig. 6：奖励曲线几乎和纯 DMD 重合，对齐基本没发生。

论文给的解释是：标准 RL 损失为了在连续生成模型上不崩，被设计得过于保守（裁剪、KL 惩罚、小步长），梯度太弱，被 DMD 梯度淹没。我认为这个解释成立，但可以说得更结构化——两种「相加」的区别在于：

  • 损失相加（loss addition）：两个损失来自不同的数学对象（一个是分布散度，一个是策略梯度期望），量纲不可比，梯度量级只能靠 λ 硬调，而且 RL 那一项的梯度是稀疏的（只有采到的轨迹上有信号）。
  • 梯度相加（gradient composition，本文）：两项都是分数空间里的向量，量纲天然一致，作用点相同（都通过 dGθ/dθ），而且都是稠密的（对每个样本的每个像素/隐变量都有分量）。

论文原话说自己提供的是「dense, stable, and highly compatible guidance」，稠密性我认为是这里最本质的那个词。不过论文 Fig. 6 只画了奖励曲线，没有给这个变体的 VBench 分数或调参范围——严格说，这个对照实验证明的是「按论文的调法加不动」，而不是「原理上加不动」。

10.2为什么不做两阶段

这一条 §01 已经拆过，这里补一个论文没写但值得点破的对称性：两个方向的失败原因其实是同一个——都是「后一个阶段的目标函数不认识前一个阶段的成果」。

  • RL → 蒸馏：蒸馏的目标是靠近教师，而教师是未对齐的，所以它有一个显式的项在撤销对齐。表现为分数回落（可测、渐进、不崩）。
  • 蒸馏 → RL：RL 的目标里没有任何项在维护少步能力，同时奖励模型可以被退化内容骗（§4.1 自陈）。表现为崩溃（不可测、突然、不可逆）。

本文的单阶段之所以两边都躲开，是因为 λDMDLDMD 这一项永远在场：它既是「保持少步能力」的约束，又是「不许跑出教师分布」的正则。Tab. 5 的 1:3 那一列就是把这个约束调弱后的实证：四组里有三组跌破了纯蒸馏基线，退化的方向和「蒸馏后再 RL」是同一种。

我读下来认为这篇论文最有价值的一句话

不是「我们更快更好」，而是：当两个优化目标可以被写成同一个空间里的向量时，它们就不再需要按阶段排队。 这句话的适用面比视频生成宽得多——任何「先做 A 再做 B，结果 B 撤销 A」的两阶段流程，都值得先问一句：A 和 B 的梯度能不能被写成同一个形状。

11Limitations & Reservations

论文自陈的局限，和我读下来的保留意见

11.1论文自己写的两条（§4.5）

局限一
加权求和没有收敛保证

虽然对齐梯度有推导，但「两个梯度加权相加」这个联合优化动力学缺乏严格的收敛性理论。论文用词是 “lack strict theoretical convergence guarantees”。Tab. 5 的 1:3 崩塌就是这个缺口的实证边界。

局限二
被绑在 DMD 系上

整个框架依赖「有一个持续训练的 μfake 提供分数」这个前提，因此无法用于 GAN 系的蒸馏方法（如 APT、PoSE）。论文认为这是可接受的取舍，因为 DMD 系已被社区验证为视频任务上最稳的一支。

论文同时给了一个正面论证：DM-Align 是正交的分数梯度提供者，所以可以和后续的 DMD 增强（Phased DMD、TDM 等）叠加。这个说法我认为是合理的——只要 μfake 还在，第二个梯度就还能加。

11.2我的保留意见

一 · 式 (6) 的推导有一处结构性跳跃

这是最重要的一条，§04 已经完整展开：式 (5) 要的是两个分数场在同一点的差，式 (6) 给的是同一个分数场在两点的差。 按 Tweedie 展开后，字面读法要么退化成噪声、要么符号相反；只有按「去噪预测差」读才成立。我倾向于认为实现是对的、表述不够严谨，但论文没有放代码，这一点无法证实。 对读者的实际影响：如果你要复现，务必按 μfake(x⁺t) − μfake(xt) 实现，而不是按字面的分数差。

二 · 「x⁺ 是 p* 的样本」这个身份从未被验证

式 (4) 定义的 p* 依赖奖励模型 r 和温度 β；而 Pair 变体的 x⁺ 是真实视频，与 r、β 都无关。 换句话说，Pair 变体在 §3.2 的理论框架下其实没有落点——它的合理性来自「真实数据更好」这个经验判断，不来自式 (4)。这不影响它有效，但影响「统一框架」这个叙事的完整性：真正落在框架里的只有 Group 变体。

三 · 反向 KL + 单一锚点，多样性没有被测量

DMD 的目标是反向 KL（mode-seeking），本身就偏向收窄分布；DM-Align 在此之上再加一个指向偏好锚点的力。两个收窄的力叠加，多样性会怎样？ 论文完全没有报告任何多样性指标——没有 recall/coverage，没有同 prompt 多次采样的方差，VBench 的六项也都不测这个。Tab. 5 里 1:3 的崩塌大概率就是多样性彻底塌掉的表现，但那是极端点；1:1 时塌了多少，我们不知道。 考虑到 Group 变体的锚点是「top-4 均值」——均值本身就是一个比任何单个样本都更「平均」的目标——我认为这个风险不小。

四 · 只在 1.3B 上做完整对照，14B 只有一行

主表全部基于 Wan2.1-T2V-1.3B。MoE 的 Wan2.2-A14B 只有 Tab. 4 的三个数（80.00 / 78.35 / 83.45），没有基线细分、没有人评、没有指标拆解，而且「只对齐 high-noise 专家」这个关键设计没有对照实验（没有「只对齐 low-noise」或「两个都对齐」的数字）。 这一条对论文的核心论点影响不大，但「scalability to MoE」这个小标题目前是被一行数字支撑的。

五 · 视频是动的，评测却主要是逐帧的

Group 变体的奖励是 HPSv2 时，论文明确说「按惯例把每帧的图像分数取平均」得到视频奖励。逐帧平均的奖励对时间维度是完全盲的——它无法区分「一段流畅的运动」和「一串各自好看但抖动的帧」。 VideoAlign 是视频原生的，好一些，但论文因为它对退化内容误判而只用了 TA 一项。所以严格说：本文在时间维度上真正被优化的信号非常有限，而 Dynamic Degree 的大幅提升是间接得来的。这既是好消息（泛化），也让人想知道如果直接优化运动质量会怎样。

六 · 一个小的记账问题

Tab. 3 的 51 NFE 与 Group 变体的 K=8 表面上矛盾，我在 §06 和 §07 给出了「组是从已有 batch 里切的」这个解释，并且 Algorithm 1 第 19 行的措辞支持它。 但论文没有明说，而这直接影响读者估算复现成本（如果你只有 8 张卡，K=8 意味着什么？）。这属于可以一句话补上的信息缺口。

11.3那么，这篇论文的贡献到底有多硬

把上面所有意见放在一起，我的判断是：工程贡献非常硬，理论叙事偏软。

  • 硬的部分：「一次采样喂三条梯度」这个工程结构是实打实的，51 vs 1536 NFE 不是修辞；「两阶段会互相撤销」这个对照是干净的、别人绕不开的；四种骨架/奖励组合上的稳健性也做了。这套东西如果开源，我认为会被广泛采用。
  • 软的部分：从式 (5) 到式 (6) 的那一步近似缺乏误差分析；Pair 变体没有真正落在自己的理论框架里；多样性完全没有被测量。论文自己也承认「本文的算法设计有意优先考虑简洁性与基础验证」——这是诚实的定位。

换个角度说：这篇论文的价值不在于「DM-Align 这个损失是对的」，而在于「蒸馏和对齐可以共用一个分数估计器」这个观察被落实成了可跑的代码结构。即使式 (6) 的具体形式将来被更严格的推导替换掉，Fig. 2 那个「一次采样、两股梯度、共享 μfake」的骨架大概率会留下来。

12In Context

放回 Awesome-Interactive-Video-World-Models 的坐标系里

按本仓库的三条严格标准逐条对照，这篇论文三条都不满足——它不是一个交互式视频世界模型，也不打算是。 但它落在仓库「宽口径」的第二条轴上：实时与流式生成里的蒸馏子方向，而且落得很正。

严格标准本文判定
逐步动作条件纯 T2V，一个 prompt 给到底，没有动作接口不满足
因果 / 流式生成整段 5 秒双向去噪，4 步一次出完不满足
持久世界状态无显式记忆，无跨段状态不满足
宽口径 · 实时与流式生成100 步 → 4 步的少步蒸馏，且不牺牲偏好对齐正中

为什么一个非交互的 T2V 蒸馏工作值得进这个列表：交互式世界模型的延迟预算是逐帧的，所有已知的实时系统都建立在少步蒸馏之上。 而少步蒸馏一旦和「对齐」冲突，实时系统就只能在「快」和「好」之间二选一。这篇论文说的正是：这个二选一不是必然的，只要你换个框架。

仓库里几条明显相邻的线索（以下仅按各自标题判断关系，未逐篇精读）：

  • Reward Forcing（arXiv 2512.04678，Efficient Streaming Video Generation with Rewarded Distribution Matching Distillation）——从标题看是最近的一篇，同样是「奖励 + DMD」，但落在流式生成上。本文没有引用它，值得并读。
  • Self Forcing（arXiv 2506.08009）与 DMD 系的因果化路线——本文的 μfake 机制与之同源（论文引了 Self Forcing，编号 [14]）。
  • KVPO（arXiv 2605.14278，ODE-Native GRPO for Autoregressive Video Alignment）——从标题看，同样是「不做 SDE 转换」的对齐路线，但走的是 KV 语义探索而非分布匹配。这两条路线的对比会很有意思。
  • RAVEN（arXiv 2605.15190，Real-time Autoregressive Video Extrapolation with Consistency-model GRPO）——一致性模型 + GRPO 的实时组合。
  • 论文自己点名的两个并行工作：FlashDMD（2511.20549）与 DMDR（2511.13649），都是「蒸馏 + RL 联合优化」，但走的是「损失相加」路线，且都是图像域。本文的差异化正是 §10.1 那一节。

如果要给这篇论文在仓库里选一个位置，我会放进 Real-Time & Streaming Generation，并在描述里点出「preference-aligned distillation」这个子标签——因为它和纯加速的蒸馏工作（采样器、缓存、稀疏注意力）解决的不是同一个问题。

C术语

Distribution Matching Distillation (DMD)
Yin et al. 2024 提出的蒸馏范式：交替训练「假模型」与生成器，最小化生成分布与教师分布的反向 KL。本文全部建立在它之上（DMD2 = 其改进版）。
Tweedie 公式
把「去噪预测」和「分数」联系起来的恒等式：s(xt,t) = (αt·x̂0(xt,t) − xt)/σt²。有了它，任何扩散去噪器都可以当分数估计器用——这是本文能把 μfake 当作「目标分数」的技术前提。
NFE (Number of Function Evaluations)
神经网络前向次数。在推理语境里≈采样步数（本文 4 vs 100）；在训练语境里是每个优化步的总前向次数（本文 51 vs DanceGRPO 1536）。两个语境的 NFE 不是一回事，读 Tab. 1 和 Tab. 3 时要分开。
GSB 协议
人评常用的三分法：Good / Same / Bad。「净偏好」= Good 比例 − Bad 比例。论文 Fig. 3 只报了净值。
VBench 的六个维度
本文用到：主体一致性、背景一致性（时序一致）、运动平滑度、动态程度（运动质量）、美学质量、成像质量（视觉质量）。动态程度与运动平滑度存在天然张力——完全静止的视频平滑度接近满分，所以要一起看。
Reward hacking
模型找到奖励模型的漏洞而非真正提升质量。本文 §4.1 自陈 VideoAlign 会给纯白噪声和闪烁帧高分，这是一个具体的、已被观察到的 hacking 面。

D如果要复现，我会按这个顺序读

  1. 先读 Algorithm 1（不是 §3.2）。26 行把整个数据流说完了，尤其注意第 6 行的缩进位置和第 5 / 8 / 13 行的两个 timestep。
  2. 再读 §3.1，确认你的 DMD2 基线是对的。如果 DMD2 的 4 步生成质量不对，后面的一切都无从谈起。
  3. 然后是式 (6)——按 §04.3 的去噪预测形式实现，不要按字面的分数差。先只做 Pair 变体（不需要奖励模型，变量最少）。
  4. 最后加 Group。这里要决定 Ai 的定义（论文没给），并想清楚 K 个样本从哪来（跨卡 gather 还是 batch 内复制 prompt）。
  5. λ 从 1:1 起步，先别做调度。如果发现分布收窄，往 3:1 走，不要往 1:3 走。
