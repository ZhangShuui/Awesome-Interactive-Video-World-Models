§1一页读懂

先按论文自己的逻辑讲一遍，再给判断。后面每一节都会回到这里的某一条。

Problem · 钱花在哪

视频 DiT 一次要处理上万个 token，自注意力是 O(N²)。我按 Wan 的公开结构复算：Wan2.2-5B 在 704p、121 帧时（N = 27,280），单个块 53% 的 FLOPs 花在注意力核心（Q·Kᵀ 与 A·V）上。已有的提速办法都一视同仁：

  • 稀疏或线性注意力：让每个 token 都便宜一点；
  • 特征缓存：依赖多步之间的冗余，蒸馏到 3 步后冗余基本没了；
  • MoE：只动 FFN。

Idea · 按难度分配

天空、雾、静止背景看邻居就够了；运动物体、细长结构、遮挡需要全局信息。于是分两阶段：

  • 阶段一：给 DMD 学生加一个分支，逐 token 输出 ui。把 DMD 的 MSE 形式换成"带方差的高斯负对数似然"来训练它。
  • 阶段二：冻结分支。u 超过 μ + cσ 的 token 走全局注意力，其余走局部注意力；另外随机交换 7% 的 token 以扩大覆盖。然后用标准 DMD 再微调。

Results · 论文报告

Wan2.2-5B，3 步：

  • 质量：VBench 83.28（稠密 DMD 3 步 82.94），VBench-2.0 58.9（60.8）。人评 32 / 32 / 36，与稠密版分不出高下。
  • 效率：注意力 FLOPs 4.85×，块级 1.73×；FlexAttention 实测块延迟 1.63×。

Wan2.1-1.3B：VBench 83.10（稠密 DMD 83.61）。

§2钱花在哪：一个 Transformer 块的 FLOPs 账

"只给 20% 的 token 全局注意力"值多少，取决于注意力在整块里占多大比例。下面按 Wan 的公开结构，逐项数一个块里每个 token 的 FLOPs。结构参数包括隐藏维度、FFN 宽度、VAE 压缩率 4×8×8（2.2-5B 为 4×16×16）、1×2×2 分块、512 个文本 token。

关键一行是"上限"：就算注意力核心完全免费，5B 的块级加速也最多 2.13×，因为投影、交叉注意力、FFN 一点都没省。HetA 在 5B 上报告块级 1.73×，已经吃掉了这个上限的大半。所以在注意力内部继续压，边际收益会越来越小，后面的延迟分析也印证了这一点。

§3阶段一：不确定度分支到底在学什么

这是全文最巧的一步，也最容易被一句"预测去噪难度"带过去。结论先说：ui 学的是 DMD 在第 i 个 token 上"拉"学生的典型力度，也就是学生和老师在这里还有多大分歧。它不是"离真实视频还差多少"。训练全程只用 prompt，根本没有真实视频可比。

3.1 DMD 在做什么（三句话）

  1. 学生 Gθ 从噪声一步出一个干净 latent x̃0，再把它加噪到随机时刻 τ，得到 x̃τ。
  2. 两个打分网络看这个 x̃τ：老师 sT 是冻结的原版 Wan，代表"真实分布"；假分网络 sS 一边训练一边拟合"学生当前的分布"。
  3. 两者之差 sS − sT 就是"让学生分布往老师分布挪"的方向。

论文式 (8) 用了一个常见的改写：把这一步挪动写成一个临时靶子（伪目标），让学生去贴靶子。

式 (8) x̂0 = sg[ x̃0 − w(τ)·( sS(x̃τ) − sT(x̃τ) ) ],    ∇θℒDMD = 𝔼 ∇θ‖ x̃0 − x̂0 ‖² sg 是停止梯度。靶子与当前输出之差 g = x̃0 − x̂0 = w·(sS − sT)，就是 DMD 的"拉力"。下文记作 gi，逐 token 一份。

3.2 把 MSE 换成"带方差的高斯"

MSE 等价于方差固定为 1 的高斯负对数似然。论文把每个 token 的方差放开，由新分支预测 ui：

式 (9)(10) ℒuncDMD = 𝔼 Σi [ λrec·‖ x̃0,i − x̂0,i ‖²ui² + λlog·log ui ] 第一项：拉力大的 token，u 被推大。第二项：不让 u 无限变大。λrec、λlog 的取值、u ≥ 0 用什么函数保证、分支是什么结构、接在哪一层，论文都没写。

对 ui 求导并令其为零，得到最优解（我的推导）：

推导 ui*² = 2λrecλlog · 𝔼[ ‖ gi ‖² | 输入 ] 所以 ui 预测的是 DMD 拉力的均方根，条件是学生看到的输入（噪声 latent、时刻、prompt）。拉力大，说明老师认为学生在这里"还不像"。它和"去噪难度"相关，但不是一回事。

3.4 附录 D 的直觉：不确定 = "更吵的时刻"

附录 D 把 u 当成 x0 预测的标准差：x0 ≈ x̂0 + uη。把这个预测重新加噪到 τ，等效噪声方差变成 στ² + ατ²u²。也就是说，这个 token 的有效信噪比，相当于处在一个更吵的时刻 τ′ ≥ τ。论文据此认为，越吵的 token 越应该拿到全局计算，这和"高噪声阶段注意力更偏全局、负责布局"的经验一致。

§4阶段二：token 怎么被分到稠密或局部

分支冻结之后，每一步都用它的输出决定下一步谁看全局。规则一共 6 条：

  1. 对每个样本、每个时刻，算全部 N 个 ui 的均值 μ 与标准差 σ，阈值 T(τ) = μ + c·σ。默认 c = 0.9，论文说约对应 80% 局部。
  2. mi = 𝟙[ui < T]。m = 1 → 局部，m = 0 → 稠密。
  3. 在每个 Transformer 块里，再随机挑一部分不确定 token，和随机挑的确定 token 对调，默认 7%。目的是让更多 token 有机会看全局。
  4. 这个掩码用于下一步 τ − Δ，所以推理时不用多跑一次网络。
  5. 输出 z′i = mi·Attnlocal(i) + (1 − mi)·Attndense(i)，局部邻域是 11×11×11 的三维窗口。
  6. 冻结分支，用标准 DMD 目标把其余参数微调 6k 次。

4.1 路由沙盒

下面用 Wan2.2-5B 在 704p、121 帧时的真实 token 网格：31 个 latent 帧 × 22 × 40。每帧 880 个 token，总共 27,280 个。u 是我造的合成场，模仿附录图里的几种形态。统计量 μ、σ 和随机交换都在整段视频上计算，与论文一致。点击任一 token，可以看它在当前帧能看到的范围。

4.2 三个容易误解的地方

稠密只发生在 query 侧

K/V 始终来自全部 token。局部 token 的 query 只看 11×11×11 = 1,331 个 key，是 5B 全部 27,280 个的 4.9%、1.3B 全部 32,760 个的 4.1%。在 5B 的 31×22×40 网格上，11 帧的时间窗约覆盖全片 1/3，11 行覆盖画面高度的一半。这个"局部"并不小。

局部不等于看不到远处

每层局部窗的半径是 5 个 token，30 层叠起来，理论感受野半径达 150。5B 网格最长的一边是 40，第 8 层就已经覆盖整帧。局部注意力损失的是一层之内直达的长程交互，不是信息能不能传到。这能解释为什么"全局部"版本已有 82.85 分（§7.5）。

"自适应"只管在哪算，不管算多少

阈值 μ + cσ 是相对的，稠密比例主要取决于 c 和 u 的分布形状：近似高斯时 c = 0.9 对应 18.4%；指数或对数正态这类右偏分布约 10–15%。一段处处都难的视频不会因此多拿算力。好处是延迟可预测。论文没报告 ρ 在样本和时刻之间的分布。复算

§5训练与推理的时间线

两个训练阶段加一次推理。容易出问题的地方有三处：掩码的来源在训练和推理时不同；分支冻结了，但它读取的主干特征还在变；第 1 步没有掩码来源。

第 1 步是一个关键空白。3 步里如果第 1 步走全稠密，5B 的块级延迟加速就从 1.63× 降到整条管线的 1.35×。这时 HetA 的 3 步约等于 2.23 个稠密步，比 DMD 2 步（2.0 个稠密步）还慢 11%。如果 3 步都能稀疏（需要另找第 1 步的掩码），约 1.84 个稠密步，比 DMD 2 步快 8%。§6 的计算器里可以切换这两种情况。复算

§6算力账本：用论文自己的公式复算

论文式 (14) 给出的注意力成本是 O(ρN²d + (1 − ρ)NMd)，其中 ρ 是稠密 query 的比例，M = |𝔑(i)| 是局部窗口里的 key 数。把 Wan 的真实 token 数代进去，块级数字对得上，注意力这一层对不上。

6.1 注意力这一层为什么对不上

取 ρ = 0.2、M = 11³、N = 27,280，式 (14) 给出 5B 的注意力缩减是 4.18×，论文报告 4.85×。核大小扫描（Table 7）的差距更明显：

可能的解释有三种，论文都没有交代：

  1. 实际 ρ 小于 0.2。按 4.85× 反推，ρ ≈ 0.165；但这解释不了 Table 7 的斜率。
  2. "11×11×11"不是以 token 为单位，比如以分块前的 latent 为单位。
  3. FLOPs 计数器没把 FlexAttention 的局部部分算全。论文只说用 DeepSpeed 数 FLOPs。

不管是哪一种，Fig.4 的横轴（全文的帕累托论据）用的就是这个口径。→ D5

另一个没交代的实现细节。FlexAttention 按 128×128 的块来跳过计算。如果 20% 的稠密 query 在序列里是散开的，几乎每个 128 个 query 的块里都会有稠密 token：随机分布时，一个块里一个都没有的概率是 0.8¹²⁸ ≈ 4×10⁻¹³。这样整行 KV 块都得算，稀疏就失效了。要拿到 1.84×，必须先按路由把 query 重排或 gather。另外，每个 Transformer 块都有不同的随机交换，所以每层每步都要重建一次 BlockMask。论文说延迟"已含摊销的 BlockMask 构建"，但没说怎么排布。→ D10

§8存疑清单（22 条）

分三档：高 影响核心结论；中 影响某个数字或可复现性；低 表述或笔误。每条都写了依据，能量化的给了数字，最后附上建议补的实验。

D1高质量增益来源混淆：稀疏版反超稠密版，但它多训了 21k 步，阶段一还改了目标

Wan2.2-5B 上，HetA 83.28 > 稠密 DMD3s 82.94，语义 +1.09；90% 局部的变体 82.98，也 > 82.94；全局部 82.85 ≈ 82.94。一个只做近似的稀疏模型反超被近似的稠密模型，最自然的解释是后续训练本身带来了增益：阶段一 15k 次，用的是改过的、逐 token 归一化的 DMD 目标（§3.3）；阶段二再 6k 次。

Fig.3 里同一 prompt 下 HetA 与 DMD3s 的内容明显不同：DMD3s 前几帧是一只花篮，HetA 从头到尾是花瓶。这说明 HetA 已经是一个不同的模型，而不是 DMD3s 的稀疏近似。不过论文没说两边是否用了同一个种子。

① 阶段一结束时的模型直接用全稠密注意力评测；② 稠密 DMD3s 用同样的数据和 21k 次迭代续训；③ 在这两个基础上再比稀疏化带来的变化。
D2高"按不确定度路由"本身的价值几乎没被证明

同成本（80% 局部）下：随机 82.78，纯不确定度（0% 随机）83.00，固定均匀 83.13，不确定度 + 3% 随机 83.18，+ 7% 随机 83.27。不确定度单独使用时输给了均匀覆盖；要靠混入随机覆盖才反超 0.14 分。全局部 82.85 离最好的变体只差 0.43。

全部差异都在 0.5 分以内，而论文没有给种子方差、置信区间，也没有在这些变体之间做人评。论文说"uncertainty-based routing is consistently superior"，在这组数字下站不住。

多种子重复 Table 6/8；在全局部、固定均匀、纯不确定度、+7% 之间做人评；补"均匀 + 7% 随机"一格，用来隔离不确定度的贡献。
D3高VBench-2.0 五大类全部低于稠密 DMD3s，Wan2.1-1.3B 上三项也全低；正文只挑有利的比较

VBench-2.0：58.9 vs 60.8，五大类全低。逐维看（从雷达图解码），掉得最多的是 Dynamic Attribute −10.2、Motion Rationality −9.2、Multi-View Consistency −7.4、Diversity −6.9。前三维都依赖跨帧长程一致，正是局部注意力最可能损失的能力。正文只写"胜过 50 步 Wan2.2 和 2 步 DMD"。

D4高第 1 步的掩码从哪来没写；真正算力相当的对照是 DMD 2 步，而这个比较没有被正面讨论

掩码来自"上一步"的 u，而第 1 步没有上一步。如果第 1 步走全稠密，5B 块级延迟加速就从 1.63× 变成整条 3 步的 1.35×。此时 HetA 的 3 步约等于 2.23 个稠密步，比 DMD 2 步（2.0）还慢 11%。如果 3 步都能稀疏，是 1.84 个稠密步。

无论哪种，HetA 和 DMD2s 的算力都在同一量级。好消息是 HetA 在这个对比里确实更好：VBench +0.80，人评 50% vs 24%。这其实是全文最有力的证据，但论文把 DMD2s 当作普通基线，没把它当成"算力对照"来讨论。

写清第 1 步的处理；报告整条管线（含文本编码与 VAE 解码）的端到端时延，并与 DMD2s 并列；试一下 2 步的 HetA。
D5中注意力 FLOPs 按论文式 (14) 复现不出来：局部部分像只按 ≈15% 的 k³ 计入

5B：N = 31×22×40 = 27,280，M = 11³，ρ = 0.2，式 (14) 给出 4.18×，论文报告 4.85×。Table 7 的 k = 9/11/13 按式 (14) 应为 4.52/4.18/3.78×，论文是 4.91/4.85/4.76×。三点的斜率等价于 Meff ≈ 0.148·k³。同一个折扣还能精确复现 Fig.4 的 1.58/1.73/1.90×。

块级数字由注意力数字推出来是对的，所以问题出在注意力这一层怎么数。Fig.4 的横轴，也就是帕累托论据，用的正是这个口径。

公开 FLOPs 计数脚本；说明局部窗口的单位与边界处理；按实测 ρ 报告，而不是按 0.2。
D6中掩码来源训练与推理不一致；冻结的分支读的是一直在变的主干特征

阶段二训练时，u 来自额外一次全稠密、无梯度的学生前向，在"更早的时刻"上计算；推理时，u 来自上一步异构注意力的前向。分支虽然冻结，但它的输入是阶段二正在微调的主干特征（论文没给分支结构，这是我的推断）。所以推理时的 u 分布可能漂移。相对阈值 μ + cσ 能吸收整体缩放，这一点设计得不错，但吸收不了形状变化。

对比两种掩码来源；报告推理时 u 的分布与阶段一结束时的差异；说明"更早的时刻"是固定 Δ 还是模拟推理步。
D7中阶段一改变了生成器的训练信号，且关键超参全缺

NLL 对 x̃0 的梯度是 2λrec·g/u²：难 token 的 DMD 更新被压小，易 token 的被放大；同时去掉了 DMD 的逐样本归一化。这会改变质量和多样性。VBench-2.0 的 Diversity −6.9 是一个信号，但分不清是阶段一还是稀疏化造成的。λrec、λlog、u 的参数化（softplus 还是 exp）、分支结构、分支接在哪一层，全部没给。

消融"梯度 stop 在 u 分支、不回传到生成器"的版本；报告 λ 与分支结构。
D8中"不确定度 = 去噪难度 = 需要全局注意力"这条链没被验证，附录图还与 Fig.1 的叙述相反

u 学的是 DMD 拉力的均方根（§3.2），不是 x0 误差，也不是"需要全局信息"的直接度量。论文没有 u 与"换成局部注意力后该 token 输出变化"的相关性分析，只有 5 张 σ = 0.6 的定性图。山路航拍那张里，平整路面 u 最高，纹理极细的密林最低，和 Fig.1"细结构要全局、平滑区域局部即可"正好相反。整体看更像显著物体掩码。

逐 token 测量 ‖Attndense − Attnlocal‖，与 u 求秩相关；给出不同时刻的 u 图；与"显著性 / 光流幅度"这类廉价信号做路由对照。
D9中5B 的延迟数字内部有张力；稠密基线的 kernel、硬件、batch 都没写

注意力 1.84× 要换来块级 1.63×，注意力必须占稠密块耗时的 85%。而按 FLOPs 它只占 53%，含 QKV/O 投影也只有 65%。1.3B（74%）和 14B（64%）没有这个问题。最可能的情况是稠密基线用了偏慢的注意力实现，比如不带掩码的 FlexAttention 而不是 FlashAttention-3，块级加速因此被放大。

以 FlashAttention-3 作为稠密基线重测，写明 GPU、batch、序列长度与是否 torch.compile。
D10中FlexAttention 的关键实现细节缺失：query 重排与逐层 BlockMask

FlexAttention 按 128×128 的块跳过计算。20% 的稠密 query 如果散落在序列里，几乎每个 query 块都含稠密 token，稀疏就失效了。要拿到 1.84×，必须先按路由把 query 重排或 gather，再散回原位。另外随机交换是逐块进行的，所以 30 个块 × 每步都要不同的 BlockMask。这些都没写，复现者很可能拿不到论文的延迟。

公开 kernel 实现，或至少给出伪代码与各部分耗时拆分（掩码构建、gather/scatter、稠密、局部）。
D11中"内容自适应"只管在哪算，不管算多少；ρ 的分布没报告

阈值 μ + cσ 是相对的，稠密比例由 c 与 u 的分布形状决定：高斯时 18.4%，右偏分布时 10–15%。一段处处都难的视频拿到的稠密比例和一段简单视频差不多。摘要说"content- and timestep-adaptive"，严格说只是位置自适应。ρ 在样本和时刻之间的分布、它和延迟的关系，都没报告。

报告 ρ 的分布；试一个绝对阈值或预算控制器，看"按难度增减总量"是否有额外收益。
D12中基线公平性：训练预算不透明，ToCa 被限制，部分基线同组，STA 不同基座

HetA 训练 21k 次；VSA"大体遵循 FastVideo 配方"，Attention Surgery 和 ReHyAt 各三阶段，但迭代数都没列。ToCa 只允许在 3 步中的第 2 步缓存，有效 FFN 缓存率 10.3%，却让 VBench 掉了 2.4 分（80.52），dynamic degree 掉到 18.1。这个配置本身就不太像 ToCa 的正常用法。Attention Surgery、ReHyAt 与本文同组。STA 是 HunyuanVideo 基座，不该和 Wan 基座的方法并列比较。

同组的 Neodragon、MobileWan 都面向手机 NPU。HetA 的掩码逐样本、逐步、逐层变化，这在静态图的 NPU 上很难高效实现。论文只有 H100 + FlexAttention 的数据，没有讨论可部署性。

D21低"约 12 GPU·天，比预训练低 4–5 个数量级"无法核实

21k 次迭代、4 张卡、约 3 天，平均每步约 12 秒，数量级说得通。但 Wan 的预训练算力没有公开，"4–5 个数量级"无从验证。这 12 GPU·天也不含得到起点 DMD 检查点的成本。

D22低附录 B 的覆盖率公式有个小瑕疵

1 − (1 − r)B 把 r 当成"每个确定 token 每层被抽中的概率"。如果 r 是占全部 token 的比例（从"20%（all）"看应是如此），概率应为 r/(1 − ρ)，覆盖率从 0.89 变为 0.94。不影响结论。

§9与前人工作的关系

"按 token 分配计算"这个想法并不新，HetA 的新意在于三点组合：放在注意力层、适配3 步 DMD、用不确定度做路由信号。

§10收尾：公道话、对世界模型的启示、最值钱的后续实验

做对的地方

  • 把问题放在 3 步蒸馏这个真实部署点上。缓存方法在这里确实失效，HetA 不依赖多步冗余。
  • 推理零额外前向：用上一步的 u 做下一步的掩码。
  • 用 NLL 改写 DMD 的伪目标，让"不确定度"在只有 prompt、没有真实视频的条件下也能训练。这一步很漂亮。
  • 相对阈值让延迟基本可预测，也能吸收冻结分支的尺度漂移。
  • 块级 FLOPs、VBench 汇总、雷达图与表格彼此一致，数字不是随手写的。

对交互式视频世界模型的启示

  • 世界模型每一步真正在变的，往往只是动作影响的区域和运动物体，大片背景是静止的。这正是 token 级异构计算的甜区，而且那里同样是少步蒸馏加流式生成。
  • "上一步的 u 决定下一步谁看全局"，可以自然推广成"上一个 chunk 的 u 决定下一个 chunk 谁读长程 KV 记忆"：稠密 query 读全部缓存，局部 query 只读近邻帧。这既省算力，也是一种记忆检索门控。
  • 先跑"全局部 + 同样训练"的基线。这篇论文显示它已经很强；在世界模型里加路由之前，先确认局部注意力加足够的深度是否就已经够用。
  • 不确定度头还可以当"模型哪里没把握"的信号，用于触发记忆检索、局部重生成或多次采样。

最值钱的后续实验

  1. 拆开 D1：阶段一模型直接用稠密注意力评测，加上同迭代数的稠密 DMD 续训。
  2. 同成本、同训练的路由对照（均匀、全局部、纯不确定度、+7%），多种子，并做人评。
  3. 写明第 1 步怎么处理；报告含 VAE 的端到端时延，与 DMD2s 并列。
  4. u 与"局部化带来的误差"做逐 token 相关，并给出不同时刻的 u 图。
  5. 公开 FLOPs 计数与 FlexAttention 的排布方式。
  6. 1.3B 补人评，并解释为什么那里全面低于稠密版。
