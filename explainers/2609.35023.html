Proxy2World — 没见过白盒，也能照着白盒画世界

用低模、方块、甚至残缺的「白盒」摆好布局、写好角色动作，再让视频模型负责外观、光照和细节。难点是配对数据做不出来。这篇论文完全不用（白盒，真实视频）配对：只用普通带位姿的 RGBD 视频，教一个 14B 视频模型学会两种模式，推理时在同一条去噪轨迹上把它们拼起来。

一句话判断：核心机制和「控制信号只在前几步生效」（ControlNet 的 guidance end、SDEdit）同源。新的地方在三点：放开条件后，模型切到的是「RGB + 深度联合生成」，而不是无条件生成；这两种模式用普通 RGBD 视频就能训出来；相机和深度被拉到同一个米制尺度。想法干净，可以迁移。但实验对比的口径不齐（主力行多了参考首帧），核心旋钮 τ 怎么选、敏不敏感都没交代，而正文说放在附录的细节在 v1 里并不存在。

01 · TL;DR

一分钟版

想解决什么

游戏关卡设计、影视预演里常见这样的流程：先用灰色方块和低模人偶搭一个「白盒」（whitebox / blockout），写好镜头轨迹和角色动作脚本（比如「骑士放下吊桥、推开城门、走进大厅」），再交给美术去做。这篇论文想让视频模型来当那个美术：布局、占位、动作照白盒来，外观、光照、细节由模型发挥。

卡点在数据上。「合适的白盒」没有唯一答案：哪些物体要建、简化到什么程度、哪些可以省略，都是设计师的主观抽象。所以没法自动地大规模构造（白盒，真实视频）配对。

怎么做

训练时完全不碰白盒。只用普通的带位姿 RGBD 视频，让同一个 DiT 学两门课：课 1 给定干净深度，生成 RGB；课 2 RGB 和深度一起从噪声生成。两门课都一直带着相机网格条件。

推理时把两门课拼接起来。前几步用课 1，把白盒渲染出的深度当干净条件，定下布局。之后切到课 2，深度变成要生成的变量，模型可以把人偶修成人、把方块修成房子。切换点由 τ 控制。

结果（论文口径）

在 ProxyBench 的 78 段上，混合模式 TI2V 的 VLM「细化」胜率最高（77.96%），「遵循」胜率第三（64.18%，低于 Cosmos-Depth 的 72.26% 和自家纯深度模式的 68.79%）。人评排名第一。消融显示：去掉米制尺度对齐，相机误差最大；去掉联合 RGBD 学习，相机误差和人评都变差。

要小心的地方

  • 默认配置下，真正「看」白盒的只有 40 步里的前 3 步，噪声水平 t ∈ [0.974, 1]（§5）。
  • 最亮眼的对比（vs Cosmos / VACE / Coarse2Real）是「我们有参考首帧、对方没有」。输入对齐后遵循度明显落后（§6）。
  • τ* 怎么选的、换个值会怎样，都没说。评测指标定义、VLM prompt、ProxyBench 的构建方式、参考首帧的来源，全部指向一个不存在的附录（§8）。
02 · SETUP

问题设定：白盒到底以什么形式进入模型

先说最容易误解的一点：白盒进入模型时，只剩一段逐帧深度视频。没有物体类别，没有实例 ID，没有法线，也没有白盒的 RGB 渲染。角色动作只表现为深度图里一团人偶形状在移动。

三件事决定了后面的一切

  1. 标题里的 “without seeing them” 是字面意思。训练集里没有任何白盒。深度全部来自真实场景和游戏录像（第 4 节）。模型推理时第一次见到「人偶形状的深度」。
  2. 严格服从深度，和自然外观是冲突的。如果从头到尾都严格服从白盒深度，模型会忠实地把人偶的圆柱四肢、方块房子一起画出来（论文 Fig 5a 的 τ=0 列）。如果只给相机，外观自然了，角色却会跑到别处（τ=1 列）。整篇论文要解决的就是在两者之间找平衡。
  3. 参考首帧 I_ref 是可选的，但影响很大。它要和白盒的第一视角对齐，相当于第一帧的「精装修」已经给好了。论文没说 ProxyBench 里的参考首帧是怎么来的（推测是用某个图像模型按白盒首帧生成的）。第 6 节会看到，有没有它，比有没有白盒对分数的影响还大。

训练时　模型见到的深度

来自 DL3DV、RealEstate10K 的真实场景深度，以及游戏数据的深度。深度精细、贴合真实物体表面，并且和 RGB 一一对应。论文没说 DL3DV / RE10K 的深度是用什么估计的，只说它们和相机「共享一个任意尺度」，再用 DA3 对齐到米制。

推理时　喂进去的深度

从白盒渲染出来的深度：圆柱四肢、平板墙、缺失的几何（缺失处深度为空或是远处背景）。在粗尺度上（哪里有墙、地面在哪、有一团东西在往左走）和真实深度相似；在细尺度上则完全是分布外的。整个方法押注的就是这个「粗像细不像」。

03 · SIGNALS

三种条件信号：相机网格、米制尺度、伪彩深度

论文把「相机怎么动」和「场景长什么样」分成两路条件，两路都做成视频的样子，塞进同一个冻结的视频 VAE。这样做不用改骨干网络，但要求两路信号的尺度严格一致。

3.1　相机网格：把相机轨迹画成一段视频

做法沿用 OmniDirector：在世界坐标系里放一个固定的空间网格 𝒢，沿着给定轨迹把它渲染出来，得到网格视频 G = Rgrid(𝒢, C)（式 3）。网格线在画面里怎么移动、汇聚、产生视差，就编码了相机怎么移动。这段视频不包含任何场景表面信息。

编码后的网格潜变量 zg 始终是干净的（不加噪），按通道拼接到 RGB 流和深度流的每一个位置上（§4）。所以三种推理模式里它都在。

和 Plücker 射线、相机 token 这类做法比，好处是零结构改动：它就是一段视频，VAE 直接编码。代价是网格的物理间距是固定的，网格的运动只有在米制单位下才有确定含义，这引出 3.2。

3.2　米制尺度对齐：为什么「单位」会直接伤相机控制

RealEstate10K 和 DL3DV 的位姿来自 SfM / SLAM，尺度是任意的：同样叫「平移 1」，有的片段对应 10 厘米，有的对应 5 米。论文的办法（式 4）是：用 DA3 估第一帧的米制深度，把整段深度对齐过去，得到一个片段级系数 s，然后把同一个 s 同时乘到深度和相机平移上。

Dimetric = s·Di,　　timetric = s·ti式 4：一个系数同时管深度和平移，相对几何不变

为什么需要它？考虑只给相机、不给深度的情况：τ=1，或者联合模式里深度本身也在生成。模型要把「网格说相机走了多少」换算成「画面里的门该挪多少像素」，就必须知道门有多远。这只能靠外观去猜（门大约 2 米高），而外观暗含的是米制尺度。如果训练片段的平移单位是任意的，同样的网格运动在不同片段里对应的真实位移差一个未知倍数 u，模型只能学到一个平均的换算，误差就是这个倍数的离散程度。

我的补充：如果深度和平移同时处在同一个任意单位里，「平移 ÷ 深度」这个比值其实不受 u 影响。所以在「给定深度」的课 1 里，问题并不大。真正受伤的是两种情况：一是深度靠生成、靠外观推断的情形（τ=1 和联合阶段）；二是伪彩映射 H 是固定的绝对映射，「0.3 米」这个颜色会同时出现在桌面特写和整间屋子上，颜色的语义被搅乱。这也解释了为什么消融里受伤最重的是相机误差。

3.3　伪彩深度：把一个数塞进三个颜色通道

视频 VAE 只认 RGB，深度要变成图片才能编码。论文沿用 Vision Banana 的做法（式 5）：H = h(f(D))。其中 f 把米制距离非线性地压到有界区间，近处分辨率更高；h 沿 RGB 立方体里一条类 Hilbert 曲线取颜色。这样一个深度值对应一个颜色，而且理论上可逆。映射在所有帧、所有场景之间固定不变，所以绝对尺度信息保留了下来，真实深度和白盒深度也共用同一套表示。

为什么不用灰度？灰度只用了一条对角线，三个通道存的是同一个数。Hilbert 曲线在立方体里来回折叠，把「一维长度」拉长了几十倍，同样的颜色误差对应的深度误差就小得多。代价是折叠处相邻的两段曲线在颜色空间里很近，在深度上却可能相隔很远：颜色一旦被扰动越过那条缝，解码出的深度会整段跳走。下面的实验室可以直接看这个取舍。

这对论文意味着什么：作为输入条件，这个编码很合适，因为白盒深度是干净渲染的，只经过一次 VAE 编码。作为输出，生成出来的深度伪彩要解码回米制深度，就会碰上折叠处的跳变，物体边缘这类 VAE 误差大的地方尤其明显。论文说这个映射「可逆、可以恢复米制深度」，但没有评估解码出的深度质量，也没说评测里是否用到了它（§8 第 13 条）。
04 · TRAINING

训练：一个 DiT，同时学两门课

关键设计是给 RGB 和深度各配一个噪声水平，tq 和 th。两门课的区别只在于深度那一路的噪声水平是 0 还是 t。

用人话读式 7–8

ztmm = (1 − tm) z0m + tm εm,　 目标速度 um = εm − z0m,　 m ∈ {q, h}式 7：rectified flow，t=0 是干净数据，t=1 是纯噪声
ℒ = 𝔼 [ Σm wm ‖ vθm(zqtq, zhth, tq, th; zg, c) − um ‖² ]式 8
  • 课 1（深度 → RGB）：(tq, th) = (t, 0)，(wq, wh) = (1, 0)。深度是干净的，模型只需要把 RGB 从噪声里「画」出来，并且和这张深度对得上。这就是一个 depth-ControlNet，只不过条件不是通过旁路注入，而是作为 token 和 RGB 一起做注意力。
  • 课 2（联合 RGBD）：(t, t)，(1, 1)。两路同时加同样程度的噪声，同时去噪，学的是 RGB 和几何的联合分布。只给相机的时候，模型会自己「想出」一个几何，再照着它画。
  • 两门课在训练中各占一半，参数完全共享。注意：训练里从来没有出现过 tq ≠ th 且 th ≠ 0 的组合。推理时的切换设计正好只用到这两种训练过的组合，这一点做得很干净（§5）。
概念上的前辈：「每个模态单独一个时间步，同一个网络既能做条件生成又能做联合生成」，这个思路最早系统化于 UniDiffuser（Bao et al., 2023）。Diffusion Forcing 的「逐 token 噪声水平」也属于同一脉络。论文没有引用这两篇。它的贡献更多在于把这个思路落到 14B 视频模型加深度这个场景，并用于白盒控制。

意味着什么

即使在「深度 → RGB」阶段，深度 token 也要参与每一步的全注意力。它们是干净的条件，但因为要和变化中的 RGB token 互相注意，没法简单地缓存。所以三种模式的单步成本都在同一个量级。

论文没有报告推理耗时。对「世界模型」这个定位来说，这是一个 81 帧、双向、离线、每步约 3 倍算力的生成器，离交互或流式还很远。结论里也承认「长时程交互生成留待未来」。

05 · INFERENCE

混合去噪：前 3 步定骨架，后 37 步长血肉

推理时把两门课接在同一条去噪轨迹上。τ ∈ [0, 1] 是「分给联合精修的步数占比」。在 40 步的调度 1 = t0 > … > t40 = 0 上，切换点是 ks = ⌊(1 − τ)N⌋，对应的噪声水平是 ts = tks。

① 白盒定骨架　t > ts

白盒深度编码成 zh,S，在这一阶段固定不变、当作干净条件。RGB 从纯噪声出发，用课 1 更新：

dzq/dt = vθq(zqt, zh,S, t, 0; zg, c)

式 9。只更新 RGB，深度一动不动。

② 切换　t = ts

RGB 潜变量原样保留。深度那一路用白盒深度加噪到 ts 来初始化：

zhts = (1 − ts) zh,S + ts εh

式 10。此刻两路的噪声水平相同，都是 ts，正好落在课 2 训练过的 (t, t) 组合上。

③ 联合精修　t ≤ ts

深度也变成要生成的变量，两路一起按课 2 更新。白盒不再作为约束，相机网格仍然一直在：

dzm/dt = vθm(zqt, zht, t, t; zg, c)

式 11。m ∈ {q, h}。

调度探索器：τ* = 0.925 到底意味着什么

只看 3 步够吗？噪声里其实藏着布局

t = 0.974 时，信号幅度只有 2.6%。按单个坐标算，信噪比约 −31 dB，看起来就是纯噪声。那布局是怎么被「定下来」的？关键在于布局是一个覆盖整幅画面、在 21 帧里基本一致的低频图样。模型不需要逐像素认出信号，只需要判断「整体更像哪种布局」。这就像匹配滤波：把几百万个微弱但方向一致的证据加起来，总信噪比可以很高。下面这个玩具演示了这一点：左边是 t 时刻的「潜变量」，右边是把它大半径模糊之后的样子。

顺带澄清一个容易想歪的点：式 10 用加噪的白盒深度来初始化深度流。ts = 0.974 时，白盒在这一路里同样只剩 2.6% 的幅度。所以联合阶段「知道」白盒布局，靠的是两股同样微弱、但同样是整体图样的信号：前 3 步写进 RGB 潜变量里的布局，以及加噪后白盒深度的残留。两者各贡献多少，论文没做消融。一个很便宜的实验是把式 10 里的 zh,S 换成纯噪声，看遵循度掉多少（§11）。

τ 的三个档位（论文 Fig 5a 的描述）

τ = 0　全程深度条件

布局和角色位置最准，相机误差最低（Table 1：nATEt 0.0302）。但人偶的圆柱体形和方块轮廓会被原样画出来，角色显得僵硬、比例失调。VLM 细化胜率只有 31.71%，全表最低。

τ = τ* = 0.925　3 步 + 37 步

主要的空间关系保住了，角色被修成自然的人形，场景细节更丰富。Fig 5a 里 τ* 和 τ=0 的构图几乎一样，背景建筑则被自由改写，比如窗换成拱门。论文只展示了这三个点，没有中间档位的扫描。

τ = 1　只给相机

外观最自然，但角色位置、场景结构都会偏离白盒。Fig 5a 里整个构图都变了。它等价于一个带参考首帧的相机控制视频模型，和 Lyra、SCoPE 同一类。

和已有技巧的关系：「条件只在前若干步生效」是图像生成里的常用旋钮，比如 diffusers 里 ControlNet 的 control_guidance_end，思路上也接近 SDEdit 的「从中间噪声开始」。Proxy2World 的不同之处在于，条件撤掉之后，模型不是退化成无条件生成，而是进入同样训练过的「RGB+深度联合生成 + 相机条件」模式，并且继续生成几何。这是它比「直接给 VACE 设个 guidance end」更有道理的地方。可惜论文恰好没有做这个最直接的对照（§8 第 2 条）。

读 Table 1：先看每一行拿到了什么输入

Table 1 用四个小图标标注每个方法拿到了哪些输入：文本、参考首帧、相机轨迹、白盒。灰色表示没用。PDF 抽出来的文字里看不出颜色，我在 arXiv HTML 版里逐个核对了图标颜色（#000000 表示用了，#D1D1D1 表示没用）。这些图标决定了哪些行之间的比较是公平的。

指标（论文交代了的部分）

  • nATEt / nATEr：用 VIPE 从生成视频里估位姿，和目标轨迹比较，得到归一化的平移 / 旋转误差。
  • Reproj.：重投影误差，排除动态物体。
  • Geo. / Temp. Align：与白盒的几何 / 时序一致性。计算方式未给出。
  • Adh. / Ref. WR：Gemini（论文写作「Gemini-v3.7-flash」）两两比较，平局算半胜，对所有对手取平均胜率。Adherence 看布局和角色行为有没有保住，Refinement 看几何、外观、运动有没有被合理地丰富。

几个基线数字也值得怀疑

  • Coarse2Real 原本是用配对合成数据训练、面向人群仿真的粗到真渲染器，输入是粗仿真渲染。它在 ProxyBench 上吃的是什么（深度？RGB 渲染？），论文没说。
  • Lyra 2.0 的相机精度（0.0418 / 0.0413）其实优于 Ours TI2V τ*（0.0659 / 0.0558）。「混合模式在相机上也更好」这个说法不成立。论文正文也没这么说，只是把相机误差放在表里、不作讨论。
07 · ABLATION

消融与人评：Fig 5b 的数值还原

Fig 5b 在论文里是一张双纵轴柱状图，没有标数值。arXiv HTML 版里它是 pgfplots 生成的 SVG，我按柱子的路径高度和刻度线的位置换算出了数值：左轴刻度 0.04 对应 34.36 个单位，右轴 100% 对应 103.09 个单位。下面把两个量拆成两张单轴图。

  • 去掉米制对齐：nATE 0.062 → 0.098（+58%），偏好 75% → 32%。和 §3.2 的机制分析一致，是最伤的一项。
  • 去掉联合 RGBD（精修阶段改成只生成 RGB、只给相机）：nATE 0.071，偏好 54%。论文据此认为「光把深度约束撤掉还不够，得同时生成几何」。
  • 但三个 Preference 加起来是 161%。所以它既不是「三选一的份额」，也不是三者之间的循环赛胜率（那样平均值必须是 50%）。可能是和某个共同参照比较的胜率，也可能是「可接受」的比例。定义缺失，样本量也缺失。
  • 「Full model」的 nATE 是 0.062，和 Table 1 里 TI2V τ* 的 (0.0659 + 0.0558) / 2 = 0.0609 接近，但不相等。消融用的是哪个子集、哪种 nATE，都没说。
  • 「w/o joint RGBD」是怎么实现的？有两种可能，论文都没排除：一是重新训练一个「深度→RGB + 只给相机的纯 RGB」模型，那就要交代训练预算是否相同；二是同一个 checkpoint 在精修阶段直接去掉深度 token，那模型从没见过这种输入，这个消融对照组本身就处在分布外，不公平。

08 · DOUBTS

存疑清单（16 条，按严重程度排）

分级是我的判断：「高」会影响核心结论能不能成立；「中」影响结论的强度或可复现性；「低」是细节。每一条都写了证据和能解决它的实验。点击展开。

高 3 条中 8 条低 5 条
01高主力对比混进了参考首帧：和 VACE、Cosmos、Coarse2Real 比的时候，只有「我们」拿到了参考首帧▶

证据：Table 1 的输入图标（HTML 版颜色值）显示，VACE-Depth、Cosmos-Depth 只用了「文本 + 白盒」，Coarse2Real 用了「文本 + 相机 + 白盒」，三者都没有参考首帧。正文重点讨论的是「Ours TI2V τ*」，它四样全有。同一个模型从 T2V 换成 TI2V，Adh 涨 +21.37、Ref 涨 +26.66，比加白盒（+10.63 / +6.52）还多。Fig 4 的定性对比里，VACE、Cosmos、Coarse2Real 的画面色调和首帧完全不同，也印证了这一点。

影响：「细化胜率 77.96 vs 40.28」里有很大一部分来自参考首帧。输入对齐到 T2V 后是 51.30 vs 40.28，而遵循胜率是 42.81 vs 72.26。另外，参考首帧本身从哪来（哪个模型、按什么条件生成），论文没说。如果它已经是「按白盒首帧精装修」好的图，那 TI2V 的第一帧细化其实是那个图像模型的功劳。

怎么解决：给 VACE 补上参考首帧再比（VACE 支持参考图 / 首帧），或者全表统一用 T2V；公开参考首帧的生成流程。

02高缺最关键的对照：把「深度只在前 k 步生效」这一招直接用到 VACE / Cosmos 上，会怎样？▶

证据：论文的核心卖点是「平衡」。但「控制只作用于前若干步」在 ControlNet 生态里是现成的旋钮（control_guidance_end），VACE 也有 context scale 可以按步调。表里的 VACE / Cosmos 都是全程强制深度，所以它们落在「高遵循、低细化」一端，和自家的 τ=0 一样。

影响：分不清收益来自哪里：是来自新的训练方式（课 1 + 课 2 + 放开后切到联合 RGBD），还是仅仅来自「条件只给前几步」这个调度。另一个也没做的对照是：只训练联合 RGBD（课 2），前几步用 replacement 的方式把白盒深度塞进深度流，也就是 RePaint 式的条件采样。这能检验课 1 是否必要。

怎么解决：VACE-Depth 加 guidance end（前 3 / 5 / 10 步），和 Ours 画在同一张 Adh–Ref 图上。再加一个「只有课 2 + replacement」的消融。

03高「详细协议见附录」，但 v1 没有附录▶

证据：第 4.1 节末尾写「Detailed protocols are provided in the appendix」。arXiv v1 的 PDF 一共 13 页，第 10–13 页是参考文献，后面什么也没有。HTML 版的章节列表同样只到参考文献。

因此无从核查的内容：Geo / Temp Align 的计算方式；nATE 怎么归一化；VLM 的 prompt、是否交换左右顺序、看的是哪些帧；人评流程；ProxyBench 的「agent-driven」构建流程；78 / 300 的挑选标准；每个基线的适配方式；参考首帧的来源。

怎么解决：等 v2 或代码发布（项目页目前都标注 Coming soon）。在那之前，Table 1 里所有「operator-based」指标都只能当作不透明的数字来看。

04中τ* = 0.925 怎么选的？只报告了 3 个 τ，没有敏感性曲线▶

证据：只报告了 τ = 0、τ*、1 三个点。τ* 对应「前 3 步」，粒度是每步 0.025：τ=0.95 是 2 步，τ=0.9 是 4 步。§5 的分析表明，这几步决定的是最粗的布局，结果对 ks 很可能相当敏感。论文没说 τ* 是不是在 ProxyBench 这个测试集上选的。

怎么解决：τ 从 0 到 1 全扫一遍，画出 Adh、Ref、nATE 随 τ 变化的曲线；τ* 在留出的场景上选。

05中混合模式在相机精度和 3D 一致性上并不占优▶

证据：T2V 下从 τ=0 到 τ*，nATEt 从 0.0302 升到 0.0863（×2.86）。TI2V τ* 的 nATE（0.0659 / 0.0558）不如 Lyra 2.0（0.0418 / 0.0413），也不如 Cosmos-Depth（0.0446 / 0.0362）。它的重投影误差 2.524 在自家四个变体里最差。方法部分说「相机网格在联合阶段继续约束视角」，但数字表明，撤掉深度以后，相机网格一个信号撑不住原来的精度。

影响：对需要精确机位的应用（游戏过场、预演）来说，这是实打实的代价。「better balance」只在两个 VLM 胜率的平面上成立。

06中Fig 5b 消融的定义不清：Preference 加起来 161%；nATE 是哪种；「w/o joint RGBD」怎么实现的▶

证据：从 SVG 还原出来的数值是 nATE 0.098 / 0.071 / 0.062，Preference 32% / 54% / 75%（§7）。三个偏好加起来 161%，而且图上没有误差棒，也没有样本量。「w/o metric scale alignment」必须重新训练一个模型，训练预算是否相同没说。「w/o joint RGBD」如果是同一个 checkpoint 直接删掉深度 token，那这个对照组本身就处在分布外。

怎么解决：给出偏好的定义、样本量和置信区间，说明各消融模型的训练预算。

07中人评规模很小，而且只报名次：10 人 × 10 段▶

证据：10 段只占评测集 78 段的 13%。只给了名次，没有得分、置信区间或显著性，也没说是否盲评、是否打乱顺序。第一、二名都是自家变体。人评和 VLM 的一致性一般：和 Ref WR 的 Spearman 只有 0.50（§7）。

08中声称能适应「不同抽象层级」的白盒，却没有按层级拆开的结果；ProxyBench 是自建的，也还没发布▶

证据：引言把「能否适应不同抽象层级」列为中心问题之一，相关工作也说「enabling transfer to low-poly, primitive, and incomplete proxies」。但实验只报告了 78 段的总平均，没有按低模 / 基本体 / 残缺分组。ProxyBench 由作者自己构建（「agent-driven」，流程没写），78 段的挑选标准是「强调交互、平衡运动类型」，比较模糊。基准和方法出自同一个团队、同时发布，而基准本身还没公开。

09中Table 1 里 τ=0 这一行的相机图标是灰的，和方法描述矛盾▶

证据：§3.4 写的是「Camera-grid guidance is retained throughout both stages」，三种模式应该都带相机网格。但 Table 1 里「Ours (T2V, τ=0)」的输入图标只有文本和白盒亮着，相机是灰的（#D1D1D1），和 VACE、Cosmos 一样。要么 τ=0 这一行其实没给相机网格，那 τ=0 和 τ* 之间就同时变了两个量；要么图标标错了。

10中部分基线的相机误差大得反常▶

证据：FantasyWorld 的 nATEt / nATEr 是 0.2966 / 0.3472，Coarse2Real 的 nATEr 是 0.3152，比其他方法高一个量级。这种量级常见于坐标系约定（OpenCV 和 OpenGL、c2w 和 w2c）或平移尺度没对齐的情况。Coarse2Real 原本面向人群仿真的粗渲染，适配到 ProxyBench 的方式没有说明。

影响：基线弱会放大「我们更好」的印象。好在最关键的比较（vs Cosmos / VACE）不受这一条影响。

11中没报告推理代价；「world model」的定位和一个离线双向生成器之间有落差▶

证据：token 数翻倍（65,520），我估算每步算力约为原 Wan2.2 的 3 倍。一次生成 81 帧、40 步、带 CFG，不是自回归，也不能边交互边生成。结论承认「长时程交互生成留待未来」。标题和引言用的是 world generation / world model 的叙事，项目页也展示了游戏玩法和 UGC，但这些都是离线渲染出来的片段。

12低⌊(1 − 0.925) × 40⌋ 在浮点里等于 2，不是 3▶

证据：在 IEEE 754 双精度下，1 − 0.925 = 0.07499999999999996，乘以 40 得 2.9999999999999982，floor 之后是 2。论文正文写的是「three geometry-conditioned steps」。如果代码逐字实现了 ks = ⌊(1−τ)N⌋，实际只跑 2 步。复现时要留意：用 round、加一个 ε，或者直接指定 ks。

13低Hilbert 伪彩的「可逆」很脆弱；生成出来的深度质量没有评估▶

证据：§3.3 的模拟显示，3 阶曲线在颜色噪声 σ ≥ 0.03 时开始出现整段跳变，σ = 0.05 时约 13% 的样本误差超过量程的 1%。论文把生成的深度伪彩当作副产物输出，还说它「可以恢复米制深度」，但没有任何关于解码深度质量的数字。这一条不影响 RGB 结果。如果有人想拿它的深度输出做下游任务，需要注意。

14低训练数据的细节：以静态场景为主；深度来源不明；有一处引用很奇怪▶

证据：三个数据源里，DL3DV 和 RE10K 都是静态场景，动态主体只能靠游戏数据来学，但各数据源占多少没有给。「深度和相机共享任意尺度」这句话引用的是一篇合成到真实的自监督深度估计论文（Yan et al., 2025，第一作者与本文二作同名），但没说训练深度是不是由它生成的。

15低相关工作漏掉了几篇最接近的前作▶
  • LooseControl（Bhat, Mitra, Wonka, 2023）：用场景边界和 3D 包围盒这类「松散深度」控制图像生成，处理的正是「粗几何作为条件、细节交给模型」这个问题。
  • CineMaster（2025）：用 3D 包围盒加相机轨迹控制文生视频，和白盒控制非常接近。
  • UniDiffuser（Bao et al., 2023）：每个模态一个时间步，一个网络同时学条件生成和联合生成，是 §4 设计的直接前辈。
  • ControlNet 的 guidance end / SDEdit：「条件只在前若干步生效」的思路来源。

这些前作不否定本文的组合创新，但会改变读者对「新意在哪」的判断。

  • 「gampeplay dataset」「we istead」「Rerpoj.」（Fig 3）。
  • 评测用的「Gemini-v3.7-flash」，引用的却是 2023 年的 Gemini 技术报告。

09 · CREDIT

做对了的地方

  • 完全绕开配对数据。课 1 + 课 2 + 中途切换，训练只需要随处可得的 RGBD 视频。这个配方简单，可迁移，而且不依赖任何白盒风格，换成胶囊骨架、包围盒也同样适用。
  • 切换点设计得很干净。推理只用训练中出现过的 (t, 0) 和 (t, t) 两种噪声组合，切换那一刻两路噪声水平相等。没有引入训练时从未见过的异步噪声。
  • 米制尺度对齐。动机清楚、代价很低（一次 DA3 前向），而且有消融支撑。用「网格视频」表示相机的做法，都应该配上这一步。
  • 一个 checkpoint，三种控制强度。τ 可以直接当成用户旋钮：只给相机、白盒、精细深度，不需要为每种白盒单独训练。
  • 数字自洽。VLM 胜率是完整的循环赛（均值恰为 50%），正文里的百分比全部可以复算。
  • Table 1 标了输入图标。正是这个细节让口径问题看得出来。这点值得肯定，只是正文的讨论没有顺着它展开。

对 CWM 渲染器路线意味着什么

对照你在 papers/cwm-renderer-candidates-2609.md 里整理的需求：CWM（精读）要的是「固定 log 深度 + 语义 ID」的白盒视频、逐实体的结构化文本、首帧锚图，并且最终要做成自回归实时渲染。

维度Proxy2World对 CWM 的含义
条件形态只有深度（Hilbert 伪彩）+ 相机网格；没有语义、实例 ID，也没有实体和文本的绑定不够用。CWM 需要「哪个 ID 是哪个实体」，要借 PWM（精读）的身份槽，或者 DAR / Marionette 的 ID 通道
训练数据不要配对，普通 RGBD 视频即可最值得借鉴的一点。CWM 目前靠 GTA V 5.6 小时的配对录制。换成这个配方，任何带深度（或可以估深度）的视频都能用，数据规模就不再受配对的限制
生成方式14B MoE、双向、81 帧、40 步、每步约 3 倍算力不能直接当实时渲染器。更适合当老师或数据生成器：用它批量产出（白盒，视频）配对，再蒸馏一个因果学生
τ 旋钮依赖 40 步的细粒度：前 3 步给条件蒸馏到 3–4 步以后，「前 3/40 步」没有对应的粒度。可以让学生的第一步带深度、之后不带，或者训练时把 τ 当作一个输入条件
首帧锚图TI2V 比 T2V 高 20 多个胜率点和 CWM 用 GPT Image 2 做锚图的设计一致，说明锚图非常值钱。评测时也要把锚图的效应单独拆出来，否则会高估渲染器本身的能力
米制对齐DA3 对齐深度和平移CWM 的白盒来自程序，本来就是精确的米制，可以直接受益。如果训练数据混入 SfM 视频，一定要做这一步
建议在候选清单里的定位：放在「第三梯队：老师 / 设计参考」，和 Marionette、DAR 并列。它的配方（不用配对数据的两模式训练 + 中途切换）应该被吸收进「正式方案」的训练流程：用课 1 + 课 2 训出 Wan2.2-5B 双向老师，再按 Magpie / AlayaRenderer-Flash 的路线自蒸馏出因果学生。代码目前没发布，以上都要等开源后再确认。
