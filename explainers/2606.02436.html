GIM-World

几何不该只是喂给生成器的又一路条件，它应该是「被记住的世界」自带的属性

世界模型跑长了会崩，崩的方式很具体：回到走过的地方，那里已经不是原来的样子了。 现有做法要么把过去原样存下来（存帧、存 KV、存在线三维重建），要么把过去压成一个定长状态。 前者受检索启发式和重建误差的拖累，后者——这是本文的切入点——压完之后没人规定里面必须装什么： 只用流匹配损失训练，定长状态完全可以把容量花在跨视角高度冗余的外观信息上，而不是场景结构。 作者的解法是给记忆加一道训练期的问答题：拿一个历史相机的位姿生成 ray map 去查询记忆， 要求查出来的东西能对上 VGGT 在那一帧上的特征。答得上，说明记忆里存的是跨视角的场景结构而不是某几张图的外观。 推理时几何头和 VGGT 一起丢掉，只剩一个占 DiT 0.26% 时间的编码器。

00TL;DR

三件套：一个编码器、一道训练期问答题、一条剪枝规则

论文的方法部分只有三块，而且互相独立到可以分开评价。真正新的只有中间那一块——把 3D 基础模型的监督 从「贴在生成器的中间层上」挪到「贴在记忆状态上」，并且用相机 ray map 作为查询来绕开「压缩后的 token 和输入帧不再一一对应」这个障碍。 另外两块都是成熟零件的合理组装。

① §3.2 编码器
把变长历史压成 Nm 个槽
一组可学习的 memory query 去 attend 历史 token，两层 block 就结束。注意力在 s×s 池化后的低分辨率上做（s = 2），FFN 保持全分辨率。 记忆尺寸不随历史长度变化，推理开销 0.26% DiT。
② §3.3 几何监督
用历史相机去「考」记忆
随机抽一个历史帧 i，把它的位姿变成逐 patch 的射线查询，cross-attend 记忆，要求输出对齐冻结 VGGT 在该帧的特征（逐 patch 余弦）。 训练期存在，推理期删除。这是全文唯一的原创机制。
③ §3.4 剪枝
编码之前先扔掉冗余帧
在「位置 + 朝向 + 时间」的高斯过程下，按 Krause 等人的传感器布点准则挑 K = 200 帧，使保留集对被丢掉的帧最有预测力，贪心求解。 记忆是定长的，但建记忆的成本仍随历史增长，这块专治这个。
一句话概括这篇论文的赌注

Geometry Forcing 把 VGGT 特征对齐到生成器的中间层，本文把同样的教师对齐到记忆状态。 在同一套骨干、同一份数据、同一个训练预算下，这个位置的差别把 3D 重投影分数从 63.40 拉到 81.70（Tab. 2）。 如果这个数字站得住，那么它说明的东西比方法本身更有意思：长程一致性的瓶颈不在生成器懂不懂几何，而在被压缩的那个状态里到底留下了什么。

01Problem

观测离开上下文窗口之后，还剩下什么

世界模型的长程一致性问题可以精确地重述一次：当一帧观测滑出模型的原生上下文窗口之后，它以什么形式继续影响生成？ 这个问题的答案就是「记忆算子 M」的设计空间。论文把它切成两族，并且给出了各自的失效模式。

族记忆里存的是代表工作论文点名的失效模式

把这张表读一遍就能看出本文的落点：它不打算修复显式记忆，而是接受隐式记忆「尺寸不随历史增长」这个优点， 然后专门去补它唯一的缺口——训练信号。这是一个很干净的论证结构，值得给分。

另一条相关的线是「把几何塞进视频生成器」。论文把它归纳成三条轴，并且明确说自己不走这三条：

  • 直接条件化：把几何 token / point-map 投影拼进生成器输入（Uni3C、Geometry-as-Context、GEN3C、CineScene、LaVR）；
  • 特征监督：训练时把生成器骨干的中间特征对齐到 3D 特征（Geometry Forcing、REPA）；
  • 后训练对齐：从 3D 特征里导出奖励或偏好，再跑一轮 DPO / RL（VideoGPA、Epipolar-DPO、VGGRPO）。

三条轴的共同点是几何最终作用在生成器或它的输出上。论文原文的表述是 “We take the opposite view. Geometry is best treated as a property of the remembered world rather than only as an additional signal on the generator.” 这句话是全文的支点，后面所有设计都是它的推论。

读到这里我的第一个疑问

「记忆 vs 生成器」这个二分法在本文的架构下其实是滑动的：记忆 m 最终是沿时间轴拼进 DiT 的输入序列的（照搬 Context-as-Memory 的做法）， 也就是说它是 DiT 的一段 context token。那么「监督记忆」和「监督生成器的输入端 token」的边界在哪？ 我倾向于认为本文真正的对照不是「记忆 vs 生成器」，而是「监督一组无帧序对应的抽象槽位」vs「监督一组与帧/patch 一一对应的特征」—— 这也正是 §3.3 里作者自己给出的技术理由。这个区别是实在的，但它比论文摘要里那句口号要窄。

02§3.2 Memory Encoder

编码器：两层 block，注意力在池化后的分辨率上做

这一块几乎没有新东西，但有两个设计决定值得单独拎出来：相机信息只加在历史 token 上，memory query 保持 pose-free； 以及 Compact 只作用在注意力分支，FFN 留在全分辨率。后者在消融里是全表最敏感的一个开关。

03§3.3 Camera-Queryable Geometry Supervision

核心：为什么不能照抄 Geometry Forcing，以及绕过去的那一步

这是全文唯一的原创机制，而它的动机是一个非常具体的技术障碍。 Geometry Forcing 那种「逐 token 对齐」有一个隐含前提：学生的表示仍然按「帧 × 空间位置」索引，所以才能一格对一格地贴上去。 记忆 token 恰好没有这个性质——压缩之后，第 k 个槽位不对应任何一帧、任何一个 patch。

论文对这一点的表述很清楚，我原样抄下来因为它是整个设计的逻辑起点：“its tokens carry no one-to-one correspondence with input frames or patches, and direct token matching would impose an artificial ordering on the memory slots and collapse the representation back toward a frame-indexed cache.”

这句话里藏着两层意思。第一层是技术上做不到：没有对应关系就没法算逐 token 损失。第二层更重要，是不应该做： 如果硬给记忆槽位安排一个「第 k 个槽对应第 k 帧」的顺序，那这个记忆就退化回一个按帧索引的 cache，隐式记忆的全部意义就没了。 所以作者需要一种与槽位顺序无关的读取方式——他们选的是用相机去查询：不问「第 k 个槽里是什么」，而问「从这个位姿看出去，应该是什么」。

3.1查询是怎么造出来的：ray map 的六个通道

ρ(ci)u,v = [ oi , di,u,v ] ∈ ℝ6(11) 每个 patch (u, v) 对应一条世界坐标系下的射线：相机光心 o（3 维）拼上归一化的射线方向 d（3 维）。 注意 o 对整张图是同一个值，所以这 6 个通道里真正随 patch 变化的只有 3 个。
qi,u,v = MLPray( ρ(ci)u,v ) + eu,v(12) 射线经一个小 MLP 嵌入，再加上一个跨帧共享的可学习 2D 网格位置嵌入 e。后面这一项很关键：它给了查询一个「我是第几号 patch」的身份， 补上了射线本身不含的网格结构信息。
Ĝi = FFN( SelfAttn( CrossAttn( qi , m ) ) )(13) Cross-attention 负责「从记忆里取出回答这条射线所需的信息」（Q 来自射线，K/V 来自记忆）， self-attention 负责在 patch 网格内互通有无，FFN 把维度投到 VGGT 的特征维 dg。
Lgeo = 1 − 1HgWg Σu,v cos( Ĝi,u,v , Gi,u,v )(14) 纯角度对齐，不含 Geometry Forcing 里的 scale alignment 项。论文没有解释为什么省掉这一半—— 而 Geometry Forcing 的消融里，Angular 单独用是 FVD 253，加上 Scale 是 243，作者认为「两者缺一不可」。这是一处可追问的取舍。

每一步只均匀采样一个历史帧 i 来算这个损失。论文给的理由是无偏性：因为 i 每步重采，单帧估计对「全帧对齐目标」是无偏的， 而每步的蒸馏开销与历史长度无关。这个说法在数学上是对的（对帧求平均的目标，均匀采样一项即为无偏估计），而且按 batch 32 × 8K 步算， 总共约 26 万次帧级查询，覆盖不是问题。真正的代价在别处：每步只有一帧的梯度流回记忆，而这块记忆是由 200 帧压出来的—— 也就是说单步里 99.5% 的输入内容拿不到几何梯度，只能靠训练全程去平均。

我在这一节最想追问的两点

① 「VGGT encoder feature」到底取的是哪一层？论文写的是 “the VGGT encoder feature map Gi”。 VGGT 的结构是：DINOv2 patch encoder → 交替注意力聚合器（帧内 + 全局）→ 各任务头。 如果取的是聚合器输出，那是几何特征（Geometry Forcing 明确说取 “features from the Transformer backbone of VGGT”，并且聚合了全部 block）； 如果取的是DINOv2 编码器，那基本是语义特征——Geometry Forcing 自己的消融里，对齐 DINOv2 只能到 FVD 297，对齐 VGGT 是 243。 这个词的歧义直接决定「几何蒸馏」这个说法有多硬。

② VGGT 是逐帧跑的还是多帧一起跑的？论文说 “dense per-frame geometric features”，并且每步只采一帧。 但 VGGT 的全局注意力是跨帧的：单帧输入时它退化成单目估计，尺度与全局对齐都无从谈起，不同帧的特征也就不在同一个坐标系里。 Geometry Forcing 恰好做过这个消融（Tab. 9）：对齐上下文长度 4 → 8 → 16 帧，FVD 从 261 单调降到 243，结论是「上下文越长几何信息越完整」。 如果 GIM-World 真的每步只送一帧进 VGGT，那么它蒸馏的「几何」其实是单目、相对、每帧各自一套的东西， 而它却指望记忆据此建立跨视角一致的结构——这中间是有缝的。论文没有交代这个细节。

04§3.4 Information-Guided Pruning

剪枝：记忆是定长的，但「建记忆」的成本不是

这一块解决的问题很朴素：编码器要读完所有历史 token，而历史会一直变长。 论文的做法是在编码之前先挑 K = 200 帧，挑的准则不是「均匀」也不是「离得远」，而是 「留下的这一批，对被扔掉的那一批最有预测力」——直接搬的是 Krause 等人 2008 年的传感器布点准则。

S⋆ = arg maxS  I( S ; H \ S )    s.t. |S| ≤ K(15) 选一个子集，让它和「补集」之间的互信息最大。直觉：如果留下的帧能高度预测被扔掉的帧，那扔掉它们就没损失多少信息。 注意这不是「覆盖最广」——覆盖最广的解会去挑那些谁也预测不了的离群帧，而这个准则会主动避开它们。
k(ci, cj) = exp( − ‖pi − pj‖²2σp² − ∠(fi, fj)²2σr² − (ti − tj)²2σt² )(16) 高斯过程的核：位置近、朝向近、时间近的两帧被认为高度相关。三个带宽 σp, σr, σt 的取值论文一个也没给， 但下面这个玩具会告诉你它们决定了整个算法的行为。

这条核函数只看位姿和时间，不看内容

式 (16) 的三项全是几何/时序的代理量。这带来两个已知的盲区： ① 遮挡——两台相机位置相近、朝向相同，但中间隔了一堵墙，核函数认为它们高度相关，实际上看到的是两个不同的场景； ② 动态内容——同一位姿在不同时刻看到的东西可能完全不同（角色走过、门开了），时间核会把它们当成「不相关」而各留一帧，这恰好是对的； 但如果 σt 很大，它们又会被当成冗余而只留一帧，这就错了。 论文既没给 σ 的取值，也没做 σ 的敏感性分析，而上面的沙盘显示σt 单独一个旋钮就能让 MI 贪心在「等价于均匀采样」和「纯空间选点」之间滑动。 Tab. 3 里 MI 贪心比均匀采样好 4.65 个重投影分——这个增量到底是准则本身的功劳，还是一组恰好调好的带宽的功劳，从论文里看不出来。

05§3.5 Training & Inference

一个损失，一个阶段，推理时删掉一半模块

L = LFM + λ · Lgeo ，　λ = 0.05(19)(20) LFM 是条件在记忆与未来动作上的流匹配损失。记忆编码器、几何头、DiT 骨干三者联合优化， 没有预训练、没有蒸馏、没有分阶段微调——这在工程上是个真实的优点，值得给分。

推理时几何头和 VGGT 都不再需要，直接丢弃。这意味着几何监督对部署形态零成本：一个已经上线的世界模型， 换成这套训练方式重训之后，推理代码不需要动。这是它相对「在线三维重建」类方案最实际的优势。

两个论文没写、但决定这套东西能不能用的问题

① rollout 时生成帧的相机位姿从哪来？记忆编码器要求每一帧都带 ci，而自回归时新帧是模型生成的。 在 MIND 的设定里位姿可以从动作序列（Δp、Δr 是已知常数）直接积分出来，所以这个问题在基准内不存在。 但这也意味着：方法依赖一个精确的「动作 → 位姿」映射，换到没有这种映射的真实视频上就没法用。 更微妙的是，RPE 指标本身说明生成内容并不严格跟随指令位姿（第一人称旋转 RPE 0.4126）， 也就是说写进记忆的位姿标签会随 rollout 逐渐偏离画面真正的视角——这是一条论文完全没有讨论的误差通路。

② 记忆不是循环状态。按 Fig. 2 的数据流，每一步是「把新帧追加进历史 → 重新剪枝 → 重新编码」。 也就是说被剪掉的帧不会以任何压缩形式残留，记忆的有效感受野严格等于当前保留的那 K 帧。 这和「把无界历史压进定长状态」的叙事有出入：真正处理无界历史的是剪枝规则，记忆只是对剪枝结果做了一次编码。

6.1先说这张表最值得肯定的地方

重投影分数上的差距是真的大。第一人称 81.70 vs 最强显式基线 73.97、隐式 SSM 53.95；第三人称 87.10 vs 70.82 / 61.26。 而且旋转 RPE 的改善同样显著（0.4126 vs 0.5697 最好基线；第三人称 0.1588 vs 0.2852）。 旋转误差和几何一致性一起改善，这在机制上是自洽的——记忆里如果真的存了跨视角结构，模型对「转过去应该看到什么」会更有把握。

另外，把「几何记忆」和「动作可控性」分开看是重要的：论文声称动作精度「至少与最强基线持平」。 严格说这句话在第一人称平移上不成立——Context-as-Memory 的 0.0235 好于本文的 0.0247，本文是第二。 但差距在千分之一量级，而且其余七个动作指标本文都最好，所以这只是措辞不够精确，不是结论问题。

6.2再说这张表必须打折的地方

绝对值告诉你：所有方法都在「基本对不上」的区间里

PSNR 全场 11.76 – 13.58 dB，LPIPS 0.60 – 0.74。这不是排版错误，这是长程自回归逐帧对齐比较的常态 （Geometry Forcing 在 RealEstate10K 上 256 帧的 PSNR 也只有 11.4–11.9）。但它的含义要说清楚： 在这个量级上，逐帧重建指标已经几乎不携带「看起来像同一个场景」的信息了， 它主要在量「漂移得多快」。所以 MSE 从 0.0706 降到 0.0614、PSNR 从 12.50 涨到 13.40，方向是对的，但不足以支撑「视觉上与真值一致」这类表述—— 那部分结论实际上是靠 Fig. 3–5 的定性图撑起来的。真正拉开差距的是重投影分数，而它是个归一化到 0–100 的自定义分数，论文没有给出归一化公式。

MIND 自带的那个「重访一致性」指标，恰好没被报告

MIND 定义了五个评测维度，本文只用了其中两个（Long Context Memory 的 MSE、Action Accuracy 的 RPE）， 没有报告 Generated Scene Consistency——那是 MIND 专门为「场景一致性」设计的指标：让模型沿 10 条对称路径走过去再原路返回， 比较去程帧与回程帧的 MSE。这恰恰是最直接衡量「回到走过的地方还一样吗」的量，也正是本文全篇要解决的问题。 同时被略过的还有 Action Space Generalization、Aesthetic Quality、Imaging Quality。 我不认为这是刻意隐瞒（本文自己加了重投影分数，工作量并不小），但在一个自带专用指标的基准上不报告那个指标，需要一句解释，而论文没有给。

09Open questions

我的存疑清单：20 条，按「会不会动摇结论」排序

先说结论：我认为这篇论文的核心主张是站得住的——把 3D 教师的监督从生成器挪到记忆状态上，在同一套对照下带来了大幅提升， 而且机制解释（旋转 RPE 与重投影一起改善）是自洽的。下面的疑问不是要推翻它，而是标出「哪些数字目前无法被独立验证」以及 「哪一个实验能把话说死」。前四条如果得不到回答，主结论的强度要打折；后面的多数是可修复的表述与细节问题。

筛选严重度：
D-01高「几何蒸馏」这个说法有多硬，取决于两个论文没写的词▸
论文怎么写的
“we supervise against the VGGT encoder feature map Gi of the same frame” · “3D foundation models recover dense per-frame geometric features”
为什么可疑

① “encoder” 指哪一层？VGGT = DINOv2 patch encoder → 交替注意力聚合器 → 任务头。取聚合器 = 几何特征；取 DINOv2 = 语义特征。 Geometry Forcing 明确写了取 “features from the Transformer backbone of VGGT” 并聚合了全部 block，还专门做过消融： 对齐 DINOv2 只到 FVD 297，对齐 VGGT 是 243。本文用的词恰好是最含糊的那个。

② 是不是逐帧单独跑 VGGT？“per-frame” + 每步只采一帧，读起来像是单帧输入。但 VGGT 的跨帧全局注意力在单帧下失效， 输出退化为单目、相对尺度、各帧一套坐标系的表示。而记忆被要求学的是跨视角一致的结构——用一堆互不对齐的单帧特征去教跨视角一致性，中间是有逻辑缝隙的。 Geometry Forcing 的 Tab. 9 正好显示对齐上下文 4→8→16 帧单调变好。

怎么一句话验证

作者公布：取的是聚合器第几层（或哪些层的聚合）、VGGT 每次前向送几帧。若是「聚合器 + 多帧」，D-01 直接消解；若是「DINOv2 + 单帧」，那这篇的贡献要重新表述为「可查询的表示蒸馏」而非「几何蒸馏」。

D-02高缺一个对照：收益来自「几何」，还是来自「记忆被迫可解码」？▸
问题

Tab. 2 一次改了两件事：监督位置（生成器→记忆）和监督接口（token 配对→相机查询）。 因此 58.80 → 81.70 里，无法区分以下两种机制：
(a) 记忆里真的被写进了三维结构；
(b) 记忆多了一个与流匹配正交的辅助解码任务，任何这样的任务都会迫使它保留更多可复原的信息（类似自编码正则）。

缺的那一行

保持完全相同的相机可查询几何头，只把监督目标换掉：
· 换成该帧的 VAE latent / RGB（纯外观重建）
· 换成 DINOv2 特征（纯语义）
如果 RGB 版也能到 75+，那论文的标题就该改。这是我认为审稿最应该要的一个实验，成本也最低（改一个 target，重跑 8K 步）。

D-03高主结论最依赖的那个数字，没有给出定义▸
论文怎么写的
“we estimate per-frame depth and camera pose with Depth Anything 3, compute cross-frame cycle reprojection error, and normalize it to a 0–100 score where higher is better.”
为什么可疑

归一化函数是什么、用哪些帧对、循环长度多少、误差以像素还是相对单位计——一条也没说。 而全文最大的差距（81.70 vs 63.40 vs 53.95）全部落在这个分数上。一个未知的非线性映射可以把很小的原始误差差异放大成几十分。 没有这个公式，任何第三方都无法复现这一列，也无法把本文与其他论文的「几何一致性」横向比较。

反方证据（对论文有利）

Tab. 4 里 Full attention 81.85 与本文 81.70 几乎相同，而 Global Compact 掉到 62.45——说明这个分数确实能稳定地区分架构质量，不是纯噪声放大器。所以我的判断是「不可验证」而不是「有问题」。

D-04高从头到尾没有直接检查过记忆里到底有没有几何▸
问题

论文的全部证据都是下游的：生成结果的重投影分数高、旋转误差低、定性图看起来稳。 但「记忆状态编码了跨视角场景几何」是一个关于表示的断言，而它从未被直接测过。

同行是怎么做的

Geometry Forcing 做了：冻结模型、在中间特征上训一个 DPT 头回归深度，直接展示「基线的特征重建不出有意义的三维，我们的可以」（其 Fig. 1c），这是一个线性探针式的证据。 本文有一个现成的、更好的探针——几何头本身就是「相机 → 特征」的解码器，只要把它接上 VGGT 的 DPT 头，就能从记忆里渲出深度图/点云。 这个实验几乎不要额外成本，却是全文最有说服力的一张图，作者没做。

附带的问题

训练时查询的一律是历史帧的相机。从没测过没见过的视角。「记忆是一个可从任意视角查询的世界状态」这个更强的说法，目前没有实验支持。

D-05中基准自带的「重访一致性」指标恰好没被报告▸

MIND 定义了 Long Context Memory、Generated Scene Consistency、Action Space Generalization、Action Accuracy、Aesthetic/Imaging Quality。 本文只报了第一和第四。其中 Generated Scene Consistency 是让模型沿 10 条对称路径走过去再原路返回、比较去程与回程帧的 MSE—— 这是最直接量「回到走过的地方还一样吗」的指标，也正是本文的问题定义。 本文另起炉灶做了自己的重投影分数（工作量不小，不像是回避），但在自带专用指标的基准上略过那个指标，需要一句解释。 同时被略过的 Aesthetic / Imaging Quality 也意味着：无法判断几何监督有没有牺牲单帧画质。

D-06中剪枝那一节的数值细节一条都没给，而它们决定行为▸
缺什么

① 三个带宽 σp, σr, σt 的取值；② GP 的噪声项/nugget（没有它 KAA 在近重复帧上会奇异）； ③ 式 (18) 分母 σ²(h | S̄\{h}) 的实现——严格算是每个候选一次 O(N³) 求逆，Krause 等人靠 local kernel 截断，本文只字未提； ④ K = 200 指的是原始帧还是 latent 帧；⑤ 剪枝本身的耗时。

为什么要紧

§04 的沙盘里，只拨 σt 一个旋钮，MI 贪心就能在「几乎等于均匀采样」和「纯空间选点」之间滑动。 Tab. 3 里 MI 比均匀好 4.65 分——这个增量是准则的功劳还是一组恰好调好的带宽的功劳，论文里看不出来。 另外 ⑤ 尤其讽刺：引入剪枝的理由就是「控制随历史增长的成本」，而它自己是全流程唯一随历史增长的模块，却是唯一没被计时的。

D-07中抄来的两行基线，设定与本文不可比▸

Matrix-Game 2.0 在 MIND 原表里位于 “w/o Context Memory (Image-to-World)” 一栏，即在没有上下文记忆的设定下测得， 却在本文 Tab. 1 中被归入「显式记忆」组，成为该组表现最差的一行（MSE 0.1188 / 0.1404）。这会让「显式记忆很弱」的印象被放大。
MIND-World 的骨干是 SkyReels-V2-I2V-1.3B，且是 4 步因果蒸馏的实时流式学生；本文是 Wan2.1 多步扩散。 两者的 MSE 差距里有多少来自记忆设计、多少来自「实时 4 步 vs 非实时多步」，无法分离。
公允地说，论文确实标注了这两行是直接引用、且用「–」标出缺失列，没有隐瞒。问题只在于它们和重训的三行被放进了同一张表、同一个分组标题下。

D-08中8K 步 / batch 32 的预算，对重训基线是否足够▸

「同骨干、同预算、同数据」是本文对照设计里最值得肯定的部分，但它有一个副作用： FramePack 与 Context-as-Memory 各自原本有专门的训练配方（FramePack 的 anti-drifting 采样、CaM 的检索式上下文构造与训练课程）， 被统一成 8K 步、lr 1e-5、同一个 memory-token 预算之后，它们是不是被训到了各自的水平，无从判断。 对本方法而言 8K 步够用（它只是给 Wan2.1 加模块微调），但对结构差异更大的基线未必。 能消解这条的最小实验：给每个基线画一条 4K/8K/16K 步的曲线，证明大家都收敛了。

D-09中只在一个合成数据集上验证，且训练场景只有 50 个▸

MIND 全部是 UE5 渲染的，共享同一套 WASD + 四方向旋转的动作空间；训练用 50 条第一人称 + 50 条第三人称片段。 按每条约 3 分钟 / 24fps 算，训练视频总量约 4.3 小时。没有真实视频实验，没有跨数据集迁移，没有换动作空间的测试 （MIND 自带的 Action Space Generalization 子集也没用）。 对一个声称学到「场景几何」的方法，合成渲染的几何过于干净——真实视频里 VGGT 教师本身的可靠性会显著下降，而这正是 Geometry Forcing 自陈的局限（VGGT 主要在静态场景上训练）。

D-10中rollout 时的位姿从哪来，以及位姿标签会漂移▸

编码器要求每帧带 ci，但自回归生成的新帧没有真实位姿。在 MIND 里可以从动作序列积分出来（Δp、Δr 是常数）， 所以基准内没问题——但这把方法绑死在「存在精确动作→位姿映射」的环境里。
更细的一层：RPE 不为零说明生成画面并不严格执行指令位姿。于是写进记忆的位姿标签会随 rollout 与画面真实视角逐渐脱节， 而几何头恰恰是靠位姿建立对应关系的。这是一条会随时间放大的误差通路，论文没有讨论，也没有做「位姿加噪」的鲁棒性实验。

D-11中「把无界历史压成定长状态」——压缩主要是剪枝干的▸

见 §02 的推算：Nm = 20 个 latent 帧的 token，而剪枝后的历史是 50 个 latent 帧（K=200 原始帧）—— 学出来的那一步压缩约 2.5 倍，从几千帧到 200 帧的那 16 倍是不含学习成分的启发式规则做的。 同时记忆不是循环状态（每步重新编码），被剪掉的帧不留任何残迹，有效感受野严格等于保留的 K 帧。 这不影响实验结论，但让摘要里 “compresses variable-length history into fixed-size memory tokens” 这句话听起来比实际做的事更强。

前提：这里假设 Wan2.1 VAE 为空间 8× / 时间 4× 压缩、patch (1,2,2)，且 K=200 计的是原始帧。论文没给训练分辨率与骨干规格，所以这是推算而非事实。

D-12中没有敏感性分析，没有误差棒，单次运行▸

λ = 0.05、Nm = 20 latent 帧、K = 200、s = 2、几何头的层数与宽度——除了 s 之外一个都没有扫过。 全文没有多种子、没有方差、没有置信区间。这在视频生成领域是常态，但它让某些细小的反直觉结果（比如 Tab. 4 里 Attention Compact 的 LPIPS 反而好于 Full attention）无法判断是信号还是噪声。 考虑到主表里几个方法在 MSE 上的差距只有 0.005–0.01 量级，至少给主表加一组种子是值得的。

D-13低省掉了 scale alignment，没解释▸

式 (14) 只有角度项。Geometry Forcing 的做法是 Angular + Scale 两项，并且它的 Tab. 3 显示：Angular 单独 FVD 253，加 Scale 是 243，直接 MSE 则崩到 1648。 本文继承了「角度」但丢掉了「尺度」，也没说为什么。合理的猜测是记忆 token 与 VGGT 特征的尺度差异更大、加 scale 项不稳定； 但既然对照组就是 Geometry Forcing，这个取舍值得一句说明——否则「本文赢了 GF」里有一部分可能只是「本文的 GF 复现少了一半」。 （论文说 Geometry Forcing 那一行是「reproduces Wu et al. by distilling VGGT features into intermediate diffusion layers」，没写是否含 scale 项。）

D-14低符号冲突：K 有两个意思▸

§3.1 里 K 是一次生成的未来帧数（xt+1:t+K, at+1:t+K）； §3.4 里 K 是剪枝预算（|S| ≤ K），§4.1 写「K = 200」。两者在同一篇里没有区分。 读到 §4.1 时会真的产生歧义：200 是生成块长度还是保留帧数？（按上下文是后者。）

D-15低「四个重训基线」，但只描述了三个▸

§4.1 原文：重训 FramePack 与 Context-as-Memory，复现 VideoSSM 的 SSM 模块——共三个；紧接着写 “The four retrained baselines share the same Wan2.1 backbone…”。要么少描述了一个基线，要么把本方法也算进去了。小笔误，但读者会数一遍。

D-16低一处抄录偏差：0.3328 vs 0.3338▸

Tab. 1 第三人称 MIND-World 的 Rot RPE 写作 0.3328；MIND 原论文 Tab. 3（w Context Memory 行）是 0.3338。 其余抄录的数字（0.1188 / 0.0265 / 0.6914 / 0.1035 / 0.0384 / 0.5534 / 0.1404 / 0.0622 / 0.9031 / 0.1042 / 0.0321）我逐个核对过，都一致。 纯排版级问题，不影响任何结论，列在这里只是为了说明其余数字是核对过的。

D-17低“I(S; H\S) is submodular” 说得比原文强▸

Krause、Singh、Guestrin (JMLR 2008) 的结果是：互信息目标在足够细的离散化下是近似次模的（带一个 ε 项），并且它不是单调的， 贪心的 (1−1/e) 型保证需要附加条件。本文写成「I(S; H\S) is submodular, and the standard greedy rule is near-optimal」， 把「近似次模 + 条件性保证」压成了「次模 + 近最优」。工程上无所谓（贪心本来就是当启发式用的），但理论表述不够严谨。

D-18低「动作精度至少与最强基线持平」有一个反例▸

第一人称平移 RPE：Context-as-Memory 0.0235 优于本文 0.0247，本文第二。 其余七个动作指标（第一人称旋转、第三人称平移与旋转，及与其他基线的比较）本文都最好。 所以这只是措辞问题——写成「除第一人称平移外均最优」会更准确。

D-19低ray map 用的是原始世界坐标，没提归一化▸

式 (11) 里 oi 是世界系光心。论文没有提到任何中心化或尺度归一化。 在 UE5 里不同场景的坐标原点和量纲各不相同，MLPray 拿到的输入分布会随场景平移。 训练集 50 个场景、评测集是另外的场景，所以这不会造成泄漏，但会影响泛化，也几乎肯定挡住向真实数据集的迁移 （真实数据的位姿由 SfM 恢复，尺度是任意的）。见 §03 Fig. 4 的交互——拖「光心 x」时，6 个通道里有 3 个整体平移。

D-20中相关工作把「显式三维重建」立为对照族，实验里却一个都没比▸

§1 和 §2.2 花了不少篇幅论证「在线三维重建类记忆」的缺点（重建管线开销、对动态/遮挡/弱纹理敏感、误差累积）， 并把 GEN3C、VMem、Long-term Spatial Memory、UCM 等列为该族代表。但 Tab. 1 里一个都没有出现。 实际比较的显式基线全是「存帧/存 token」类（FramePack、CaM）。 这在工程上可以理解（重训一套在线重建管线到同一骨干上代价很大），但它意味着本文最直接的几何竞争者从未被量化对比过—— 而重投影分数恰恰是显式三维记忆最可能占优的指标。

如果只做一件事来加固这篇论文

做 D-02：保持相机可查询的几何头不变，把监督目标换成 RGB / VAE latent 再跑一遍 8K 步。 这一个实验同时回答三件事——收益是不是来自「几何」而不是「任何可解码任务」、这套查询接口本身有多大价值、以及标题该不该叫 Geometry-Aware。 第二件事做 D-04：把几何头接上 VGGT 的 DPT 头，从记忆里直接渲一张深度图出来。这是全文最应该有却没有的那张图。

C术语

显式记忆 / 隐式记忆
前者把过去保留为可枚举的条目（帧、KV、点云），读取靠检索或渲染；后者把过去压成一个定长状态，读取靠网络自己。二者的分界不在「有没有几何」，而在「记忆里的东西能不能被逐条指认」。
相机可查询（camera-queryable）
本文的关键词。不问「记忆的第 k 个槽是什么」，而问「从这个位姿看出去应该是什么」。作用是绕开压缩后失去的 token 对应关系，让一个无序槽集合也能被逐 patch 地监督。
VGGT
Visual Geometry Grounded Transformer（CVPR 2025）。前馈式 3D 基础模型，一次前向输出相机参数、深度图、点图。结构是 DINOv2 编码器 → 交替注意力聚合器 → 任务头。本文只用它当冻结教师，取其特征。
互信息传感器布点准则
Krause 等人 2008 年提出：选一批测点使其与未测点的互信息最大。与「覆盖最大化」的关键区别是它会主动避开离群点——离群点信息量大但没有代表性。
3D 重投影分数
本文自定义指标：用 Depth Anything 3 估每帧深度与位姿，把同一三维点在不同帧之间来回投影，测偏移，归一化到 0–100。归一化公式论文未给。
MIND
2026 年 2 月的世界模型基准。特点是「开放域 + 闭环 + 重访」：路径会绕回起点，因此能测「回到走过的地方还一样吗」。共 250 条 UE5 视频。
