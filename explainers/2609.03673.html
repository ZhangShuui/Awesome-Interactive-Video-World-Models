视频生成器，能跨片段追踪世界吗？

Do Video Generators Track the World Across Segments? — 把「上一段视频建立了什么状态」和「下一段提示要求它怎么变」拆开来问：StateBench 用 200 个「先藏起来、再揭示」的续写任务测量生成器是否携带了正确的世界状态；StateAgent 用一张显式的实体状态图和一张预测出来的未来末帧，把状态推理从视频渲染里剥离出来。

Yingmao Miao1,2†Pengfei Zhang2‡Chaoran Xu2†Meng Yu2,3†Jing Tang2*Xiangxiang Chu2Chao Shen1Chenhao Lin1* 1西安交通大学 · 2阿里巴巴 DreamX Team · 3上海交通大学 · †DreamX 实习期间完成 · ‡项目负责人 · *通讯作者

一句话结论：观测记忆 ≠ 世界状态。最后一帧、近几帧、关键帧库、KV cache 保存的是「过去看见过什么」，而下一段真正需要的是「现在什么为真、按新提示该变成什么」。当边界帧把关键关系藏起来（球进了盒子、颜料在不透明杯里混好了、面包在烤面包机里），只靠观测接口的生成器分不清两段后果不同的历史。把状态显式写成实体状态图、按新提示更新、再用图像编辑把更新后的状态落成一张未来末帧、最后首末帧生视频——全案例状态分 SCS-All 从 45.2 提到 69.3；而单纯塞进更多关键帧，只把 43.9 变成 45.2。

论证链§1 · §2 · §5

论证链：从「观测记忆不是状态接口」到「用一张未来末帧携带状态」

这篇论文的骨架只有一句话：历史帧记录的是过去某刻看得见的东西，下一段需要的是此刻应当为真的东西。下面七步把它从问题定义推到实验结论。

01 · 出发点
长视频 = 分段拼接逐段生成或自回归扩块，每个新单元都要依赖历史。完整历史太贵，所以现有系统把历史压成「观测记忆」：最后一帧、近几帧、关键帧、记忆库、缓存特征。
02 · 缺口
观测 ≠ 状态一张过去的帧是合法历史，却不一定描述当前状态：关键关系可能在边界被遮住、可能在更早的观测之后又变了、也可能是一段看不见的过程的产物。
03 · 形式化 Eq.(3)
接口缺口两段历史 (a)(b) 暴露给下一段生成器的证据几乎相同，Mobs(V(a)) ≈ Mobs(V(b))，但后历史状态不同，S(a) ≠ S(b)。只看接口的生成器只能猜。
04 · 测量
StateBench200 个「先建立状态 → 尾帧藏住 → 新提示揭示/使用/变换」的单元测试。先判揭示动作是否完成（SES），再在成功样本上判暴露出的状态是否与历史一致（SCS）。
05 · 观察
更强的观测记忆不够最后一帧、近帧、关键帧、记忆库、自回归全线在「隐藏更新」与「复杂变换」上失败；把 StoryMem 的记忆库塞满覆盖全过程的关键帧，SCS-All 只从 43.9 到 45.2。
06 · 方法
StateAgent：状态推理与渲染解耦VLM 解析实体状态图 St → 按 pt+1 更新为 Ŝt+1 → 图像编辑把它落成未来末帧 → 首末帧生视频。SCS-All 45.2 → 69.3，条件 SCS 58.5 → 74.9。
07 · 归因
增益来自耦合只给文字状态提示：SES 冲到 90.0 但 SCS 停在 61.9（没有外观绑定）；只直接编辑末帧：56.6（有视觉但没有状态更新）；两者串起来才到 74.9。
读法提醒：论文把这条能力称为「未来的视频世界模型应当内化的能力」，StateAgent 只是当前模型能力下的实用方案——一个不改任何视频模型权重的测试时智能体。这决定了它的定位：它证明的是「显式状态载体能补上这个缺口」，而不是「视频模型学会了追踪状态」。
问题形式化§2 · Eq. 1–5

跨片段状态交接：两条路径，一个接口缺口

记上一段视频为 Vt，它的源提示为 pt，下一段的提示为 pt+1。现有续写系统通过一个观测记忆接口把历史传给下一段：

Ot = Mobs(Vt),   Vt+1 ∼ G(Ot, pt+1)(1)

这里 Mobs 是真正暴露给下一段生成器的历史接口（最后一帧、近几帧、检索到的关键帧、记忆库条目、缓存的时序特征），而不是 Vt 的全部信息量。它以稀疏、压缩、可能过期的形式暴露视觉证据，生成器很难从中推出一个能被查询、更新、并用于渲染的状态。作者要求的状态感知续写则要同时保留视觉证据和一个显式的后历史状态信念：

St = E(Vt, pt),   Vt+1 ∼ G(Ot, St, pt+1)(2)

Ot 负责外观、身份、布局、风格；St 负责「上一段之后什么在物理上为真」。核心问题出现在观测接口把不同历史映射到相似证据、而后历史状态不同的时候：

Mobs(Vt(a)) ≈ Mobs(Vt(b)),   St(a) ≠ St(b)(3)

这正是页首小实验里的 A/B：尾帧像素相同，一个盒里有球、一个没有。接着，续写提示被当成一次动作条件，诱导一次状态更新——揭示、使用、或进一步变换这个状态：

St+1 = τ(St, at+1)(4)
St = {ri},  ri ∈ F(5)

其中 at+1 是 pt+1 描述或隐含的物理事件，τ 抽象了「续写提示如何使用或更新从上一段带来的状态」。状态本身被定义为一组可能超越可见性而持续存在的任务相关物理关系——作者称之为「因果信念」（state as causal belief）。StateBench 评测的状态类型 F 包括： 可见性 位置 容纳关系 变换 表面/材质状态 数量 主体–物体关系。

观测记忆与状态推理是互补而非替代。论文反复强调：视觉记忆机制能保留实体长什么样、出现在哪、镜头怎么取景，这些对续写不可或缺；它只是不能可靠地回答「动作之后什么应当为真」。StateAgent 因此没有丢掉观测记忆——历史末帧和参考帧仍然进入渲染，只是在它们旁边多了一份显式状态。
三类状态证据§3.1 · Fig. 2

状态被历史「证明」的三种方式，对应三种失败

StateBench 不按物体或场景分类，而按目标状态如何被历史证据支撑分成三类。每一类里，尾帧都把任务相关的关系藏住或弄模糊，续写提示则要求一个揭示 / 使用 / 变换该状态的动作，且不点名答案。

过去可见

历史里存在一帧直接显示目标状态，随后它被藏起来。检索到的帧确实有帮助，但模型仍要判断「那张过去的观测现在还成立吗」。

50complex-transition

复杂变换

更难的物理或关系变换：空间转移（杯球）、数量变化（9−5=4）、颜色混合（蓝+黄）、溶解、材质/表面变换（面包→烤面包、水→冰）。与过去观测的相似性在这里只是弱线索，必须做一步计算。

基线典型失败：抹出蓝色或黄色（复制最近看到的颜色）、数量不对、纸上什么都没有。
① 蓝、黄两罐颜料，不透明黑杯，白纸，搅拌棒
② 倒入蓝色（杯内始终不可见）
③ 尾帧：倒入黄色并搅匀，杯子不透明
SEGMENT CUT
揭示：抽出搅拌棒抹在纸上 → 应是绿色
为什么按「证据方式」而不是按「物体」分类？因为三类分别对应观测记忆的三个不同缺陷：past-visible 考验的是时效判断（检索能拿到帧，但帧可能过期）；occluded-process 考验的是无帧可用时的推理（目标状态没有任何像素证据）；complex-transition 考验的是计算（要把两个可见的原因合成一个不可见的结果）。Table 1 的按类结果正好沿着这三条线展开。
基准§3 · App. A.1–A.2 · Tab. 4

StateBench：200 个「先藏起来、再揭示」的单元测试

每个任务给出一段 5–10 秒的上一段视频 Vt、它的源提示 pt、和一条续写提示 pt+1。上一段建立一个物理状态，尾帧把任务相关的关系藏住或弄模糊；续写必须使用边界之前建立的状态，而不只是末帧的表面，来完成被要求的状态更新。

数据怎么来

先定义细粒度状态类型，再为「上一段」和「续写段」生成成对提示：上一段提示制造一个建立状态的事件，续写提示要求一个揭示 / 使用 / 变换该状态的动作，且不点名答案。

上一段视频用 Wan2.2-T2V/I2V-plus 生成，480p、16 FPS；多步设置的任务按段顺序生成，每段以前一段的边界为条件。

人工过滤的四个条件

保留的案例必须满足：(1) 状态改变事件确实完成了；(2) 边界帧没有直接暴露任务相关状态；(3) 续写提示没有泄露目标答案；(4) 能用具体的「揭示/动作」与「状态一致性」checklist 评测。不满足的重生成或删除。

评测协议§3.2 · Eq. 6–9 · App. A.3

两阶段 checklist：先问「揭示了吗」，再问「揭示出来的对吗」

所有方法收到同一个三元组 (Vt, pt, pt+1)，各生成一段续写 V̂t+1。评判器收到 (Vt, pt, pt+1, V̂t+1)、任务专属 checklist、以及从 Vt 中为外观敏感实体选出的参考帧——参考帧只给评判器，不给生成器。

令 ei ∈ {0,1} 表示样本 i 是否完成了被要求的状态揭示/更新动作，yiq ∈ {0,1} 表示评判器对样本 i 的 checklist 问题 q 是否回答「yes」。Ci 是状态正确性问题集，Hi 是反幻觉问题集。

SES = 1N Σi=1N ei(6)
SC = Σi ei Σq∈Ci yiqΣi ei |Ci|HR = 1 − Σi ei Σq∈Hi yiqΣi ei |Hi|(7)
SCScond = Σi ei Σq∈Ci∪Hi yiqΣi ei |Ci ∪ Hi|(8)
SCSAll = 1N Σi ei ci,   ci = 1|Ci ∪ Hi| Σq yiq(9)

SES · State Exposure Score

揭示/更新动作是否完成。它不看状态对不对：盒子倾斜了、抽屉拉开了、杯子举起来了就算 1。

SC · State Correctness

在 SES=1 的样本上，状态正确性问题的 yes 率。是「揭示出来的东西对不对」的核心。

HR · Hallucination Rate

在 SES=1 的样本上，反幻觉问题的 no 率（1 − yes 率）：多出来的物体、重复目标、身份改变、矛盾属性、不可能的内容。越低越好。

SCS · 条件 / 全案例

SCScond 把 C 与 H 两组问题合起来算 yes 率；SCS-All 把揭示失败视为端到端的状态失败。表格里的 SCS 一律指条件版。

亲手算一遍：8 个样本的 checklist → 五个指标

按公开数据的典型结构，每个样本有 1 道揭示问题（决定 ei）、3 道状态正确问题（Ci）、2 道反幻觉问题（Hi）。点格子切换 yes/no；揭示失败的样本不再计入条件指标，但会把 SCS-All 拉下来。右侧几个预设复现了几种典型画像。

两个从数字里读出来的事实

SCS-All ≈ SES × SCS

Table 1 的每一行都满足 SCS-All ≈ SES × SCS（StateAgent：0.925 × 74.9 = 69.3；StoryMem+全关键帧：0.785 × 57.5 = 45.1 ≈ 45.2；MAGI-1：0.33 × 42.8 = 14.1）。这不是巧合：只要条件 SCS 按样本平均，Eq. (9) 就恰好是两者的乘积。所以 SCS-All 没有带来新信息，它只是把「做了动作」和「做对了」乘起来，惩罚那些只擅长其中一件的方法。

SCS 里一半是反幻觉分，地板很高

SCS 把 C、H 两组问题合并计算，而反幻觉问题对「保守」的输出天然友好。Wan-I2V 在 complex-transition 上 SC 只有 17.1（状态基本全错），HR 18.4 意味着反幻觉题有 81.6% 的 yes，两者一混，SCS 还有 48.2。看方法到底有没有把状态带过去，盯 SC；看它有没有乱画，盯 HR；SCS 是两者的折中。

评判器怎么工作

论文描述（§3.2 · A.3）

沿用 VideoPhy、PhyGenBench、StEvo-Bench 等基准的「按准则打分的 VLM 评判」协议。评判器是 Qwen3.5-Plus，收到上一段视频、两条提示、生成的续写、任务 checklist，以及需要比对外观时的实体参考帧，逐题回答 yes/no 并给一句理由，输出紧凑 JSON。三组问题：reveal_achieved（1 道动作完成题）、state_correct（暴露/使用的状态是否符合标注目标）、no_violation（不引入无依据的物体、重复目标、身份改变、矛盾属性、不可能内容）。

公开代码里的实现（statebench/eval/evaluate.py）

评判器只收到揭示段视频（video_url）、揭示提示、expected_state 的文字、以及 checklist 问题引用到的三张参考帧——它们取自最后一段历史的 12% / 50% / 88% 处（ref_history_start / ref_history_action / ref_pre_reveal）。整段历史视频本身并不进入评判请求。温度 0.1，enable_thinking=false。checklist 高度模板化：三道状态题中有一道就是「最终状态是否符合：{expected_state}」。

还有一个命名上的不一致：仓库 README 把 SES 写成 State Equivalence Score、SCS 写成 State Correctness Score，论文里分别是 State Exposure Score 与 State Consistency Score。本页一律按论文。

方法§4 · Eq. 10–12 · Fig. 3

StateAgent：把状态推理从渲染里拆出来，用一张未来末帧把状态带过去

核心洞见只有一句：状态一致的续写应当解耦「决定下一个状态」与「把状态渲染成像素」。一个显式的状态推理角色决定下一段结束时世界应该是什么样，视频生成器只负责把这个预测出来的状态画出来、并从上一段末帧平滑运动过去。

4.1 结构化状态载体：一张故意稀疏的实体状态图

给定 (Vt, pt)，StateAgent 不去检索帧，而是建一张轻量状态图 St。每个实体节点存：身份、它在哪些帧里可见的引用、以及一段概括当前状况的简短描述（开着/破了/被藏起/被拿着/被弄脏）。关系边记录可见性、容纳、位置等。图是故意稀疏的：只存未来续写需要的状态变量，把纹理、姿态、运动留给渲染器。

它和关键帧记忆有两个本质区别：可以把一条关系标为「为真」即使它在边界处不可见（球在盒里）；可以把一次更早的观测标为「已过期」（球曾在桌上，但后来的动作改变了这一点）。构建 St 时，pt 只用来把文字里的名字绑定到画面里的实体，状态解析以观测到的视频证据为准——提示与视频不一致时，以视频为准。

4.2 提示条件下的状态更新

St+1 = U(St, pt+1)(10)

续写提示被当成一个动作条件。Ŝt+1 是方法对「续写里应当体现的状态」的显式估计：它可能揭示一条隐藏关系、使用一条既有关系、或进一步变换物理状态。这一步直接对准观测记忆的瓶颈——隐藏物体可以留在 St 里，而更早帧里的过期外观不会被当成当前状态。

4.3 未来帧落地：把符号状态变成视频生成器能跟随的视觉条件

Fendt+1 = Gframe(Fendt, Rt, St+1, pt+1)(11)

结构化状态本身不足以条件化视频生成器，因为它没有具体的外观绑定。于是把 Ŝt+1 落成一张未来末帧：历史末帧 Fendt 提供相机、布局和可见实体；参考帧 Rt 提供那些在边界处不可见、但预测状态里需要出现的实体的外观。编辑指令由预测的状态变化和选出的视觉参考生成，使编辑后的帧反映目标状态、同时保持外观与布局。目标帧不是一张记忆帧，而是对未来状态的可视化预测。

4.4 视频渲染与诊断

Vt+1 = Gvideo(Fendt, Fendt+1, pt+1)(12)

Gvideo 用 Wan 的首末帧生视频接口实现。历史末帧保证与上一段的时间连续性，未来末帧约束续写必须体现的状态，渲染器只需负责运动与真实感，而不是从零重新发现隐藏的物理状态。模块化还带来可诊断性：一次错误的续写可以归因到历史解析、状态更新、未来帧落地或视频渲染中的某一环。

为什么载体是一张「未来末帧」，而不是文字或潜变量

纯文字状态

  • 容易更新、可读、可检查
  • 太抽象，无法保留外观绑定：「红球」是哪个红球？
  • 视频生成器对文字状态提示的跟随不可靠（消融：SES 90.0 但 SCS 61.9）

隐式潜状态

  • 可以支撑动力学（PAN、ReMind 一类）
  • 难以检查、训练昂贵
  • 可能丢掉忠实续写需要的视觉细节；实体身份绑定弱

未来末帧（本文）

  • 符号状态由 VLM 预测 → 可读可改
  • 图像编辑器用历史参考把状态落成像素 → 外观绑定
  • 当前视频生成器天然能跟随「首末帧」条件，无需重训
  • 首末帧差异过大时可能出现镜头切换（作者自述局限）

作者把这一思路与 ImageWAM 相提并论：后者用图像编辑作为世界-动作建模的紧凑「目标状态变换先验」。两者共同的直觉是——一张画出来的目标帧，是当前生成器能理解的最便宜的状态接口。

四段核心提示词（App. A.4）：每个 VLM 角色只做一件事

ENTITY BINDING 实体绑定
Extract only entity names, entity types, and explicitly mentioned appearance attributes from the source prompt. Do not infer hidden state, future state, or task answers.
只从源提示里抽名字、类型、显式提到的外观属性；禁止推断隐藏状态、未来状态或任务答案。抽出来的实体只用于把名字绑定到视频里观察到的实体。
STATE PARSING 状态解析
Analyze the observed video evidence and return the actual state of each entity at the current boundary … If the prompt and video disagree, report the observed video state.
报告可见实体、隐藏实体、位置、容器开合、物理状况，以及 inside / holding / wearing / covered by / behind / occluded by 等关系；源提示可辅助绑定名字，但提示与视频冲突时以视频为准。
STATE UPDATE 状态更新
Given the current world state and the next-shot prompt, predict the complete world state at the end of the next shot. Treat the prompt as an action condition … Carefully distinguish physical existence from camera visibility.
把提示当作动作条件，更新每个实体的可见性、位置、物理状况、外观描述、状态描述与开放式关系（容纳、附着、表面/材质、数量、主体-物体交互）。物理存在 ≠ 相机可见：东西可以存在但不在当前视角里。
EDITING PROMPT WRITER 编辑指令撰写
The last numbered image is the current frame to edit, and earlier numbered images are appearance references. Describe the expected result image in natural photographic language … If the prompt changes viewpoint, describe the full scene from the new viewpoint.
用自然的摄影语言描述结果图应当是什么样：动作之后什么可见、需要匹配外观时引用哪张参考图、视角不变时保留背景/光照/相机/未变物体；视角改变则描述新视角下的完整场景。
参考帧的选择规则。未来帧落地时只带两类实体的参考：参与了这次预测更新的实体，以及在边界处不可见、但续写中应当变为可见的实体。其余实体不进参考，避免编辑器被无关外观带偏。论文附录只报告了这四段提示的「核心逻辑」，输出 schema、格式约束、重试规则等工程细节放在了代码里——下一节就去代码里看。

论文与代码对照：五处值得记住的差异

① 「以视频证据为准」在代码里是「以末帧为准」

论文 §4.1 说状态解析「grounded in the observed video evidence」。VideoObserver.observe 收到的视觉输入只有一张末帧；被遮挡过程的知识来自两处：该段的文字提示（观察器被要求「比较已知状态与本段描述，判断实际发生了什么」）和「对不可见实体按逻辑推断」的指令。历史视频的中间帧只在外观绑定与底帧选择时被抽成 6 张关键帧看过。

② 状态更新是纯文本推理

StatePredictor 的请求里没有任何图像：输入是格式化的记忆 JSON（含 has_appearance 布尔值，而非图片）和续写提示。这与「状态推理与渲染解耦」的主张完全一致，也解释了为什么它能显式区分「物理存在」与「相机可见」——这是语言层面的推理，不是像素层面的。

③ 底帧不一定是最后一帧，甚至可以不编辑

FrameSelector 让 VLM 在历史视频的 6 张候选帧（取自 T/7…6T/7，不含真正的末帧）里挑一张最接近未来状态的做编辑底帧，给出 0–10 的满足度；若某帧已经满足未来状态（needs_editing=false），则跳过图像编辑，直接把那张历史帧当未来末帧。对 past-visible 任务这相当于一次「关键帧检索」的捷径——论文正文没有描述这个分支。首末帧生视频的首帧则始终是真正的历史末帧。

④ 编辑有校验重试，最终校验只做记录

EditVerifier 对比底帧与编辑帧，分别判断状态维度与场景维度（含相机运动时背景是否应变），失败则把反馈交给 FrameSpecWriter.refine 改写指令，最多重试 2 次（最多 3 次生成）。而第 9 步的 Verifier（scs / identity / visibility）结果只写进 results.json，不触发任何重生成。论文附录提到的「retry rules」指的是前者。

⑤ 渲染阶段有两处「静默」的提示改写

kf2v.generate_video 在续写提示后追加 “Maintain smooth, continuous motion between the first and last frame.”，并开启 API 端的 prompt_extend；同样的 prompt_extend 也用于 T2V 基线。这意味着渲染器实际看到的提示并不完全等于 pt+1。另外，仓库示例里 FrameSpecWriter 产出的编辑指令含有「图1」「图2」这样的中文图号（“the red sphere from 图1 is clearly visible”），说明提示词模板经历过中英版本迭代，指令会原样交给图像模型。

作者的边界

能力归属

StateBench 定义的是「未来的视频生成模型最终应当内化的能力：跨生成边界携带世界状态并在新提示下更新它」。StateAgent 被明确定位为当前模型能力阶段的实用方案——外置一个显式的状态推理角色，而不是让视频模型学会状态推理。

镜头切换（App. D）

StateAgent 从历史末帧渲染到预测的未来末帧；当两帧差异很大时，生成的视频可能出现镜头切换。作者提出更丰富的时间约束或中间状态锚点可能缓解。

探针而非本体

Tab. 4 的六族 23 型是「受控探针，而不是世界状态的完整本体」；基准是一个紧凑的单元测试，故意把状态的建立、隐藏、揭示分到两段，以便归因。

与相邻工作的区隔

StEvo-Bench 在单次生成内耦合建立/隐藏/演化/揭示，失败难归因；PAN 用 LLM 潜特征做状态，缺外观绑定；LiveWorld 的 4D 记忆昂贵，且仍是在更丰富的空间里存观测而非把事件转成状态；ReMind 用训练教 KV cache 记忆——本文则不重训视频生成器。

我的保留意见（读者视角，不代表论文观点）

  • 最大的疑问：pt 对 StateAgent 是一份几乎完美的文字状态说明，对基线却不是。所有方法名义上收到同一个三元组，但 Wan-I2V、LongCat-Video、MAGI-1 这类生成器本质上只能消费像素与 pt+1，论文没有说明它们如何（或是否）使用 pt。而 StateAgent 的 VLM 把 pt 读进了观察器——在 StateBench 里，pt 就是生成上一段视频的提示，它逐字叙述了被遮挡的事件（“drops it into the open blue box”、“pours blue paint … pours yellow paint … stirs”）。对 occluded-process 与 complex-transition 而言，pt + pt+1 在语言层面几乎已经决定了答案，「把证据转换成状态」有相当一部分是「把提示读成状态」。论文说 pt 只用于实体绑定，但代码里观察器的指令是「比较已知状态与本段描述来判断实际发生了什么」。一个不给 pt、或把事件从 pt 里抹掉的 video-only 变体，才能回答标题里的问题到底被回答了多少。
  • 评判器与推理器同一个模型。Qwen3.5-Plus 既是 StateAgent 的解析器、更新器、编辑指令撰写器与校验器，也是 StateBench 的评判器，而 checklist 里直接写着 expected_state。自偏好偏差在这种设置里是已知风险。双盲人评（450 对，状态一致性得分率 85.6）在方向上支持了自动指标，但人评只覆盖 4 个基线、15 位参与者，且没有报告 VLM 评判与人类判断的逐样本一致率。
  • 生成器也同源。历史视频由 Wan2.2 生成，StateAgent 用 Wan2.2-KF2V-Flash 渲染、Wan2.7-Image 编辑，末帧 I2V 基线也是 Wan2.2。LongCat-Video 与 MAGI-1 是在别家模型生成的历史上做续写，域不匹配可能放大了它们的劣势（MAGI-1 的 SES 只有 33.0，说明它在这个设置里连揭示动作都很少完成）。
  • SCS 的一半是反幻觉分。C 与 H 合并计算让 SCS 有一个高地板（Wan-I2V complex-transition：SC 17.1、SCS 48.2）。真正衡量「状态带过去了没有」的是 SC；论文正文里的对比多以 SCS 表述（58.5 → 74.9），若以 SC 论，差距其实更大（overall SC 未单列，按类看是 ~52 → 61、~36 → 69、~28 → 61）。
  • 条件指标的选择效应与小分母。SCScond 只在揭示成功的样本上算，一个只在容易的样本上完成揭示的方法会得到虚高的条件分；SCS-All 用乘积修正了这一点，但按类的 SC/HR 没有对应修正——MAGI-1 在 complex-transition 上的 SC 44.4 / SCS 59.2 来自约 6 个样本。
  • 底帧选择的捷径没有被单独消融。代码里 FrameSelector 可以跳过编辑、直接把一张历史帧当未来末帧，这对 past-visible 任务就是关键帧检索。Table 2 的「直接编辑末帧」变体用的是末帧，「完整 StateAgent」的增益里混有这一分支的贡献，读者无法拆开。
  • 观察器只看一张末帧。论文强调状态解析「以观测到的视频证据为准」，代码里视觉证据只有末帧一张图（中间帧仅用于外观绑定与底帧候选）。这与第一条相互印证：隐藏过程的信息主要来自文字。
  • 成本与定位。每段续写约 8–10 次 VLM 调用（部分携带 6 张图）、1–3 次图像生成、1 次首末帧生视频，全部走 API 异步任务；论文没有报告延迟。StateAgent 是离线的智能体封装，不是交互式世界模型；它的可诊断性是用一条很重的流水线换来的。
  • 基准是模板化的族，类别与提示风格绑定。如「基准」一节所述，complex-transition 是 5 族 × 10，occluded-process 是 5 族 × 10 + 15；past-visible 全用手持风格模板、complex-transition 几乎全用固定机位模板。按类别的差异里混着生成风格的差异；单族的系统性错误会以 10 为单位放大。
  • 「有益于故事生成」主要是定性证据。ST-Bench 上 PF 与 Consistency 的提升只有 0.008，美学 +0.54；Fig. 5 的定性对比更有说服力，但只有一个例子。

这些保留意见不推翻主线。「观测记忆接口把不同后果的历史映射到相似证据 → 只看接口的生成器只能猜 → 一个显式、可更新、能绑定外观的状态载体能补上这个缺口」这条论证是自洽的，Table 1 与 Table 2 也确实支持它。它们只是把结论收窄成：在历史提示可读的条件下，用 VLM 外置状态推理 + 图像编辑落地，能显著提升当前视频生成器的跨段状态一致性；至于视频生成器本身能否从像素里读出状态，这篇论文没有（也没打算）回答。

术语表

观测记忆 observation memory暴露给下一段生成器的历史接口：最后一帧、近帧、关键帧、记忆库、缓存特征。保存「看见过什么」。
状态接口 / 状态推理把历史证据转成「此刻什么为真、按新提示该怎么变」的显式表示，并可查询、更新、用于渲染。
跨段状态交接 cross-segment state handoff在生成边界把上一段建立的状态传给下一段、并在新提示下更新它的问题（Eq. 2–4）。
边界帧 / 尾帧上一段的最后一帧，也是两段的生成边界；StateBench 里它藏住或弄模糊任务相关关系。
因果信念 state as causal belief状态 = 一组可能超越可见性而持续存在的任务相关物理关系。
past-visible / occluded-process / complex-transition目标状态曾直接可见 / 在遮挡中改变从未可见 / 需要一步物理或关系计算。
SESState Exposure Score：完成揭示/更新动作的样本比例，不看状态对错。
SC / HRSES 为正样本上，状态正确题的 yes 率 / 反幻觉题的 no 率。
SCScond / SCS-All合并 C、H 两组题的 yes 率 / 把揭示失败计为 0 的全案例版本，≈ SES × SCS。
实体状态图 / MemoryBankStateAgent 的稀疏状态载体：实体 id、类型、属性、可见性、位置、开合、关系、外观帧、状态描述、来源段。
过期观测 stale observation某帧曾显示的状态已被后来的动作改变；状态图可显式标记，关键帧记忆不能。
未来末帧 future end frame把 Ŝt+1 用图像编辑落成的视觉条件——「对未来状态的可视化预测，而非记忆帧」。
KF2V / 首末帧生视频给定首帧与末帧渲染中间运动的接口（Wan2.2-KF2V-Flash）。
entities_becoming_visible预测器输出的、从 hidden/partially_visible 变为 visible 的实体列表，决定哪些外观参考进入编辑。
needs_editing / satisfaction_score底帧选择器的输出：所选历史帧是否已满足未来状态、满足程度 0–10。
ST-BenchStoryMem 提出的 1 分钟多镜故事生成协议，评美学、提示跟随、跨镜一致性。
