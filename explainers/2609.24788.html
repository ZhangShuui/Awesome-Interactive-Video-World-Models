SVEET在双向视频模型上学会编辑，再原封不动地插到流式因果模型上用

原题：Streaming Video Editing with Easy Adaptation。流程分三步：先在离线的双向模型 Wan2.1-VACE-1.3B 上，用 LoRA 微调 VACE 控制分支（风格化 / 补洞 / 深度转视频）；再把这个分支直接接到实时的因果模型 Causal Forcing 上，逐块（chunk）生成，因果骨干一个参数都不改。为了让分支换了骨干还能用，论文做了两处改动：控制分支改成逐帧注意力；训练时把 LoRA 的更新限制在“两个骨干特征差异最大的方向”的正交补里（ODT）。

一句话判断：工程上的思路是对的：控制分支在双向老师上训练、到蒸馏出来的学生上用。条件编码逐帧独立，训练和推理的计算就一模一样，也不用额外的缓存。这两点对做实时世界模型的人有直接参考价值。

但论文的两根“理论支柱”都有问题。第一，ODT 在代码里的校准只在 t=0 的干净潜变量上、两个模型都用双向注意力跑，测到的并不是“因果性”造成的差异。第二，附录两个定理的关键不等式有反例。此外，发布版推理代码用的不是论文写的逐帧注意力，训练端最关键的模型代码被 .gitignore 漏掉了。表 1 还有一行疑似复制粘贴错误。详见 §10。

§1一页读懂

整篇论文就是三个阶段。前两个在离线时各做一次，第三个是实时运行的部分。

① 校准：找“两个骨干哪里不一样” 代码

取 500 条视频，分别喂给双向 Wan 和因果 CF，记录第 0,2,…,28 层的输出特征。每层用岭回归拟合一个 1536×1536 的线性映射 W，让双向特征 × W ≈ 因果特征。对 A = W − I 做 SVD，取能量占前 80% 的奇异方向 Vk，得到投影 Π⊥ = I − VkVk⊤。

注意：代码里这一步用 t=0 的干净潜变量，两个模型都开全双向注意力（§5）。

② 训练：在双向骨干上教会 VACE 编辑

骨干冻结，只训 VACE 控制分支的 LoRA。两处改动：

  • 逐帧注意力：控制分支里每个 token 只看同一帧的 token（式 3）。
  • ODT：LoRA 的更新限制在 Π⊥ 的子空间里，不去碰“双向和因果特征差异最大的方向”。

用的是普通的 flow matching 损失，单卡 A100，每个任务训一个分支。

③ 部署：原样插到因果骨干上，逐块生成

骨干权重换成 Causal Forcing，VACE 分支（LoRA 已合并）照旧挂上，不再训练。每个 chunk 是 3 个潜帧，第一块覆盖 9 个视频帧，之后每块 12 帧。流程是：4 步去噪 → 用 t=0 再跑一遍写入 KV cache → 下一块。控制分支每次只处理当前块的源视频。

81 帧 = 7 块，每块 5 次前向。

三个要点：

  1. 这篇的“迁移”能成立，前提是两个骨干同源同构：CF 是从 Wan2.1-T2V-1.3B 蒸馏出来的，层数、宽度、hint 注入点都一样。所谓“跨异构骨干”其实没有被测过。
  2. 头条数字里，最大的一块增益在同管线的 3D 版（VACE 分支 + 任务 LoRA 微调 + 接到 CF，不加两项新设计）上就已经拿到了：风格任务上它比最强外部基线 LiveEdit 高 1.20 分，而 LiveEdit 也是在 Ditto 上训练的。两个新设计合起来再加 0.37（风格）/ 0.41（补洞）。
  3. ODT 的直觉是“别往两个骨干不一致的方向写控制信号”，这个直觉说得通。但校准的方式、投影作用在哪一侧、理论证明，这三处都站不稳（§5、§6）。

§2它要解决什么

实时视频生成已经做到了：Self Forcing / Causal Forcing 把 Wan2.1-1.3B 蒸馏成 4 步、块因果、带 KV cache 的生成器，H100 上 17 FPS。但好用的编辑模型（VACE 这类）都是双向、整段处理的，要看到未来帧，没法边收边出。怎么让实时模型也能“按源视频改画面”？眼下有三条路：

路子 A · 重新训 / 蒸馏一个流式编辑器

LiveEdit（2606.26740）分三阶段：先在双向模型上微调编辑能力（通道拼接）→ 用 teacher forcing 改成因果 → 用 DMD 蒸馏成 4 步。训练数据是 20K 条 Ditto 编辑对，12.66 FPS。外部

代价：整个骨干都要重训一遍。

路子 B · 什么都不训，直接插

Daydream / Fosdick（2602.14381）把现成的 VACE 权重直接接到 LongLive、StreamDiffusionV2、MemFlow、Krea-14B、Reward Forcing 这 5 条 Wan 系自回归管线上。深度控制多 20–30% 延迟；参考图生视频严重退化。外部

SVEET 表 1 里的 “DayDream+CF” 就是这条路。论文没写它的具体配置，按 Fosdick 的做法应该是零训练。

路子 C · SVEET：在双向上训，零样本迁移

只在双向骨干上训练控制分支（LoRA，很便宜），但为“迁移”做了两处针对性设计，然后零样本插到 CF 上。因果骨干不动。

相对路子 B 的增量：① 用任务数据微调 VACE；② 控制分支逐帧注意力；③ ODT。

为什么“在老师上训、在学生上用”有吸引力 推断

论文给的动机是“流式蒸馏很贵（128 H100 GPU·天）”。更根本的原因可能在别处：蒸馏出来的 4 步因果生成器是用 DMD 训的，它不再是一个“在任意噪声水平都能去噪”的模型，想给它加一个新的控制条件，没有现成的、简单的训练目标。双向老师则是标准的扩散模型，加控制分支用普通 flow matching 训练就行，便宜又稳。图像领域早有类似经验：在 SD1.5 上训的 ControlNet，拿到它的微调版、蒸馏版上照样能用。SVEET 是在视频的“双向老师 → 因果学生”上验证了同一件事，并尝试缩小其中的落差。

§3架构：VACE 是怎么挂在骨干上的

VACE 是一条“旁路”：15 个和骨干同构的 Transformer 块读条件视频，各输出一个 hint，加到骨干第 0,2,4,…,28 层的输出上。骨干本身冻结。SVEET 的训练和推理用的是同一张图，区别只在骨干的权重和注意力方式。切换下面的开关对比两种状态。

论文没强调、但很关键的一点 代码

控制分支并不是自给自足的。它第 0 块的输入是 before_proj(条件) + x，这里的 x 是骨干 patch embedding 之后的噪声潜变量；每个块的时间调制 e（AdaLN）和交叉注意力用的文本嵌入，也都来自骨干自己的 time / text embedding。

部署时这些模块整体换成了 CF 的权重（infer_single.py 先按合并后的 VACE 建模型，再 load_state_dict(CF generator, strict=False)）。所以“换骨干”不只是换了 hint 的接收方，控制分支自己的输入分布也跟着变了。

为什么能插得上

hint 是直接加到骨干残差流上的一个 1536 维向量，这就要求两个骨干逐层同宽、同层数、注入点一一对应。CF（以及附录里的 Self Forcing）都是从 Wan2.1-T2V-1.3B 蒸馏出来的，这个条件天然满足 外部。

摘要里说的“跨异构骨干架构的零样本迁移”，实际测的只是同一架构、不同权重和注意力方式之间的迁移。换一个宽度或层数不同的骨干，这个方法本身就用不了。

§4逐帧注意力：让控制分支训练和推理算的是同一件事

原版 VACE 的控制块用全时空（3D）注意力：训练时一次喂 21 个潜帧，每个 token 能看到全部 21 帧。流式推理时一次只来一个 chunk（3 个潜帧），要么只让它看这 3 帧（和训练对不上），要么也给控制分支配一个 KV cache（多一份显存和复杂度）。SVEET 的办法是把注意力掩码改成只看同一帧（式 3）：

M(t,s),(t′,s′) = 1 若 t = t′，否则 0

这样第 t 帧的控制特征只取决于第 t 帧的源画面。下面的交互图把几种掩码放在一起比较：训练时（一次看到全部帧）和流式推理时（处理第 2 个 chunk、前面的帧已经过去）各是什么样。

逐帧的好处

  • 训练和推理完全一致：训练时虽然一次喂 21 帧，每帧只看自己；推理时一个 chunk 3 帧，每帧还是只看自己。
  • 控制分支不需要 KV cache，不随视频变长增加开销。
  • 与绝对时间位置无关 推断：同一帧内的 token 时间下标相同，RoPE 的时间分量在 q·k 里相互抵消，控制特征只取决于画面本身，不取决于“这是第几帧”。论文没提这一点，但它正是逐帧设计能无限往后推的原因（前提是骨干撑得住）。

代价与没试的替代方案

  • 控制分支看不到运动，时间一致性全靠骨干的 KV cache。风格化这类逐帧任务影响不大；需要跨帧推理的编辑（例如跟踪一个被遮挡的物体）就可能吃亏。
  • 论文把 P2 表述成“条件编码必须逐帧独立”。其实逐帧只是充分条件。最自然的替代是：训练时控制分支也用块因果掩码，推理时给它配 KV cache，同样满足“训练 = 推理”，还保留了运动信息。论文没有做这个对照。
  • 按表 2，2D 注意力的增益（+0.10~0.12）小于 ODT 的增益（+0.24~0.27）。“3D + ODT”（7.33）甚至高于“2D 不加 ODT”（7.19）。

发布代码和论文对不上 代码

在 Self-Forcing/wan/modules/causal_model.py 里，VACE 块推理时拿到的是 kv_cache=None、block_mask=None（pipeline/causal_inference.py 里 _initialize_vace_kv_cache 的调用被注释掉了；block_mask 只在训练前向里才创建）。这样走到的是 flex_attention(..., block_mask=None)，也就是对当前 chunk 全部 3 个潜帧、4,680 个 token 做稠密注意力，不是式 3 的逐帧掩码。训练端的 VACE 模型定义（diffsynth/models/wan_video_vace_causal.py）不在仓库里（原因见 §9），所以没法确认训练时用的是哪种掩码。如果训练确实是逐帧的，发布版推理就引入了论文本来要消除的训练 / 推理不一致。

§5ODT：别往“两个骨干意见不一致”的方向写控制信号

直觉：同一段视频喂给双向 Wan 和因果 CF，每层算出来的特征不完全一样，而且差异集中在少数几个方向上。控制分支学编辑时如果恰好把信号写进这些方向，换到 CF 上就会被“扭曲”。所以 ODT 把控制分支的更新限制在这些方向的正交补里，只在两个骨干“意见一致”的子空间里做编辑。

论文的写法（§3.2，式 4–8）：用岭回归求每层的线性映射 W1 使 W1Xb ≈ Xc，令 A1 = W1 − I，SVD 后取前 k 个右奇异向量 Vk，令 Π⊥ = I − VkVk⊤，然后把控制更新约束成 A2 = C Π⊥，其中 C 由 LoRA 参数化。下面按代码把每一步实际做了什么摊开。

5.1校准流水线：代码里到底怎么算的

这一步测到的不是“因果性” 代码 推断

因果骨干和双向骨干至少有三处不同：① 权重（蒸馏改过）；② 注意力方式（块因果 + KV cache，看不到未来帧）；③ 工作的噪声水平（4 个大步，有效噪声 σ ≈ 1 → 0.9375 → 0.833 → 0.625）。代码的校准只保留了 ①，而且只在 t = 0 上测：两个模型都用全双向注意力、看整段干净视频。

公平地说，推理时 t = 0 那一遍（写 KV cache）也会注入 hint，所以 hint 会通过缓存影响后面所有块，t = 0 并非完全无关。但那一遍用的是块因果 + 缓存注意力，不是校准时的双向注意力；而决定当前块画面的 4 个去噪步（σ ≈ 1 → 0.625）完全没有测。附录 B 自己说“功能 1 负责扩散时间步调制”，却只在一个时间步上估计它。所以 Vk 充其量是“t = 0、双向注意力下，蒸馏导致的权重漂移方向”，拿它代表论文说的“因果性方向”，中间差了好几步。

5.2“80% 能量”意味着砍掉多少维

附录 A 说每层只要 4%–21% 的方向就能解释 80% 的差异能量。按 1536 维算，k ≈ 61–323。下面用一条合成谱演示阈值、固定 k 和能量定义（σ 还是 σ²）怎么影响 k。论文图 8 的真实数值没能读到（arXiv 页面被限流），所以这里只示意机制，不代表论文数据。

5.3投影在二维里长什么样，估偏了会怎样

把 1536 维压成 2 维来看：虚线是估计出的差异方向 v，青色箭头是控制分支想做的更新 Δ，投影后的更新是 Π⊥Δ。附录的式 24（勾股分解）说，被砍掉的能量 = ‖ΔPk‖²，也就是“控制更新本来就想用差异方向的那部分”。再加一个滑块“估计偏差 δ”：如果真正起作用的差异方向（比如去噪时间步上的方向）和 t = 0 时估出的方向差了 δ，投影后的更新和真实方向之间还剩多少重叠。

5.4投影到底乘在哪一侧：六个 LoRA 目标层逐个看

peft 按模块名后缀匹配，所以 “q/k/v/o” 同时命中自注意力和交叉注意力，每个 VACE 块其实挂了 10 个 LoRA 代码。其中交叉注意力的 k / v 输入是文本嵌入，不在残差流里。没有哪一侧能同时覆盖所有层。式 8 的 A2 = CΠ⊥ 在论文的列向量约定下是乘在输入侧；代码里 Vk 按行向量约定求出，更像输出侧的量。实现函数缺失，作者怎么处理的无从得知。

坐标系也对不上 推断

Vk 是在骨干第 ℓ 块的输出空间里估计的。LoRA 却作用在 VACE 分支自己的内部流 c 上：q/k 的输出甚至在注意力头空间里。hint 等于 after_proj(c)，而 after_proj 是一个冻结的、不在 LoRA 目标里的 1536×1536 全连接层，会把各个方向重新混合。

所以就算把 c 空间里的 LoRA 更新投影掉了 Vk，也不能保证最终加进骨干的 hint 避开了 Vk。要做到这一点，更直接的办法是投影 hint 本身。推理代码里其实有两个相关开关，默认都关着：use_W（hint @ W）和 use_pi_perp_path（hint @ Π⊥）。表 2 的“推理期投影”被描述为“用估计的映射矩阵做事后投影”，对应的应该是前者（6.43 分，比不投影还差）。至于直接把 hint 投影到 Π⊥ 的效果，论文没有报告。

§6理论核查：两条关键不等式都有反例

定理想说什么（人话）：设有两个“功能”，分别对应同一个权重矩阵 W 上的两个参数更新：ΔW1（双向 → 因果）和 ΔW2（控制）。把 ΔW2 投影到 ΔW1 主奇异方向的正交补上，得到 ΔW̃2 = ΔW2(I − Pk)。定理 1 说控制对功能 1 的干扰不超过 ΔW1 的“尾部”；定理 2 说两个更新叠加时的非线性交叉项也受尾部奇异值控制。于是 f(W+ΔW1+ΔW̃2) ≈ f(W+ΔW1) + f(W+ΔW̃2) − f(W)，即“因果模型加控制 ≈ 因果模型的输出 + 控制在双向模型上学到的效果”。

定理 1 · 式 22，证明 26–27‖XPΔW̃₂‖₂ ≤ σk+1(XP)·‖ΔW₂‖₂不成立(26) 用 Eckart–Young 说 ‖XP(I−Pk)‖₂ = σk+1(XP)，但 Pk 是 ΔW₁ 的主奇异投影，不是 XP 的，Eckart–Young 只对矩阵自己的奇异向量成立。(27) 把 XPΔW₂(I−Pk) 改写成 XP(I−Pk)ΔW₂(I−Pk)，中间凭空多了一个 (I−Pk)。维度记号也自相矛盾：论文把 Vk 写成 d×k，那 ΔW₂(I−Pk) 就要求 m = d；按“d×m 矩阵的右奇异向量”来理解，则 XP(I−Pk) 要求 d = m。哪种读法都隐含 d = m。另外，非正式表述说干扰由“ΔW₁ 的尾部”控制，正式的式 22 用的却是 σk+1(XP)，两处本身就不一致。反例见下面计算器的预设 ③。
定理 2 · 式 43 / 54‖ΔW₁⊤ΔW̃₂‖F ≤ σk+1(ΔW₁)·‖ΔW₂‖F不成立乘积顺序写反了。反例：ΔW₁ = diag(1, 0)，ΔW₂ = E₁₂，左边 = 1，右边 = 0。交换顺序后的 ‖ΔW̃₂ΔW₁⊤‖F ≤ σk+1‖ΔW₂‖F 才成立（ΔW̃₂ΔW₁⊤ = ΔW₂V尾Σ尾U尾⊤）。随机 2×2 高斯矩阵（k = 1）：原式约 69% 的情况下被违反（numpy 2 万次），交换顺序后 0 次。违反率取决于 k 与维度的比例：8×8、k = 1 约 0.1%，8×8、k = 4 约 53%。
定理 2 · “H 对角”若 Hessian 对角，则 ‖Ecomp‖ ≤ ‖H‖₂σk+1‖ΔW₂‖F条件不够对角但非标量的 H 是逐元素加权，会破坏子空间正交性。反例：ΔW₁ = ½·𝟙（秩 1，σ₂ = 0），ΔW₂ = I，H 只保留对角两格，得 ⟨ΔW₁, H⊙ΔW̃₂⟩ = 0.5 ≠ 0。至少要 H = h·I（各向同性），这时界是 |h|·‖ΔW₁ − [ΔW₁]k‖F·‖ΔW₂‖F（尾部 Frobenius 能量，不是 σk+1）。
定理 ↔ 方法“We theoretically validate that such disentanglement … enables effective zero-shot transfer”对象不同定理里两个更新作用在同一个权重矩阵上。SVEET 里，A₁ 是两个模型块输出之间的特征映射，没有对应的参数更新；控制更新则在 VACE 分支的另一组参数上。在参数空间里两者不共享坐标，⟨ΔW₁, ΔW₂⟩ 恒为 0；交叉项由“骨干参数 × 控制参数”的交叉 Hessian 决定，和对 A₁ 做 SVD 没有直接关系。

公道地说：理论有错，不等于方法没用。ODT 在表 2 上确实带来 +0.24~0.27 的 VLM 分，这个经验结果要单独看，它的可信度取决于实验本身（见 §8、§10）。问题在于论文说“理论上验证了”，这个说法不成立。另外，“把第二个更新投影到第一个更新主子空间的正交补”这个思路本身来自模型合并文献（论文引用的 Cheng et al. 2025）。

§7流式推理：81 帧是怎么一块一块出来的

推理时，骨干是 Causal Forcing 的分块版，配置文件是 causal_forcing_dmd_chunkwise.yaml：每块 3 个潜帧，去噪步 [1000, 750, 500, 250]，经 shift = 5 变换后有效噪声 σ ≈ 1, 0.9375, 0.833, 0.625。每块的最后一步出结果后，再用 t = 0 跑一遍，把干净特征写进 KV cache。VACE 分支在每次前向里都要重新跑一遍，读的是当前块的源视频潜变量。点“下一步”或“播放”逐步看。

15 FPS 从哪来

CF 论文表 1 报的是 17.0 FPS、首帧 0.69 s（单卡 H100，和 Self Forcing 分块版完全相同）外部。SVEET 在它上面多挂了 15 个控制块，每次前向都要跑。如果两个数字口径相同，15 FPS 意味着控制分支带来约 13% 的开销；但 SVEET 没说计时包括什么，这个比较只能算粗估 推断。作为参照，Fosdick 测到：LongLive-1.3B 加 VACE 深度控制，每块延迟从 539 ms 升到 698 ms（约 +30%，RTX 5090，368×640）；Krea-14B 上约 +20%（H100）外部。

结论：“实时”基本是骨干给的，SVEET 本身不加速。论文也没有报首帧延迟，而 Self Forcing 和 CF 都报了。

“流式”只测了 5 秒

所有评测都是 81 帧，和训练长度一样。CF 论文自己承认：它在 5 s 视频上训练、注意力窗口最多 5 s，直接往后推会有训练 / 推理不一致，质量会下降，需要 LongLive、Rolling Forcing 之类的长视频方案 外部。

“直播风格化”这类应用真正关心的是：1 分钟以后画面是否漂移、控制是否还跟得上。论文没有这方面的数据。

§10存疑清单（21 条）

按对核心结论的影响分三级：高 会动摇主要结论，中 会让某个数字或说法打折扣，低 是口径或表述问题。推断 表示是我的推断，论文或代码里没有直接证据。

H1高“首个”和“跨异构骨干”两个说法都站不住

贡献第一条写“据我们所知，首个研究不重训、不蒸馏流式骨干的双向→流式编辑迁移”。可是 Fosdick（Daydream，2602.14381，2026-02）已经把在双向 Wan 上训练的 VACE 权重，零训练地接到 LongLive、StreamDiffusionV2、MemFlow、Krea-14B、Reward Forcing 五条自回归管线上，还报了深度 RMSE 和掩码 SSIM 这类客观控制指标 外部。SVEET 把它当作基线（DayDream+CF），却没在相关工作里讨论它。真正的增量应该表述为：用任务数据微调 + 逐帧注意力 + ODT。

摘要说“跨异构骨干架构的零样本知识迁移”，但 CF 和 Self Forcing 都是 Wan2.1-T2V-1.3B 蒸馏出来的同一个架构（30 层、1536 维），只是权重和注意力方式不同。hint 是逐层加到残差流上的，维度必须对得上，所以这个方法天生只能在同源同构的骨干之间迁移。

H2高ODT 校准测的是“t = 0 的权重漂移”，不是“因果性”

代码 代码：两个模型都在干净潜变量、t = 0、全双向注意力、整段 21 帧上跑，CF 的权重被装进标准 WanModel，prompt 统一是 “a high quality video”。这样估出的 A₁ 只反映蒸馏导致的权重差，既不含块因果注意力 / KV cache 带来的差异，也不含 hint 实际起作用的那几个噪声水平（σ ≈ 1 → 0.625）上的差异。

推理时 t = 0 写缓存那一遍也会注入 hint，所以 t = 0 并非完全无关。但那一遍用的是块因果 + 缓存注意力，而决定当前块画面的 4 个去噪步没有测。附录 B 明确说功能 1 “负责扩散时间步调制”，却只在一个时间步上估计它。表 2 里“推理期投影”（直接用估出的映射变换 hint）比不做还差，这也说明估出来的映射和实际部署时的差异对不上 推断。至少应该在 4 个去噪时间步上、用真正的块因果推理方式采特征，并报告各时间步子空间之间的主角度。

H3高理论与方法对不上，两个定理的关键不等式都有反例

① 对象不同：定理讨论同一个权重矩阵上的两个参数更新。SVEET 里 A₁ 是两个模型块输出之间的特征映射；控制更新在 VACE 分支的另一组参数上，hint 还要经过冻结的 after_proj。在参数空间里两者不共享坐标。

② 定理 2 式 43 / 54 乘积顺序写反：ΔW₁ = diag(1, 0)、ΔW₂ = E₁₂ 时，左边 = 1，右边 = 0；交换顺序后才成立。“Hessian 对角”也不够，至少要各向同性；对角加权的反例见 §6。

③ 定理 1 式 22 误用 Eckart–Young：Pk 来自 ΔW₁，不是 XP 的奇异向量；证明中式 27 凭空插入了 (I − Pk)；维度记号自相矛盾，隐含 d = m。反例：X = I、P = diag(1, 0)、ΔW₁ = E₁₂、ΔW₂ = E₁₁，左边 = 1，右边 = 0。

引言说 “We theoretically validate …”，这个说法不成立。ODT 有没有用只能看实验，而实验本身也有 H4、H5、M4 的问题。

H4高发布代码：推理不是逐帧注意力，训练端核心代码缺失

推理时 VACE 块是对当前 chunk 的 3 个潜帧做块内稠密注意力，不是式 3 的逐帧掩码（§4、§9）代码。训练端的模型定义目录被 .gitignore 的 models/ 规则整个排除，所以 2D 掩码在训练中怎么实现、Π⊥ 怎么作用于 LoRA，都没法核实，训练也跑不起来。

两条原则之一（P2）和 ODT 的具体实现都无法从发布版复现。如果论文数字就是用这份推理代码跑出来的，那表里的 “2D” 在推理时其实是 “chunk-3D”，训练时是否是 2D 也不确定。

H5高表 1 的完整性和可比性

① 表 1(c) 深度任务里，Channel concat 和 DayDream+CF 两行的 8 个数有 7 个逐位相同（CLIP 0.2892、主体一致 0.9332、背景一致 0.9239、闪烁 0.9818、平滑 0.9884、美学 0.5096、整体一致 0.0811），只有 VLM 分不同（6.0830 vs 7.1502）。两个不同方法不可能在 7 个指标上四位小数全部相同，至少有一行是复制粘贴错误。

② SDEdit+CF、StreamDiffusionV2、LiveEdit 都是文本引导的视频到视频编辑器，拿它们做补洞和深度转视频时，掩码和深度图怎么喂进去，论文没说。LiveEdit 原本做的是局部属性编辑。

③ 补洞和深度两个任务里，只有 SVEET 和它的两个同管线对照用 VPData（与测试集同源）训练过；DayDream+CF 按 Fosdick 的做法应是零训练。风格任务里 LiveEdit 也在 Ditto 上训练过，这一项相对公平。

④ 头条指标是 GPT-4o 的 1–10 分，没给 prompt、抽帧方式和方差。补洞和深度转视频都有真值视频，却没报任何有参考指标，比如非掩码区 PSNR / SSIM、输出视频重新估深度后的误差。Fosdick 就报了深度 RMSE 和掩码 SSIM。

M1中Π⊥ 作用在哪一侧、哪个坐标系，论文都没定义清楚

式 8 的 A₂ = CΠ⊥ 在论文的列向量约定下是乘在输入侧；代码里 Vk 按行向量约定求出，更像输出侧的量。六个 LoRA 目标里，ffn.0（1536→8960）只能在输入侧乘 1536² 的 Π，ffn.2（8960→1536）只能在输出侧乘，没有一个统一的“侧”。更根本的是，Vk 在骨干残差流里估计，LoRA 却作用在 VACE 分支内部流和注意力头空间里，hint 还要经过冻结的 after_proj 重新混合，所以训练期的约束不能保证 hint 避开 Vk 推断。

M2中大头增益在“同管线 3D 版”上就已拿到，不是来自两项新设计；深度任务的结果反常

风格化：同管线 3D 版（VACE + LoRA，无 ODT，接 CF）已经比最强外部基线 LiveEdit（同样用 Ditto 训练）高 1.20 分，逐帧 + ODT 再加 0.37。补洞：+0.28 和 +0.41。深度转视频：3D 版 5.75，比完全没训练的 DayDream+CF（7.15）还低 1.40，SVEET 却是 8.41（+2.66）。为什么在深度任务上 LoRA 微调反而把 3D 版训差了，而 2D + ODT 能把它拉回来还超出一大截？消融只做了风格任务，这个问题没有解释。

M3中正文的结论和自己的数字对不上

§5.2 说在补洞和深度任务上“时间稳定性明显更好”。可深度任务里，本文的运动平滑度在 7 个方法中排第 6（0.9882），时间闪烁排第 4；补洞任务的平滑度排第 2，美学排第 4。§5.3 说“2D 注意力改善源结构保持”，但表 2 只有 VLM 分和运动平滑。全文唯一的“结构保持”数字是用户研究（表 3）里的主观打分，而且表 3 不含 3D / 2D 对照。

M4中统计力度不够

表 2 的差距在 0.10–0.27 之间：1–10 分制、120 条视频、单一裁判（GPT-4o），没报种子数，也没有误差棒。用户研究 10 人 × 15 条视频，没有包括表 1 中最强的外部基线 LiveEdit，也没有包括同管线的 3D 版，量表也没说明。

M5中“流式 / 实时”只在 5 秒、同长度上验证

所有评测都是 81 帧，和训练长度相同。CF 自己承认超过 5 s 会退化 外部。论文没有报首帧延迟，也没说 FPS 的计时口径。发布代码先把整段源视频做 VAE 编码，最后整段解码，计时只包去噪循环 代码。“实时”基本是 CF 骨干（17 FPS）给的，SVEET 本身不加速，只会多出控制分支的开销。

M6中“条件编码必须逐帧独立”说成了必要条件

证据只有图 3 的一组定性图，加上表 2 里 +0.10~0.12 的差距。最自然的替代方案没有测：训练时控制分支也用块因果掩码，推理时给它配 KV cache。这样同样满足“训练 = 推理”，还能保留运动信息。另外 ODT 的作用比 2D 大，“3D + ODT”（7.33）高于“2D 无 ODT”（7.19）。P1（控制与骨干解耦）的证据是 Wan-Fun 迁移失败，这几乎是定义上的结果：控制能力如果写进了骨干权重，换掉骨干自然就没了。Wan-Fun 具体怎么“迁移”的，论文也没说。

M7中“只在双向上训练”有前提；迁移到 Self Forcing 只有定性图

ODT 需要先在目标流式骨干上跑 500 条校准视频，所以严格说是“每一对（双向，因果）骨干各训一次”。附录 D.1 换到 Self Forcing 时，沿用的是基于 CF 算出的 Π⊥ 训练出来的分支，只给了图 10 的定性结果，没有数字。

M8中缺上界和强基线

缺三类对照：① 离线双向 VACE 加同一 LoRA 的结果（质量上界，能看出迁移损失了多少）；② 直接在冻结的 CF 上训练控制分支（用 teacher forcing，或者把“双向 VACE”用 DMD 蒸馏到“因果 VACE”）；③ 用同样的任务数据微调 DayDream 方案。“两阶段 TF”只有一句话，训练细节不详。

M9中“训练成本高得难以承受”的动机被放大了

“128 H100 GPU·天”没有注明具体出处（引了三篇）。Self Forcing 自己报告 DMD 阶段约 64 × H100 × 1.5 h ≈ 4 GPU·天（外加 ODE 初始化）外部；128 这个数可能来自 CausVid 推断。SVEET 自己的训练开销也没报：单卡 A100、13K 样本 × 10 epoch、batch 1，约 13 万步，墙钟时间不详。

L7低岭回归正则项把 W 往 0 拉，而不是往 I 拉

式 4 用 λ‖W‖²。在方差很小的特征方向上，W 会被压向 0，A₁ = W − I 就趋于 −I，这些方向可能被误当成“差异方向”。更合理的写法是 λ‖W − I‖²。代码里 λ = 1e-3，每层 token 数约 1,640 万，实际影响大概率很小 推断。

§11公道话与启示

做对了的地方

  • 问题选得实在：已经有很多好用的控制分支和编辑器，都长在双向模型上，把它们搬到实时模型上是真实需求。
  • 成本低：只训 LoRA，单卡 A100，因果骨干一个参数不动。
  • 逐帧条件编码这个设计干净：训练和推理的计算完全一致，不需要额外缓存，而且与绝对时间位置无关。
  • 做了受控的 2 × 2 消融，也有“推理期投影”这样的负对照，说明事后对齐映射行不通。
  • 代码和风格权重公开了（虽然不完整）。

对交互式世界模型方向的启示

  • 控制分支可以在老师上训、在学生上用：动作、相机、深度、姿态这类控制，如果在双向 Wan 上训好，只要学生是同源同构的蒸馏模型，就有机会零样本迁移，省掉“给 DMD 学生加控制”的麻烦。
  • 逐帧条件编码器很适合动作条件：世界模型的动作本来就是逐步的，按帧独立编码，天然和块因果推理对齐。
  • SVEET 的“子空间避让”是一个便宜的旋钮，但要做对：在实际去噪时间步上、用真正的因果推理方式采特征，最好直接约束 hint 本身。
  • 评测教训：控制遵循要用客观指标（深度误差、掩码区 SSIM、位姿误差），要测长时域和首帧延迟，不能只看 GPT 分。

按本项目的严格标准定位

① 逐步动作条件：部分满足。条件是逐块流入的源视频，不是用户动作；提示词整段固定，没有演示中途切换。② 闭环：不满足，输出不会反馈到任何环境或决策。③ 跨步持久状态：弱，只有骨干在 5 秒窗口内的 KV cache。

所以它不是交互式世界模型，而是一个“流式条件生成器”。它对本方向的价值在于把控制能力迁移到因果骨干这套基础设施。

最值钱的后续实验

  1. 在 4 个去噪时间步上、用块因果推理方式重新估 A₁，报告各时间步子空间之间的主角度，看 t = 0 的 Vk 能代表多少。
  2. 直接投影 hint 与投影 LoRA 做对比；以及“块因果控制分支 + cache”与“逐帧”的对照。
  3. 加上离线双向 VACE 上界和直接在 CF 上训练的对照，量化迁移到底损失了多少。
  4. 用客观指标（深度 RMSE、非掩码区 SSIM）评测，多种子，报误差棒；修正表 1(c) 的重复行。
  5. 1 分钟以上的长视频、首帧延迟、端到端（含编解码）的 FPS。
