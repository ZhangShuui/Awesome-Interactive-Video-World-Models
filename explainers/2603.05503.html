CalibAtt

把「哪些注意力块可以不算」这件事，从在线猜改成离线标定一次、推理零开销地查表。

视频扩散 DiT 的 self-attention 占端到端延迟的一半上下，而 post-softmax 注意力矩阵本身极稀疏。已有的训练无关加速分两派：静态 mask（无开销但形状写死、稀疏度上不去），在线剖析（自适应但每步都要付估计开销）。CalibAtt 走第三条路——用 64 条标定 prompt 跑一遍离线 pass，为每一个 (timestep, layer, head) 组合各自拟合一张 128×128 block mask，编译成 skip list 常驻显存；推理时只查表，不做任何在线判断。Wan 2.1 14B 720p 上 62.5% 稀疏度 / 1.58×；4 步蒸馏模型上 73.9% / 1.57×，而在线方法在这里反而更慢。

一图看懂：一次离线标定，换来一张永久的「哪里不用算」清单

CalibAtt 的全部赌注是一句话：注意力该跳过哪些块，几乎与输入无关，但强烈依赖于你在第几个 timestep、第几层、第几个 head。前半句让它可以离线算好；后半句让它必须为 T×L×H 个组合各存一张图。Wan 2.1 14B 50 步就是 50×40×40 = 8 万张 mask。

Fig 1 · CalibAtt 的两个阶段
读法。整篇论文的工程重心在上半条带：它把「该跳哪些块」这个原本要在推理时边算边猜的问题，挪到了一次性的离线 pass 里。下半条带因此变得极简——查表 + 一个能读 skip list 的 FA3 变体，没有任何 online 判据、没有 warmup 步、也不需要人工指定「这些层不做稀疏」。代价全部前置：标定的 GPU 小时、以及把 8 万张 mask 常驻显存的 21.5 GB。
赌注 A：数据无关

同一个 (t,l,h)，换 prompt、换初始噪声，被跳过的块高度重合（Fig 3a/3b）。所以可以用 64 条 prompt 投票投出一张通用 mask。

赌注 B：结构依赖 (t,l,h)

但换层、换头、换 timestep，图案完全不同（Fig 2）。所以不能像 Radial Attention 那样用一张固定形状的 mask 套所有位置。

代价 A：一次性算力

720p 上 89.6 H100·h。可以砍到 13.7 h（16 条 mask prompt + 1 条相似度 prompt），质量基本不掉。

代价 B：常驻显存

720p 未裁剪 52 GB，逐层裁剪后 21.5 GB，再合并区间 + 跨步共享可到 3.6 GB（1.56× vs 1.58×）。

01

它在解什么问题：稀疏度高、开销小、形状自由，三者原本只能挑两个

训练无关的注意力加速，本质上都在回答同一个问题：在不算 QK⊤ 的前提下，怎么知道哪些块可以不算？已有答案分成两族，各自放弃了一样东西。

静态先验派 · Radial / STA

用位置先验直接写死 mask：注意力随时空距离指数衰减，于是窗口随帧距收缩。推理零开销，但形状是人设计的，稀疏度上不去，而且对「不服从衰减律」的头会伤得厉害。实践上还必须配 12/50 步 dense warmup 和首个 DiT block 全稠密才不崩（Radial 自己的 Table B：0 步 warmup 时 PSNR 掉到 12.8）。

在线剖析派 · SpargeAttn / SVG2 / XAttention

推理时用压缩表示（池化 Q/K、k-means 质心、反对角评分）估出块重要性再决定跳不跳。自适应、稀疏度高，但每一步都要付估计开销，而且估计本身会错。SVG2 还要做 k-means 聚类与置换。

CalibAtt：把「估」挪到离线

既然图案本来就和输入关系不大，那就不必在线估——离线用真实的、完整的 post-softmax 注意力去挑（离线时可以慢慢算），挑完编译成 skip list。于是同时拿到在线零开销 + 逐 (t,l,h) 的自由形状。代价挪成了标定算力与显存。

这个取舍在少步蒸馏模型上会被放大到极端：当整个生成只有 4 次前向时，任何「每步都要跑一遍的估计开销」都无法被摊薄。论文 Table 2 里最扎眼的一行就是 SVG2 在 LightX2V 480p 上做到 0.60×——比 dense 还慢 40%。

Fig 2 · 在线开销如何吃掉少步模型的收益 4

怎么用。拖 layer 或 head：图案会整个换一种结构（帧内块 / 跨帧条纹 / 全局列 / 弥散）。拖 prompt：结构基本不动，只有细节在抖——这正是 Observation 3 的内容，也是整套方法成立的前提。拖 timestep：早期（t 小 = 噪声大）更弥散，后期趋于稳定并彼此相似（论文 Fig S4 的 IoU 热图量化了这一点）。图案由确定性哈希生成，用来解释论文的定性描述，不要当成论文 Fig 2 的复制品。

逐条掂量

  • Obs 1 · 注意力图很稀疏，且在 block 粒度上仍然稀疏。这条最扎实，也最没有争议——从 H2O、Quest 到 SpargeAttn、SVG、Radial，所有人都看到同一件事。CalibAtt 的增量是把「block 粒度也稀疏」明确成 FlashAttention 友好的前提。
  • Obs 2 · 图案不跨 head / layer / timestep 复制。这条是对 Radial Attention 那类「一张形状套全场」方法的直接反驳，论文用它论证「必须逐 (t,l,h) 拟合」。同时论文自己留了口子：后期 timestep 之间高度相似（Fig S4 的 IoU），这一口子后来被用来省显存（跨步共享 mask）。
  • Obs 3 · 图案跨输入稳定。这是全文的命门。论文给的证据是 Fig 3a（四条 prompt 的图看起来一样）和 Fig 3b（保留率直方图双峰）。但 Fig 3b 自己的数字说明这个「双峰」没那么干净：ρ 从 0.10 挪到 0.70，稀疏度从 47% 走到 70%——中间地带藏着约 23 个百分点的预算。详见 §05。
  • Obs 4 · 帧内不同空间行的注意力模式高度重复。最有意思也最激进的一条：如果同一帧里第 3 行和第 17 行的 query 对所有 key 的分布几乎一样，那就只算 5 条代表行、把结果广播给其余 25 行。论文还发现它与块稀疏负相关（Fig 6a），因此两条路互补。§06 会拆这条。
03

能量选择器：整个方法的核心只有三行，但第一行藏了一个平均

固定一个 (t, l, h)，把 N×N 的 post-softmax 矩阵 P 切成 B×B 的块。对第 r 个 query 块行、第 c 个 key 块列，定义块能量：

Eq. (5) Er,c = (1/B) · Σi∈Ir Σj∈Jc Pij 除以 B 是为了让每个块行的总能量归一：Σc Er,c = (1/B)·Σi∈Ir 1 = 1。我验算过，这一步是对的。

然后对每个块行，求「累积能量达到 ε 所需的最少块数」：

Eq. (6) minSr |Sr|   s.t.   Σc∈Sr Er,c ≥ ε(t) 降序排序后取最短前缀即为最优解——这是对的，属于经典的「取最大元素直到满足下界」贪心。论文也如实说明了这一点。
Fig 4 · 拖动 ε 看一个 query 块行的取舍 0.950
左：该块行对 42 个 key 块的能量（降序）。中：累积曲线与 ε 的交点，交点左侧的块被保留。右：还原到原始 key 位置后的保留/跳过图。切到「弥散型块行」会看到同一个 ε 下保留的块数暴涨——这解释了为什么论文的 ε 要设得极高（0.84–0.99）却仍能拿到 60%+ 稀疏度：绝大多数块行的能量都压在极少数块上，只有少数块行需要付出代价。

第一行里的那个平均：能量准则并不是逐 query 的保证

Eq. (5) 先对块行内的 B=128 个 query 取了平均。于是「保留 ε 的能量」是一个块行平均意义上的承诺，不是对每个 query 的承诺。一个 key 块如果对块行里 5 个 query 至关重要、对另外 123 个可以忽略，它的 Er,c 会被平均稀释到阈值以下而被整块丢掉——对那 5 个 query 来说，它丢掉的不是 1% 的能量，可能是 30%。

这是所有 block-level 方法的共同代价（SVG2 的整篇动机就是想缓解它，做法是按语义而非位置聚类），但 CalibAtt 的写法容易让人把 Eq. (6) 读成逐 query 的误差界。论文没有给任何 per-query 的最坏情况统计。
第二个被忽略的东西：V。能量准则只看注意力权重 P，完全不看被加权的 V。两个能量相同的块，如果它们的 value 向量范数差 10 倍、方向相反，对输出 A = PV 的贡献完全不同。论文自己在 Obs 4 处引用的 Delta Attention（ref [30]）正是冲着这个问题去的，但块选择这一支没有用上。一个几乎零成本的改进是把 Er,c 换成 ‖Σj∈Jc P̄rjVj‖ 这类带 V 的量——论文把它留给了 future work 里的「更丰富的参数化」。
04

ε(t) 调度：论文最「不 training-free」的地方

ε 不是常数，而是随 timestep 衰减的三参数指数（t=0 是噪声最大的那一步）：

Eq. (7) ε(t) = A + (C − A) · exp(−k·t/T) 高步数档：C = 0.99，k = 16，而底线 A 被设成序列长度的线性函数 A(N) = 0.796 + 1.41×10−6·N；少步蒸馏档：A = 0.763, C = 0.863, k = 5.64（480p/720p 共用）。三个参数都由 Optuna 在标定集上按 VBench + 稀疏度搜出来。

三处值得记下的细节

  • A(N) 是一条两点拟合。高步数档只有三个配置（Wan 480p N=32,760、Wan 720p N=75,600、Mochi），却要拟合一个两参数的线性式。把它外推到一个新模型/新分辨率上，是没有被验证过的。论文的措辞是「在低步数档常数、高步数档让 A 线性依赖序列长度」，读起来像一条规律，实际上更像一次插值。
  • k=16 意味着额外保守度以 T/k ≈ 3.1 步为时间常数衰减。也就是说 ε 在大约前 6–9 步明显高于底线，之后基本贴着 A 走。论文正文批评别的方法「需要在特定层或时间步上关掉自己」，而 ε(t) 的前段本质上就是一个连续版的 warmup，量级与 Radial 的 12/50 步硬 warmup 同阶。说它「更少人工、更少武断」是公允的；说它「不需要排除」则是措辞上的胜利多于机制上的。
  • 调参目标与汇报指标是同一个。Optuna 的每个 trial 用 64 条标定 prompt 算 mask，然后测 VBench 与稀疏度；论文最后汇报的头条指标也是 VBench。标定 prompt 来自 MovieGen-Bench、评测 prompt 来自 VBench 官方集，prompt 层面没有泄漏，这点要给分。但指标层面的搜索预算是不对等的：CalibAtt 的调度被针对 VBench 搜过，三个基线用的是各自仓库的默认配置，没有得到同等预算的搜索。
05

跨 prompt 投票：把 Fig 3b 的四个数字算成一个分布

64 条 prompt 各自产生一张 mask，逐元素平均得到保留率 M̄r,c ∈ [0,1]，再用阈值 ρ 二值化：

Eq. (8–9) M̄(t,l,h) = (1/|D|) Σp∈D M(t,l,h)p   →   Mr,c = 1 若 M̄r,c ≥ ρ，否则 0 ρ 小 ≈ 取并集（任何一条 prompt 想留就留，稀疏度低）；ρ 大 ≈ 取交集（几乎全票才留，稀疏度高）。论文全程用 ρ = 0.5，即简单多数。
论文只给了一张直方图和四个稀疏度数字，但这四个数字足以把分布算出来。Fig 3b 的标注是：ρ=0.10→47%、ρ=0.30→57%、ρ=0.50→63%、ρ=0.70→70%。而稀疏度(ρ) 按定义就是 P(M̄ < ρ)，也就是保留率的累积分布函数。于是：

ρ=0.5 到底承诺了什么

在 ρ = 0.5 这个默认值下，被跳过的 63% 里有 47 个百分点是「几乎所有 prompt 都同意可以跳」，另外 16 个百分点是「10%–50% 的 prompt 明确想留、但被多数票否决」。对那些少数派 prompt 来说，Eq. (6) 承诺的「保留 ε(t) 的能量」在聚合之后已经不再成立——论文从头到尾没有测过聚合后每条 prompt 实际保住了多少能量。这是一个几乎零成本的诊断（拿标定集本身跑一遍就有），却缺席了。

还有一个分布问题：标定集和评测集都是「benchmark prompt」。标定用 MovieGen-Bench，评测用 VBench 官方集——两者互不重叠，这点做得对。但它们都属于同一类文本分布：英文、写实/通用题材、中等长度描述。论文没有测试任何真正 OOD 的输入：强风格化（水墨、像素、2D 动画）、含大量文字的画面、非 16:9 的比例、I2V（图生视频，其注意力结构与 T2V 已知不同）。「数据无关」这个结论的适用半径，目前只被验证到 benchmark prompt 的范围内。

好消息是 Fig 7 的曲线确实很快收敛：从 1 条 prompt 涨到 16 条，稀疏度–质量前沿基本就定住了；Table S3 也显示 16 条 mask prompt + 1 条相似度 prompt 就能把标定成本从 89.6 压到 13.7 GPU·h，Total 只从 79.69 掉到 79.45。真正的断崖出现在 8 条（Total 78.53），所以 16 是个有据可依的拐点，不是随便挑的。

空间重复分支：第二根支柱，但它比正文叙述的要细

三点保留意见

  • 它的实际贡献远小于正文给它的篇幅。论文 Fig S5b 的横轴是「按重复头占比加权后的注意力加速」，整个取值范围只有 1.02×–1.12×。反推一下：若 x 比例的头拿到 5.3× 而其余不变，总注意力时间 = (1−x) + x/5.3；要得到 1.10× 需要 x ≈ 11%。Fig S6 也显示重复头集中在首尾几层。所以这条支路更像是「捡一成左右的额外便宜」，而不是与块稀疏并列的第二根支柱——Table S2 里那个 5.3×（甚至 k=1 时的 20.5×）很容易被读成端到端量级。
  • 它广播的是「输出」，不是「模式」。被标记的头里，同一帧内 25 条行的注意力输出逐元素等于它们各自 anchor 行的输出。这意味着该头在这一帧上丧失了纵向分辨能力。判据是行间余弦相似度 ≥ γ=0.87 ——对一个 52×N 的展平概率向量来说，0.87 并不算很紧；论文给的误差只有一个跨 (t,l,h) 与 prompt 平均后的相对 L2 ≈ 10−3，没有任何最坏情况或按帧/按行的分布。视频里最容易被这种操作抹掉的，恰恰是「细长的横向结构随高度缓慢变化」这类内容（地平线、栏杆、字幕条），而 VBench 对此基本不敏感。
  • 它绑死了 token 的排布方式。整套推导依赖「行主序 + 每帧固定 W 列 + 帧边界对齐」。换一种 patchify（例如 3D patch 或非 2 的因子）、换一种 3D RoPE 的 token 排序、或者做了 SVG2 那样的语义置换之后，I(f,i) 的连续性就没了。论文在 Wan 与 Mochi 上都能用，是因为这两个模型恰好都是这种排布。
给作者一个好评。Fig S5 的结论是反直觉且诚实的：用更低的 γ 标记更多头、但每个头多留几条 anchor 行，在同等误差下比「只标少数头、每头只留 1 条 anchor」更划算。这是一个真正有信息量的消融，而不是走过场。γ=0.87 / k=5 就是这么定下来的。

Skip-list 与显存：52 GB 这个数字可以被完全复原

  • Total = 0.8×Quality + 0.2×Semantic。我用这个官方加权把论文全部 5 张 VBench 表、40 多行全部重算了一遍，每一行都在 ±0.01 的舍入范围内对上。这篇论文的数字录入是干净的，没有任何对不上的行。

稀疏度口径：一个可以被反推出来的不一致

现象。论文报 SVG2 在 Wan 720p 上稀疏度 46.3%。但 SVG2 自己的论文（Table 1）在完全相同的模型/分辨率/硬件上报的是 density 29.51%，也就是稀疏度 70.5%。差了 24 个百分点。RadialAttention 同理：论文报 54.7%，而 Radial 自己在 Wan2.1 上用的 mask 稀疏度是 73.6% 量级。

这不是谁算错了，是口径不同，而且差异可以被精确复原。两个基线都要配 dense warmup：SVG2 是前 30% 的步全稠密，Radial 是 12/50 步全稠密 + 首个 DiT block 全稠密。它们自报的密度是稀疏阶段内的密度；而 CalibAtt 的「稀疏度」定义是「跳过的 query-key 对占全部时空 token 对的比例，对所有 timestep、层、头取平均」，也就是把那些全稠密的步也算进分母。代入：

基线自报（稀疏阶段内）dense 部分折算成全程平均论文实报
SVG2 · Wan 720p70.5%前 30% 的步0.70 × 70.5% = 49.3%46.3%
Radial · Wan 720p≈73.8%（反推）12/50 步 + 1/40 层0.76 × (39/40) × 73.8% = 54.7%54.7%
我的判断：CalibAtt 这个口径是更正确的那一个——你关心的是整条生成流程省了多少计算，而不是某个子区间里的密度。而且这恰恰把 CalibAtt 的一个真实优势量化了出来：它全程都在稀疏，不需要任何 warmup 步。问题只在于论文一个字也没解释这个换算，于是任何拿论文表和基线原文对照的读者都会得到「CalibAtt 把基线跑坏了」的错误印象。一个脚注就能解决。
而延迟那一列里，有多少是算法、有多少是核？Radial Attention 自己的论文白纸黑字写着：「我们目前的实现用 FA2，升级到 FA3 与算法正交，留作 future work」。CalibAtt 的补充材料则说：对 Radial 与 SVG2，「我们把 dense/warmup 部分的后端设为 FA3 以对齐我们的 dense 基线」——也就是说，稀疏部分仍然跑各家自己的核。于是 Table 1 的延迟比较里，CalibAtt（为本方法定制的 FA3 block-sparse 核 + 预编译 skip list）对 Radial（FA2 时代的块稀疏核）有一层实现代差。

这不削弱 CalibAtt 的工程价值——把核写好本来就是贡献的一部分，论文也把核实现明确列为 contribution。但它确实意味着：表里的加速差距不能被当成算法差距来引用。唯一能拆开两者的做法——在相同稀疏度下对比各方法的孤立注意力核延迟——论文没有做。

这意味着 Quality 与 Semantic 单独读是不可靠的，而 Total 之所以稳，是因为这两项在沿同一条权衡轴反向滑动。论文的多处表述依赖单项：720p 上 CalibAtt 的 Semantic 72.81 vs dense 71.65（+1.16）完全落在这个摆幅之内；480p 上 RadialAttention 的 Semantic +3.98 同样是沿轴滑动的产物（它的 Quality 同时掉了 0.95，见 §09 的残差计算）。全文没有多 seed、没有置信区间、没有方差报告，而方法之间的 Total 差距只有 0.1–1.4 分。

怎么排除

3 个 seed × VBench 给出 CI（按 720p 0.346 GPU·h/支估算，一轮约 330 GPU·h，对一个已花 89.6 h 做标定的工作并不离谱）；或至少在正文写明「请引用 Total」。注意 Table S4 给出的 0.03 是下界——这七行共享 mask 与评测集，真实 run-to-run 方差只会更大。

高D2没有任何与 dense 输出的保真度指标，无法放上同行的 Pareto 图▶
现象

论文明确拒绝报告 PSNR/SSIM/LPIPS：「我们关注生成质量与提示遵从，而非逐 seed 的重建指标，因为目标是保持整体质量水平而非精确复现 dense 输出」。全篇唯一的保真度数字是 Fig S5 里空间重复分支的注意力输出相对 L2（≈10−3）——块稀疏那一支一个都没有。

② 结合 D1：VBench Total 的分辨率只有 ±0.03（乐观下界），对系统性分布漂移（运动变平缓、细节变柔、高频纹理丢失）几乎不敏感。一个把输出整体往「更安静」的方向推的方法，在 VBench Total 上可以毫发无损。

高D3「稀疏度」这一列与基线论文自报的口径不同，且全文未作说明▶
现象

论文报 SVG2 在 Wan 720p 上 46.3% 稀疏度；SVG2 自己在同模型、同分辨率、同 H100 上报的是 density 29.51%（= 70.5% 稀疏）。Radial 报 54.7%，而 Radial 自己在 Wan2.1 上的 mask 稀疏度是 73.6% 量级。

为什么重要

差异的来源可以被精确复原：两个基线都带 dense warmup（SVG2 前 30% 的步；Radial 12/50 步 + 首个 DiT block），它们自报的是稀疏阶段内的密度，而 CalibAtt 的定义是对所有 timestep/层/头取平均。代入即得 0.70×70.5% = 49.3%（报 46.3%）与 0.76×(39/40)×73.8% = 54.7%（报 54.7%，完全吻合）。CalibAtt 的口径是更正确的那个，并且恰好量化了它「全程稀疏、无需 warmup」这个真实优势。问题纯粹在于：论文一个字也没解释，任何拿论文表去对照基线原文的读者都会误以为基线被跑坏了。

怎么排除

一个脚注：「本文稀疏度对全部 timestep 取平均，包含各基线的 dense warmup 步；基线原文报告的是稀疏阶段内的密度，两者不可直接对照。」再补一列「稀疏阶段内密度」即可两全。

高D4延迟优势里混入了核实现的代差，论文没有把算法和核拆开▶
现象

CalibAtt 为自己写了定制的 FA3 block-sparse kernel（读预编译 skip list，按 (t,l,h) 换表）。对基线，补充材料写的是「对 Radial 与 SVG2，我们把 dense/warmup 部分的后端设为 FA3 以对齐 dense 基线」——稀疏部分仍跑各家自己的核。而 Radial 自己的论文白纸黑字写着：「我们目前的实现用 FA2，升级到 FA3 与算法正交，留作 future work」。

为什么重要

于是 Table 1 的延迟列里，CalibAtt 的「定制 FA3 核」在和 Radial 的「FA2 时代块稀疏核」比。正文说「所有方法都用 FlashAttention3 后端或等价物」——「或等价物」承担了太多含义。这不削弱工程价值（核实现本来就被列为 contribution 之一），但它意味着表里的加速差距不能当作算法差距引用。反证也在表里：SpargeAttention 按官方建议用了 SageAttention2（INT8/INT4 量化）后端，理论上每块更快，却只拿到 1.15×——说明后端选择对结果影响巨大。

怎么排除

补一张孤立的注意力核基准：在相同稀疏度下，各方法的 attention kernel 延迟（就像论文 Table S2 为 anchor-row 核做的那样）。或者退一步，报出 dense FA3 下自注意力占每步的百分比 + CalibAtt 核在该稀疏度下的加速比——两个数字就能把两件功劳分开。

高D5最直接可比的基线 LiteAttention 被引用、被借用核，却没有进任何一张表▶
现象

论文在 §3.4 写：「我们的实现基于 FlashAttention3 以及此前工作 [24, 41] 提出的块稀疏核」——[24] 正是 LiteAttention（NeurIPS 2025，MoonMath.ai，代码开源），[41] 是 SpargeAttention。相关工作里也准确描述了 LiteAttention「把 SpargeAttention 改造成 FA3 核并跨 timestep 复用 skip list」。但四张结果表里的基线只有 SpargeAttn / Radial / SVG2，没有 LiteAttention。同样缺席的还有 XAttention 与 Sliding Tile Attention。

为什么重要

LiteAttention 是与 CalibAtt 设计空间最接近的方法：同样基于 FA3、同样用 skip list、同样把「重复剖析」这件事摊掉（它的做法是前几步在线判定、之后冻结并单调演进）。而且它开源、CalibAtt 还直接用了它的核。缺了这一行，「state-of-the-art among training-free methods」这句话就缺了最关键的一个对照。
公平起见我要说清楚：LiteAttention 自报的 1.89×（Wan2.1-14B、42% 稀疏、H200、12 条 OpenSora prompt）与 CalibAtt 的数字不可直接比较——硬件、prompt 集、分辨率/帧数全不同，它的 dense 基线 1707 s 明显对应更大的工作量。所以这里的问题是缺少对照，不是「CalibAtt 输了」。

怎么排除

跑一行 LiteAttention（官方仓库 + 同样的 VBench 协议）。如果确实赢了，这是全文最有说服力的一行；如果打平，那么「零在线开销 + 无 warmup」这个卖点依然成立，只是需要更精确的措辞。

中D6「无需人工排除层/时间步」被 ε(t) 和 Optuna 稀释了；A(N) 是一条两点拟合▶
现象

ε(t) = A + (C−A)e−kt/T，高步数档 C=0.99、k=16。k=16 意味着额外保守度以 T/k ≈ 3.1 步为时间常数衰减，前 6–9 步明显高于底线。三个参数由 Optuna 逐配置搜索，目标是标定集上的 VBench + 稀疏度。底线 A 被写成 A(N) = 0.796 + 1.41×10−6·N。

为什么重要

① 论文批评别人「在特定层或时间步上关掉自己」，而 ε(t) 的前段本质上是连续版 warmup，量级与 Radial 的 12/50 步硬 warmup 同阶。说它更平滑、更少武断是公允的；说它「不需要排除」是措辞上的胜利多于机制上的。
② 高步数档只有三个配置（Wan 480p、Wan 720p、Mochi），却要定一个两参数线性式。把它外推到新模型/新分辨率是未经验证的，而这恰恰是「自动适配任何模型」这个卖点的落点。
③ 搜索预算不对等：CalibAtt 的调度被针对 VBench 搜过（prompt 层面无泄漏，这点要给分），三个基线用的是仓库默认配置。

怎么排除

在第四个配置（比如 HunyuanVideo 或 Wan 2.2）上直接套用 A(N) 而不重搜，报出结果——这一条就能把「拟合」升级成「规律」。以及给基线同等的 Optuna 预算，或至少说明为何不给。

中D7能量准则是「块行平均」而非逐 query 保证，而且完全不看 V▶
现象

Er,c 先对块行内 B=128 个 query 取了平均（Eq. 5）。Eq. (6) 承诺的「累积能量 ≥ ε」因此是块行平均意义上的。此外整个准则只用 post-softmax 权重 P，不涉及 V。

为什么重要

① 一个 key 块若对块行内 5 个 query 至关重要、对另外 123 个可忽略，它的平均能量会被稀释到阈值以下而被整块丢掉——对那 5 个 query 而言损失的远不止 1−ε。这是所有 block-level 方法的共同代价（SVG2 的整篇动机就是缓解它，做法是按语义聚类而非按位置），但 CalibAtt 的写法容易让 Eq. (6) 被读成逐 query 的误差界，论文没有给任何 per-query 的最坏情况统计。
② 输出是 A = PV。两个能量相同的块，若 V 的范数差一个量级，对输出的贡献完全不同。论文在 Obs 4 处引用的 Delta Attention 正是冲这个去的，但块选择这一支没用上。

怎么排除

报一条 per-query 的能量保留分位数曲线（5%/1% 分位，而不只是均值）；以及把 Er,c 换成带 V 的量（如 ‖Σj∈Jc P̄rjVj‖）做一次消融——这是离线阶段，算得起。

中D8「数据无关」比声称的弱：至少 23% 的块落在争议地带，且没有 OOD 测试▶
现象

Fig 3b 的四个锚点：ρ=0.10→47%、0.30→57%、0.50→63%、0.70→70%。由于稀疏度(ρ) 按定义就是 P(M̄ < ρ)，可直接得到 P(0.10 ≤ M̄ < 0.70) = 23%。

为什么重要

① 若分布真如论文所说「双峰、大量块聚在 0 或 1 附近」，ρ 这个旋钮本该几乎不起作用。实际上它能把稀疏度从 47% 拨到 70%，这 23 个百分点全部来自中间地带——它们是真正依赖输入的块。在 ρ=0.5 下，被跳掉的 63% 里有 16 个百分点属于「10%–50% 的 prompt 想留、被多数票否决」。

③ 标定用 MovieGen-Bench、评测用 VBench，两者互不重叠（这点做对了），但都属于同一类「英文写实通用题材 benchmark prompt」。没有任何真正 OOD 的测试：强风格化、含大量文字的画面、非 16:9、I2V。

怎么排除

补一张「聚合后实际保留能量」的分位数图；再补一组 OOD prompt（动画/水墨/文字招牌/竖屏）的 VBench + 保真度，看 ρ=0.5 的 mask 是否仍然安全。

中D9CFG 的 unconditional 分支从未被标定，却共用同一套 mask，零证据▶
现象

补充材料 A 开头一句带过：「使用 CFG 时，我们只用 conditional 分支标定 mask 与相似度分数。推理时同一套 mask 同时施加于 conditional 与 unconditional 两个分支。」

为什么重要

中D10空间重复分支：正文叙事把它抬成第二根支柱，附录的数字说它只值一成▶
现象

Table S2 给出 k=5 时 5.3×（k=1 时 20.5×）的核级加速，读起来非常醒目。但 Fig S5b 的横轴——按重复头占比加权后的注意力加速——整个取值范围只有 1.02×–1.12×；Fig S6 显示重复头集中在首尾几层。

为什么重要

① 反推：若 x 比例的头拿到 5.3×，总注意力时间 = (1−x)+x/5.3，要得到 1.10× 需 x ≈ 11%。所以这条支路贡献的是「大约一成的额外注意力加速」，而不是与块稀疏并列的一半。摘要与 §3.3 的篇幅容易让人误读 Table S2 的 5.3× 为端到端量级。
② 它广播的是输出：被标记的头里，同一帧 25 条行的注意力输出逐元素等于各自 anchor 行的输出，该头在这一帧上丧失纵向分辨力。判据 cos ≥ 0.87 对一个 52×N 的展平概率向量并不算紧，而论文给的误差只有跨 (t,l,h) 与 prompt 平均后的相对 L2 ≈ 10−3，没有最坏情况、没有按帧/按行分布。最容易被抹掉的恰是「随高度缓慢变化的细长横向结构」（地平线、栏杆、字幕条），而 VBench 对此基本不敏感（见 D1/D2）。
③ 它绑死了 token 排布：行主序 + 每帧固定 W 列 + 帧边界对齐。换 patchify、换 3D RoPE 排序、或做 SVG2 式语义置换之后就不成立。
④ 另外，这条支路的稀疏度按 1−k/H = 83.3% 计入全局平均稀疏度，但它省的是 query 行而非 KV 块，硬件收益曲线与块稀疏不同，两者混在同一个「稀疏度」数字里会让 §10 那个「边际收益断崖」更难诊断。

怎么排除

在主表里拆出「仅块稀疏」与「块稀疏 + 空间重复」两行（Table S4 已经为 480p 做了「仅块稀疏」的隔离，只差一步）；并报 anchor 广播的逐行误差分布而非均值。

720p 未裁剪 52 GB、逐层裁剪 21.5 GB（Table 1 的 1.58× 用的就是这档）、合并区间 + 跨步共享可到 3.6 GB（1.56×）。复原：NB=⌈75600/128⌉=591，列宽 2×295+1=591，int16，80,000 张 ⇒ 52.0 GiB，与论文完全一致。

中D12标定成本 ≈ 每条 prompt 生成四支视频；回本点 703 支（廉价档 111 支）▶
现象

把 Table S3 的四个点（8→7.1h、16→13.7h、32→27.0h、64→53.0h）线性拟合：块能量 0.820 GPU·h/prompt，斜率外的截距 0.543 h 恰好等于「1 条相似度 prompt」，而独立算出的相似度单价是 (89.6−53.0)/63 = 0.581 h/prompt——两者吻合，分解自洽。对照：720p dense 生成一支 = 1244 s = 0.346 GPU·h。

为什么重要

于是：标定一条 prompt ≈ 4.05 次 dense 生成（块能量 2.37× + 相似度 1.68×）。回本点 = 标定成本 ÷ 每支节省：89.6 h ÷ (459 s = 0.1275 h) = 703 支；廉价档 13.7 h ÷ (443 s) = 111 支。论文给了 GPU 小时但没做这个换算，而它直接决定了方法适合谁：批量推理服务划算，研究者跑几十支对比实验不划算，边缘设备走不通。

怎么排除

不是错误，是缺失的一句话。把「回本点 ≈ N 支视频」写进 Limitations 会让这篇论文的定位清晰得多。顺带：论文自承相似度那一半的 PyTorch 实现还有优化空间，把它与块能量 kernel 融合是明确的省钱项。

中D13稀疏度换不成加速比：Mochi 稀疏度最高却加速最低，且边际收益有断崖▶
现象

Mochi 稀疏度 69.1%（全表最高）→ 1.16×（全表最低）；Wan 720p 62.5%（最低）→ 1.58×（最高）。按 加速=1/(1−f·s) 反解出的注意力时间占比：Mochi f≈0.20、Wan 480p 0.46、Wan 720p 0.59、4步 480p 0.32、4步 720p 0.49（完美核假设下的下界）。

为什么重要

怎么排除

报出 dense FA3 下自注意力占每步的比例，以及 CalibAtt 核在不同稀疏度下的孤立延迟曲线（LiteAttention 的 Table 3 就是这么做的，并显示其运行时间随跳过比例近乎 1:1 下降）。这一条同时解决 D4。

谱系与定位：它占的是哪个象限

把训练无关的稀疏注意力按两个轴摆开：横轴是「跳哪里」这个决定在什么时候做，纵轴是mask 形状有多自由。CalibAtt 主张自己占住了此前是空的那个象限——离线决定 + 逐 (t,l,h) 自由形状。

一句话总结各家的赌注

  • Radial Attention（NeurIPS'25）：赌「注意力随时空距离指数衰减」这条物理式先验。赢在零开销与 O(n log n)，输在形状写死，且必须靠 12 步 dense warmup 兜底。
  • SpargeAttn（ICML'25）：赌「用压缩的 Q/K 能在线估准块重要性」。通用（任何模型都能挂），但估计要花钱，且本文里它的稀疏度全程钉在 ~49.7%（默认配置）。
  • SVG2（NeurIPS'25）：赌「按语义 k-means 聚类再置换，能同时提高识别精度并消除计算浪费」。在 50 步 720p 上确实拿到 Pareto 前沿，但聚类开销在少步模型上反噬（本文实测 0.60×）。
  • LiteAttention（NeurIPS'25）：赌「稀疏图案跨 timestep 时间相干」——早期标记的可跳 tile 之后仍可跳，于是只付一次剖析。与 CalibAtt 是同一枚硬币的两面：它把剖析摊到本次生成内部，CalibAtt 把剖析摊到所有未来生成。
  • CalibAtt（ECCV'26）：赌「图案跨输入稳定」。把剖析彻底移出推理路径，换来零开销与 (t,l,h) 级自由形状；代价是标定算力、常驻显存，以及一份绑死在具体配置上的字典。
放回这个仓库的语境（交互式视频世界模型）里看。CalibAtt 不是世界模型，是使能层：交互式 rollout 要求低延迟，而低延迟的主流路线是少步蒸馏。恰恰在少步这一档，所有需要在线剖析的加速方法都会失效（SVG2 在 4 步 480p 上 0.60×），而 CalibAtt 的零开销属性在这里从「优雅」变成「唯一可行」。它与这个仓库里已有的少步蒸馏工作（CrossDistill、DMD 系）是相乘而非替代的关系：蒸馏把 50 步压到 4 步，CalibAtt 再把每一步压掉 36%。

但也要看到限制：交互式世界模型通常是自回归、变长、KV 缓存的，而 CalibAtt 的字典绑定固定的 (N, T)。把它搬到自回归 rollout 上，需要先回答「序列长度在变化时 mask 怎么办」——论文没有触及这个方向。
