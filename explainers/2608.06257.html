这篇论文真正证明了什么

平均字段准确率是个假指标。三个独立的 dense 架构（CNN / U-Net / RSSM）在同预算下能把 91–96% 的字段猜对， 同时对每一个实体在哪一无所知（位置准确率 ≤ 2.7%），且 100% 的预测 tick 结构自相矛盾。 这个诊断超出多智能体的范围 —— 它是对整个 latent world model 范式的一次很硬的检验。

而这四句话不能按字面读

①「10,000 recurrent steps」是 no-op 动作流 + 空 spawn 的结构性压力测试，且 277–306 步后进入循环吸引子； 真实语义衰减在 SRSC 表里：Snake 的 Logic 分 H=300 掉到 33.8，Crate Pusher H=100 就掉到 10.0。
②「X-view = 0.000」是同义反复 —— 所有视角从同一份状态确定性投影，不一致数学上不可能。
③「structurally valid by construction」是 schema mask 给的，不是模型学的。
④ MASS 不是实时的：Logic Engine 45.55 ms/tick，是 dense 基线的 12–15 倍；同期 Gamma-World 24 FPS、MIRA 20 FPS 都是真实时。

01

问题：单人世界模型里成立的那个等式，在多人时破了

单人世界模型里，「世界的记忆」和「玩家看到的画面」是同一个对象 —— 像素，或者视觉 latent。 GameNGen、Oasis、DIAMOND、Genie、WHAM 全都建立在这个等式上：每一帧从一个递归状态解码出来，而这个状态同时又是下一步的输入。响应快、细节丰富、不需要游戏引擎。

多人的时候这个等式破了。MASS 引言里那句话说得很干净：

「A thousand players can inhabit one world, yet each camera reveals only a small part of it.」

后果被拆成三条，可以直接当作这个领域的问题定义：

图 1 · 单人世界模型的核心等式，以及它在多人场景下失效的三条后果。MASS 的全部设计动机就是让「递归记忆」和「同步对象」变成同一个东西。

03

Schema：全部游戏特定配置只从这一个文件进入模型

Σg = { (kindj, fieldsj, countj) }j=1..Jg Eq. 1

每条声明一种实体：叫什么、有哪些字段、每个字段的合法取值域、世界里有多少个实例。关键的分工是：

schema 只定义「什么是合法状态」，不定义「蛇怎么长、箱子怎么推、碰撞怎么判」 —— 后者全部从记录的转移里学。原文："The schema defines representation and validity, while the learned model supplies the transition."

下面是 population-scale Snake（1024 玩家）的真实 schema（论文附录 A.1，原文 157 行的删节版）：

schema_version: snake-n1024-factorized-v4 game: snake factorization: constants: arena: [512, 512] viewport_cells: 31 globals: row_kind: global fields: [tick] tables: - state_field: snakes # 一行一个玩家实体 row_kind: snake rows: 1024 matching: index action: joint_index # ← 该行接收对应玩家的动作 token anchor: body.0 # ← 记录空间锚定在蛇头 - state_field: food # 世界拥有的实体，按空间分桶 row_kind: food_bucket rows: 4096 matching: index canonical: sorted_unique # ← 解码成规范排序集合（由 selector 强制） anchor: $index layout: type: spatial_buckets width: 512 ; height: 512 ; bucket_width: 8 ; bucket_height: 8 spatial_context: # 每条记录能看到自己锚点周围的什么 arena_field: arena radius: 4 layers: - {source_field: food, points: $item, value: {fixed: food}} - {source_field: snakes, points: body, value: {fixed: body}} - source_field: snakes points: body.0 indexed_action: true # ← 邻居「尚未执行的动作」是可见的 value: template: head_{heading_x}_{heading_y}_a{action}

三个值得单独指出的设计点：

  1. anchor（空间锚点） —— 每条记录声明自己「在哪」。这是记录级分解能成立的前提：邻域窗口 cit 就是绕着锚点取的。
  2. indexed_action: true —— 邻居的待执行动作被写进上下文窗口。这一条很关键：它让「两条蛇同时冲向同一格」这类交互能在记录级并行预测下被正确解决，而不需要记录之间的注意力。
  3. canonical: sorted_unique —— 这类跨记录约束不是学出来的，是解码器层面由确定性 selector 强制的。
这条路线最大的实践成本

schema 是人写的，而且训练需要能导出 ground-truth typed state 的引擎。相比之下 Solaris / MIRA / Gamma-World 只需要视频 + 动作。 MetaWorld 就明确批评过这类依赖，称之为 "privileged infrastructure"。MASS 全篇没有讨论 schema 从哪来。

04

World State Tokenizer：把世界压成一串整数

uit = TΣg( ρit, cit, aπ(i)t, eit ) Eq. 3
  • ρit —— 这条记录当前的字段值
  • cit —— 从当前状态和联合动作算出来的邻域窗口（Snake / Crate Pusher 用 9×9 radius-4；Pac-Man 用 3×3 radius-1 + chunk 内最多 64 条 agent 记录）
  • aπ(i)t —— 该记录归属玩家的动作（有归属时）
  • eit —— exogenous input：属于这条记录的那份「被记录下来的随机性」（如预告的食物刷新点）。它是喂进去的，不是预测出来的 —— 这样就把「环境随机性」和「交互结果」干净地分开了。

一个真实的 token 序列

matched Snake（48×48，≤8 玩家槽）在 tick 142、双人局的完整 447-token 输入前缀：

图 3 · 447-token 输入前缀的分段解剖。读这张图的收获：世界状态被压成了一个 421 维的定长整数向量 —— 全部「世界模型的记忆」就在这 421 个整数里，没有任何一个 bit 在视觉 latent 里。

规范序列化的规则：记录种类按 schema 固定顺序；表内记录按持久 slot 或 canonical key 索引；布尔 / 类别 / 整数坐标用不相交的 typed token 区间；可选字段有显式 present/absent token；有界列表以长度开头、以规范 padding 结尾；空间桶等变长集合序列化前先排序去重。解码严格反向，无损还原。

Logic Engine：5.66 M 参数，记录之间零注意力

decoder-only causal Transformer width 256 layers 6 heads 8 MLP ratio 4 params 5.66 M max len 1024 tied embeddings coordinate embeddings
pθ( st+1 | st, at, et ) ≈ ∏i=1..Kg ∏j pθ( yi,jt+1 | uit, yi,<jt+1 ) Eq. 5
全篇最关键的架构决定

"Self-attention stays confined to each record's sequence. Interactions between world objects enter through the neighborhood window cit, computed from the shared state before prediction. Records are batched freely at training and inference with no attention between them."

记录之间没有任何注意力。5,121 条记录就是 5,121 个独立的 batch item。实体之间的相互作用，全部通过「预测开始之前就算好的邻域窗口」传递。 这是 MASS 能在 1024 实体规模上跑起来的唯一原因，也解释了为什么 schema 要把邻居的待执行动作写进上下文。

图 4 · Logic Engine 的一次更新。约束解码只保证格式合法，不保证语义正确 —— 论文明确列出「body adjacency、合法移动、碰撞、生长、死亡、食物消耗」全部仍是学出来的。所以 Table B.2 里 MASS 的 Contradiction 恒为 0.0 是 mask 的功劳，这一列没有模型信息量。

Rendering Engine：从 16 通道语义栅格到 RGB

ôit = Rϕ( Pi(ŝt), κi ) ， pϕ( ôCtt | ŝt, κ ) = ∏i∈Ct pϕ( ôit | Pi(ŝt), κi ) Eq. 7–8
这个连乘式就是全篇的核心断言

给定 ŝt，各视角条件独立。跨视角一致性不是被优化出来的，是被这个分解定义掉的。 所以 Table 2 里那个 X-view = 0.000，是架构的定义性质，不是一条实验发现。

投影 Pi（非学习部分）把预测状态栅格化成一个 16 通道张量：可见占据 · 语义角色 · 归属与被选中玩家身份 · 深度/距离 · 视图几何。 相机锚定在被选中的实体上，参数化为 heading、pitch、有界 FOV。每个相机独立投影，但全部读同一份完整预测状态。

geometry-aware residual U-Net 64 通道 stem 3× 下采样 bottleneck 5 个空洞残差块 3× 带 skip 上采样 sigmoid RGB 随机初始化

stem 的输入不只是 16 个语义通道，还包括坐标特征、语义梯度特征、深度梯度特征。损失是 object-weighted Charbonnier + multiscale L1 + image-gradient alignment + SSIM + color saturation 的组合， 无感知损失、无对抗网络。AdamW / lr 2e-4 / batch 8 / bf16 / clip 1.0；native 渲染器 6,000 步、matched 渲染器 20,000 步。 分辨率 matched 128×128、六渲染器矩阵 96×96、跨游戏 native 256×256。

推理时 renderer 不接收目标像素，也不接收 RGB 历史。这是四轴误差分解（SRSC）的基础：用同一个网络渲染 ground-truth 状态，就能把图像合成误差从动力学误差里隔离出来。

由此得到的四个工程性质

  • 相机可以在 rollout 中途增加、移动、升级，世界转移不变 —— 这是九篇里唯一把相机做成一等公民 query 的
  • 分辨率、材质、光照可以改而不重训动力学
  • 渲染工作量在客户端本地，与服务器推进世界的代价无关
  • 不同视觉主题共用同一个 typed 接口（在 8 个游戏上验证，256×256 下 PSNR 23.72–40.24 dB，5/8 超过 32 dB）

Server / Client：netcode 被原样搬了过来

Tserver = Tlogic(N) + C · tsync(S) Eq. 9

N = 活跃实体数，C = 状态接收方数，S = 快照大小。 学习到的转移只跑一次；分发对 C 线性；渲染在每个客户端本地从收到的 typed 状态跑。

09

诚实的部分：长程语义衰减

论文摘要说「advances predicted worlds with 1,024 concurrent players for 10,000 recurrent steps」。这句话要非常小心地读。

10,000 步压力测试的真实设定（附录 C.3 原文）

"We extend the horizon with a separate stress test from held-out initial states, using a fixed no-op action stream and explicit empty-spawn tokens. The test measures structural decodability, roster survival, collapse, and recurrence independently of a reference continuation."

以及："The trajectories visit between 277 and 306 unique predicted states before entering a recurrent attractor."

所以：动作流是全 no-op、spawn 是空的；度量的是能不能解码、名册有没有掉人、有没有崩溃，不是语义对不对；而且 277–306 步之后就开始循环了。

真实的语义衰减在 SRSC 表里。判官是 Qwen3.5-27B（temperature 0、pinned seed 20260722、结构化 JSON schema 强制、协议哈希绑定），Logic 轴与程序化状态指标相关性 r = 0.962。

图 6 · SRSC 四轴分解随 horizon 的变化。Snake 的 Logic 分 H=300 掉到 33.8、H=600 基本归零；Crate Pusher（交互密度更高）H=100 就掉到 10.0。样本量较小（Snake / Crate Pusher 20 个场景，Pac-Man 只有 6 个），引用时应注明。

SRSC 的四个轴，每个写成 (reference, candidate)

Logic：teacher 渲染 GT 状态 vs teacher 渲染预测状态 → 纯 Logic Engine 误差
Renderer-GT：teacher 渲染 GT 状态 vs learned 渲染 GT 状态 → 纯 Rendering Engine 误差
Renderer-Pred：两边都条件在预测状态 → 退化输入分布下的渲染误差
End-to-end：teacher 渲染 GT vs learned 渲染预测 → 全链路

同一个衰减在图像指标上也看得到（Figure B.1 的关键点值）：MASS 的世界可恢复性 tick 1 时 0.963 → tick 128 时 0.642；位置召回 1.000 → 0.224。 而论文自己点破了 LPIPS 曲线比状态曲线平滑得多的含义：一个视觉上合理、距离上很近的帧，完全可以代表一个不同的交互结果。

一处论文内部不一致

Table B.4 给出 matched 双人 Logic Engine 延迟 45.55 ms，附录 D.1 也说 "the transition takes 45.6 ms"； 但 Table C.2 里 N=2/4/8 的延迟是 740–867 ms，相差 17–19 倍，论文未说明口径差异。引用时必须注明。

另外要跟同期工作对齐一下速度概念：MASS 的 45.55 ms/tick「fits a 20 Hz tick budget」—— 20 Hz 是游戏 tick 率，不是渲染帧率，这个说法成立； 但它跟 Gamma-World 的 24 FPS（4 步去噪）或 MIRA 的 20 FPS（单张 B200，70 ms 出两帧）完全不是一回事。MASS 赢的是解耦和可验证性，不是速度。

三条跨论文的负面证据

  1. 重建指标不预测生成质量，被三次独立证实。MIRA Table 3（from-scratch PSNR 32.2 > 冻结 DINOv3 的 29.7，但 gFID 22.5 vs 10.7）；MIRA Table 6（无感知损失时 PSNR/SSIM 最高但 gFID 26.8）；MASS Table 2（B-UN 的 LPIPS 第二好但 Parser 归零）。三种不同的指标体系，同一个结论。
  2. 效率改进往往是质量中性甚至负的。Gamma-World 从 dense 换成 SHA 后 FID 29.6 → 30.2、LPIPS 0.265 → 0.269 都变差；而且 Fig. 3 里 P=2 时 SHA 实测反而更慢（DiT 170 vs 129 ms），交叉点在 2–4 players 之间 —— 论文正文没提这个交叉。
  3. 训练技巧存在「画质 vs 动作跟随」的明确 trade-off。Solaris 开启 KV 反传后 FID 全线改善，但 VLM 动作跟随在 3/5 任务上退化（Movement 78.6→68.2、Grounding 72.9→62.5、Memory 49.0→37.5）。作者承认了，仍然选择开启。这个 trade-off 在其他论文里没人报，但很可能普遍存在。
Khora 的「首个线性复杂度」主张不成立

RhOS × Ophilus 的 Khora（无论文，只有项目页 + 通稿）声称是 "the first scalable multi-agent world model to achieve linear-time complexity"。 但 MultiWorld（2026.04）用共享全局状态 + 各视角并行生成早三个月做到同一件事，且有 FVD / RPE 定量结果；Gamma-World（2026.05）的 SHA 也明确证明并实测了 linear in P。 另外 Khora 官网那个「1024 视角需要超过一百万 GPU」的对比，是把 n² × 单视角成本朴素外推的框定。

六条打折读法 · 与它证明了什么

论文里的说法打折后应该怎么理解
"advances 1,024 players for 10,000 recurrent steps"no-op 动作 + 空 spawn 的结构性压力测试；277–306 步后进入循环吸引子。语义正确性看 SRSC：Snake H=300 → 33.8，Crate Pusher H=100 → 10.0
"X-view disagreement 0.000"同义反复。所有视角从同一份状态确定性投影，不一致数学上不可能。论文自己写的是 guaranteed by construction
"every decoded state is structurally valid by construction"是 schema mask + selector 给的，不是模型学的。Contradiction 恒为 0.0 这一列没有模型信息量
"superior state accuracy"成立，且很强（99.1% vs ≤2.7%）。但只在 2D 网格游戏上，且 Logic Engine 只有 5.66 M —— Snake 的动力学本来几百行代码就能写完
"cost stays independent of the number of cameras"成立，有 C.4 扫描支撑。但总渲染代价仍随视角涨（189.6 → 842.4 ms），且单视角时 97.7% 的时间花在非学习的投影上
"MASS leads six of seven metrics"诚实。输掉的 Invalid（0.177 vs 0.052）其实是指标假象 —— 基线恢复出的内容太少所以违规也少

证明了（三条，我认为很扎实）

  1. dense / latent 递归载体在「实体身份与位置」上是系统性失效的，而这个失效被平均字段准确率完全掩盖。三个独立的 dense 架构在同预算下位置准确率全部 ≤ 2.7%，同时语义准确率 91–96%。这个诊断超出多智能体的范围，是对 latent world model 范式的普遍检验。
  2. 「显式共享」不够，必须「typed」。B-UN 保留整条 pipeline 只换载体，LPIPS 保持第二好，Parser 直接归零 —— 共享一个 dense 状态图不能保住实体身份。
  3. 把世界推进与视角渲染解耦，架构上可行且干净，而且顺带把 netcode 的 client-side prediction 免费拿了过来（oracle 输入下 8 tick agreement 恒 1.000，本地 avatar 位移恒 0）。

没有证明（三条）

  1. 能不能扩到 3D、连续状态、丰富外观。全部实验是 2D 网格游戏，投影是确定性栅格化，渲染器从 16 通道语义栅格出图。作者自己列为未来工作 —— 但这不是小的工程延伸：3D 场景里「schema 应该声明什么」本身就不清楚。
  2. schema 从哪来。全篇假设 schema 是给定的。这意味着每接一个新游戏都要人写 schema + 要有能导出 ground-truth typed state 的引擎。这是 typed state 路线最大的实践成本，而论文没有讨论。
  3. 能不能扛住真正复杂的动力学。Crate Pusher（交互密度更高）的 SRSC Logic 在 H=100 就掉到 10.0，比 Snake 差一个数量级。这暗示 typed state 的优势可能随交互密度快速衰减。
一句话定位

MASS 不是一个更好的多人视频世界模型，它是一次架构论证 —— 论证「世界的记忆」应该长得像游戏状态表而不是像图像。 这个论证在 2D 网格游戏上做得非常漂亮且诚实，但它离「能替代视频世界模型」还隔着一整个 3D 世界。

一个没人做过的明显组合

MASS 的 typed state 当权威状态 + MIRA 的 RAE latent 当视觉载体 + WorldWeaver 的三路监督当桥梁。 typed state 保证语义一致性和可同步性，冻结 DINOv3 的 RAE latent 保证视觉表达力和抗漂移，监督头保证两者对齐。 九篇里没有任何一篇同时拿到「构造保证的一致性」和「视频级的表达力」这两头。
