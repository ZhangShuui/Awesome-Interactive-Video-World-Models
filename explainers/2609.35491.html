Elastic Forcing 精读不请老师打分，直接拿样本对齐分布

论文全名 From Scores to Samples: Elastic Forcing for Autoregressive Video Generation。它沿用 Self-Forcing 的自回归自展开训练，但把 DMD 换掉了。DMD 需要一个双向扩散老师，外加一个在线训练的“假分数”网络；Elastic Forcing（下称 EF）改为在冻结视频编码器的特征空间里算 MMD，让一批生成视频去贴一批参考视频。本页用人话拆开它的三个部件：匹配空间、参考侧估计器、生成侧梯度。玩具实验、偏差–方差、批内相互作用和训练成本都做成了可以动手的图。论文里能复算的数字我都复算了，最后列出存疑之处。

一句话训练信号从“老师给的分数差”换成“样本之间的核相似度”：每个生成视频被相似的参考视频拉近，被相似的其他生成视频推开（MMD 的吸引 + 排斥）。为了在视频训练的显存预算内把这个统计量估准，作者在两侧各做了一件事。参考侧：吸引项用“全参考集的 Nyström 常驻摘要 + 小批蒙特卡洛”按 2:1 混合估计。生成侧：先在特征空间里算完 256 个视频两两之间的全部相互作用，得到每个视频的特征梯度；再随机抽 128 个视频重放生成过程做反传，梯度乘 B/b 保持无偏。去掉两个评分网络后，14B 模型能在单机 8 卡上后训练；换一套参考视频，就能把风格、角色、构图“教”给学生。

01一句话与定位

少步自回归视频生成是流式生成、实时交互和视频世界模型的主力路线。目前标准的后训练是 Self-Forcing + DMD：学生按推理时的方式，自己一块接一块生成完整视频（自展开，self-rollout），再用 DMD 把这批视频的分布推向老师的分布。

DMD 的梯度是“老师在带噪样本上的分数 − 假分数网络在同一样本上的分数”。所以训练时 GPU 上要同时放三个大网络：学生；冻结的老师（Self-Forcing 用的是 Wan2.1-14B，CFG 3.0）；一个跟着学生在线训练的假分数网络（从 1.3B 初始化）。学生越大，两个陪练网络越贵；而且学生最多学到老师的分布。EF 保留自展开，把 DMD 换成 MMD。MMD 只要两堆样本就能算，目标分布由一个固定的参考视频集定义，不再需要任何评分网络。

部件 1 · 在哪里比

冻结编码器的特征空间

V-JEPA 2（时间动态）+ VideoMAE v2（时空结构）+ DINOv3（逐帧语义），高斯核。在像素或 VAE 潜空间里直接比，作者说信号无效。

部件 2 · 参考侧

Nyström 常驻摘要 + MC 小批

用 k-means 地标把全部参考视频压成一个一次算好、没有采样噪声的吸引场，再按 2:1 混入每步随机抽的参考小批，用 MC 的无偏去抵消 Nyström 的有限秩偏差。

部件 3 · 生成侧

先估计、后求导

256 个新鲜视频全部参与 MMD，先算出每个视频的特征梯度；再只抽 128 个重放生成过程做反传，乘 B/b 保持条件无偏。

我的理解

把 EF 看成“iRDM 的自回归视频版”最省力。真正属于它的技术问题只有一个：视频 DiT 的激活太大，没法像图像那样一次反传几千个样本。那么该怎么估计分布、怎么求导？另外要注意，EF 的训练是“短绳牵引”：从 ODE 初始化出发，只更新 100–150 步（14B 是 80 步）。它更像一次分布层面的精修，而不是从头学会生成。

02先补课：自展开、DMD，以及 EF 换掉了什么

一段 5 秒视频是 81 帧、16 fps、832×480，经 Wan 的 VAE 压成 21 个潜帧。Self-Forcing 的做法是每 3 个潜帧一块，共 7 块；每块从纯噪声开始去噪 4 步（1.3B），以前面已生成的块的 KV 缓存为条件。训练时就按这个流程真的生成一遍，所以训练和推理看到的历史是同一种分布。

03MMD 用人话：吸引 + 排斥

MMD（最大均值差异）比较两个分布，不需要密度，也不需要分数，只看样本之间的核相似度。

MMD²k(P, Q) = 𝔼z,z′∼P[k(z,z′)] − 2 𝔼z∼P, u∼Q[k(z,u)] + 𝔼u,u′∼Q[k(u,u′)],   k(x,y) = exp(−‖x−y‖²/2σ²)(2)

第三项只和参考集有关，训练时是常数，可以丢掉。剩下两项：生成–生成的相似度要小（彼此推开，防止塌成一团），生成–参考的相似度要大（被参考拉过去）。

𝓛̂EF = Σe λe [ 1/(B(B−1)) Σi≠j ke(zi, zj) − 2/B Σi m̂α(zi) ](11)

zi = φe(xi) 是第 i 条生成视频在编码器 e 下的特征；m̂α(z) 是“z 与整个参考集的平均相似度”的估计，第 05 节细讲。

我的改写 · 每个样本受的力

对式 (11) 求 −∂/∂zi，高斯核下正好是两股力：

−∂𝓛̂/∂zi ∝ (1/(B−1)) Σj≠i k(zi,zj)(zi − zj) + Σn wn k(zi,un)(un − zi)

前一项把 zi 从相近的兄弟样本旁推开，后一项把它往相近的参考点拉。权重 wn 取决于估计方式：精确计算时每个参考点都是 1/Nref；MC 是随机抽的 Bref 个点，各 1/Bref；Nyström 是 R 个地标，各带系数 βr。力的大小乘了 k，距离超过约 3σ 的点几乎没有作用。所以带宽 σ 决定了“看得多远”：一个样本如果离所有参考点都很远，就拿不到任何拉力。论文只说 σ 是固定带宽，没给数值，也没说怎么定。

动手：把论文 Fig. 3 的玩具实验重做一遍

1,000 个参考点排成螺旋，200 个粒子全部从原点附近出发，这一点和论文的 Fig. 3 一样。四个面板用同一初值、同一个核、同一步长，而且排斥项都精确计算；唯一不同的是吸引项 m̂ 的估计方式。第四个“精确”面板是论文消融里没有的上界：每一步都对全部参考点算吸引。

这个玩具说明了什么

  • 哪个估计器赢，取决于偏差和方差谁大。默认预设下混合最好；地标够多时纯 Nyström 已经接近精确，混进 MC 反而添乱；参考小批够大时纯 MC 最好。这正是论文式 (10) 的含义，α* 应该随情况变，但论文在视频实验里固定用 1/3。
  • 精确版几乎总是最好。在参考点只有几千个的规模上，每步全算一遍并不贵。见第 05 节的算账。
  • 式 (10) 给出的 α* 几乎是 0，混合却赢了。默认预设下，单步的 α*（无论按数值还是按梯度算）只有 0.00x，意思是“几乎纯用 Nyström”；可跑完一整条轨迹，α = 1/3 的混合明显优于纯 Nyström。原因是：MC 的噪声在成百上千步里会被平均掉，Nyström 的偏差却每一步都朝同一个方向推。式 (10) 只衡量单步误差，所以它会系统性地低估该给 MC 的份额。这是我从玩具里看到的，论文没有讨论。

顺带看到的两个 MMD 本身的毛病

  • 被甩出去的粒子回不来。开局所有粒子挤在一点，排斥力很大，会把一些粒子甩到离螺旋很远的地方。那里没有任何参考点在 3σ 以内，拉力为零。MC 的噪声会加重这种情况。
  • 带宽决定细节。σ 大时整体收敛快，但螺旋的细结构被抹平；σ 小时 Nyström 的地标覆盖不过来，偏差暴涨。

04在哪个空间里比：三个冻结编码器

论文说在像素或 Wan VAE 潜空间里算 MMD，训练信号无效（Fig. 2：VAE 空间匹配的宇航员头盔和衣服会变形）。原因是，为重建而训练的潜空间，距离不对应语义和时间上的一致性。所以改在自监督视频编码器的特征里比。

V-JEPA 2

在潜空间里做预测式训练，负责时间动态。每个视频 1024 个 token × 1024 维。

VideoMAE v2

掩码视频重建，负责时空结构。每个视频 1280 个 token × 1024 维。

DINOv3

图像自蒸馏，逐帧的局部语义。每个视频 1024 个 token × 1024 维。损失权重 ×10。

三项损失合成 (10·NDINOv3 + NV-JEPA2 + NVideoMAE)/3，作者说权重是“大致按数值量级平衡选的”。表 7 只给了每个视频的 token 数和维度，没说这 1024 个 token 怎么来（抽几帧、什么分辨率）。附录 D.4 明确不赞成池化（“池化会丢掉损失本可约束的信息”），所以特征是稠密 token；但核是算在每个视频摊平后约 106 维的向量上，还是把每个 token 当一个样本，没有写。

我的推断

81 帧 832×480 的视频被压成约 1,000 个 token。若按常见的 16×16 图块、2 帧一组、256×256 输入算，每组 256 个 token，1,024 个 token 只相当于 8 帧；输入分辨率越高，能容纳的帧就越少。也就是说，编码器看到的是时间和空间上都大幅下采样后的视频。高频的时间伪影（细小闪烁、局部形变）很可能落在盲区里，作者在附录 C.5 也承认“特征分布匹配会漏掉编码器不敏感的错误”。

05参考侧：Nyström 常驻摘要 + MC 小批

所有和参考集有关的监督，都集中在一个量上：参考核均值 mref(z) = (1/Nref) Σn k(z, vn)，即查询 z 与全部参考视频的平均相似度。论文给了两种省钱的估计方法，然后把它们混起来用。

MC 小批 · 无偏但有噪

m̂MC(z) = (1/Bref) Σj k(z, φ(yj)),  yj 随机抽(6)

每步随机抽 Bref 个参考视频。它对经验参考均值无偏，但 Bref 小时方差大，方差为 Var[k(z,φ(Y))]/Bref（式 24）。

Nyström 摘要 · 无噪但有偏

mNys(z) = Σr βr k(ur, z),  (KUU+εI) β = c(19–20)

先对全部参考特征做 k-means，得到 R 个地标 ur。cr = (1/Nref) Σn k(ur, vn) 表示每个地标周围有多少参考质量。解一个 R×R 的小线性方程组得到 β，只算一次。之后每次查询只需 R 次核计算，却带着全部参考的信息。代价是秩 ≤ R 的近似偏差，以及正则 ε 带来的误差。

m̂α(z) = (1−α) mNys(z) + α m̂MC(z),   α* = B²/(B² + V)(9)(10)

附录 C.3：固定查询分布 Q，B² 是 Nyström 偏差平方的平均，V 是 MC 方差的平均。因为 Nyström 是固定值、MC 误差均值为零，交叉项消失，MSE(α) = (1−α)²B² + α²V。实际设置：Nyström:MC = 2:1，即 α = 1/3；玩具实验里用 α = 0.55。R、ε、Bref、σ 都没给。

动手：α 该取多少

一个被跳过的问题：参考集只有 8 千条，为什么不精确算？

iRDM 用 Nyström 把 128 万张 ImageNet 图压成 4,096 个地标，理由是每步重采样参考小批会引入噪声，而压缩后的摘要既没有噪声，计算量也只是零头。EF 的参考集只有 8,000 余条视频，式 (11) 又把每个视频当成一个样本。按这个写法，精确计算吸引项就是一次 B×Nref 的核矩阵运算。下面的计算器按“摊平、池化、逐 token”三种可能的表示方式算账，结果与第 07 节估出的每步训练成本对比。

结论

按论文式 (11) 的写法（每个视频一个样本），无论摊平还是池化，精确计算吸引项每步只要几毫秒到几十毫秒，与一步约 1,700–4,500 GPU·s 的训练成本相比可以忽略。即使按论文没写的“每个 token 当一个样本”来理解，精确计算也只占一步的 1–2%（要像 FlashAttention 那样分块算，不能把整个核矩阵存下来）。三个编码器的参考特征按 bf16 约 50–55 GB（VideoMAE 每视频 1,280 个 token），可以分到 4 张卡上，或从主存流式读取。所以在 8 千条参考的规模上，Nyström 解决的“算不起”问题并不存在，表 4 的消融少了一个最自然的对照：精确全参考。混合估计器比纯 Nyström 只高 0.05，这个优势能否成立，要先和这个上界比。

06生成侧：先估计、后求导

式 (11) 的生成–生成项让每个视频的梯度依赖另外 B−1 个视频。批越大估计越准，但端到端反传要为每个视频都保留视频 DiT 的激活，显存扛不住。

行不通的办法 · 普通梯度累积

把 256 个视频切成 m 个微批，每个微批各算一个 MMD 再把梯度相加。这样只看到了微批内部的配对，跨微批的配对全部丢失，优化的已经不是同一个目标。m = 4 时，只剩约 1/4 的配对。

EF 的办法 · 先在特征空间里算完

关键观察：损失把各视频的特征耦合在一起，但各视频的生成计算图不必同时存在。先不留图地生成 256 条并抽特征，在特征空间里算完整个 MMD，得到每个视频的特征梯度 gi（余切向量）。gi 已经包含了全体样本和参考的影响。剩下的 Σi Ji⊤gi 是各视频独立的向量–雅可比积，可以一条一条重放、反传、释放。这就是 GradCache 的做法。

∇̂θ𝓛 = (B/b) Σi∈𝒮 Σe (Jeθ,i)⊤ gei,   Cov = (B²/b)(1 − b/B) Sh(13)(29)

在 256 个里均匀抽 b = 128 个做重放，每个被抽中的概率是 b/B，乘 B/b 就是 Horvitz–Thompson 无偏估计。无偏是有条件的：给定这一批视频和这一次参考估计，对这一步求出的混合目标梯度无偏，而不是对真实总体 MMD 无偏，论文对此写得很清楚。没被抽中的视频仍然通过 gi 影响被抽中的视频。

我的理解

两件事各管一头：重放管显存，子采样管算力。逐条重放已经把峰值显存限制在“一条视频（或一段）的计算图”，与 b 无关；b 决定要做多少次“重放 + 反传”。把 b 从 256 降到 128，按上面的粗算每步省约 37%（1024 → 640 个单位），代价是梯度方差从 0 变成 B·Sh。v2 正文写得很准确：“重放控制峰值显存，但对全部 B 条都求导仍要 B 次反传”。v1 的说法是 b 同时控制“显存和反传开销”，显存那一半在逐条重放下并不成立。

11换参考就换目标：“超越老师”的实验

DMD 的目标被老师固定了；EF 的目标就是参考集。换一套参考视频，学生就朝新方向走，不需要先去改造一个扩散老师。

单色外观

用黑白视频作参考（论文没说是整体替换还是混入），学生生成单色视频。任务分 9.910（最高），但总体分 8.942 低于 Wan2.1-14B 的 8.992。

角色：奶龙

把含奶龙的视频混入通用参考集。角色保真 8.072（最高），总体 8.380（最高），视觉质量 8.834 低于 Wan2.1-14B 的 8.906。

空间：全景构图

用广角视频作参考。任务分从 Self-Forcing 的 5.000 升到 8.544，总体从 6.272 升到 8.292。附录说这个分数衡量的是投影外观，不是三维几何。

另外两个定性实验：把参考集换成 OpenVid 真实视频（只有样例图，没有定量对比）；在 Wan2.1-14B VACE 上跳过 ODE 初始化，用首帧和光流作条件，先做 100 步“MMD + 辅助回归”，再做 100 步纯 MMD（只有样例图）。附录 E.3 还提到一个重要的负面观察：去掉 ODE 初始化后，单块看着还行，块与块之间的连续性会变差。

这组实验缺的对照
  • 缺最简单的基线。对照组是从没见过奶龙、全景、黑白的 Wan-14B 和 Self-Forcing 学生，赢它们并不意外。该比的是：拿同一批参考视频，直接对学生做回归或扩散式微调（或对老师做 LoRA 再蒸馏）。
  • 缺泄漏检查。损失只匹配视频的边缘分布，不看提示词。把奶龙视频混进参考集后，学生可能在不相关的提示下也生成奶龙，而论文没有报告这种情况出现的频率。单色和全景实验大概是整个参考集都换了，那就等于把整个模型改成了黑白或全景模型。
  • 只有一种 0–10 分的评分，论文没说由谁打。附录 H 的两种 VLM 协议都不是 0–10 分。表 10 的“总体”分也不是四项平均（例如 Self-Forcing 单色：四项平均 8.352，表中 8.308）。

13存疑清单

按严重程度分三档。高动摇论文的主要结论；中削弱某项结论，或影响复现与使用；低口径或表述问题。每条尽量给出能消除疑问的实验。

#1高 主结果的差距与评测噪声同量级，Self-Forcing 基线也不是作者自己跑的

表 1 的 11 行基线与 Reward Forcing 论文表 1 逐格相同。Self-Forcing 那一行（83.80）是 Reward Forcing 重跑的数，Self-Forcing 原论文在名义上相同的协议下（946 条扩写提示 × 5 个种子）报告的是 84.31。同一个公开模型，两次评测差 0.51；CausVid 更是差了 1.68。

EF 的领先幅度正好落在这个量级里：2 编码器对 83.80 是 +0.84，对 84.31 是 +0.33；附录称为主力变体的 3 编码器是 84.25，比 84.31 还低。论文没有报告种子方差，看起来是单次运行；评测提示用谁扩写也没说。正文“在匹配的初始化和评测下 84.64 对 83.80”这句话，“匹配的评测”这一半缺少支撑。

怎样消除：用同一套评测脚本、同一份扩写提示，重跑官方 Self-Forcing 检查点和 EF，各跑 3 个以上种子，报告均值和置信区间。

#2高 混合估计器的价值没有被证明，最自然的对照“精确全参考”缺席

它是论文的两个核心设计之一，但证据有三处缺口。① 表 4 里混合比纯 Nyström 只高 0.05 Total，Quality 反而低 0.04；VLM 2.07 对 1.97，而机会均值是 2.00。② 没有“每步对全部参考精确计算”的对照。按式 (11)“每个视频一个样本”的写法，8,000 条参考下精确计算每步只需几十毫秒；即使逐 token 计算，也只占一步训练成本的 1–2%（第 05 节计算器）。iRDM 面对的是 128 万张图，EF 只有 8 千条，精确计算更便宜，没有理由只拿近似版去比。③ α 固定为 1/3，并没有用式 (10) 去估。按我的推导，α = 1/3 只有在 0.5 < V/B² < 5 时才同时胜过两端，而论文没有估计过自己的 B² 和 V。更根本的是，式 (10) 优化的是单步估计误差；在本页的玩具里，单步 α* ≈ 0，而整条轨迹上 α = 1/3 反而更好，因为 MC 噪声会跨步平均掉、偏差不会。也就是说，这套偏差–方差理论既没被用来选 α，也不是选 α 的合适依据。

论文里的偏差–方差分析本身是对的，但它讲的是核均值的数值误差，不是梯度的误差，作者在附录 C.3 也承认了。玩具实验（图 3）用的是 α = 0.55，而且三条 MMD² 曲线几乎重合。

怎样消除：表 4 加“精确全参考”一行；扫 α ∈ {0, 0.1, 1/3, 0.55, 1} 和 R；在训练中实测 B² 与 V。

#3高 “14B 胜过 Krea Realtime”的证据偏薄：换了尺子，还少列一格

这是引言和 §4.2 的头条结论之一（摘要只说能在 8 卡上训练 14B）。① 到 14B 就不用 VBench 了。其实有一个 14B 的 EF 变体有 VBench 数（表 9，84.05，低于 EF-1.3B；论文没说它是否就是表 2 的检查点），但 Krea 的没有报告。理由“Wan2.1-14B 在 VBench 上低于 1.3B”没有给出处。② VLM 表只列了四个维度中的三个。按附录 H“总分 = 四项等权平均”倒推，被省略的时间连贯性 EF-14B 最低（3.698，Krea 3.910）。即使只假设总分是正权重加总，“SF 三项合计高出 Krea 0.13、总分却最多持平”也说明省略的那一项明显偏向 Krea。v2 正文的措辞是“在列出的 VLM 维度上都更好”。③ 人评只有 20 对视频、各一个种子，3.354 对 3.054，没有显著性检验。

怎样消除：补全四个 VLM 维度；给 Krea 和 EF-14B 都报 VBench（以及 VBench-Long）；人评扩到 ≥ 100 个提示词、多种子，报告配对检验结果。

#4中 “3 编码器更稳”可能部分是“动得更少”

在 VJ+VM 基础上加 DINOv3，动态程度从 65.28 掉到 55.00；只用 DINOv3 时是 32.22，接近静止。VLM 偏好 3 编码器（3.63 对 3.03），作者把它解读为“时间上更稳定”，可 VLM 只看 16 帧，动得少的视频天然显得稳。此外，VBench 的“主体一致性”是用 DINO（v1）特征算的，用 DINOv3 训练相当于朝与尺子相近的方向优化。附录 D.1 把 DINOv3 当作表示约束之间的取舍，附录图 8 的图注也写了“去掉 DINOv3 动态程度更高”；但 3 编码器动态下降 10 分、以及这可能解释 VLM 偏好，没有讨论。另外，150 步的 3 编码器最终模型没有给出 16 个分项。

怎样消除：报告最终模型的 16 个分项；VLM 协议里单独打“运动量”分；换一个不基于 DINO 的一致性指标做交叉验证。

#5中 只匹配视频的边缘分布：损失函数不知道哪条视频对应哪个提示

式 (11) 比较的是“一批不同提示生成的视频”和“一批参考视频”在特征空间里的分布，没有任何提示信息。只要整体分布对得上，把猫的提示生成成狗，损失也照样下降。作者在附录 C.5 和 D.3 承认了这一点。文本对齐之所以没有崩，很可能是因为 ODE 初始化本身已经对齐，而后训练只有 100–150 步，“绳子很短”。论文没有给训练曲线，也没有更长训练下的语义分变化。

这和 iRDM 的结论相反：iRDM 认为条件任务必须匹配“图像–文本”的联合分布。EF 试过文本–视频联合匹配，掉了 0.77，但没有报告是否调过联合核的带宽和权重。

怎样消除：报告语义分随训练步数的变化（例如跑到 500 步）；调好联合核的带宽和权重后，重做联合匹配。

#6中 训练成本的口径不完整

图 6 只算后训练本身。没算的有三项：生成 8,000 条参考视频（若用 Wan2.1-1.3B，按 H100 延迟约 229 GPU·h，超过 EF-1.3B 训练本身的 70–125 GPU·h；若用 14B 要多得多）、抽参考特征、k-means。Self-Forcing 是 data-free 的，没有这笔开销。图里 Self-Forcing-1.3B 的 110–151 GPU·h 也没交代步数、批大小和硬件；Self-Forcing 原论文自报约 96 H100·h。参考视频用的是哪个 Wan 也没说，这一点还决定了 EF 学的是 1.3B 还是 14B 的分布。

怎样消除：写明参考集的生成模型和采样设置；把参考集生成、特征抽取、k-means 的成本单独列出（可以注明“可复用”）。

#7中 关键超参和表示细节缺失，代码未核实

以下都没有给：核带宽 σ（高斯核在约 106 维的摊平特征上，单一带宽很容易让所有核值都接近 0 或都接近 1）、地标数 R、正则 ε、参考小批 Bref、学习率和优化器、编码器输入的帧采样和分辨率、稠密 token 是摊平成一个向量还是逐 token 当样本（附录 D.4 只排除了池化）、梯度截断是否与 Self-Forcing 完全相同（只说“规定的截断”）、梯度是否经过 VAE 解码器、14B 的 B 和 b。损失权重 (10:1:1)/3 是“大致平衡数值”选出来的。论文给了 Gitee 仓库链接，本次没能访问。

怎样消除：补一张完整的超参表；确认代码仓库包含训练脚本和参考集构建流程。

#8中 三种 VLM 协议，只验证了一种；消融的统计力不足

单视频打分（12 帧，0–100 分，用于表 2）、多视频排名（16 帧，用于表 3–5）、成对比较（24 帧，用于附录 G 的相关分析）是三种不同的协议。与人评对过的只有成对协议。消融里的排名分没报组数，也没有置信区间。

怎样消除：对表 2 实际使用的协议也做人评相关；排名分附上组数和自助法置信区间。

#9中 “超越老师”缺最简单的基线和泄漏检查

对照组是从没见过目标内容的 Wan-14B 和 Self-Forcing 学生，赢它们说明不了多少。真正的问题是：同样一批参考视频，直接拿来做监督微调行不行？另外，边缘匹配（见 #5）会不会让奶龙出现在不相关的提示里，论文没有检查。单色实验中，Wan2.1-14B 的总体分（8.992）仍然高于 EF（8.942）。

怎样消除：加“用同一批参考视频做回归或扩散微调”和“LoRA 老师 + 蒸馏”两个基线；统计无关提示下目标内容的出现率。

#10中 只评了 5 秒，而这是一个面向流式生成的方法

表 1 里的 LongLive、Rolling Forcing、Reward Forcing 都是长视频方法，这里只在 5 秒 VBench 上比。EF 沿用 Self-Forcing 的自展开流程（那是 5 秒、81 帧），没提更长的训练片段。流式场景最关心的长时漂移、身份保持、饱和度漂移，论文都没有评测。

怎样消除：在 30–60 秒上跑 VBench-Long 和漂移指标，与 LongLive、Reward Forcing 对比。

#11中 新颖性的边界：核心配方来自图像领域的前作

“冻结编码器 + 高斯核 MMD + 批内精确排斥 + 对全参考集一次算好的 Nyström 吸引 + 大批新鲜样本 + 梯度缓存”，在 iRDM（arXiv 2607.02375，2026-07）里已经完整出现。“估计总体与求导批解耦”在 FD-loss（arXiv 2604.28190）里是核心思想。EF 正文引用了 iRDM（表示分布匹配、Nyström 近似两处），附录 A.2 也点名了 FD-loss 与 Run-Sort-ReRun 的“估计与求导分离”；但正文把混合估计器和解耦作为自己的两项设计来讲，没有单独说明与 iRDM 的差别。EF 真正的增量是：嫁接到自回归视频自展开、MC 混入、子采样重放、视频编码器选择，以及 14B 和适配实验。

怎样消除：正文明确写出与 iRDM 的差异；加一组“iRDM 原样（纯 Nyström + b = B）”对照。

#12低 “Wan2.1-14B 在 VBench 上低于 1.3B”没有数字和出处

Wan 团队发布时称 Wan2.1-T2V-14B 以 86.22% 登顶 VBench 榜单。在本文的扩写提示协议下情况也许不同，但这句话是换评测尺子的依据，应该给出数据。

#13低 表 1 的两行 EF 同时变了两个因素

2 编码器训练 100 步，3 编码器训练 150 步。标题数字用 2 编码器，14B 和适配实验用 3 编码器。v1 正文曾说“后续实验都用 3 编码器”，可估计器消融的“混合”行与 2 编码器完全相同；v2 已改成“规模与适配实验用 3 编码器”。3 编码器在 100 步时是 83.81，和 Self-Forcing 的 83.80 相同。

#14低 玩具实验支撑不了“最好收敛”

图 3 的混合用 α = 0.55，与视频实验的 1/3 不同；优化对象是粒子，而不是生成网络；三条 MMD² 曲线在对数坐标上几乎重合，“最好”来自肉眼看螺旋。本页第 03 节的复现也表明，换一组 R 或 Bref，胜者就会换。

#15低 v1 对求导批 b 作用的描述不准确

按算法 1 的逐条重放，峰值显存由“一条视频（或一段）的计算图”决定，与 b 无关；b 控制的是“重放 + 反传”的次数。按第 06 节的粗算，b 从 256 降到 128 每步省约 37% 的计算量，代价是梯度方差从 0 变成 B·Sh。v1 说 b 同时控制“显存和反传开销”，显存那一半不成立；v2 已改成“重放控制峰值显存，b 控制反传次数”。

#16低 表 2 的 Self-Forcing 行没标规模，小数位也不统一

Self-Forcing-14B 在 8 卡上爆显存，所以这一行应该是 1.3B，但表里没写。数值有的保留两位、有的保留三位（4.111、4.11、4.224）。

#17低 单一、固定的核带宽

单一带宽的高斯核，对离所有参考点都很远的样本几乎没有拉力（第 03 节玩具里被甩出去的粒子）。iRDM 用中位数启发式给每个编码器定带宽，并在结论里建议试多尺度核。EF 只说“固定带宽”。

14结论、做对的地方、对交互式世界模型的启示

总评

EF 把一条已经在图像上跑通的“冻结编码器 + MMD”路线，搬进了少步自回归视频的 Self-Forcing 框架。最扎实的贡献在工程上：去掉两个评分网络后，14B 模型能在单机 8 卡上完成分布级后训练（Self-Forcing-14B 在同条件下爆显存）；参考集成了可以替换的训练目标。1.3B 的质量提升和评测噪声同量级，混合估计器的必要性也没有被证明。

做对的地方

  1. 问题选得准。DMD 的两个陪练网络是扩大自回归视频后训练规模的真实瓶颈，EF 直接把它们拿掉了。
  2. 数学写得干净，边界也写得清楚。吸引 / 排斥分解、按样本的特征梯度加重放、Horvitz–Thompson 重缩放的条件无偏、偏差–方差分解都正确，而且附录反复注明“这是条件无偏，不是对总体 MMD 无偏”“这是数值误差，不是梯度误差”。
  3. 评测上有诚实的部分。VBench 和 VLM 打架时，两个结果都报了，并承认加 DINOv3 会降 VBench；人评的相关分析按提示词聚合，没有把 42 人的打分当成独立样本。
  4. “参考集就是规格”是 DMD 路线没有的能力。换参考就换目标，还能用真实视频当参考。

对交互式视频世界模型的启示

  1. 老师门槛降低了。想把一个自回归世界模型做成少步、实时，却没有双向的、带动作条件的老师时，EF 路线只需要一堆高质量录屏作参考，再加冻结编码器。
  2. 但边缘匹配对动作是盲的。模型完全可以忽略动作输入，而损失照样下降（#5）。至少要把动作序列的嵌入和视频特征拼起来做联合核，并认真调带宽和权重（iRDM 的做法；EF 在文本上试过、掉了分，未报告调参）；或者按动作分桶做条件 MMD。动作跟随要单独评测。
  3. 编码器只看约 1,000 个 token。回访一致性、长时记忆不在它的视野里，世界模型的长程一致性需要另外的监督或专门的特征。
  4. 最直接的用途是“换皮”。14B 单机可训，加上参考驱动的适配，可以把一个通用自回归视频模型快速变成某个游戏或风格的实时渲染器，但要先做泄漏检查（#9）。

最值钱的后续实验

  1. 在同一评测流水线里重跑官方 Self-Forcing 和 EF，多个种子，报告置信区间（#1）。
  2. 表 4 加“精确全参考”，并扫描 α 与 R；在训练中实测 B² 和 V（#2）。
  3. 14B 补全四个 VLM 维度，给 Krea 和 EF 都报 VBench，扩大人评规模（#3）。
  4. 最终 3 编码器模型的 16 个分项，外加一个独立的运动量指标（#4）。
  5. 语义分随训练步数的变化；调好带宽后的联合文本–视频核（#5）。
  6. 适配实验加监督微调基线和泄漏统计（#9）。
  7. 30–60 秒长视频的漂移评测（#10）。
