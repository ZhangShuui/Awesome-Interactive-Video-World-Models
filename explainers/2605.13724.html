    Flow Map Distillation · Any-Step Video Diffusion

    把「跳到终点」换成「跳一段」

    AnyFlow 的全部赌注压在一件事上：蒸馏目标从 zt → z0 改成 zt → zr，于是多步采样不再需要「重新加噪」这个动作。

    NVIDIA · Show Lab, NUS · MIT 底座 Wan2.1 1.3B / 14B 480×832 · 81 帧 LoRA r=256 代码 NVLabs/AnyFlow

    一致性蒸馏（rCM、Self-Forcing）在 2–4 步很强，但给它更多步反而更差：rCM 在 1.3B 上从 4 步的 82.51 一路掉到 32 步的 75.72。AnyFlow 说这不是调参问题，是结构问题——一致性采样每一步都要把状态打回 z0 再用新噪声加回去，这个动作本身就在把轨迹推离 PF-ODE。换成 flow map 之后，多步采样退化成普通 Euler，曲线就单调了。本页把两阶段训练拆开，逐条对着 NVLabs 放出的代码核对，并列出 14 条存疑——其中 3 条是论文公式与代码直接矛盾。

    01

    一图看懂：多出来的那根虚线箭头

    两种采样器画在同一张状态空间图上。唯一的结构差别是一致性采样里那根「重新加噪」的虚线——它是后面所有问题的源头。

    三句话版本

    • Stage 1（前向）：用 MeanFlow 目标把预训练的 Wan2.1 改造成两时刻模型 uθ(zt, t, r)。JVP 用中心差分绕开（TiM 的做法），外加四个改装：插值式时间条件、Beta(2,1.5) 时间加权、CFG 融合、以边界样本为基准的自适应损失归一。
    • Stage 2（on-policy）：DMD，但 rollout 用 Flow Map Backward Simulation——不跑完整的 N 步，而是靠 flow map 的复合性把整条轨迹压成 3 段：T→t（抄近路）、t→r（真正要学的那一步）、r→0（抄近路）。三段全部带梯度。于是无论 N=4 还是 N=50，训练代价恒定。
    • 结果：VBench 曲线从「越采越差」变成「单调但很快饱和」。1.3B 双向 4→32 步涨 0.48；14B 双向只涨 0.06。真正的卖点不是 scaling 有多强，而是不再崩，外加一个模型同时覆盖 2 步预览和 32 步交付。
    02

    为什么一致性模型「越采越差」：一个能自己跑出来的玩具

    论文用 Fig. 2 讲这个道理，但没给可验证的机制。下面这个二维玩具把误差模型摊开写明白：拖动步数，看两条曲线各自往哪儿走。

    这不是训练不足

    关键在于：一致性模型的多步采样器需要一个它从未被训练过的状态分布。训练时 zt 来自「干净视频 + 噪声」，推理时第 2 步之后的 zt 来自「学生自己的 ẑ₀ + 新噪声」。学生的 ẑ₀ 本身带偏置，于是喂进去的是一个偏移过的分布，误差被反复放大。步数越多，这个循环转得越多次。

    03

    Flow map：一个把三种目标装进同一个函数的参数化

    形式上极简：给模型多喂一个时间戳。但这一步把「一致性模型」「流匹配」「区间转移」统一成了 (t, r) 平面上的三块区域。

    精确流映射　Φr←t(zt) = zr，　1 ≥ t ≥ r ≥ 0
    恒等性　Φt←t(z) = z　　复合性（整篇论文的支点）　Φq←r ∘ Φr←t = Φq←t

    神经网络近似　fθ(zt, t, r) = zt − (t − r)·uθ(zt, r, t)　u 是区间 [r,t] 上的平均速度

    两个退化情形决定了这个参数化的全部张力：令 r = 0，fθ 就是一致性模型的终点映射；令 t = r，uθ 就是瞬时速度场，也就是原始的流匹配。AnyFlow 的主张是：预训练模型已经把 t = r 这条对角线学得很好了，蒸馏要做的是把它向内部区域外推，而不是像一致性蒸馏那样只盯住 r = 0 这条边。

    MeanFlow 目标与它的 JVP 麻烦

    ℒ(θ) = 𝔼 ‖ uθ(zt, r, t) − sg(utgt) ‖²， utgt = v(zt, t) − (t − r)· d uθ(zt, r, t) / d t

    那个 d/dt 是 Jacobian-vector product，在 FSDP 下难搞。AnyFlow 采用 Transition Model（TiM）的中心差分近似，每步多两次前向：

    d u / d t ≈ [ u(zt+Δ, r, t+Δ) − u(zt−Δ, r, t−Δ) ] / (2Δ)　代码里 Δ = 5/1000，且整段在 torch.no_grad() 下算

    代码细节：扰动点用的是真实速度 v = ε − x 来构造 zt±Δ = zt ± Δ·v。在线性插值路径 zt = (1−t)x + tε 上这恰好是精确的 dz/dt，所以这一步没有额外近似误差——近似只来自有限差分本身。

    04

    Stage 1 的四个改装：哪些是真设计，哪些是论文写错了

    MeanFlow 是为「从零预训练」设计的，直接搬到「后训练一个已有的视频扩散模型」会炸。AnyFlow 加了四件东西，其中第一件的公式与开源代码系数是反的。

    ① 插值式时间条件 —— 论文与代码对不上

    要把单时间戳模型改成两时间戳，得新加一个 r 的嵌入。MeanFlow 用 emb(t) + emb′(t−r)；TMD 用零初始化的输出投影。AnyFlow 说这两者都会让嵌入范数越训越大、画面过饱和（Fig. 11），改用插值：

    系数矛盾Interpolated Timestep Conditioning
    论文 §4.2.1 正文
    g · emb(t) + (1 − g) · emb′(r)，「g 固定为 0.25」
    → t 只占 0.25，r 占 0.75
    代码 transformer_far_wan_model.py
    rt_emb = (1 - gate) * temb + gate * delta_emb，gate_value: 0.25
    → t 占 0.75，r 占 0.25
    谁是对的：代码。让主时间戳 t 占大头才符合「轻微改装预训练模型」的意图，也才解释得了为什么它比零初始化更稳。两者在边界 t = r 处等价（因为 delta_embedder 是 time_embedder 的 deepcopy，插值退化为预训练嵌入本身），所以论文的稳定性论证仍然成立——但写出来的那个式子在 t ≠ r 时给的是相反的权重。
    符号撞车同一个 g，两个含义
    §4.2.1 插值门控
    g = 0.25，无量纲插值系数
    flowmap_cfg.gate_value: 0.25
    式 (6) 引导融合
    g = CFG 引导强度
    text_encoder_cfg.fuse_guidance_scale: 3.0
    论文在相邻两段里用同一个字母 g 指代两个数值完全不同的量（0.25 与 3.0），且都只说「fixed to」。Alg. 1 里的 g 是后者。读的时候必须自己分辨。

    ② 引导融合训练：CFG 被烤进权重

    训练时不是直接监督模型输出，而是先把条件与无条件预测按 CFG 公式合成，再去回归目标：

    u = (1/g)·( uc − (1 − g)·sg(u∅) )，　t = r 时监督 u = v
    反解 →　uc = g·v + (1 − g)·u∅ = u∅ + g·(v − u∅)　这正是 CFG 的形式

    也就是说，学生的条件输出直接等于教师做完 CFG 之后的结果。推理时 guidance_scale=1.0，一步只前向一次。这是 AnyFlow 的 NFE 能和 Wan2.1 的 50×2 直接比较的原因——分母里那个 ×2 被它省掉了。

    代价：引导强度被固化

    代价有两个，论文都没讨论。其一，fuse_guidance_scale=3.0 被烤死，用户在推理时无法调节引导强度。其二，式 (6) 里被称作「null conditioning」的 u∅，在代码里其实是 assets/negative_embedding/wan_negemb_cn.pth——Wan 官方那段很长的中文负面提示词嵌入，不是空条件。这意味着那段负面提示词的效果也被固化进了权重。

    一个被跳过的项。Alg. 1 里 du/dt 的有限差分只对条件分支求差，再除以 g；而被训练的对象是融合后的 u，它的时间导数应当是 (duc/dt − (1−g)·du∅/dt)/g。缺的那一项在 g = 3 时系数是 2/3，不小。代码与论文在这里是一致的（都这么做），所以它不是笔误，而是一个未被承认的近似。

    ③ 时间采样器：三个选项差 0.21 分

    t, r 先各自从 U(0,1) 采样再排序，因此 t = max 的边缘密度是 p(t) = 2t。在此之上再乘一个重加权 w(t)。

    ④ 自适应损失重加权：拿对角线当尺子

    MeanFlow 预训练用 w = 1/(‖Δ‖² + c)。AnyFlow 认为后训练场景下 t = r 的瞬时速度场已经是可信的，于是拿它的平均损失当基准去缩放其它时间对：

    wt,r = 1（当 t = r）；　wt,r = μt=r / (‖Δ‖² + c)（当 t ≠ r） 
    # trainer_wan_anyflow_pretrain.py · train_bidirection()
global_loss  = torch.cat(dist.nn.all_gather(loss), dim=0)        # 跨 rank 收集
scale_weight = global_loss[global_diffusion_mask].mean() / (loss[~is_diffusion] + 1e-5)
loss[~is_diffusion] = loss[~is_diffusion] * scale_weight          # 整段在 no_grad 下算 → 只改幅度不改方向

    效果上等价于把 t ≠ r 的梯度幅度钳到 μt=r 这个量级：损失越大，缩放越狠，上限恒为 μ。注意 μ 是全局（跨所有 rank）统计量，单卡复现时这里的数值会不一样。

    05

    论文没画的那根轴：shift = 5 把「4 步」变成了什么样

    所有图里的时间轴都画成均匀的。但 Wan2.1 用 flow shift = 5，模型真正看到的噪声水平被严重拉向高噪声端。这件事决定了 flow map 到底在解什么。

    调度器的采样格点是先在 u 上取均匀 linspace，再做 shift 映射：

    σ = s·u / (1 + (s − 1)·u)，　s = 5　（scheduling_flowmap_euler_discrete.py · apply_shift）
    06

    Flow Map Backward Simulation：用复合性把整条 rollout 压成三段

    这是论文真正的技术贡献。DMD 要求学生先自己走完一条 rollout 到 z0 才能算 KL 梯度；N 步 rollout 就要 N 次前向。AnyFlow 用 flow map 的复合性把它压成恒定的 3 次。

    fθ(zt, t, q) ≈ fθ( fθ(zt, t, r), r, q )，　t > r > q　式 (8)：一切的支点 
    # far/pipelines/pipeline_wan_anyflow.py · training_rollout()　（删去无关行）
timesteps = self.scheduler.timesteps                 # shift 后的 N 个格点
timesteps = torch.cat([timesteps, timesteps.new_tensor([0])])

prev_timestep    = [timesteps[0],              timesteps[grad_timestep]]      # T → t  shortcut
current_timestep = [timesteps[grad_timestep],  timesteps[grad_timestep + 1]]  # t → r  目标转移
post_timestep    = [timesteps[grad_timestep+1], timesteps[-1]]                # r → 0  shortcut

latents = inference_range(latents, prev_timestep)     # 三段都带梯度：整个函数里没有 no_grad
latents = inference_range(latents, current_timestep)
latents = inference_range(latents, post_timestep)
    最该追问的一条：这个 on-policy 是近似的

    训练时喂给目标转移的那个 zt，是一次大跳 fθ(zT, T, t) 的产物；推理时 N 步采样走到 t 的那个状态，是若干次小步复合的产物。两者相等，当且仅当式 (8) 的复合性精确成立。而复合性不精确，正是整篇论文要修的那个误差——如果大跳和小步复合已经一样准，一步生成就等于 N 步生成，也就不需要 any-step 了。

    所以这套 on-policy 的「on-policy 性」是自举的：它用模型自己的复合近似来生成「模型自己的轨迹」。N 越大、shortcut 跨度越大，训练分布与真实 rollout 分布的偏差越大。这大概率是 32 步收益很快饱和（1.3B +0.48，14B 只有 +0.06）的一个结构性原因。论文没有度量过这个偏差——最直接的诊断是把 shortcut 得到的 zt 与真实 N 步 rollout 的 zt 做距离统计，论文与代码里都没有。

    另一处正文与算法框对不上。Alg. 2 写的是 s ∼ Uniform(1, 2, …, T)，即从所有可能的步数里均匀采。代码里是 num_inference_steps_list: [2, 4, 8, 16, 50]，只有五个离散预算。评测用的 32 步不在这个列表里——这一点其实对论文有利（说明确实泛化到了没训过的预算），但训过的最大预算 50 从未被汇报，1 步、3 步、5 步这些「任意步」最该验证的点也一个都没给。
    07

    因果版：chunk、KV cache，和一堵梯度墙

    AnyFlow-FAR 把同一套东西搬到自回归模型上。这里的「on-policy」含义变了：它修的不再只是离散化误差，还有逐块生成的曝光偏差。

    这堵梯度墙的意义值得说清楚：第 k 块的生成条件是学生自己生成的前 k−1 块（所以是 on-policy，曝光偏差被暴露出来了），但 DMD 梯度只修正「给定这个有瑕疵的上下文，第 k 块该怎么画」，不会反过来要求前面的块为后面的错误负责。这与 Self-Forcing 的做法一致，不是 AnyFlow 的新选择。

    一次 generator step
    8 块 × 3 段 = 24 次带梯度前向（N 无关）。对比一致性路线在 N=16 时的 8×16=128 次前向。
    bidirectional_modeling_prob
    0.1——10% 的训练步把因果模型当双向模型训。论文没有提及。
    long_context_training_ratio
    0.5。同样未在论文出现。
    DMD 的两个评分网络
    均以 is_causal=False 调用，即双向地看完整段视频再给梯度。与 Self-Forcing「用双向教师指导因果学生」同构。

    续训能力：论文里被低估的那个卖点

    Fig. 7–8 讲的是一件很实用的事：Self-Forcing 蒸出来的因果模型很难再往下游数据上接着训（它的参数化已经绑死在一致性采样器上）；AnyFlow 因为保留了 t = r 这条对角线上的瞬时速度场，等于保留了一个完整可用的流匹配模型，可以直接在机器人、驾驶、游戏数据上继续微调。对「交互式世界模型」这个方向来说，这比 VBench 上那 0.5 分重要得多——它意味着蒸馏不再是管线的终点。

    08

    DMD 那一半：谁是 real、谁是 fake，以及一个命名陷阱

    on-policy 阶段的损失本身是标准 DMD2，没有创新。但代码里的命名会让人读错，而且「教师」的身份比论文正文说的复杂。

    ∇θ ℒDMD = −𝔼t,z [ ( sreal(zt, t) − sfake(zt, t) ) · ∂fθ(z)/∂θ ]
    命名陷阱

    代码里那个叫 self.discriminator 的模型不是 GAN 判别器。discriminator_loss() 算的是标准流匹配去噪损失 (noise_pred − (noise − latents))²，训练对象是学生生成样本上的分数函数——也就是 DMD 里的 sfake（critic）。论文 Tab. 1 把 APT 系列标为 "GAN Loss"、把自己标为 "DMD Loss" 是对的；只是读代码时别被这个变量名带偏。discriminator_update_ratio: 1，即 critic 与 generator 1:1 交替更新。

    sreal 是谁
    不是原始 Wan2.1，而是 Wan2.1 在同一份 256K 合成数据上 LoRA 微调后的版本（real_cfg.pretrained_path 指向 train_wan1b_teacher_*/step_6000.pt 的 EMA 权重）。论文只在 ODE-Init 对照那一小节提过一句「我们在同一合成数据上微调了教师，因为拿不到 Wan 的原始训练数据」，但实际上整个 stage 2 的 real score 都是这个微调版教师。
    real_guidance_scale
    3.0——real score 自己再做一次 CFG 才作为目标。与 stage 1 的 fuse_guidance_scale: 3.0 同值，保证两阶段的等效引导强度一致。
    梯度归一化
    grad / |pred_video − pred_real_video|.mean()，逐样本。沿用 DMD2 / Self-Forcing 的实现。
    co-train
    cotrain_forward_kl 默认 True：stage 2 每个 generator step 同时跑一次 stage 1 的前向 flow map 损失。所以 stage 2 不是纯 on-policy，是前向正则 + 反向 KL 的混合。
    DMD 加噪时刻
    generator 用 t ~ U(0,1) 再 shift；critic 用 logit_normal(0, 1.0) 再 shift。两者不同，论文未提。
    数据来源的混淆风险。stage 1 的 256K 合成视频全部由 Wan2.1-T2V-14B 生成，而 1.3B 学生和 14B 学生用的是同一份数据。对 14B 来说这是自蒸馏；对 1.3B 来说，它的 stage 1 目标分布来自一个比它自己的教师更强的模型。因此「AnyFlow-1.3B 4 步 83.48 > Wan2.1-1.3B 50×2 步 83.24」这个结论里，有多少来自 flow map 蒸馏、有多少来自 14B 数据的隐性跨尺寸蒸馏，论文没有做区分实验。与 rCM-1.3B（82.51）的比较也因此不是同一训练协议下的对照。

    存疑清单：14 条，按严重度排序

    前 5 条是论文与开源代码直接冲突或影响结论归因的；中间 7 条影响结论强度；最后 2 条是记录性的。所有代码引用来自 github.com/NVLabs/AnyFlow 主分支。

    高 · 01插值时间条件的系数，论文与代码相反
    论文
    g·emb(t) + (1−g)·emb′(r)，g = 0.25 → r 占 0.75
    代码
    (1-gate)*temb + gate*delta_emb，gate = 0.25 → t 占 0.75
    按论文写法，主时间戳的权重只有 1/4，这与「轻改装预训练模型、保住 t=r 边界」的论证方向矛盾。以代码为准。
    高 · 02同一个符号 g 指代两个量
    §4.2.1
    插值门控 g = 0.25（gate_value）
    式 (6) / Alg. 1
    CFG 引导强度 g = 3.0（fuse_guidance_scale）
    两段相隔不到一页，且都说「fixed to」。复现时若把 Alg. 1 里的 g 当成 0.25，引导融合会完全失效。
    高 · 0325% 的前向训练其实是一致性训练，论文未披露
    论文
    「我们在每次迭代中让 50% 的 batch 来自边界情形 t = r」——只说了这一条
    代码
    diffusion_ratio: 0.5（r ← t）+ consistency_ratio: 0.25（r ← 0）
    真正落在「一般区间转移」内部的训练样本只有 25%。这对全文叙事有直接影响：论文的立论是「一致性公式是问题根源，我们换成 flow map」，而实现里四分之一的前向监督就是终点一致性监督。它很可能是让 4 步性能站住的关键——也意味着「flow map vs consistency」不是一次干净的替换，而是一次配比。这个配比没有任何消融。
    高 · 04on-policy 的「on-policy 性」是自举近似，且没有被度量
    训练时的 z_t
    由一次大跳 fθ(zT, T, t) 得到
    推理时的 z_t
    由 grad_timestep 次小步复合得到
    二者相等当且仅当复合性式 (8) 精确成立，而它不精确恰恰是本文要修的误差。N 越大、shortcut 跨度越大，训练分布偏得越多。最直接的诊断是统计两者的距离随 N 的变化，论文与代码里都没有。这很可能是 32 步收益迅速饱和的结构性原因。
    高 · 051.3B 的对比不是同协议：stage-1 数据来自 14B
    事实
    256K 合成视频全部由 Wan2.1-T2V-14B 生成，1.3B 与 14B 学生共用
    后果
    「AnyFlow-1.3B@4 = 83.48 > 自己教师 50×2 = 83.24」里混进了跨尺寸蒸馏的收益

    中 · 08stage-2 迭代数对不上，且 checkpoint 可能按 VBench 选
    论文 §5.1

    代码 config

    配置里训练 1200 步、每 400 步在 VBench 上评一次并存 checkpoint。若最终报告的是其中按 VBench 挑出的最好一档，那么报告分数与选择指标是同一个，差值 0.1 量级的结论会被系统性抬高。论文未说明选择规则。
    中 · 09评测只有 VBench：没有多样性、没有误差棒，第三方复测有差
    本文报告
    AnyFlow-1.3B@4 → 83.48
    第三方复测（CrossDistill, 2609.14725）
    同一模型同设定 → 83.41；并测得多样性仅为教师的 66%
    DMD 的反向 KL 是 mode-seeking，会系统性砍多样性，而 VBench 不惩罚这件事。AnyFlow 全文没有任何多样性、FVD 或人评指标，也没有种子间方差。对「交互式世界模型」这个用途来说，多样性掉到 66% 比 VBench 涨 0.5 分重要得多——同一个 prompt 反复 rollout 会越来越像确定性回放。
    中 · 10融合目标的时间导数漏了一项
    被训练的对象
    u = (uc − (1−g)u∅)/g
    Alg. 1 / 代码的 du/dt
    只对 uc 做中心差分再除以 g

    谱系、定位与复现速查

    对交互式世界模型这条线意味着什么

    AnyFlow 本身不是世界模型，是使能层，它解决的是交互式 rollout 的一个具体矛盾：实时交互要求 2–4 步，但用户偶尔需要一次高质量渲染；过去这需要两个模型（一个蒸馏版、一个原版），而蒸馏版还不能继续微调。AnyFlow 把这两件事合成一个模型，并保住了续训能力（图 7–8 的机器人、驾驶、游戏微调）。真正的未决问题是多样性：第三方复测显示它只剩教师的 66%，而交互式世界模型一旦失去 seed 级分岔，就退化成了确定性回放。

    如果要接着做，这四个实验最值钱

    1. 量化 shortcut 偏差（对应存疑 04）：统计 ‖fθ(zT,T,t) − EulerN(zT→t)‖ 随 N 的曲线。如果它随 N 显著增长，就能解释饱和，也给出「shortcut 该跨多远」的设计依据。
    2. 扫 consistency_ratio（对应存疑 03）：0 / 0.125 / 0.25 / 0.5。这是论文叙事与实现之间最大的缝，也最可能是少步性能的真实来源。
    3. 同协议对照（对应存疑 05）：用 1.3B 自己生成的数据重跑 stage 1，再和 rCM-1.3B 比。
    4. 补多样性与延迟（对应存疑 09、12）：固定 prompt 多 seed 的成对距离 + 实测 s/video。这两条决定了它在交互式 rollout 里是否真的可用。
